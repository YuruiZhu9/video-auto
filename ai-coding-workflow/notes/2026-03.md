### 新增来源：Dev.to CRISP Prompt Framework 2026

**CRISP框架（开发者的Prompt工程标准）：**

| 组件 | 说明 | 示例 |
|------|------|------|
| **C - Context** | 画好技术背景：语言、框架、架构 | "Node.js + Express + MongoDB" |
| **R - Role** | 定义AI角色定位 | "资深后端工程师" |
| **I - Instructions** | 用动作动词明确任务 | "实现、审查、调试" |
| **S - Specifications** | 定义成功标准、性能要求、代码风格 | "响应时间<200ms" |
| **P - Polish** | 请求解释、权衡和备选方案 | "说明取舍" |

**进阶Prompt模式：**

1. **约束优先模式（Constraint-First）**：先描述限制（内存、性能、网络条件），再提功能需求 → 得到更贴近生产环境的方案

2. **演化模式（Evolution Pattern）**：从简单开始逐步增加复杂度，理解每个级别的权衡

3. **链式推理（Chain-of-Thought）**：引导AI逐步推理，适用于复杂问题和架构决策

**工具适配策略（2026）：**
- **GitHub Copilot**：最适合来自现有代码库的上下文；使用描述性注释和有意义变量名
- **Claude**：擅长复杂需求和架构讨论；用于系统设计和代码审查
- **Cursor IDE**：理解整个代码库；用于跨项目重构

**常见错误（避免清单）：**
1. 一次性要求所有内容 → 应分解为顺序Prompt
2. 跳过"为什么" → 解释问题背景，AI才能给出更好的替代方案
3. 忽略错误场景 → 始终显式要求错误处理和边界情况

**有效上下文的四要素框架（核心新增）：**

| 要素 | 说明 | 示例 |

| **可量化的完成标准** | 测试通过、bug消失、功能正常 | "单元测试覆盖率 > 80%" |

**Codex 核心观点：**
> AI只是将人类需求表达方式放大了，它无法像人一样主动猜测你的意图。说清楚要什么、背景是什么、有什么限制、如何验收——这种沟通逻辑与人类协作如出一辙。

**规划优先原则（与 Addy Osmani 一致）：**
- 复杂任务：先做计划再动手执行
- AI能快速执行任何方向的任务，包括错误的方向
- 前期多花时间规划，显著减少后期返工成本

**可复用规则文档（AgentS.md / CLAUDE.md）：**
- 项目运行方式 + 测试方法 + 规范要求 + 禁忌事项
- 文档应短而准确，先框架后补充
- AI犯同样错误两次 → 及时复盘加入文档

**工具权限配置建议：**
- 初期设置严格权限，熟悉后逐步放开
- 控制 AI 何时需要征求同意、何时可直接执行
- 控制能访问哪些文件、运行哪些命令

### 新增更新 (2026-03-25 第三次) — 重大新增

#### 来源：cursor.com - Best Practices for Coding with Agents

**Cursor Agent 三大组件模型：**
> 每个 Agent = Instructions（系统提示） + Tools（文件编辑/搜索/终端） + Model（模型）

**Debug Mode（调试模式）：**
> 当遇到难以复现的 bug 时，Debug Mode 会：
> 1. 生成多个错误假设 → 2. 在代码中植入日志语句 → 3. 请求你重现 bug，同时收集运行时数据 → 4. 分析实际行为，定位根因 → 5. 基于证据做精准修复
> 最佳场景：可复现但找不到原因的 bug、竞态条件、性能问题、回归

**Rules 系统（`.cursor/rules/`）：**
- 为项目提供持久化指令（命令、模式、权威示例）
- 避免：复制整个风格指南（用 linter 代替）、记录所有命令、处理罕见边界情况
- 增量添加：只在 Agent 重复犯错时才添加规则

**Hooks 系统（`.cursor/hooks.json`）：**
- 前置/后置 Hook 可让 Agent 持续运行直到目标达成（如所有测试通过）

**自定义命令（`.cursor/commands/`）：**
- `/pr`：提交、推送并打开 PR
- `/fix-issue [number]`：拉取 Issue、修复、提 PR
- `/review`：运行 linter 并检查常见问题
- `/update-deps`：检查过时依赖，逐个更新

**TDD 与 Agent 结合流程（原创六步法）：**
1. 让 Agent 根据输入/输出对写测试 → 2. 运行测试，确认失败（无实现代码）→ 3. 提交测试 → 4. 让 Agent 写通过测试的代码 → 5. 持续迭代直到全部通过 → 6. 提交实现

**并行 Agent - Git Worktree 原生支持：**
- Cursor 自动创建和管理 git worktrees，每个 Agent 在隔离文件中运行，点击 "Apply" 合并回主分支

**多模型并行对比：**
- 同时选择多个模型提交相同 Prompt，并排比较结果，适用于难题有多种解法思路的场景

**Agent Review + Bugbot：**
- Agent 完成后 Review → Find Issues 逐行分析 proposed edits；推送到 source control 后 Bugbot 自动在每个 PR 上应用高级分析

**Visual Debugging（视觉调试）：**
- 对错误状态截图，让 Agent 调查，无需文字描述；Agent 可控制浏览器截图验证视觉变更

**关键新增 — `prompt-caching.md` 核心设计原则：**
> "Prompt caching is a prefix match. Any change anywhere in the prefix invalidates everything after it."

- **设计原则**：稳定内容放前面，易变内容放后面
- **工作流**：追踪 prompt 装配路径 → 分类稳定性 → 检查渲染顺序 → 放置 breakpoint
- **反模式**：时间戳/UUID/random ID 必须放最后，否则整段不可缓存
- **常见模式**：大 system prompt 共享 → breakpoint 在最后一个 system block；多轮对话 → breakpoint 在最后一条消息的最后 content block

# 01 - 需求分析

> 需求清晰是AI协作成功的一半

## 为什么需求分析重要

AI不理解你的心理预期，它只能根据你的描述来理解需求。模糊的需求 = 模糊的结果。

## 好的需求描述结构

### 基础信息

```
## 项目概述
- 项目名称：[名称]
- 目标用户：[谁会用]
- 核心价值：[解决什么问题]

## 功能需求
1. [功能点1]
2. [功能点2]
3. [功能点3]

## 非功能需求
- 性能要求：[响应时间/并发]
- 兼容性：[浏览器/设备]
- 安全性：[数据保护要求]

## 验收标准
- [可测试的具体指标]
```

## AI友好的提问方式

### ❌ 模糊的提问
> "帮我做一个用户管理系统"

### ✅ 清晰的提问
> "帮我做一个用户管理系统，需要：
> 1. 用户注册/登录（邮箱+密码）
> 2. 用户资料编辑（头像、昵称、简介）
> 3. 管理员后台（查看/禁用用户）
> 4. 技术栈：React + Node.js + MySQL
> 5. 预计用户量：1万"

## 需求clarify清单

在开始编码前，和AI确认：

- [ ] 技术栈确定了吗？
- [ ] 数据结构想清楚了吗？
- [ ] 第三方依赖选好了吗？
- [ ] 有参考项目吗？
- [ ] 优先级是什么？（MVP vs 完整版）

## 常见问题

| 问题 | 解决方案 |
|------|----------|
| 需求太大 | 拆分成多个小需求，分批完成 |
| 描述不精确 | 用具体例子说明："比如微信的登录界面" |
| 遗漏边界情况 | 主动问AI："有哪些边界情况要考虑？" |
| 技术选型纠结 | 先让AI分析各方案优缺点，再做决定 |

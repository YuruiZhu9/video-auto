OpenClaw 是一个自托管的 Node.js AI 代理运行时，模型无关（支持多种先进 AI 模型，包括 DeepSeek 等），数据默认留在本地，MIT 开源协议完全免费。它最核心的能力是：

对于中文互联网用户，信息消费的主战场是：

* **B 站**：技术教程、UP 主知识分享、纪录片
* **小红书**：产品评测、生活方式、学习笔记
* **抖音**：行业资讯、短知识切片（[抖音AI视频总结](https://bibigpt.co/features/ai-douyin-summary?utm_source=blog&utm_medium=inline-link&utm_campaign=try-free)）

这些平台上的内容，OpenClaw 的原生 summarize 完全触及不到。你可以让 OpenClaw 每天整理 AI 领域动态，它能搜索文章、汇总推文……但那个你订阅了 3 年的 B 站 UP 主昨天发的深度讲解视频？它只能说"这里有一条链接"。

### 核心命令速查

![]()bibi CLI 帮助信息

| 命令 | 说明 |
| --- | --- |
| `bibi summarize "<url>"` | 标准总结 |
| `bibi summarize "<url>" --chapter` | 按章节分段总结 |

bibigpt-skill vs. OpenClaw 原生 summarize：核心差异对比
----------------------------------------------

这是很多人忽略的关键问题。OpenClaw 的 ClawHub 上确实有原生的 summarize skill，但它的局限很明显：

| 能力 | OpenClaw 原生 summarize | bibigpt-skill |
| --- | --- | --- |
| YouTube | ✅ | ✅ |
| B 站 / Bilibili | ❌ 不支持 | ✅ 完整支持 |
| 小红书 | ❌ 不支持 | ✅ 完整支持 |
| 抖音 / Douyin | ❌ 不支持 | ✅ 支持 |
| 小宇宙 / 播客 | ❌ 不支持 | ✅ 支持 |
| 本地音视频文件 | ❌ 不支持 | ✅ 支持 |
| 章节分段总结 | ❌ | ✅ `--chapter` |
| 结构化 JSON 输出 | ❌ | ✅ `--json` |
| 仅获取字幕文本 | ❌ | ✅ `--subtitle` |
| 长视频异步处理 | ❌ | ✅ `--async` |
| 多语言字幕翻译 | ❌ | ✅ 自动双语对照 |

原生 summarize 本质上是一个「对网页内容调用 LLM 总结」的通用工具，无法处理需要专门解析的视频平台（B 站的 API 鉴权、小红书的内容结构、抖音的短视频格式）。

bibigpt-skill 的背后是 BibiGPT 多年深耕中文视频平台的完整管线——这正是 JimmyLv 所说的「进阶封装」：不只是调用 LLM，而是先完成平台特定的字幕抓取、转录、多语言处理，再交给 AI 生成结构化摘要。

三条实战路径：从开发者到全自动代理
-----------------

### Path 1：纯 Claude Code 路径（开发者日常工作流）

最简单的入门方式。在任何 Claude Code 会话中，直接说：

> "帮我总结这个视频，重点提取实现细节：<https://www.youtube.com/watch?v=xxxxx>"

Claude Code 会自动识别 bibigpt-skill，调用 `bibi summarize`，返回结构化摘要。

**适合场景：**

* 在代码仓库中工作时，让 Claude Code 自动总结相关技术讲座
* 研究竞品演示视频，提炼关键功能点
* 快速消化会议录屏、产品演示（参见[用 AI 从视频自动生成会议纪要](/en/blog/posts/create-meeting-minutes-from-video-ai-guide-2026)）

### Path 2：OpenClaw → Claude Code → bibigpt-skill

这是 2026 年最优雅的组合路径。OpenClaw 通过 spawn mode 调用 Claude Code，Claude Code 调用 bibigpt-skill，形成完整的视频研究代理链：

```
OpenClaw (规划/调度)
  → spawn Claude Code (执行)
    → bibigpt-skill (视频理解)
      → 输出结构化报告

```

![]()OpenClaw 与 bibigpt-skill 集成演示：B 站视频 AI 总结实战

**配置示例（OpenClaw skill 调用）：**

```
// 在 OpenClaw 中配置 Claude Code spawn
const result = await sessions_spawn({
  mode: "claude-code",
  prompt: `用 bibigpt-skill 总结以下视频，
    输出 JSON 格式包含：标题、核心论点（3-5条）、关键数据点、行动建议：
    ${videoUrl}`
})

```

**适合场景：**

* 竞品研究：自动分析竞品产品演示视频
* 学术追踪：定期总结领域顶会的演讲视频
* 内容创作：从视频中提炼素材用于写作

关于如何在内容创作场景中用 bibigpt-skill 实现 [AI 视频转文章自动化工作流](/en/blog/posts/openclaw-content-creator-bibigpt-skill-video-to-article-xiaohongshu-douyin-2026)，有专门的实战教程。

### Path 3：OpenClaw 心跳任务（全自动研究助手）

这是终极形态：**什么都不用做，AI 代理每天自动替你"看视频"**。

配置 OpenClaw 的心跳任务（每天早 8 点执行）：

1. 读取你订阅的 YouTube 频道 RSS，获取过去 24 小时新视频
2. 对每条新视频调用 `bibi summarize --json`
3. 汇总生成 Markdown 日报
4. 发送到你的 Slack 频道 / 邮箱

**真实配置的 OpenClaw prompt 示例：**

```
每天早上 8 点执行：
1. 用 web_fetch 获取以下频道的 RSS：
   - https://www.youtube.com/@AndrejKarpathy/videos
   - https://www.youtube.com/@3blue1brown/videos
2. 筛选出过去 24 小时内发布的新视频
3. 对每条视频运行：bibi summarize "<url>" --chapter --json
4. 把所有摘要汇总为 AI 日报 Markdown 格式
5. 通过 Slack skill 发送到 #ai-daily 频道

```

这个工作流的关键价值：\*\*从"信息到达你"到"你主动追踪信息"\*\*的范式转换。在信息爆炸时代，这种自动化研究助手能让你真正做到"知道发生了什么"。更多关于 YouTube 场景下的 [AI 高光笔记 + 自动研究工作流实战](/en/blog/posts/openclaw-youtube-bibigpt-skill-ai-highlight-research-workflow-2026)，可以参考系列教程。

--------------------------------------

`bibi summarize` 调用的是 BibiGPT 完整的 AI 视频处理管线。但 CLI 只是冰山一角——在 Web 和桌面端，BibiGPT 提供了从"看懂视频"到"记住知识"再到"二次创作"的完整工作流。以下每一项能力都可以与 bibigpt-skill 的 Agent 工作流形成联动。

### AI 视频对话与智能溯源——每个回答都能追溯原片

![]()AI视频对话溯源演示：可点击时间戳直接定位原始视频片段

对视频内容进行深度问答，AI 的每个回答都附带**可点击的时间戳**，鼠标悬停即可预览该信息点的视频原文，直接定位到原始视频片段。不再担心 AI 幻觉——每个信息点都有据可查。

更强大的是，对话窗口还支持：

* **AI 智能推荐 3 个相关问题**，引导你深入思考
* **基于视频截图提问**，上传图片即可获得精准回答
* **通用 AI 对话与视频问答自由切换**，一个窗口搞定所有交互

这个能力通过 `--json` 模式输出的字幕数据，已经可以在 Agent 工作流中二次利用：拿到字幕后，让 Claude Code 对字幕做深度分析、问答、信息提取——相当于给你的 AI Agent 装上了"带引用的视频理解能力"。

### AI 高光笔记——一键提取视频精华

![]()AI高光笔记演示：自动按主题分类的带时间戳高光片段

自动从视频中提取带时间戳的高光片段，AI 不仅生成高光列表，还能智能地按"核心论点"、"实操步骤"、"关键数据"等主题进行分类，方便快速筛选定位。所有高光片段点击即可跳转播放，并支持一键分享。

对于 OpenClaw 的 Path 3 自动化场景，高光笔记的结构化数据可以在 `--json` 输出中直接获取，进一步精炼到日报中——你的 AI Agent 不只是"看了视频"，而是"自动提取了重点"。

### 合集归纳总结（Collection Summary）——多视频知识图谱

研究场景的杀手锏：把一个话题的多个相关视频（如某 UP 主的技术系列、某领域的多段演讲）加入同一合集，点击「立即总结」，BibiGPT 基于**合集内所有视频**生成整体归纳综述，并附带可展开的引用来源（Citation），一键追溯到原视频位置。同时自动生成详细的思维导图，帮你一键理清系列知识脉络。

![]()合集归纳总结：一键梳理多视频知识脉络与思维导图

对于 OpenClaw 的竞品研究场景，这意味着：你可以先用心跳任务批量收集竞品演示视频到一个合集，再用合集总结一键提炼整体竞品格局——而不是一条一条手动处理。关于 B 站合集总结的完整实战教程，参见：[《B 站合集总结实战：用 bibigpt-skill 一键梳理 UP 主系列教程知识脉络》](/en/blog/posts/openclaw-bilibili-bibigpt-skill-collection-summary-chinese-learning-2026)。

### 多语言字幕翻译——打破语言壁垒

![]()上传音视频自动翻译入口

上传外语视频时，BibiGPT 支持在转录阶段自动翻译为目标语言（如英语 → 简体中文），处理完成后直接展示双语对照的字幕和总结。配合 bibigpt-skill 的 `--subtitle` 模式，你的 AI Agent 可以获取任意语言视频的双语字幕数据，再进行深度分析——这是面向多语言团队和跨境研究者的核心能力。

### 播客生成——视频变身双人对谈音频

![]()小宇宙播客生成功能截图

常见问题
----

**Q：bibigpt-skill 免费吗？**

A：bibigpt-skill 本身开源免费（MIT 协议），但使用需要有效的 BibiGPT 账号（BibiGPT 提供免费试用额度）。安装 BibiGPT 桌面端后运行 `bibi auth check` 查看当前额度。

**Q：bibigpt-skill 和 OpenClaw 原生 summarize 的本质区别是什么？**

A：OpenClaw 原生 summarize 是通用网页抓取 + LLM 总结，无法处理需要 API 鉴权的视频平台。bibigpt-skill 背后是 BibiGPT 多年深耕的专用视频处理管线：B 站 API 鉴权、小红书内容解析、抖音短视频格式、本地文件上传——这些都不是通用工具能解决的。

**Q：bibigpt-skill 和 NotebookLM 有什么不同？**

A：NotebookLM 擅长处理文档和 PDF，而 bibigpt-skill 专注于视频和音频内容，尤其在中文视频平台（B 站、小红书、抖音）上有深度集成。两者可以互补：用 bibigpt-skill 提取视频知识，用 NotebookLM 整理文档资料。

**Q：能在 Claude Desktop 或 Cursor 里用 bibigpt-skill 吗？**

A：bibigpt-skill 是标准 Claude Code skill，目前最佳体验在 Claude Code CLI 中。Claude Desktop 暂不支持自定义 skills；Cursor 可通过 Claude Code MCP 间接调用。

**Q：bibigpt-skill 支持哪些平台？**

A：B 站（Bilibili）、YouTube、小红书、抖音（Douyin）、小宇宙（播客）、喜马拉雅，以及本地 mp3/mp4/m4a/mov 文件。完整列表见 [BibiGPT 全部功能](https://bibigpt.co/features)。

**Q：视频很长（2小时+）怎么办？**

A：使用 `--async` 模式：`bibi summarize "<url>" --async`。系统会在后台处理并返回任务 ID，长视频一般 3-5 分钟内完成。

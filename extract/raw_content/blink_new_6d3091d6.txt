## [What Is in the OpenClaw 2026.3.28 Update?](https://blink.new/blog/openclaw-2026-3-28-whats-new-update-guide\#what-is-in-the-openclaw-2026328-update)
OpenClaw 2026.3.28 (March 28) is a full platform drop, not a cosmetic bump: \*\*45\*\* new features, \*\*13\*\* breaking changes, and \*\*82\*\* bug fixes ship together, so release notes and migration guidance deserve a scheduled read before you flip traffic.
\*\*Plug-in approval hook.\*\* Operators gain an explicit gate before new or updated plug-ins execute in sensitive contexts. You define policy at the hook: approve, deny, or route through a human or automation step. That control layer shrinks the blast radius when a supply-chain package, mislabeled skill, or overly powerful extension reaches your agent host—especially relevant if you sync skills from community paths. Pair this hook with the hygiene patterns in [Is OpenClaw safe? A ClawHub malware guide for 2026](https://blink.new/blog/%5BREDACTED%5D/blog/is-openclaw-safe-clawhub-malware-guide-2026) so approvals rest on provenance checks, not gut feel.
\*\*xAI Responses API plus Grok `x\_search`.\*\* Agents now call xAI's Responses API with Grok models and can issue `x\_search` backed lookups when your workflow needs fresh web signal instead of stale training cutoffs. Use this stack for research-heavy automations—incident summaries, competitive scans, policy monitoring—where latency and citation-style answers beat a single completion without tools.
\*\*Discord and iMessage ACP channels.\*\* Apple Continuity Platform (ACP) style wiring lands for Discord and iMessage, expanding where your gateway receives and sends agent traffic without bolting on unofficial bridges. Teams that already standardize on those surfaces get first-class paths to route prompts, approvals, and alerts into the same OpenClaw session graph you run for Slack or Telegram.
\*\*Scale context.\*\* OpenClaw sits at \*\*247,000+\*\* GitHub stars—signal that regressions and breaking changes receive fast scrutiny. Plan for the \*\*13\*\* breaking changes: diff `openclaw.json`, gateway auth profiles, and channel tokens against the official migration notes before you declare the upgrade done.
## [What Critical Security Vulnerabilities Were Patched in 2026.3.28?](https://blink.new/blog/openclaw-2026-3-28-whats-new-update-guide\#what-critical-security-vulnerabilities-were-patched-in-2026328)
A PSA trending on r/selfhosted captures the tone serious operators already adopted: \*\*"Update OpenClaw to 2026.3.28 now — Critical privilege escalation and sandbox file read patched."\*\* Treat Reddit as an alarm bell, then verify details in OpenClaw's GitHub releases and Security Advisories—those sources own CVE identifiers, affected tags, and exact fixed revisions.
\*\*Privilege escalation (patched in 2026.3.28).\*\* In vulnerable builds, an attacker who already influences agent inputs or plug-in loading paths edges toward executing actions with more privilege than the sandbox and role model intend—think host-level side effects or cross-tenant bleed on shared infra. The 2026.3.28 line draws a hard boundary again: upgrade every runtime that executes untrusted or semi-trusted code.
\*\*Sandbox file read (patched in 2026.3.28).\*\* A flawed sandbox read path exposes files the agent must never see—SSH keys, `.env` dumps, private prompts, customer attachments—straight into model context or exfiltration channels. The patch removes that read primitive; staying on a pre-2026.3.28 tag keeps the hole open.
\*\*Action item.\*\* Move production gateways, workers, and CI sandboxes to \*\*2026.3.28 or newer\*\* before you prioritize feature work. If you need a structured review cadence, walk the controls in the [security audit checklist](https://blink.new/blog/%5BREDACTED%5D/blog/openclaw-security-audit-checklist-2026) immediately after you deploy the new image.
## [What New Features Shipped in the 2026.3.31 Release?](https://blink.new/blog/openclaw-2026-3-28-whats-new-update-guide\#what-new-features-shipped-in-the-2026331-release)
Tag \*\*2026.3.31\*\* published \*\*April 1\*\*—calendar date, not an April Fools drop—extends the March security baseline with operator-facing channel and media upgrades.
\*\*QQ bot bundle.\*\* APAC teams and cross-border support desks pick up a packaged QQ integration instead of stitching unofficial bots. "Bundle" here means dependencies, defaults, and channel wiring ship together so your gateway configuration stays coherent across regions.
\*\*LINE Media.\*\* LINE stops being text-only in practice: richer media handling lands for the channel, which matters for OCR-heavy tickets, receipt photos, and mixed-language threads common in Japan, Thailand, and Taiwan.
\*\*Background Task Flows.\*\* Long-running jobs—queued summarization, large file ingestion, multi-step approvals—gain a durability story that keeps state out of fragile one-shot completions. Operators see fewer dropped tasks when laptops sleep or containers restart mid-run.
\*\*CJK TTS upgrades.\*\* Japanese, Chinese, and Korean text-to-speech paths receive quality and locale coverage improvements, tightening voice responses for agents that serve multilingual customers without forcing English fallbacks.
## [How Do You Update OpenClaw to the Latest Version?](https://blink.new/blog/openclaw-2026-3-28-whats-new-update-guide\#how-do-you-update-openclaw-to-the-latest-version)
\*\*Docker path (most common).\*\* Pull the current image, recycle the stack, and verify health checks:
```
docker pull openclaw/openclaw:latest && docker-compose down && docker-compose up -d
```
Budget \*\*30–60 minutes\*\* per self-hosted upgrade once you count image pulls, compose churn, smoke tests, and channel reconnects—not just the shell command.
\*\*Pre-flight checklist.\*\*
1. Snapshot volumes that hold workspace files, SQLite or local stores, and uploaded media.
2. Export `openclaw.json`, gateway tokens, and connector secrets from your secret manager—never rely on a single disk copy.
3. Read the \*\*13\*\* breaking changes for 2026.3.28; grep your repo for deprecated flags before restart.
4. Stage a canary host or namespace if you run multiple agents; promote traffic after gateway and plug-in hooks pass tests.
\*\*Post-flight verification.\*\* Open the gateway UI or WS client, send a probe message on each channel (Slack, Discord, iMessage ACP, etc.), run one plug-in workflow under the new approval hook, and confirm logs show the \*\*2026.3.28\*\* or \*\*2026.3.31\*\* build string.
\*\*Non-Docker paths.\*\* Bare-metal and cloud-VM installs follow the same discipline: sync to the tagged release, rebuild binaries or pull OCI artifacts, restart systemd units, validate ports. For cloud-only installs without local Docker, follow [How to run OpenClaw without Docker in the cloud (2026)](https://blink.new/blog/%5BREDACTED%5D/blog/how-to-run-openclaw-without-docker-cloud-2026) so parity checks match your hosting model.

## [What Should You Do If You Can't Update Immediately?](https://blink.new/blog/openclaw-2026-3-28-whats-new-update-guide\#what-should-you-do-if-you-cant-update-immediately)
Deferral is expensive when privilege escalation and sandbox file read issues apply to your deployment topology. If a hard stop blocks the upgrade today, execute compensating controls now, not tomorrow:
- Block untrusted plug-ins and third-party skills at the network and filesystem layer until 2026.3.28 is live.
- Remove gateway admin interfaces from the public internet; force VPN or identity-aware proxy paths.
- Rotate secrets that ever sat on hosts reachable by agent sandboxes pre-patch.
- Schedule the maintenance window within \*\*24 hours\*\* and run the `docker pull … && docker-compose down && docker-compose up -d` sequence in staging first.
This triage does not replace the patch—it buys calendar space while you drive the real fix.

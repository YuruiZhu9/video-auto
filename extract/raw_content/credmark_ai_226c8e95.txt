## 13.Explain user-based collaborative filtering and implement it using cosine similarity.
MediumCollaborative Filtering
In user-based collaborative filtering, we recommend items to a user based on what similar users liked. We compute similarity between users (often with cosine similarity) and then predict scores by taking a weighted average of neighbor ratings.
Steps:
\* Build a user-item rating matrix.
\* Compute cosine similarity between the target user and all others.
\* Pick top-K similar users.
\* Predict a user’s rating for an item by summing neighbors’ ratings weighted by their similarity, normalized by the sum of similarities.
This approach captures shared tastes across users.
python
```
from sklearn.metrics.pairwise import cosine\_similarity
import numpy as np
# sample ratings: rows are users, cols are items, 0 means no ratingratings = np.array([[5,3,0,1],[4,0,0,1],[1,1,0,5],[1,0,0,4],[0,1,5,4],])# compute user-user cosine similarityuser\_sim = cosine\_similarity(ratings)# shape (5,5)defpredict\_rating(user\_idx, item\_idx, k=2): sims = user\_sim[user\_idx]# all similarities to target ratings\_col = ratings[:, item\_idx]# all users' ratings for item# pick top k neighbors with ratings neighbors = np.argsort(sims \*(ratings\_col>0))[-k:] num = np.dot(sims[neighbors], ratings\_col[neighbors]) den = np.sum(np.abs(sims[neighbors]))return num/den if den else0# predicted ratingprint(predict\_rating(0,2))# prints predicted rating for user 0, item 2
```
\*\*Mistake to avoid:\*\* "I’ll use all users when computing predictions without filtering zeros."
Only include neighbors who actually rated the item when summing, as shown by masking `ratings\_col>0`.

## 16.Explain matrix factorization with SGD and code a simple SVD-based recommender.
MediumAlgorithms
Matrix factorization models decompose the user-item matrix R into two lower-rank matrices, P (users×factors) and Q (items×factors). We minimize the squared error on known ratings using stochastic gradient descent. After training, predicted ratings are the dot product P�Qᵀ.
Loss = Σ (rᵤᵢ - pᵤ·qᵢ)² + λ(∥pᵤ∥²+∥qᵢ∥²)
SGD iterates over observed ratings, updates pᵤ and qᵢ by taking a step opposite the gradient.
python
```
import numpy as np
deftrain\_sgd(R, num\_factors=2, lr=0.01, reg=0.1, iters=1000): num\_users, num\_items = R.shape
P = np.random.rand(num\_users, num\_factors) Q = np.random.rand(num\_items, num\_factors)# get observed entries observed =[(u,i,R[u,i])for u inrange(num\_users)for i inrange(num\_items)if R[u,i]>0]for \_ inrange(iters): np.random.shuffle(observed)for u,i,r in observed: pred = P[u].dot(Q[i]) err = r - pred
# gradient updates P[u]+= lr\*(err\*Q[i]- reg\*P[u]) Q[i]+= lr\*(err\*P[u]- reg\*Q[i])return P, Q
# sample ratingsR = np.array([[5,0,3],[4,0,0],[1,1,0]])P, Q = train\_sgd(R)print(P.dot(Q.T))# prints full rating matrix approx
```
\*\*Mistake to avoid:\*\* "I’ll train on zeros as if they’re real ratings."
Only include observed (non-zero) entries in your SGD loop, as shown.
Companies ask this question because they want to see you can build a scalable, latent-factor recommender from scratch.

## 20.What’s approximate nearest neighbor search and show a simple LSH-based lookup snippet.
MediumAlgorithms
Brute-force nearest neighbor is O(n) per query, too slow at scale. Locality Sensitive Hashing (LSH) hashes vectors so that similar ones land in the same bucket with high probability. You only search inside those buckets.
Key idea:
\* Hash with random hyperplanes for cosine LSH.
\* Store item IDs in buckets.
\* At query time, hash the query and only compare with items in matching buckets.
python
```
import random
import numpy as np
# random hyperplanesdims, num\_planes =5,3planes =[np.random.randn(dims)for \_ inrange(num\_planes)]defhash\_vec(v):# each bit is sign of projectionreturntuple(int(np.dot(v,p)>0)for p in planes)# index itemsvectors ={i: np.random.rand(dims)for i inrange(100)}buckets ={}for i,v in vectors.items(): h = hash\_vec(v) buckets.setdefault(h,[]).append(i)# queryquery = np.random.rand(dims)hq = hash\_vec(query)candidates = buckets.get(hq,[])# only theseprint(candidates)
```
\*\*Mistake to avoid:\*\* "I’ll use too few hash tables and expect perfect recall."
Use multiple independent LSH tables and merge candidate lists.

## 21.Explain NDCG and compute it for a small example.
MediumEvaluation Metrics
Normalized Discounted Cumulative Gain (NDCG) scores ranked lists by giving higher-position hits more credit, and then normalizing by the ideal ordering.
DCG@K = Σ (2^{rel\\_i} −1) / log₂(i+1)
IDCG@K is DCG@K on the perfect sort.
NDCG = DCG/IDCG.
It balances relevance and position nicely.
python
```
import math
rels =[3,2,3,0,1]# relevance scores for ranked itemsdefdcg(rels, k):returnsum((2\*\*rels[i]-1)/math.log2(i+2)for i inrange(k))defndcg(rels, k): ideal =sorted(rels, reverse=True)return dcg(rels, k)/dcg(ideal, k)print(ndcg(rels,5))# prints NDCG@5
```
\*\*Mistake to avoid:\*\* "I’ll forget to normalize by the ideal DCG."
Always divide by IDCG@K so scores range 0–1.

## 22.Explain how matrix factorization works for collaborative filtering and implement a basic version using singular value decomposition (SVD).
AdvancedAlgorithms
Think of matrix factorization like finding two smaller maps that multiply back to your big user-item matrix. One map shows users in a latent factor space, the other shows items in the same space. Multiplying them gives predicted ratings.
In practice, you start with your user–item rating matrix R (with missing entries). You decompose R ≈ U Σ Vᵀ, where U and V are low-rank factor matrices and Σ holds singular values. You can then reconstruct only observed entries or predict new ones by multiplying U, Σ, and Vᵀ.
python
```
import numpy as np
# sample user-item matrix (0 means missing)R = np.array([[5,3,0,1],[4,0,0,1],[1,1,0,5],[1,0,0,4],[0,1,5,4]])# fill missing with the mean of observed entriesmask = R !=0mean\_rating = R[mask].mean()R\_filled = np.where(mask, R, mean\_rating)# compute SVDU, S, VT = np.linalg.svd(R\_filled, full\_matrices=False)# pick k latent factorsk =2U\_k = U[:,:k]S\_k = np.diag(S[:k])V\_k = VT[:k,:]# reconstructR\_pred = U\_k @ S\_k @ V\_k
print(R\_pred)# low-rank approximation of the original ratings
```
\*\*Mistake to avoid:\*\* "I’ll fill missing ratings with zeros and directly apply SVD."
Impute the mean or use optimization methods (e.g., ALS) that only train on observed entries.

## 23.Describe how you’d handle implicit feedback data (clicks, views) using alternating least squares (ALS).
AdvancedCollaborative Filtering
Implicit feedback is trickier because absence of interaction doesn’t mean dislike. You model confidence: high if user clicked/viewed an item often.
With ALS for implicit data, you set up a confidence matrix C = 1 + α R, where R holds interaction counts. The objective minimizes ∑₍u,i₎ Cᵤᵢ (pᵤᵢ − Uᵤ•Vᵢ•)² + λ(‖U‖² + ‖V‖²), where p=1 if R>0 else 0. You alternate solving for U then V via regularized least squares.
python
```
import numpy as np
from numpy.linalg import solve
# assume R is interaction count matrixR = np.array([[3,0,1],[0,2,0],[1,0,0]], dtype=float)alpha, reg, k =40,0.1,2num\_users, num\_items = R.shape
# binary preferenceP =(R >0).astype(float)C =1+ alpha \* R
# initialize latent factorsU = np.random.rand(num\_users, k)V = np.random.rand(num\_items, k)# ALS stepsfor \_ inrange(5):for u inrange(num\_users): Cu = np.diag(C[u]) A = V.T @ Cu @ V + reg \* np.eye(k) b = V.T @ (Cu @ P[u]) U[u]= solve(A, b)for i inrange(num\_items): Ci = np.diag(C[:, i]) A = U.T @ Ci @ U + reg \* np.eye(k) b = U.T @ (Ci @ P[:, i]) V[i]= solve(A, b)print(U @ V.T)# predicted preference scores
```
\*\*Mistake to avoid:\*\* "I'll treat no-click as negative feedback and train directly on zeros."
Use a confidence-weighted loss (ALS for implicit) or sample negatives carefully.
Companies ask this question because implicit feedback is far more common in production, and they need you to know how to convert signals into a model that learns effectively.

## 24.How do you evaluate a recommendation system? Explain precision@K and NDCG@K.
AdvancedEvaluation Metrics
Precision@K asks, "Of the top K items recommended, how many were actually relevant?" It’s hit rate divided by K. NDCG@K accounts for position: getting a relevant item at rank 1 matters more than rank 10. It uses discounted cumulative gain (DCG) and normalizes by the ideal DCG so you get a score between 0 and 1.
In formulas:
\* Precision@K = (1/K) ∑\\_{i=1}^K relᵢ
\* DCG@K = ∑\\_{i=1}^K (2^{relᵢ}−1) / log₂(i+1)
\* IDCG@K is the max DCG you could get if you ranked perfectly.
\* NDCG@K = DCG@K / IDCG@K
Precision@K is easy and interpretable. NDCG@K gives you more nuance when you care about ranking quality at the top.
python
```
import numpy as np
defprecision\_at\_k(true\_items, pred\_items, k): hits =len(set(pred\_items[:k])&set(true\_items))return hits / k # fraction of top-k that are relevantdefndcg\_at\_k(true\_items, pred\_items, k): dcg =0.0for i, item inenumerate(pred\_items[:k]):if item in true\_items: dcg +=1/ np.log2(i+2)# ideal DCG: all top k are relevant idcg =sum(1/np.log2(i+2)for i inrange(min(len(true\_items), k)))return dcg / idcg if idcg >0else0.0# exampleground\_truth =[101,102,103]pred =[102,201,101,104]print(precision\_at\_k(ground\_truth, pred,3))# prints 0.666...print(ndcg\_at\_k(ground\_truth, pred,3))# prints ~0.765
```

Adopt ranking metrics like precision@K or NDCG@K that reflect real-world targets.

## 26.Describe how you’d implement an explore/exploit strategy using a multi-armed bandit for recommendations.
AdvancedEmerging Technologies
Think of each candidate item as an "arm". You want to pull arms to learn their click rates but also show your best guesses. The classic Balance is UCB (Upper Confidence Bound): you pick the item maximizing (\hat p\\_i + c\sqrt{\frac{\ln t}{n\\_i}}), where (\hat p\\_i) is observed success rate, nᵢ how often you showed it, t is total trials, and c controls exploration.
This way, rarely-shown items get big confidence bonuses. Over time you converge to good items but still try others occasionally.
python
```
import math
import random
# simulate 3 arms with unknown success ratestrue\_rates =[0.1,0.3,0.5]counts =[0,0,0]successes =[0,0,0]defucb1(t): ucb\_scores =[]for i inrange(len(true\_rates)):if counts[i]==0: ucb\_scores.append(float('inf'))else: avg = successes[i]/counts[i] bonus = math.sqrt(2\*math.log(t)/counts[i]) ucb\_scores.append(avg + bonus)return ucb\_scores
# run bandit for T stepsfor t inrange(1,101): scores = ucb1(t) choice = scores.index(max(scores)) counts[choice]+=1# simulate clickif random.random()< true\_rates[choice]: successes[choice]+=1print(counts, successes)# more pulls for the best arm
```
\*\*Mistake to avoid:\*\* "I’ll use epsilon-greedy with a fixed epsilon forever."
Use decaying epsilon or UCB/Thompson Sampling to balance exploration adaptively.

## 28.How would you build a session-based recommender (e.g., for shopping carts) using an RNN or transformer?
AdvancedMachine Learning Techniques
Session-based means you only see the current session clicks or views—no persistent user ID. You can feed the sequence of item IDs into an RNN (like GRU) or a transformer, embed each item, and predict the next item at each step.
You train it with sequences: Input (i₁, i₂,…,iₜ) predicts iₜ₊₁. The model learns transitions in sessions. At inference, you pass the live session up to now and sample top recommendations from the output distribution.
python

## 31.What are Factorization Machines and how do they help with sparse features?

## 32.How do you ensure diversity and fairness in recommendations?

Diversity: you don’t want all top results to be the same genre or popular items. A simple way is Maximal Marginal Relevance (MMR): you re-rank candidates by blending relevance and novelty to earlier picks.
Fairness: you define protected groups and impose constraints or regularize so each group gets fair exposure. For example, add a penalty when the distribution deviates from a desired ratio.
Both often become a post-processing step after scoring.

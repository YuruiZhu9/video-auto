This section demonstrates Qwen3-VL's video analysis capabilities, including temporal event localization, text-timestamp alignment, hour-long video processing, and frame-level indexing. The model natively supports up to 256K context length (expandable to 1M), enabling comprehensive understanding of extended video content with second-level temporal precision.

For video preprocessing utilities, see [Vision Processing Pipeline](/QwenLM/Qwen3-VL/4.1-vision-processing-pipeline). For model loading and inference setup, see [Model Loading and Inference](/QwenLM/Qwen3-VL/4.3-model-loading-and-inference).

Video Input Methods
-------------------

Qwen3-VL supports multiple video input formats for flexible integration into different workflows:

**Video Input Format Options**

| Input Type | Description | Use Case | Example |
| --- | --- | --- | --- |
| Video URL | HTTP/HTTPS URL to video file | Remote video analysis | `https://example.com/video.mp4` |
| Local Path | File system path to video | Local video processing | `file:///path/to/video.mp4` |
| Frame List | Pre-extracted frame sequence | Fine-grained control | `[frame1.jpg, frame2.jpg, ...]` |
| Video Tensor | Processed video data | Advanced preprocessing | `torch.Tensor` with video data |

Frame Sampling and Resolution Control
-------------------------------------

Video processing uses intelligent frame sampling to balance temporal coverage with computational efficiency. The `qwen-vl-utils` package provides controls for frame extraction and resolution management.

### Frame Sampling Parameters

| Parameter | Function | Default | Effect |
| --- | --- | --- | --- |
| `fps` | Frames per second sampling rate | 2.0 | Controls temporal resolution |
| `num_frames` | Fixed number of frames | None | Overrides fps when set |
| `min_pixels` | Minimum pixels per frame | 4 × 32 × 32 | Lower resolution bound |
| `max_pixels` | Maximum pixels per frame | 256 × 32 × 32 | Upper resolution bound |
| `total_pixels` | Total pixels across all frames | 20480 × 32 × 32 | Overall token budget |

Hour-Long Video Processing
--------------------------

Qwen3-VL's native 256K context length (expandable to 1M) enables processing of hour-long videos with full recall and frame-level indexing. This allows comprehensive analysis of extended content without summarization or chunking.

**Context Length Configuration**

To process videos longer than the default 256K tokens, enable YaRN (Yet another RoPE extensioN):

**vLLM Server Configuration for Extended Context**

**Important**: Because Interleaved-MRoPE's position IDs grow more slowly than vanilla RoPE, use a **smaller scaling factor**. For 1M context with 256K base length, set `factor=2` or `3`, not `4`.

### Hour-Long Video Example

**Long Video Processing Strategies**

| Video Length | Recommended fps | Token Budget | Notes |
| --- | --- | --- | --- |
| 0-5 minutes | 2-4 fps | 256-16384 tokens | Standard processing |
| 5-30 minutes | 1-2 fps | 4096-20480 tokens | Reduce temporal resolution |
| 30-60 minutes | 0.5-1 fps | 8192-20480 tokens | Focus on key frames |
| 1+ hours | 0.25-0.5 fps | Up to 24576 tokens | Extended context + low fps |

Usage Patterns and Integration
------------------------------

Video understanding integrates with the standard Qwen3-VL inference pipeline through the same conversation interface used for images. The key difference is in the preprocessing stage where videos are converted to frame sequences.

### Basic Video Processing Flow

1. **Video Input**: Provide video file path or URL through conversation interface
2. **Frame Extraction**: `fetch_video` processes the video and extracts frames
3. **Preprocessing**: Frames undergo `smart_resize` and normalization
4. **Token Generation**: Vision tokens are created for each frame
5. **Context Integration**: Temporal sequence is integrated into conversation context
6. **Model Inference**: Standard `AutoModelForImageTextToText` processing
7. **Response Generation**: Text response with temporal understanding

### Performance Considerations

Video processing requires additional computational resources compared to static images:

* **Memory Usage**: Multiple frames increase memory requirements
* **Processing Time**: Frame extraction and encoding add latency
* **Token Limits**: Longer videos may exceed context length limits
* **Sampling Strategy**: Frame selection impacts both performance and accuracy

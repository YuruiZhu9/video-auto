没有 Claude Code 的 OpenClaw：2026 年最佳替代 Harness
============================================

Anthropic 宣布 Claude 订阅将不再覆盖在 OpenClaw 等第三方工具上的使用。以下是这意味着什么，以及你有哪些替代方案。

撰写者[![]()LobeHubOfficial Account](https://github.com/lobehub)

刚刚发生了什么
-------

从 2026 年 4 月 5 日起，Anthropic 的 Claude 订阅计划不再覆盖在 OpenClaw 等第三方工具上的使用。

如果你一直使用 Claude 登录在 OpenClaw 中使用服务，那么这部分访问现在会被 “额外用量包（extra usage bundles）” 付费墙拦住。或者，你需要提供自己的 Claude API key。

这不是技术故障，而是一次有意的政策调整。

---

OpenClaw 除了 API 访问之外还失去了什么
--------------------------

订阅变化是最显眼的标题，但下面还有一个更隐蔽的问题。

OpenClaw 之前主要依赖 **Claude Code** —— Anthropic 自家的 Agent 基础设施 —— 作为执行任务、tool-calling 与多步骤工作流的主要 harness。而现在，这也属于需要额外付费的部分之一。

OpenClaw 自己也有一个 harness 作为备用方案，但它并不是主角。那些依赖 OpenClaw 完整 agentic 能力的用户，现在要么付更多钱，要么得到更少能力。

---

你现在的选择
------

### 1. 从 Anthropic 购买额外用量包

Anthropic 在过渡期提供折扣。这样可以保持你现有的工作流不变 —— 但需要增加成本。

### 2. 切换为使用 Claude API key

把你的客户端配置为直接使用你自己的 API key。用量将由 Anthropic 按量计费（pay-as-you-go）。大多数第三方客户端都支持这一点，包括 OpenClaw。

### 3. 切换到从一开始就不依赖这些机制的客户端

有些客户端从第一天起就不依赖 Anthropic 的订阅透传（subscription passthrough）或 Anthropic 原生的 Agent 基础设施。它们从未受到这次变化影响，因为它们本来就不需要这些。

---

------------------

这意味着两点：

**没有政策风险。** 当 Anthropic 改变 Claude 订阅覆盖范围时，LobeHub 用户不会有任何感知，因为根本没有 “会失去访问权限” 的东西。

**没有模型锁定。** LobeHub 的 harness 可与 Claude、GPT-5、Gemini 等一起工作。你可以在不损失能力的情况下切换模型。无论底层是哪种 LLM，Agent 层都保持一致。

当政策变化时，工作质量不会下降，因为能力从来不是租来的。

结论
--

OpenClaw 的处境暴露了两个叠加风险：依赖订阅透传来获得访问权限，以及依赖提供商的原生基础设施来获得能力。其中任何一项发生变化，都会带来伤害；两项同时变化，影响更大。

OpenAI和Anthropic世纪联手！codex-plugin-cc震动AI圈，两大巨头开放王炸产品
====================================================

![]()[鲸选AI](https://news.qq.com/omn/author/8QMX3H9c6IMZvTc%3D)

2026-03-31 10:15发布于北京

问AI · OpenAI为何主动将工具送入竞争对手生态？

**【导读】**AI 圈炸了。OpenAI 官方发布了一个 Claude Code 插件 codex-plugin-cc，让开发者可以直接在 Claude Code 里调用 Codex。这是 OpenAI 首次主动把自家工具送进竞争对手的地盘，背后是 Claude Code 年收入 25 亿美元、占据 46% 开发者市场的残酷现实。

---

还记得今年印度 AI 峰会上，OpenAI 的 Sam Altman 和 Anthropic 的 Dario Amodei 在台上一起联手欢呼，两个人却并没有实际接触的照片吗？

![]()

两位曾经的 OpenAI 创业合伙人，因为理念分歧分道扬镳后，此后极度避免公开同框，即使遇到也要刻意避嫌。

但 3 月 30 日，发生了一件很意外的事。

OpenAI 官方 GitHub 仓库里悄悄上线了一个插件，名字叫 **codex-plugin-cc**。功能只有一句话：**让 Claude Code 用户可以直接在 Claude Code 里，调用 OpenAI 的 Codex**。

这不是民间开发者的野路子，而是 OpenAI 官方出品。这意味着，OpenAI 主动把自己的编程工具送进了竞争对手 Anthropic 的地盘，让两个原本针锋相对的 AI 编程助手，第一次在同一个工作流里“握手言和”。

AI 圈从来没见过这种操作。这不是合作，更像是 OpenAI 的一次“战略投降”。

codex-plugin-cc：三大核心能力，让两个 AI 互相配合
----------------------------------

说白了，这个插件就是让你在 Claude Code 里随时能叫 Codex 过来帮忙。OpenAI 官方文档和推特用户 @reach\_vb（Vaibhav Srivastav）详细介绍了三个核心命令。

第一个是 `/codex: review`，标准代码审查。

你在 Claude Code 里写完代码，输入这个命令，Codex 就会像个资深工程师一样，把你的代码从头到尾过一遍。它支持分支对比，可以后台运行，而且只看不改，纯粹给建议。比如你刚完成一个功能模块，想要一个“第二双眼睛”来检查潜在问题，或者准备提交 PR 前快速过一遍代码质量，这个功能就很实用。

第二个是 `/codex: adversarial-review`，对抗性审查。这个功能最有意思，它不是简单地找 bug，而是主动挑战你的实现思路。Vaibhav Srivastav 特别强调，这个功能专门用来“挑战现有实现的隐藏假设”。它会问一些尖锐的问题，比如“为什么选择这个架构？有没有更简单的方案？”“这个实现在边界情况下会不会出问题？”适合那些高风险操作，像数据库迁移、权限系统变更、基础设施脚本这些不能出错的场景。

举个例子，你在迁移生产环境数据库，可以用这个命令让 Codex 挑战你的迁移脚本：`/codex: adversarial-review --base prod "challenge the rollback strategy"`。它可能会指出你没考虑到的边界情况，比如迁移过程中网络中断怎么办，回滚时如何处理已经写入新库的数据。

第三个是 `/codex: rescue`，任务移交。

这是最强大的功能。当你在 Claude Code 里卡住了，或者觉得当前的思路不对，直接用这个命令把整个任务扔给 Codex 接管。它支持后台运行，可以继续之前的任务，也可以重新开始。比如 `codex: rescue "refactor the payment service to use the new API"` 或者 `/codex: rescue --background "run the full test suite and fix any failures"`。

配套还有几个辅助命令：`/codex: status`查看任务进度，`/codex: result` 获取完成结果（包含 session ID，可以直接在 Codex 里继续），`/codex: cancel`取消后台任务。

还有一个高级功能叫 **review gate**，启用后每次 Claude Code 给出回复，插件会自动调用 Codex 做审查。如果 Codex 发现问题，Claude Code 就不会退出，强制你先解决。听起来很酷炫，但 Vaibhav Srivastav 警告说：这可能导致两个智能体循环调用，快速烧掉你的使用额度。所以要谨慎使用。

这背后的战略意义：不是示弱，是抢占分发渠道
---------------------

其实在 OpenAI 官方出手之前，开发者社区早就在做类似的事情了。

鲸哥了解到很多项目都在尝试搭建“桥梁”，让不同的 AI 工具互相配合。Michael Guo 专门做了一个 GitHub 项目叫 “claude-codex-bridge”，用于双向 AI 代码比较。Tristan Lee 也提到刚折腾完项目 smux。这些民间项目证明了一件事：开发者们早就不满足于单一工具，他们需要多 AI 协作。

技术细节之外，更值得关注的是战略层面的意义。开发者 Hua Ming 在推特上一针见血地指出：“把 Codex 塞进 Claude Code 等于承认了 distribution 策略的重要性。plugin 生态的赢家从来不是功能最强的，是嵌入最深的。下一步大概率是各家 Agent 在 IDE 里互相调用成常态。”

这个观点太精准了。OpenAI 这次不是在示弱，而是在抢占分发渠道。与其眼睁睁看着 41% 的开发者完全不碰 Codex，不如主动送个插件过去，至少还能分一杯羹。用户习惯在哪，你就去哪。

有开发者在推特上打了个很形象的比方：“两个 Agent 互相 review 代码，这个画面像极了产品经理和开发互相挑刺，只不过这次两边都是AI ，甩锅效率提升了100倍。”这话虽然是调侃，但确实说出了多 AI 协作的本质——不同的 AI 有不同的强项，让它们互相制衡、互相补充，反而能得到更好的结果。

但也存在一些问题，虽然产出更高了，但是Token消耗也将更加惊人，用户对两大AI的订阅都不得不调向更高档。

真实场景：这个插件到底怎么用？
---------------

Callstack 团队在 3 月 27 日发布了两个 Codex 插件，专门用于 React Native 开发。他们的工作流很典型：先在 Claude Code 里用自然语言描述功能需求，Claude Code 生成初版代码，然后用 `/codex: review` 让 Codex 检查 React Native 特有的性能陷阱，再用 `/codex: adversarial-review` 挑战组件架构设计，最后用 Codex 的测试插件跑一遍自动化测试。

这种“Claude Code 写代码 + Codex 审查”的组合，让他们的开发效率提升了 30% 以上。

OpenAI 官方文档里还提到一个很实用的场景：**无障碍功能审查**。你可以直接输入 `/codex: review "Focus on accessibility regressions"`，Codex 会专门检查 ARIA 标签是否正确、键盘导航是否完整、屏幕阅读器兼容性、色彩对比度是否符合 WCAG 标准。这种定制化审查，比通用的代码检查工具精准得多。

还有一个高级用法很有意思：**让 Codex 做评分改进循环**。比如你要生成一个高质量的数据可视化图表，可以让 Codex 不断迭代，直到评分达到 90% 以上。它会自动生成初版、打分、分析哪里不够好、改进、重新生成，一直重复到达标。这种“AI 自我迭代优化”的能力，是传统编程工具完全做不到的。

Claude Code 为什么能赢？
------------------

OpenAI 为什么会做出这个看起来“屈辱”的决定？看看市场数据就明白了。

Claude Code 在 2026 年初的年收入达到了 25 亿美元，占 Anthropic 总收入的 13%。更夸张的是，从 0 到 10 亿美元，Claude Code 只用了 6 个月，这是 AI 编程工具史上最快的增长速度。每月有 176.12 万访问量，移动端 MAU 达到 738 万。

开发者市场更能说明问题。VS Code 市场数据显示，Claude Code 拿到了 46% 的“最受喜爱”评分。DEV.to 的调查显示，41% 的专业开发者在使用 Claude Code，在 200 人以下的公司，这个数字飙升到 75%。GitHub 上约 4% 的公开提交都是 Claude Code 生成的。企业市场方面，Claude Code 已经服务超过 30 万企业客户，企业用户贡献了收入的一半以上。Anthropic 在 2026 年新签的企业订单中，70% 选择了 Claude 而非 OpenAI。

而且 Claude Code 的产品迭代速度也很快。就在 3 月 25 日，Anthropic 刚刚发布了 **auto mode（自动模式）**，现在已经对企业计划和 API 用户开放。更新安装后运行 `claude --enable-auto-mode`，Claude 就可以代替你做权限决策，不用每次都等你批准。当然，安全保障措施会在执行任何操作之前进行检查。

更厉害的是 **computer use（电脑使用）** 功能，现在已经集成到 Claude Code 里了。Claude 可以直接打开你的应用程序、点击界面、测试你刚构建的内容，全程在命令行里完成。这个功能目前在 Pro 和 Max 计划中作为研究预览版提供。更多Claude产品更新请看文章52天73次产品级更新，个个爆款太神了，AI原生组织的进化恐怖如斯

这两个新功能的推出，让 Claude Code 不只是一个代码生成工具，而是一个真正能“自主工作”的 AI 助手。相比之下，Codex 虽然有 200 万周活用户，但市场占有率不到 20%。起步价 200 美元/月，是 Claude Code（100 美元/月）的两倍。在开发者社区的讨论热度也远低于 Claude Code。ZDNet 的资深编辑 David Gewirtz 说得很直白：“我接触的每个程序员都在用 Claude Code。”

更能说明用户忠诚度的是这个细节：Anthropic 在 3 月 26 日遇到了一次使用限额 bug，导致部分用户的 5 小时额度在 10% 的时间内就烧完了。但开发者社区的反应不是“我要换回 Codex”，而是“希望 Anthropic 赶紧修复”。用户忠诚度已经形成了。

如果说 Claude Code 只是在编程领域挑战 Codex，那 Claude Cowork 就是在更广阔的战场上发起总攻。

Claude Cowork 在 1 月 30 日发布 Mac 版、2 月发布 Windows 版后，直接触发了 2850 亿美元的企业软件股抛售。为什么？因为它能做的事情太多了。自动化办公能整理邮件、生成报告、制作 PPT，数据分析能从 Excel 里提取数据、生成可视化图表，项目管理能跟踪任务进度、自动发送提醒，财务处理能处理发票、生成财务报表，市场营销能撰写文案、分析竞品、生成营销方案。这些原本需要专门软件的功能，现在一个 AI 就能搞定。难怪投资人要重新定价那些企业软件公司。

尤其3 月 9 日，微软宣布推出 Copilot Cowork，底层技术来自 Anthropic 的 Claude Cowork。要知道，微软在 OpenAI 身上砸了 130 亿美元，是 OpenAI 最大的投资方。

OpenAI 的“特洛伊木马”策略
-----------------

codex-plugin-cc 看起来像是 OpenAI 的妥协，但实际上是一个聪明的策略。既然打不过你，那我就加入你。

通过这个插件，OpenAI 能触达 Claude Code 的庞大用户群。与其眼睁睁看着这 41% 的开发者完全不碰 Codex，不如主动送个插件过去，至少还能分一杯羹。更重要的是，OpenAI 可以通过插件收集用户行为数据，了解开发者在什么场景下更倾向用 Codex，什么场景下更倾向用 Claude Code。

对抗性审查、任务移交这些功能，正是 Codex 的强项。让 Claude Code 用户体验到这些能力，可能会吸引一部分人转投 Codex。就像 Hua Ming 在推特上说的：“plugin 生态的赢家从来不是功能最强的，是嵌入最深的。”

这个插件传递了一个更重要的信号：AI 编程工具的未来，不是单一工具的垄断，而是多工具协作的生态。

面对 Claude的重击，OpenAI 也没闲着。3 月 26 日，OpenAI 在推出 codex-plugin-cc 的同时，还透露了一个更大的计划：要把 Codex 和 ChatGPT 合并成一个“超级应用”，预计在 2026 年下半年推出。这个策略很明确，既然在垂直领域打不过 Anthropic，那就拼生态和规模。

ChatGPT 有 3 亿月活用户，如果能把这些用户导流到编程、办公、创作等垂直场景，形成一个类似微信的“超级应用”，OpenAI 还是有机会翻盘的。但问题是，Anthropic 也在做同样的事。Claude Cowork 已经不只是一个编程工具，它现在可以自动处理市场营销、财务分析、项目管理等十几个企业场景，而且 Anthropic 开放了插件架构，让第三方开发者可以自由扩展功能。

写在最后：AI 编程的新纪元
--------------

竞争还在继续，近期，Anthropic 从 AWS 的 Madison 和 New Carlisle 数据中心获得了大量新增算力，可能使他们的总容量翻了一番。这让 Anthropic 的总算力接近了 OpenAI。以目前的发展态势看， OpenAI 在 2026 年下半年的算力竞争中会落后，2027 年会接近曾经的小老弟Anthropic。

但硬币的另一面，接触也在悄悄进行。codex-plugin-cc 的发布，标志着 AI 编程工具进入了一个新阶段：**从单一工具竞争，到多工具协作生态**。

开发者不再需要“站队”选择 Codex 还是 Claude Code，而是可以在同一个工作流里，让两个 AI 各司其职：

* Claude Code 负责快速迭代和代码生成
* Codex 负责深度审查和对抗性挑战

两者互补，形成更强大的开发助手。这种“AI 协作”的模式，可能才是未来的方向。就像我们不会只用一个工具开发软件，我们也不应该只依赖一个 AI。

对于 OpenAI 和 Anthropic 来说，这场竞争远未结束。Claude Code 在开发者市场的统治力已经形成，但 OpenAI 的 ChatGPT 生态和即将推出的“超级应用”，仍然是一张强大的底牌。

而对于我们这些开发者来说，这是最好的时代。竞争越激烈，产品迭代越快，我们能用到的工具就越好。

AI 编程的变天，才刚刚开始。

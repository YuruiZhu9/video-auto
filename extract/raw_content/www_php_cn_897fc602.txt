原创




> SubAgent是主Agent派生的隔离后台工作单元，按需创建、并行执行、结果自动回传。支持命令行spawn、AGENTS.md规则触发、agentToAgent跨体调用、Coding Team批量初始化及飞书多账户物理隔离五种启用方式。

如果您已部署 OpenClaw 主 Agent，但希望其能自动派生独立工作单元执行细分任务，则需启用 SubAgent 机制。SubAgent 并非长期驻留进程，而是按需创建、隔离运行、结果回传的轻量级后台会话。以下是开启与使用 SubAgent 的多种可行方式：

一、通过命令行直接 spawn 子代理
-------------------

此方式适用于调试、快速验证或单次任务触发，无需修改配置文件，由主 Agent 实时调用 sessions\_spawn 工具生成子会话。

1、在主 Agent 当前会话中输入指令：**/subagents spawn --task "调研2026年Qwen开源模型生态进展" --model [qwen](https://www.php.cn/zt/157147.html)-portal/coder-model**

2、系统立即返回唯一 runId（如 **agent::subagent:8a3f9c2e**），主会话不阻塞，可继续响应用户

3、子代理在独立会话中加载 AGENTS.md 与 TOOLS.md，启动信息收集流程

4、任务完成后，结果自动通过 announce 通道推送至主会话聊天流

二、在 AGENTS.md 中声明委派协议并触发调用
--------------------------

该方式将调度逻辑固化为规则，使主 Agent 具备条件判断能力，仅在满足特定语义时自动调用 SubAgent，实现“策略驱动”的任务拆分。

1、编辑主 Agent 配置目录下的 **AGENTS.md** 文件，在顶部添加 Orchestration Contract 区块

2、写入明确规则：**当用户请求含“对比”“搜集”“整理”“生成初稿”等动词，且涉及外部信息源时，必须调用 subagent qwen 执行**

3、保存后重启主 Agent 或执行 reload 指令使规则生效

4、向主 Agent 发送消息：“对比 Qwen2.5 与 Codex 在代码补全任务上的延迟与准确率”，系统将自动识别关键词并 spawn 对应子代理

三、通过全局工具 agentToAgent 启用跨智能体指令
------------------------------

此方式支持主 Agent 在任意上下文中主动构造结构化指令，发送给已注册的子 Agent，适用于需精确控制输入格式与输出约束的场景。

1、确认 **~/.[openclaw](https://www.php.cn/zt/214490.html)/openclaw.json** 中已启用 agentToAgent 工具，且 allow 列表包含目标子 Agent ID

2、在主 Agent 会话中调用：**agentToAgent(target:"coder", message:"请用 Opencode 分析 ./src/api/auth.js 的鉴权逻辑漏洞，并输出修复建议清单")**

3、子 Agent coder 收到指令后，在其专属 workspace 和工具权限下启动 Opencode TUI

4、结果以结构化 JSON 格式返回，主 Agent 可直接解析并整合进最终响应

四、使用 Coding Team Setup v2.0 技能批量初始化子代理军团
----------------------------------------

该方式面向复杂工程任务，通过预设角色模板一次性创建多个协同子 Agent，并绑定专用工作流，适合需多角色并行推进的项目场景。

1、确保已安装 Coding Team Setup v2.0 技能，执行：**claw skill install coding-team-setup@v2.0**

2、运行初始化命令：**coding-team-setup --size 3 --template react-fullstack --name frontend-team**

3、系统自动创建三个子 Agent：architect、developer、tester，各自拥有独立 workspace 与 SOUL.md 规则

4、主 Agent 可通过 **team frontend-team assign "实现登录页响应式布局"** 指令分发任务至整组

五、基于飞书多账户绑定实现物理级子代理隔离
---------------------

此方式通过通道层隔离，使每个子 Agent 拥有独立飞书机器人身份，从通信入口即完成分流，杜绝上下文污染，适用于生产环境多业务线并行。

1、在 **~/.openclaw/openclaw.json** 的 channels.feishu.accounts 下新增子账户配置，例如：**{"researcher": {"appId": "cli\_xxx", "appSecret": "xxx", "botName": "研报助手"}}**

2、在 bindings 数组中添加绑定项：**{"agentId": "researcher-subagent", "match": {"channel": "feishu", "accountId": "researcher"}}**

3、启动 researcher-subagent 实例，其将监听专属飞书应用的 webhook 流量

4、用户直接在飞书中 @研报助手 发起请求，该请求不经主 Agent，直通子代理会话

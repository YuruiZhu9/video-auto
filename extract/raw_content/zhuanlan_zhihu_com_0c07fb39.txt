## 第一部分：OpenClaw对接Telegram机器人，5分钟零失败步骤
Telegram应该是对机器人最友好的平台了，接口开放、无严格调用频率限制，也是海外用户用OpenClaw做AI助手的首选，全程跟着走，5分钟就能搞定。
### 步骤1：Telegram端创建机器人，拿核心API Token
这一步是基础，一定要用官方的BotFather，别用任何第三方工具，避免账号和Token泄露。
1. 打开Telegram客户端，顶部搜索栏搜\\*\\*@BotFather\\*\\*，认准带官方蓝标的那个，点进对话页。
![](https://pic2.zhimg.com/v2-e743b8f9108ed9efa4b988f739b4f741\_1440w.jpg)
2.点击底部的START按钮，发送`/newbot`指令，开始创建你的机器人。
![](https://pic4.zhimg.com/v2-d0ef05e7ac8e2b42cf8d4467d06c7c59\_1440w.jpg)
3.跟着BotFather的提示走，先给机器人起个名字（随便起，支持中文），再设置机器人的 \*\*用户名\*\*，注意！用户名必须以`bot`结尾，比如`OpenClaw\_AI\_Test\_bot`，而且是全局唯一的，重复了就换一个。
![](https://pic3.zhimg.com/v2-0545eb23dafaf8f7625afa7c5f86bb40\_1440w.jpg)
4.设置完成后，BotFather会直接给你生成一串 \*\*API Token\*\*，格式大概是`7123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw`， \*\*这个Token一定要复制好存起来，后面配置全靠它，千万别泄露给别人\*\*。
![](https://pica.zhimg.com/v2-6c820aebb5ec384a4b664b3e248d1ac4\_1440w.jpg)
5.【必做群聊配置】给BotFather发送`/setprivacy`指令，选择你刚创建的机器人，把隐私模式改成 \*\*Disable\*\*。
> 避坑提醒：这步不做，机器人进群后只能收到@它的消息，甚至直接装死，改成Disable后才能正常获取群聊消息，实现群聊AI助手功能。
### 步骤2：OpenClaw端添加Telegram通道配置
这里给大家提供两种配置方式，新手推荐用CLI命令配置，不容易出错；有基础的用户可以直接修改配置文件。
\*\*方式一：CLI命令配置（新手零出错首选）\*\*
1. 打开终端，执行以下命令，进入通道配置向导：
```text
openclaw channels add
```
2.在平台列表中选择 \*\*Telegram (Bot API)\*\*，按回车确认。
3.粘贴你刚才从BotFather获取的Bot Token，按回车确认。
4.私聊访问策略选择`open`（所有人都能对话），群聊策略选择`open`，完成配置。
![](https://picx.zhimg.com/v2-a5d64b20c11a2bf6faaf22c9569284b7\_1440w.jpg)
\*\*方式二：配置文件修改（有基础用户推荐）\*\*
1. 执行对应系统的命令，打开OpenClaw核心配置文件：
```bash
# Windows系统（管理员PowerShell执行）
notepad "$env:USERPROFILE\.openclaw\config.json"
# Mac/Linux系统终端执行
vim ~/.openclaw/config.json
```
2.在配置文件里找到`channels`节点，把下面的Telegram配置代码复制进去，只需要把`token`换成你自己的，其他参数按注释改就行：
```json
{
"models": [\
// 这里是你之前配好的大模型参数，不用动！\
],
"channels": {
// 这里是你之前配好的其他通道，不用动！
"telegram": {
"enabled": true, // 必须设为true，不然通道不启用
"token": "你从BotFather拿到的API Token",
"webhook\_url": "https://你的服务器公网IP:18789/telegram/webhook",
"group\_policy": "open", // open=所有群聊都能用，allowlist=仅白名单群聊可用
"allow\_from": [] // 白名单里填用户ID/群聊ID，不想限制就空着
}
}
}
```
### 步骤3：重启网关，自动完成webhook配置
保存好配置后，回到终端执行这两行命令，重启网关让配置生效：
```bash
# 重启OpenClaw网关服务
openclaw gateway restart
# 查看通道状态，Telegram显示configured就是配置成功了
openclaw channels list
```
> 这里划重点：OpenClaw会自动帮你完成Telegram webhook的注册和校验，不用你手动调用Telegram接口，终端不报错就代表配置成了，不用额外操作。
### 步骤4：测试机器人，验证对接成功
1. 打开Telegram，搜你刚创建的机器人用户名，点进对话页，发一句“你好”，机器人正常回复，就代表单聊对接成功了。
![](https://pic1.zhimg.com/v2-1a41be4a242610c04e857b544c5bef0e\_1440w.jpg)
2.群聊测试：把机器人拉进Telegram群聊，随便发句话并@机器人，能正常回复就代表群聊功能也正常了。
3.进阶测试：直接给机器人发PDF、图片，测试文件解析、图文理解能力，OpenClaw的所有功能都能在Telegram里直接用。

## 第二部分：OpenClaw对接QQ机器人，官方通道稳定不封号
很多人用OpenClaw接QQ，都是为了做社群运营、群聊智能客服、私域自动回复，这里用的是QQ官方机器人开放平台的接口，不是第三方非官方插件，稳定性拉满，基本没有封号风险。
### 步骤1：QQ开放平台创建机器人，拿核心凭证
1. 打开 \*\*QQ机器人开放平台\*\*（官网地址： [https://q.qq.com/](https://link.zhihu.com/?target=https%3A//q.qq.com/)），用你的QQ号扫码登录，先完成账号实名认证，没认证是创建不了机器人的。
2. 点首页的「创建机器人」，类型选 \*\*私域机器人\*\*（个人用、社群用都选这个，单聊群聊都支持），点下一步。
![](https://picx.zhimg.com/v2-8ab6edc2049c507d58f089f3a7c8e451\_1440w.jpg)
![](https://picx.zhimg.com/v2-84f2f6c96a757c875e84c74f13268081\_1440w.jpg)
![](https://pic3.zhimg.com/v2-a4b9f40b524b8839734e11fce779e6f6\_1440w.jpg)
3.填机器人的基础信息：上传头像、起名字、写功能介绍、选标签，填完点「确认」就行，审核很快，基本秒过。
![](https://pic3.zhimg.com/v2-0ddbea486258b5afa1cb106dd80965c6\_1440w.jpg)
4.机器人创建好后，进入管理后台，点左侧「开发设置」-「基础信息」，这里能拿到3个核心凭证， \*\*一定要复制存好，后面配置全靠它，千万别泄露\*\*：
1. AppID：机器人的唯一ID
2. Token：接口调用令牌
3. AppSecret：接口签名密钥
![](https://pic4.zhimg.com/v2-59e2eb4a2417d714946113c62f26eab1\_1440w.jpg)
4.【必做】IP白名单配置：在「开发管理」页面，找到「IP白名单」，把你的OpenClaw服务器公网IP添加进去，不然接口请求会被拦截。
![](https://picx.zhimg.com/v2-a89365122661e01cc769b8c579c08ec7\_1440w.jpg)
5.再点左侧「开发设置」-「事件订阅」，先把这个页面放着，后面配完OpenClaw再回来填地址，顺便把「单聊消息、群聊消息、@机器人消息」的权限都开了。
### 步骤2：OpenClaw端添加QQ通道配置
同样给大家提供新手友好的可视化配置，和手动配置两种方式。
\*\*方式一：Web控制台可视化配置（新手首选）\*\*
1. 打开浏览器，输入`http://你的服务器公网IP:18789`，登录OpenClaw Web控制台。
2. 进入「渠道管理」>「QQ」>「配置」。
3. 填写从QQ开放平台获取的AppID、AppSecret、机器人QQ号，点击「保存」，等待配置生效即可。
![](https://pic1.zhimg.com/v2-b69be051d5e4d0a8013cb2a34cbf7284\_1440w.jpg)
\*\*方式二：配置文件手动配置\*\*
1. 同样的，打开OpenClaw的核心配置文件，命令和上面Telegram的一样：
```bash
# Windows系统（管理员PowerShell）
notepad "$env:USERPROFILE\.openclaw\config.json"
# Mac/Linux系统
vim ~/.openclaw/config.json
```
2.在`channels`节点里，加上QQ机器人的配置代码，把对应的凭证换成你自己的就行：
```json
{
"models": [\
// 这里是你之前配好的大模型参数，不用动！\
],
"channels": {
// 这里是你之前配好的其他通道，不用动！
"qq": {
"enabled": true, // 必须设为true，不然通道不启用
"app\_id": "你的机器人AppID",
"token": "你的机器人Token",
"app\_secret": "你的机器人AppSecret",
"webhook\_url": "http://你的服务器公网IP:18789/qq/webhook",
"intents": ["direct\_message", "group\_at\_message"]
}
}
}
```
> 参数说明：`intents`就是你要订阅的消息类型，`direct\_message`是单聊消息，`group\_at\_message`是群聊里@机器人的消息，想要更多功能可以按官方文档加对应的事件类型。
### 步骤3：重启网关，完成事件订阅验证
1. 保存配置文件，执行命令重启OpenClaw网关，让配置生效：
```bash
# 重启网关服务
openclaw gateway restart
# 查看通道状态，QQ显示configured就是配置成功了

```
1. 回到QQ机器人开放平台的「事件订阅」页面，把消息接收地址填成：`http://你的服务器公网IP:18789/qq/webhook`，点「保存验证」。
2. 页面提示「验证成功」，就代表webhook配置完成了，OpenClaw和QQ机器人已经打通了。
### 步骤4：测试机器人，验证对接成功
1. 打开QQ客户端，搜你创建的机器人QQ号，加为好友，发一句“你好，帮我写一份周末出游攻略”，机器人正常回复，就代表单聊对接成功了。

## 90%的人都会踩的坑！全场景报错解决方案
我把自己踩过的、评论区高频问的报错都整理好了，遇到问题直接对着找，基本都能解决。
### Telegram对接高频报错
1. \*\*配置全对，但给机器人发消息没任何回复\*\*
1. 最常见原因：API Token填错了，检查一下Token是不是和BotFather给的完全一致，有没有多复制空格、少复制字符；
2. 第二常见原因：服务器访问不了Telegram接口，测试一下服务器能不能ping通`api.telegram.org`，不通的话换个海外节点的云服务器；
3. 终极解决：重启网关`openclaw gateway restart`，再看终端有没有报错。
3. \*\*webhook注册失败，提示invalid url\*\*
1. 原因1：18789端口没放行，去服务器防火墙/安全组里放开TCP 18789端口；
2. 原因2：webhook\\_url写错了，检查IP、端口、路径是不是完全正确，路径必须是`/telegram/webhook`；
3. 原因3：HTTPS证书无效，先用HTTP地址测试，Telegram对HTTP地址兼容度很高。
5. \*\*单聊正常，群聊里机器人装死不回复\*\*
1. 原因：机器人隐私模式没关，给@BotFather发`/setprivacy`，把对应机器人的隐私模式改成Disable；
2. 补充：把机器人设为群聊管理员，能拿到完整的群聊消息权限，基本不会出现收不到消息的情况。
### QQ对接高频报错
1. \*\*事件订阅地址验证失败，死活保存不了\*\*
1. 原因1：18789端口没放行，去服务器防火墙/安全组里放开TCP 18789端口；
2. 原因2：webhook\\_url写错了，检查IP、端口、路径和配置文件里的是不是完全一致；
3. 原因3：AppID、Token、AppSecret填错了，核对一下和QQ开放平台里的是不是完全一样；
4. 原因4：IP白名单没配置，把服务器公网IP添加到QQ开放平台的IP白名单里。
3. \*\*能收到消息，但机器人不回复\*\*
1. 原因1：大模型配置错了，执行`openclaw llm test`看看模型能不能正常调用，检查API密钥有没有过期、额度够不够；
2. 原因2：消息事件权限没开，去QQ开放平台把单聊、群聊的消息权限都打开，配置文件里的`intents`和开启的权限要对应；
3. 原因3：机器人没发布上线，去QQ开放平台提交机器人发布审核，通过后就能全平台正常用了。
5. \*\*单聊正常，群聊里@机器人没反应\*\*
1. 原因：群聊@消息的权限没开，去QQ开放平台开启「群聊@机器人消息」权限，配置文件里的`intents`加上`group\_at\_message`；
2. 补充：把机器人设为群聊管理员，确保消息接收权限正常。

## 不想折腾代码？懒人零代码一键对接方案
说实话，我当初为了把这两个平台的机器人跑通，前前后后踩了一周的坑，不是webhook调不通，就是机器人装死不回复，哪怕一个参数错了，整个流程就全白费了。

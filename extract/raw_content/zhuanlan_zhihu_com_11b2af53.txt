## 0 摘要
LLM 不仅彻底改变了 NLP 领域，还具有重塑许多其他领域（例如推荐系统）的潜力。然而，大多数相关工作将大模型视为传统推荐流程的一个组件（例如作为特征提取器），这可能无法充分利用大模型的生成能力。与将推荐过程分为评分计算和重新排序等多个阶段不同，利用大模型可将这一过程简化为单一阶段：直接从完整的物品池中生成推荐。本综述通过探讨三个问题，回顾了基于大模型的生成式推荐的进展、方法和未来方向：
- 1）什么是生成式推荐？
- 2）为什么推荐系统需要向生成式推荐发展？
- 3）如何针对各种推荐系统任务实现基于大模型的生成式推荐？
希望本综述能够为探索这一有趣的新兴主题提供必要的背景和指导。

## 1 简介
大模型（LLM）正深刻影响着自然语言处理（NLP）领域，其处理各种任务的强大能力也为其他领域的从业者开辟了新路径，例如推荐系统（RS）。作为解决当今信息过载的有效手段，推荐系统已深度融入我们的日常生活，而如何利用大模型对其进行有效重塑是一个极具前景的研究课题。尽管自然语言是一种富有表现力的媒介，但它也可能存在模糊性。例如，当大模型用于车辆识别和调度时，使用 “一辆黑色 SUV” 等模糊描述而非车辆识别码（VIN）或车牌号等精确标识符来识别车辆可能会带来风险。类似地，在需要物品精确唯一标识符的推荐场景中，模糊性也可能成为问题，因为推荐系统需要确保为用户生成的推荐是真实存在的，以避免幻觉问题。这也解释了为什么推荐系统中通常会为每个用户 / 物品分配一个 ID。尽管如此，当前对 ID 的理解通常局限于一种形式，即大多数推荐系统研究将每个 ID 视为与嵌入向量相关联的离散 token。在本综述中，作者对 ID 的定义进行了扩展，以加强其与大模型的联系：
\*\*定义 1（推荐系统中的 ID）\*\* 推荐系统中的 ID 是指能够唯一标识一个实体（如用户或物品）的token序列。ID 可以采用多种形式，例如 \*\*嵌入 ID、数字 token 序列或词语 token 序列（包括物品标题、物品描述甚至完整的新闻文章），只要其能够唯一标识该实体即可\*\*。例如，电子商务平台上的某个商品可能被分配 ID “item\\_7391”，并进一步表示为如⟨item⟩⟨\\_⟩⟨73⟩⟨91⟩的 token 序列。需要注意的是， \*\*ID 不一定由数字\*\* token \*\*组成。只要是物品的唯一标识符，均可视为该物品的 ID。\*\* 例如，电影《指环王》的标题可作为其 ID，甚至一串没有明确含义的词语序列（如 “ring epic journey fellowship adventure”）也可作为 ID。传统推荐系统中的 ID 可视为上述定义的特例，即仅包含单个 token 的序列。在此定义下，ID 类似于文本中的 token 序列，因此自然适配自然语言环境和大模型。
由于现实系统中物品数量庞大，传统推荐系统通常采用多阶段过滤范式—— 即 使用一些简单高效的方法（如基于规则的过滤）将候选物品数量从数百万减少到几百个，然后将先进的推荐算法应用于这些物品，进一步筛选出少量物品用于推荐。因此，先进的推荐算法并未应用于所有物品，而仅适用于几百个物品。
大模型的生成能力有望将推荐系统的范式从多阶段过滤重塑为单阶段过滤。具体而言，大模型本身可作为单一的完整推荐流程，直接生成推荐物品，无需多阶段过滤。通过这种方式，基于大模型的先进推荐算法以隐式方式应用于系统中的所有物品。作者将这一过程称为生成式推荐，并正式定义如下：
\*\*定义 2（生成式推荐）\*\* \*\*生成式推荐系统直接生成推荐或与推荐相关的内容，无需逐一计算每个候选的排序分数。\*\*
从更广泛的意义上讲，这与通用人工智能（AI）研究的趋势一致 —— 近年来，该领域正从判别式 AI（如分类和回归）转向生成式 AI（如 ChatGPT）。
基于上述定义，作者在第 2 节首先探讨推荐系统为何向生成式推荐发展。第 3 节回顾在大模型环境中可保留 ID 协作信息的 ID 创建方法。第 4 节通过提供通用公式，说明如何利用大模型执行典型推荐任务，第 5 节则聚焦大模型时代的机遇。最后，第 6 节总结本综述。
需要注意的是，本综述与近期一些基于大模型推荐的综述在两个方面存在差异：
- 1）本综述以生成式推荐为核心焦点，为清晰起见排除了判别式推荐模型；
- 2）从推荐领域汲取灵感，为基于大模型的推荐研究建立了分类体系，而非盲目遵循自然语言处理领域的大模型分类方法。
综上所述，本综述做出了以下贡献：
- 这是首个系统总结基于大模型的生成式推荐研究的综述。为了将该主题与传统推荐系统区分开来，作者对生成式推荐的 ID 定义进行了扩展。
- 本综述具有实用性，在对相关研究进行分类时，为不同的基于大模型的推荐任务提供了形式化描述，这将为未来的研究提供有用的指导。
- 探讨了基于大模型的生成式推荐研究需要探索的重要且有前景的方向，这可能有助于拓宽这个尚未充分研究领域的范围。
## 2 为何需要生成式推荐
为解释推荐系统为何向生成式推荐发展，首先讨论 \*\*判别式推荐\*\* 存在的问题。当推荐平台的物品数量庞大到难以处理时，为每个物品计算排序分数将导致极高的计算成本。因此，工业界的推荐系统通常采用多阶段流程来缩小候选物品范围：在早期阶段，使用简单模型（如逻辑回归）或直接过滤策略（如特征匹配）筛除非相关物品，仅在最后阶段启用相对复杂的先进模型。这一机制导致学术研究与工业应用之间存在天然鸿沟 —— 尽管近年来推荐模型日益精巧复杂，但实际落地的却寥寥无几。
在大模型时代，我们看到了弥合这一鸿沟的重大机遇。由于学术研究与工业应用可共享同一大模型底座，大模型领域的大部分研究进展可直接惠及下游应用。在推荐流程层面，传统多阶段框架可升级为单阶段的生成式推荐，即直接生成推荐物品。两类流程的对比见图 1。在推荐生成的每一步，大模型输出一个向量，表示所有可能的 ID token 的概率分布；经若干步骤后，生成的 token 组合成完整的目标物品 ID。这一过程通过隐式枚举所有候选物品来生成推荐，与传统推荐从过滤后的子集选取物品的方式形成根本差异。
![](https://pica.zhimg.com/v2-5b671db5fff36d3fb6ed14ac24e14152\_1440w.jpg)
大模型实现生成式推荐的核心奥秘在于利用 \*\*有限token表示近乎无限的物品。\*\* 假设使用 1000 个token（可以是数字token、词语token甚至未登录词（OOV）token）来表示用户或物品 ID，且每个 ID 由 10 个token组成，则可表示的唯一 ID 数量可达 1000^{10}=10^{30} 种 —— 这一数字几乎覆盖了现实推荐系统的所有需求。当采用波束搜索算法生成物品 ID 时，每步的概率向量仅涉及 1000 个token，使得直接从全量物品池生成推荐在计算上可行。

## 3 ID 创建方法
在使用大模型实现生成式推荐时，输入（尤其是用户和物品 ID）需要适配大模型的格式。直观来看，用户和物品的元数据（如用户名、物品标题）可作为 ID 的一种表示形式，相关研究中这类方法较为常见（见表 1）。
![](https://pic1.zhimg.com/v2-114b4eba6111cab3b738dba427effe64\_1440w.jpg)表 1：基于大模型的生成式推荐中 ID 的表示方法
尽管流行，但其存在两个问题：
- 首先，当 ID 过长时（如物品描述），生成过程的计算成本会显著增加，且长 ID 在数据库中难以精确匹配 —— 验证每个 ID 的存在性需与数据库中的物品逐一比对，这会退回到判别式推荐的逻辑。
- 其次，自然语言虽具表现力，但常存在模糊性，例如 “Apple” 可能指代水果或公司，而数据挖掘中经典的 “啤酒与尿布” 案例则表明， \*\*高度相关的物品可能拥有完全不同的标题\*\*。
因此，推荐场景需要简洁且唯一的 ID 表示，以精准区分用户或物品。传统推荐系统常将 ID 与嵌入向量关联，但工业级推荐系统涉及海量用户和物品，存储嵌入向量需消耗大量内存，且这些 ID 对大模型而言属于未登录 token（OOV tokens），兼容性较差。
为此， \*\*需要以 token 序列而非单一嵌入向量的形式表示 ID。\*\* 核心思路是 \*\*利用少量 token 表示海量用户或物品\*\*（如前所述）， \*\*相似用户或物品的 ID 序列共享部分 token，剩余 token 用于确保唯一性。\*\* 以下介绍三种遵循该原则的典型 ID 创建方法，这些方法大多旨在将用户 - 用户、物品 - 物品或用户 - 物品的协作信息编码到 ID 中，融合传统推荐的协同过滤优势与大模型的生成能力。
### 3.1 奇异值分解
> Aleksandr V Petrov and Craig Macdonald. 2023. Generative sequential recommendation with GPTRec. InGen-IR@SIGIR 2023: The First Work-shop on Generative Information Retrieval.
（Petrov 和 Macdonald，2023） \*\*从物品的潜在因子中获取其 ID 的 token\*\*。具体而言，他们首先对用户 \- 物品交互数据进行截断奇异值分解，以获得 \*\*物品嵌入矩阵。\*\* 经过归一化、加噪、量化和偏移调整等一系列操作后，每个物品的嵌入向量转化为整数数组，该数组即作为该物品的 ID 序列。特别地， \*\*加噪操作可确保不存在相同的物品嵌入，从而使每个物品 ID 唯一。\*\*
![](https://pic1.zhimg.com/v2-819668a4bdee4664ac7e9cead30b77ce\_1440w.jpg)
### 3.2 协作索引
> Wenyue Hua, Shuyuan Xu, Yingqiang Ge, and Yongfeng Zhang. 2023b. How to index item ids for recommendation foundation models. InProceedings of 1st International ACM SIGIR Conference on Information Retrieval in the Asia Pacific.
（Hua 等人，2023b）将物品 ID 构造成层次树节点的组合。具体来说，他们首先构建一个物品图，图中边的权重表示任意两个物品在所有用户交互历史中的共现频率。然后计算该图的邻接矩阵和拉普拉斯矩阵，以及拉普拉斯矩阵的特征向量。利用特征向量，通过 \*\*谱聚类\*\* 将相似物品聚为同一簇。通过递归操作，大簇可进一步划分为小簇。当每个簇的节点数小于阈值时，这些簇及其子簇自然构成一棵层次树，其叶子节点即为物品。为每个节点分配 token 后，每个物品通过从根节点到叶子节点的路径获得唯一的 ID 序列。

### 3.3 残差量化变分自编码器
> Bowen Zheng, Yupeng Hou, Hongyu Lu, Yu Chen, Wayne Xin Zhao, and Ji-Rong Wen. 2023. Adapt-
>
> ing large language models by integrating collaborative semantics for recommendation. arXiv
>
> preprint arXiv:2311.09049.
（Zheng 等人，2023）利用残差量化变分自编码器（RQ-VAE）（Zeghidour 等人，2021）对物品嵌入进行量化以获取物品 ID。具体流程为：首先通过大模型对物品的文本描述进行编码，得到物品嵌入向量；将该嵌入向量输入 VAE 的编码器，获得潜在表示；随后将该表示作为初始残差向量，进行多步残差量化。每一步均存在一个码本（即嵌入表），从中找到与残差向量最接近的嵌入向量，该嵌入在码本中的索引即作为当前步骤的码字（即物品 ID 序列的一个 token）。通过从旧残差向量中减去最接近的嵌入向量，计算得到新的残差向量。重复此过程，直至形成完整的物品 ID。
除上述三种 ID 创建方法外，（Hua 等人，2023b）还讨论了其他策略，如基于用户交互历史的顺序索引和基于物品元数据信息的语义索引，这些均为有效的物品 ID 创建方法。由于原理较为简单，此处不再详述。

## 4 如何实现生成式推荐
基于上述定义的用户和物品 ID，现在讨论如何使用大模型执行不同的生成式推荐任务。表 2 总结了每个任务的相关研究，可见部分模型（如 P5）可支持多任务推荐。为使大模型理解每个任务（尤其是输入数据相同的任务），可构建描述任务的提示模板，并在提示中填充用户和物品信息（如 ID）。推理阶段，所有输出（如预测的物品 ID）以自然语言生成的自回归方式产生。以下先介绍各任务的通用公式，再讨论最新进展，最后说明评估方法。
![](https://pica.zhimg.com/v2-7cc5f0bac1c8e92a142dc51fc1ef3fdc\_1440w.jpg)表 2：基于大模型的七种典型生成式推荐任务。
### 4.1 评分预测
传统推荐系统中，评分预测任务的形式为：给定用户 u 和物品 i，推荐模型 f(u, i) 需估计用户对物品的评分 \\hat{r}\\_{u,i} 。在大模型场景下，u 和 i 不再是嵌入 ID，而是定义 1 中所述的 token 序列。将这两个 ID 填入指令提示 \\(p(u, i)\\) （如 “user\\_1234 会如何评价 item\\_5678”），大模型即可理解任务。输入提示后，大模型生成 1-5 分的数字字符串（如 “4.12”），表示用户与物品交互的可能性。
已有研究对此任务进行了测试，其中多数基于 ChatGPT。由于用户未必对所有交互物品留下显式评分，评分预测在实际系统中实用性较低。相比之下，点击等隐式反馈更易收集，因此如何从隐式反馈推断用户偏好，推动了 Top-N 推荐任务的发展。
### 4.2 Top-N推荐
Top-N推荐任务（又称排序任务）旨在为给定用户 u 选择 N\个物品作为推荐。为此，传统推荐系统通常会计算物品集 v 中每个物品 i 的评分 \\(\\hat{r}\\_{u,i}\\) 。过滤掉用户已交互过的物品集合 I\\_u 后，剩余物品中评分最高的候选集可作为推荐结果，即 \\(\\text{Top}(u, i) := \\arg \\max\\_{i \\in I \\setminus I\\_u}^N \\hat{r}\\_{u,i}\\) 。
然而，由于大模型的上下文长度限制， \*\*无法向模型输入所有物品\*\*。目前学界探索了两种解决方案：
1\. 直接推荐：提示仅包含用户信息（如ID或元数据），要求大模型直接为该用户生成推荐。
2\. 选择性推荐：提示中同时提供用户信息和候选物品列表 I\\_c ，要求大模型从候选集中选择推荐物品。候选集可包含一个测试物品和若干采样的负样本。例如，将用户和候选集填入提示 p(u, I\\_c) （如“从以下候选物品item\\_6783、...、item\\_9312、item\\_2834中为user\\_1234选择一个推荐物品”），大模型会生成一个物品ID（如“9312”）作为推荐。结合波束搜索，模型可生成多个物品ID，形成包含 N\个推荐的列表。除生成物品ID外，近期研究还通过提示大模型生成“是”或“否”，判断用户是否会与给定物品交互。尽管以生成文本形式输出，但这类方法需为每个物品生成答案或评分（如“是”的概率），本质上仍属于判别式推荐。
### 4.3 序列推荐
序列推荐任务在Top-N推荐基础上进一步考虑交互的时间或顺序，目标是根据用户 u 的历史交互记录预测其下一个可能交互的物品。用户交互过的物品按时间戳排序为 I\\_u 。考虑到数据的时序性，传统方法常使用马尔可夫链、循环神经网络（RNN）或Transformer等序列模型。在大模型场景下，可将用户及其交互序列填入提示 \\(p(u, I\\_u)\\) （如“给定user\\_1234的交互历史item\\_3456、...、item\\_4567、item\\_5678，预测用户下一步将交互的物品”），然后提示大模型生成一个物品ID作为预测（如“6789”）。为减少推理时间，可在填入提示前截断较早的历史物品。 该任务是当前研究热点，大量基于大模型的工作已涉足。例如，Bao等人利用大模型生成候选集供后续过滤，Yang等人向大模型提供候选物品进行推荐，而Bao等人则通过提示大模型判断用户是否喜欢特定物品。
### 4.4 可解释推荐
除生成推荐外，让用户理解推荐依据的解释同样重要。解释推荐的方法包括基于显式物品特征和可视化突出显示等。为全面探讨可解释推荐，感兴趣的读者可参考相关综述。 基于大模型的典型推荐解释任务可归结为自然语言解释生成：给定用户 u 和物品 i，引导模型生成自然语言句子或段落，解释为何将 i 推荐给 u。真实解释可从用户评论中挖掘。由于输入（u 和 i）与评分预测任务相同，可将其填入提示 \\(p(u, i)\\) 以告知大模型当前为解释任务，例如 “向 user\\_1234 解释为何推荐 item\\_5678”。模型可能生成 “这部电影堪称一流” 之类的解释。 然而，仅在提示中使用 ID 可能导致模型不明确应从哪些维度展开解释。为此，可在提示中提供物品特征 f 作为提示词，如 “演技”。此类场景的提示 p(u, i, f) 可设计为 “从演技角度为 user\\_1234 撰写关于 item\\_5678 的推荐理由”，此时大模型可能生成 “这部电影的演技很吸引人” 的解释。 相关研究中，（Geng 等人，2022c, 2023；Li 等人，2023b；Liu 等人，2023a,b；Wang 等人，2023d）执行上述解释生成任务；（Cui 等人，2022）通过关键词 “因为” 触发解释任务；（Rahdari 等人，2024）采用多步推理的思维链提示；（Li 等人，2023a）使用连续提示向量替代离散提示模板。
### 4.5 评论生成
除解释生成外，上述框架还可适配评论生成任务，这有助于用户在购买商品、观看电影、乘车等场景后更便捷高效地留下评论，生成的数据又能反哺可解释推荐、对话式推荐等相关研究。通常，将用户及其交互物品填入提示 \\(p(u, i)\\) ，如 “为 user\\_1234 生成关于 item\\_5678 的评论”，大模型可能生成一段评论（例如 “这家酒店位于……”）。目前尚未发现基于大模型的评论生成研究，可能因其框架与解释生成高度相似，仅文本长度更长。
### 4.6 评论摘要
阅读长篇评论耗时较长，用户未必具备足够耐心。高度凝练的评论摘要可帮助用户快速把握物品优缺点。当前基于大模型的评论摘要方法主要聚焦于总结用户 u 对物品 i 的评论 R，并将评论标题或核心要点作为摘要。例如，构建提示 p(u, i, R) 并填入三元数据：“总结 user\\_1234 对 item\\_5678 的以下评论：这家酒店位于……”，大模型可能生成 “地理位置优越” 的摘要。 然而，总结用户自身的评论可能缺乏必要性（用户已了解该物品），更有价值的是为未交互过该物品的用户生成摘要，或对同一物品的多条用户评论进行综合摘要。
### 4.7 对话式推荐
对话式推荐的目标是通过多轮对话为用户推荐物品。与主要依赖用户历史交互的传统推荐不同，对话环境中用户可通过自然语言自由表达偏好甚至提供负反馈（如拒绝推荐）。目前学界对此任务的形式化定义尚未达成共识。 相关研究中，（Cui 等人，2022；Friedman 等人，2023；He 等人，2023）在向大模型输入对话前使用 “USER” 和 “SYS-TEM” 标签标记发言者；（Huang 等人，2023）引导大模型调用传统推荐系统、SQL 等工具缩小候选物品范围；（Lin 和 Zhang，2023）直接与 ChatGPT 进行对话实验，旨在建立对话式推荐的记忆机制、修复机制等原则而非开发新模型。在评估方面，（Wang 等人，2023c）指出现有协议存在的问题：尽管 ChatGPT 的对话能力出色，但其在现有指标上表现不佳，原因是指标过度强调生成响应与标注推荐或话语的匹配度。
### 4.8 评估规则
评估大模型在上述任务中的表现时，可沿用传统指标：评分预测任务采用均方根误差（RMSE）和平均绝对误差（MAE）；对于其他两项推荐任务，即 Top-N 推荐和序列推荐，可以采用面向排序的指标，如归一化折损累积增益（NDCG）、精确率（precision）和召回率（recall）。除了离线评估，还可以采用在线 A/B 测试，因为它们能反映用户与推荐物品的实际交互情况。
对于自然语言生成任务（包括解释生成、评论生成、评论摘要和对话式推荐），大模型的生成质量可借助机器翻译领域的 BLEU和文本摘要领域的 ROUGE进行评估。这两种指标均通过衡量生成内容与真实数据的文本片段匹配度来量化质量。然而，正如（Wang 等人，2023c）指出的，过度强调与标注数据的匹配可能存在问题，且 BLEU 或 ROUGE 无法反映文本相似性之外的其他维度。作为早期尝试，（Li 等人，2020）提出了特征覆盖率、特征多样性等指标，将显式元素特征纳入解释评估，但这些指标仍不成熟。尽管存在基于学习的指标（如 BERTScore），但仍需开发更先进的标准化指标。除自动评估外，还可通过人工评估衡量大模型在生成任务上的表现，但其依赖研究人员设计合理的问卷，且参与者数量可能有限。

## 5\. 挑战与机遇
本节探讨大模型时代生成式推荐的研究挑战与机遇，尤其是需要迫切关注的重要问题。
### 5.1 基于大模型的智能体
模拟器在解决推荐系统数据稀缺问题（尤其是真实交互数据通常不可得的对话式推荐场景）中发挥了重要作用。近期，基于大模型的生成式智能体已能模拟几乎任何场景，如小型社会或世界大战，推荐系统领域也出现了用户行为模拟器。然而，将模拟器应用于推荐系统时存在一个悖论： \*\*一方面，若模拟器生成的交互数据与目标用户的真实偏好不一致，则数据可能缺乏实际价值；另一方面，若模拟器能完美模拟用户偏好，则可能无需推荐算法，因为模拟数据可直接作为推荐结果。\*\*
作者认为，基于大模型的智能体在推荐系统中的潜力远超简单模拟。当前，它们可调用工具、API 和专家模型，通过多步推理解决复杂任务。这一能力可推动基于大模型的推荐系统向更广泛的现实应用场景拓展。以旅行推荐为例，系统可结合用户的个性化需求（如行程时长、预算、偏好景点），通过查询实时信息（如景点开放时间、景点间交通时间）生成行程规划。若将此类系统嵌入车辆，其甚至可通过调用地图 API 为驾驶员规划路线，并推荐车外服务（如餐厅、充电站 / 加油站）。无论何种场景，若用户无法按原计划执行，系统可动态调整行程以适应用户当前状态。通过与现实世界物体的连接，新一代推荐系统有望改变人们的生活方式。
### 5.2 幻觉问题
幻觉 指大模型生成的内容可能偏离事实，这是大模型及其应用中的重要问题。具体到基于大模型的推荐系统，需确保推荐给用户的物品真实存在，否则可能导致用户不满、挫败，甚至降低系统在现实中的用户接受度。例如，用户可能耗费时间前往推荐的餐厅，却发现该餐厅根本不存在。尤其在药物推荐、医疗方案推荐、金融投资推荐等高风险领域，幻觉推荐可能给用户造成严重损失。
解决基于大模型的推荐系统中幻觉问题的可能路径有两条：
- \*\*使用精心设计的物品 ID 进行生成\*\*：例如，（Hua 等人，2023b）创建物品 ID 并将其组织为前缀树（Trie）结构。只要波束搜索生成过程遵循树中的根到叶路径，生成的物品将始终存在。
- \*\*对大模型应用检索增强\*\*：即通过检索到的物品对大模型进行条件约束，使推荐物品与数据库中的实际物品匹配。
此外，索引和检索这两种方法可结合使用，以有效且高效地解决幻觉问题。
### 5.3 偏差与公平性
基于大模型的推荐系统可能存在两类偏差： \*\*内容偏差\*\* 和 \*\*推荐偏差\*\*。
前者指生成内容中可直接观察到的偏差，性别偏差是典型例子。（Wang 等人，2023b）发现，在游戏领域，机器为男性用户生成的推荐解释通常比女性用户更长，这一问题可能源于适配自游戏用户评论的训练数据。此外，基于大量人类生成数据训练的大模型可能会重复甚至强化数据中隐藏的偏差。以语言偏差为例，（Zhang 等人，2021）观察到，大模型在生成物品标题时倾向使用通用 token 以确保流畅性和语言合理性，这会导致推荐结果与用户偏好物品差异显著。在适配下游推荐任务时，需减轻甚至完全消除此类偏差，以避免负面影响扩散并提升用户体验。
关于推荐偏差，（Li 等人，2023f）指出，ChatGPT 倾向于推荐其标记为 “流行” 的新闻来源内容。（Xu 等人，2023a）在要求 ChatGPT 为不同性别身份和种族的用户推荐新闻和工作时，观察到领域差异。类似地，（Zhang 等人，2023b）发现，ChatGPT 为不同人口统计属性用户（如白人与非裔美国人）生成的音乐推荐存在差异。尽管这些结果看似有偏差，但也可能是一种个性化表现，因为不同文化背景的人音乐品味可能不同。因此，需回答一个关键问题： \*\*偏差与个性化的边界何在？\*\*（Hua 等人，2024）尝试通过将偏差提炼为连续提示，使基于大模型的推荐模型在年龄、婚姻状况、职业等敏感属性上实现公平性。由于偏差与公平性仍是开放性问题，需从公平性定义和大模型推荐系统的偏差缓解等角度开展更多研究。
### 5.4 透明性与可解释性
让推荐对用户透明且可解释，一直是推荐系统及通用人工智能的重要问题。由于大模型的规模和复杂性，解释基于大模型的推荐给学界带来了新挑战。此类推荐系统的可解释性分为两类：一是为推荐物品生成合理的自然语言解释，二是深入模型内部解释大模型的工作机制。尽管研究者已对第一类可解释性开展了一定探索，但第二类可解释性仍近乎空白。一种可能的方法是将大模型（如提示）与知识图谱等显式知识库对齐，使模型决策过程与知识库中的显式路径一致，从而实现可解释性。然而，该方向总体仍处于初级阶段，需要学界提出创新性方法和大胆设想。
### 5.5 可控性
可控性是大模型的重要问题，因为我们通常无法精确控制其输出。缺乏可控性可能导致严重后果，例如大模型生成骚扰性内容、虚假信息或违背基本道德标准的内容。对推荐系统而言，由于各类推荐任务或场景均需要可控性，可控性问题更为复杂。例如，用户可能希望控制解释所涉及的特征—— 若用户关注餐厅 “价格”，解释应围绕价格展开；若关注 “距离”，则解释应讨论距离。除解释的可控性外，用户还可能希望控制推荐物品的特征（如价格区间、颜色、品牌），例如要求大模型仅推荐特定价格范围内的物品。尽管这些特征可通过提示引导大模型生成，但生成的推荐仍可能无法满足用户需求。当前，基于大模型的推荐可控性研究主要聚焦于解释控制，而对推荐结果本身的可控性研究亟待加强。
### 5.6 推理效率
由于大模型包含海量参数，且推荐系统对延迟敏感，基于大模型的推荐模型效率至关重要。训练效率可通过选项微调或是适配器微调提升。为减少大模型的训练时间，（Li 等人，2023b）提出任务交替训练策略以处理多推荐任务。由于大模型的训练效率可在离线环境中提升，且通常无需频繁重新训练，因此其重要性低于推理效率问题。（Cui 等人，2022）通过预计算大模型的前几层并缓存结果来提升推理效率，但该策略可能仅适用于以元数据表示用户和物品的特定大模型架构。（Li 等人，2023b）观察到移除离散提示可略微减少大模型的推理时间。总体而言，基于大模型的推荐模型在推理效率上仍有较大提升空间。
### 5.7 多模态推荐
除文本外，大模型还可利用其他模态数据，只要这些数据能表示为可融入文本句子的 token 序列（如 DALL・E（Ramesh 等人，2021）和 Sora² 的处理方式）。例如，（Geng 等人，2023）将物品图像融入大模型以提升推荐任务性能；在图像生成方面，（Geng 等人，2022a）基于视觉 - 语言模型为推荐生成可视化解释，（Cui 等人，2022）则为产品设计合成图像。除图像外，视频和音频也可通过自回归方式生成（Rubenstein 等人，2023；Yan 等人，2021），这使得基于大模型的多模态推荐成为有前景的方向，如短视频推荐和音乐推荐。此外，当物品库中无满足用户兴趣的现有物品时，系统可生成新物品（尤其在时尚推荐领域，如服装设计）。即使生成的物品不完全符合用户需求，也可用于检索现有相似物品或激发设计师的创意以优化设计。同时，模型开发者需确保机器生成内容的真实性，避免用户产生负面体验（例如，将夏威夷景点图片标注为韩国用于旅行推荐）。
### 5.8 冷启动推荐
由于大模型在预训练阶段已学习世界知识，即使未在推荐特定数据集上微调，也能执行推荐任务。典型案例是 ChatGPT，如前所述，其可通过指令完成各类推荐任务。核心原因在于用户偏好和物品属性可通过自然语言表达。因此，基于大模型的推荐模型有望缓解著名的冷启动问题 —— 即新用户或新物品的交互数据有限甚至缺失的场景。尽管交互数据不足，仍可利用元数据（如用户人口统计信息、物品描述信息）进行推荐。

## 6 结论
本综述回顾了基于大模型的生成式推荐的最新进展，并根据相关研究为每个生成式推荐任务提供了通用形式化描述。为鼓励研究者探索这一充满潜力的方向，作者阐述了其相较传统推荐系统的优势，扩展了 ID 的定义，总结了各类 ID 创建方法，并指出若干值得深入探索的研究方向。我们期待大模型与推荐系统深度融合，在多样化场景中创造高质量的个性化服务。

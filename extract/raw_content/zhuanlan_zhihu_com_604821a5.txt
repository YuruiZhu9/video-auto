Kokoro TTS 是一个轻量级的TTS模型，具有速度快及相对不错的[音质](https://zhida.zhihu.com/search?content\_id=254966026&content\_type=Article&match\_order=1&q=%E9%9F%B3%E8%B4%A8&zd\_token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJ6aGlkYV9zZXJ2ZXIiLCJleHAiOjE3NzUyMzMxNTAsInEiOiLpn7PotKgiLCJ6aGlkYV9zb3VyY2UiOiJlbnRpdHkiLCJjb250ZW50X2lkIjoyNTQ5NjYwMjYsImNvbnRlbnRfdHlwZSI6IkFydGljbGUiLCJtYXRjaF9vcmRlciI6MSwiemRfdG9rZW4iOm51bGx9.vZFdS3KX0wWm8xY6k1m5rNm6CpH2dWSvtTq5dMdBE0k&zhida\_source=entity)的特点。作为一个仅有82M参数的文本转语音（TTS）模型，Kokoro 在 [TTS Arena](https://link.zhihu.com/?target=https%3A//huggingface.co/spaces/TTS-AGI/TTS-Arena) 中击败了许多参数规模更大的竞争对手，成为语音合成领域的一颗新星。
![](https://pic1.zhimg.com/v2-e4c4237423b54710f4c0b3630b231b84\_1440w.jpg)
我前一段时间测试过Kokoro ( [北方的郎：Kokoro TTS：支持多语言的轻量级TTS（文本转语音）模型](https://zhuanlan.zhihu.com/p/18450040389)), 哪个时候我发现“Kokoro TTS生成中英文、数字混合内容，发现英文和数字都不能很好的生成。”
前几天Kokoro分别发布了Kokoro-82M（1.0）和Kokoro-82M-v1.1-zh模型，对音质和能力进行了大幅提升。尤其是Kokoro-82M-v1.1-zh针对中文进行了优化。具体如下：
模型地址： [https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh](https://link.zhihu.com/?target=https%3A//huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)

我根据官方提供的方法进行了安装和测试
```text
pip install -q kokoro>=0.8.2 "misaki[zh]>=0.8.2" soundfile
apt-get -qq -y install espeak-ng > /dev/null 2>&1
wget https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh/resolve/main/samples/make\_zh.py
python make\_zh.py
```
因为第一次使用的时候会下载模型，所以用以下命令运行代码：
```text
HF\_ENDPOINT=https://hf-mirror.com python make\_zh.py
```
make\\_zh.py代码如下：
```text
# This file is hardcoded to transparently reproduce HEARME\_zh.wav
# Therefore it may NOT generalize gracefully to other texts
# Refer to Usage in README.md for more general usage patterns
# pip install kokoro>=0.8.1 "misaki[zh]>=0.8.1"
from kokoro import KModel, KPipeline
from pathlib import Path
import numpy as np
import soundfile as sf
import torch
import tqdm
REPO\_ID = 'hexgrad/Kokoro-82M-v1.1-zh'
SAMPLE\_RATE = 24000
# How much silence to insert between paragraphs: 5000 is about 0.2 seconds
N\_ZEROS = 5000
# Whether to join sentences in paragraphs 1 and 3
JOIN\_SENTENCES = True
VOICE = 'zf\_002' if True else 'zm\_010'
device = 'cuda' if torch.cuda.is\_available() else 'cpu'
texts = [(\
"Kokoro 是一系列体积虽小但功能强大的 TTS 模型。",\
), (\
"该模型是经过短期训练的结果，从专业数据集中添加了100名中文使用者。",\
"中文数据由专业数据集公司「龙猫数据」免费且无偿地提供给我们。感谢你们让这个模型成为可能。",\
), (\
"另外，一些众包合成英语数据也进入了训练组合：",\
"1小时的 Maple，美国女性。",\
"1小时的 Sol，另一位美国女性。",\
"和1小时的 Vale，一位年长的英国女性。",\
), (\
"由于该模型删除了许多声音，因此它并不是对其前身的严格升级，但它提前发布以收集有关新声音和标记化的反馈。",\
"除了中文数据集和3小时的英语之外，其余数据都留在本次训练中。",\
"目标是推动模型系列的发展，并最终恢复一些被遗留的声音。",\
), (\
"美国版权局目前的指导表明，合成数据通常不符合版权保护的资格。",\
"由于这些合成数据是众包的，因此模型训练师不受任何服务条款的约束。",\
"该 Apache 许可模式也符合 OpenAI 所宣称的广泛传播 AI 优势的使命。",\
"如果您愿意帮助进一步完成这一使命，请考虑为此贡献许可的音频数据。",\
)]
if JOIN\_SENTENCES:
for i in (1, 3):
texts[i] = [''.join(texts[i])]
en\_pipeline = KPipeline(lang\_code='a', repo\_id=REPO\_ID, model=False)
def en\_callable(text):
if text == 'Kokoro':
return 'kˈOkəɹO'
elif text == 'Sol':
return 'sˈOl'
return next(en\_pipeline(text)).phonemes
# HACK: Mitigate rushing caused by lack of training data beyond ~100 tokens
# Simple piecewise linear fn that decreases speed as len\_ps increases
def speed\_callable(len\_ps):
speed = 0.8
if len\_ps <= 83:
speed = 1
elif len\_ps < 183:
speed = 1 - (len\_ps - 83) / 500
return speed \* 1.1
model = KModel(repo\_id=REPO\_ID).to(device).eval()
zh\_pipeline = KPipeline(lang\_code='z', repo\_id=REPO\_ID, model=model, en\_callable=en\_callable)
#path = Path(\_\_file\_\_).parent
path = Path('.').parent
wavs = []
for paragraph in tqdm.tqdm(texts):
for i, sentence in enumerate(paragraph):
generator = zh\_pipeline(sentence, voice=VOICE, speed=speed\_callable)
f = path / f'zh{len(wavs):02}.wav'
result = next(generator)
wav = result.audio
sf.write(f, wav, SAMPLE\_RATE)
if i == 0 and wavs and N\_ZEROS > 0:
wav = np.concatenate([np.zeros(N\_ZEROS), wav])
wavs.append(wav)
sf.write(path / f'HEARME\_{VOICE}.wav', np.concatenate(wavs), SAMPLE\_RATE)
```
Kokoro-82M-v1.1-zh最大的特点就是预设了多大100个中文的voice，使用的时候直接修改上文代码中的：
VOICE = 'zf\\_002' 为对应的voice文件名（不加.pt）即可。
![](https://pic1.zhimg.com/v2-736b0f16de02a3442007eae76a104eae\_1440w.jpg)
其实Kokoro-82M-v1.1-zh应该就是Kokoro-82M在中文数据上又训练一下的结果。所以上文中的代码
```text
REPO\_ID = 'hexgrad/Kokoro-82M-v1.1-zh'
VOICE = 'zf\_002'
```
修改为：
```text
REPO\_ID = 'hexgrad/Kokoro-82M'
VOICE = 'zf\_xiaobei'
```
支持的声音，参考每个模型的模型卡下面的VOICE目录下面的文件。开头z表示中文，f表示female, m表示male。
对比测试后发现Kokoro-82M-v1.1-zh有了很大的提升，尤其是对中英文+数字的混合内容。
后续准备用xinference或者[fastapi](https://zhida.zhihu.com/search?content\_id=254966026&content\_type=Article&match\_order=1&q=fastapi&zd\_token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJ6aGlkYV9zZXJ2ZXIiLCJleHAiOjE3NzUyMzMxNTAsInEiOiJmYXN0YXBpIiwiemhpZGFfc291cmNlIjoiZW50aXR5IiwiY29udGVudF9pZCI6MjU0OTY2MDI2LCJjb250ZW50X3R5cGUiOiJBcnRpY2xlIiwibWF0Y2hfb3JkZXIiOjEsInpkX3Rva2VuIjpudWxsfQ.GZ-yP2n-munNGpYK7OjBPTi5bjeV4\_DfVV2fHbpOmiI&zhida\_source=entity)对它进行服务化，再试用一下。

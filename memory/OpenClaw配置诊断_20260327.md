## 🔴 二、安全隐患（高优先级）

### 2.1 敏感凭证明文存储
**严重程度：高**

以下敏感信息以明文形式存储在配置文件中：

| 字段 | 位置 | 风险 |
|------|------|------|
| Minimax API Key | `models.providers.minimax.apiKey` | ⚠️ 泄露风险 |
| DingTalk Client Secret | `channels.dingtalk.clientSecret` | ⚠️ 泄露风险 |
| DingTalk Client Secret | `plugins.entries.dingtalk.config.clientSecret` | ⚠️ **重复暴露** |
| Gateway Auth Token | `gateway.auth.token` ("minimax-agent") | ⚠️ 弱凭证 |

**建议**：
- 平台环境变量替代（如果支持）
- 使用密文或引用外部密钥管理服务
- 当前文件权限 `0670`（owner+group 可读写）已做基础防护，**请勿将文件权限改为 0644 或更宽松**

### 2.2 DingTalk 凭证重复暴露
**严重程度：中**

DingTalk `clientId` 和 `clientSecret` 在配置中出现了 **两次**：
```
channels.dingtalk.clientId / clientSecret
plugins.entries.dingtalk.config.clientId / clientSecret
```

这种冗余增加了凭证泄露的攻击面，且维护困难（两处需同步更新）。

**建议**：清理 `channels.dingtalk` 中的凭证，仅保留 `plugins.entries.dingtalk.config` 中的配置（反之亦然）。

### 2.3 DingTalk 插件调试模式开启
**严重程度：中**

```json
"dingtalk": {
  "debug": true
}
```

调试模式会产生额外日志，可能包含敏感通信数据，影响性能。

**建议**：生产环境中将 `debug` 设为 `false`。

## 🟡 三、配置不一致（中优先级）

### 3.1 工具禁用配置冗余
**问题**：Web 搜索和图片工具被双重禁用：

```json
"tools": {
  "deny": ["image", "web_search", "web_fetch"],
  "web": {
    "search": { "enabled": false },
    "fetch": { "enabled": false }
  },
  "media": {
    "image": { "enabled": false }
  }
}
```

`tools.deny` 和 `tools.web.search.enabled: false` / `tools.media.image.enabled: false` 同时存在。前者是全局黑名单，后者是分模块标志，存在优先级冲突风险。

**建议**：统一使用 `tools.deny` 数组或分模块 `enabled: false` 标志之一，避免维护混乱。

### 3.2 未配置的已加载插件

这些插件可能以最小权限运行（符合最小暴露原则），但如果未来需要启用，需提前规划配置。

## 🟠 四、性能风险（中优先级）

### 4.1 子 Agent 并发数较高
```json
"subagents": { "maxConcurrent": 8 }
```

加上主 Agent 的 `maxConcurrent: 4`，理论最大并发执行体为 **12 个**（4 主 + 8 子）。在资源受限环境下可能导致：
- 内存占用激增
- LLM API 调用排队
- 模型提供商限流

**建议**：根据实际服务器资源和 API 限流情况，酌情降低至 4-6。

### 4.2 热重载防抖延迟较短
```json
"reload": { "debounceMs": 300 }
```

300ms 的防抖在高频配置变更场景下可能触发频繁重启。

**建议**：如无高频配置变更需求，可考虑提升至 500-1000ms。

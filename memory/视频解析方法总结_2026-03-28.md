## 一、视频内容理解（Video Understanding）

### 1.1 大语言模型驱动视频理解（LMM / Video-LLM）

视频理解是大模型最热门的落地方向之一。核心思路是将视频的视觉信息通过视觉编码器映射到语言空间，再借助大语言模型进行问答、推理、总结。

#### 代表性模型

| 模型 | 机构 | 核心特点 | 开源 |
|------|------|----------|------|
| **InternVideo2** | 上海AI Lab | 三阶段渐进式训练（ViT+VA+MLM），支持视频问答/检索/字幕，在7B/8B规模达到SOTA | ✅ |
| **InternVideo2.5** | 上海AI Lab | 支持长视频上下文建模（长达数小时），增强VideoQA和视频多模态对话 | ✅ |
| **Video-LLaVA** | PKU-YuanGroup | 统一视觉表示学习，在对齐前进行投影，在13个图文/视频基准上达到SOTA | ✅ |
| **VideoChat** | 上海AI Lab | 以对话为中心的视频理解，支持指令微调的视频多模态对话系统 | ✅ |
| **LLaVA-Video** | Microsoft/GAIR | 利用合成数据进行视频指令微调，支持短视频理解和推理 | ✅ |

| **Video-LLaMA** | - | 早期多模态视频指令模型 | ✅ |

#### 长视频理解技术路线

长视频（数分钟到数小时）是当前的核心难题，主要有三条技术路线：

1. **流式推理（Streaming）**：StreamingVLM（MIT&NVIDIA）用流式推理机制处理无限长视频，训练阶段使用短视频片段全注意力，推理时保持流式状态
2. **压缩记忆（Compression+Memory）**：VideoAgent式方案将视频帧压缩为视觉token，通过外部记忆模块（如VideoMem）存储历史信息
3. **分段级联（Chunking）**：LongVLM将长视频切分为语义一致的短片段，分别编码后级联输入LLM

## 二、视频分割（Video Segmentation）

### 2.1 SAM2 (Segment Anything Model 2)

**Meta AI 2024年发布**，是视频分割领域的里程碑模型。

**核心能力：**
- **视频实时分割**：对视频中任意目标进行像素级跟踪分割
- **零样本泛化**：无需训练即可分割新类别目标
- **文本提示**：支持文本驱动的目标分割
- **点/框提示**：支持交互式点/框提示

**与SAM1的区别：**
- SAM1仅支持图像分割，SAM2新增视频时序跟踪能力
- 新增Memory机制，利用历史帧信息维持目标一致性
- 新增SAM2-Hiera图像编码器（基于Hierarchical ViT），推理速度提升3-6倍

**相关工具：**
- SAM2官方Python API：`pip install segment-anything-2`
- Gradio网页界面 demo
- Sa2VA：SAM2 + LLaVA的视觉语言视频分割

## 三、视频帧提取（Video Frame Extraction）

### 3.1 命令行工具

#### FFmpeg（最通用）

```bash
# 提取所有帧
ffmpeg -i input.mp4 frames/frame_%04d.png

# 按固定间隔提取（如每秒1帧）
ffmpeg -i input.mp4 -vf fps=1 output_%04d.png

# 提取关键帧（I帧）
ffmpeg -i input.mp4 -vf "select='eq(pict_type,PICT_TYPE_I)'" -vsync vfr frame_%04d.png

# 提取特定时间点的帧
ffmpeg -ss 00:01:30 -i input.mp4 -frames:v 1 output.png

# 按帧号提取（第300帧）
ffmpeg -i input.mp4 -vf "select=eq(n\,300)" -frames:v 1 output.png
```

#### ffmpeg-python（Python封装）

```python
import ffmpeg
stream = ffmpeg.input('input.mp4')
stream = ffmpeg.filter(stream, 'fps', fps=1)
stream = ffmpeg.output(stream, 'frames/frame_%04d.png')
ffmpeg.run(stream, overwrite_output=True)
```

### 3.2 Python库方案

| 库 | 优点 | 缺点 |
|------|------|------|
| **OpenCV (cv2)** | 通用、速度快、支持所有格式 | GIL限制，并发性差 |
| **Decord** | 支持视频随机访问、GPU加速读取、速度快（比OpenCV快3-5倍） | 依赖FFmpeg，特定格式可能不兼容 |
| **MoviePy** | API简洁，支持视频剪辑和特效 | 速度较慢，不适合大批量处理 |
| **PyAV** | FFmpeg底层绑定，支持流式读取 | API相对底层 |
| **imageio-ffmpeg** | imageio的FFmpeg后端，无缝集成 | 功能相对单一 |

#### Decord示例

```python
from decord import VideoReader, cpu
vr = VideoReader('video.mp4', ctx=cpu(0))
frames = vr[:].asnumpy()  # 读取所有帧
# 按间隔采样
indices = range(0, len(vr), vr.get_avg_fps())  # 每秒1帧
frames = vr[indices].asnumpy()
```

### 3.3 采样策略

| 策略 | 方法 | 适用场景 |
|------|------|----------|
| **等间隔采样** | `range(0, n, fps)` | 通用、降采样 |
| **均匀采样** | LLaVA等模型使用的均匀帧选择 | 视频理解模型推理 |
| **关键帧提取** | select I帧/场景切换帧 | 内容检索、故事板生成 |
| **密集采样** | 连续帧 | 动作识别、跟踪 |
| **自适应采样** | 基于内容复杂度动态调整 | 长视频处理 |

## 五、视频字幕生成（Video Captioning & Subtitling）

### 5.1 字幕提取与生成

#### 方式一：直接提取已有字幕（无语音视频）

```python
# 用FFmpeg检测字幕流
ffmpeg -i input.mp4 2>&1 | grep Subtitle

# 提取SRT字幕
ffmpeg -i input.mp4 -map 0:s:0 subtitle.srt
```

#### 方式二：语音识别生成字幕（最主流）

| 工具 | 特点 |
|------|------|
| **Whisper** (OpenAI) | 支持99种语言，高精度，支持SRT/VTT格式导出；tiny/base/small/medium/large多规格 |
| **WhisperX** | Whisper + 词级时间戳对齐 + 说话人分离 |
| **FunASR** (阿里达摩院) | 中文优化，支持标点恢复，大模型版本Paraformer |
| **SenseVoice** (阿里) | 阿里自研语音识别，专为中文场景优化 |

**FFmpeg + Whisper 一键生成字幕（FFmpeg 8.0+内置Whisper滤镜）：**

```bash
ffmpeg -i input.mp4 -c:v copy -c:a aac -b:a 192k -filter_threads 4 \
  -af "whisper=model=base/lang=auto" subtitle.srt
```

**Whisper Python调用示例：**

```python
import whisper
model = whisper.load_model("base")
result = model.transcribe("audio.mp3", word_timestamps=True)
# 输出SRT
with open("subtitle.srt", "w") as f:
    for i, segment in enumerate(result["segments"]):
        f.write(f"{i+1}\n")
        f.write(f"{segment['start']:.3f} --> {segment['end']:.3f}\n")
        f.write(f"{segment['text']}\n\n")
```

**视频指纹提取示例（pHash）：**

```python
import imagehash
from PIL import Image
import cv2

def video_phash(video_path, max_frames=30):
    cap = cv2.VideoCapture(video_path)
    hashes = []
    frame_idx = 0
    while len(hashes) < max_frames and cap.isOpened():
        ret, frame = cap.read()
        if not ret: break
        if frame_idx % (int(cap.get(cv2.CAP_PROP_FPS)) or 1) == 0:
            img = Image.fromarray(cv2.cvtColor(frame, cv2.COLOR_BGR2RGB))
            hashes.append(imagehash.phash(img))
        frame_idx += 1
    cap.release()
    return hashes
```

### 6.3 语义检索与RAG

```
视频 → 帧提取 → CLIP/VLM编码 → 向量数据库(FAISS/Milvus) 
用户Query → 编码 → 向量检索 → Top-K相关片段
```

常用组合：
- **文本→视频检索**：`InternVideo2` / `CLIP4Clip` + FAISS
- **视频→视频检索**：视频指纹 + 余弦相似度
- **视频问答检索**：Molmo2 / VideoChat + Milvus

## 九、技术演进趋势（2024-2026）

```
2022-2023: CNN时代 → Transformer时代（SlowFast, TimeSformer）
2023:     SAM发布 → 视频分割成为可能
2023-2024: LLM爆发 → Video-LLM崛起（VideoChat, Video-LLaMA）
2024:     SAM2 → 视频分割实用化
2024-2025: 长视频理解突破（LongVA, StreamingVLM, InternVideo2.5）
2025:     R1推理范式进入视频（Video-R1）
2025:     多模态融合深化（Molmo 2: 视频+指向+跟踪+密集字幕）
2025-2026: 视频理解与视频生成边界模糊（Sora, Veo, Kling）
```

**核心趋势：**
1. **视频理解→视频推理**：R1范式向视频领域迁移，模型从"看视频"进化到"理解并推理视频"
2. **短视频→长视频**：长视频处理（流式推理、压缩记忆）是下一个突破点
3. **单模态→多模态融合**：视频+音频+字幕+深度的联合理解成为标配
4. **专用→通用**：从单一任务（动作识别）向通用视频助手演进

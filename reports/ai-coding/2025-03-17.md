## 代码理解框架

针对算法工程师转型 AI Coding，推荐以下理解框架:

### 1. 整体把握 (Top-Down)

```
┌─────────────────────────────────────────┐
│  1. 整体架构                              │
│     - 这个代码要解决什么问题？              │
│     - 输入 → 处理 → 输出 的流程是什么？       │
│     - 核心模块有哪些？它们的关系？           │
├─────────────────────────────────────────┤
│  2. 核心逻辑                              │
│     - 最重要的函数/类是哪个？               │
│     - 关键的数据结构是什么？                │
│     - 算法复杂度是多少？                    │
├─────────────────────────────────────────┤
│  3. 细节理解                              │
│     - 这行代码的具体作用？                  │
│     - 为什么不采用另一种写法？               │
│     - 边界条件如何处理？                    │
└─────────────────────────────────────────┘
```

### 2. AI 代码 Review 要点清单

| 检查项 | 说明 |
|--------|------|
| 逻辑正确性 | 业务逻辑是否正确实现了需求 |
| 边界条件 | 空值、越界、并发等情况 |

## AI 协作提示词模板

### 1. 请求代码解释

```
请逐行解释这段代码，重点说明：
1. 每个函数/方法的作用
2. 数据的输入、流转、输出
3. 关键的算法逻辑和实现思路
4. 如有复杂逻辑，给出简化示例
```

### 2. 请求代码 Review

```
请审查这段代码，重点关注：
1. 逻辑错误和潜在 bug
2. 边界条件处理
3. 性能问题（时间/空间复杂度）
4. 安全漏洞
5. 代码风格和可维护性

代码背景：[描述代码用途和上下文]
```

### 3. 请求优化建议

```
请分析这段代码的性能瓶颈：
1. 找出最耗时的操作
2. 给出具体的优化方案
3. 预估优化后的性能提升
4. 如涉及算法改进，解释原理
```

### 4. Plan 模式启动语

```
接下来你只做一件事：帮我整理开发计划，不要写任何代码。
1. 先列出你需要确认的问题
2. 给出分步骤的开发方案
3. 按模块划分任务，说明每块涉及哪些文件

等我对齐后，再进入写代码阶段。
```

## 实践建议

### 立即可做

1. **创建项目 CLAUDE.md**: 在根目录放置工作手册，定义代码规范和关键约束
2. **使用文件头注释**: 每个源文件加三行注释说明 INPUT/OUTPUT/POS
3. **启用 Plan 模式**: 大任务先规划再动手，减少返工
4. **建立 Code Review 习惯**: 即使是 AI 生成的代码，也要自己过一遍

### 进阶技巧

1. **多 Agent 协作**: 一个负责实现，一个负责审查，一个负责测试
2. **MCP 知识库**: 把 API 文档、设计说明放到 MCP 供 AI 查阅
3. **Custom Skills**: 把高频工作流固化成可复用的 Skill

### 心态调整

- 从"代码作者"转变为"代码架构师"
- 接受"80%正确，快速迭代" vs "100%正确，长期开发"
- 保持对关键逻辑的理解力，即使不亲自写

## 代码理解框架

### AI 代码理解四步法

```
1. 整体把握
   - 这个代码要解决什么问题？
   - 整体架构是怎样的？（输入→处理→输出）
   - 使用了什么语言和框架？

2. 核心逻辑
   - 最重要的函数/类是哪个？
   - 数据流是怎样的？
   - 核心算法是什么？

3. 细节理解
   - 这行代码做了什么？
   - 为什么不这样写？
   - 边界条件如何处理？

4. Review 要点
   - 逻辑正确性
   - 边界条件
   - 性能考虑
   - 安全问题
```

### AI 代码特殊检查清单
- [ ] 是否缺少 import 语句？
- [ ] 依赖是否完整？
- [ ] 是否有硬编码的密钥/密码？
- [ ] 代码是否符合项目规范？
- [ ] 错误处理是否完善？

**请求代码解释**:
```

1. 每个函数的作用

**请求代码 Review**:
```
请审查这段代码，重点关注：
1. 逻辑错误
2. 边界条件（空值、异常输入）
3. 性能问题（时间/空间复杂度）
4. 安全漏洞（注入、越权）
5. 代码规范和最佳实践
```

**请求优化建议**:
```
请分析这段代码的性能瓶颈，并给出：
1. 具体优化点
2. 优化后的代码
3. 优化前后的性能对比

## 实践建议

### 1. 每日练习
- 每天用 AI 生成一段代码，然后手动理解并 review
- 对比自己的理解和 AI 的解释是否一致

### 2. 分步生成
- 不要一次性生成大段代码
- 先骨架 → 核心逻辑 → 错误处理 → 测试

### 3. 建立自己的提示词库
- 收集工作中高效的提示词
- 根据项目特点定制模板

### 4. 重视测试
- 始终要求 AI 生成测试代码
- 用测试验证代码正确性

### 5. 安全意识
- 不要在提示中暴露敏感信息
- 要求 AI 检查安全漏洞

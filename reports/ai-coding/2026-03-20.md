## 三、代码理解框架

### AI 代码理解四步法

```
# AI 代码理解框架

## 1. 整体把握 (5分钟)
- 这个代码要解决什么问题？
- 整体架构是怎样的？（输入→处理→输出）
- 来自 AI 的哪个部分？（Copilot / ChatGPT / Claude）

## 2. 核心逻辑 (10分钟)
- 最重要的函数/类是哪个？
- 数据流是怎样的？
- 调用链路是什么？

## 3. 细节理解 (10分钟)
- 这行代码做了什么？
- 为什么不这样写？（问 AI）
- 潜在的边缘情况？

## 4. Review 要点checklist
□ 逻辑正确性 - 功能真能实现吗？
□ 边界条件 - 空值、越界、并发？
□ 性能考虑 - 大数据量会挂吗？
□ 安全问题 - 注入、越权、密钥？
□ 依赖审查 - 包真的存在吗？维护状态？
□ AI 特定陷阱 - 幻觉 API？删除测试而非修复？
```

### 审查 AI 代码的 8 个技巧（GitHub 官方）

1. **从功能检查开始** - 运行测试和静态分析
2. **验证上下文和意图** - 对照原始需求
3. **评估代码质量** - 可读性、可维护性
4. **仔细审查依赖** - 包是否存在？许可证？
5. **识别 AI 特定陷阱** - 幻觉 API、删测试不修
6. **使用协作审查** - 团队 Code Review
7. **自动化可自动的** - CI/CD lint/安全扫描
8. **持续改进工作流** - 记录最佳实践

## 四、AI 协作技巧

### 高效 Prompt 模板（BROKE 框架）

| 要素 | 英文 | 比喻 | 示例 |
|------|------|------|------|
| 角色 | Role | 类定义 | "你是一位 10 年经验的 Spring 架构师" |
| 背景 | Background | 上下文/字段 | "我们正在将 JSP 单体迁移到微服务" |
| 目标 | Objective | 方法名 | "请重构这段代码" |
| 约束 | Key Constraints | 接口/配置 | "用 Java 17 Record，不用 Lombok" |
| 示例 | Examples | 单元测试 | "输入 JSON，输出实体类，像这样..." |

### 场景化提示词模板

```
## 请求代码解释
"请逐行解释这段代码，重点说明：
1. 每个函数的作用
2. 数据的流向
3. 关键的算法逻辑
4. 可能的边缘情况"

## 请求代码 Review
"请审查这段代码，重点关注：
1. 逻辑错误
2. 边界条件（空值、越界）
3. 性能问题
4. 安全漏洞（注入、硬编码密钥）
5. AI 特定陷阱（幻觉 API、删除测试）"

## 请求优化建议
"请分析这段代码的性能瓶颈，并给出优化建议。
使用 Java 21 VirtualThreads 重写。"

## 请求 TDD 开发
"我们使用 TDD。请先写一个失败的测试，验证 [具体需求]。
然后我会确认测试，再让你写实现代码。"
```

## 五、实践建议

### 每日练习

1. **晨间 10 分钟**: 用 AI 生成代码，自己复述理解
2. **代码审查**: 至少找一处 AI 代码的潜在问题
3. **Prompt 迭代**: 同一个需求，改三版 Prompt 对比结果

### 关键原则

> **2025 年最优秀的开发者不是用 AI 生成最多代码的人，而是知道何时信任它、何时质疑它以及如何负责任地集成它的人。**

- ✅ AI 是结对编程伙伴，不是自动驾驶仪
- ✅ 小增量生成，每次集成后测试
- ✅ 验证意图，不仅仅是语法
- ✅ 人工代码审查不可替代
- ✅ 持续学习，每周更新工具箱

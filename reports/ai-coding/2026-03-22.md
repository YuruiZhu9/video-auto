## 二、核心资源深度解读

### 资源 1：Navigator/Driver 七步工作流

**来源**: [AI Pair Programming Complete Guide 2026](https://aiproductivity.ai/blog/ai-pair-programming-guide/)（2026年1月最新数据）

**核心洞察**：
- **65%** 的专业开发者定期使用 AI 编程助手
- AI 结对编程提速基准：**CRUD 任务 50-70%**，**新功能 25-40%**，**重构 40-60%**

**Navigator/Driver 角色分配：**

| 角色 | 你（Navigator）做什么 | AI（Driver）做什么 |
|------|----------------------|-------------------|
| **你主导** | 定义"做什么"（需求、目标、约束） | 实现"怎么做"（语法、模板、样板代码） |
| **AI 主导** | 学习新模式（让 AI 解释，自己敲代码） | 安全关键代码（自己写，AI 只 review） |
| **混合** | 性能调优（先 profile，再让 AI 优化） | 遗留代码重构（你理解奇癖，AI 做机械改动） |

**七步工作流（可直接套用）：**

```
Step 1: 写清楚规格说明
  // 创建一个函数：
  // 1. 从 /api/users/:id 获取用户数据
  // 2. 处理 loading 和 error 状态
  // 3. 实现指数退避重试（最多 3 次）
  // 4. 返回类型化 User 对象或抛出描述性错误

Step 2: 让 AI 生成初版代码

Step 3: 审查逻辑错误（必须做！）
  - 循环/数组索引的 off-by-one
  - 缺失的 null 检查
  - 错误的 async/await 模式
  - 安全漏洞

Step 4: 用具体反馈精修
  ❌ "修复这个问题"
  ✅ "重试逻辑没有实现指数退避，请添加延迟倍增：1s→2s→4s"

Step 5: 明确要求边界情况处理

Step 6: 生成测试（但自己验证覆盖率）

Step 7: 文档化复杂逻辑
```

### 资源 2：用 Cursor 快速理解复杂代码工程

**来源**: [如何利用 Cursor 快速理解复杂代码工程？- 知乎](https://www.zhihu.com/question/7468595725)（作者：笙囧同学，国科大硕士）

**核心原则**：
> **主动探索，而非被动接收** — 让 AI 帮助克服你在代码探索中遇到的障碍，而非让 AI 替你总结一切。

**六步系统方法（强烈推荐）：**

#### Step 1：从一个具体问题开始
不要问"架构是什么"，要问**数据流路径**：

```
❌ "这个项目整体架构是什么？核心模块、设计模式、数据流、关键算法都讲一下"
✅ "推理请求从进入系统到返回结果，经历了哪些步骤？"
✅ "当我执行 @app.get('/users') 时，FastAPI 是如何把这个装饰器变成能处理 HTTP 请求的东西的？"
✅ "执行 SET key value 时，从接收到命令到写入内存之间发生了什么？"
```

#### Step 2：找到入口点
```
入口点在哪里？用户发起请求时，从哪个文件和函数开始执行？
只需要告诉我文件路径和函数名，不需要细节。
```
（只给路径不给解释，避免信息过载）

#### Step 3：追踪调用链
遇到不熟悉的函数调用时：
```
这个函数做了什么？用 1-2 句话总结核心职责，然后告诉我它定义在哪个文件。
```
- 答案保持简短——只需判断走哪条路径
- 跳过非必要分支（日志、参数校验、缓存检查）
- 问"哪一行执行了核心逻辑？"来找到主线

#### Step 4：处理陌生的技术栈
```
我不懂 CUDA 编程。请用我能理解的方式解释这段代码在做什么——
不要解释 CUDA 语法细节，只告诉我它的输入、输出和执行了什么计算。
用 Python 思维来解释。
```

#### Step 5：画地图（做笔记）
创建一个 markdown 文件记录你的探索路径：
```markdown
## 推理请求路径
1. 入口：LLM.generate() (vllm/entrypoints/llm.py)
   - 接收用户 prompt，封装成 SequenceGroup
2. 调度器：Scheduler.schedule() (vllm/core/scheduler.py)
   - 决定哪些请求可以处理
3. 执行器：ModelRunner.execute_model() (vllm/worker/model_runner.py)
   - 批处理请求，运行模型前向传播
4. 采样器：Sampler.forward() (vllm/model_executor/layers/sampler.py)
   - 从 logits 中采样下一个 token
```

#### Step 6：在关键节点深入
- **粗粒度阶段**：问"是什么 + 在哪里"——总结每个组件做什么、在哪里
- **细粒度阶段**：问"怎么做 + 为什么"——具体实现细节和设计理由
- 遵循**"先粗后细"**的节奏

**不同类型项目的最佳探索路线：**

| 项目类型 | 最佳探索主线 |
|----------|------------|
| Web 框架（FastAPI/Express/Gin） | HTTP 请求生命周期：监听→接收→路由→中间件→处理器→响应 |
| 数据库（Redis/LevelDB/SQLite） | 写操作路径：命令解析→数据结构操作→内存写入→磁盘持久化 |
| AI 框架（vLLM/DeepSpeed/PyTorch） | 前向传播：数据预处理→模型加载→计算→后处理 |
| 编译器/解释器（CPython/V8/GCC） | 源代码路径：词法分析→语法分析→AST→IR→优化→代码生成/执行 |

### 资源 3：AI 安全边界——绝对不能让 AI 写的代码

**来源**: [AI Pair Programming Guide](https://aiproductivity.ai/blog/ai-pair-programming-guide/) + [AI Pair Programming 2025 Case Studies](https://logiciel.io/blog/pair-programming-with-ai-best-practices-case-studies-2025)

**🚨 绝对不要让 AI 独立生成的代码：**
- 认证逻辑（密码哈希、Token 验证）
- 权限检查（RBAC）
- 加密操作
- 拼接用户输入的 SQL 查询
- 处理敏感数据的 API 端点

**AI 可以辅助（但需人工验证）：**
- 正确使用安全库（after verification）
- 添加输入验证
- 编写安全测试
- 检查常见漏洞

**两轮 Review 系统：**
```
第一轮 AI Review：
"请检查这段代码是否有 SQL 注入、XSS、CSRF、认证绕过风险"

第二轮 人工 Review：
手动验证所有安全敏感逻辑
```

## 三、代码理解实用模板

### 模板 1：复杂代码理解四步法

```markdown
# 复杂代码理解框架

## 第一步：定位入口（What + Where）
- 问题：这段代码要解决什么？
- 入口点：main / API handler / __init__
- 输出：文件路径 + 函数名（不做解释）

## 第二步：追踪主线（Call Chain）
对每个关键函数，记录：
- 核心职责（1-2 句话）
- 输入 → 输出
- 所在文件

## 第三步：识别关键节点
- 哪一行执行了核心计算/逻辑？
- 有哪些分支/条件判断？
- 异常路径是什么？

## 第四步：复现验证
- 写一个最小可运行示例
- 打断点，跟踪执行流程
- 预期行为 vs 实际行为的差异 → 最宝贵的学习机会
```

- [ ] 性能（循环、重复计算、内存泄漏）

## 算法专项（根据你的方向选择）
### 推荐系统方向

## 四、AI 协作高效提示词模板库

### 模板 1：让 AI 帮你理解陌生代码
```
我正在看一个 [项目类型，如：推荐系统排序模块]，
请帮我追踪从 [输入，如：用户点击日志] 到 [输出，如：排序分数] 的数据流。
先告诉我入口文件和关键函数名，不需要细节解释。
```

### 模板 2：让 AI 解释算法逻辑
```
请用 [你熟悉的语言，如：Python] 思维来解释这个 [你不熟悉的语言，如：CUDA] 代码：
- 输入是什么
- 输出是什么
- 执行了什么计算
不要解释语法细节，专注于计算逻辑。
```

### 模板 3：让 AI 帮你做 Code Review
```
请审查这段 [语言] 代码，重点关注：
1. 逻辑错误和潜在 bug
2. 边界条件和异常处理
3. 性能问题（时间/空间复杂度）
4. 安全漏洞（注入、认证、敏感数据）
5. [我的特殊关注点，如：推荐系统中 itemCF 的相似度计算是否正确]

请逐文件/逐函数给出具体问题和建议。
```

### 模板 4：让 AI 生成测试用例
```
请为这个函数生成单元测试，覆盖：
1. 正常输入（预期输出）
2. 边界条件（空输入、最大输入、极端值）
3. 异常输入（错误类型、无效格式）
4. 并发场景（如适用）

测试框架：[你的框架，如：pytest]
```

### 模板 5：当 AI 给了错误答案时
```
你的上一次回答可能有问题（或者我理解错了）。
请重新考虑：
1. 简化这个问题：[把复杂任务拆成小步骤]
2. 提供更多上下文：[展示相关代码片段]
3. 给出 3 种不同的实现方式，说明各自的权衡
```

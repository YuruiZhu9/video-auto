## 一、核心资源汇总

### 📄 论文精读：Prompt Engineering for Code Reliability（arXiv:2506.10989）

**发布时间**：2025年3月19日（极新！）  
**核心结论**：专门设计的提示模板，比 Zero-shot 和 Chain-of-Thought（CoT）方法效果更好、token 消耗更低。

| 方法 | 代码通过率 | Token 消耗 | 推荐度 |
|------|-----------|-----------|--------|
| Zero-shot | 基线 | 中 | ⭐⭐ |
| Chain-of-Thought | 较高 | 高 | ⭐⭐⭐ |
| **本文模板方法** | **最优** | **显著低于CoT** | ⭐⭐⭐⭐⭐ |

**算法工程师启示**：与其花更多 token 让 AI"思考"，不如精心设计 prompt 结构。用**结构化指令**替代**长篇思维链**。

---

### 📝 实战指南：如何高效利用 AI 进行编程（掘金）

**核心要点**：

1. **让 AI 理解你的需求**：简明扼要、直击重点；保持上下文一致；逐步引导而非一次性抛出
2. **让 AI 参与架构设计**：先让 AI 给出多种方案对比，再做选择
3. **代码质量把控三板斧**：Linter 统一风格 → AI 解释代码逻辑 → AI 提供优化建议
4. **AI 结对编程工作流**：明确需求 → AI 设计方案 → 多次迭代生成 → 代码实现与调试

---

### 💡 AI 时代协作方法论（博客园）

**五大协作原则**：

- ✅ 明确需求：模糊问题 → 模糊答案，具体描述 → 精确代码
- ✅ 迭代对话：不求一次到位，持续微调
- ✅ 善用上下文：多轮对话中保持项目整体结构
- ✅ 批判性思维：验证关键代码，理解而非盲从
- ✅ 建立工作流：AI 做初稿，人工精修；AI 做头脑风暴，人工决策

## 二、本期专题：结构化 Prompt 模板

### 2.1 代码生成请求模板

```
## 【角色设定】
你是一位 [语言/框架] 专家，擅长编写高质量、生产级别的代码。

## 【任务目标】
请为以下需求生成代码：[具体描述要解决的问题]

## 【约束条件】
- 输入：[描述输入格式]
- 输出：[描述输出格式]
- 性能要求：[如有]
- 依赖限制：[如只能使用标准库]

## 【质量要求】
1. 代码必须可直接运行
2. 添加必要的注释说明关键逻辑
3. 包含错误处理
4. 避免常见的 [语言] 反模式
```

### 2.2 代码 Review 请求模板

```
## 【代码审查请求】
请审查以下代码，重点关注：
1. 逻辑正确性：是否有 bug 风险？
2. 边界条件：是否处理了空值/异常输入？
3. 性能问题：是否有 O(n²) 或不必要的循环？
4. 安全漏洞：是否有注入风险？
5. 可维护性：命名是否清晰？结构是否合理？

## 【代码】
[粘贴代码]

## 【审查背景】
这段代码用于：[描述业务场景]
```

### 2.3 调试请求模板

```
## 【问题描述】
我在开发 [项目/功能] 时遇到以下问题：
- 预期行为：[描述期望结果]
- 实际行为：[描述错误现象]
- 错误信息：[粘贴错误日志]

## 【已尝试的方法】
1. [尝试过的解决方案]
2. [结果]

## 【环境信息】
- 语言/框架版本：
- 相关配置：
```

### 2.4 架构设计请求模板

```
## 【设计需求】
需要设计 [系统/模块]，核心功能：
1. [功能点1]
2. [功能点2]

## 【约束条件】
- 规模：[小/中/大型]
- 技术栈限制：
- 性能要求：

## 【请输出】
1. 推荐的架构方案（给出 2-3 种对比）
2. 各方案的优缺点分析
3. 最终推荐及理由
```

## 三、AI 代码理解四步框架

当 AI 生成了你不熟悉的代码时，用这个框架逐步理解：

### Step 1：整体把握（What & Why）
- **这个代码要解决什么问题？**
- **整体架构是怎样的？** 输入 → 处理 → 输出

### Step 2：核心逻辑（Core）
- **最重要的函数/类是哪个？**
- **数据流是怎样的？**（沿变量传递路径追踪）

### Step 3：逐行理解（Details）
- **这行代码做了什么？**
- **为什么不这样写？**（尝试理解设计决策）

### Step 4：Review 要点
- [ ] 逻辑正确性
- [ ] 边界条件处理
- [ ] 性能考虑（时间/空间复杂度）
- [ ] 安全问题（注入/越界/泄漏）
- [ ] 可测试性

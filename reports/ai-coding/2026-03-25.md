### 📖 资源 3：如何审讯（理解）陌生代码
**来源：** [Stack Overflow Blog](https://stackoverflow.blog/2022/08/15/how-to-interrogate-unfamiliar-code/)

**核心要点（必学！）：**
1. **至少读两遍**：第一遍扫轮廓，第二遍逐行抠细节
2. **IDE 是你最好的朋友**：语法高亮、跳转到定义、查看引用、静态分析
3. **重构变量名**：把 `x`, `tmp` 重命名为有意义的名字，暴露真实逻辑
4. **运行单测**：测试比脑内模拟更可靠，证明代码"实际上"怎么跑
5. **用调试器**：设置断点单步跟踪，观察变量实际值
6. **Git Blame**：追溯作者和 commit 上下文，理解"为什么这么写"
7. **橡皮鸭调试法**：向一个假想对象解释代码，常能发现盲点

**点评：** 策略系统全面，特别适合算法工程师阅读推荐系统等复杂代码库

## 三、代码理解框架（可直接使用）

### 🧠 四步理解法

```
第一步：问目的（Why）
  ├── 这个代码解决什么问题？
  ├── 输入是什么，输出是什么？
  └── 谁在调用它，什么场景下？

第二步：看架构（What）
  ├── 核心文件/类是哪个？
  ├── 数据流向是怎样的？（输入→处理→输出）
  └── 依赖了哪些外部库/模块？

第三步：抠细节（How）
  ├── 逐行理解关键函数
  ├── 为什么要这样写？（不只是怎么写）
  └── 边界条件和异常处理在哪里？

第四步：做 Review（Review）
  ├── 逻辑正确性：这段代码真的能完成目标吗？
  ├── 边界条件：空输入、大数据量会崩吗？
  ├── 性能：时间/空间复杂度是否可接受？
  ├── 安全：有没有注入、越权风险？
  └── 可维护：变量命名清晰吗？注释够吗？
```

### 📋 AI 代码 Review 清单（算法工程师专用）

| 检查项 | 重点问题 |
|--------|----------|
| **算法正确性** | 逻辑是否符合数学/机器学习原理？ |
| **数值稳定性** | 浮点溢出、除零、梯度消失/爆炸？ |
| **数据处理** | 缺失值、异常值、类型转换是否处理？ |
| **训练/推理一致** | train 和 inference 代码逻辑是否对齐？ |
| **可复现性** | 随机种子是否固定？超参是否暴露？ |
| **线上性能** | 延迟、吞吐量是否满足 SLA？ |
| **可扩展性** | 新增特征/模型是否容易扩展？ |

## 四、高质量 AI 协作提示词模板

### 🤖 请求代码解释
```
请逐行解释下面这段代码，重点说明：
1. 每个函数/类的职责是什么
2. 数据在各函数之间是如何流动的
3. 关键的算法逻辑是什么
4. 有什么需要注意的边界条件

[粘贴代码]
```

### 🔍 请求代码 Review
```
请审查以下推荐系统代码，重点关注：
1. 逻辑错误或算法实现问题
2. 缺失的边界条件处理
3. 数值稳定性（溢出、除零等）
4. 训练/推理代码一致性
5. 性能瓶颈和优化建议
6. 安全漏洞（注入、数据泄露等）

[粘贴代码]
```

### 🚀 请求代码优化
```
请分析这段代码的性能瓶颈，给出：
1. 时间复杂度分析
2. 空间复杂度分析
3. Top 3 优化建议（附具体代码修改）
4. 如果涉及矩阵运算，是否可以用 GPU 加速？

[粘贴代码]
```

### 📐 请求生成测试
```
请为以下函数生成单元测试，覆盖：
1. 正常输入
2. 边界值（空列表、单元素、极大值）
3. 异常输入（类型错误、None）
4. 性能测试（大数据量时的运行时间）

[粘贴函数代码]
```

```
1. 最可能的原因是什么？
2. 需要检查哪些变量/中间结果？
3. 具体的 debug 步骤是什么？

[粘贴代码]
[附上错误信息/日志]
```

## 五、实践建议（本期重点）

### ✅ 今天就可以做的 3 件事

**1. 设置你的 IDE 代码理解工具链**
- 安装插件：语法高亮、跳转到定义、查看引用、Git Blame
- 学会用调试器单步跟踪（推荐：VS Code + Python 调试器）
- 激活"格式化文档"快捷键，一键看清代码结构

**2. 用"四步理解法"读一个 AI 生成的代码片段**
- 找一段你之前让 AI 生成的代码
- 用四步法走一遍：问目的 → 看架构 → 抠细节 → 做 Review
- 对照：你真的理解这段代码了吗？哪里有疑问？

**3. 改进你的下一个 AI 提示词**
- 避免模糊请求（"帮我写个排序"）
- 明确：语言 + 输入类型 + 约束条件 + 边界情况
- 用模板：`请用 [语言] 实现 [功能]，输入是 [类型]，要求 [约束]`

### ⚠️ 常见误区

| 误区 | 正确做法 |
|------|----------|
| 直接复制 AI 代码到生产环境 | 先理解，再验证，最后提交 |
| 问"这段代码对不对" | 问"这段代码在 X 场景下会不会有问题" |
| 一次问太多需求 | 拆分成多个聚焦的小问题 |
| 不看 AI 的中间步骤 | 让 AI 先解释思路，再生成代码 |
| 完全相信 AI 的优化建议 | 用 profiling 工具实测性能再做决定 |

## 一、核心认知框架

### AI Coding 的本质定位

来自 Nx (Victor Savkin) 的研究给出了关键结论：

> **"AI 可能写代码，但你为每一行代码负责。"**
> **"高效使用 AI = 更多思考和阅读，更少打字。"**

| 指标 | 预期收益 |
|------|----------|
| 编码生产力提升 | 10–30% |
| 内容创作速度 | 30–50% |
| 文档编写成本 | 降低 10 倍 |

**重要提醒：** AI 生成的代码看起来正确，可能隐藏逻辑缺陷（如排序在重复元素时失效）。**永远不要提交你不理解的代码。**

## 二、顶级资源汇总与点评

### 1. DEV Community — "AI Coding Best Practices 2025"
**推荐指数：** ⭐⭐⭐⭐⭐
**核心要点：**
- 把 AI 当「初级开发者」而非自动驾驶仪
- 每行代码生成后立即 review
- 用 TDD 思维：先写测试，再集成 AI 代码
- 工具选型指南：

| 场景 | 推荐工具 |
|------|----------|
| 内联代码补全 | GitHub Copilot |
| 大段重构 / 知识库查询 | Copilot Agent / Claude |
| 架构咨询 / 调试解释 | ChatGPT |
| 终端快速原型 | Gemini CLI |

### 2. Graphite — "Best Practices for AI Coding Assistants"
**推荐指数：** ⭐⭐⭐⭐
**核心要点：**
- 提示词三要素：**具体 + 有上下文 + 有约束**
- AI 最擅长的任务：样板代码、文档生成、单元测试、代码重构
- 陷阱：过度依赖 → 代码失控；缺乏理解 → 无法维护

### 3. Vibe Coding Today — "Debugging, Refactoring & Code Review"
**推荐指数：** ⭐⭐⭐⭐⭐
**核心要点（专为 Vibe Coding 用户设计）：**
- **Debugging 陷阱：** AI 修表面不修根因；在微服务场景容易"管中窥豹"
- **Refactoring 陷阱：** 过度简化可能抹掉关键业务逻辑；改一处文件导致架构不一致
- **Code Review 陷阱：** AI 可能漏掉微妙 bug 或误报正常代码
- **核心原则：** AI 处理快、浅、常规任务；人类处理慢、深、判断性任务

### 4. Engify.ai — "Prompt Engineering for Code Generation"
**推荐指数：** ⭐⭐⭐⭐
**核心要点（提示词模板组合）：**
- 最强组合：**Persona + 思维链 + Few-Shot** 三合一
- 必须明确：语言 + 框架 + 版本
- 必须明确：输入类型 + 输出类型
- 必须明确要求：错误处理、输入校验、安全实践
- 必须要求：JSDoc + 注释 + 示例用法

### 5. Nx (Victor Savkin) — "AI as Your Peer Programmer"
**推荐指数：** ⭐⭐⭐⭐⭐
**核心要点：**
- 核心工作流：**Plan → Act → Review → Repeat**
- 常见错误：跳过 Plan 或跳过 Review
- **会话管理：** 保持聊天简短，防止上下文漂移；每个任务开新对话
- **幻觉应对：** 感觉太完美时追问"Are you sure?"往往触发自我纠正
- **AI 最强场景：** 测试生成（线性、公式化）、文档编写、代码翻译
- **AI 较弱场景：** 复杂分布式系统调试、深度业务逻辑理解

## 三、代码理解框架（实用模板）

```
┌─────────────────────────────────────────────────────────────┐
│              AI 代码理解四步法                                │
├─────────────────────────────────────────────────────────────┤
│  第一步：整体把握                                            │
│  ─────────────                                              │
│  • 这段代码要解决什么问题？                                    │
│  • 整体架构是怎样的？输入 → 处理 → 输出                       │
│  • 涉及哪些文件/模块？它们之间的关系？                        │
│                                                             │
│  第二步：核心逻辑                                            │
│  ─────────────                                              │
│  • 最重要的函数/类是哪个？                                   │
│  • 数据从哪来、流向哪去？                                    │
│  • 主要算法/模式是什么？                                     │
│                                                             │
│  第三步：逐行理解                                            │
│  ─────────────                                              │
│  • 这一行在做什么？                                          │
│  • 为什么要这样写，换一种方式行吗？                          │
│  • 边界条件和异常情况有哪些？                                │
│                                                             │
│  第四步：Review 要点                                        │
│  ─────────────                                              │
│  □ 逻辑正确性：算法是否符合预期？                            │
│  □ 边界条件：空输入、极端值如何处理？                        │
│  □ 性能考虑：时间/空间复杂度可接受吗？                       │
│  □ 安全问题：注入、越界、硬编码敏感信息？                    │
│  □ 可维护性：命名清晰、注释充分、结构合理？                  │
└─────────────────────────────────────────────────────────────┘
```

## 四、AI 协作提示词模板库

### 模板 A：请求代码解释
```
请逐行解释以下代码，重点说明：
1. 每个函数/方法的作用是什么
2. 数据的流向是怎样的（输入→处理→输出）
3. 关键的算法逻辑是什么，有没有更优解
4. 可能的边界条件和潜在 bug

[粘贴代码]
```

### 模板 B：请求代码 Review
```
请审查以下代码，重点关注：
1. 逻辑错误（与需求不符的地方）
2. 边界条件（空值、极端值、类型转换）
3. 性能问题（循环、查询复杂度、不必要的复制）
4. 安全漏洞（注入、硬编码、权限问题）
5. 代码风格不一致之处

[粘贴代码]
```

### 模板 C：请求 Bug 定位
```
请分析以下报错信息，定位根因并给出修复方案：

【报错信息】
[粘贴错误日志]

【相关代码】
[粘贴代码]

请说明：
1. 最可能的根因是什么
2. 如何修复
3. 如何避免类似问题
```

### 模板 D：请求优化建议
```
请分析以下代码的性能瓶颈，并给出优化建议：

[粘贴代码]

请说明：
1. 当前代码的时间和空间复杂度
2. 最大的性能瓶颈在哪里
3. 优化方案（含代码示例）
4. 优化后的预期提升
```

### 模板 E：请求测试用例生成
```
请为以下函数生成单元测试用例：

[粘贴函数代码]

要求：
1. 覆盖正常输入
2. 覆盖边界条件（空值、零值、负数等）
3. 覆盖异常输入
4. 使用 [pytest / JUnit / Jest] 框架
5. 每个测试用例要有清晰的名称和注释
```

## 五、Vibe Coding 场景专项指南

### 什么时候 AI 代码最危险？

| 场景 | 风险等级 | 原因 |
|------|----------|------|
| 复杂遗留系统 | 🔴 高 | AI 无法理解数十年积累的业务逻辑 |
| 跨服务微服务调试 | 🔴 高 | 缺乏全系统上下文，容易瞎猜 |
| 性能关键路径 | 🟡 中 | 微妙优化可能出错 |
| 金融/医疗合规代码 | 🔴 高 | 需要人类专家审查 |
| 样板代码/文档/测试 | 🟢 低 | AI 效果极佳 |

### AI review 作为第一轮 + 人类 review 作为终审

```
第一轮：AI review（快速、全局）
  → 安全扫描、风格检查、未用代码、重复代码

第二轮：人类 review（深度、判断性）
  → 业务逻辑、性能架构、安全敏感部分
```

## 六、本周实践建议

### 本周行动清单（算法工程师视角）

1. **✅ 今天开始用** — 对任何 AI 生成的代码，要求 AI 解释"这一步在做什么"，直到你能自己复述
2. **✅ 建立自己的提示词模板库** — 收藏本文的 5 个模板，按需调用
3. **✅ 用代码理解四步法** — 下次拿到新代码，先用四步框架拆解，不要直接运行
4. **✅ 每周做一次代码 review** — 找一段 AI 写的代码（或开源代码），自己 review 后再让 AI review，对比差异
5. **✅ 警惕"完美感"** — AI 代码越漂亮，越要追问"Are you sure?"

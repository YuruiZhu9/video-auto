## 三、代码理解框架

### 🔍 AI 代码理解四步法

```
┌─────────────────────────────────────────────────────────┐
│                 AI 代码理解框架                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  第1步：整体把握                                         │
│  ├─ 这个代码要解决什么问题？                              │
│  ├─ 整体架构是怎样的？（输入→处理→输出）                 │
│  └─ 用到了哪些关键库/框架？                               │
│                                                         │
│  第2步：核心逻辑                                         │
│  ├─ 最重要的函数/类是哪个？                               │
│  ├─ 数据流是怎样的？（追踪变量传递路径）                  │
│  └─ 算法的时间/空间复杂度？                              │
│                                                         │
│  第3步：细节理解                                         │
│  ├─ 这行代码做了什么？逐步分解                            │
│  ├─ 为什么不这样写？（对比其他方案）                      │
│  └─ 边界条件和异常处理是否完整？                         │
│                                                         │
│  第4步：Review 要点                                      │
│  ├─ 逻辑正确性：数学证明 vs 代码实现一致吗？              │
│  ├─ 边界条件：空输入、极端值处理                          │
│  ├─ 性能考虑：是否有 O(n²) 可以优化成 O(n log n)？       │
│  ├─ 安全问题：注入、XSS、敏感数据暴露？                   │
│  └─ 可维护性：命名清晰、注释充分、模块化？                │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 📋 代码审查自检清单（适合 AI 辅助）

**逻辑正确性：**
- [ ] 算法逻辑与数学定义是否一致？
- [ ] 循环边界是否正确（start/end）？
- [ ] 条件判断是否覆盖所有情况？

**边界条件：**
- [ ] 空输入、None、0、空字符串处理？
- [ ] 最大值溢出风险？（如 int32 max + 1）
- [ ] 递归深度限制？

**性能考虑：**
- [ ] 是否有嵌套循环（可能的 O(n²)）？
- [ ] 是否有重复计算（考虑 memoization）？
- [ ] 数据结构选择是否最优？

**安全问题：**
- [ ] 用户输入是否经过验证？
- [ ] 是否有 SQL 注入/XSS 风险？
- [ ] 敏感数据是否明文存储/传输？

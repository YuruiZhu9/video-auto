## 二、核心资源汇总

### 1. 🔗 [DEV.to - AI Coding Best Practices in 2025](https://dev.to/ranndy360/ai-coding-best-practices-in-2025-4eel)

**一句话点评**：2025 AI Coding 实战必读，10 条原则覆盖了从工具选型到安全审查的全流程。

**核心要点**：
- 把 AI 当作"初级配对程序员"，不是自动驾驶仪
- 小步迭代（生成小块代码 + 立即测试）
- 警惕 AI 的"逻辑看起来对但实际错"陷阱
- 安全审查不能外包给 AI（注入、密钥、权限）
- 保持人工 Code Review 不等于降低标准

**适用动作**：把这些原则写进你的个人开发规范

---

### 2. 🔗 [Nx.dev - A Practical Guide on Effective AI Use](https://nx.dev/blog/practical-guide-effective-ai-coding)

**一句话点评**：最系统的 AI 协作方法论，核心是 **Plan → Act → Review → Repeat** 循环。

**核心要点**：
- 预期收益：编码速度提升 10-30%（小团队收益更大）
- AI 最擅长：测试生成（线性、公式化）、代码重构、文档编写
- 会话管理：保持短会话，用 `/compact` 防止上下文漂移
- 幻觉处理：答案太完美时追问"你确定吗？"
- 编码风格：保持代码风格一致，AI 对风格一致的代码生成质量更高

**适用动作**：建立自己的 `STANDARDS.md`，让 AI 每次参考

---

### 3. 🔗 [Stack Overflow Blog - How to Interrogate Unfamiliar Code](https://stackoverflow.blog/2022/08/15/how-to-interrogate-unfamiliar-code/)

**一句话点评**：代码阅读的核心心法——理解优先，写代码其次。

**核心要点**：
- 代码阅读与代码写作是完全不同的技能
- 第一遍：建立整体轮廓，10 分钟写一句话总结
- 第二遍：逐行追踪参数值、返回值、外部调用
- 用 IDE 重命名模糊变量（几乎零风险）
- 用 Git Blame 追溯上下文：找到原始作者、Commit 记录、关联 Issue
- Debugger 是理解代码最好的工具之一

**适用动作**：养成用 Debugger 理解陌生代码的习惯，而不是只看

---

### 4. 🔗 [Mavigadget - Demystifying Code: Your Friendly Guide to Reading Any Codebase](https://blog.mavigadget.com/demystifying-code-your-friendly-guide-to-reading-any-codebase/)

**一句话点评**：大型代码库阅读的渐进式路径图，从 README 到具体功能的完整地图。

**核心要点**：
- Phase 1：先看 README + 目录结构 + 依赖配置，理解"为什么"
- Phase 2：以一个具体功能/端点为单位追踪，不要试图理解全部
- Phase 3：建立个人代码笔记，记录理解过程和困惑点
- 测试是最好的文档——输入输出、边界 case 全在里面
- 用画图工具画组件图、时序图、数据流图

**适用动作**：追踪一个具体功能，用 Debugger + 打印日志验证理解

## 三、代码理解框架（本期重点）

### 三层渐进法

| 层次 | 目标 | 方法 |
|------|------|------|
| **宏观层** | 建立整体认知 | README、入口文件、目录结构、依赖配置 |
| **中观层** | 追踪核心路径 | 选一个功能点，追踪输入→处理→输出 |
| **微观层** | 理解每行逻辑 | Debug 断点、单步执行、变量观察 |

### AI 生成代码专项检查

| 检查项 | 危险信号 |
|--------|---------|
| 幻觉调用 | 引用了不存在的 API/库 |
| 命名漂移 | 与项目风格不一致 |
| 安全漏洞 | 未参数化查询，硬编码密钥 |
| 逻辑错误 | 看起来对，跑起来不对 |
| 边界缺失 | 空值/极端值没有处理 |

## 四、AI 协作技巧（本期重点）

### 4.1 提示词黄金模板

```
【代码解释】
请逐行解释，重点说明：函数作用、数据流向、算法逻辑、隐式假设。

【Code Review】
按清单审查：逻辑正确性 → 边界条件 → 性能 → 安全 → 风格一致性。

【Debug】
粘贴完整错误信息，让 AI 定位根源 + 给出修复 + 解释原因。

【代码生成】
先说思路 → 确认后生成 → 小步迭代 → 立即测试。
```

### 4.2 会话管理原则

- ❌ 不要在一个会话里讨论多个模块
- ✅ 大任务先 Plan，执行完 Review，发现问题回到 Plan
- ✅ 用 AI 总结当前会话关键结论，再开新会话
- ✅ 遇到"太完美的答案"立刻追问

### 4.3 AI 幻觉应对

> 当 AI 给出一个看起来完美无缺的答案 → 立即追问：
> "你确定吗？这个 API 在所有版本中行为一致吗？有没有我需要补充的上下文？"

## 五、实践建议（本周行动）

### 本周 3 件事

1. **📝 建立你的 STANDARDS.md**
   - 整理项目的命名规则、错误处理规范、测试要求

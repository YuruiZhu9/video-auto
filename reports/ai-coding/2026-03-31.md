## 🧠 代码理解框架

### AI 代码理解四步法（改编自 Stack Overflow + Claude Code）

```
## 1. 整体把握（What & Why）
- 这段代码要解决什么问题？（给 AI 看：描述你看到的问题场景）
- 整体架构是怎样的？输入 → 处理 → 输出
- 有没有 README 或文档？

## 2. 核心逻辑（Core & Flow）
- 最重要的函数/类是哪个？
- 数据从哪里来，往哪里去？
- 控制流是怎样的？（分支、循环、递归）

## 3. 细节理解（Line by Line）
- 逐行分析：每个变量、每个调用在做什么
- 用 AI 解释：把有疑问的代码片段粘贴给 AI，逐段要解释
- 追踪外部依赖：hover 查看库函数文档

## 4. Review 要点（Quality Gates）
- [ ] 逻辑正确性：这个算法真的能解决这个问题吗？
- [ ] 边界条件：空输入、最大输入、异常输入会怎样？
- [ ] 性能考虑：有没有 O(n²) 或隐藏的全表扫描？
- [ ] 安全问题：注入、硬编码密钥、越权访问？
- [ ] 代码风格：和项目规范一致吗？
```

## 💬 AI 协作提示词模板

### 模板 1：请求代码解释
```
请逐行解释以下代码，重点说明：
1. 每个函数/方法的作用（用一句话）
2. 数据流向（输入 → 处理 → 输出）
3. 关键的算法逻辑或业务规则
4. 潜在的边界条件或异常

【粘贴代码】
```

### 模板 2：请求代码 Review
```
请审查以下代码，重点检查：
1. 逻辑错误和 bug
2. 边界条件和空指针处理
3. 性能问题（如循环嵌套、重复计算）
4. 安全漏洞（注入、硬编码、明文密码）
5. 与项目代码风格的兼容性

【粘贴代码】
```

### 模板 3：请求优化建议
```
请分析这段代码的性能瓶颈，并给出：
1. 当前问题点（按影响程度排序）
2. 每项优化的具体实现方式
3. 优化前后的对比（时间/空间复杂度）

【粘贴代码或描述场景】
```

### 模板 4：请求 TDD 先行（测试驱动）
```
请为以下函数编写测试用例，要求：
1. 覆盖正常输入
2. 覆盖边界条件（空值、最大值、特殊字符）
3. 覆盖异常输入
4. 使用 [你项目的测试框架，如 pytest/Jest]
5. 先写测试，再实现功能

【粘贴函数签名和需求描述】
```

### 模板 5：请求架构分析（大项目）
```

请帮我：
```

## ✅ 实践建议（本周行动项）

1. **创建自己的 CLAUDE.md**  
   在你的项目根目录创建 CLAUDE.md，把代码规范、测试命令、架构约定写进去（< 2000 tokens）。这是你给 AI 的"记忆宫殿"。

2. **强制使用 Plan Mode**  
   任何超过 1 小时的任务，先进入 Plan Mode 探索和规划，不要直接跳到代码。

3. **建立三文件工作法**  
   每个大任务创建：`-plan.md`（计划）、`-context.md`（上下文）、`-tasks.md`（任务清单）。断点续传，避免上下文污染。

4. **TDD 意识引入 AI 协作**  
   让 AI 先写测试用例，再实现功能。测试是 AI 最擅长的"公式化"任务。

5. **每周回顾 AI 代码质量**  
   记录 AI 生成的代码中出现过哪些 bug/问题，下次提示 AI 重点避免。形成你自己的"AI 避坑手册"。

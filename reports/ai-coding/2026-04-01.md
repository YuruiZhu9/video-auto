## 一、核心资源汇总

### 1.1 Claude Code 最佳实践（中文详解）— CSDN

**来源：** https://blog.csdn.net/zhq426/article/details/149076280

**核心要点：**
- **CLAUDE.md 文件**：Claude Code 会话启动时自动加载，是项目的"记忆文件"。放置仓库根目录并提交 git，适合记录：常用命令、代码风格规范、测试说明、分支规范等。重要性被严重低估——相当于给 AI 配了一个永久记忆助手。
- **提示词要具体**：「参考首页现有 widget 的实现模式，尤其是代码与接口如何分离」远比「帮我实现一个 widget」效果好 10 倍。
- **think 思考模式**：在指令中加入 "think hard" / "ultrathink"，Claude 获得更多计算时间处理复杂问题。
- **四步工作流（EPCM）**：探索（Explore）→ 规划（Plan）→ 编码（Code）→ 提交（Commit）。其中规划阶段最关键，强烈建议 AI 先出计划，确认后再写代码。

**点评：** 这篇是中文世界里对 Claude Code 最系统的解读之一，尤其适合从 Cursor 转向 Claude Code 的用户。

### 1.2 How to Supercharge Coding with Claude AI — Apidog

**来源：** https://apidog.com/blog/claude-code-beginners-guide-best-practices/

**核心要点：**
- **Few-Shot Prompting（示例引导）**：给出输入→输出的具体示例，Claude 输出质量显著提升。例如："把 Python dict 转成 Java HashMap"，直接附上 dict 示例和期望的 Java 代码。
- **角色设定**：先给 Claude 分配一个专业角色（如"你是安全编码专家，专注识别 SQL 注入、XSS、缓冲区溢出"），后续所有回复都在这个框架内。
- **TDD 工作流**：写测试 → 确认测试失败 → 提交测试 → 写实现 → 迭代直到通过 → 提交代码。对算法工程师特别有价值——用测试定义预期行为，AI 不会跑偏。
- **多 Claude 并行协作**：一个 Claude 写代码，另一个 Claude 审查，第三个 Claude 根据反馈修改。适合重要 PR 的深度 review。

**点评：** 实践导向，提供了可直接套用的工作流模板，对"不知道 AI 问什么、怎么问"的工程师非常友好。

## 二、代码理解核心框架

### 2.1 AI 代码理解四步法

面对 AI 生成的代码（或陌生代码），用以下框架系统理解：

```
## 1. 整体把握（What & Why）
- 这个代码要解决什么问题？（问题描述）
- 整体架构是怎样的？输入 → 处理 → 输出
- 用了什么库/框架？为什么要用这个？

## 2. 核心逻辑（Core Logic）
- 最重要的函数/类是哪个？为什么是它？
- 数据流是怎样的？（变量怎么传、状态怎么变）
- 算法复杂度是多少？有无更优方案？

## 3. 细节理解（Line by Line）
- 这行代码做了什么？（逐行追问）
- 为什么不这样写？（反问训练理解深度）
- 边界条件和异常情况如何处理？

## 4. Review 要点（Checklist）
□ 逻辑正确性：算法符合预期吗？
□ 边界条件：空值、极端输入如何处理？
□ 性能考虑：大数据量时会有问题吗？
□ 安全问题：有注入、泄露、权限问题吗？
□ 可维护性：命名清晰吗？注释够用吗？
```

### 2.2 向 AI 追问代码的万能模板

```
"请逐行解释这段代码，重点说明：
1. 每个函数/方法的作用
2. 数据的流向（输入→中间变量→输出）
3. 关键的算法或业务逻辑
4. 这段代码可能的边界条件和潜在 bug"

"这段代码在什么情况下会出错？请列出所有 edge cases。"
```

### 3.4 请求根据测试驱动实现（TDD）

```

```

3. 常用命令（启动、测试、构建）
4. 代码风格规范（如命名规则、禁止使用的模式）
5. 核心文件路径说明

### 对算法工程师的特别建议

| 行动 | 说明 | 优先级 |

### 关键心法

> **AI 是你的结对编程伙伴，不是魔法棒。**
>
> 你越清楚自己要什么（问题描述 + 约束条件 + 预期输出），AI 输出质量越高。
> 代码理解能力的本质是：能把模糊需求翻译成精确描述的能力。
> 这正是算法工程师的核心竞争力——与其担心被 AI 取代，不如先掌握驾驭 AI 的协作方法。

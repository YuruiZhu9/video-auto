## 🧠 一、快速阅读陌生代码的核心策略

来源：[Ayende - Reading Unfamiliar Codebases Quickly](https://ayende.com/blog/201313-B/reading-unfamiliar-codebases-quickly-lmdb)

**核心理念：不需要理解整个系统，只需要提取你需要的那一点。**

### 五步法

| 步骤 | 行动 | 关键问题 |
|------|------|----------|
| 1 | **设定明确目标** | "我只需要知道 X，不关心整个系统" |
| 2 | **搜索关键函数** | 从已知 API 入手（如 `WriteFile()`），追踪调用链 |
| 3 | **质疑简单代码** | 代码看起来太简单？保持警惕，可能有你不懂的行为 |
| 4 | **区分文档 vs 实际行为** | 文档说的 ≠ 实际做的，要实测验证 |
| 5 | **寻求权威解释** | 查官方文档、社区帖子，必要时直接问代码作者 |

### 关键认知

- **"代码看起来简单"** 往往是最大的陷阱——可能存在隐式行为
- 对 Windows API 有十年经验的开发者也会误解其行为
- 不要假设，要实验验证

## 🛠️ 四、代码理解框架（可直接使用）

```
# 📖 AI 代码理解框架

## 1. 整体把握（2 分钟）
- 这个代码要解决什么问题？
- 输入是什么？输出是什么？
- 整体架构是怎样的？（画一个简单流程图）

## 2. 核心逻辑（5 分钟）
- 最重要的函数/类是哪个？
- 数据在各个函数间如何传递？
- 关键算法逻辑是什么？（能用一句话描述吗？）

## 3. 逐段理解（遇到不懂的代码时）
- 这行代码做了什么？
- 为什么要这样做？
- 不这样做会有什么问题？

## 4. AI 代码专项检查
- 逻辑正确性：结果是否符合预期？
- 边界条件：空输入、极大值、特殊字符会怎样？
- 性能考虑：大数据量下会卡吗？
- 安全问题：注入、泄露、权限是否处理？

## 5. 向 AI 提问的正确方式
- ❌ "这段代码不对"
- ✅ "这段代码在输入为空数组时报错，错误信息是...，
  请解释原因并修复"
```

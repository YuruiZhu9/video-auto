## 🧠 三、代码理解实用框架

### 🔄 四步法：理解任意代码

```
┌──────────────────────────────────────────────────────┐
│                   代码理解四步法                       │
├──────────────────────────────────────────────────────┤
│  ① 整体把握                                          │
│     - 这个代码要解决什么问题？                          │
│     - 入口点在哪里？（main / API 路由 / __main__）      │
│                                                      │
│  ② 架构梳理                                          │
│     - 核心函数/类是哪个？                              │
│     - 数据流向：输入 → 处理 → 输出                      │
│     - 模块之间的依赖关系                               │
│                                                      │
│  ③ 逐行破译                                          │
│     - 这个函数/语句做了什么？                          │
│     - 为什么不这样写？（替代方案思考）                   │
│     - 边界条件如何处理？                               │
│                                                      │
│  ④ 批判性 Review                                     │
│     - 逻辑正确性：会产生误判吗？                       │
│     - 性能：时间/空间复杂度？                         │
│     - 安全：用户输入是否被过滤？                       │
│     - 可维护性：变量命名清晰吗？                       │
└──────────────────────────────────────────────────────┘
```

### 📋 AI 生成代码 Review 检查清单

当 AI 给你一段代码后，用这个清单过一遍：

| 检查项 | 问题示例 | 怎么做 |
|--------|---------|--------|
| **逻辑正确性** | 这段 if-else 分支覆盖了所有情况吗？ | 列出所有输入边界，逐一验证 |
| **空值处理** | 如果输入是 null/undefined 会怎样？ | 要求 AI 在开头加防御性检查 |
| **类型安全** | Python 有没有类型提示？TS 类型是否准确？ | 检查每处类型声明 |
| **性能考虑** | 循环嵌套？大量数据重复查询？ | 关注 O(n) 以上的算法 |
| **安全漏洞** | SQL 注入、XSS、密码明文？ | 检查用户输入处理路径 |
| **可测试性** | 逻辑和副作用是否分离？ | 能否单独测试每个函数 |

## 💬 四、AI 协作提示词模板库

### 模板 A：请求代码解释
```
请逐行解释下面这段代码，重点说明：
1. 每个函数/类的核心作用
2. 数据在这段代码中如何流动
3. 关键的算法逻辑（为什么要这样写）
4. 是否有我需要注意的边界条件

[粘贴代码]
```

### 模板 B：请求代码 Review
```
你是一位资深 [语言] 工程师，请审查以下代码，重点关注：
1. 逻辑错误或潜在的 bug
2. 边界条件是否处理完整
3. 性能问题（时间/空间复杂度）
4. 安全漏洞（注入、密码安全、输入验证）
5. 代码可读性和可维护性

[粘贴代码]

请用这个格式回复：
- 🔴 严重问题：[描述 + 位置 + 修复建议]
- 🟡 改进建议：[描述 + 位置 + 建议]
- 🟢 做得好的地方：[简要说明]
```

### 模板 C：请求优化建议
```
我有一段处理 [问题描述] 的代码，目前 [现状，如：运行较慢/占用内存大]。

请分析：
1. 主要性能瓶颈在哪里？
2. 可以用什么算法或数据结构优化？
3. 给出优化后的版本，并对比优化前后的复杂度

[粘贴代码]
```

### 模板 D：请求添加测试
```
为以下函数生成单元测试：
- 覆盖正常输入
- 覆盖边界条件（空值、超长输入、特殊字符）
- 覆盖错误情况
- 使用 [pytest / Jest / unittest] 框架

[粘贴函数代码]
```

### 模板 E：代码转换（语法迁移）
```
将以下 [语言A] 代码转换为 [语言B]，要求：
- 保持相同的输入输出接口
- 遵循 [语言B] 的惯用写法（idiomatic）
- 如果 [语言A] 的特性在 [语言B] 没有对应，解释替代方案

[粘贴代码]
```

### 模板 F：高效代码生成（Role → Goal → Constraints）

```
# 结构化 Prompt 示例

你是 [角色]。

【任务】
[具体要做什么，如：实现一个用户登录 API 端点]

【技术栈】
- 语言/框架：[如 Python 3.10 + FastAPI]
- 数据库：[如 PostgreSQL + SQLAlchemy ORM]
- 其他依赖：[如 Zod 验证、Pydantic 模型]

【输入/输出】
- 输入：[如 { email, password } ]
- 输出：[如 { token: string, user: User } ]

【约束】
1. 密码必须 bcrypt 哈希存储
2. 使用 JWT token，过期时间 24h
3. 错误码：400（参数错误）、401（认证失败）
4. 包含 Zod/Pydantic 输入验证 schema
5. 包含 JSDoc 注释和类型注解
6. 包含单元测试

【补充说明】
[任何业务上下文或特殊要求]
```

## 🏆 五、主流 AI 模型代码能力对比（2025）

| 模型 | 代码质量 | 上下文 | 最适合场景 |
|------|---------|--------|-----------|
| **GPT-4/o3** | ~90% HumanEval | 128K | 精确指令执行、多语言 |

## ✅ 六、实践建议（本周可执行）

1. **每天用一次"模板 A"**：把你遇到的 AI 代码粘贴进去，逼自己完整理解
2. **Review 清单养成习惯**：每次 AI 给代码后，对照检查清单过一遍，不用全懂，能发现明显问题就行
3. **积累自己的模板**：把用得顺手的 Prompt 保存下来，形成个人模板库
4. **尝试 Claude 解释功能**：把看不懂的算法代码扔给 Claude，让它用大白话解释，比看注释有效
5. **理解 > 记忆**：遇到不认识的语法/库，不要硬背，去查文档，重复几次自然就记住了

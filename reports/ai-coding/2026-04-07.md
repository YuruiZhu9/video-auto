## 三、代码理解框架（可直接使用）

### 框架一：理解陌生代码的 4 步法

```
第一步：整体把握
- 这个代码要解决什么问题？
- 整体架构是怎样的？（输入 → 处理 → 输出）
- 有哪些核心文件/模块？

第二步：追踪数据流
- 数据从哪里来？
- 经过了哪些处理？
- 最终输出是什么？

第三步：定位核心逻辑
- 最重要的函数/类是哪个？
- 关键算法在哪里？
- 有哪些依赖关系？

第四步：逐行验证
- 这行代码做了什么？
- 为什么要这样写（而不是另一种写法）？
- 有没有边界条件没处理？
```

### 框架二：AI 代码 Review 专项检查

```
【逻辑正确性】
- AI 生成的逻辑是否符合业务需求？
- 条件判断是否覆盖所有情况？
- 循环是否有终止条件？

【边界条件】
- 空输入怎么处理？
- 极端值（0、最大值、负数）？
- 并发/竞态条件？

【性能考虑】
- 有没有不必要的重复计算？
- 数据库查询是否高效？
- 内存使用是否合理？

【安全问题】
- 用户输入是否经过验证？
- 是否有 SQL 注入/XSS/CSRF 风险？
- 敏感数据是否加密？
```

## 四、AI 协作提示词模板

### 模板 1：请求代码解释
```
请逐行解释以下代码，重点说明：
1. 每个函数/方法的作用
2. 数据的流向和转换过程
3. 关键的算法逻辑（时间/空间复杂度）
4. 如果有不熟悉的部分，用类比的方式解释

（附上代码）
```

### 模板 2：请求代码 Review
```
你是资深代码审查员。请审查以下代码，重点关注：
1. 逻辑错误和潜在的 Bug
2. 边界条件和异常处理
3. 性能问题（复杂度、内存）
4. 安全漏洞（注入、越权、敏感数据）
5. 与现有代码风格的一致性

输出格式：
- 问题列表（严重/警告/建议 三级）
- 每条问题的修复建议

（附上代码）
```

### 模板 3：请求安全加固
```
请审查以下代码的安全问题，特别关注：
1. 用户输入验证
2. 认证与授权
3. 数据加密
4. API 安全（如果有）
5. 已知漏洞模式（如 CWE Top 25）

如果有安全风险，请给出具体修复代码。
```

### 模板 4：请求优化建议
```
请分析以下代码的性能瓶颈：
1. 找出时间复杂度和空间复杂度最高的代码段
2. 识别重复计算和不必要的 I/O
3. 给出优化前后的对比分析
4. 提供优化后的完整代码

使用场景：（描述你的实际场景，如"日活10万用户"、"处理GB级日志"等）
```

### 模板 5：学习新代码库（给算法工程师）
```
我是一个有算法背景但刚接触这个项目的工程师。
请给我一个这个代码库的结构概览：
1. 整体架构图（文字版）
2. 核心模块及职责
3. 数据流的关键节点
4. 我需要重点关注哪些文件？
5. 有没有推荐的学习路径？
```

## 五、实践建议

### 本周可执行的 3 件事

**① 建立"AI 双工具"工作流（最重要）**
> 不要只用 GitHub Copilot 生成代码，再用 Copilot 审查。
> 换一个工具做 review——比如用 Claude 或 Qodo Gen 做独立审查。
> 实测效果：Bug 率从 20-35/千行 降至 5-10/千行。

**② 每次提交前，问 AI 这两个问题：**
> 1. "这段代码的边界条件是什么？有没有我没处理的极端情况？"
> 2. "有没有任何安全风险？请具体说明。"

**③ 用 AI 理解你不熟悉的代码段时，用这个结构化提问：**
> "请解释这段代码做什么 → 它依赖哪些其他模块 → 如果它失败了会影响哪些功能？"
> 比直接问"这段代码干嘛的"得到的信息深 3 倍。

## 六、关键认知更新

| 旧认知 | 新认知 |
|--------|--------|
| AI 生成代码 → 直接用 | AI 生成代码 → AI Review → 安全检查 → 人工验证 |
| 一个 AI 工具搞定所有 | 生成用 Copilot，Review 用另一个 AI |
| 问 AI "代码对不对" | 问 AI "这段代码的假设是什么？哪些情况下会失败？" |
| AI 懂了 = 我懂了 | 我能用我的话复述逻辑 = 我懂了 |

## 🧠 代码理解框架（针对算法工程师优化版）

### 框架一：AI代码理解四步法

```
第一步：整体把握
├── 这个代码要解决什么问题？（问题域）
├── 输入是什么？输出是什么？
└── 整体架构：输入 → 处理 → 输出

第二步：核心逻辑定位
├── 最重要的函数/类是哪个？（通常AI会高亮它）
├── 核心算法是什么？（匹配算法？排序？统计？）
└── 是否有AI幻觉（看起来合理但逻辑错误的部分）

第三步：细节穿透
├── 逐行追问：这行代码在做什么？为什么这样写？
├── 边界条件：空输入、极端值如何处理？
└── 性能考虑：时间复杂度、空间复杂度

第四步：Review要点（AI代码专项）
├── 逻辑正确性：AI可能"看起来对"但运行结果错误
├── 安全漏洞：注入、硬编码密钥、不安全默认配置
├── 边界条件：线程安全、并发、异常处理
└── 性能问题：N+1查询、大循环、内存泄漏
```

### 框架二：算法工程师专属代码阅读顺序

```text
1. 先看测试用例（test_*.py）
   → 了解输入/输出格式、边界条件
   
2. 再看核心算法函数（通常在文件中部）
   → 追踪数据流向
   
3. 然后看入口函数（main / API endpoint）
   → 理解整体调用链
   
4. 最后看工具函数和依赖（utils / helpers）
   → 理解支撑逻辑
```

### 模板2：请求代码审查（Review）

```

1. 逻辑正确性：代码真的实现了需求吗？
2. 边界条件和异常处理：空值、极端值会怎样？
3. 安全漏洞：注入、密钥暴露、权限问题
```

## 🛠️ AI 代码常见陷阱清单（算法工程师重点关注）

| 陷阱类型 | 具体表现 | 识别方法 | 应对策略 |
|---------|---------|---------|---------|
| **逻辑幻觉** | 变量名对、逻辑看起来对，但运行结果错误 | 用测试用例验证 | 要求AI给出测试覆盖 |
| **复杂度陷阱** | AI用O(n²)替代O(n log n)，大数据集会炸 | 看循环嵌套层数 | 明确要求复杂度 |
| **类型错误** | Python/JS动态类型，边界类型处理不当 | 边界值测试 | 要求类型注解+边界测试 |
| **并行问题** | 多线程/异步场景，共享状态处理错误 | 读代码找全局变量 | 避免AI生成并发代码 |
| **梯度消失** | 深度学习代码中，AI可能漏掉梯度更新步骤 | 检查optimizer调用 | 用PyTorch验证脚本 |
| **数据泄露** | 训练代码中测试集混入训练集 | 检查数据split逻辑 | 要求AI画出数据流图 |

## 🧠 AI 代码 8 大失败模式详解

### Pattern 1: API 幻觉（虚假库/方法）
- AI 生成导入一个听起来合理但**根本不存在的包**，或调用不存在的方法
- **识别**：Import 错误；npm/PyPI/pkg.go.dev 查不到
- **预防**：配置静态分析工具标记未知导入

### Pattern 2: 安全漏洞（看起来能用但不安全）
- 认证绕过、SQL 注入、错误处理泄露敏感信息
- **识别**：看错误处理是否暴露太多；检查认证逻辑边界
- **工具**：CodeQL、npm audit、Snyk

### Pattern 3: 性能反模式（开发能跑，生产必挂）
- 循环内字符串拼接（应用 StringBuilder）
- O(n²) 嵌套循环（存在 O(n) 解法）
- **识别**：上线前用 profiler 分析；注意嵌套循环

### Pattern 4: 乐观路径错误处理
- try-catch 只记录日志，不实际处理错误
- **识别**：检查输入在使用前是否验证

### Pattern 5: 边界条件缺失
- AI 训练数据过度代表常见场景，边界情况很少出现
- **测试必做**：空输入、null、零、负数、最大整数、空数组

### Pattern 6: 过时库用法
- 生成代码用了已废弃的 API
- **识别**：如果 AI 安装的包是 2023 年以前的，需调查原因

### Pattern 7: 数据模型不匹配
- AI 基于假设的数据结构生成代码，而非实际 Schema
- **预防**：用 TypeScript interface 或运行时 Schema 验证

### Pattern 8: 外部上下文依赖缺失
- 代码单独能跑，但依赖未定义的环境变量或配置
- **预防**：文档化所有外部依赖；建立环境验证脚本

| ESLint / Pylint | Linter | 格式、标点、风格 |

```
3. 性能问题（有没有循环内的低效操作？）
4. 安全漏洞（输入验证？SQL/命令注入？）

```

## 🚀 算法工程师转型实践建议

**本周可执行清单：**

1. **建立 Debug 习惯**：遇到 AI 代码报错，先用五步法（读错误→定位→大白话解释→排除法→单点修复）而不是直接让 AI 重写
2. **补充安全意识**：在 AI 代码提交前，跑一遍 `npm audit` 或 `pip audit`，形成肌肉记忆
3. **边界测试优先**：对 AI 生成的任何函数，第一件事用空值、零、负数测试，不是正常输入
4. **学会拆分函数**：AI 一次生成 100 行，先拆成 5 个小函数再理解，每个小函数容易追责
5. **记录失败模式**：遇到 AI 代码 bug，按 8 大模式分类记录，积累自己的"AI 踩坑笔记"

**风险分级处理原则：**
- 🔴 **高风险**（认证、支付、数据库）：自动扫描 + 人工 Review + 渗透测试
- 🟡 **中风险**（业务逻辑、数据处理）：自动化测试 + 静态分析 + 边界 case 审查
- 🟢 **低风险**（UI 组件、工具函数）：lint + 类型检查 + 基础测试

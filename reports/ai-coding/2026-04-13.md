**核心框架：**

```
Role（角色）  → 设置 AI 身份，如 "Senior Python ML engineer"
Goal（目标）  → 明确具体交付物，如 "implement cosine similarity"
Constraints（约束）→ 编码规范、测试要求、输出格式
```

**高级技巧：**
- **思维链提示**（Chain-of-thought）：加 "explain your reasoning step by step"，复杂推理准确率提升 40%
- **自我评估**：以 "review your solution for bugs and security issues" 结尾
- **元提示**：让 AI 解释"为什么选择这个方案而非其他"
- **少样本提示**：提供 2-3 个示例让 AI 匹配风格模式

**核心认知：** AI 编程助手就像"能力极强的实习生——精通所有编程语言，但对你的代码库一无所知"。

## 三、代码理解框架（实用模板）

### 🔷 框架 1：AI 代码理解四步法

拿到一段 AI 生成的代码，按以下顺序理解：

```
Step 1: 整体把握
├── 这个代码要解决什么问题？
├── 整体架构是怎样的？（输入 → 处理 → 输出）
└── 有哪些核心文件和依赖？

Step 2: 核心逻辑
├── 最重要的函数/类是哪个？
├── 数据流是怎样的？
└── 关键算法逻辑是什么？

Step 3: 细节理解
├── 这行代码做了什么？
├── 为什么不这样写？
└── 有哪些隐含假设？

Step 4: Review 要点
├── 逻辑正确性：算法符合预期吗？
├── 边界条件：null、空数组、异常输入如何处理？
├── 性能考虑：是否有 N+1 查询、内存泄漏？
└── 安全问题：输入验证、硬编码密钥、依赖来源？
```

### 🔷 框架 2：AI 生成代码专项审查清单

**功能正确性**
- [ ] 对照原始需求逐项验证
- [ ] 检查 null 值、空数组、负数等边界情况
- [ ] 测试错误处理是否符合项目约定
- [ ] 检查并发场景（死锁、竞态条件）

**安全检查**
- [ ] SQL 注入、XSS 攻击风险
- [ ] eval() 等危险函数 → JSON.parse() 等安全替代
- [ ] 硬编码密钥/凭证（用环境变量替代）
- [ ] 依赖真实性验证（19.7% 的 AI 建议包不存在！）
- [ ] 许可证合规检查

**代码质量**
- [ ] 命名是否描述性（避免 data、processor 等通用词）
- [ ] 函数是否简洁（50-100 行以内，嵌套 ≤4 层）
- [ ] 重复代码 → 提取为复用函数
- [ ] 注释是否解释"为什么"而非"做什么"

**性能**
- [ ] N+1 查询问题（循环中串行数据库查询）
- [ ] 循环中串行网络请求 → 改用 Promise.all
- [ ] 大数据集 Big O 复杂度
- [ ] 资源泄漏（内存/文件句柄）

```

2. 数据的流向（输入什么、输出什么）
3. 关键的算法逻辑（重点解释这一步做了什么）
4. 可能的潜在问题（你认为值得注意的地方）

语言：中文
代码：
[粘贴代码]
```

### 📝 模板 B：代码审查请求

```
请审查以下代码，重点关注：
1. 逻辑错误 — 算法是否符合预期行为
2. 边界条件 — null、空数组、异常输入如何处理
3. 性能问题 — 是否有 N+1 查询、内存泄漏风险
4. 安全漏洞 — SQL 注入、XSS、硬编码密钥等
5. 代码风格 — 是否符合 Python 最佳实践

代码：
[粘贴代码]
```

### 📝 模板 C：优化建议请求

```
这段代码在处理大数据集时性能较差。请：
1. 分析当前实现的时间/空间复杂度
2. 找出主要性能瓶颈
3. 给出 2-3 个优化方案（从保守到激进）
4. 解释每个方案权衡了什么

代码：
[粘贴代码]
```

### 📝 模板 D：使用已有模式（Copilot/Cursor 场景）

```
Following the same pattern as the [existing_function_name] above,
implement a new function to [specific_task].

Constraints:
- Must follow the same error handling approach
- Use the same naming conventions
- Include similar type hints and docstrings
- Add appropriate unit tests
```

### 📝 模板 E：分步重构请求

```
我需要重构这段代码，请分步指导：

当前状态：[描述现状]
目标状态：[描述目标]
约束：[任何限制条件]

请：
1. 先解释当前代码的工作原理
2. 给出重构计划（3-5 个步骤）
3. 每步实现前先说明原因
4. 最后验证是否符合预期
```

3. 覆盖边界条件（空值、零、极大值）
4. 每个测试用例有清晰的 name 和 description

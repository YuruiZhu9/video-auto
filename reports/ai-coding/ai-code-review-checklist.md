# AI 代码审查清单（可打印版）

## ✅ 阶段一：功能正确性
- [ ] 对照原始需求逐项验证
- [ ] 边界条件：null、空数组、负数、超大输入
- [ ] 错误处理是否符合项目约定
- [ ] 并发场景：死锁、竞态条件
- [ ] 集成测试：与现有系统交互是否正常

## ✅ 阶段二：安全审查
- [ ] SQL 注入风险（使用参数化查询）
- [ ] XSS 攻击风险（输入输出转义）
- [ ] 硬编码密钥 / 凭证 → 应使用环境变量
- [ ] 依赖真实性：AI 建议的包是否真实存在
- [ ] eval() / exec() 等危险函数 → 寻找安全替代
- [ ] 许可证合规（AGPL vs MIT 等）

## ✅ 阶段三：代码质量
- [ ] 命名描述性（避免 data、item、temp 等模糊词）
- [ ] 函数简洁（50-100 行，嵌套 ≤4 层）
- [ ] 无重复代码（DRY 原则）
- [ ] 注释质量：解释"为什么"而非"做什么"
- [ ] 代码风格统一（Prettier / Black / ESLint）

## ✅ 阶段四：性能审查
- [ ] N+1 查询（循环中串行 DB 查询）
- [ ] 循环中串行网络请求 → Promise.all 并行化
- [ ] 大数据集 Big O 复杂度分析
- [ ] 内存泄漏 / 文件句柄泄漏
- [ ] 阻塞操作 → 异步替代方案

## ✅ 阶段五：部署就绪
- [ ] CI/CD 质量门禁通过
- [ ] SAST 扫描无高危漏洞
- [ ] 依赖无已知 CVE
- [ ] 测试覆盖率 ≥ 80%（如适用）
- [ ] 文档已更新（README / API 文档）

---

**经验法则：** 审查阶段修复问题，比部署后修复**便宜 10-100 倍**

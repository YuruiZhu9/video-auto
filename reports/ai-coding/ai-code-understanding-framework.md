# AI 代码理解框架

> 适用于：阅读不熟悉的代码、审查 AI 生成的代码、理解大型项目  
> 核心理念：**不理解就签字 = 埋雷**

---

## 一、整体把握（1 分钟）

拿到一段代码，先回答这三个问题：

- **这段代码要解决什么问题？** （问题域）
- **输入是什么，输出是什么？** （边界）
- **整体架构是怎样的？** （数据流向）

```
[输入] → [处理模块A] → [处理模块B] → [输出]
              ↓
         [依赖/状态]
```

### 怎么做：
- 让 AI 描述：`"用一句话说明这段代码的功能"`
- 找入口函数（main / handler / controller）
- 识别核心数据结构

---

## 二、核心逻辑（3 分钟）

### 2.1 找到最重要的函数/类

```
问 AI："这段代码中最重要的 3 个函数是哪些？它们各自负责什么？"
```

### 2.2 追踪数据流

- 入口数据从哪来？
- 中间经过哪些转换？
- 最终输出到哪里？

```
数据来源 → 清洗/转换 → 核心计算 → 输出/存储
```

### 2.3 理解控制流

- 条件分支（if/else/switch）覆盖了哪些场景？
- 循环（for/while）处理什么批量数据？
- 异常处理（try/catch）捕获了什么错误？

---

## 三、细节理解（遇到不懂的代码时）

### 3.1 逐行/逐段分析方法

遇到不懂的代码，用这个万能问法：

```
"请逐行解释这段代码，重点说明：
1. 每个函数/变量的作用
2. 数据的流向和变化
3. 关键的算法逻辑或数学原理
4. 这里为什么要这样写，而不是那样写？"
```

### 3.2 对比理解法

找到相似功能的代码，让 AI 对比：

```
"这段代码和 src/utils/format.ts 的区别是什么？"
```

### 3.3 逆向追溯法

```
"这段代码中 `xxx` 的值是从哪里来的？追踪一下它的来源。"
```

## 四、Review 要点检查清单

### 4.1 逻辑正确性

- [ ] 代码逻辑和需求描述一致吗？
- [ ] 分支条件覆盖了所有情况吗？（特别是 else/default）
- [ ] 边界值有没有处理？（0、负数、空值、超大值）

### 4.2 边界条件

- [ ] 空输入 → 有处理吗？
- [ ] 超大输入 → 会 OOM 或超时吗？
- [ ] 非法输入 → 会抛异常还是静默失败？
- [ ] 并发情况 → 有竞态条件吗？

### 4.3 性能考虑

- [ ] 有没有不必要的循环嵌套？
- [ ] 大数据有没有分页/流式处理？
- [ ] 有没有重复计算可以缓存？
- [ ] SQL 查询有没有 N+1 问题？

### 4.4 安全问题（对 AI 代码尤其重要）

- [ ] 用户输入有没有做校验/转义？
- [ ] 有没有 SQL 注入风险？
- [ ] 有没有硬编码的密钥或密码？
- [ ] 权限检查有没有遗漏？
- [ ] 错误信息有没有泄露敏感信息？

### 4.5 可维护性

- [ ] 变量/函数命名清晰吗？
- [ ] 注释说明了"为什么"而不是"是什么"？
- [ ] 有没有重复代码可以抽取？
- [ ] 依赖是不是都显式声明了？

## 五、AI 代码专项审查

> AI 生成的代码有特殊风险，额外检查：

### 5.1 常见 AI 幻觉模式

| 幻觉类型 | 表现 | 检查方法 |
|----------|------|----------|
| **过度工程化** | 写了很多不需要的类/接口 | 问："这段代码是否解决当前问题所需？" |
| **边界遗漏** | happy path 全对，异常路径缺失 | 问："空输入、异常输入怎么处理？" |
| **版本不匹配** | 用了新版本才有的 API | 确认目标环境的版本 |
| **幻觉依赖** | 引用了不存在的包/函数 | `import` 检查 + `npm test` 跑一遍 |
| **安全盲区** | 没考虑注入、XSS、CSRF | 用 Bandit/Semgrep 扫描 |

### 5.2 快速验证三板斧

```
1. 读测试 → 先看测试用例，理解代码的预期行为
2. 跑测试 → npm test / pytest / cargo test，有没有失败？
3. 扫安全 → bandit -r src/（Python）/ npm audit（JS）
```

## 六、不熟悉语言的代码理解策略

### 场景：你要 Review 一个 Go 项目，但你只会 Python

**Step 1：让 AI 翻译核心概念**
```
"用 Python 的概念解释这段 Go 代码：
- struct = ?
- goroutine = ?
- channel = ?"
```

**Step 2：找关键函数**
```
"找出这段代码中最重要的 3 个函数，用一句话描述各自作用"
```

**Step 3：追踪数据**
```
"追踪 user_id 从哪里来，经过哪些处理，最终存到哪里"
```

**Step 4：逻辑验证**（不需要懂语法）
- 这段代码有没有明显的逻辑矛盾？
- 输入和输出是否匹配？
- 错误处理是否完整？

> **关键心态：不需要完全读懂每一行，但要理解"这段代码在做什么，以及是否正确地做了"。**

## 七、实战模板（直接复制用）

### 当你让 AI 解释一段不熟悉的代码时：

```
请帮我理解这段代码（src/xxx.ts）。

请按以下结构回答：
1. 这段代码的总体功能（一句话）
2. 核心数据流（输入→处理→输出）
3. 最重要的 3 个函数及其作用
4. 我需要重点审查的 3 个地方（边界/安全/性能）
5. 有没有明显的问题？

如果代码有问题，请给出具体的问题描述和修复建议。
```

### 当你要人工 Review AI 生成的代码时：

```
think harder。请审查以下代码，从以下维度打分（1-5）并给出具体问题：

1. 逻辑正确性：代码逻辑是否正确实现需求？
2. 边界处理：空值、异常、超大输入是否处理？
3. 性能问题：有没有明显的性能瓶颈？
4. 安全漏洞：有没有注入、XSS、权限问题？
5. 可维护性：命名是否清晰、代码是否冗余？

对每个维度，给出：
- 评分（1-5）
- 发现的具体问题
- 建议的修复方案

最后给出总体建议：这段代码是否可以合并？
```

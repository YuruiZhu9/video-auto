# 高效 AI 协作提示词模板库

> 来源：Nx.dev 实战指南 + DEV.to 2025 AI Coding 最佳实践  
> 适用场景：代码解释、Code Review、代码优化、Debug、架构设计

---

## 一、核心原则（使用前必读）

1. **Plan → Act → Review → Repeat** — 大任务先规划，再执行，最后审查
2. **小步迭代** — 一次只生成一个模块，不要让 AI 一次性生成大段代码
3. **永远审查** — 不要提交你不理解的代码
4. **怀疑幻觉** — 当答案"过于完美"时，追问："你确定吗？"

## 二、代码解释类提示词

### 🔍 基础解释
```
请逐行解释以下代码，重点说明：
1. 每个函数/方法的作用
2. 数据的流向（输入→处理→输出）
3. 关键的算法逻辑，为什么要这样实现
4. 这段代码做了哪些隐式假设？
```

### 🔍 架构层面理解
```
我正在阅读一个 [Python/React/Spring] 项目中的 [推荐系统模块]。
请帮我：
1. 找出核心文件和它们的关系
2. 描述数据如何在模块间流动
3. 指出最需要理解的关键代码路径
```

### 🔍 识别问题
```
这段代码可能有隐藏问题。请检查：
1. 边界条件（空值、零值、极端值）
2. 并发/竞态条件
3. 资源泄漏风险
4. 与项目其他部分的一致性
```

## 三、Code Review 类提示词

### 📋 全面 Review
```
请审查以下代码，重点关注：
1. ✅ 逻辑正确性：是否符合需求？
2. ✅ 边界条件：空值、异常、超大输入是否处理？
3. ✅ 性能问题：有无明显瓶颈？
4. ✅ 安全漏洞：注入、硬编码凭证、权限问题？
5. ✅ 代码风格：与项目现有风格一致吗？

语言/框架：[XXX]
```

### 📋 AI 生成代码专项 Review
```
这是 AI 生成的代码，请帮我做专项审查：
1. 是否有幻觉调用（引用了不存在的 API/库）？
2. 命名和风格是否与项目保持一致？
3. 是否有安全风险（SQL注入、XSS、硬编码密钥）？
4. 测试覆盖是否充分？
```

### 📋 算法逻辑 Review（适合算法工程师）
```
作为推荐系统算法工程师，请审查以下代码：
1. 算法实现是否正确？时间/空间复杂度是多少？
2. 是否有数值稳定性问题（浮点溢出、除零）？
3. 离线评估指标与在线策略是否对齐？
4. 是否存在特征处理/数据泄露问题？
```

## 四、代码生成类提示词

### ⚙️ 清晰需求模板
```
【任务】：实现 [具体功能描述]
【语言】：Python 3.10+
【框架】：FastAPI / PyTorch
【输入】：[数据格式/接口描述]
【输出】：[预期结果描述]
【约束】：
  - 不能使用 [某库/某方法]
  - 必须支持 [某特性]
  - 性能要求：[延迟/吞吐量]

请先说明你的实现思路，得到确认后再生成代码。
```

### ⚙️ 测试生成
```
请为以下函数生成单元测试：
1. 覆盖正常输入
2. 覆盖边界条件（空值、零值、极端值）
3. 覆盖错误输入
4. 使用 [pytest / unittest / doctest] 框架

[粘贴函数代码]
```

### ⚙️ 优化请求
```
请分析以下代码的性能瓶颈，并给出：
1. 每个瓶颈的具体位置和原因
2. 优化方案（附代码）
3. 优化后的预期收益

[粘贴代码]
```

## 五、Debug 类提示词

### 🐛 错误分析
```
我遇到了以下错误：
[粘贴完整错误信息/traceback]

请帮我：
1. 定位问题根源
2. 解释为什么会出现这个错误
3. 给出修复方案和代码
4. 告诉我如何避免类似问题
```

### 🐛 定位未知问题
```
系统出现了以下异常行为：[描述现象]

我的排查过程：
- [你尝试过的方法1]
- [你尝试过的方法2]

请帮我分析可能的原因，并建议下一步排查方向。
```

### 🐛 追问策略
当 AI 给了一个看起来太完美的答案时，追问：
```
你确定这个方案正确吗？请检查：
1. 是否有边界条件没考虑到？
2. 这个 API 的行为在所有版本都一致吗？
3. 是否有我需要补充的上下文？
```

## 六、架构与设计类提示词

### 🏗️ 设计评审
```
我计划实现 [功能描述]，技术栈是 [XXX]。
请帮我：
1. 提出 2-3 种可行的架构方案
2. 分析每种方案的优缺点
3. 推荐最适合的方案及理由

约束条件：[性能/成本/兼容性要求]
```

### 🏗️ 重构评估
```
以下模块需要重构，请帮我评估：
1. 当前架构的主要问题是什么？
2. 重构的目标架构是怎样的？
3. 推荐的迁移步骤（渐进式重构）
4. 重构的风险点和回滚方案

[粘贴相关代码或描述]
```

## 七、会话管理技巧

### 保持上下文
- 每个问题开一个新会话，避免上下文漂移
- 在新会话开始时粘贴 `/compact` 总结（Claude Code）
- 或手动请求 AI 总结之前的关键结论

### 让 AI 保持专注
- 一次只讨论一个模块/一个问题
- 明确限制输出范围："只生成 XX 函数，不需要其他部分"

### 编码标准植入
在项目根目录创建 `STANDARDS.md`，让 AI 每次都参考：
```
项目编码规范：
- 命名：[具体规则]
- 错误处理：[统一方式]
- 测试覆盖：[要求]
```

## 八、算法工程师专属提示词

### 📊 特征工程咨询
```
请帮我审查以下推荐系统的特征处理代码：
1. 特征是否做了正确的归一化/标准化？
2. 类别特征编码是否合理？
3. 是否存在数据泄露（训练/推理时信息不一致）？
4. 缺失值处理策略是什么？
```

### 📊 模型实现验证
```
请验证以下推荐模型实现是否正确：
1. 损失函数是否与任务匹配？
2. 梯度更新方向是否合理？
3. 是否有数值稳定性问题？
4. 与论文/标准实现是否一致？
```

### 📊 A/B 实验分析
```
请帮我分析以下 A/B 实验数据：
[粘贴数据]

假设：
- 实验组：[描述]
- 对照组：[描述]

请给出统计显著性分析和决策建议。
```

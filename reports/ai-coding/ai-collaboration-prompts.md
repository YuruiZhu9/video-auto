# 高效 AI 协作提示词模板

> 收藏这些模板，用时直接复制改写。核心原则：**问对人、问对比、一次一问**。

---

## 📖 请求代码解释

### 模板 A：整体理解（适合新代码）
```
请用大白话解释这段代码，重点说明：
1. 这段代码要解决什么问题？（一句话）
2. 整体流程是怎样的？（输入 → [关键步骤] → 输出）
3. 最重要的函数/类是哪个？为什么？

背景：我是从算法工程师转过来的，习惯数学逻辑，对工程代码不熟。
```

### 模板 B：逐行解释（适合复杂函数）
```
请逐行解释这个函数 [函数名]，每行格式如下：
第 N 行：[代码] → [大白话解释]

要求：
- 用类比的方式解释（比如说"这就像..."）
- 标注哪些是关键逻辑行
- 标注哪些可能是潜在的 bug 点
```

### 模板 C：理解错误信息
```
我遇到了这个错误：

```
[粘贴完整错误信息]
```

代码在这 [文件名:行号]：
[粘贴 10-20 行相关代码]

请用"我奶奶都能听懂"的话解释：
1. 这个错误在说什么？（不是错误代码本身，而是它背后的意思）
2. 最可能的原因是？
3. 我应该先检查什么？

我不需要你直接修，先帮我理解。
```

## 🔍 请求代码 Review

### 模板 A：全面 Review（适合重要代码）
```
请审查以下代码，重点关注（按优先级排序）：

1. 【最关键】逻辑错误：这个逻辑在什么边界条件下会出错？
2. 【高优先级】边界条件：空值、零、负数、最大值会怎样？
3. 【高优先级】安全问题：输入验证？注入风险？错误泄露信息？
4. 【中优先级】性能问题：有没有 O(n²) 或循环内低效操作？
5. 【低优先级】代码质量：命名、可读性、注释

代码：[粘贴代码]
语言/框架：[说明]

背景：这段代码 [说明用途，如"用于用户认证"或"是推荐系统的召回模块"]。
```

### 模板 B：针对性 Review（适合快速检查）
```
请快速检查这段代码有没有：
1. 明显的逻辑错误
2. 常见的边界条件 bug（如空数组访问、null.property）
3. 安全问题（如硬编码密码、未验证输入）

只说问题，不说优点。问题按严重程度排序。
代码：[粘贴代码]
```

### 模板 C：安全专项 Review
```
这是一个 [认证/支付/数据处理/用户输入] 相关模块。
请专门检查：
1. 认证绕过风险
2. 注入攻击（SQL/命令/XSS）
3. 敏感数据泄露（日志、错误信息）
4. 权限控制是否完整

代码：[粘贴代码]
```

## 🐛 请求 Debug 辅助

### 模板 A：Debug 第一步（不要让 AI 直接修）
```
我遇到了这个报错：

```
[粘贴完整错误 + 堆栈]
```

出在 [文件名:行号]。

请先帮我：
1. 用大白话解释这个错误
2. 列出最可能的 3 个原因（按概率从高到低）
3. 告诉我应该先检查哪个变量/条件

我自己来修，修完告诉你结果。这样我能学到东西。
```

### 模板 B：Debug 第二步（孤立问题）
```
我已经定位到问题在 [文件名:函数名] 的第 N 行附近。
这部分代码：[粘贴 20 行]

请问：
1. 这一段代码是做什么的？（大白话）
2. [具体问题，如"为什么 users.map 会失败？" ]
3. 如果要让这段代码不报错，users 需要满足什么条件？

请不要直接给完整修复方案，先解释原因。
```

### 模板 C：修完验证
```
我按你的建议改了 [文件名:行号]，改法是：
[粘贴修改后的代码]

现在报错变成了：
```
[粘贴新错误或"没有报错"结果]
```

这个结果是预期的吗？还是引入了新问题？
```

## ⚡ 请求代码优化

### 模板 A：性能诊断（不需要完整代码）
```
请分析这段代码的性能问题，给出：
1. 性能瓶颈排序（按影响大小，从大到小）
2. 每个瓶颈的优化方向（不需要完整代码，给思路）
3. 优化前后的复杂度对比（Big-O 标注）

我需要决定优先优化哪个，想先评估工作量。
代码：[粘贴代码]
```

### 模板 B：完整优化（接受大改）
```
请重写这段代码，要求：
1. 保持相同的输入输出接口（不要改函数签名）
2. 优化性能（注意 [具体问题，如"避免循环内字符串拼接"）
3. 保持可读性（加注释说明关键逻辑）
4. 保持边界条件处理（不要去掉空值检查）

背景：这是 [说明场景，如"推荐系统的实时排序特征生成" ]
代码：[粘贴代码]
```

## 📚 请求学习辅助

### 模板 A：理解陌生概念
```
请用通俗语言解释这个概念：
[概念名称，如"Python 的装饰器 decorator"]

要求：
1. 先给一句话定义
2. 用一个生活类比说明
3. 给一个最简单的代码示例
4. 说明什么情况下我会用到它
```

### 模板 B：对比概念
```
请对比 [概念 A] 和 [概念 B]：
1. 核心区别是什么？
2. 各自适合什么场景？
3. 在 [你的场景，如"推荐系统特征工程" ] 里用哪个更好？

我之前用的是 [你熟悉的工具]，请结合这个背景解释。
```

## 💡 提示词技巧总结

| 技巧 | 说明 | 效果 |
|------|------|------|
| **说背景** | "我是算法工程师转型，不熟悉工程代码" | AI 会降低术语密度 |
| **说用途** | "这段代码是给推荐系统用的" | AI 会考虑业务场景 |
| **先理解后修复** | "先解释再修，不要直接给答案" | 学习效果最大化 |
| **一次一问** | 每次只问一个问题 | 答案更精准 |
| **指定格式** | "按 [这个格式] 输出" | 回答更有条理 |
| **说风险等级** | "这是认证模块，高风险，请仔细检查" | AI 会更谨慎 |
| **说不要什么** | "请不要说优点，只说问题" | 避免废话 |

# 高效 AI 协作提示词模板库

> 适用于：Claude Code / Cursor / ChatGPT / GitHub Copilot  
> 场景：代码解释 / Review / 重构 / 测试 / Debug / 架构分析  
> 原则：具体 > 模糊，验证 > 猜测，上下文 > 指令

---

## 1. 请求代码解释

### 基础版
```
请解释以下代码，重点说明：
1. 每个函数/方法的作用
2. 数据的流向（输入 → 处理 → 输出）
3. 关键的算法逻辑或业务规则
4. 潜在的边界条件

【粘贴代码】
```

### 进阶版（带背景）
```
我的背景是 [你的专业方向，如推荐系统算法工程师]，  
我现在在理解 [项目/模块名]，目标是 [你的目标，如理解推荐排序逻辑]。
请用我的背景知识来解释以下代码，跳过我已经熟悉的部分：

【粘贴代码】
```

### 深度追问
```
针对你刚才的解释，我还有以下疑问：
1. [具体疑问1]
2. [具体疑问2]
请继续深入解释。
```

## 2. 请求代码 Review

### 全面 Review
```
请审查以下代码，重点检查：
1. 逻辑错误和潜在 bug
2. 边界条件和空指针处理
3. 性能问题（时间/空间复杂度）
4. 安全漏洞（注入、硬编码、明文密码）
5. 与 [项目名] 代码规范的兼容性

【粘贴代码】
```

### 专注版（指定维度）
```
请只审查以下代码的 [安全性 / 性能 / 错误处理]，忽略其他方面：

【粘贴代码】
```

### 风格与规范
```
请对照以下规范检查代码：
- [规范1，如：必须使用 async/await]
- [规范2，如：禁止使用 any 类型]
- [规范3，如：错误必须上报 Sentry]

【粘贴代码】
```

## 3. 请求优化建议

### 性能优化
```
请分析这段代码的性能瓶颈，并给出：
1. 当前问题点（按影响程度排序）
2. 每项优化的具体实现方式
3. 优化前后的对比（Big-O 复杂度）

【粘贴代码或描述场景】
```

### 重构建议
```
这段代码 [描述问题，如：太长了，嵌套太深]，
请重构，要求：
1. 保持功能不变
2. 提高可读性
3. 方便后续测试

【粘贴代码】
```

## 4. 请求 TDD 先行（测试驱动）

### 生成测试用例
```
请为以下函数编写测试用例，要求：
1. 覆盖正常输入
2. 覆盖边界条件（空值、最大值、特殊字符）
3. 覆盖异常输入（无效参数）
4. 使用 [pytest / Jest / unittest] 框架
5. 先写测试，再实现功能（请按这个顺序输出）

函数签名：
【粘贴函数签名和需求描述】
```

### 解释测试覆盖率
```
请告诉我以下测试用例的覆盖率，
哪些边界情况没有被覆盖？

【粘贴测试代码 + 被测函数】
```

## 5. 请求架构分析（大项目）

### 模块关系图
```
我正在阅读 [项目名]，请帮我：
1. 画出 [模块名] 核心模块的关系图（文字 Mermaid 格式）
2. 找出数据流的关键路径
3. 推荐接下来应该读哪些文件

我的背景：[描述]
```

### 决策溯源
```
[类/模块名] 的设计看起来 [描述你的疑惑]，  
请帮我：
1. 查找 git 历史，追溯这个设计的原始决策
2. 找到相关的 PR 和 issue
3. 总结当时的权衡考虑
```

## 6. 请求 Debug

### 报错分析
```
遇到了以下错误：
【粘贴完整错误信息】

请分析：
1. 错误根本原因
2. 是哪行代码引起的
3. 修复方案（含具体代码）
```

### 逻辑 Debug（无报错）
```
这段代码的预期行为是 [描述]，实际行为是 [描述]，
请帮我：
1. 找出差异所在
2. 给出修复代码
3. 告诉我如何验证修复

【粘贴代码】
```

### AI 协助动态调试
```
我已经设置了断点，当前变量值为：
- [变量1] = [值]
- [变量2] = [值]
下一步应该关注哪个变量？请解释判断逻辑。
```

## ⚡ 通用原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **给上下文** | 说明你的背景和目标 | "我是推荐系统工程师" |
| **指来源** | 告诉 AI 参照哪个文件/规范 | "参考 src/api/auth.ts 的风格" |
| **定范围** | 明确要什么、不要什么 | "只检查安全性，忽略性能" |
| **要验证** | 让 AI 给出验证方法 | "写完请运行测试验证" |
| **限格式** | 指定输出格式 | "用表格输出对比" |
| **分步骤** | 复杂任务拆成多轮 | 先解释 → 再优化 → 再写测试 |

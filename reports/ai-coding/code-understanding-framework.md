# AI 代码理解框架

> 适用于：理解 AI 生成代码 / 接手陌生代码库 / 代码审查

---

## 第一步：整体把握

在读任何一行代码之前，先回答这 3 个问题：

```
1. 这个代码要解决什么问题？
   - 是什么业务场景？
   - 输入是什么？输出是什么？

2. 整体架构是怎样的？
   - 画出输入→处理→输出的流程
   - 有哪些核心模块？它们之间如何协作？

3. 这段代码在项目中的位置是？
   - 谁调用它？它依赖什么？
   - 为什么在这里而不是别的地方？
```

---

## 第二步：核心逻辑定位

找到代码的"脊柱"——最重要的函数/类：

```
1. 入口函数是哪个？（被外部调用的第一个函数）

2. 数据流是怎样的？
   - 数据从哪进来
   - 经过哪些转换
   - 最终去哪

3. 关键的算法逻辑是什么？
   - 核心计算/判断是什么
   - 为什么这样设计（而不是别的方案）
```

---

## 第三步：逐行细节理解

对每个关键函数，逐行回答：

```
对于每一行代码：
- 这一行在做什么？（字面意思）
- 这一行改变了什么状态？
- 这一行依赖于什么前置条件？
- 这一行的"为什么"是什么？

对于每个外部调用：
- 这个函数/库是做什么的？
- 返回值代表什么？
- 失败时会发生什么？
```

**工具推荐**：
- IDE 跳转定义（Ctrl+点击）
- AI 解释器：`"请逐行解释这段代码，标注每一行的作用"`
- 调试器：打断点，观察变量真实值

---

## 第四步：审查要点

### 逻辑正确性
- [ ] 这个逻辑是否真的能实现目标？
- [ ] 有没有我没考虑到的执行路径？
- [ ] 特殊值（0、空字符串、None、最大值）是否处理？

### 边界条件
- [ ] 输入为空时会发生什么？
- [ ] 输入为最大值时会发生什么？
- [ ] 循环次数为 0 或 1 时是否正常？
- [ ] 浮点数比较是否用 epsilon？

### 性能考虑
- [ ] 有没有隐藏的 O(n²) 操作？
- [ ] 有没有 N+1 查询问题？
- [ ] 大数据集是否分页/流式处理？
- [ ] 循环内有没有重复计算？

### 安全问题
- [ ] 用户输入是否被 sanitize？
- [ ] 有没有 SQL/命令注入风险？
- [ ] 敏感数据是否被打印到日志？
- [ ] 权限检查是否完整？

---

## 第五步：用 AI 辅助理解

当遇到特别复杂的代码时，使用以下模板向 AI 提问：

```
请帮我理解这段代码：

1. 这段代码的输入是什么？输出是什么？
2. 核心逻辑用一句话概括是什么？
3. 第 X 行到第 Y 行做了什么？（指出你困惑的部分）
4. 哪些边界条件会导致问题？
5. 如果要修改这段代码，最可能出错的地方在哪里？

[粘贴代码]
```

---

## 快速上手：三遍阅读法

| 轮次 | 时间 | 目标 | 操作 |
|------|------|------|------|
| 第 1 遍 | 5 分钟 | 全局观 | 扫描 + 总结代码做什么 |
| 第 2 遍 | 15 分钟 | 细节理解 | 逐行分析 + 跳转外部方法 |
| 第 3 遍 | 10 分钟 | 执行验证 | 用简单参数手动走一遍 |

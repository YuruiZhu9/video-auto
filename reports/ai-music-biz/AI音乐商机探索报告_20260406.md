## 🧠 三、TapToTab 技术路线深度校正

### 3.1 关键发现：TapToTab 不是 MediaPipe，是 YOLO

上周报告将 TapToTab 描述为"MediaPipe Hands + 音频融合"，这是**不准确的**。

经过深度查阅原始论文（arXiv 2409.08618），TapToTab 的实际技术架构如下：

### 3.2 TapToTab 完整技术栈

```

│              TapToTab 系统架构                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  【输入】吉他演奏视频（含音轨）                          │
│       ↓                                                  │
│  ┌────────────────┐    ┌────────────────┐            │
│  │  视频流分析     │    │  音频流分析     │            │
│  │                 │    │                │            │
│  │  YOLO V8 /      │    │  傅里叶变换    │            │
│  │  YOLO V8 OBB    │    │  (Fourier)     │            │
│  │                 │    │                │            │
│  │  指板检测       │    │  频域分析      │            │
│  │  手部区域定位   │    │  音符频率识别  │            │
│  └────────┬───────┘    └───────┬────────┘            │
│           │                     │                      │
│           ↓                     ↓                      │

│  │         视听数据融合层                   │           │
│  │                                         │           │
│  │  ① 起始点检测（音符演奏时刻对齐）        │           │
│  │  ② 视觉位置 ↔ 音频频率 关联分析          │           │
│  │  ③ 综合判断：哪根弦 + 哪个品位            │           │
│  └────────────────────┬────────────────────┘           │
│                       ↓                                 │
│              【输出】吉他TAB谱                          │
└─────────────────────────────────────────────────────────┘
```

### 3.3 各模块详解

**① 视频分析：YOLO V8 + YOLO V8 OBB**

| 模块 | 技术 | 参数 |
|------|------|------|
| 数据标注 | Roboflow | 12类指板区域标注 |
| 模型 | YOLO V8 / YOLO V8 OBB | 目标检测+旋转框 |
| 能力 | 实时指板+手部检测 | 适应不同光照/角度/遮挡 |
| **精确度** | **~98.8%** | |
| **召回率** | **~98.8%** | |
| **mAP** | **~99.3%** | |

**② 音频分析：傅里叶变换**

```
时域音频 → 傅里叶变换 → 频域信号 → 音符频率 → 吉他音高映射

技术路径：
• 短时傅里叶变换（STFT）分析音频信号
• 频谱峰值检测识别每个音符的基频
• 泛音列分析排除干扰
• 吉他标准音高映射（E2/A2/D3/G3/B3/E4）
```

**③ 视听融合（核心创新）**

```
这是 TapToTab 的核心价值，也是音频only工具无法复制的部分：

音频分析只能告诉我们：演奏了哪些音符（频率）
视频分析只能告诉我们：手在指板哪个位置

两者结合才能确定：
→ 具体品位（5弦3品 = A2 vs 4弦空 = D3，频率相近但品位不同）
→ 具体指法（食指按 vs 中指按，影响指法标注）

融合方法：
① 起始检测（Onset Detection）→ 找准每个音符演奏时刻
② 时刻对齐 → 该时刻视频帧 ↔ 该时刻音频频率
③ 查表 → 手在指板位置 + 频率 = 具体品位和品位
```

## 💡 五、本周核心洞察：为什么 TapToTab 路线仍然值得

### 5.1 音频only工具的天花板

**无论 Songsterr / Klang.io / TabIt 多强，它们都无法解决：**

```
场景1：你看到一段吉他手演奏视频（指弹/电吉他solo）
→ 想学这段指法，但：
→ 没有原曲录音（只有翻奏视频）
→ 即使有录音，音频转谱也只能给音符，给不出品位

场景2：你在学一首指弹吉他曲
→ 网上能找到的谱子版本不统一
→ 最好的参考是演奏者的手部特写
→ 音频转谱无法从特写视频中提取指法

场景3：你想知道"这个大师这个音是怎么按的"
→ 品位+指法 = 只有视频手势分析才能给出
→ 音频只能告诉你音高，无法告诉你指位
```

### 5.2 TapToTab 的精准定位

```
TapToTab 的价值公式：

音频分析 → "这是什么音？"（频率）
视频分析 → "手在哪个位置？"（指板坐标）
融合判断 → "这个音在哪个品位？"（品位+指法）

音频only工具：只能回答问题1
TapToTab路线：能回答问题1+2+3

这就是护城河。
```

### 5.3 技术可行性：现在做TapToTab级别产品，需要什么

**基于TapToTab论文（arXiv 2409.08618）的技术路径：**

| 阶段 | 任务 | 工具/模型 | 难度 |
|------|------|---------|------|
| **Phase 1** | 指板检测模型训练 | YOLO V8 + 自定义数据集（Roboflow标注）| ⭐⭐⭐ |
| **Phase 2** | 手部关键点检测 | MediaPipe Hands（无需训练）| ⭐ |
| **Phase 3** | 音频音符识别 | MAI-Transcribe-1 或 Basic Pitch + STFT | ⭐⭐ |
| **Phase 4** | 视听融合引擎 | 起音检测 + 时间对齐算法 | ⭐⭐⭐⭐ |
| **Phase 5** | TAB生成与导出 | GuitarPro API / VEx Tab renderer | ⭐⭐ |

**MVP优先级建议（个人项目）：**
```
MVP = Phase 1(简化) + Phase 2 + Phase 3(现成API) + Phase 5

Phase 1 简化版：用预训练的吉他检测模型（如果有）
         或：用 MediaPipe Hands 代替（手部→指板映射）
         → 降低数据标注成本，快速验证可行性

Phase 3 复用：Basic Pitch（免费开源）
         → 不需要自己训练音频模型

Phase 4 简化：只用音频音符结果，不做复杂融合
         → 先做音频only版MVP，验证市场
         → 再加入视频分析作为差异化卖点
```

# 依赖注入（DI）实战指南

> 从"能跑就行"到"可测试、可替换、可复用" — 理解依赖倒置的最佳实践

---

## 一、为什么需要依赖注入？

### 核心问题

你有没有遇到过这种情况？

```python
# ❌ 硬编码依赖：UserService 直接 new 了一个 MySQL 用户仓库
class UserService:
    def __init__(self):
        self.repo = UserRepository()  # 写死了！
    
    def get_user(self, user_id):
        return self.repo.find(user_id)
```

**问题在哪：**
- `UserService` 依赖了具体的 `UserRepository` 实现
- 想换成 `RedisUserRepository`？得改 `UserService` 源码
- 想写单元测试 Mock 数据库？很难做到
- 违反了 SOLID 的 **DIP（依赖倒置原则）**：高层模块（Service）不应依赖低层模块（Repository），两者都应依赖抽象

### 依赖注入是什么

**依赖注入（Dependency Injection）** = 把对象创建的权利"反转"出去，由外部在运行时塞进来，而不是内部自己 new。

```
❌ 内部创建（紧耦合）          ✅ 外部注入（松耦合）
┌──────────────────┐         ┌──────────────────┐
│   UserService    │         │   UserService    │
│  ┌────────────┐  │         │                  │
│  │ new Repo() │  │         │  repo: IUserRepo │ ← 外部注入
│  └────────────┘  │         │                  │
└──────────────────┘         └──────────────────┘
        ↑                              ↑
   内部控制依赖                   外部控制依赖
```

## 二、三种依赖注入方式

### 1. 构造函数注入（最推荐 ✅）

通过构造函数把依赖传进来，最清晰、最显式。

```python
# 接口定义（抽象）
class IUserRepository(Protocol):
    def find(self, user_id: int) -> Optional[User]: ...
    def save(self, user: User) -> User: ...

# 具体实现
class MySQLUserRepository(IUserRepository):
    def find(self, user_id: int) -> Optional[User]:
        return db.session.query(User).get(user_id)
    
    def save(self, user: User) -> User:
        db.session.add(user)
        db.session.commit()
        return user

class RedisUserRepository(IUserRepository):
    def __init__(self, redis_client):
        self.redis = redis_client
    
    def find(self, user_id: int) -> Optional[User]:
        data = self.redis.get(f"user:{user_id}")
        return User.from_dict(json.loads(data)) if data else None
    
    def save(self, user: User) -> User:
        self.redis.setex(f"user:{user.id}", 3600, json.dumps(user.to_dict()))
        return user

# Service 只依赖接口，不依赖实现
class UserService:
    def __init__(self, repo: IUserRepository):
        self._repo = repo  # 注入进来，不 new
    
    def get_user(self, user_id: int) -> Optional[User]:
        return self._repo.find(user_id)
    
    def create_user(self, name: str, email: str) -> User:
        user = User(name=name, email=email)
        return self._repo.save(user)
```

**使用的地方（组装/注入点）：**

```python
# 生产环境：注入 MySQL 实现
user_repo = MySQLUserRepository()
user_service = UserService(user_repo)
```

```python
# 测试环境：注入 Mock 实现（完全不用连数据库！）
class MockUserRepo(IUserRepository):
    def __init__(self):
        self.data = {1: User(id=1, name="Test", email="test@test.com")}
    
    def find(self, user_id):
        return self.data.get(user_id)
    
    def save(self, user):
        self.data[user.id] = user
        return user

# 单测：完全隔离，只测 Service 逻辑
def test_get_user():
    mock_repo = MockUserRepo()
    service = UserService(mock_repo)
    
    user = service.get_user(1)
    
    assert user.name == "Test"
    # ✅ 没有数据库，没有网络，毫秒级执行
```

### 2. 属性注入（Field Injection）

通过 public 属性注入，用 `@inject` 装饰器或框架完成。

```python
# ❌ 不推荐：属性注入让依赖不可见（构造函数看不出依赖什么）
class UserService:
    @inject
    user_repo: IUserRepository  # 谁负责注入？不知道
    
    def get_user(self, user_id):
        return self.user_repo.find(user_id)
```

```python
# ✅ 勉强可用：属性注入 + 类型注解（Python）
class UserService:
    repo: IUserRepository  # type: ignore  # 由框架注入
    
    def get_user(self, user_id):
        return self.repo.find(user_id)
```

**缺点：** 依赖关系不透明，构造函数签名不完整，单元测试需要手动设置属性。

### 3. 方法注入（Method Injection）

把依赖作为方法参数传入，适合依赖只在一个方法里用。

```python
class RecommendationEngine:
    # user_repo 只在 recommend 方法里用，不需要存为实例属性
    def recommend(self, user_id: int, repo: IUserRepository, top_k: int = 10) -> list[Item]:
        user = repo.find(user_id)
        if not user:
            return []
        
        # 召回逻辑...
        candidates = self._recall_candidates(user)
        
        # 排序逻辑...
        ranked = self._rank(candidates, user)
        
        return ranked[:top_k]
```

### 方案2：自己实现一个简易 DI 容器（学习目的）

如果不想引入外部依赖，几十行代码就能实现：

```python
class DIContainer:
    """简易依赖注入容器"""
    
    def __init__(self):
        self._services: dict[type, object] = {}
        self._factories: dict[type, callable] = {}
    
    def register(self, interface: type, implementation: type | object, 
                 singleton: bool = True):
        """注册服务"""
        if isinstance(implementation, type):
            self._factories[interface] = (implementation, singleton)
        else:
            self._services[interface] = implementation
    
    def resolve(self, interface: type) -> object:
        """解析服务"""
        if interface in self._services:
            return self._services[interface]
        
        if interface not in self._factories:
            raise ValueError(f"未注册的服务: {interface}")
        
        factory, singleton = self._factories[interface]
        
        if singleton:
            self._services[interface] = factory()
            return self._services[interface]
        else:
            return factory()
    
    def inject(self, cls: type) -> object:
        """自动注入：创建实例并注入所有带 type hint 的参数"""
        import inspect
        sig = inspect.signature(cls.__init__)
        kwargs = {}
        for name, param in sig.parameters.items():
            if name == 'self':
                continue
            hint = param.annotation
            if hint != inspect.Parameter.empty:
                kwargs[name] = self.resolve(hint)
        return cls(**kwargs)


# 使用
container = DIContainer()
container.register(IUserRepository, MySQLUserRepository)
container.register(ICacheService, RedisCacheService)

# 自动解析依赖并创建实例
service = container.inject(UserService)
```

## 四、FastAPI 中的依赖注入

FastAPI 有**原生依赖注入系统**，优雅得让人惊喜：

```python
from fastapi import Depends, FastAPI, HTTPException
from typing import Optional

app = FastAPI()

# ========== 第一层：接口定义 ==========
class IUserRepository(Protocol):
    def get_user(self, user_id: int) -> Optional[User]: ...

# ========== 第二层：具体实现 ==========
class MySQLUserRepo:
    def get_user(self, user_id: int) -> Optional[User]:
        user = db.session.query(User).get(user_id)
        return user

# ========== 第三层：依赖提供者（Provider） ==========
def get_user_repo() -> IUserRepository:
    """提供什么实现，在这里决定"""
    return MySQLUserRepo()

# ========== 第四层：Service 层 ==========
class UserService:
    def __init__(self, repo: IUserRepository = Depends(get_user_repo)):
        self._repo = repo
    
    def get_user(self, user_id: int) -> User:
        user = self._repo.get_user(user_id)
        if not user:
            raise HTTPException(status_code=404, detail="用户不存在")
        return user

# ========== 第五层：Controller 层 ==========
@app.get("/users/{user_id}", response_model=UserResponse)
def get_user(
    user_id: int,
    service: UserService = Depends()
):
    """✅ Controller 只负责解析请求和包装响应"""
    return service.get_user(user_id)

# ========== 进阶：Mock 测试（零数据库） ==========
# 测试时直接注入 Mock，不需要改任何业务代码
@pytest.fixture
def mock_repo():
    return MockUserRepo()

@pytest.fixture
def test_service(mock_repo):
    return UserService(repo=mock_repo)

def test_get_user(test_service):
    user = test_service.get_user(1)
    assert user.name == "Test User"
    # ✅ 完全不碰数据库
```

### FastAPI 依赖注入高级技巧

**1. 叠加依赖（Scoping）**

```python
# 同一个接口，不同场景不同实现
def get_read_repo() -> IUserRepository:
    return ReadReplicaUserRepo()  # 读从库

def get_write_repo() -> IUserRepository:
    return MasterUserRepo()       # 写主库

class UserService:
    def __init__(
        self,
        read_repo: IUserRepository = Depends(get_read_repo),   # 读
        write_repo: IUserRepository = Depends(get_write_repo), # 写
    ):
        self._read_repo = read_repo
        self._write_repo = write_repo
```

**2. 可选依赖**

```python
class UserService:
    def __init__(
        self,
        repo: IUserRepository,
        cache: Optional[ICacheService] = None,  # 可选，默认真实环境有缓存
    ):
        self._repo = repo
        self._cache = cache
    
    def get_user(self, user_id: int) -> User:
        # 尝试从缓存取
        if self._cache:
            cached = self._cache.get(f"user:{user_id}")
            if cached:
                return cached
        
        user = self._repo.find(user_id)
        
        if self._cache:
            self._cache.set(f"user:{user_id}", user)
        
        return user
```

**3. 带参数的依赖（Factory 模式）**

```python
def get_recommendation_service(
    strategy: str = Query(default="embedding"),  # 从请求参数决定
) -> IRecommendationStrategy:
    strategies = {
        "item_cf": ItemCFStrategy(),
        "user_cf": UserCFStrategy(),
        "embedding": EmbeddingStrategy(),
    }
    return strategies.get(strategy, EmbeddingStrategy())

@app.get("/recommend")
def recommend(
    user_id: int,
    service: IRecommendationStrategy = Depends(get_recommendation_service),
):
    return service.recommend(user_id)
```

## 五、TypeScript / NestJS 依赖注入

NestJS 是"依赖注入原生框架"，Angular 风格的 DI 容器开箱即用：

```typescript
// ========== 第一层：接口定义 ==========
// 接口用抽象类或者纯粹的对象类型表示
export abstract class IUserRepository {
  abstract find(id: number): Promise<User | null>;
  abstract save(user: User): Promise<User>;
}

// ========== 第二层：具体实现 ==========
// 用 @Injectable() 声明这是一个可注入的类
@Injectable()
export class MySQLUserRepository implements IUserRepository {
  constructor(
    @Inject('DB') private db: Database,  // 嵌套注入
  ) {}

  async find(id: number): Promise<User | null> {
    return this.db.query('SELECT * FROM users WHERE id = ?', [id]);
  }

  async save(user: User): Promise<User> {
    await this.db.query('INSERT INTO users ...', [...]);
    return user;
  }
}

// ========== 第三层：Service ==========
@Injectable()
export class UserService {
  // ✅ 通过构造函数注入，TypeScript + NestJS 自动解析
  constructor(
    @Inject(IUserRepository) private readonly userRepo: IUserRepository,
    @Inject(ICacheService) private readonly cache: ICacheService,
  ) {}

  async getUser(userId: number): Promise<User> {
    // 先查缓存
    const cached = await this.cache.get(`user:${userId}`);
    if (cached) return cached;

    const user = await this.userRepo.find(userId);
    if (!user) throw new NotFoundException('用户不存在');

    await this.cache.set(`user:${userId}`, user);
    return user;
  }
}

// ========== 第四层：模块注册 ==========
// 模块声明"我需要什么实现"
@Module({
  providers: [
    { provide: IUserRepository, useClass: MySQLUserRepository },
    { provide: ICacheService, useClass: RedisCacheService },
    UserService,
  ],
  controllers: [UserController],
})
export class UserModule {}
```

### NestJS 依赖注入高级技巧

**1. Token 注入（字符串/Class Token）**

```typescript
// 用字符串做 Token（适合跨模块共享配置）
export const CONFIG_TOKEN = 'APP_CONFIG';

// 定义
@Injectable()
export class DatabaseService {
  constructor(
    @Inject('DB_HOST') private host: string,
    @Inject('DB_PORT') private port: number,
  ) {}
}

// 注册（在 Module 或 main.ts 中）
app.useFactory({
  provide: 'DB_HOST',
  useFactory: () => process.env.DB_HOST || 'localhost',
});
```

**2. 条件注入（Factory Provider）**

```typescript
// 根据环境决定用什么实现
{
  provide: IUserRepository,
  useFactory: (): IUserRepository => {
    if (process.env.NODE_ENV === 'test') {
      return new MockUserRepository(); // 测试用 Mock
    }
    return new MySQLUserRepository();  // 生产用真实 DB
  },
}
```

**3. NestJS 单元测试（自动 mock）**

```typescript
// NestJS 的 Testing 模块帮你自动创建 mock
import { Test } from '@nestjs/testing';

describe('UserService', () => {
  let service: UserService;
  let mockRepo: jest.Mocked<IUserRepository>;

  beforeEach(async () => {
    const module = await Test.createTestingModule({
      providers: [
        UserService,
        {
          provide: IUserRepository,
          useValue: {
            find: jest.fn(),
            save: jest.fn(),
          },
        },
      ],
    }).compile();

    service = module.get<UserService>(UserService);
    mockRepo = module.get(IUserRepository);
  });

  it('should get user by id', async () => {
    mockRepo.find.mockResolvedValue({ id: 1, name: 'Test' });
    
    const user = await service.getUser(1);
    
    expect(user.name).toBe('Test');
    expect(mockRepo.find).toHaveBeenCalledWith(1); // 验证调用
  });
});
```

## 六、推荐系统中的 DI 实战

### 场景：多路召回的策略注入

```python
# 推荐引擎：支持多种召回策略，由外部注入
class RecommendationEngine:
    def __init__(
        self,
        recall_strategies: list[IRecallStrategy],  # 注入多路召回
        ranker: IRanker,                             # 注入排序器
        rebuilder: IRebuilder,                       # 注入重排器
    ):
        self._recall_strategies = recall_strategies
        self._ranker = ranker
        self._rebuilder = rebuilder
    
    def recommend(self, user_id: int, ctx: RecommendContext) -> list[Item]:
        # 第一步：多路召回（策略模式 + DI）
        all_candidates = []
        for strategy in self._recall_strategies:
            candidates = strategy.recall(user_id, ctx)
            all_candidates.extend(candidates)
        
        # 第二步：排序
        ranked = self._ranker.rank(all_candidates, user_id)
        
        # 第三步：重排
        final = self._rebuilder.rebuild(ranked, ctx)
        
        return final


# 启动时组装（体现"组合优于继承"）
recall_strategies = [
    ItemCFRecallStrategy(),
    UserCFRecallStrategy(),
    EmbeddingRecallStrategy(),
]
ranker = DNNRanker()
rebuilder = DiversityRebuilder()

engine = RecommendationEngine(
    recall_strategies=recall_strategies,
    ranker=ranker,
    rebuilder=rebuilder,
)

# ✅ 测试时可以只注入一个 Mock 策略
# ✅ A/B 测试时可以注入不同的 ranker 实现
# ✅ 不改一行业务代码，换策略靠配置
```

## 七、常见坑 & 最佳实践

### ❌ 坑1：循环依赖（A → B → A）

```python
# ❌ 踩坑：Service A 和 Service B 互相注入
class ServiceA:
    def __init__(self, b: "ServiceB"):  # forward reference
        self._b = b

class ServiceB:
    def __init__(self, a: "ServiceA"):
        self._a = a

# → 报错：RecursionError 或初始化顺序问题
```

```python
# ✅ 解决：提取公共接口，或延迟注入（属性注入）
class ISharedService(Protocol):
    pass

class ServiceA:
    def __init__(self, shared: ISharedService):
        self._shared = shared  # 不直接依赖 B

# 或用事件/消息总线解耦
```

### ❌ 坑2：依赖层次过深

```python
# ❌ 踩坑：3层以上嵌套注入，难以追踪
class A:
    def __init__(self, b: B): ...

class B:
    def __init__(self, c: C): ...

class C:
    def __init__(self, d: D): ...

# → 调试时不知道 D 初始化失败在哪一层
```

```python
# ✅ 解决：依赖层次不超过2-3层；用容器统一管理
container = DIContainer()
container.register(ID, A).register(IB, B).register(IC, C)
a = container.resolve(A)  # 容器帮你理清顺序
```

### ❌ 坑3：Singleton vs Transient 混乱

```python
# ❌ 常见：把有状态的服务注册为 Singleton（单例）导致数据污染
@injectable(singleton=True)
class UserSessionService:
    def __init__(self):
        self.current_user = None  # ❌ 单例有状态，多请求共享！
    
    def set_user(self, user):
        self.current_user = user  # 请求A设置的用户被请求B看到

# ✅ 解决：有状态对象用 request-scoped；无状态服务才用 singleton
# FastAPI 中用 Depends() 确保每个请求拿到新实例
# NestJS 中用 @Injectable({ scope: Scope.REQUEST })
```

### ✅ 最佳实践总结

| 原则 | 说明 |
|------|------|
| **接口优于抽象类** | 接口更灵活，Python 用 `Protocol`（结构子类型） |
| **构造函数注入优先** | 显式、透明、最易测 |
| **单一职责** | 每个 Service 只做一件事 |
| **Singleton 无状态** | 单例服务必须无状态，有状态用 Scoped |
| **测试时全 Mock** | 单元测试不需要任何真实数据库/网络调用 |
| **容器配置集中** | 所有依赖注册集中在一处（main.py / Module），一目了然 |

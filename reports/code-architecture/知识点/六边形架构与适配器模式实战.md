# 六边形架构（端口与适配器）实战

> 从"框架驱动"到"业务驱动"——让推荐系统核心逻辑与外部世界彻底解耦

## 什么是六边形架构？

六边形架构（Hexagonal Architecture），由 Alistair Cockburn 提出，也叫**端口与适配器模式（Ports & Adapters）**。

核心思想只有一句话：

> **业务逻辑在中间，外面是端口，端口外是适配器。**
> **框架、数据库、第三方 SDK，都是适配器。业务逻辑永远不知道自己被谁调用。**

```
                    ┌──────────────────────────────────────────┐
                    │              外 部 世 界                  │
                    │                                          │
         HTTP适配器      gRPC适配器      Kafka适配器      AI模型适配器
         (REST API)   (同步调用)     (异步事件)       (模型推理)
                    └───────┬──────────┬──────────┬──────────┘
                            │          │          │
                         端口A      端口B       端口C
                            │          │          │
                    ┌───────┴──────────┴──────────┴───────┐
                    │           应 用 层 (用例)              │
                    │    RecommendUseCase / RecallUseCase   │
                    └───────────────────┬──────────────────┘
                                        │
                    ┌───────────────────┴──────────────────┐
                    │           领 域 层 (核心)              │
                    │                                          │
                    │  RecallStrategy (召回策略接口)             │
                    │  RankingModel     (排序模型接口)           │
                    │  UserProfile      (用户画像)              │
                    │  Recommendation   (推荐结果)              │
                    │                                          │
                    └─────────────────────────────────────────┘
```

### 为什么推荐系统必须学六边形架构？

| 痛点场景 | 不用六边形架构 | 用六边形架构 |
|---------|--------------|-------------|
| 模型从 XGBoost 换到 DeepFM | 改 Service 代码 | 换个 Adapter 插上就行 |
| 微信登录改企业微信登录 | 改认证模块所有调用处 | 换个 Adapter |
| 召回从 ItemCF 换成 Embedding | 重写召回服务 | 实现新策略类 |
| 测试推荐逻辑 | 需要启动 MySQL/Redis | Mock 端口，纯内存测试 |

## 核心概念：端口（Port）vs 适配器（Adapter）

### 端口（Port）—— 接口契约

**端口是"我们要什么"，适配器是"谁来提供"。**

```python
# =============================================
# 领域层：定义端口（接口契约）
# 文件：domain/ports.py
# =============================================

from abc import ABC, abstractmethod
from typing import List
from dataclasses import dataclass

@dataclass
class UserProfile:
    user_id: str
    age: int
    gender: str
    categories: List[str]  # 兴趣类目

@dataclass
class Item:
    item_id: str
    title: str
    category: str
    embedding: List[float]

@dataclass
class RecallResult:
    strategy_name: str
    items: List[Item]
    scores: List[float]


# === 端口定义：召回策略（输入侧）===
class RecallPort(ABC):
    """召回端口：定义了"召回"这件事的契约"""
    
    @property
    @abstractmethod
    def name(self) -> str:
        """策略名称"""
        pass
    
    @abstractmethod
    async def recall(self, user: UserProfile, top_k: int) -> RecallResult:
        """根据用户画像召回候选集"""
        pass


# === 端口定义：排序模型（输入侧）===
class RankingPort(ABC):
    """排序端口：定义了"排序"这件事的契约"""
    
    @abstractmethod
    async def rank(self, user: UserProfile, items: List[Item]) -> List[Item]:
        """对候选集排序，返回排序后的列表"""
        pass


# === 端口定义：用户画像（输入侧）===
class UserProfilePort(ABC):
    """用户画像端口"""
    
    @abstractmethod
    async def get_profile(self, user_id: str) -> UserProfile:
        pass


# === 端口定义：推荐结果存储（输出侧）===
class RecommendationStoragePort(ABC):
    """推荐结果存储端口——存储可以是 MySQL / Redis / MongoDB"""
    
    @abstractmethod
    async def save(self, user_id: str, items: List[Item]) -> None:
        pass
    
    @abstractmethod
    async def get_recent(self, user_id: str, limit: int) -> List[Item]:
        pass


# === 端口定义：行为事件发布（输出侧）===
class EventPublishPort(ABC):
    """事件发布端口——可以是 Kafka / Redis Stream / HTTP"""
    
    @abstractmethod
    async def publish(self, event_type: str, payload: dict) -> None:
        pass
```

## 反例：没有端口的代码（耦合地狱）

```python
# =============================================
# 反例：业务逻辑直接依赖具体实现（坏味道）
# 文件：bad_example_v1.py
# =============================================

from flask import Flask, request
import pymysql
import redis
import requests

app = Flask(__name__)

# ❌ 问题1：硬编码数据库连接，逻辑和MySQL耦合
def get_user_profile(user_id: str):
    conn = pymysql.connect(
        host='10.0.1.5', port=3306,
        user='rec', password='rec123',
        database='recommend_db'  # ❌ 写死在代码里
    )
    cursor = conn.cursor()
    cursor.execute("SELECT * FROM user_profiles WHERE user_id=%s", (user_id,))
    return cursor.fetchone()

# ❌ 问题2：业务逻辑直接调用第三方API，无端口抽象
def recall_items_Embedding(user_profile):
    response = requests.post(
        'http://model-service:8001/recall',
        json={'user_id': user_profile[0], 'top_k': 100},
        timeout=5  # ❌ 超时写死
    )
    return response.json()['items']

# ❌ 问题3：直接操作Redis，测试时无法Mock
def cache_recommendation(user_id, items):
    r = redis.Redis(host='localhost', port=6379, db=0)  # ❌ 本地Redis
    r.setex(f'rec:{user_id}', 3600, json.dumps(items))

# ❌ 问题4：Service层和HTTP框架耦合，无法换到gRPC
@app.route('/recommend')
def recommend():
    user_id = request.args.get('user_id')
    profile = get_user_profile(user_id)  # ❌ 无法单元测试
    items = recall_items_Embedding(profile)
    cache_recommendation(user_id, items)
    return {'items': items}
```

### 反例的六大罪状

| # | 罪状 | 后果 |
|---|------|------|
| 1 | 硬编码 MySQL 连接字符串 | 换环境要改代码 |
| 2 | 硬编码 Redis 地址 | 测试必须启动 Redis |
| 3 | 直接 `requests.post` 模型服务 | 换模型服务要改业务代码 |
| 4 | Flask Route 就是适配器 | 换 gRPC 整个重写 |
| 5 | `get_user_profile` 里有 SQL | 无法在不启动 DB 的情况下测试 |
| 6 | 所有逻辑在一个文件 | 改一处可能坏十处 |

### 领域服务（核心逻辑，零外部依赖）

```python
# =============================================
# 领域层：推荐核心业务逻辑
# 文件：domain/service.py
# 注意：这里只有业务规则，没有任何外部依赖
# =============================================

from dataclasses import dataclass, field
from typing import List
from .model import UserProfile, Item, RecallResult
from .ports import RecallPort, RankingPort, EventPublishPort


class RecommendationService:
    """
    推荐服务领域逻辑：
    协调多个端口（召回→排序→事件），自身不含任何数据库/HTTP/Redis代码
    """
    
    def __init__(
        self,
        recall_strategies: List[RecallPort],    # 注入召回端口列表
        ranking_model: RankingPort,              # 注入排序端口
        event_publisher: EventPublishPort,        # 注入事件端口
    ):
        self._recall_strategies = recall_strategies
        self._ranking_model = ranking_model
        self._event_publisher = event_publisher
    
    async def recommend(self, user: UserProfile, top_k: int = 20) -> List[Item]:
        """
        推荐主流程：
        1. 多路召回 → 2. 排序 → 3. 发行为事件
        """
        # Step 1: 多路召回（并行调用多个RecallPort）
        all_candidates: List[Item] = []
        for strategy in self._recall_strategies:
            result = await strategy.recall(user, top_k=top_k)
            all_candidates.extend(result.items)
        
        # 去重
        seen = set()
        unique_candidates = []
        for item in all_candidates:
            if item.item_id not in seen:
                seen.add(item.item_id)
                unique_candidates.append(item)
        
        if not unique_candidates:
            return []
        
        # Step 2: 排序
        ranked_items = await self._ranking_model.rank(user, unique_candidates)
        
        # Step 3: 发布推荐事件（异步，不阻塞主流程）
        await self._event_publisher.publish(
            event_type='recommendation_served',
            payload={
                'user_id': user.user_id,
                'item_ids': [i.item_id for i in ranked_items[:top_k]],
                'strategy_count': len(self._recall_strategies)
            }
        )
        
        return ranked_items[:top_k]
```

### 主适配器：Flask HTTP（Driving Adapter）

```python
# =============================================
# 主适配器：Flask REST API
# 文件：adapters/primary/flask_adapter.py
# 作用：将 HTTP 请求转换为领域逻辑可理解的格式
# =============================================

from flask import Blueprint, request, jsonify
from domain.service import RecommendationService
from domain.model import UserProfile
from typing import Optional

recommend_bp = Blueprint('recommend', __name__)

# 注入的领域服务（由 DI 容器注入）
_recommendation_service: Optional[RecommendationService] = None


def init_adapter(recommendation_service: RecommendationService):
    """由 DI 容器调用，注入领域服务"""
    global _recommendation_service
    _recommendation_service = recommendation_service


@recommend_bp.route('/api/v1/recommend', methods=['GET'])
async def recommend():
    """
    GET /api/v1/recommend?user_id=123&top_k=20
    返回用户推荐列表
    """
    user_id = request.args.get('user_id')
    top_k = int(request.args.get('top_k', 20))
    
    if not user_id:
        return jsonify({'error': 'user_id required'}), 400
    
    # 从 DI 容器获取用户画像（我们用的是 MySQL 适配器）
    from di.container import container
    user_profile = await container.get_user_profile(user_id)
    
    if not user_profile:
        return jsonify({'error': 'user not found'}), 404
    
    # 调用领域逻辑（完全不知道是 Flask 在调用）
    items = await _recommendation_service.recommend(user_profile, top_k=top_k)
    
    return jsonify({
        'user_id': user_id,
        'count': len(items),
        'items': [
            {'item_id': i.item_id, 'title': i.title, 'category': i.category}
            for i in items
        ]
    })


@recommend_bp.route('/api/v1/health', methods=['GET'])
async def health():
    """健康检查接口（无需鉴权）"""
    return jsonify({'status': 'ok'})
```

### 次适配器：MySQL 用户画像

```python
# =============================================
# 次适配器：MySQL 用户画像存储
# 文件：adapters/secondary/mysql_user_adapter.py
# 实现 UserProfilePort 端口
# =============================================

import aiomysql
from typing import Optional
from domain.model import UserProfile
from domain.ports import UserProfilePort
from config.settings import settings


class MySQLUserProfileAdapter(UserProfilePort):
    """
    MySQL 用户画像适配器
    实现 UserProfilePort 接口
    """
    
    def __init__(self):
        self._pool: Optional[aiomysql.Pool] = None
    
    async def initialize(self):
        """初始化连接池（启动时调用一次）"""
        self._pool = await aiomysql.create_pool(
            host=settings.MYSQL_HOST,
            port=settings.MYSQL_PORT,
            user=settings.MYSQL_USER,
            password=settings.MYSQL_PASSWORD,
            db=settings.MYSQL_DATABASE,
            minsize=5,
            maxsize=20,
            autocommit=True,
        )
    
    async def get_profile(self, user_id: str) -> Optional[UserProfile]:
        async with self._pool.acquire() as conn:
            async with conn.cursor(aiomysql.DictCursor) as cursor:
                await cursor.execute(
                    """
                    SELECT user_id, age, gender, interest_categories
                    FROM user_profiles WHERE user_id = %s
                    """,
                    (user_id,)
                )
                row = await cursor.fetchone()
        
        if not row:
            return None
        
        return UserProfile(
            user_id=row['user_id'],
            age=row['age'],
            gender=row['gender'],
            categories=row['interest_categories'].split(',') if row['interest_categories'] else []
        )
    
    async def close(self):
        if self._pool:
            self._pool.close()
            await self._pool.wait_closed()
```

### 次适配器：Embedding 模型推理（AI 服务）

```python
# =============================================
# 次适配器：Embedding 模型推理
# 文件：adapters/secondary/embedding_model_adapter.py
# 实现 RecallPort 端口
# =============================================

import httpx
from typing import List
from domain.model import UserProfile, Item, RecallResult
from domain.ports import RecallPort
from config.settings import settings


class EmbeddingRecallAdapter(RecallPort):
    """
    Embedding 向量召回适配器
    对接 AI 模型推理服务（可以是内部服务或 OpenAI/HuggingFace）
    """
    
    def __init__(self, service_url: str, timeout: float = 3.0):
        self._service_url = service_url
        self._timeout = timeout
    
    @property
    def name(self) -> str:
        return "embedding_recall"
    
    async def recall(self, user: UserProfile, top_k: int) -> RecallResult:
        """调用 Embedding 服务进行向量召回"""
        async with httpx.AsyncClient(timeout=self._timeout) as client:
            response = await client.post(
                f"{self._service_url}/recall",
                json={
                    'user_profile': {
                        'user_id': user.user_id,
                        'age': user.age,
                        'gender': user.gender,
                        'categories': user.categories
                    },
                    'top_k': top_k
                }
            )
            response.raise_for_status()
            data = response.json()
        
        items = [
            Item(
                item_id=item['item_id'],
                title=item['title'],
                category=item.get('category', ''),
                embedding=item.get('embedding', [])
            )
            for item in data.get('items', [])
        ]
        
        return RecallResult(
            strategy_name=self.name,
            items=items,
            scores=data.get('scores', [1.0] * len(items))
        )


class ItemCFRecallAdapter(RecallPort):
    """
    ItemCF 协同过滤召回适配器
    对接 ItemCF 召回服务
    """
    
    @property
    def name(self) -> str:
        return "item_cf_recall"
    
    async def recall(self, user: UserProfile, top_k: int) -> RecallResult:
        # 实现 ItemCF 召回逻辑（简化示例）
        # 真实实现可调用内部 ItemCF 服务或直接从 Redis 取结果
        return RecallResult(
            strategy_name=self.name,
            items=[],
            scores=[]
        )
```

### 次适配器：Kafka 事件发布

```python
# =============================================
# 次适配器：Kafka 事件发布
# 文件：adapters/secondary/kafka_event_adapter.py
# 实现 EventPublishPort 端口
# =============================================

import json
import asyncio
from typing import Dict, Any
from domain.ports import EventPublishPort
from config.settings import settings


class KafkaEventAdapter(EventPublishPort):
    """
    Kafka 事件发布适配器
    将领域事件发布到 Kafka，供下游消费者处理
    """
    
    def __init__(self, bootstrap_servers: str, topic_prefix: str = 'rec'):
        self._bootstrap_servers = bootstrap_servers
        self._topic_prefix = topic_prefix
        self._producer = None
        self._connected = False
    
    async def connect(self):
        from aiokafka import AIOKafkaProducer
        self._producer = AIOKafkaProducer(
            bootstrap_servers=self._bootstrap_servers,
            value_serializer=lambda v: json.dumps(v, ensure_ascii=False).encode('utf-8'),
            acks='all',  # 所有副本确认
            retries=3,
            retry_backoff_ms=100,
        )
        await self._producer.start()
        self._connected = True
    
    async def publish(self, event_type: str, payload: Dict[str, Any]) -> None:
        """
        发布事件到 Kafka
        如果 Kafka 不可用，记录日志但不影响主流程（韧性好）
        """
        if not self._connected:
            return
        
        topic = f"{self._topic_prefix}.{event_type}"
        
        event = {
            'type': event_type,
            'payload': payload,
            'timestamp': asyncio.get_event_loop().time()
        }
        
        try:
            # 异步发送，不阻塞主流程
            await self._producer.send_and_wait(topic, event)
        except Exception as e:
            # ❌ Kafka 挂了不应该让推荐失败——打印日志即可
            print(f"[WARN] Kafka publish failed for {event_type}: {e}")
            # 这里是容错：事件发送失败 = 不影响推荐结果
            # 真实生产环境可以写本地文件作为 fallback
            pass
    
    async def close(self):
        if self._producer:
            await self._producer.stop()
```

## 依赖注入容器（DI Container）

```python
# =============================================
# 依赖注入容器
# 文件：di/container.py
# 作用：组装所有适配器，统一管理生命周期
# =============================================

from adapters.primary.flask_adapter import init_adapter as init_flask
from adapters.secondary.mysql_user_adapter import MySQLUserProfileAdapter
from adapters.secondary.embedding_model_adapter import (
    EmbeddingRecallAdapter, ItemCFRecallAdapter
)
from adapters.secondary.kafka_event_adapter import KafkaEventAdapter
from adapters.secondary.redis_cache_adapter import RedisCacheAdapter
from domain.ports import RankingPort
from domain.service import RecommendationService
from config.settings import settings


class DIContainer:
    """
    依赖注入容器：
    所有适配器的创建和组装都在这里
    """
    
    def __init__(self):
        self._user_profile_adapter: MySQLUserProfileAdapter = None
        self._redis_cache: RedisCacheAdapter = None
        self._kafka_adapter: KafkaEventAdapter = None
        self._recommendation_service: RecommendationService = None
    
    async def initialize(self):
        """启动时初始化所有适配器（连接池/Kafka生产者等）"""
        
        # 用户画像：MySQL
        self._user_profile_adapter = MySQLUserProfileAdapter()
        await self._user_profile_adapter.initialize()
        
        # 缓存：Redis
        self._redis_cache = RedisCacheAdapter(
            host=settings.REDIS_HOST,
            port=settings.REDIS_PORT,
            db=settings.REDIS_DB
        )
        await self._redis_cache.connect()
        
        # 事件发布：Kafka
        self._kafka_adapter = KafkaEventAdapter(
            bootstrap_servers=settings.KAFKA_BOOTSTRAP_SERVERS
        )
        await self._kafka_adapter.connect()
        
        # 召回策略列表（可热插拔，加载顺序就是优先级）
        recall_strategies = [
            EmbeddingRecallAdapter(settings.EMBEDDING_SERVICE_URL),
            ItemCFRecallAdapter(),  # 可以随时增加新的召回策略
        ]
        
        # 排序模型（Mock，真实环境替换为实际模型适配器）
        ranking_adapter = MockRankingAdapter()
        
        # 推荐服务（核心领域逻辑）
        self._recommendation_service = RecommendationService(
            recall_strategies=recall_strategies,
            ranking_model=ranking_adapter,
            event_publisher=self._kafka_adapter,
        )
        
        # 通知 Flask 适配器
        init_flask(self._recommendation_service)
    
    async def get_user_profile(self, user_id: str):
        """获取用户画像（走Redis缓存，缓存miss走MySQL）"""
        # 先查 Redis 缓存
        cached = await self._redis_cache.get_user_profile(user_id)
        if cached:
            return cached
        # 缓存 miss，查 MySQL
        profile = await self._user_profile_adapter.get_profile(user_id)
        if profile:
            await self._redis_cache.set_user_profile(user_id, profile, ttl=3600)
        return profile
    
    async def shutdown(self):
        """关闭时释放所有资源"""
        await self._user_profile_adapter.close()
        await self._redis_cache.close()
        await self._kafka_adapter.close()


# 全局单例
container = DIContainer()
```

```python
class MockRecallAdapter(RecallPort):

    def name(self):
```

## 六边形架构 vs 整洁架构 vs MVC 对比

| 维度 | MVC | 整洁架构 | 六边形架构 |
|------|-----|---------|-----------|
| 核心 | 分 UI / 数据 / 逻辑 | 分层依赖方向 | 分端口与适配器 |
| 依赖方向 | Controller → Service → Model | 外层依赖内层 | 适配器依赖端口 |
| 框架位置 | 框架 = 核心 | 框架在外层 | 框架 = 适配器 |
| 测试友好度 | 需启动整个应用 | 可按层 Mock | 所有外部依赖可 Mock |
| 适用场景 | Web 小应用 | 中大型系统 | **推荐系统 / AI 服务集成** |
| 适配器概念 | 无 | 有 | **核心概念** |
| 换数据库成本 | 改 Repository | 换 Adapter | 换 Adapter |

### 六边形 + 整洁架构结合（推荐系统最优实践）

```
┌────────────────────────────────────────────────────────────┐
│                      外 层（Infrastructure）                  │
│  Flask适配器 │ gRPC适配器 │ MySQL适配器 │ Redis适配器 │ Kafka适配器 │
├────────────────────────────────────────────────────────────┤
│                    应 用 层（Application）                    │
│           RecallUseCase │ RankUseCase │ ABTestUseCase        │
├────────────────────────────────────────────────────────────┤
│                     领 域 层（Domain）                        │
│   RecallPort(interface) │ RankingPort(interface) │ Service  │
│   Entity: UserProfile / Item / RecommendationResult          │
│   ValueObject: RecallResult / ScoreCard                      │
├────────────────────────────────────────────────────────────┤
│                   接 口 层（Interfaces）                      │
│              Request/Response DTOs │ 协议转换                │
└────────────────────────────────────────────────────────────┘
         依赖方向：外层 ──────────────► 内层（只能向内）
```

## 推荐系统六边形架构决策树

```
你的推荐系统需要接入新的外部服务吗？
├─ 是用的什么协议？
│   ├─ HTTP REST → 新写一个 Driving Adapter（Flask/gRPC 同理）
│   ├─ gRPC     → 新写一个 Secondary Adapter（实现对应 Port 接口）
│   └─ 消息队列  → 新写一个 Event Adapter（实现 EventPublishPort）
│
├─ 需要换 AI 模型？
│   ├─ 召回模型换 → 实现新的 RecallPort 插进去（热插拔！）
│   ├─ 排序模型换 → 实现新的 RankingPort 插进去
│   └─ AB实验对比 → 同时注册两个 RankingPort，AB分流路由选
│
├─ 需要加新的召回策略？
│   └─ 写一个新的 RecallPort 实现，加到 recall_strategies 列表即可
│
└─ 需要换数据库？
    └─ 实现新的 Repository Port，换掉 MySQLAdapter → Done！
```

## 常见误区

| 误区 | 正确做法 |
|------|---------|
| ❌ 端口里写了业务逻辑 | 端口只是接口契约，逻辑在 Service 层 |
| ❌ 一个适配器实现多个端口 | 一个适配器实现一个端口，职责单一 |
| ❌ 领域服务直接调 Redis | 领域服务只调端口，具体实现在适配器 |
| ❌ 所有东西都写一个 container | 按功能分 container，避免上帝对象 |
| ❌ 过度抽象：每个小功能都写端口 | 只对"可能变化"的外部依赖抽象端口，不要过度设计 |
| ❌ 12-Factor = 硬编码环境变量 | 敏感信息用 Vault / K8s Secret，不要写进环境变量明文 |

## 适用场景

- **推荐系统核心服务**：召回/排序/重排策略需要灵活切换
- **AI 模型服务集成**：随时切换 XGBoost → DeepFM → LLMRank
- **多租户系统**：不同租户用不同的 Adapter 实现（隔离策略）
- **AB 测试平台**：不同实验组用不同 Adapter，动态注入
- **遗留系统改造**：新功能用六边形架构，对接遗留代码用 Adapter 包装

| 问题 | 六边形解决方案 |
|------|--------------|

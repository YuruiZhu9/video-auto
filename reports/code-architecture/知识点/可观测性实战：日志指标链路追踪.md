# 可观测性实战：日志 · 指标 · 链路追踪

> 上线只是开始，上线之后你能不能看清系统的"心跳"，才决定你能睡多少个好觉。

## 什么是可观测性？

可观测性（Observability）= 你能从外部输出，推断出系统内部状态的能力。

传统的"监控"是：CPU > 80% → 告警。这是被动的。

可观测性是：你知道任意时刻推荐结果的点击率、延迟分布、哪个用户看到了什么推荐，以及**为什么**。

```
可观测性三支柱（The Three Pillars）
═══════════════════════════════════════════════════════
📝 日志（Logs）      → "发生了什么"（离散的事件）
📊 指标（Metrics）   → "现在怎么样"（聚合的数值）
🔗 链路（Traces）    → "怎么发生的"（调用链路）
```

三者互补，缺一不可：

| 维度 | 回答的问题 | 推荐系统中的例子 |
|------|-----------|----------------|
| Logs | 刚才发生了什么？ | "用户 123 的推荐请求失败，原因是 Redis 超时" |
| Metrics | 系统健康吗？ | "P99 延迟 350ms，超过了 300ms 的 SLO" |
| Traces | 慢在哪一步？ | "排序服务耗时 280ms，其中模型推理占 250ms" |

import logging
import json
import time
from datetime import datetime, timezone
from typing import Optional
from contextvars import ContextVar

# 请求级别的 context，打印日志时自动带上
request_ctx: ContextVar[dict] = ContextVar("request_ctx", default={})

class StructuredFormatter(logging.Formatter):
    """输出 JSON 格式日志，方便 ELK 采集"""
    
    def format(self, record: logging.LogRecord) -> str:
        log_data = {
            "timestamp": datetime.now(timezone.utc).isoformat(),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            **{k: v for k, v in request_ctx.get().items()}
        }
        if record.exc_info:
            log_data["exception"] = self.formatException(record.exc_info)
        if hasattr(record, "extra"):
            log_data.update(record.extra)
        return json.dumps(log_data, ensure_ascii=False)


def setup_logger(name: str, level: int = logging.INFO) -> logging.Logger:
    logger = logging.getLogger(name)
    logger.setLevel(level)
    if not logger.handlers:
        handler = logging.StreamHandler()
        handler.setFormatter(StructuredFormatter())
        logger.addHandler(handler)
    return logger

# FastAPI 中间件：自动注入请求上下文
# =============================================
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request

class RequestContextMiddleware(BaseHTTPMiddleware):
    """每个请求自动生成 request_id，写入所有日志"""
    
    async def dispatch(self, request: Request, call_next):
        request_id = request.headers.get("X-Request-ID", f"req-{time.time_ns()}")
        ctx = {
            "request_id": request_id,
            "user_id": request.headers.get("X-User-ID", "anonymous"),
            "ip": request.client.host if request.client else "unknown",
            "path": request.url.path,
        }
        token = request_ctx.set(ctx)
        try:
            response = await call_next(request)
            response.headers["X-Request-ID"] = request_id
            return response
        finally:
            request_ctx.reset(token)

**正例：结构化 JSON 日志**
```python

})
```

**日志级别使用规范：**

| 级别 | 什么时候用 | 推荐系统例子 |
|------|-----------|-------------|
| DEBUG | 开发调试，上线关闭 | 召回候选集内容（太多，上线关掉） |
| INFO | 正常流程 | 推荐请求、用户点击、曝光 |
| WARNING | 异常但能处理 | 缓存未命中、降级触发、单次超时 |
| ERROR | 需要处理 | 模型推理失败、Redis 连接断开 |

# =============================================
# 推荐请求指标采集（装饰器）
# =============================================
import time
from functools import wraps

def track_rec_metrics(scene: str):
    """装饰器：自动采集推荐请求的指标"""
    def decorator(func):
        @wraps(func)
        async def wrapper(request, *args, **kwargs):
            start = time.perf_counter()
            status = "success"
            num_items = 0
            try:
                result = await func(request, *args, **kwargs)
                num_items = len(result.get("items", []))
                return result
            except Exception as e:
                status = "error"
                rec_request_errors.labels(scene=scene, error_type=type(e).__name__).inc()
                raise
            finally:
                latency = time.perf_counter() - start
                rec_request_total.labels(scene=scene, status=status).inc()
                rec_request_duration.labels(scene=scene).observe(latency)
                rec_items_returned.labels(scene=scene).observe(num_items)
        return wrapper
    return decorator

## 三、链路追踪实战（Traces）

### 3.1 为什么推荐系统需要链路追踪？

```
一次推荐请求的完整链路：
═══════════════════════════════════════════════════════════════

客户端
   ↓ HTTP (10ms)
API Gateway
   ↓ gRPC (20ms)
召回服务 ──────────────────────────────────────
   ├─ ItemCF 召回     (15ms)
   ├─ UserCF 召回     (18ms)       ← 需要知道各路耗时
   ├─ Embedding 召回  (45ms)  ←─── 这路慢！
   └─ Hot 召回        (5ms)
   ↓ 合并             (3ms)
排序服务
   ↓ gRPC (8ms)
模型推理服务         (150ms)  ←─── 这步也不快！
   ↓
重排服务             (10ms)
   ↓
Redis 写入缓存        (5ms)
   ↓
返回客户端

总耗时：280ms
═══════════════════════════════════════════════════════════════

如果没有链路追踪：你只知道总耗时 280ms
有链路追踪：你知道 Embedding 召回 45ms + 模型推理 150ms = 瓶颈在这里
```

### 3.2 OpenTelemetry 链路追踪实现

```python
# =============================================
# 推荐系统链路追踪（OpenTelemetry Python）
# =============================================
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.sdk.resources import Resource
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.trace import Status, StatusCode
import time

# 初始化 OTLP（发送到 Jaeger / Grafana Tempo）
def setup_tracing(service_name: str):
    provider = TracerProvider(
        resource=Resource.create({"service.name": service_name})
    )
    otlp_exporter = OTLPSpanExporter(
        endpoint="http://tempo:4317",
        insecure=True,
    )
    provider.add_span_processor(BatchSpanProcessor(otlp_exporter))
    trace.set_tracer_provider(provider)
    return trace.get_tracer(service_name)


# =============================================
# 推荐链路追踪工具类
# =============================================
class RecommendationTracer:
    """封装推荐系统各阶段的链路追踪"""
    
    def __init__(self, tracer):
        self.tracer = tracer
        self._spans = {}
    
    def start_span(self, name: str, attrs: dict):
        """启动一个 span"""
        span = self.tracer.start_span(name, attributes=attrs)
        self._spans[name] = span
        return span
    
    def end_span(self, name: str, extra_attrs: dict = None):
        """结束一个 span"""
        span = self._spans.pop(name, None)
        if span:
            if extra_attrs:
                for k, v in extra_attrs.items():
                    span.set_attribute(k, v)
            span.set_status(Status(StatusCode.OK))
            span.end()
    
    def record_error(self, name: str, error: Exception):
        """记录 span 错误"""
        span = self._spans.get(name)
        if span:
            span.set_status(Status(StatusCode.ERROR, str(error)))
            span.record_exception(error)


# =============================================
# 链路追踪中间件（自动注入 trace_id）
# =============================================
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request

class TracingMiddleware(BaseHTTPMiddleware):
    """自动把 trace_id 注入响应头，方便查日志"""
    
    async def dispatch(self, request: Request, call_next):
        span = trace.get_current_span()
        trace_id = format(span.get_span_context().trace_id, "032x")
        
        ctx = request_ctx.get().copy()
        ctx["trace_id"] = trace_id
        token = request_ctx.set(ctx)
        
        try:
            response = await call_next(request)
            response.headers["X-Trace-ID"] = trace_id
            return response
        finally:
            request_ctx.reset(token)


# =============================================
# 带链路追踪的推荐流程
# =============================================
async def recommend_with_tracing(tracer_obj, user_id: str, scene: str, num_items: int = 20):
    """
    带链路追踪的推荐流程。
    在 Grafana/Jaeger 中可以看到完整调用树：
    
    recommend (根 span)
    ├─ recall.item_cf
    ├─ recall.embedding_sim
    ├─ recall.hot
    ├─ rank.model_inference
    └─ rerank.diversity
    """
    root_span = tracer_obj.start_span(
        "recommend",
        {"user_id": user_id, "scene": scene, "num_items": num_items}
    )
    
    try:
        # ================== 召回阶段 ==================
        span_name = "recall.item_cf"
        tracer_obj.start_span(span_name, {
            "stage": "recall", "strategy": "item_cf",
            "request_id": request_ctx.get().get("request_id", "")
        })
        t0 = time.perf_counter()
        item_cf_items = await recall_item_cf(user_id, top_k=50)
        tracer_obj.end_span(span_name, {"num_recalled": len(item_cf_items), "latency_ms": (time.perf_counter()-t0)*1000})
        
        span_name = "recall.embedding_sim"
        tracer_obj.start_span(span_name, {"stage": "recall", "strategy": "embedding_sim"})
        t0 = time.perf_counter()
        emb_items = await recall_embedding_sim(user_id, top_k=50)
        tracer_obj.end_span(span_name, {"num_recalled": len(emb_items), "latency_ms": (time.perf_counter()-t0)*1000})
        
        span_name = "recall.hot"
        tracer_obj.start_span(span_name, {"stage": "recall", "strategy": "hot"})
        t0 = time.perf_counter()
        hot_items = await recall_hot(trending_tag=None, top_k=20)
        tracer_obj.end_span(span_name, {"num_recalled": len(hot_items), "latency_ms": (time.perf_counter()-t0)*1000})
        
        merged = merge_recall_results(item_cf_items, emb_items, hot_items)
        
        # ================== 排序阶段 ==================
        span_name = "rank.model_inference"
        tracer_obj.start_span(span_name, {
            "stage": "rank", "model_name": "xgb_rank_v3",
            "num_candidates": len(merged)
        })
        t0 = time.perf_counter()
        ranked_items = await rank_with_model(merged, user_features=None)
        tracer_obj.end_span(span_name, {"num_ranked": len(ranked_items), "latency_ms": (time.perf_counter()-t0)*1000})
        
        # ================== 重排阶段 ==================
        span_name = "rerank.diversity"
        tracer_obj.start_span(span_name, {"stage": "rerank"})
        t0 = time.perf_counter()
        final_items = await rerank_diversity(ranked_items, num_items=num_items)
        tracer_obj.end_span(span_name, {"num_final": len(final_items), "latency_ms": (time.perf_counter()-t0)*1000})
        
        root_span.set_attribute("num_final", len(final_items))
        return final_items
        
    except Exception as e:
        tracer_obj.record_error("recommend", e)
        raise
    finally:
        tracer_obj.end_span("recommend")
```

### 5.1 推荐系统 SLO 设定

```python
# =============================================
# 推荐系统 SLO 定义与健康度检查
# =============================================
from dataclasses import dataclass

@dataclass
class ServiceLevelObjective:
    name: str
    description: str
    target: float          # 目标值，如 0.999
    unit: str              # 单位：ratio / seconds / ratio
    
    def check(self, actual: float) -> dict:
        ok = actual >= self.target if self.unit == "ratio" else actual <= self.target
        return {
            "name": self.name,
            "ok": ok,
            "actual": actual,
            "target": self.target,
            "status": "🟢 OK" if ok else "🔴 BREACHING",
        }


# 推荐系统核心 SLO
RECOMMENDATION_SLOS = [
    ServiceLevelObjective("可用性", "推荐 API 成功返回率", 0.999, "ratio"),
    ServiceLevelObjective("延迟-P50", "P50 请求延迟", 0.100, "seconds"),
    ServiceLevelObjective("延迟-P99", "P99 请求延迟", 0.300, "seconds"),
    ServiceLevelObjective("缓存命中率", "Redis 缓存命中率", 0.950, "ratio"),
    ServiceLevelObjective("曝光正确性", "曝光数据上报完整率", 0.995, "ratio"),
]


def check_all_slos(metrics: dict) -> list:
    """检查所有 SLO，返回健康状态"""
    checks = [
        RECOMMENDATION_SLOS[0].check(metrics.get("availability", 0)),
        RECOMMENDATION_SLOS[1].check(metrics.get("latency_p50", 0)),
        RECOMMENDATION_SLOS[2].check(metrics.get("latency_p99", 0)),
        RECOMMENDATION_SLOS[3].check(metrics.get("cache_hit_ratio", 0)),
        RECOMMENDATION_SLOS[4].check(metrics.get("expose_completeness", 0)),
    ]
    return checks
```

### 5.2 错误预算告警（Error Budget Burn Rate）

```python
# =============================================
# 错误预算消耗速度监控
# =============================================
class ErrorBudgetMonitor:
    """
    错误预算 = 允许的"不健康"时间。
    消耗速度太快 → 提前预警，不要等真的 SLO 破了再告警。
    
    burn_rate = 1.0 → 正好按计划消耗（正常）
    burn_rate > 1.0 → 消耗太快（预警）
    burn_rate > 14.4 → 1 小时内烧完整月预算（紧急）
    """
    
    def __init__(self, slo_target: float, window_days: int = 30):
        self.error_budget = 1 - slo_target
        self.window_days = window_days
        self.window_hours = {"1h": 1, "6h": 6, "3d": 72, "30d": 720}
    
    def burn_rate(self, current_error_rate: float) -> dict:
        """
        计算多窗口燃烧速度。
        """
        results = {}
        for window_name, hours in self.window_hours.items():
            # 燃烧速度 = (当前错误率 × 窗口时长) / (错误预算 × 窗口时长)
            rate = current_error_rate / self.error_budget
            results[window_name] = {
                "burn_rate": round(rate, 2),
                "severity": self._severity(rate),
                "description": self._description(rate, window_name),
            }
        return results
    
    def _severity(self, rate: float) -> str:
        if rate >= 14.4:
            return "🔴 CRITICAL"    # 1h 内烧完整月预算
        elif rate >= 6.0:
            return "🟠 HIGH"         # 6h 内烧完
        elif rate >= 1.0:
            return "🟡 WARNING"      # 按计划消耗
        else:
            return "🟢 HEALTHY"     # 消耗慢于计划
    
    def _description(self, rate: float, window: str) -> str:
        if rate <= 0:
            return f"{window} 内无错误，预算不消耗"
        hours_left = self.window_days * 24 / rate
        return f"按当前速度，约 {hours_left:.0f} 小时烧完整月错误预算"
```

## 七、常见误区

| 误区 | 真相 |
|------|------|
| "日志越多越好" | 日志太多反而找不到重点，只记关键的 4 类日志 |
| "只监控技术指标就够了" | CTR/CVR 等业务指标同等重要 |
| "链路追踪太重了，上线再装" | 上线前就要装好，否则出问题无从排查 |
| "告警越敏感越好" | 告警太多 → 告警疲劳 → 真正的问题被忽视 |
| "Grafana 看板建好就够了" | 看板要有人看才有价值，每天至少 review 一次 |

# 向量数据库架构实战：推荐系统语义召回基础设施

> 为什么推荐系统需要向量数据库？
> 
> 当"看了这个视频的人也在看…"从"同类目"进化到"语义相似"，当搜索"适合女生的生日礼物"能直接召回礼物类商品——这一切的背后，是 Embedding 向量 + ANN 搜索在驱动。

---

## 概念解释

### 什么是向量数据库？

**向量数据库（Vector Database）** 是专门存储和检索高维向量（Embedding）的数据库，支持**近似最近邻（ANN）**搜索，在毫秒级从数十亿向量中找出最相似的 Top-K。

**为什么不用 MySQL 的 LIKE 或 ES 的倒排索引？**

| 维度 | LIKE / 倒排索引 | 向量数据库 |
|------|----------------|-----------|
| 搜索方式 | 精确匹配 / 关键词 | 语义相似度 |
| 相似性定义 | 字符串相等 |  cosine / euclidean / dot |
| 召回能力 | 只能找"同类" | 能找"同义/相关" |
| 适用场景 | 关键词搜索 | 语义搜索、推荐召回 |

**推荐系统中向量数据库的核心价值：**

```
传统召回（基于标签/类目）：
  用户点击"手机" → 召回落叶"手机"类目 → 结果单调

语义向量召回：
  用户点击"拍照好的手机" → 查用户向量 → ANN 搜索 → 召回落叶语义相似物品
  （"旗舰影像手机"、"人像摄影强机"、"自拍神器" 都能被召回）
```

### 核心概念

| 概念 | 说明 | 推荐系统中的应用 |
|------|------|----------------|
| **Embedding** | 将文本/图片/视频映射为固定维度向量 | text2vec / item2vec / image2vec |
| **ANN 索引** | Approximate Nearest Neighbor，近似最近邻 | HNSW / IVF-Flat / DiskANN |
| **Top-K 检索 | 从海量向量中找出最相似的 K 个 | 粗召回 → 精排 → 重排 |
| **向量维度** | 常见 128/256/512/1024/1536/3072 | 维度越高越精确，但存储/检索更慢 |
| **相似度度量** | cosine / euclidean / dot_product | 推荐系统常用 cosine |
| **Filtering | 预过滤条件（SQL WHERE 级别） | "只召回落叶该类目的商品" |
| **Hybrid Search | 向量检索 + 关键词混合 | 语义 + 精确双重召回 |

## ANN 索引算法对比与选型

### 四种主流算法横向对比

| 算法 | 召回精度 | QPS | 内存占用 | 构建时间 | 适用场景 |
|------|---------|-----|---------|---------|---------|
| **HNSW** | ⭐⭐⭐⭐⭐ 最高 | ⭐⭐⭐⭐ 高 | ⭐⭐⭐ 中 | ⭐⭐ 慢 | **生产首选**，精度要求高的场景 |
| **IVF-Flat** | ⭐⭐⭐⭐ 高 | ⭐⭐⭐ 中 | ⭐⭐⭐ 中 | ⭐⭐⭐ 中 | 大量数据、需要精确召回 |
| **IVF-PQ** | ⭐⭐⭐ 中 | ⭐⭐⭐⭐⭐ 最高 | ⭐⭐⭐⭐⭐ 最低 | ⭐⭐⭐⭐ 快 | 超大规模数据、内存敏感 |
| **DiskANN** | ⭐⭐⭐⭐ 高 | ⭐⭐⭐⭐ 高 | ⭐⭐⭐⭐⭐ 最低 | ⭐⭐⭐⭐⭐ 最快 | **十亿级数据**，无法全量内存 |

### HNSW 详解（生产最常用）

**HNSW（Hierarchical Navigable Small World）** 是分层可导航小世界图，通过构建多层图实现 O(log N) 级别的搜索复杂度：

```
HNSW 分层结构（类似电梯选层）：

Layer 2:  ──[节点A]───────────────[节点B]───────────────[节点C]──  ← 跳层快速定位
            ↓                         ↓
Layer 1:  [A]──[D]──[E]──[A]──[G]──[H]──[I]──[B]──[J]──[K]──[C]  ← 中层筛选
            ↓        ↓     ↓     ↓     ↓     ↓     ↓     ↓
Layer 0:  [A]──[D]──[E]──[A]──[G]──[H]──[I]──[B]──[J]──[K]──[C]── ...  ← 底层精确搜索
```

**HNSW 核心参数：**

| 参数 | 说明 | 推荐值 | 越大越… |
|------|------|-------|---------|
| `M` | 每层连接数 | 16-64 | 精度越高，内存越大 |
| `efConstruction` | 构建时搜索范围 | 100-400 | 精度越高，构建越慢 |
| `efSearch` | 搜索时搜索范围 | 50-500 | 精度越高，QPS 越低 |
| `ef` | 搜索候选集大小 | Top-K × 2~10 | 越大越精确 |

### 选型决策树

```
数据量级是多少？
├─ < 100万向量 → HNSW 或 IVF-Flat，优先 HNSW
├─ 100万 ~ 1亿 → HNSW，ef 参数调优
└─ > 1亿 → DiskANN（内存不足用 DiskANN，避免 PQ 精度损失）

是否内存敏感？
├─ 是 → IVF-PQ（压缩 4~16 倍），精度可接受
└─ 否 → HNSW（精度最高，内存可接受）

是否需要实时更新？
├─ 是 → Milvus / Qdrant（HNSW 支持删除+增量插入）
└─ 否 → FAISS（离线构建，不支持实时更新）
```

## 推荐系统召回架构中的向量数据库

### 典型推荐系统召回层架构

```
用户请求（uid, context）
    │
    ├─ 协同过滤召回（ItemCF/UserCF）
    ├─ 热门召回（规则引擎）
    ├─ 新品召回（时间窗口过滤）
    └─ 🌟 语义向量召回（向量数据库） ← 核心新增
           │
           ├─ 查用户 Embedding
           ├─ ANN 搜索 Top-200
           ├─ SQL 过滤（类目/品牌/库存）
           └─ 返回候选集
    │
    ▼
精排模型（粗排 Top-200 → 精排 Top-50）
    │
    ▼
重排（多样性、频控、广告穿插）
    │
    ▼
返回 Top-10 推荐结果
```

### 多路召回中的向量召回策略

```python
# 推荐引擎 - 多路召回编排器（简化版）
from abc import ABC, abstractmethod
from typing import List, Dict, Any
import numpy as np

class RecallResult:
    """统一召回结果格式"""
    def __init__(self, strategy_name: str, items: List[Dict[str, Any]], scores: List[float]):
        self.strategy_name = strategy_name
        self.items = items
        self.scores = scores

    def __len__(self):
        return len(self.items)

class BaseRecallStrategy(ABC):
    """召回策略基类（策略模式）"""
    
    @abstractmethod
    async def recall(self, user_id: str, context: Dict, top_k: int) -> RecallResult:
        pass

    @property
    @abstractmethod
    def name(self) -> str:
        pass


class VectorRecallStrategy(BaseRecallStrategy):
    """语义向量召回 - 向量数据库驱动"""
    
    def __init__(self, vector_db: 'VectorDBClient', embedding_service: 'EmbeddingService'):
        self.vector_db = vector_db
        self.embedding_service = embedding_service
    
    @property
    def name(self) -> str:
        return "语义向量召回"
    
    async def recall(self, user_id: str, context: Dict, top_k: int) -> RecallResult:
        # Step 1: 获取用户实时 Embedding（从 Redis 或实时计算）
        user_embedding = await self._get_user_embedding(user_id, context)
        
        # Step 2: ANN 搜索 - 从向量数据库召回相似物品
        raw_results = await self.vector_db.search(
            collection="item_embeddings",
            vector=user_embedding,
            top_k=top_k * 3,  # 多召回一些，后面会过滤
            filter={"status": "online", "category_id": context.get("category_filter")}
        )
        
        # Step 3: 后处理 - 移除用户已交互物品（去重）
        interacted_ids = await self._get_user_interacted_items(user_id)
        filtered = [
            (item, score) for item, score in zip(raw_results["items"], raw_results["scores"])
            if item["item_id"] not in interacted_ids
        ][:top_k]
        
        return RecallResult(
            strategy_name=self.name,
            items=[item for item, _ in filtered],
            scores=[score for _, score in filtered]
        )
    
    async def _get_user_embedding(self, user_id: str, context: Dict) -> np.ndarray:
        # 优先用 Redis 缓存的用户向量
        cached = await redis.get(f"ue:{user_id}")
        if cached:
            return np.frombuffer(cached, dtype=np.float32)
        
        # 否则实时计算（用户序列 → Embedding 服务）
        user_history = await self._get_user_history(user_id, limit=50)
        embedding = await self.embedding_service.encode_text(
            " ".join([item["title"] for item in user_history])
        )
        # 缓存 1 小时
        await redis.setex(f"ue:{user_id}", 3600, embedding.tobytes())
        return embedding
    
    async def _get_user_interacted_items(self, user_id: str) -> set:
        """获取用户已交互物品，避免重复推荐"""
        key = f"interacted:{user_id}"
        items = await redis.smembers(key)
        return set([i.decode() for i in items]) if items else set()
    
    async def _get_user_history(self, user_id: str, limit: int) -> List[Dict]:
        """获取用户行为历史"""
        return await mysql.fetchall(
            "SELECT item_id, title FROM user_behavior WHERE user_id=%s ORDER BY ts DESC LIMIT %s",
            (user_id, limit)
        )


class ItemCFRecallStrategy(BaseRecallStrategy):
    """ItemCF 协同过滤召回"""
    
    @property
    def name(self) -> str:
        return "ItemCF协同过滤召回"
    
    async def recall(self, user_id: str, context: Dict, top_k: int) -> RecallResult:
        # 获取用户最近交互的物品
        recent_items = await self._get_recent_items(user_id, n=5)
        if not recent_items:
            return RecallResult(self.name, [], [])
        
        # 对每个物品找相似物品（这里简化为查 MySQL）
        candidate_scores: Dict[str, float] = {}
        for item in recent_items:
            similar = await self._get_similar_items(item["item_id"], top_k=20)
            for sim_item, score in similar:
                if sim_item["item_id"] not in candidate_scores:
                    candidate_scores[sim_item["item_id"]] = 0.0
                candidate_scores[sim_item["item_id"]] += score * item.get("weight", 1.0)
        
        # 排序取 Top-K
        sorted_items = sorted(candidate_scores.items(), key=lambda x: -x[1])[:top_k]
        item_ids = [x[0] for x in sorted_items]
        items = await self._get_items_by_ids(item_ids)
        scores = [x[1] for x in sorted_items]
        
        return RecallResult(self.name, items, scores)


class RecallerEngine:
    """多路召回引擎 - 编排多种召回策略"""
    
    def __init__(self):
        self.strategies: Dict[str, BaseRecallStrategy] = {}
    
    def register(self, name: str, strategy: BaseRecallStrategy):
        self.strategies[name] = strategy
    
    async def recall(self, user_id: str, context: Dict) -> Dict[str, RecallResult]:
        """
        并行执行所有召回策略
        返回：{策略名: RecallResult}
        """
        tasks = {
            name: strategy.recall(user_id, context, top_k=100)
            for name, strategy in self.strategies.items()
        }
        
        results = {}
        for name, coro in asyncio.as_completed(tasks.items()):
            _, result = await coro
            results[name] = result
        
        return results
```

### 生产推荐：Milvus 深度解析

```python
# Milvus 实战 - Python SDK v2
from pymilvus import (
    connections, Collection, FieldSchema, CollectionSchema,
    DataType, utility, List, AnnSearchRequest, RRFRanker
)
import numpy as np

class MilvusVectorDB:
    """Milvus 向量数据库封装 - 推荐系统语义召回"""
    
    def __init__(self, host: str = "localhost", port: int = 19530):
        self.host = host
        self.port = port
        self.connected = False
    
    def connect(self):
        """建立连接（通常在应用启动时调用）"""
        connections.connect(
            alias="default",
            host=self.host,
            port=self.port,
            timeout=30
        )
        self.connected = True
        print(f"✅ Milvus connected: {self.host}:{self.port}")
    
    def create_collection(
        self,
        name: str,
        dimension: int,
        metric_type: str = "COSINE",
        index_type: str = "HNSW",
        description: str = ""
    ):
        """
        创建 Collection（类似 MySQL 的 Table）
        
        Args:
            name: Collection 名称
            dimension: 向量维度（text2vec-base 是 768 维）
            metric_type: 相似度度量方式（COSINE/IP/EUCLIDIAN）
            index_type: 索引类型（HNSW/IVF_FLAT/IVF_PQ）
        """
        # 定义 Schema
        fields = [
            FieldSchema(name="item_id", dtype=DataType.INT64, is_primary=True, description="商品ID"),
            FieldSchema(name="title", dtype=DataType.VARCHAR, max_length=512, description="商品标题"),
            FieldSchema(name="category_id", dtype=DataType.INT64, description="类目ID"),
            FieldSchema(name="brand_id", dtype=DataType.INT64, description="品牌ID"),
            FieldSchema(name="status", dtype=DataType.VARCHAR, max_length=16, description="状态"),
            FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=dimension, description="文本向量"),
        ]
        schema = CollectionSchema(fields=fields, description=description)
        
        # 删除旧 Collection（重建时）
        if utility.has_collection(name):
            utility.drop_collection(name)
        
        collection = Collection(name=name, schema=schema)
        
        # 创建索引（索引创建后才能插入数据）
        index_params = {
            "metric_type": metric_type,
            "index_type": index_type,
            "params": {"M": 16, "efConstruction": 200}  # HNSW 参数
        }
        collection.create_index(
            field_name="embedding",
            index_params=index_params
        )
        
        # 创建 Field 索引（加速 Filtering）
        collection.create_index(
            field_name="category_id",
            index_params={"index_type": "STL_SORT", "params": {}}
        )
        collection.create_index(
            field_name="status",
            index_params={"index_type": "INVERTED", "params": {}}
        )
        
        collection.load()  # 加载到内存
        return collection
    
    async def insert_items(self, collection_name: str, items: List[Dict]):
        """批量插入商品向量数据"""
        collection = Collection(collection_name)
        
        data = [
            [item["item_id"] for item in items],                          # item_id
            [item.get("title", "") for item in items],                    # title
            [item.get("category_id", 0) for item in items],               # category_id
            [item.get("brand_id", 0) for item in items],                   # brand_id
            [item.get("status", "online") for item in items],             # status
            [item["embedding"] for item in items],                       # embedding (List[float])
        ]
        
        result = collection.insert(data)
        collection.flush()  # 刷盘，确保数据可搜索
        print(f"✅ Inserted {len(items)} items, insert_count={result.insert_count}")
        return result
    
    async def search(
        self,
        collection_name: str,
        query_vector: List[float],
        top_k: int = 100,
        category_filter: int = None,
        brand_filter: int = None,
        status_filter: str = "online"
    ) -> List[Dict]:
        """
        ANN 语义搜索
        
        Args:
            query_vector: 查询向量（用户 Embedding 或 Query Embedding）
            top_k: 返回数量
            category_filter: 类目过滤（支持 SQL WHERE 级别过滤）
            status_filter: 状态过滤
        
        Returns:
            List[Dict] - 最相似的商品列表
        """
        collection = Collection(collection_name)
        
        # 构建过滤表达式（Milvus Expr）
        filters = [f'status == "{status_filter}"']
        if category_filter:
            filters.append(f"category_id == {category_filter}")
        if brand_filter:
            filters.append(f"brand_id == {brand_filter}")
        filter_expr = " && ".join(filters)
        
        # 搜索参数
        search_params = {
            "metric_type": "COSINE",
            "params": {"ef": 128}  # ef 越大精度越高，QPS 越低
        }
        
        results = collection.search(
            data=[query_vector],
            anns_field="embedding",
            param=search_params,
            limit=top_k,
            expr=filter_expr,
            output_fields=["item_id", "title", "category_id", "brand_id"]
        )
        
        # 解析结果
        hits = []
        for hits_per_query in results:
            for hit in hits_per_query:
                hits.append({
                    "item_id": hit.entity.get("item_id"),
                    "title": hit.entity.get("title"),
                    "category_id": hit.entity.get("category_id"),
                    "brand_id": hit.entity.get("brand_id"),
                    "score": hit.distance,  # cosine 相似度（0~1，越高越相似）
                })
        
        return hits
    
    async def hybrid_search(
        self,
        collection_name: str,
        query_vector: List[float],
        query_text: str,
        top_k: int = 100,
        category_filter: int = None
    ) -> List[Dict]:
        """
        混合搜索：向量相似度 + BM25 关键词权重融合
        
        推荐系统场景：
        - 用户搜索 query_text = "拍照好的手机"
        - query_vector = text2vec("拍照好的手机")
        - 召回：向量语义相似 OR 关键词命中（标题含"手机"/"拍照"）
        """
        collection = Collection(collection_name)
        
        # 构建向量搜索请求
        vec_search_params = {"metric_type": "COSINE", "params": {"ef": 128}}
        vec_req = AnnSearchRequest(
            data=[query_vector],
            anns_field="embedding",
            param=vec_search_params,
            limit=top_k,
            expr=f"category_id == {category_filter}" if category_filter else None,
            output_fields=["item_id", "title", "category_id"]
        )
        
        # 构建关键词搜索请求（BM25）
        keyword_params = {"metric_type": "BM25"}
        keyword_req = AnnSearchRequest(
            data=[query_text],  # 传入原始文本，Weaviate/Qdrant 会自动做 BM25
            anns_field="title",  # 对 title 字段做关键词搜索
            param=keyword_params,
            limit=top_k,
            expr=f"category_id == {category_filter}" if category_filter else None,
            output_fields=["item_id", "title", "category_id"]
        )
        
        # RRF 融合（Reciprocal Rank Fusion）- 取两种召回排名的综合
        # 两者都在 Top-K → 排名都高 → 最终分数高
        results = collection.hybrid_search(
            reqs=[vec_req, keyword_req],
            ranker=RRFRanker(k=60),  # k=60 是 RRF 标准参数
            limit=top_k
        )
        
        hits = []
        for group in results:
            for hit in group:
                hits.append({
                    "item_id": hit["item_id"],
                    "title": hit["title"],
                    "category_id": hit["category_id"],
                    "score": hit.get("_score", 0),
                })
        
        return hits
    
    def close(self):
        connections.disconnect(alias="default")
        self.connected = False
```

### 训练-服务一致性（Skew）问题

**核心问题**：训练时的 Item Embedding 和在线推理时的 Embedding 必须来自同一模型，否则会导致"离线 AUC 高、在线效果差"。

```python
class EmbeddingService:
    """
    统一 Embedding 服务 - 解决训练-服务一致性问题
    
    训练时和推理时都用这个服务，保证向量来源完全一致
    """
    
    def __init__(self, model_name: str = "text2vec-base-chinese"):
        self.model_name = model_name
        # 加载模型（启动时一次，加载到内存）
        self.model = SentenceTransformer(model_name)
        self.device = "cuda" if torch.cuda.is_available() else "cpu"
        self.model.to(self.device)
    
    def encode_item(self, title: str, description: str = "") -> np.ndarray:
        """编码商品向量（离线和在线必须用同一个方法）"""
        text = f"{title} {description}".strip()
        embedding = self.model.encode(
            text,
            device=self.device,
            normalize_embeddings=True,  # cosine 相似度必须归一化
            show_progress_bar=False
        )
        return embedding.astype(np.float32)
    
    def encode_batch(self, texts: List[str]) -> np.ndarray:
        """批量编码（离线 ETL 使用）"""
        embeddings = self.model.encode(
            texts,
            device=self.device,
            batch_size=256,  # 批量加速
            normalize_embeddings=True,
            show_progress_bar=True
        )
        return embeddings.astype(np.float32)


# ==================== 离线 ETL 流程 ====================
async def sync_item_embeddings_to_milvus():
    """
    定时任务：全量同步商品向量到 Milvus
    推荐系统建议：每小时增量同步 + 每日全量同步
    """
    milvus = MilvusVectorDB(host="milvus-service", port=19530)
    milvus.connect()
    
    embedding_service = EmbeddingService(model_name="text2vec-base-chinese")
    
    # 1. 增量同步：获取过去 1 小时新增/更新的商品
    last_sync_time = await redis.get("last_embedding_sync_time")
    new_items = await mysql.fetchall("""
        SELECT item_id, title, description, category_id, brand_id
        FROM items
        WHERE updated_at > %s AND status = 'online'
    """, (last_sync_time or (datetime.now() - timedelta(hours=1)),))
    
    if not new_items:
        print("No new items to sync")
        return
    
    # 2. 批量生成 Embedding
    texts = [f"{item['title']} {item.get('description', '')}" for item in new_items]
    embeddings = embedding_service.encode_batch(texts)
    
    # 3. 批量写入 Milvus
    for item, embedding in zip(new_items, embeddings):
        item["embedding"] = embedding.tolist()
    
    await milvus.insert_items("item_embeddings", new_items)
    
    # 4. 记录同步时间
    await redis.set("last_embedding_sync_time", datetime.now().isoformat())
    print(f"✅ Synced {len(new_items)} item embeddings to Milvus")
    
    milvus.close()
```

### 反例：没有向量数据库时的"语义搜索"实现

```python
# ❌ 反例：基于 MySQL LIKE 的"伪语义搜索"
async def bad_semantic_search(keyword: str, top_k: int = 10):
    """
    问题：
    1. 只能精确匹配关键词，用户搜"手机"找不到"智能电话"
    2. 无法理解语义，"拍照好的手机"和"摄影强机"无法匹配
    3. 全表扫描，百万级数据直接超时
    4. 无法融合多模态（图片+文本）
    """
    results = await mysql.fetchall("""
        SELECT item_id, title, 
               MATCH(title) AGAINST(%s IN NATURAL LANGUAGE MODE) AS score
        FROM items
        WHERE MATCH(title) AGAINST(%s IN NATURAL LANGUAGE MODE)
          AND status = 'online'
        ORDER BY score DESC
        LIMIT %s
    """, (keyword, keyword, top_k))
    return results


# ✅ 正例：基于向量数据库的真语义搜索
async def good_semantic_search(
    milvus: MilvusVectorDB,
    embedding_service: EmbeddingService,
    keyword: str,
    top_k: int = 10,
    category_id: int = None
):
    """
    改进：
    1. 语义理解："拍照好的手机" → 向量 → 召回所有拍照相关手机
    2. 毫秒级响应（HNSW 索引）
    3. 支持 Filter 过滤（类目/品牌）
    4. 可扩展：图片搜索、多模态搜索
    """
    # 1. Query → Embedding
    query_vector = embedding_service.encode_item(keyword)
    
    # 2. ANN 搜索
    results = await milvus.search(
        collection_name="item_embeddings",
        query_vector=query_vector.tolist(),
        top_k=top_k,
        category_filter=category_id
    )
    
    return results
```

### 常见架构坑与解决方案

| 坑 | 问题 | 解决方案 |
|---|------|---------|
| **Embedding 模型版本不一致** | 训练用 v1，在线用 v2，向量空间不兼容 | 统一 EmbeddingService，版本号写入 Milvus Collection Tag |
| **向量维度不匹配** | text2vec-768维，milvus-1024维，报错 | 建库时明确维度，后续不随意更换模型 |
| **没有 Filtering 导致召回质量差** | 全量 ANN 搜索，召回一堆无关商品 | 必须带类目/品牌/库存等 Filtering |
| **Milvus 内存 OOM** | 1亿向量 × 768维 × 4字节 = 300GB | 用 IVF-PQ 压缩或 DiskANN 分片 |
| **实时更新导致内存碎片** | HNSW 增量插入后查询变慢 | 定期 Merge 或用 Qdrant（增量优化更好）|
| **向量和原始数据不同步** | 商品下架了，向量库还有 | 下架时同步删除 Milvus 中的向量 |
| **Embedding 服务超时** | 批量推理慢，导致 ETL 任务延迟 | 用 GPU 加速 + 模型量化（INT8） |

## 面试表达模板

**Q: 你们的推荐系统如何实现语义召回？**

> 我们的语义召回层基于向量数据库实现。用户请求进来后，首先用他的行为序列（点击/购买/收藏商品的标题拼接）生成用户向量，然后通过 Milvus 做 ANN 搜索。
> 
> 具体流程：用户最近 30 条行为记录 → 拼接成文本 → SentenceTransformer 编码 → 向量检索 Top-200 → SQL 过滤（类目/品牌/库存）→ 移除用户已交互物品 → 进入精排。
> 
> 向量库方面我们用的是 Milvus + HNSW 索引，维度 768（text2vec-base-chinese），用 COSINE 相似度。每个小时增量同步商品向量，每日全量重建一次。
> 
> 踩过的坑：早期Embedding 模型和训练模型不一致，导致离线离线 AUC 很高但在线效果差。后来统一了 EmbeddingService，版本号管理后解决了。还有一次 Milvus 内存 OOM，我们加了 Filtering 条件并切到 IVF-PQ 压缩解决了。

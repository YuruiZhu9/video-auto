# 推荐系统冷启动全链路解决方案

> ⏱ 推荐系统最痛的慢性病：新用户没数据、新物品没曝光，系统启动时一片空白。
> 本文档从症状诊断→策略体系→工程实现→评估验收，完整覆盖三类冷启动问题。

---

## 一、问题本质：为什么冷启动是系统性问题

### 1.1 三类冷启动全景图

```
┌──────────────────────────────────────────────────────────────┐
│                    推荐系统冷启动全景                          │
├──────────────┬──────────────────┬───────────────────────────┤
│  用户冷启动   │    物品冷启动     │     系统冷启动            │
│              │                  │                           │
│ 新用户注册    │ 新商品上架        │ 系统刚上线/大版本升级      │
│ 用户清空行为  │ 违规下架后重新上架 │ 数据全部迁移/重建索引      │
│ 账号换设备    │ 爆款补货后新ID    │ 模型全量重训练            │
│              │                  │                           │
│ ⏱ 影响周期   │   ⏱ 影响周期     │   ⏱ 影响周期              │
│ 数天～数周    │   数小时～数天    │   数分钟～数小时          │
│              │                  │                           │
│ 💔 危害程度   │   💔 危害程度     │   💔 危害程度              │
│ 极高（流失风险）│  中等（马太效应）  │   高（口碑风险）          │
└──────────────┴──────────────────┴───────────────────────────┘
```

### 1.2 马太效应：为什么强者越强、弱者越弱

```
推荐系统 → 吐出去的数据越多，推荐越准 → 推荐越准 → 吐更多数据
    ↑                                              │
    └──────── 恶性循环：新物品永远没机会 ──────────┘

新用户：没有任何行为 → 猜你喜欢不准 → 流失 → 更少行为
新物品：没有任何曝光 → 没有点击 → 没有特征 → 永无出头
```

**核心矛盾**：推荐系统天然偏向有数据的用户/物品，形成"富者愈富"的幂律分布。

### 1.3 冷启动的量化代价

| 场景 | 冷启动占比 | 点击率损失 | 流失风险 |
|------|-----------|-----------|---------|
| 电商新品上架（前7天） | 10-30% SKU | CTR -40%~60% | 商家体验差 |
| 内容平台新用户（首日） | 100% 新用户 | 推荐命中率 < 20% | 次日留存 -15% |
| 新闻推荐大事件后 | 5-15% 突发新闻 | 曝光机会归零 | 时效性浪费 |
| 推荐系统重训练后 | 30-50% 用户 | 短期体验下降 | 需3-7天恢复 |

## 二、用户冷启动：从0到能推荐

### 2.1 策略分层体系

```
用户冷启动解决方案分层
═══════════════════════════════════════════════
Level 1 【最快生效】热门/非个性化兜底
  → 新用户直接推热门/运营推荐，0计算，即时可用
Level 2 【次快生效】基于基础属性的人群匹配
  → 注册信息（年龄/性别/地域）→ 找同类人群的共同偏好
Level 3 【中等延迟】轻量级实时学习
  → 用户进来后快速记录行为，边用边学习
Level 4 【长期优化】Bandit探索策略
  → 主动探测用户兴趣，用概率模型平衡探索与利用
Level 5 【协同增强】跨域知识迁移
  → 借用其他产品/平台的用户行为数据
```

### 2.2 Level 1：热门兜底（立即可用）

**适用场景**：完全没有任何信息的用户，系统上线第一天的前5分钟。

```python
from dataclasses import dataclass
from typing import List
import json

@dataclass
class HotItem:
    item_id: str
    category: str
    popularity_score: float  # 综合点击+加购+成交的加权分数

class HotItemService:
    """热门兜底推荐：Top-N热销商品"""

    def __init__(self, redis_client):
        self.redis = redis_client
        self._hot_key = "rec:hot:items"
        self._default_items = self._load_default_items()

    def _load_default_items(self) -> List[HotItem]:
        """系统默认热门商品（配置文件，可人工调整）"""
        return [
            HotItem("item_001", "数码", 9500.0),
            HotItem("item_002", "服饰", 9200.0),
            HotItem("item_003", "食品", 8900.0),
            HotItem("item_004", "美妆", 8700.0),
            HotItem("item_005", "家居", 8500.0),
        ]

    def recommend_for_new_user(self, user_id: str, limit: int = 10) -> List[str]:
        """
        新用户热门兜底推荐
        策略：70% 推全局热门 + 30% 运营配置兜底
        """
        # 1. 查 Redis 实时热门
        hot_items = self.redis.zrevrange(
            self._hot_key, 0, limit * 2 - 1, withscores=True
        )

        if not hot_items:
            return [item.item_id for item in self._default_items[:limit]]

        result = [item_id.decode() if isinstance(item_id, bytes)
                  else item_id for item_id, _ in hot_items[:limit]]

        # 2. 多样性检查：若热门同质化严重，强制混入不同类目
        if self._is_too_concentrated(result):
            fallback = [item.item_id for item in self._default_items
                        if item.item_id not in result][:3]
            result = self._interleave(result, fallback, every_n=3)

        return result[:limit]

    @staticmethod
    def _interleave(primary: List, secondary: List, every_n: int) -> List:
        """交叉合并：[A,A,A] + [B,B] → [A,A,B,A,A,B,A]"""
        result = []
        sec_idx = 0
        for i, item in enumerate(primary):
            result.append(item)
            if (i + 1) % every_n == 0 and sec_idx < len(secondary):
                result.append(secondary[sec_idx])
                sec_idx += 1
        return result

    def _is_too_concentrated(self, item_ids: List[str]) -> bool:
        """检查推荐列表是否类目过度集中"""
        return False  # 简化：实际需查 ItemService 获取类目分布
```

### 2.3 Level 2：人口属性人群匹配

**核心思想**：相似用户有相似偏好。用注册信息找"同类人"的偏好。

```python
from dataclasses import dataclass
from typing import List, Dict, Optional

@dataclass
class UserProfile:
    user_id: str
    age_range: str       # "18-24" / "25-34" / "35-44" / "45+"
    gender: str           # "M" / "F" / "unknown"
    city_level: str       # "tier1" / "tier2" / "tier3"
    interest_tags: List[str]  # 用户自选兴趣标签

class DemographicMatcher:
    """
    基于人口统计学的推荐
    原理：相同年龄段/性别/城市的用户，偏好有统计相关性
    """

    def __init__(self, clickhouse_client, redis_client):
        self.ch = clickhouse_client
        self.redis = redis_client

    def _get_demographic_key(self, profile: UserProfile) -> str:
        """生成人群唯一标识"""
        return f"{profile.age_range}_{profile.gender}_{profile.city_level}"

    def get_demographic_recommendations(
        self, profile: UserProfile, limit: int = 20
    ) -> List[Dict]:
        """
        基于人群统计的推荐
        """
        cache_key = f"demo:pref:{self._get_demographic_key(profile)}"
        cached = self.redis.get(cache_key)
        if cached:
            data = json.loads(cached)
            return [{"item_id": k, "score": v} for k, v in data.items()][:limit]

        # 从 ClickHouse 查询（人群较大时走每日 ETL 预计算）
        sql = f"""
        SELECT item_id,
               count() as action_count,
               sum(if(action='click', 1, 0)) as clicks,
               sum(if(action='purchase', 3, 0)) as purchases
        FROM user_behavior
        WHERE age_range = '{profile.age_range}'
          AND gender = '{profile.gender}'
          AND city_level = '{profile.city_level}'
          AND event_date >= today() - 7
        GROUP BY item_id
        ORDER BY clicks + purchases DESC
        LIMIT {limit * 2}
        """
        try:
            results = self.ch.execute(sql)
        except Exception:
            return []

        # 过滤：去掉用户明确不感兴趣的类目
        if profile.interest_tags:
            results = self._filter_by_interest(results, profile.interest_tags)

        # 缓存 1 小时
        cache_data = {str(r[0]): float(r[1]) for r in results[:limit * 2]}
        self.redis.setex(cache_key, 3600, json.dumps(cache_data))

        return [{"item_id": str(r[0]), "score": float(r[1])} for r in results[:limit]]

    def _filter_by_interest(self, items: List, user_tags: List[str]) -> List:
        """过滤掉用户明确不感兴趣的类目（简化实现）"""
        return items
```

### 2.4 Level 3：实时行为快速学习（边用边学）

**核心思想**：用户进来后前 3-5 个行为最宝贵，快速记录并学习。

```python
from collections import defaultdict
from dataclasses import dataclass, field
from typing import List, Dict, Optional
import time, json

@dataclass
class UserRealtimeProfile:
    """用户实时画像（内存缓存 + Redis 持久化）"""
    user_id: str
    viewed_categories: Dict[str, int] = field(
        default_factory=lambda: defaultdict(int)
    )
    clicked_items: List[str] = field(default_factory=list)
    session_start: float = field(default_factory=lambda: time.time())
    interaction_count: int = 0

class RealtimeLearningEngine:
    """
    实时学习引擎：边用边学
    核心：第 3-5 次交互内快速收敛，避免用户等太久
    """

    def __init__(self, redis_client, feature_store):
        self.redis = redis_client
        self.features = feature_store
        # 内存缓存（热数据），避免 Redis 读压力
        self._memory_cache: Dict[str, UserRealtimeProfile] = {}
        self._min_interactions = 3

    def record_interaction(self, user_id: str, item_id: str, action: str):
        """记录用户实时行为（曝光/点击/加购）"""
        profile = self._get_or_create_profile(user_id)

        if action == "click":
            profile.clicked_items.append(item_id)
            item_category = self._get_item_categories(item_id)
            for cat in item_category:
                profile.viewed_categories[cat] += 1

        profile.interaction_count += 1
        self._sync_to_redis(user_id, profile)
        self._memory_cache[user_id] = profile

    def get_realtime_recommendations(
        self, user_id: str, candidate_items: List[str], limit: int = 10
    ) -> List[str]:
        """基于实时偏好，对候选集重排序"""
        profile = self._memory_cache.get(user_id)
        if not profile or profile.interaction_count < self._min_interactions:
            return []  # 交给上游兜底策略

        top_categories = sorted(
            profile.viewed_categories.items(),
            key=lambda x: x[1], reverse=True
        )[:3]
        top_cats = [cat for cat, _ in top_categories]

        scored = []
        for item_id in candidate_items:
            item_cats = self._get_item_categories(item_id)
            match_count = len(set(item_cats) & set(top_cats))
            if match_count > 0:
                # 越近期点击的类目权重越高（指数衰减）
                score = sum(0.8 ** i for i in range(match_count))
                scored.append((item_id, score))
            else:
                scored.append((item_id, 0.0))

        scored.sort(key=lambda x: x[1], reverse=True)
        seen = set(profile.clicked_items[-20:])
        result = [item_id for item_id, _ in scored if item_id not in seen]
        return result[:limit]

    def _get_or_create_profile(self, user_id: str) -> UserRealtimeProfile:
        if user_id in self._memory_cache:
            return self._memory_cache[user_id]
        cached = self._load_from_redis(user_id)
        if cached:
            self._memory_cache[user_id] = cached
            return cached
        return UserRealtimeProfile(user_id=user_id)

    def _get_item_categories(self, item_id: str) -> List[str]:
        return self.features.get_item_feature(item_id, "categories") or []

    def _sync_to_redis(self, user_id: str, profile: UserRealtimeProfile):
        key = f"rt_profile:{user_id}"
        data = {
            "viewed_cats": dict(profile.viewed_categories),
            "clicked_items": profile.clicked_items[-20:],
            "count": profile.interaction_count,
        }
        self.redis.setex(key, 86400, json.dumps(data, ensure_ascii=False))

    def _load_from_redis(self, user_id: str) -> Optional[UserRealtimeProfile]:
        key = f"rt_profile:{user_id}"
        raw = self.redis.get(key)
        if not raw:
            return None
        d = json.loads(raw)
        p = UserRealtimeProfile(user_id=user_id)
        p.viewed_categories = defaultdict(int, d["viewed_cats"])
        p.clicked_items = d["clicked_items"]
        p.interaction_count = d["count"]
        return p
```

## 三、物品冷启动：新物品如何获得初始曝光

### 3.1 流量分配策略体系

```
物品冷启动流量分配四策略
══════════════════════════════════════════════════════════════
策略A 【保守型】热门商品带动
  → 新品和热门品打包推荐，用户"顺便"看到新品
  → 曝光量：低 | 转化率：中 | 资源消耗：低

策略B 【均衡型】独立流量池分配
  → 预留 10-20% 流量专门推新品，不和其他物品竞争
  → 曝光量：中 | 转化率：中 | 资源消耗：中

策略C 【激进型】EE-Bandit 动态探测
  → 动态给新品分配流量，根据实时反馈调整
  → 曝光量：高 | 转化率：高（稳态后） | 资源消耗：中

策略D 【运营型】人工干预
  → 运营配置新品推广计划，强制曝光
  → 曝光量：高（可控） | 转化率：视商品质量 | 资源消耗：高
```

### 3.2 四种 Bandit 算法对比

| 算法 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| **Epsilon-Greedy** | ε概率随机，1-ε选最优 | 简单粗暴 | 盲目探索浪费流量 | 快速baseline |
| **UCB (Upper Confidence Bound)** | 置信上界 = 均值 + 不确定性 | 有理论保证收敛 | 需要足够的探索轮次 | 物品量中等 |
| **Thompson Sampling** | Beta分布抽样 | 收敛快，天然平衡EE | 计算略复杂 | 推荐系统首选 |
| **LinUCB (Contextual)** | 加入上下文的UCB | 个性化探索 | 实现复杂 | 有丰富特征的推荐 |

### 3.3 Thompson Sampling 完整实现

```python
import math
import random
import json
from dataclasses import dataclass
from typing import Dict, List, Tuple, Optional

@dataclass
class ArmStats:
    """每个"臂"（物品/类目）的统计数据"""
    alpha: float = 1.0   # Beta分布成功参数（点击次数+1）
    beta: float = 1.0    # Beta分布失败参数（曝光未点击+1）
    pulls: int = 0       # 总曝光次数

class ThompsonSamplingRecommender:
    """
    Thompson Sampling 推荐引擎
    核心：每个物品维护一个 Beta(α,β) 分布
    每次选择：从所有物品的分布抽样，选最高分
    → 自动平衡：点击率高的物品被"利用"，点击率低的物品继续"探索"
    """

    def __init__(self, redis_client):
        self.redis = redis_client
        self._arms: Dict[str, ArmStats] = {}
        self._epsilon = 0.05  # 5% 概率强制随机（保证多样性）

    def _get_arm_key(self, item_id: str, context: str = "global") -> str:
        return f"ts:arm:{context}:{item_id}"

    def select_arm(self, candidate_items: List[str], user_id: str) -> str:
        """
        Thompson Sampling 选臂
        推荐系统最佳实践：以类目为单位做 Bandit（物品量太大，收敛更快）
        """
        if not candidate_items:
            return ""

        # 5% 概率强制随机探索
        if random.random() < self._epsilon:
            return random.choice(candidate_items)

        best_item = None
        best_score = -1.0
        for item_id in candidate_items:
            arm = self._get_arm(item_id)
            try:
                import numpy as np
                theta = np.random.beta(arm.alpha, arm.beta)
            except Exception:
                theta = arm.alpha / max(1, arm.alpha + arm.beta)
            if theta > best_score:
                best_score = theta
                best_item = item_id

        return best_item or candidate_items[0]

    def update(self, item_id: str, clicked: bool):
        """
        更新臂的统计（每条反馈都更新）
        clicked=True  → α+1（成功）
        clicked=False → β+1（失败）
        """
        arm = self._get_arm(item_id)
        arm.pulls += 1
        if clicked:
            arm.alpha += 1
        else:
            arm.beta += 1
        self._sync_arm(item_id, arm)

    def _get_arm(self, item_id: str) -> ArmStats:
        if item_id not in self._arms:
            stats = self._load_arm(item_id)
            self._arms[item_id] = stats
        return self._arms[item_id]

    def _sync_arm(self, item_id: str, arm: ArmStats):
        """持久化到 Redis"""
        key = self._get_arm_key(item_id)
        self.redis.hset(key, mapping={
            "alpha": str(arm.alpha),
            "beta": str(arm.beta),
            "pulls": str(arm.pulls),
        })
        ctr = arm.alpha / max(1, arm.alpha + arm.beta)
        ttl = 604800 if ctr > 0.1 else 86400
        self.redis.expire(key, ttl)

    def _load_arm(self, item_id: str) -> ArmStats:
        key = self._get_arm_key(item_id)
        data = self.redis.hgetall(key)
        if not data:
            return ArmStats()
        return ArmStats(
            alpha=float(data.get(b"alpha", 1.0)),
            beta=float(data.get(b"beta", 1.0)),
            pulls=int(data.get(b"pulls", 0)),
        )

    def get_expected_ctr(self, item_id: str) -> float:
        """获取期望 CTR（用于调试和监控）"""
        arm = self._get_arm(item_id)
        if arm.pulls == 0:
            return 0.5  # 无数据时假设 50%（高探索）
        return arm.alpha / (arm.alpha + arm.beta)

    def get_confidence_interval(
        self, item_id: str
    ) -> Tuple[float, float]:
        """获取 CTR 置信区间（用于监控展示）"""
        arm = self._get_arm(item_id)
        if arm.pulls < 10:
            return (0.0, 1.0)
        n = arm.alpha + arm.beta
        p = arm.alpha / n
        z = 1.96
        denom = 1 + z**2 / n
        center = p + z**2 / (2 * n)
        spread = z * math.sqrt(p * (1 - p) / n + z**2 / (4 * n**2))
        lo = max(0.0, (center - spread) / denom)
        hi = min(1.0, (center + spread) / denom)
        return (lo, hi)
```

### 3.4 UCB 新品流量探测

```python
import math
from typing import Dict, Optional

class ItemColdStartUCB:
    """
    UCB 新品冷启动探测器
    每个新品上架后，自动分配"探测流量"逐步增加曝光
    表现好 → 快速进入主推荐池
    表现差 → 降低曝光，减少资源浪费
    """

    def __init__(self, redis_client, clickhouse_client):
        self.redis = redis_client
        self.ch = clickhouse_client
        self._ucb_c = 1.5        # UCB 探索系数（越大越激进探索新品）
        self._hourly_budget = 1000  # 每小时新品最大曝光预算

    def get_item_exposure_budget(self, item_id: str) -> Dict:
        """计算新品当前应获得的曝光预算"""
        stats = self._get_item_stats(item_id)
        if not stats or stats["pulls"] == 0:
            return {
                "budget": 20,
                "urgency": "high",
                "reason": "initial_burst",
                "ucb_score": 0.5
            }

        pulls = stats["pulls"]
        ctr = stats["ctr"]

        # UCB 分数 = 真实CTR + 探索奖励
        avg_ctr = self._get_global_avg_ctr()
        total_pulls = self._get_total_pulls()
        exploration_bonus = self._ucb_c * math.sqrt(
            math.log(total_pulls + 1) / pulls
        )
        ucb_score = ctr + exploration_bonus

        # 决策逻辑
        if ucb_score > avg_ctr * 1.2:
            budget = min(
                int(self._hourly_budget * ucb_score / avg_ctr),
                self._hourly_budget
            )
            urgency = "high" if ctr > avg_ctr * 1.5 else "medium"
            reason = "ucb_positive"
        elif ctr > avg_ctr * 0.5 and stats["age_hours"] < 24:
            budget = int(self._hourly_budget * 0.5)
            urgency = "medium"
            reason = "early_stage_neutral"
        else:
            budget = int(self._hourly_budget * 0.1)
            urgency = "low"
            reason = "below_avg_ctr"

        return {
            "budget": budget,
            "urgency": urgency,
            "reason": reason,
            "ucb_score": round(ucb_score, 4),
            "exploration_bonus": round(exploration_bonus, 4),
        }

    def _get_item_stats(self, item_id: str) -> Optional[Dict]:
        key = f"coldstart:item:{item_id}"
        data = self.redis.hgetall(key)
        if not data:
            return None
        pulls = int(data.get(b"pulls", 0))
        clicks = int(data.get(b"clicks", 0))
        return {
            "pulls": pulls,
            "clicks": clicks,
            "ctr": clicks / max(1, pulls),
            "age_hours": int(data.get(b"age_hours", 0)),
        }

    def _get_global_avg_ctr(self) -> float:
        val = self.redis.get("coldstart:global_avg_ctr")
        return float(val) if val else 0.05

    def _get_total_pulls(self) -> int:
        val = self.redis.get("coldstart:total_pulls")
        return int(val) if val else 1

    def record_exposure(self, item_id: str, clicked: bool):
        """记录一次曝光反馈"""
        key = f"coldstart:item:{item_id}"
        pipe = self.redis.pipeline()
        pipe.hincrby(key, "pulls", 1)
        if clicked:
            pipe.hincrby(key, "clicks", 1)
        pipe.incr("coldstart:total_pulls")
        pipe.expire(key, 86400 * 8)
        pipe.execute()
```

### 3.5 冷热融合推荐器

```python
from dataclasses import dataclass, field
from typing import List, Dict, Optional

@dataclass
class CandidateItem:
    item_id: str
    category: str
    base_score: float
    pulls: int = 0
    age_hours: int = 0
    feature_coverage: float = 0.0

class ColdStartBlender:
    """
    冷热融合推荐器
    核心：热品用协同过滤，冷品用内容特征+UCB探测，动态加权融合
    融合公式：综合分 = 个性化分数 × (1 + 冷度权重 × 冷度 × UCB分数)
    """

    def __init__(
        self,
        hot_recall,
        content_recall,
        ucb_probe: ItemColdStartUCB,
        ts_recommender: ThompsonSamplingRecommender,
        item_feature_store,
    ):
        self.hot_recall = hot_recall
        self.content_recall = content_recall
        self.ucb = ucb_probe
        self.ts = ts_recommender
        self.features = item_feature_store

    def recommend(
        self, user_id: str, top_k: int = 10,
    ) -> List[Dict]:
        """冷热融合推荐主流程"""
        # Step 1: 候选集召回（热品 + 潜在冷品）
        hot_items = self.hot_recall.recall(user_id, n=40)
        cold_items = self._get_cold_candidates(top_k=20)
        all_candidates: List[CandidateItem] = hot_items + cold_items

        # Step 2: 计算综合分
        scored_candidates = []
        for item in all_candidates:
            coldness = self._calc_coldness(item)
            ucb_info = self.ucb.get_item_exposure_budget(item.item_id)
            ucb_score = ucb_info.get("budget", 0) / max(
                1, self.ucb._hourly_budget
            )
            # 冷品加成：冷度越高，UCB 曝光预算的加权越大
            coldness_weight = 0.3  # 冷品加分上限 30%
            adjusted_score = item.base_score * (
                1 + coldness_weight * coldness * ucb_score
            )
            scored_candidates.append({
                "item_id": item.item_id,
                "category": item.category,
                "score": adjusted_score,
                "coldness": coldness,
                "is_cold": coldness > 0.5,
                "ucb_budget": ucb_info.get("budget", 0),
                "reason": ucb_info.get("reason", "hot"),
            })

        # Step 3: 排序
        scored_candidates.sort(key=lambda x: x["score"], reverse=True)

        # Step 4: 多样性约束（冷品最多占 30%）
        result = self._diversity_constraint(
            scored_candidates, top_k=top_k, cold_ratio=0.3
        )

        # Step 5: 记录曝光（给 UCB 学习用）
        for item in result:
            self.ucb.record_exposure(item["item_id"], clicked=False)

        return result

    def _calc_coldness(self, item: CandidateItem) -> float:
        """
        计算物品冷度（0=热门，1=全新）
        三维度加权：曝光量(40%) / 上线时间(30%) / 特征覆盖率(30%)
        """
        exposure_score = min(1.0, item.pulls / 1000)   # 1000 曝光算"热"
        age_score = min(1.0, item.age_hours / 168)     # 7 天算"老"
        feature_score = item.feature_coverage          # 0-1

        coldness = 1.0 - (
            0.4 * (1 - exposure_score) +
            0.3 * (1 - age_score) +
            0.3 * (1 - feature_score)
        )
        return coldness

    def _get_cold_candidates(self, top_k: int) -> List[CandidateItem]:
        """获取冷启动候选物品（按 UCB 分数排序）"""
        candidates = self._load_new_items_pool()
        scored = []
        for item in candidates:
            info = self.ucb.get_item_exposure_budget(item.item_id)
            scored.append(CandidateItem(
                item_id=item.item_id,
                category=item.category,
                base_score=info.get("budget", 0) / 100.0,
                pulls=item.pulls,
                age_hours=item.age_hours,
                feature_coverage=item.feature_coverage,
            ))
        scored.sort(key=lambda x: x.base_score, reverse=True)
        return scored[:top_k]

    def _diversity_constraint(
        self, candidates: List[Dict], top_k: int, cold_ratio: float = 0.3
    ) -> List[Dict]:
        """多样性约束：结果中冷品不超过 cold_ratio"""
        max_cold = int(top_k * cold_ratio)
        result = []
        cold_count = 0
        for item in candidates:
            if len(result) >= top_k:
                break
            if item["is_cold"]:
                if cold_count >= max_cold:
                    continue
                cold_count += 1
            result.append(item)
        return result

    def _load_new_items_pool(self) -> List[CandidateItem]:
        """从 Redis/MySQL 获取新品池（上架 <7 天）"""
        return []
```

## 四、系统冷启动：系统刚上线怎么做

### 4.1 三阶段系统冷启动方案

```
系统冷启动三阶段
═══════════════════════════════════════════════════════════════
阶段1：数据准备期（上架前 1-2 周）
  目标：建立内容库 + 种子用户 + 历史数据导入
  策略：
  ├─ 商品/内容：录入基本信息 + 运营补充类目标签
  ├─ 种子用户：用运营账号模拟行为，或导入历史数据
  └─ 评分矩阵：用内容相似性（类目/标签）生成伪行为数据

阶段2：灰度验证期（第 1-3 天）
  目标：小流量验证推荐效果，不出重大事故
  策略：
  ├─ 推荐比例：10% 用户 → 推荐系统，90% 用户 → 热门兜底
  ├─ 快速反馈：每小时看核心指标（曝光/点击/互动率）
  └─ 熔断阈值：错误率 > 5% → 自动回退热门兜底

阶段3：全量上线期（第 4-14 天）
  目标：逐步扩大流量至 100%，持续监控调整
  策略：
  ├─ 扩量节奏：10% → 30% → 50% → 80% → 100%（每日检查）
  ├─ 兜底策略：每个阶段保留兜底选项，随时可回退
  └─ 数据积累：每天分析新用户留存，调整冷启动策略
```

### 4.2 Bootstrap 推荐引擎（伪行为数据生成）

**适用场景**：系统刚上线，历史行为数据为零，必须"无中生有"。

```python
import math
from collections import defaultdict
from dataclasses import dataclass
from typing import Dict, List, Optional

@dataclass
class UserProfile:
    user_id: str
    age_range: str
    gender: str
    city_level: str
    interest_tags: List[str]

class BootstrapRecommender:
    """
    Bootstrap 推荐器：在完全没有行为数据时生成伪评分矩阵
    核心方法：基于内容相似性计算用户-物品伪偏好
    """

    def __init__(self, item_feature_store, user_profile_service):
        self.items = item_feature_store
        self.users = user_profile_service
        self._pseudo_ratings: Dict[str, Dict[str, float]] = {}

    def build_pseudo_ratings(self, target_user_id: str) -> Dict[str, float]:
        """
        为指定用户构建伪评分矩阵
        原理：用户画像（年龄/性别/兴趣标签）
              → 匹配物品内容特征（类目/标签/品牌）
              → 生成伪评分（0-1之间）
        """
        if target_user_id in self._pseudo_ratings:
            return self._pseudo_ratings[target_user_id]

        user_profile = self.users.get_profile(target_user_id)
        if not user_profile:
            return {}

        user_tags = self._extract_user_tags(user_profile)
        all_items = self.items.list_items()

        ratings = {}
        for item in all_items:
            item_tags = self.items.get_item_tags(item.item_id)
            similarity = self._cosine_similarity(user_tags, item_tags)
            if similarity > 0.1:
                ratings[item.item_id] = similarity

        self._pseudo_ratings[target_user_id] = ratings
        return ratings

    def _extract_user_tags(self, profile: UserProfile) -> Dict[str, float]:
        """从用户画像提取标签权重"""
        tags = {}
        if profile.interest_tags:
            for tag in profile.interest_tags:
                tags[tag] = 1.0
        gender_default = {
            "M": ["数码", "运动", "游戏", "户外"],
            "F": ["美妆", "服饰", "家居", "母婴"]
        }
        if profile.gender in gender_default:
            for cat in gender_default[profile.gender]:
                tags[cat] = tags.get(cat, 0.0) + 0.5
        return tags

    def _cosine_similarity(
        self, vec_a: Dict[str, float], vec_b: Dict[str, float]
    ) -> float:
        """余弦相似度"""
        if not vec_a or not vec_b:
            return 0.0
        common = set(vec_a.keys()) & set(vec_b.keys())
        if not common:
            return 0.0
        dot = sum(vec_a[k] * vec_b[k] for k in common)
        norm_a = math.sqrt(sum(v**2 for v in vec_a.values()))
        norm_b = math.sqrt(sum(v**2 for v in vec_b.values()))
        if norm_a == 0 or norm_b == 0:
            return 0.0
        return dot / (norm_a * norm_b)
```

### 5.1 跨域推荐的适用条件

### 5.2 跨域推荐工程实现

```python
class CrossDomainRecommender:
    """
    跨域推荐：借用源域（短视频）数据为目标域（电商）服务
    核心思想：短视频的点赞/收藏 → 电商的购买偏好
    """

    def __init__(self, short_video_recall, ecommerce_recall):
        self.short_video = short_video_recall
        self.ecommerce = ecommerce_recall
        # 短视频类目 → 电商类目映射表
        self._category_mapping = {
            "美妆教程": ["美妆", "护肤"],
            "美食探店": ["食品", "餐饮具"],
            "健身运动": ["运动", "服饰"],
            "数码测评": ["数码", "配件"],
            "家居装修": ["家居", "家装"],
        }

    def recommend_by_cross_domain(
        self, user_id: str, short_video_behavior: List[dict], top_k: int = 10
    ) -> List[dict]:
        """
        基于短视频行为，推荐电商商品
        """
        # Step 1: 从短视频行为提取用户兴趣类目
        video_categories = [b.get("category") for b in short_video_behavior]
        category_counter: Dict[str, int] = defaultdict(int)
        for cat in video_categories:
            if cat:
                category_counter[cat] += 1

        # Step 2: 映射到电商类目
        ecomm_cats: Dict[str, float] = defaultdict(float)
        for video_cat, weight in category_counter.items():
            ecomm_mapped = self._category_mapping.get(video_cat, [])
            for ecat in ecomm_mapped:
                ecomm_cats[ecat] += weight

        if not ecomm_cats:
            return []

        # Step 3: 在电商域召回对应类目的商品
        top_ecom_cats = sorted(ecomm_cats.items(), key=lambda x: x[1], reverse=True)
        results = []
        for ecat, score in top_ecom_cats[:3]:
            items = self.ecommerce.recall_by_category(ecat, n=5)
            for item in items:
                item["cross_domain_score"] = score
                item["source_category"] = ecat
                results.append(item)

        results.sort(key=lambda x: x["cross_domain_score"], reverse=True)
        return results[:top_k]

## 六、评估指标：冷启动效果如何量化

### 6.1 用户冷启动核心指标

| 指标 | 定义 | 目标值 | 说明 |
|------|------|--------|------|
| **新用户留存率 D+1** | 注册次日回访比例 | > 40% | 冷启动质量的金指标 |
| **冷启动 CTR** | 新用户推荐点击率 | > 5% | Level 1-3 策略有效性的快速反馈 |
| **冷启动覆盖商品数** | 首次推荐的不同商品数 | > 10 | 保证多样性，不是一个商品打天下 |
| **实时学习收敛时间** | 3-5次交互后偏好准确率 | < 10 min | Level 3 实时学习的效果验证 |
| **Bandit 探索覆盖率** | 被探测过的物品比例 | > 30% | 新品获得曝光的比例 |

### 6.2 物品冷启动核心指标

| 指标 | 定义 | 目标值 | 说明 |
|------|------|--------|------|
| **新品曝光率** | 7天内新品被推荐的次数/总推荐次数 | > 15% | 马太效应的反义词 |
| **新品 CTR** | 新品的点击率 vs 老品 CTR | > 60% | 新品探测有效，不明显拖累整体体验 |
| **UCB 决策准确率** | UCB 判断"好新品"vs 实际表现 | > 70% | UCB 策略质量的验证 |
| **冷热融合多样性** | 推荐结果中新品的比例 | 10-30% | 过多新品伤害体验，过少新品伤害商家 |
| **新品成交转化率** | 新品被推荐后的购买转化 | > 3% | 商家最关心的指标 |

class ColdStartMonitor:
    """
    冷启动效果监控（供 Prometheus + Grafana 使用）
    """

    def __init__(self, redis_client, clickhouse_client):
        self.redis = redis_client
        self.ch = clickhouse_client

    def get_user_cold_start_metrics(self, day: str = None) -> dict:
        """用户冷启动核心指标"""
        if not day:
            import datetime
            day = datetime.date.today().isoformat()

        sql = f"""
        SELECT
            count(DISTINCT user_id) FILTER (WHERE age <= 7) as new_users,
            count(DISTINCT user_id) FILTER (WHERE age <= 7
                AND has_click = 1) as active_users,
            count(DISTINCT user_id) FILTER (WHERE age <= 7
                AND return_next_day = 1) as retained_users,
            avg(recall_score) FILTER (WHERE age <= 7) as avg_ctr
        FROM user_daily_stats
        WHERE date = '{day}'
        """
        try:
            results = self.ch.execute(sql)
            row = results[0] if results else {}
        except Exception:
            row = {}

        new_users = int(row[0]) if row else 0
        active = int(row[1]) if row else 0
        retained = int(row[2]) if row else 0
        avg_ctr = float(row[3]) if row and row[3] else 0.0

        return {
            "new_users_total": new_users,
            "new_users_active": active,
            "new_users_d1_retention": retained / max(1, new_users),
            "cold_start_ctr": avg_ctr,
            "pass_rate": "✅" if avg_ctr > 0.05 else "⚠️",
        }

    def get_item_cold_start_metrics(self) -> dict:
        """物品冷启动核心指标"""
        total_pulls = int(self.redis.get("coldstart:total_pulls") or 0)
        new_items = self._count_new_items()
        probed_items = self._count_probed_items()

        return {
            "new_items_total": new_items,
            "new_items_probed": probed_items,
            "probe_rate": probed_items / max(1, new_items),
            "total_item_exposures": total_pulls,
        }

    def _count_new_items(self) -> int:
        """统计新品数量（上架 <7 天）"""
        return int(self.redis.get("coldstart:new_items_count") or 0)

    def _count_probed_items(self) -> int:
        """统计被探测过的新品数量"""
        keys = self.redis.keys("coldstart:item:*")
        probed = 0
        for key in keys:
            data = self.redis.hgetall(key)
            if int(data.get(b"pulls", 0)) > 5:
                probed += 1
        return probed

## 七、常见误区与避坑指南

### 7.1 用户冷启动六大误区

| 误区 | 问题 | 正确做法 |
|------|------|---------|
| ❌ 只用热门兜底 | 用户感觉"被敷衍"，次留差 | 3-5次交互后立即切换到实时学习 |
| ❌ 强制让用户填兴趣 | 用户流失率大幅上升 | 用 Bandit 自然学习，不强制 |
| ❌ 新老用户策略完全分开 | 工程维护成本高 | 策略合一，冷启动是"初始状态" |
| ❌ Bandit 探索过于激进 | CTR 短期暴跌，老板叫停 | 从 ε=0.1 开始，逐步降到 0.02 |
| ❌ 忽视实时性的重要性 | 用户意图已变，历史行为过时 | 实时行为 > 7天历史行为 |
| ❌ 跨域数据直接复制 | 隐私合规风险 + 偏好错配 | 必须经过用户同意 + 类目映射 |

### 7.2 物品冷启动六大误区

| 误区 | 问题 | 正确做法 |
|------|------|---------|
| ❌ 新品必须保证曝光 | 劣质新品伤害用户体验 | UCB 探测，不好就降权 |
| ❌ 冷启动是阶段性问题 | 永远有新品，永无止境 | 建立持续的新品探测机制 |
| ❌ 只看 CTR 评估新品 | 高 CTR 可能因为标题党 | 综合 CTR + 转化率 + 退货率 |
| ❌ 把所有流量都给新品 | 老品体验崩塌 | 预留 10-20% 新品配额上限 |
| ❌ 人工运营主导新品曝光 | 资源消耗大，不可规模化 | Bandit 自动化为主，人工为辅 |
| ❌ 新品特征缺失不处理 | 类目标签缺失 = 无法推荐 | 强制上架前完善类目标签 |

### 7.3 系统冷启动三大坑

| 坑 | 表现 | 应对方案 |
|----|------|---------|
| **坑1：一次性全量上线** | 出问题无法回退，全量用户受影响 | 灰度 10% → 30% → 50% → 100%，每步保留回退能力 |
| **坑2：只监控算法指标** | 曝光量正常，但用户实际体验差 | 同时监控次日留存（D+1 retention）|
| **坑3：冷启动策略固化** | 运营了一段时间后忘了调整参数 | 每周 Review 冷启动指标，定期调参 |

□ 伪行为数据已生成（Bootstrap 评分矩阵）
□ 监控仪表盘已就绪（用户/物品/系统三维）

【监控告警】

  - 新用户 D+1 留存 < 35%

# 插件架构与策略模式实战

> 推荐系统工程师视角：从"硬编码 if-else"到"可扩展插拔"的设计升级

---

## 概念解释

### 什么是插件架构？

**插件架构（Plugin Architecture）** 是一种将系统核心逻辑与可变功能分离的设计方式：核心框架只定义"插槽"，具体功能以插件形式自由插拔，无需改动主代码。

类比现实：
- **电脑的 USB 接口** → 系统定义了统一接口，任何 USB 设备都能接入
- **微信小程序** → 微信定义能力接口，开发者提供具体实现
- **推荐系统中的特征算子** → 框架定义算子协议，新特征类型无需修改主线代码

### 什么是策略模式？

**策略模式（Strategy Pattern）** 是插件架构最常见的实现形式：定义一系列算法（策略），将它们一个个封装起来，使它们可以相互替换。

核心区别：
| 模式 | 关注点 | 运行时行为 |
|------|--------|-----------|
| 策略模式 | 算法家族的互换 | 可以随时切换策略 |
| 插件架构 | 功能的可扩展性 | 运行时动态加载 |
| 管道模式 | 数据流的顺序处理 | 数据沿链路流动 |

三者常常组合使用——**策略模式是内容，插件架构是形式，管道模式是组织方式**。

```python
# ❌ 反例：推荐算法选择器（硬编码）
class Recommender:
    def recommend(self, user_id: int, algorithm: str, context: dict):
        if algorithm == "cf":  # 协同过滤
            # ... 加载相似度矩阵
            # ... 计算用户相似度
            # ... 生成推荐列表
            results = []
            for item in candidates:
                score = self._cf_score(user_id, item)
                results.append((item, score))
            return sorted(results, key=lambda x: x[1], reverse=True)[:20]

        elif algorithm == "content":  # 内容推荐
            # ... 加载物品特征向量
            # ... 计算内容相似度
            results = []
            for item in candidates:
                score = self._content_score(user_id, item)
                results.append((item, score))
            return sorted(results, key=lambda x: x[1], reverse=True)[:20]

        elif algorithm == "hybrid":  # 混合推荐
            # ... 加载多个模型结果
            # ... 加权融合
            results = []
            for item in candidates:
                score = 0.5 * self._cf_score(user_id, item) + 0.5 * self._content_score(user_id, item)
                results.append((item, score))
            return sorted(results, key=lambda x: x[1], reverse=True)[:20]

        elif algorithm == "deep_model":  # 深度学习模型
            # ... 调用 TensorFlow 模型
            results = []
            for item in candidates:
                score = self._deep_score(user_id, item)
                results.append((item, score))
            return sorted(results, key=lambda x: x[1], reverse=True)[:20]

        else:
            raise ValueError(f"Unknown algorithm: {algorithm}")

    def _cf_score(self, user_id, item): ...
    def _content_score(self, user_id, item): ...
    def _deep_score(self, user_id, item): ...
```

**坏味道分析：**
- ❌ 每新增一种算法，要修改 `recommend` 方法（违反开闭原则）
- ❌ `elif` 链越来越长，难以阅读
- ❌ 无法单独测试某一种算法逻辑
- ❌ 无法在运行时动态注册新算法
- ❌ 混合推荐逻辑和具体算法强耦合

### 正例一：策略模式重构

```python
# ✅ 正例：策略模式实现推荐算法选择
from abc import ABC, abstractmethod
from typing import List, Tuple

# ========== 1. 定义策略接口 ==========
class RecommendationStrategy(ABC):
    """推荐策略抽象接口"""

    name: str  # 策略名称，供监控/日志使用

    @abstractmethod
    def score(self, user_id: int, candidates: List[int], context: dict) -> List[Tuple[int, float]]:
        """
        对候选物品打分
        返回: [(item_id, score), ...]，按 score 降序排列
        """
        pass

    def preprocess(self, user_id: int, context: dict) -> dict:
        """
        预处理钩子（可选被子类覆盖）
        例如：预加载用户特征、缓存中间结果
        """
        return context


# ========== 2. 实现具体策略 ==========
class CollaborativeFiltering(RecommendationStrategy):
    name = "协同过滤"

    def preprocess(self, user_id: int, context: dict) -> dict:
        # 预加载相似用户数据，避免重复查询
        context["similar_users"] = self._load_similar_users(user_id)
        return context

    def score(self, user_id: int, candidates: List[int], context: dict) -> List[Tuple[int, float]]:
        similar_users = context.get("similar_users", [])
        results = []
        for item in candidates:
            score = self._compute_cf_score(user_id, item, similar_users)
            results.append((item, score))
        return sorted(results, key=lambda x: x[1], reverse=True)

    def _compute_cf_score(self, user_id, item, similar_users): ...

class ContentBased(RecommendationStrategy):
    name = "内容推荐"

    def score(self, user_id: int, candidates: List[int], context: dict) -> List[Tuple[int, float]]:
        user_profile = context.get("user_profile", {})
        results = []
        for item in candidates:
            score = self._cosine_similarity(user_profile, self._get_item_features(item))
            results.append((item, score))
        return sorted(results, key=lambda x: x[1], reverse=True)

    def _cosine_similarity(self, vec1, vec2): ...
    def _get_item_features(self, item_id): ...

class DeepModelStrategy(RecommendationStrategy):
    name = "深度学习模型"

    def __init__(self, model_path: str, batch_size: int = 256):
        self.model_path = model_path
        self.batch_size = batch_size
        self._model = None  # lazy load

    @property
    def model(self):
        if self._model is None:
            import tensorflow as tf
            self._model = tf.saved_model.load(self.model_path)
        return self._model

    def score(self, user_id: int, candidates: List[int], context: dict) -> List[Tuple[int, float]]:
        # 批量推理，提升性能
        batch_features = self._build_batch_features(user_id, candidates, context)
        scores = self.model.predict(batch_features)
        return sorted(zip(candidates, scores), key=lambda x: x[1], reverse=True)

    def _build_batch_features(self, user_id, candidates, context): ...


# ========== 3. 策略选择器（核心调度器）==========
class StrategyRegistry:
    """策略注册中心——插件架构的核心"""

    def __init__(self):
        self._strategies: dict[str, RecommendationStrategy] = {}

    def register(self, strategy: RecommendationStrategy) -> None:
        """注册一个策略插件"""
        if strategy.name in self._strategies:
            raise ValueError(f"策略 '{strategy.name}' 已存在，请先注销")
        self._strategies[strategy.name] = strategy
        print(f"✅ 插件注册成功: {strategy.name} (共 {len(self._strategies)} 个策略)")

    def unregister(self, name: str) -> None:
        """注销策略"""
        if name in self._strategies:
            del self._strategies[name]

    def get(self, name: str) -> RecommendationStrategy:
        """获取策略（支持别名）"""
        if name not in self._strategies:
            # 支持别名，例如 "cf" -> "协同过滤"
            aliases = {"cf": self.name_for("协同过滤"), "dl": self.name_for("深度学习模型")}
            if name in aliases and aliases[name]:
                return self._strategies[aliases[name]]
            raise KeyError(f"未找到策略: '{name}'，可用策略: {list(self._strategies.keys())}")
        return self._strategies[name]

    def name_for(self, keyword: str) -> str | None:
        for name in self._strategies:
            if keyword.lower() in name.lower():
                return name
        return None

    def list_strategies(self) -> List[str]:
        return list(self._strategies.keys())


class HybridRecommender:
    """
    混合推荐器——使用策略模式组合多个推荐算法
    核心：算法可插拔，组合方式可配置
    """

    def __init__(self, registry: StrategyRegistry):
        self.registry = registry
        self._weights: dict[str, float] = {}  # 各策略权重
        self._fallback: RecommendationStrategy | None = None

    def set_weights(self, weights: dict[str, float]) -> None:
        """设置混合权重，例如 {"协同过滤": 0.6, "内容推荐": 0.4}"""
        self._weights = weights

    def set_fallback(self, strategy: RecommendationStrategy) -> None:
        """设置兜底策略（当所有策略都失败时）"""
        self._fallback = strategy

    def recommend(
        self, user_id: int, candidates: List[int], context: dict, top_k: int = 20
    ) -> List[Tuple[int, float]]:
        if not self._weights:
            raise ValueError("请先调用 set_weights() 设置策略权重")

        # Step 1: 对每种策略分别打分（可并行化）
        all_scores: dict[str, List[Tuple[int, float]]] = {}
        for strategy_name, weight in self._weights.items():
            try:
                strategy = self.registry.get(strategy_name)
                context = strategy.preprocess(user_id, context)
                all_scores[strategy_name] = strategy.score(user_id, candidates, context)
            except Exception as e:
                print(f"⚠️  策略 {strategy_name} 执行失败: {e}，跳过")
                continue

        if not all_scores:
            if self._fallback:
                return self._fallback.score(user_id, candidates, context)[:top_k]
            raise RuntimeError("所有策略均执行失败")

        # Step 2: 归一化 + 加权融合
        fused_scores: dict[int, float] = {item: 0.0 for item in candidates}
        for strategy_name, weight in self._weights.items():
            if strategy_name not in all_scores:
                continue
            min_s, max_s = float("inf"), float("-inf")
            for _, s in all_scores[strategy_name]:
                min_s, max_s = min(min_s, s), max(max_s, s)
            score_range = max_s - min_s if max_s != min_s else 1.0
            for item_id, score in all_scores[strategy_name]:
                normalized = (score - min_s) / score_range
                fused_scores[item_id] += weight * normalized

        # Step 3: 排序返回
        ranked = sorted(fused_scores.items(), key=lambda x: x[1], reverse=True)
        return ranked[:top_k]
```

**改进亮点：**
- ✅ 新增算法只需实现 `RecommendationStrategy` 接口，零改动主代码
- ✅ 每个策略可独立测试、独立热更新
- ✅ 支持运行时动态注册/注销插件
- ✅ 混合权重可配置，无需改代码
- ✅ 异常隔离：单个策略失败不影响整体

### 反例二：特征工程管道的硬编码

```python
# ❌ 反例：推荐系统特征处理管道（硬编码）
class FeaturePipeline:
    def process(self, user_id: int, item_id: int) -> dict:
        features = {}

        # 1. 用户统计特征
        user = self.db.get_user(user_id)
        features["user_age"] = user.age
        features["user_gender"] = user.gender
        features["user_click_count_7d"] = self.db.count_clicks(user_id, days=7)
        features["user_favorite_count"] = self.db.count_favorites(user_id)

        # 2. 物品统计特征
        item = self.db.get_item(item_id)
        features["item_popularity"] = item.view_count
        features["item_avg_rating"] = item.avg_rating

        # 3. 交叉特征
        features["user_item_ctr"] = features["user_click_count_7d"] / (features["item_popularity"] + 1)

        # 4. 文本特征（LLM embedding）
        features["text_embedding"] = self.embedding_model.encode(item.description)

        # 5. 图特征
        features["graph_embedding"] = self.graph_model.get_embedding(item_id)

        return features
```

**问题：** 每加一种特征类型，就要改 `process` 方法；无法单独跳过某类特征；无法在推理时动态选择特征组合。

### 正例二：管道-插件模式的特征工程框架

```python
# ✅ 正例：基于插件架构的特征工程管道
from typing import List, Dict, Any, Callable
from dataclasses import dataclass, field
import asyncio

# ========== 1. 特征算子抽象 ==========
@dataclass
class FeatureContext:
    """特征上下文，在管道中传递"""
    user_id: int
    item_id: int
    db: Any  # 数据库访问
    cache: dict = field(default_factory=dict)  # 进程内缓存
    features: Dict[str, Any] = field(default_factory=dict)  # 已计算的特征
    metadata: Dict[str, Any] = field(default_factory=dict)  # 元信息


class FeatureOperator(ABC):
    """
    特征算子——特征插件的最小单元
    符合 Open/Closed 原则：新增特征类型无需修改管道代码
    """

    name: str  # 特征名称，同时也是输出 dict 的 key

    # 元信息：用于自动化
    category: str = "default"  # 分类：user/item/cross/text/graph
    compute_cost: str = "low"  # low / medium / high（影响并行策略）
    cacheable: bool = True     # 计算结果是否可缓存

    @abstractmethod
    def compute(self, ctx: FeatureContext) -> Any:
        """计算特征值"""
        pass

    def dependencies(self) -> List[str]:
        """
        声明依赖的特征（用于拓扑排序 + 依赖检查）
        例如：cross_ctr 依赖 [user_click_count_7d, item_popularity]
        """
        return []


# ========== 2. 实现各类特征算子（插件）==========
class UserStatsOperator(FeatureOperator):
    """用户统计特征算子"""
    name = "user_stats"
    category = "user"
    compute_cost = "low"

    def compute(self, ctx: FeatureContext) -> dict:
        if ctx.cache.get("user"):
            user = ctx.cache["user"]
        else:
            user = ctx.db.get_user(ctx.user_id)
            ctx.cache["user"] = user

        return {
            "user_age": user.age,
            "user_gender": user.gender,
            "user_level": user.level,
        }

    def dependencies(self) -> List[str]:
        return []  # 无依赖，独立计算


class UserBehaviorOperator(FeatureOperator):
    """用户行为统计特征（跨时间窗口）"""
    name = "user_behavior_stats"
    category = "user"
    compute_cost = "medium"

    def __init__(self, time_windows: List[int] = None):
        self.time_windows = time_windows or [1, 7, 30]  # 天

    def compute(self, ctx: FeatureContext) -> dict:
        result = {}
        for days in self.time_windows:
            result[f"user_click_count_{days}d"] = ctx.db.count_clicks(ctx.user_id, days=days)
            result[f"user_favorite_count_{days}d"] = ctx.db.count_favorites(ctx.user_id, days=days)
            result[f"user_cart_count_{days}d"] = ctx.db.count_carts(ctx.user_id, days=days)
        return result

    def dependencies(self) -> List[str]:
        return ["user_stats"]  # 依赖用户基础信息


class ItemStatsOperator(FeatureOperator):
    """物品统计特征"""
    name = "item_stats"
    category = "item"
    compute_cost = "low"

    def compute(self, ctx: FeatureContext) -> dict:
        item = ctx.db.get_item(ctx.item_id)
        return {
            "item_popularity": item.view_count,
            "item_avg_rating": item.avg_rating,
            "item_price": item.price,
            "item_category_id": item.category_id,
        }

    def dependencies(self) -> List[str]:
        return []


class CrossFeatureOperator(FeatureOperator):
    """交叉特征——使用已计算的基础特征"""
    name = "cross_features"
    category = "cross"
    compute_cost = "low"

    def compute(self, ctx: FeatureContext) -> dict:
        user_clicks = ctx.features.get("user_behavior_stats", {}).get("user_click_count_7d", 0)
        item_pop = ctx.features.get("item_stats", {}).get("item_popularity", 1)
        user_age = ctx.features.get("user_stats", {}).get("user_age", 0)
        item_price = ctx.features.get("item_stats", {}).get("item_price", 0)

        return {
            "ctr_estimate": user_clicks / (item_pop + 1),       # CTR 估算
            "age_price_ratio": user_age / (item_price + 1),     # 年龄/价格比
            "popularity_score": item_pop * user_clicks,        # 热度交叉分
        }

    def dependencies(self) -> List[str]:
        return ["user_behavior_stats", "item_stats"]


class LLMTextEmbeddingOperator(FeatureOperator):
    """LLM 文本 embedding 特征（重特征，支持异步）"""
    name = "llm_text_embedding"
    category = "text"
    compute_cost = "high"
    cacheable = True

    def __init__(self, model_name: str = "text-embedding-3-small"):
        self.model_name = model_name
        self._model = None

    @property
    def model(self):
        if self._model is None:
            # lazy load embedding 模型
            self._model = self._load_model()
        return self._model

    def _load_model(self):
        # 实际项目中从模型服务器加载
        pass

    def compute(self, ctx: FeatureContext) -> dict:
        # 检查缓存
        cache_key = f"embedding:{ctx.item_id}"
        if ctx.cache.get(cache_key):
            return {"text_embedding": ctx.cache[cache_key]}

        item = ctx.db.get_item(ctx.item_id)
        text = f"{item.title} {item.description}"
        embedding = self.model.encode(text)  # 假设返回 numpy array

        if self.cacheable:
            ctx.cache[cache_key] = embedding

        return {"text_embedding": embedding}

    def dependencies(self) -> List[str]:
        return ["item_stats"]


# ========== 3. 特征管道编排器（插件容器）==========
class FeaturePipeline:
    """
    特征管道——负责注册、排序、执行特征算子插件
    """

    def __init__(self):
        self._operators: List[FeatureOperator] = []
        self._sorted_ops: List[FeatureOperator] = []  # 拓扑排序后的执行顺序

    def register(self, operator: FeatureOperator) -> "FeaturePipeline":
        """链式注册插件"""
        self._operators.append(operator)
        self._sort_operators()  # 重新拓扑排序
        return self  # 支持链式调用

    def _sort_operators(self) -> None:
        """
        拓扑排序：根据依赖关系确定执行顺序
        DAG 构建：如果 A 依赖 B，则 B 先执行
        """
        name_to_op = {op.name: op for op in self._operators}
        visited = set()
        order = []

        def visit(op: FeatureOperator):
            if op.name in visited:
                return
            visited.add(op.name)
            for dep in op.dependencies():
                if dep in name_to_op:
                    visit(name_to_op[dep])
            order.append(op)

        for op in self._operators:
            visit(op)

        self._sorted_ops = order

    def compute(self, user_id: int, item_id: int, db) -> dict:
        """执行管道，计算所有特征"""
        ctx = FeatureContext(user_id=user_id, item_id=item_id, db=db)
        ctx.cache["user"] = db.get_user(user_id)  # 预加载
        ctx.cache["item"] = db.get_item(item_id)  # 预加载

        for op in self._sorted_ops:
            try:
                result = op.compute(ctx)
                ctx.features[op.name] = result
            except Exception as e:
                print(f"⚠️  特征算子 {op.name} 计算失败: {e}，设为 None")
                ctx.features[op.name] = None

        return ctx.features

    async def compute_async(self, user_id: int, item_id: int, db) -> dict:
        """
        异步执行管道：按 compute_cost 分组并行
        high cost 算子（embedding）不阻塞 low cost 算子
        """
        ctx = FeatureContext(user_id=user_id, item_id=item_id, db=db)

        # 分组：独立算子（第0轮）+ 高成本算子（单独异步）
        independent = [op for op in self._sorted_ops if not op.dependencies()]
        dependent = {op.name: op for op in self._sorted_ops if op.dependencies()}

        # 第0轮：计算所有无依赖的算子
        tasks0 = [self._run_operator(op, ctx) for op in independent]
        results0 = await asyncio.gather(*tasks0)
        for op, result in zip(independent, results0):
            ctx.features[op.name] = result

        # 第1轮及以后：根据依赖逐步计算（简化为串行依赖链）
        remaining = [op for op in self._sorted_ops if op not in independent]
        for op in remaining:
            if all(dep in ctx.features and ctx.features[dep] is not None
                   for dep in op.dependencies()):
                result = await self._run_operator(op, ctx)
                ctx.features[op.name] = result

        return ctx.features

    async def _run_operator(self, op: FeatureOperator, ctx: FeatureContext):
        if op.compute_cost == "high":
            return await asyncio.to_thread(op.compute, ctx)
        return op.compute(ctx)


# ========== 4. 使用示例 ==========
# 构建管道（插件装配）
pipeline = (
    FeaturePipeline()
    .register(UserStatsOperator())
    .register(UserBehaviorOperator(time_windows=[1, 7, 30]))
    .register(ItemStatsOperator())
    .register(CrossFeatureOperator())
    .register(LLMTextEmbeddingOperator(model_name="bge-large-zh"))
)

# 执行推理
features = pipeline.compute(user_id=12345, item_id=9876, db=database)
# features["cross_features"]["ctr_estimate"] → 0.0234

# 新增一个图 embedding 特征，只需：
class GraphEmbeddingOperator(FeatureOperator):
    name = "graph_embedding"
    category = "graph"
    compute_cost = "high"

    def compute(self, ctx: FeatureContext) -> dict:
        return {"graph_embedding": ctx.db.get_graph_embedding(ctx.item_id)}

    def dependencies(self) -> List[str]:
        return ["item_stats"]

pipeline.register(GraphEmbeddingOperator())  # 一行代码，热插拔
```

**架构优势：**
- ✅ **插件化**：新增特征类型完全不影响现有代码
- ✅ **依赖管理**：自动拓扑排序，确保依赖先执行
- ✅ **异步优化**：高成本算子（embedding）不阻塞低成本算子
- ✅ **可观测**：每个算子独立计算耗时，可单独熔断
- ✅ **配置化**：特征组合可由配置文件决定，无需改代码

## 适用场景

### 策略模式适用场景
- **推荐系统**：多种召回策略、多种排序模型的 A/B 测试切换
- **风控系统**：多套风控规则引擎的动态切换
- **支付系统**：根据渠道/用户等级选择不同的计费策略
- **日志系统**：多种输出格式（JSON/CSV/ES）的可切换适配器

### 插件架构适用场景
- **AI Agent**：LangChain Tool 生态、OpenAI Plugin、钉钉/飞书机器人
- **IDE 扩展**：VSCode 插件体系、ESLint 规则集
- **数据处理管道**：ETL 任务的可插拔算子（推荐系统特征工程、训练数据清洗）
- **规则引擎**：业务规则的可插拔执行

## 常见误区

### 误区一：过度设计——为小系统引入插件架构
**反例：** 一个只会调用一个 API 的简单脚本，也搞一套插件注册中心。

**正确做法：** 当系统只有 1-2 种实现时，直接 if-else；当算法类型会持续增长、或者需要在运行时切换时，再引入策略模式。

> 经验法则：如果你发现自己每次加新算法都要改动多处代码，这就是引入策略模式的信号。

### 误区二：策略接口定义过大
**反例：** 把所有策略需要/不需要的方法全塞进抽象接口，导致大量空实现。

```python
# ❌ 接口污染
class Strategy(ABC):
    @abstractmethod
    def score(self, ...): pass

    @abstractmethod
    def load_model(self, path): pass  # 不是所有策略都有模型

    @abstractmethod
    def preprocess(self, ...): pass  # 不是所有策略都需要预处理
```

**正确做法：** 使用**基础接口 + 可选 Mixin** 的组合，或者用**协议（Protocol）**定义多个小接口。

```python
# ✅ 最小化接口 + 可选钩子
class ScoreStrategy(ABC):
    @abstractmethod
    def score(self, user_id, candidates, context) -> List: pass

class PreprocessingMixin:
    """可选混入：需要预处理的策略继承它"""
    def preprocess(self, ctx): ...

class ModelBackedMixin:
    """可选混入：需要加载模型的策略继承它"""
    def load_model(self, path): ...
```

### 误区三：策略之间共享状态，导致隐式耦合
**反例：** 两个策略通过共享全局变量传递中间结果，导致策略不能独立运行。

**正确做法：** 通过显式的 Context 对象传递共享数据（如 `FeatureContext`），且 Context 由框架管理，策略只读写自己声明的字段。

### 误区四：插件注册没有版本管理
**反例：** 线上运行中直接 `register` 新版插件，导致新旧策略同时存在、资源竞争。

**正确做法：** 插件支持版本号，发布时用**影子模式（Shadow Mode）**先验证新插件，再灰度切换。

## 进阶：插件架构在 AI 应用中的实践

### LLM 应用中的策略模式

```python
# 大模型调用——多后端策略
class LLMProvider(ABC):
    @abstractmethod
    def complete(self, prompt: str, **kwargs) -> str: pass

class OpenAIProvider(LLMProvider):
    def __init__(self, api_key: str, model: str = "gpt-4"):
        self.client = OpenAI(api_key=api_key)
        self.model = model

    def complete(self, prompt: str, **kwargs) -> str:
        response = self.client.chat.completions.create(
            model=self.model, messages=[{"role": "user", "content": prompt}], **kwargs
        )
        return response.choices[0].message.content

class DeepSeekProvider(LLMProvider):
    def __init__(self, api_key: str, model: str = "deepseek-chat"):
        ...

class ClaudeProvider(LLMProvider):
    ...

# Agent 核心只用 LLMProvider 接口，不关心具体实现
class RecommendationAgent:
    def __init__(self, llm: LLMProvider):
        self.llm = llm

    def explain_recommendation(self, item_id: int, reason: str) -> str:
        prompt = f"用户推荐了商品 {item_id}，推荐理由：{reason}，请用一句话解释为什么"
        return self.llm.complete(prompt)  # 切换 provider 不需要改这行代码
```

## 总结：策略模式 vs 插件架构 vs 管道模式

| 维度 | 策略模式 | 插件架构 | 管道模式 |
|------|---------|---------|---------|
| **核心目的** | 算法可互换 | 功能可扩展 | 数据流处理 |
| **典型场景** | 推荐算法选择、支付渠道 | AI Tool、特征算子 | ETL、特征工程 |
| **扩展方式** | 新增策略类 | 注册插件 | 增删管道节点 |
| **组合方式** | 策略选择器 | 插件注册中心 | 管道串联/并联 |
| **SOLID 原则** | OCP（对扩展开放）| OCP + DIP | SRP（单一职责） |

**三者的关系：**
- 策略模式解决 **"用哪个算法"** 的问题
- 插件架构解决 **"如何加载功能"** 的问题
- 管道模式解决 **"数据如何流经系统"** 的问题

在推荐系统和大模型应用中，这三者往往共同出现——例如一个 RAG Pipeline：用**管道模式**组织数据流，用**插件架构**管理各环节组件，用**策略模式**选择底层的 embedding 模型或重排模型。

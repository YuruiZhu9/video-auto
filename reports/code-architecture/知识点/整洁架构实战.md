# 整洁架构（Clean Architecture）- 推荐系统实战

> SOLID让你写好一个类，Clean Architecture让你设计好整个系统。
> 对于推荐系统这种"数据来源多、算法杂、迭代快"的场景，整洁架构是最值得掌握的架构理念。

---

## 什么是整洁架构？

**核心理念**：代码分层依赖只能向内，不能向外。

```
┌─────────────────────────────────────────────────────┐
│                    外层：基础设施                      │
│         （数据库、API、消息队列、外部服务）            │
├─────────────────────────────────────────────────────┤
│                    外层：接口适配器                   │
│         （API网关、Data Mapper、外部接口包装）         │
├─────────────────────────────────────────────────────┤
│                    中层：应用服务                      │
│         （用例编排、事务脚本、组合逻辑）                │
├─────────────────────────────────────────────────────┤
│                    内层：领域核心                      │
│         （业务实体、领域服务、业务规则、值对象）         │
├─────────────────────────────────────────────────────┤
│                    最内层：框架                       │
│              （数据库驱动、HTTP框架）                  │
└─────────────────────────────────────────────────────┘

依赖方向：只能从外向内 →
```

### 为什么要用整洁架构？

| 场景 | 无架构/三层架构 | 整洁架构 |
|------|--------------|---------|
| 换特征存储 | 改大量业务代码 | 只改Repository |
| 新增召回算法 | 修改主流程 | 新增Strategy类 |
| 换模型框架 | 重写整个服务 | 注入新实现 |
| 写单元测试 | 依赖真实DB | Mock任意层 |
| AB测试 | 改代码发版 | 配置切换 |

## 四层架构详解

### 第一层：领域层（Domain）— 最核心，最稳定

**包含内容**：
- 业务实体（Entity）
- 值对象（Value Object）
- 领域服务（Domain Service）
- 领域事件（Domain Event）
- 业务规则校验

**特点**：**零外部依赖**，只表达业务概念

```python
# ===== 领域层：零外部依赖 =====

from dataclasses import dataclass, field
from typing import List
from datetime import datetime
import uuid

@dataclass
class UserId:
    """值对象：用户ID"""
    value: str
    
    def __post_init__(self):
        if not self.value:
            raise ValueError("user_id不能为空")

@dataclass
class ItemScore:
    """值对象：带分数的物品"""
    item_id: str
    score: float
    reason: str = ""
    
    def __post_init__(self):
        if not (0 <= self.score <= 1):
            raise ValueError("score必须在[0,1]之间")

@dataclass
class Recommendation:
    """领域实体：推荐结果"""
    id: str
    user_id: str
    items: List[ItemScore]
    scene: str
    created_at: datetime = field(default_factory=datetime.now)
    
    def top_k(self, k: int) -> List[ItemScore]:
        """返回topK推荐，只读不改"""
        return sorted(self.items, key=lambda x: x.score, reverse=True)[:k]
    
    def filter_by_category(self, category: str) -> List[ItemScore]:
        """按分类过滤"""
        return [i for i in self.items if category in i.item_id]
    
    def add_item(self, item: ItemScore) -> None:
        """添加物品（受保护的业务逻辑）"""
        if len(self.items) >= 100:
            raise ValueError("单次推荐最多100个物品")
        self.items.append(item)


@dataclass
class RecallResult:
    """召回阶段领域对象"""
    strategy_name: str
    items: List[ItemScore]
    user_id: str
    count: int
    
    def merge_with(self, other: 'RecallResult') -> 'RecallResult':
        """合并多个召回结果（领域服务）"""
        merged_items = self.items + other.items
        # 去重，保留高分
        item_map = {i.item_id: i for i in merged_items}
        merged = sorted(item_map.values(), key=lambda x: x.score, reverse=True)
        return RecallResult(
            strategy_name=f"{self.strategy_name}+{other.strategy_name}",
            items=merged,
            user_id=self.user_id,
            count=self.count
        )


# 领域服务：跨实体的业务逻辑
class RecommendationDomainService:
    """核心业务规则：如何生成一个有效推荐"""
    
    MIN_RECALL_ITEMS = 10
    MIN_RANK_ITEMS = 5
    
    def validate_recall_result(self, result: RecallResult) -> bool:
        """召回结果是否符合最低要求"""
        if len(result.items) < self.MIN_RECALL_ITEMS:
            return False
        return True
    
    def select_final_items(self, items: List[ItemScore], count: int) -> List[ItemScore]:
        """精选最终推荐"""
        sorted_items = sorted(items, key=lambda x: x.score, reverse=True)
        # 业务规则：同类物品最多3个，避免结果单一
        category_count = {}
        selected = []
        for item in sorted_items:
            cat = self._extract_category(item.item_id)
            if category_count.get(cat, 0) < 3:
                selected.append(item)
                category_count[cat] = category_count.get(cat, 0) + 1
                if len(selected) >= count:
                    break
        return selected
    
    def _extract_category(self, item_id: str) -> str:
        """从item_id提取分类（业务规则）"""
        return item_id.split('_')[0] if '_' in item_id else 'default'
```

### 第二层：应用层（Application）— 用例编排

**包含内容**：
- 用例（Use Case / Service）
- 命令/查询处理
- 事务边界
- 跨领域协调

**特点**：依赖领域层，不依赖基础设施

```python
# ===== 应用层：用例 =====

from typing import List, Optional
from dataclasses import dataclass

@dataclass
class RecommendInput:
    """用例输入"""
    user_id: str
    scene: str = "home"
    count: int = 10
    include_explain: bool = True

@dataclass
class RecommendOutput:
    """用例输出"""
    items: List[ItemScore]
    scene: str
    total_recalled: int
    algorithm_version: str


class RecommendUseCase:
    """
    推荐用例：编排整个推荐流程
    
    职责：
    1. 协调多个领域服务和策略
    2. 管理事务边界
    3. 不包含具体业务逻辑（那是Domain的事）
    """
    
    def __init__(
        self,
        recall_coordinator: 'IRecallCoordinator',
        ranker: 'IRanker',
        domain_service: RecommendationDomainService,
        user_repo: 'IUserRepository',
        metrics: 'IMetricsRecorder',
    ):
        self.recall_coordinator = recall_coordinator
        self.ranker = ranker
        self.domain_service = domain_service
        self.user_repo = user_repo
        self.metrics = metrics
    
    def execute(self, inp: RecommendInput) -> RecommendOutput:
        """
        推荐主流程：
        召回 → 过滤 → 排序 → 精选 → 包装
        """
        # 1. 获取用户（校验）
        user = self.user_repo.find_by_id(inp.user_id)
        if not user:
            return RecommendOutput(items=[], scene=inp.scene, total_recalled=0, algorithm_version="")
        
        # 2. 召回（多路并发）
        recall_start = datetime.now()
        recall_result = self.recall_coordinator.coordinate(user, inp)
        recall_latency = (datetime.now() - recall_start).total_seconds()
        
        # 3. 过滤已购买/下线商品
        filtered = self._filter_items(recall_result.items, user)
        
        # 4. 排序
        ranked_items = self.ranker.rank(filtered, user)
        
        # 5. 精选（Domain核心规则）
        final_items = self.domain_service.select_final_items(
            ranked_items, inp.count
        )
        
        # 6. 记录指标
        self.metrics.record("recommend.recall_count", len(recall_result.items))
        self.metrics.record("recommend.recall_latency_ms", recall_latency * 1000)
        
        return RecommendOutput(
            items=final_items,
            scene=inp.scene,
            total_recalled=len(recall_result.items),
            algorithm_version="v2.3.1"
        )
    
    def _filter_items(self, items: List[ItemScore], user: 'User') -> List[ItemScore]:
        """过滤业务规则"""
        purchased = set(user.purchased_item_ids)
        expired = set(user.expired_item_ids)
        blocked = purchased | expired
        return [i for i in items if i.item_id not in blocked]
```

### 第三层：接口适配层（Interfaces）

**包含内容**：
- API Controller
- DTO（数据传输对象）
- Data Mapper（领域对象 ↔ DTO 转换）
- 外部服务适配器

**特点**：处理内外协议转换，不含业务逻辑

```python
# ===== 接口适配层 =====

from dataclasses import dataclass
from typing import List

# --- DTO：外部数据结构 ---

@dataclass
class RecommendRequestDTO:
    user_id: str
    count: int = 10
    scene: str = "home"
    channels: List[str] = None  # 推荐渠道
    
    def to_input(self) -> RecommendInput:
        return RecommendInput(
            user_id=self.user_id,
            scene=self.scene,
            count=self.count,
            include_explain=True
        )

@dataclass
class RecommendResponseDTO:
    code: int
    message: str
    data: dict
    
    @staticmethod
    def success(items: List[ItemScore], scene: str, total_recalled: int, version: str):
        return RecommendResponseDTO(
            code=200,
            message="success",
            data={
                "items": [
                    {
                        "item_id": i.item_id,
                        "score": round(i.score, 4),
                        "reason": i.reason
                    } for i in items
                ],
                "scene": scene,
                "total_recalled": total_recalled,
                "algorithm_version": version
            }
        )


# --- Controller ---

class RecommendController:
    """API接口：处理HTTP请求"""
    
    def __init__(self, use_case: RecommendUseCase):
        self.use_case = use_case
    
    def handle(self, request_dto: RecommendRequestDTO) -> RecommendResponseDTO:
        """请求入口"""
        try:
            # 1. 参数校验（接口层职责）
            if not request_dto.user_id:
                return RecommendResponseDTO(code=400, message="user_id不能为空", data={})
            
            # 2. 调用用例
            inp = request_dto.to_input()
            output = self.use_case.execute(inp)
            
            # 3. 转换输出
            return RecommendResponseDTO.success(
                items=output.items,
                scene=output.scene,
                total_recalled=output.total_recalled,
                version=output.algorithm_version
            )
        except ValueError as e:
            return RecommendResponseDTO(code=400, message=str(e), data={})
        except Exception as e:
            return RecommendResponseDTO(code=500, message="内部错误", data={})
```

### 第四层：基础设施层（Infrastructure）

**包含内容**：
- 数据库实现（Repository）
- 缓存实现
- 消息队列

**特点**：实现接口适配层定义的接口，具体实现随时可替换

```python
# ===== 基础设施层 =====

import redis
import json
from typing import Optional

# --- Repository 实现 ---

class RedisUserRepository:
    """用户仓储：Redis实现"""
    
    def __init__(self, redis_client: redis.Redis):
        self.redis = redis_client
    
    def find_by_id(self, user_id: str) -> Optional['User']:
        key = f"user:{user_id}"
        data = self.redis.get(key)
        if not data:
            return None
        return self._deserialize(json.loads(data))
    
    def _deserialize(self, data: dict) -> 'User':
        return User(
            user_id=data['user_id'],
            name=data['name'],
            features=data['features'],
            purchased_item_ids=data.get('purchased', []),
            expired_item_ids=data.get('expired', []),
        )


class HiveUserRepository:
    """用户仓储：Hive实现（生产环境使用）"""
    
    def __init__(self, spark_session):
        self.spark = spark_session
    
    def find_by_id(self, user_id: str) -> Optional['User']:
        df = self.spark.sql(f"""
            SELECT * FROM user_features 
            WHERE user_id = '{user_id}'
            LIMIT 1
        """)
        row = df.first()
        if not row:
            return None
        return User(
            user_id=row.user_id,
            name=row.name,
            features=json.loads(row.features_json),
            purchased_item_ids=json.loads(row.purchased_items),
            expired_item_ids=json.loads(row.expired_items),
        )


# --- 缓存实现 ---

class RedisCache:
    """缓存基础设施"""
    
    def __init__(self, client: redis.Redis):
        self.client = client
    
    def get(self, key: str) -> Optional[str]:
        return self.client.get(key)
    
    def set(self, key: str, value: str, ttl: int = 300):
        self.client.setex(key, ttl, value)
    
    def delete(self, key: str):
        self.client.delete(key)


# --- 消息队列实现 ---

class KafkaMetricsRecorder:
    """指标记录到Kafka"""
    
    def __init__(self, producer):
        self.producer = producer
    
    def record(self, metric_name: str, value: float):
        self.producer.send("metrics", {
            "name": metric_name,
            "value": value,
            "timestamp": datetime.now().isoformat()
        })
```

## 依赖注入容器

整洁架构的关键：如何把各层"粘"起来？

```python
# container.py - 手动依赖注入（适合理解原理）

class DIContainer:
    """简单的依赖注入容器"""
    
    def __init__(self, config: dict):
        self._services = {}
        self._config = config
        self._init_services()
    
    def _init_services(self):
        # 1. 基础设施
        redis_client = redis.Redis(host=self._config['redis']['host'])
        kafka_prod = KafkaProducer(bootstrap_servers=self._config['kafka']['servers'])
        
        # 2. 仓储
        user_repo = RedisUserRepository(redis_client)
        # 切换存储？一个配置的事！
        # user_repo = HiveUserRepository(spark)
        
        # 3. 领域服务
        domain_service = RecommendationDomainService()
        
        # 4. 召回策略（策略模式）
        recall_strategies = {
            'item_cf': ItemCFRecallStrategy(user_repo),
            'user_cf': UserCFRecallStrategy(user_repo),
            'embedding': EmbeddingRecallStrategy(user_repo),
        }
        
        recall_coordinator = MultiRecallCoordinator(
            strategies=recall_strategies,
            config=self._config['recall']
        )
        
        # 5. 排序器
        ranker = DNNRanker(model_path=self._config['model']['rank_path'])
        
        # 6. 指标记录
        metrics = KafkaMetricsRecorder(kafka_prod)
        
        # 7. 用例
        recommend_use_case = RecommendUseCase(
            recall_coordinator=recall_coordinator,
            ranker=ranker,
            domain_service=domain_service,
            user_repo=user_repo,
            metrics=metrics,
        )
        
        # 8. 控制器
        controller = RecommendController(recommend_use_case)
        
        self._services['controller'] = controller
        self._services['use_case'] = recommend_use_case
    
    def get_controller(self):
        return self._services['controller']


# main.py
def main():
    config = load_config("config.yaml")
    container = DIContainer(config)
    
    app = Flask(__name__)
    
    @app.route('/api/recommend', methods=['POST'])
    def recommend():
        dto = RecommendRequestDTO(**request.json)
        return container.get_controller().handle(dto)
    
    app.run()
```

## 整洁架构 vs 三层架构

| 对比项 | 三层架构 | 整洁架构 |
|--------|---------|---------|
| 分层数量 | 3层 | 4层（可细分更多） |
| 依赖方向 | 表现→业务→数据 | 四层同心圆，向内依赖 |
| 业务逻辑位置 | Service层 | Domain层（核心） |
| 可测试性 | 较难Mock | 轻松Mock任意层 |
| 学习成本 | 低 | 中 |
| 适用场景 | 简单CRUD | 复杂业务系统 |
| 扩展性 | 一般 | 强 |

**关键区别**：
- 三层架构的"业务层"包含了业务逻辑 → 难以测试
- 整洁架构把"业务规则"抽到Domain层 → 业务规则高度内聚，极易测试

## 推荐系统中的实际收益

### 场景1：切换特征存储

**三层架构问题**：
```python
# 要改很多地方...
class RecommendService:
    def get_user(self, user_id):
        # 硬编码MySQL
        return MySQL.query(...)
    
    def get_features(self, user_id):
        # 硬编码Redis
        return Redis.get(...)
```

**整洁架构方案**：
```python
# 只需要替换基础设施层的实现
class UserRepository:
    # 接口定义（在application/ports）
    pass

# MySQL实现 → 换Hive实现，只需要改这一处
class HiveUserRepository(UserRepository):
    pass
```

### 场景2：新增协同过滤召回

**三层架构问题**：要在主Service里if-else
**整洁架构方案**：新增一个Strategy类，配置注入即可

```python
# 新增策略，无需改现有代码！
class GraphRecallStrategy(RecallStrategy):
    async def recall(self, user, count):
        # 图神经网络召回
        return await self.gnn_model.predict(user.user_id, count)
```

## 常见误区

| 误区 | 正确做法 |
|------|---------|
| 每个类都要放对对应的层 | 小项目可以合并，大系统才细分 |
| 层数越多越"整洁" | 整洁的核心是依赖方向正确，不是层数 |
| Domain层可以依赖基础设施 | 绝对不行！Domain是核心，必须纯净 |
| Repository放在Domain层 | 不对，Repository是端口，在Application层定义接口 |
| 用async/await来判断是否IO | 根据业务语义分层，不是技术细节 |

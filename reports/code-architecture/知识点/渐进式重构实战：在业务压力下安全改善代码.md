# 渐进式重构实战：在业务压力下安全地改善代码

> 重构最大的风险不是技术，而是"改坏了没人知道"。渐进式重构的目标是：每次改动都小到可以回滚，大到能解决问题。

## 一、为什么渐进式重构

### 传统重构 vs 渐进式重构

| 对比维度 | 传统重构 | 渐进式重构 |
|---------|---------|-----------|
| 改动规模 | 大爆炸 | 每次一小步 |
| 风险 | 高（改完才发现问题）| 低（每步可验证）|
| 业务中断 | 长时间停摆 | 无感 |
| 团队协作 | 需要全员协调 | 独立可做 |
| 可回滚性 | 难（改动太多）| 易（版本控制+Feature Flag）|

### 渐进式重构三原则

1. **Baby Steps**：每次只做一件事，且一件事只改一处
2. **始终可运行**：每步重构后代码必须能跑，测试必须通过
3. **保险网**：有测试覆盖 + Feature Flag + 监控告警

## 二、渐进式重构路线图

```
推荐系统演进路线（渐进式）

阶段0：现状诊断（1-2天）
  └─ 代码质量评估（圈复杂度、耦合度、内聚度）
  └─ 识别最紧急的3个问题
  └─ 建立基准指标

阶段1：基础设施搭建（1周）
  └─ 引入 Feature Flag 开关
  └─ 建立 CI/CD 流水线
  └─ 补充核心模块单元测试
  └─ 添加关键监控指标

阶段2：分层隔离（2-3周）
  └─ 抽取数据访问层（Repository 模式）
  └─ 抽取领域逻辑层（Domain 层）
  └─ 建立 DI 容器

阶段3：设计模式应用（2-3周）
  └─ 引入策略模式（多路召回）
  └─ 引入模板方法（推荐流程）
  └─ 引入观察者（事件总线）

阶段4：微服务拆分（持续）
  └─ 按限界上下文逐步拆分
  └─ 先拆分非核心服务试水
  └─ 积累经验后再拆核心
```

### 第1步：添加保险网（Feature Flag + 测试）

**目标**：改动前先建立保护机制，改坏了能立即回滚。

```python
# config/feature_flags.py
FEATURE_FLAGS = {
    "recommend_new_flow": {
        "enabled": False,  # 默认关闭，保持旧逻辑
        "rollout": 0,     # 灰度0%，只有白名单用户走新逻辑
        "description": "新推荐流程（分层架构）"
    },
    "recommend_fallback": {
        "enabled": True,   # 默认开启，作为降级兜底
        "description": "旧推荐逻辑（兜底）"
    }
}

def is_enabled(flag_name: str, user_id: str = None) -> bool:
    flag = FEATURE_FLAGS.get(flag_name, {"enabled": False})
    if not flag["enabled"]:
        return False
    rollout = flag.get("rollout", 0)
    if rollout >= 100:
        return True
    if rollout > 0 and user_id:
        # 一致性哈希，保证同一用户每次判断一致
        user_hash = hash(user_id) % 100
        return user_hash < rollout
    return False

# 使用
def recommend_for_user(...):
    if is_enabled("recommend_new_flow", user_id):
        return recommend_new_flow(...)  # 新逻辑
    else:
        return recommend_fallback_flow(...)  # 旧逻辑兜底
```

**第1步小结**：建立了Feature Flag后，即使新代码有Bug，也只会影响灰度用户，且可以秒级回滚。

### 第3步：提取数据访问层（Repository 模式）

**目标**：把 SQL 查询封装起来，消除 SQL 注入风险，实现数据库可替换。

```python
from dataclasses import dataclass
from datetime import datetime
from typing import Optional

@dataclass
class UserProfile:

    age: int

@dataclass

from abc import ABC, abstractmethod

class IUserProfileRepository(ABC):
    @abstractmethod
    async def get_by_id(self, user_id: str) -> Optional[UserProfile]: ...

    @abstractmethod
    async def get_batch(self, user_ids: list[str]) -> dict[str, UserProfile]: ...

class IItemRepository(ABC):
    @abstractmethod
    async def get_by_id(self, item_id: str) -> Optional[Item]: ...

    @abstractmethod
    async def get_by_ids(self, item_ids: list[str]) -> list[Item]: ...

    @abstractmethod
    async def get_by_category(self, category: str, limit: int) -> list[Item]: ...

class IBehaviorRepository(ABC):
    @abstractmethod
    async def record(self, behavior: Behavior) -> None: ...

    @abstractmethod
    async def get_user_behaviors(self, user_id: str, 
                                  since: datetime) -> list[Behavior]: ...

# adapters/repositories.py（适配器实现）
import pymysql
import aiomysql
from typing import Optional

class MySQLUserProfileRepository(IUserProfileRepository):
    def __init__(self, config: DatabaseConfig):
        self.pool: Optional[aiomysql.Pool] = None
        self.config = config
    
    async def initialize(self):
        self.pool = await aiomysql.create_pool(
            host=self.config.host,
            port=self.config.port,
            user=self.config.user,
            password=self.config.password,
            db=self.config.database,
            minsize=5, maxsize=self.config.pool_size,
            autocommit=True
        )
    
    async def get_by_id(self, user_id: str) -> Optional[UserProfile]:
        async with self.pool.acquire() as conn:
            async with conn.cursor(aiomysql.DictCursor) as cursor:
                # ✅ 参数化查询，消除SQL注入
                await cursor.execute(
                    "SELECT user_id, name, age, tags, created_at "
                    "FROM user_profiles WHERE user_id = %s",
                    (user_id,)
                )
                row = await cursor.fetchone()
                if not row:
                    return None
                return UserProfile(
                    user_id=row['user_id'],
                    name=row['name'],
                    age=row['age'],
                    tags=json.loads(row['tags']) if row['tags'] else [],
                    created_at=row['created_at']
                )
    
    async def get_batch(self, user_ids: list[str]) -> dict[str, UserProfile]:
        if not user_ids:
            return {}
        async with self.pool.acquire() as conn:
            async with conn.cursor(aiomysql.DictCursor) as cursor:
                placeholders = ','.join(['%s'] * len(user_ids))
                await cursor.execute(
                    f"SELECT * FROM user_profiles WHERE user_id IN ({placeholders})",
                    user_ids
                )
                rows = await cursor.fetchall()
                return {
                    row['user_id']: UserProfile(...)
                    for row in rows
                }
```

- SQL注入风险消除（参数化查询）
- 数据库可替换（MySQL换PostgreSQL，只需新写适配器）
- 异步IO提升性能（aiomysql vs pymysql）
- 测试可Mock（接口抽象好了）

### 第4步：抽取领域逻辑层（核心业务隔离）

**目标**：核心推荐逻辑完全与框架/数据库/外部服务无关，可独立测试。

```python
# domain/services/recommendation_engine.py
"""
领域层：纯Python，无任何外部依赖
只有数据结构和业务规则
"""
from dataclasses import dataclass, field
from typing import Optional
from .entities import UserProfile, Item
from .ports import IUserProfileRepository, IItemRepository

@dataclass
class RecallResult:
    items: list[Item]
    channel: str  # 召回渠道名称
    score: float = 1.0

@dataclass
class RankingResult:
    items: list[Item]
    total: int

@dataclass  
class RecommendRequest:
    user_id: str
    scene: str  # home/search/category
    count: int = 20
    diversity_weight: float = 0.3
    boost_new: bool = True
    filter_blacklist: bool = True

@dataclass
class RecommendResponse:
    items: list[Item]
    request_id: str
    engine: str = "v1"
    metadata: dict = field(default_factory=dict)

class RecommendationEngine:
    """
    推荐引擎核心逻辑：完全与框架解耦
    """
    def __init__(
        self,
        user_repo: IUserProfileRepository,
        item_repo: IItemRepository,
        recall_strategies: list,  # 策略模式注入
    ):
        self.user_repo = user_repo
        self.item_repo = item_repo
        self.recall_strategies = recall_strategies
    
    async def recommend(self, request: RecommendRequest) -> RecommendResponse:
        # 1. 获取用户画像
        user = await self.user_repo.get_by_id(request.user_id)
        if not user:
            return self._empty_response(request)
        
        # 2. 多路召回（策略模式）
        recall_results = []
        for strategy in self.recall_strategies:
            if strategy.supports(request.scene):
                results = await strategy.recall(user, request)
                recall_results.append(results)
        
        # 3. 合并去重
        all_items = self._merge_recall(recall_results)
        
        # 4. 排序（策略模式，由外部注入）
        ranked = self._rank(all_items, request)
        
        # 5. 多样性处理
        diverse = self._diversify(ranked, request.diversity_weight)
        
        return RecommendResponse(
            items=diverse[:request.count],
            request_id=request.user_id,  # 简化处理
            engine="domain_engine_v1"
        )
    
    def _rank(self, items: list[Item], request: RecommendRequest) -> list[Item]:
        return sorted(items, key=lambda x: x.score, reverse=True)
    
    def _diversify(self, items: list[Item], weight: float) -> list[Item]:
        if weight <= 0:
            return items
        # MMR (Maximal Marginal Relevance) 多样性算法
        selected = []
        categories = set()
        for item in items:
            if item.category not in categories:
                selected.append(item)
                categories.add(item.category)
            if len(selected) >= len(items) * 0.5:
                break
        return selected + [i for i in items if i not in selected]
    
    def _merge_recall(self, recall_results: list[RecallResult]) -> list[Item]:
        item_map = {}
        for result in recall_results:
            for item in result.items:
                if item.item_id not in item_map:
                    item_map[item.item_id] = item
                    item.score = 0
                item_map[item.item_id].score += result.score
        return list(item_map.values())
    
    def _empty_response(self, request: RecommendRequest) -> RecommendResponse:
        return RecommendResponse(items=[], request_id=request.user_id)
```

**第4步小结**：
- 领域层零依赖（无requests、无pymysql、无redis）
- 策略模式注入（多路召回可热插拔）
- 核心逻辑可单元测试（Mock Repository即可）

```python
# application/recommend_usecase.py
"""应用层：编排领域逻辑，处理横切关注点"""
from domain.services.recommendation_engine import RecommendationEngine, RecommendRequest
from config.feature_flags import is_enabled

class RecommendUseCase:
    def __init__(self, engine: RecommendationEngine):
        self.engine = engine
    
    async def execute(self, user_id: str, scene: str, **kwargs):
        # Feature Flag 判断走哪套逻辑
        if is_enabled("recommend_new_flow", user_id):
            # ✅ 新逻辑：分层架构
            request = RecommendRequest(
                user_id=user_id,
                scene=scene,
                count=kwargs.get('count', 20),
                diversity_weight=kwargs.get('diversity_weight', 0.3),
            )
            response = await self.engine.recommend(request)
            return {
                "items": [self._serialize(i) for i in response.items],
                "engine": response.engine
            }
        else:
            # ⚠️ 旧逻辑兜底（保持原有行为）
            return self._fallback_flow(user_id, scene, **kwargs)
    
    def _serialize(self, item) -> dict:
        return {
            "item_id": item.item_id,
            "title": item.title,
            "score": item.score
        }
    
    def _fallback_flow(self, user_id: str, scene: str, **kwargs):
        # 原有旧逻辑临时保留（待新逻辑稳定后删除）
        import recommend_service as old  # 临时引用旧模块
        return old.recommend_for_user(user_id, scene, **kwargs)
```

### 第6步：建立监控门禁（守护重构成果）

```python
# monitoring/health_gate.py
from dataclasses import dataclass
import time

@dataclass
class HealthCheckResult:
    name: str
    passed: bool
    latency_ms: float
    error: str = ""

class HealthGate:
    """健康度门禁：每次请求后自动检查"""
    
    def __init__(self, container):
        self.container = container
        self.metrics = {
            "request_count": 0,
            "error_count": 0,
            "latencies": [],
            "fallback_count": 0
        }
    
    async def check_request(self, user_id: str, scene: str):
        start = time.perf_counter()
        try:
            usecase = RecommendUseCase(self.container.engine)
            result = await usecase.execute(user_id, scene)
            
            elapsed = (time.perf_counter() - start) * 1000
            self.metrics["request_count"] += 1
            self.metrics["latencies"].append(elapsed)
            
            # 新逻辑触发兜底计数
            if result.get("engine") != "domain_engine_v1":
                self.metrics["fallback_count"] += 1
            
            # 延迟告警
            if elapsed > 300:
                print(f"⚠️ 延迟告警: {elapsed:.0f}ms > 300ms")
            
            # 自动熔断：回退率 > 30% 则关闭新逻辑
            if self.metrics["request_count"] > 50:
                fallback_rate = (
                    self.metrics["fallback_count"] / 
                    self.metrics["request_count"]
                )
                if fallback_rate > 0.3:
                    print("🚨 自动熔断：新逻辑回退率过高，关闭新流程")
                    # 通过 Feature Flag 自动关闭
                    # FEATURE_FLAGS["recommend_new_flow"]["rollout"] = 0
        
        except Exception as e:
            self.metrics["error_count"] += 1
            elapsed = (time.perf_counter() - start) * 1000
            return HealthCheckResult(
                name=f"请求{user_id}", 
                passed=False,
                latency_ms=elapsed,
                error=str(e)
            )
        
        return HealthCheckResult(
            name=f"请求{user_id}", 
            passed=True,
            latency_ms=elapsed
        )
    
    def summary(self):
        if not self.metrics["latencies"]:
            return "无数据"
        
        import statistics
        latencies = self.metrics["latencies"]
        return {
            "总请求数": self.metrics["request_count"],
            "错误数": self.metrics["error_count"],
            "回退次数": self.metrics["fallback_count"],
            "P50延迟": f"{statistics.median(latencies):.1f}ms",
            "P99延迟": f"{sorted(latencies)[int(len(latencies)*0.99)]:.1f}ms",
            "最大延迟": f"{max(latencies):.1f}ms"
        }
```

## 五、渐进式重构的常见陷阱

**❌ 陷阱1：跳过 Feature Flag**
"先重构完再测" → 改了几千行后才发现问题 → 回滚代价巨大。

**❌ 陷阱2：一次性重构太多**
"我一口气把所有代码都改了" → Code Review 无法审 → 没人敢合并。

**❌ 陷阱3：忽略旧逻辑**
新逻辑写好了，旧逻辑直接删 → 生产出 Bug 才发现旧逻辑有特殊处理。

**❌ 陷阱4：没有监控**
重构后不知道新代码表现如何 → 数据异常才后知后觉。

**✅ 正确做法**：
1. Feature Flag 先搭好
2. 每次只重构一个小模块
3. 保持旧逻辑作为兜底
4. 监控 + 告警随时待命
5. 小步提交，随时可回滚

## 六、学习路径对应

```
重构实战 ← 基础模式（MVC/MVVM）
        ← 设计原则（SOLID/DRY/KISS）
        ← 代码坏味道识别
        ← 六边形架构（端口与适配器）
        → 推荐系统架构实战练习册（综合应用）
```

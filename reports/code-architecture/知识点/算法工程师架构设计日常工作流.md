## 阶段1：需求分析（接到任务的第一分钟）

### 1.1 灵魂三问（5分钟想清楚）

拿到一个新功能需求时，先问自己三个问题：

```
问题1：这个功能的"变化点"在哪里？
       → 将来什么会变？算法？数据源？业务规则？
       → 如果算法会频繁迭代 → 用策略模式，接口要稳定
       → 如果业务规则经常改 → 配置外部化，可开关

问题2：这个功能依赖什么外部服务？
       → 有哪些外部依赖（MySQL/Redis/Kafka/模型服务）？
       → 每个依赖挂了怎么办？→ 设计降级策略

问题3：这个功能有多"实时"的要求？
       → 实时（<100ms）→ 纯在线，预热缓存
       → 准实时（分钟级）→ Flink 流计算 + Redis
       → 离线（小时级）→ Spark/Hive 批处理
```

### 1.2 需求分类决策树

```
新功能类型 → 推荐架构位置 → 建议模式
═════════════════════════════════════════════════════
新增一路召回策略    → 召回层     → 策略模式（RecallStrategy）
改进排序模型        → 排序层     → 依赖注入（切换模型不改流程）
新增业务过滤规则    → 重排层     → 配置外部化 + 策略模式
实时用户统计特征    → 特征层     → Flink 流计算 + Redis
新加行为事件处理    → 数据层     → Kafka 事件驱动
缓存推荐结果        → 缓存层     → Cache-Aside + 多级缓存
新加外部数据源      → 基础设施层 → 六边形架构（适配器模式）
需要给运营提供开关   → 配置层     → Feature Flag
上线新模型          → 模型服务层  → 蓝绿部署 + A/B Test
```

### 1.3 技术债速查（接手项目第一步）

在动手之前，快速评估项目当前的技术债状况：

| 债类型 | 快速检查信号 | 影响程度 |
|--------|-------------|---------|
| **架构债** | 新增召回策略要改 5 处以上 | 🔴 高 |
| **数据债** | 不知道训练特征和推理特征是否一致 | 🔴 高 |
| **测试债** | 改代码靠 Postman，没有单元测试 | 🟡 中 |
| **性能债** | P99 延迟 > 500ms，不知道瓶颈在哪 | 🟡 中 |
| **可观测债** | 挂了只知道"慢了"，不知道哪慢 | 🟡 中 |
| **工程债** | 魔法数字散布，配置写死在代码里 | 🟢 低 |

### 2.2 SOLID 自检（写方案时）

在设计阶段，用 SOLID 五问做自我审查：

```
S（单一职责）→ 这个类/函数只做一件事吗？
               如果名字里出现"and"/"or"→ 拆分

O（开闭原则）→ 将来加新召回策略，要改现有代码吗？
               如果是 → 抽象接口，让策略可插拔

L（里氏替换）→ 换另一个排序模型，现有流程还能跑吗？
               如果不能 → 抽象 RankingPort

I（接口隔离）→ 接口方法太多了吗？
               RecallPort 只定义召回相关方法，不混入排序

D（依赖倒置）→ 业务逻辑依赖具体实现还是抽象接口？
               业务层不直接调 Redis，而是调 CachePort
```

### 2.4 降级策略设计（必做）

每个外部依赖必须设计降级策略，格式：

```
外部依赖          → 一级降级          → 二级降级          → 三级降级
──────────────────────────────────────────────────────────────────────
模型推理服务       → 缓存结果（5min）   → 上一版本模型        → 热门推荐兜底
Redis 缓存        → 直接查 MySQL       → 返回空（不崩溃）     → 静态推荐
Kafka 事件        → 本地队列重试（3次） → 写入文件（后续补发） → 丢弃（可接受）
Milvus 向量库     → ItemCF 召回替代    → 热门召回            → 空列表
用户画像服务       → 缓存画像（1h）     → 默认画像（新人）     → 不影响主流程
```

### 3.2 推荐系统代码速写模板

**策略模式新增召回策略（5步）**：

```python
# Step 1：定义端口（RecallPort）
# 文件：ports/recall_port.py
from abc import ABC, abstractmethod
from typing import List
from dataclasses import dataclass

@dataclass
class RecallResult:
    item_id: str
    score: float
    reason: str = ""

class RecallPort(ABC):
    """召回策略端口 - 所有召回策略必须实现这个接口"""
    
    @property
    @abstractmethod
    def name(self) -> str:
        """策略名称，用于日志和监控"""
        pass
    
    @abstractmethod
    async def recall(self, user_id: str, context: dict) -> List[RecallResult]:
        """执行召回，返回候选 item 列表"""
        pass

# Step 2：实现具体策略
# 文件：adapters/recall/embedding_recall.py
class EmbeddingRecallAdapter(RecallPort):
    def __init__(self, milvus_client, redis_client):
        self._milvus = milvus_client
        self._redis = redis_client
    
    @property
    def name(self) -> str:
        return "embedding_recall"
    
    async def recall(self, user_id: str, context: dict) -> List[RecallResult]:
        # 1. 获取用户向量
        user_vec = await self._redis.get(f"user_emb:{user_id}")
        if not user_vec:
            return []
        
        # 2. Milvus ANN 搜索
        results = self._milvus.search(
            collection_name="item_embeddings",
            query_vector=json.loads(user_vec),
            top_k=context.get("top_k", 100)
        )
        
        # 3. 过滤（业务规则）
        return [
            RecallResult(item_id=r["id"], score=r["distance"])
            for r in results if r["id"] not in context.get("exclude_ids", set())
        ]

# Step 3：注册到工厂
# 文件：factories/recall_factory.py
from typing import Dict

class RecallStrategyFactory:
    _strategies: Dict[str, RecallPort] = {}
    
    @classmethod
    def register(cls, name: str, strategy: RecallPort):
        cls._strategies[name] = strategy
    
    @classmethod
    def create(cls, name: str) -> RecallPort:
        if name not in cls._strategies:
            raise ValueError(f"Unknown recall strategy: {name}")
        return cls._strategies[name]
    
    @classmethod
    def list_strategies(cls) -> list:
        return list(cls._strategies.keys())

# Step 4：初始化时注册（DI 容器）
# 文件：container.py
class DIContainer:
    async def initialize(self):
        milvus = MilvusAdapter(config)
        redis = RedisAdapter(config)
        
        # 注册所有召回策略
        RecallStrategyFactory.register("embedding", EmbeddingRecallAdapter(milvus, redis))
        RecallStrategyFactory.register("item_cf", ItemCFRecallAdapter(milvus))
        RecallStrategyFactory.register("hot", HotRecallAdapter(redis))

# Step 5：应用层调用（只依赖端口，不依赖实现）
# 文件：use_cases/recall_use_case.py
class RecallUseCase:
    def __init__(self, factory: RecallStrategyFactory):
        self._factory = factory
    
    async def execute(self, user_id: str, strategy_names: List[str], top_k: int):
        results = []
        for name in strategy_names:
            strategy = self._factory.create(name)
            partial = await strategy.recall(user_id, {"top_k": top_k, "exclude_ids": set()})
            results.extend(partial)
        
        # 多路召回合并去重
        return self._merge_and_rank(results)
```

**六边形架构新增适配器（3步）**：

```python
# 当你需要新增一个外部服务时，只需：
# 1. 定义新端口（如果现有端口不适用）
class EmbeddingPort(ABC):
    @abstractmethod
    async def encode(self, texts: List[str]) -> List[List[float]]:
        pass

# 2. 写一个适配器（不影响领域逻辑）
class OpenAIEmbeddingAdapter(EmbeddingPort):
    def __init__(self, api_key: str):
        self._client = OpenAI(api_key=api_key)
    
    async def encode(self, texts: List[str]) -> List[List[float]]:
        response = await self._client.embeddings.create(
            model="text-embedding-3-small",
            input=texts
        )
        return [item.embedding for item in response.data]

# 3. 在 DI 容器里切换（改一行代码，不动业务逻辑）
container.register(EmbeddingPort, OpenAIEmbeddingAdapter(api_key=config.openai_key))
```

### 3.3 防御式编程三板斧

**每段外部调用都要用这三层保护**：

```python
async def call_model_inference(user_id: str, item_ids: List[str]) -> List[float]:
    """
    推荐系统模型推理调用模板
    三层保护：超时 → 重试 → 降级
    """
    try:
        # 保护1：设置超时（connect + read 双超时）
        async with asyncio.timeout(5.0):  # 总超时 5s
            response = await model_client.predict(
                user_id=user_id,
                item_ids=item_ids
            )
        
        # 保护2：输出校验（防御模型崩溃）
        if not isinstance(response, dict) or "scores" not in response:
            raise RankingException("Invalid model response format")
        
        scores = response["scores"]
        if len(scores) != len(item_ids):
            raise RankingException(f"Score count mismatch: {len(scores)} vs {len(item_ids)}")
        
        # 保护3：降级兜底（不能让整个推荐崩溃）
        return scores
    
    except asyncio.TimeoutError:
        logger.warning(f"Model inference timeout for user {user_id}, using fallback")
        return fallback_hot_scores(item_ids)  # 降级到热门排序
    
    except RankingException:
        logger.error(f"Model returned invalid data for user {user_id}")
        return fallback_hot_scores(item_ids)
    
    except Exception as e:
        logger.exception(f"Unexpected error in model inference: {e}")
        return fallback_hot_scores(item_ids)
```

## 阶段4：上线与迭代

### 4.1 上线前检查清单（20项）

**代码质量类（5项）**
- [ ] 核心逻辑有单元测试，覆盖率 ≥ 80%
- [ ] flake8 / ESLint 检查通过，无 E9/F63/F7 级别错误
- [ ] 无 SQL 注入风险（全部参数化查询）
- [ ] 无硬编码配置（配置外部化到 config.py 或环境变量）
- [ ] 魔法数字全部定义成常量或配置文件

**接口规范类（3项）**
- [ ] 请求参数有 Pydantic 校验（类型 + 范围）
- [ ] 统一响应格式 `{code, data, message}`
- [ ] 敏感数据在响应中脱敏

**性能类（4项）**
- [ ] 无 N+1 查询（批量查询替代循环查询）
- [ ] 外部调用设置超时（connect + read）
- [ ] 缓存 key 有 TTL，避免无限堆积
- [ ] P99 延迟在目标范围内（召回 < 50ms，排序 < 200ms，总延迟 < 300ms）

**可靠性类（5项）**
- [ ] 每个外部依赖有降级策略
- [ ] 异常不会导致整个请求崩溃（有 try-except）
- [ ] 幂等性设计（Kafka 消息 / 重试不会重复处理）
- [ ] 优雅关闭（SIGTERM 时完成当前请求再退出）

**可观测类（3项）**
- [ ] 有结构化日志（request_id + user_id + scene + 耗时）
- [ ] 有 Prometheus 指标（请求量 / 延迟 / 错误率）
- [ ] 上线后能在 Grafana 看板看到数据

### 4.3 迭代开发工作流

```
Bug 报告 / 新功能需求
        ↓
┌─ Bug？ ────────────────────────────────┐
│ Step 1：复现（本地 / Staging 环境）       │  新功能？
│ Step 2：找到根因（5 Why 分析）            │  Step 1：画架构图（5 分钟）
│ Step 3：确认是否技术债引发                │  Step 2：写 ADR（重要决策）
│ Step 4：修复（改一点测一点）              │  Step 3：TDD（先写测试）
│ Step 5：确认修复 + 回归测试               │  Step 4：增量实现
└────────────────────────────────────────┘
        ↓
Code Review（重点检查：SOLID / 异常处理 / 可测试性）
        ↓
合并到主分支（Feature Flag 控制，如需灰度）
        ↓
Staging 验证（金丝雀 5% 流量）
        ↓
全量上线 + 监控
        ↓
判断是否为常见问题 → 记录到踩坑记录
```

### 4.4 技术债还款决策（日常版）

当你在开发过程中发现技术债，问自己：

```
┌─────────────────────────────────────────────────────────┐
│              技术债还款决策树                              │
├─────────────────────────────────────────────────────────┤
│ 这个代码多久改一次？                                       │
│  ├─ 几乎不改（< 1次/月）→ 低息债 → 暂不还，加 TODO 注释     │
│  └─ 经常改（≥ 1次/月）→ 进入下一步                         │
│                                                         │
│ 改一次比正常多花多少时间？                                 │
│  ├─ < 30min → 低息债 → 顺手清理（Boy Scout Rule）          │
│  └─ ≥ 30min → 进入下一步                                   │
│                                                         │
│ 这个功能当前压力大吗？                                     │
│  ├─ 压力大（紧急上线）→ 先记账，标记 TECH_DEBT.md           │
│  └─ 压力小 → 本次顺手还掉（ROI 最高）                       │
└─────────────────────────────────────────────────────────┘
```

**TECH_DEBT.md 记录模板**：

```markdown
# 技术债登记

## 高息债（优先偿还）
| ID | 位置 | 描述 | 利息估算 | 计划 |
|----|------|------|---------|------|
| TD-001 | recall/engine.py:45 | 硬编码召回上限100，无法配置 | 2h/月 | 本周 |

## 中息债（记录跟踪）
| ID | 位置 | 描述 | 利息估算 | 计划 |
|----|------|------|---------|------|
| TD-002 | model/ranker.py | 模型无版本管理 | 1h/月 | 下月Sprint |

## 低息债（顺手清理）
| ID | 描述 | 预计清理时间 |
|----|------|------------|
| TD-003 | 魔法数字 TIMEOUT=5000 散布3处 | 5min |
```

### 场景 → 模式映射表

| 场景 | 模式 | 关键代码 |
|------|------|---------|
| 多路召回策略切换 | 策略模式 | `RecallStrategyFactory.create(name)` |

| 推荐结果加去重/广告标记 | 装饰器 | `RecommenderDecorator` |
| 换模型不重启服务 | 代理模式 | `ModelProxy` |
| Kafka 事件触发多 Consumer | 观察者 | `EventBus.subscribe()` |
| 外部服务切换（MySQL→PG） | 六边形适配器 | 实现 `StoragePort` |
| 大量对象构建 | 建造者 | `@dataclass_builder` |
| 鉴权→限流→推荐链 | 责任链 | `HandlerChain` |
| 不同场景创建推荐器 | 工厂模式 | `scene_factory[scene]()` |
| 批量操作原子化 | Unit of Work | `uow.commit()` |

### 降级策略速查

```
模型挂了     → 缓存 → 上一版本 → 热门兜底
Redis挂了   → 直接查 MySQL → 默认空列表
Kafka挂了   → 本地队列 → 文件补发 → 可接受丢弃
Milvus挂了  → ItemCF替代 → 热门召回 → 空列表
```

```
错误率     > 1%           → 立即告警（P1）

缓存命中率 < 90%           → 告警（P2）
召回非空率 < 99%           → 告警（P2）
Kafka Lag > 10000         → 告警（P2）
```

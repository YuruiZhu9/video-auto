# 自适应架构与系统韧性设计

> 核心问题：系统如何在外界环境不断变化时，自动调整自己，始终保持可用？
>
> 从"尽力防护"到"主动适应"——让系统在故障中学习，在压力下进化。

---

## 概念解释

### 什么是自适应架构？

自适应架构（Adaptive Architecture）是系统在运行时**感知环境变化、自动调整行为**的能力。传统架构假设环境可控；自适应架构承认：环境必然变化，系统必须响应。

**三类常见变化：**

| 变化类型 | 示例 | 系统响应 |
|---------|------|---------|
| **流量波动** | 秒杀、热点事件 | 自动扩容/限流 |
| **依赖故障** | Redis挂了、模型服务超时 | 降级、熔断、热切换 |
| **版本更新** | 新模型上线、新策略发布 | 灰度渐进式切换 |
| **资源耗尽** | 内存OOM、连接池打满 | 弹性回收、熔断保护 |

**自适应 vs 传统韧性：**

| | 传统韧性（防御型） | 自适应架构（进化型） |
|--|--|--|
| 策略 | 预设规则、被动触发 | 感知环境、主动调整 |
| 熔断 | 固定阈值（错误率>50%） | 动态阈值（历史基线+当前趋势） |
| 扩容 | 固定规则（CPU>70%） | 预测式扩容（ML模型预测峰值） |
| 上线 | 全量发布 | 灰度渐进，按指标自动推进/回滚 |
| 故障恢复 | 被动告警+人工介入 | 自动故障转移+自愈 |

## 一、混沌工程：主动注入故障，系统才会真正坚韧

### 核心理念

> "你无法防止不受控的故障，但可以让系统学会从故障中恢复。"

混沌工程（Chaos Engineering）最早由 Netflix 提出（Chaos Monkey），核心是**在生产环境中主动注入故障**，验证系统韧性是否如预期工作。

**混沌工程四步法：**

```
Step 1: 定义稳态（Steady State）
        "系统正常运行时的关键指标是什么？"
        → QPS、P99延迟、错误率、缓存命中率

Step 2: 假设（ Hypothesis）
        "如果 X 发生，系统 Y 指标仍然满足稳态"
        → "如果 Redis 宕机，首页推荐 P99 < 800ms"

Step 3: 注入故障（ Introduce Variable）
        关闭服务、注入网络延迟、模拟磁盘满……

Step 4: 观察与学习（ Observe & Learn）
        指标是否超出稳态边界？
        是否发现了新的弱点？→ 修复 → 重复
```

### 推荐系统混沌工程实战场景

**场景1：Redis 宕机**
```
假设：Redis 宕机时，推荐结果从本地缓存降级，P99 < 800ms
注入：redis-cli DEBUG SLEEP 30 或 kill redis进程
观测：推荐延迟是否在800ms内、错误率是否<1%
```

**场景2：模型推理服务超时**
```
假设：精排模型超时（>300ms），自动降级为规则排序
注入：注入延迟 or 返回错误码
观测：降级策略是否触发、推荐结果是否仍可用
```

**场景3：Kafka 消费延迟**
```
假设：Kafka Consumer Lag 积压，用户行为特征更新延迟
注入：Consumer 暂停消费，模拟 Lag 积压
观测：特征更新延迟告警、恢复后事件是否完整重放
```

### Python 混沌工程引擎

```python
"""
简化版混沌工程引擎：用于推荐系统
主动注入故障，验证降级链路是否有效
"""
import random
import time
import logging
from typing import Optional
from dataclasses import dataclass, field
from datetime import datetime
from enum import Enum

logger = logging.getLogger(__name__)


class FailureType(Enum):
    """可注入的故障类型"""
    REDIS_TIMEOUT = "redis_timeout"
    REDIS_OFFLINE = "redis_offline"
    MODEL_LATENCY = "model_latency"
    MODEL_ERROR = "model_error"
    KAFKA_LAG = "kafka_lag"


@dataclass
class ExperimentResult:
    """混沌实验结果"""
    experiment_name: str
    failure_type: FailureType
    start_time: datetime
    end_time: datetime
    steady_state_before: dict
    steady_state_during: dict
    hypothesis_verified: bool
    observations: list[str] = field(default_factory=list)
    recommendations: list[str] = field(default_factory=list)


class ChaosEngine:
    """
    推荐系统混沌工程引擎

    使用示例：
        engine = ChaosEngine()
        result = engine.run_experiment(
            name="redis_offline_impact",
            failure_type=FailureType.REDIS_OFFLINE,
            duration_seconds=30,
            hypothesis="P99 < 800ms 且错误率 < 5%",
        )
        print(result.hypothesis_verified)
    """

    def __init__(self):
        self.experiments: list[ExperimentResult] = []
        self._mock_redis_timeout = False
        self._model_error_mode = False

    def run_experiment(
        self,
        name: str,
        failure_type: FailureType,
        duration_seconds: int,
        hypothesis: str,
    ) -> ExperimentResult:
        """
        执行一次混沌实验

        流程：
        1. 测量注药前的稳态（30秒）
        2. 注入故障
        3. 持续监测指标
        4. 停止故障
        5. 判定假设是否成立
        """
        logger.info(f"🚀 启动混沌实验: {name}")
        logger.info(f"   故障类型: {failure_type.value}")
        logger.info(f"   假设: {hypothesis}")
        logger.info(f"   持续: {duration_seconds}s")

        start_time = datetime.now()

        # Step 1: 测量注药前稳态（取样）
        steady_before = self._measure_steady_state(min(duration_seconds, 30))
        logger.info(f"   注药前稳态: {steady_before}")

        # Step 2: 注入故障
        self._inject_failure(failure_type)

        # Step 3: 注药期间持续监测
        steady_during = self._measure_steady_state(duration_seconds)
        observations = self._collect_observations(failure_type, steady_before, steady_during)
        logger.info(f"   注药期间稳态: {steady_during}")

        # Step 4: 恢复
        self._recover_from_failure(failure_type)

        end_time = datetime.now()

        # Step 5: 判定假设
        verified = self._verify_hypothesis(steady_before, steady_during)

        result = ExperimentResult(
            experiment_name=name,
            failure_type=failure_type,
            start_time=start_time,
            end_time=end_time,
            steady_state_before=steady_before,
            steady_state_during=steady_during,
            hypothesis_verified=verified,
            observations=observations,
            recommendations=self._generate_recommendations(verified, observations),
        )
        self.experiments.append(result)
        logger.info(f"✅ 实验完成: 假设{'✅验证通过' if verified else '❌未通过'}")
        return result

    def _inject_failure(self, failure_type: FailureType):
        """注入指定类型的故障"""
        if failure_type == FailureType.REDIS_OFFLINE:
            logger.warning(f"⚠️ Redis 宕机已注入")
            self._mock_redis_timeout = True
        elif failure_type == FailureType.REDIS_TIMEOUT:
            logger.warning(f"⚠️ Redis 超时故障已注入 (timeout=2s)")
            self._mock_redis_timeout = True
        elif failure_type == FailureType.MODEL_LATENCY:
            logger.warning(f"⚠️ 模型推理延迟已注入")
        elif failure_type == FailureType.MODEL_ERROR:
            logger.warning(f"⚠️ 模型错误模式已激活")
            self._model_error_mode = True
        elif failure_type == FailureType.KAFKA_LAG:
            logger.warning(f"⚠️ Kafka Lag 故障已注入")

    def _recover_from_failure(self, failure_type: FailureType):
        """从故障中恢复"""
        self._mock_redis_timeout = False
        self._model_error_mode = False
        logger.info(f"✅ 故障已清除: {failure_type.value}")

    def _measure_steady_state(self, duration_seconds: int) -> dict:
        """采集稳态指标（模拟，实际应从Prometheus拉取）"""
        time.sleep(min(duration_seconds, 2))
        return {
            "p99_latency_ms": 150 + random.gauss(0, 30),
            "error_rate": max(0, 0.005 + random.gauss(0, 0.002)),
            "cache_hit_rate": max(0, min(1, 0.92 + random.gauss(0, 0.02))),
        }

    def _collect_observations(self, failure: FailureType,
                               before: dict, during: dict) -> list[str]:
        """收集实验过程中的观察"""
        obs = []
        latency_change = during["p99_latency_ms"] - before["p99_latency_ms"]
        error_change = during["error_rate"] - before["error_rate"]
        cache_change = during["cache_hit_rate"] - before["cache_hit_rate"]

        obs.append(f"延迟变化: {latency_change:+.0f}ms")
        obs.append(f"错误率变化: {error_change:+.3f}")
        obs.append(f"缓存命中率变化: {cache_change:+.2f}")

        if during["p99_latency_ms"] > before["p99_latency_ms"] * 2:
            obs.append("⚠️ 延迟超过基准2倍，可能需要降级策略优化")
        if during["error_rate"] > 0.05:
            obs.append("⚠️ 错误率超过5%，降级策略可能未生效")
        if cache_change < -0.1:
            obs.append("⚠️ 缓存命中率大幅下降，Redis降级链路过长")

        return obs

    def _verify_hypothesis(self, before: dict, during: dict) -> bool:
        """验证假设是否成立"""
        p99_ok = during["p99_latency_ms"] < 800
        error_ok = during["error_rate"] < 0.05
        return p99_ok and error_ok

    def _generate_recommendations(self, verified: bool,
                                   observations: list[str]) -> list[str]:
        """根据实验结果生成改进建议"""
        recs = []
        if not verified:
            recs.append("假设未验证通过，需要强化降级策略")
            for obs in observations:
                if "延迟" in obs:
                    recs.append("考虑增加多级缓存或规则兜底")
                if "错误率" in obs:
                    recs.append("完善熔断器阈值或添加降级开关")
                if "缓存" in obs:
                    recs.append("检查Redis降级后本地缓存命中率")
        else:
            recs.append("降级策略有效，继续扩大故障注入测试范围")
        return recs

    def generate_report(self) -> str:
        """生成混沌实验报告"""
        lines = ["# 🧪 混沌工程实验报告", ""]
        lines.append(f"实验次数: {len(self.experiments)}")
        if self.experiments:
            rate = sum(e.hypothesis_verified for e in self.experiments) / len(self.experiments)
            lines.append(f"通过率: {rate:.0%}")
        lines.append("")
        for exp in self.experiments[-10:]:
            status = "✅" if exp.hypothesis_verified else "❌"
            lines.append(f"## {status} {exp.experiment_name}")
            lines.append(f"故障类型: {exp.failure_type.value}")
            lines.append(f"持续: {(exp.end_time - exp.start_time).seconds}s")
            lines.append(f"观察:")
            for obs in exp.observations:
                lines.append(f"  - {obs}")
            lines.append(f"建议:")
            for rec in exp.recommendations:
                lines.append(f"  - {rec}")
            lines.append("")
        return "\n".join(lines)
```

### 混沌工程安全规范（必读）

> ⚠️ **混沌工程有风险，操作需谨慎！**

```
1. 最小化爆炸半径
   - 先在测试环境运行，再在生产低峰期运行
   - 设置自动终止开关（ExperimentKillSwitch）

2. 渐进式注入
   - 先注入单点故障，确认有效后再组合故障
   - 例如：先 Redis离线 → 再 Redis+模型同时故障

3. 自动回滚
   - 实验超时自动停止（TTL机制）
   - 指标恶化超阈值自动停止

4. 通知机制
   - 实验开始前在飞书/Slack群通知
   - 实验结束后发送结果摘要

5. 禁止在以下情况运行
   - 系统已处于故障状态
   - 业务高峰期（如双11秒杀）
   - 系统刚发布未稳定时
```

## 二、弹性伸缩：让系统自动应对流量潮汐

### 推荐系统的流量特征

```
                    流量峰值
                    ↗      ↘
                   /          \
        ╱╲        /            ╲        ╱╲
       /  ╲      /              \      /  ╲
──────/────╲────/────────────────╲────/────\─────→ 时间
      秒杀   日常低谷            热点事件

推荐系统特点：
- 日间流量 >> 夜间流量（白天推荐调用量是深夜的5-10倍）
- 热点事件导致突发流量（明星塌房/热搜事件）
- 推荐引擎计算密集，资源消耗波动大
```

### 推荐系统三阶段弹性伸缩策略

```
阶段1：日常弹性（自动响应常规流量变化）
├── 触发：推荐QPS > 100/Pod 或 P99 > 300ms
├── 动作：扩容至 CPU < 60%，最大50 Pod
└── 冷却：扩容后5分钟内不缩容

阶段2：热点事件响应（突发流量）
├── 触发：单分钟QPS增长 > 200%（环比）
├── 动作：预扩容 + 启动热点降级预案（简化召回）
└── 时限：热点结束后自动回收

阶段3：降级保护（资源极度紧张）
├── 触发：所有Pod CPU > 90% 且 Queue > 1000
├── 动作：启动限流 + 降级规则（单策略+简化排序）
└── 优先：保护精排模型推理（核心算力）
```

### Python 预测式扩容

```python
"""
预测式扩容器（简化版）

思路：不等待指标超过阈值再扩容，
而是通过历史趋势预测未来需求，提前行动
"""
import numpy as np
from datetime import datetime, timedelta
from sklearn.linear_model import LinearRegression


class PredictiveScaler:
    """
    预测式扩容器

    策略：
    - 预测峰值QPS > 当前容量 150% → 扩容到峰值对应副本数
    - 预测峰值QPS < 当前容量 60% → 缩容到最低保障副本数
    - 其他情况 → 保持不变
    """

    def __init__(self):
        self.model = LinearRegression()
        self._historical_qps: list[tuple[datetime, float]] = []

    def record_qps(self, timestamp: datetime, qps: float):
        """记录历史QPS数据"""
        self._historical_qps.append((timestamp, qps))
        cutoff = timestamp - timedelta(days=7)
        self._historical_qps = [(t, q) for t, q in self._historical_qps if t > cutoff]

    def predict_next_hour(self) -> list[tuple[datetime, float]]:
        """预测接下来1小时的QPS趋势"""
        if len(self._historical_qps) < 24:
            last = self._historical_qps[-1][1] if self._historical_qps else 100
            return [(datetime.now(), last)]

        hours, qps_values = [], []
        now = datetime.now()

        for i in range(-min(168, len(self._historical_qps)), 0, 6):
            ts = now + timedelta(hours=i)
            hours.append([ts.hour + ts.weekday() * 24])
            recent = [q for t, q in self._historical_qps
                     if abs((t - ts).total_seconds()) < 3600 * 3]
            qps_values.append(np.mean(recent) if recent else 100)

        if len(hours) < 5:
            return [(datetime.now(), np.mean(qps_values))]

        self.model.fit(hours, qps_values)

        predictions = []
        for m in range(10, 61, 10):
            future_ts = now + timedelta(minutes=m)
            future_hour = future_ts.hour + future_ts.weekday() * 24
            pred_qps = max(0, self.model.predict([[future_hour]])[0])
            predictions.append((future_ts, pred_qps))
        return predictions

    def get_target_replicas(self, current_replicas: int, max_replicas: int) -> int:
        """根据预测结果计算目标副本数"""
        predictions = self.predict_next_hour()
        if not predictions:
            return current_replicas

        peak_qps = max(qps for _, qps in predictions)
        current_capacity = current_replicas * 100  # 每Pod 100 QPS

        if peak_qps > current_capacity * 1.5:
            target = int(peak_qps / 100 * 1.2)  # 多备20%容量
            return min(target, max_replicas)
        elif peak_qps < current_capacity * 0.6:
            return max(3, int(peak_qps / 100 * 1.1))  # 保守缩容
        else:
            return current_replicas
```

## 三、灰度发布与渐进式上线：让风险可量化、可控制

### 推荐系统发布的高风险场景

```
❌ 高风险发布场景（禁止全量直接上线）：
1. 推荐模型更新（CTR/CVR模型 / Embedding模型）
   → 新模型可能导致推荐结果大幅变化
2. 召回策略重大调整（新增召回路 / 删除旧路）
   → 可能导致某类型内容完全不出现
3. 排序算法重构（特征变化 / 模型结构调整）
   → 排序结果可能与预期差异大

✅ 安全发布策略：
- 灰度发布（5% → 20% → 50% → 100%）
- 金丝雀发布（新版本5%，旧版本95%，逐步切换）
- A/B实验（不同版本服务不同用户群）
```

### 推荐系统金丝雀 + A/B 实验完整实现

```python
"""
推荐引擎金丝雀发布系统

核心思路：
- 新版本（canary）服务X%用户
- 旧版本（stable）服务(100-X)%用户
- 指标持续监控：canary更优则加速放量，更差则自动回滚
"""
import hashlib
import random
import logging
import threading
import time
from dataclasses import dataclass
from datetime import datetime, timedelta
from enum import Enum
from typing import Callable, Optional

logger = logging.getLogger(__name__)


class ExperimentStatus(Enum):
    RUNNING = "running"
    PROMOTED = "promoted"
    ROLLED_BACK = "rolled_back"


@dataclass
class ExperimentMetrics:
    timestamp: datetime
    canary_ctr: float
    stable_ctr: float
    sample_size: int


class CanaryExperiment:
    """
    推荐引擎金丝雀实验管理器

    使用示例：
        exp = CanaryExperiment(
            experiment_id="recall_v3_20260406",
            canary_fn=get_recommendations_v3,
            stable_fn=get_recommendations_v2,
        )
        exp.start(initial_canary_percent=5)
        decision = exp.evaluate_and_decide()
        # "promote_10pct" / "promote_30pct" / "rollback" / "keep_testing"
    """

    def __init__(
        self,
        experiment_id: str,
        canary_fn: Callable,
        stable_fn: Callable,
    ):
        self.experiment_id = experiment_id
        self.canary_fn = canary_fn
        self.stable_fn = stable_fn
        self.status = ExperimentStatus.RUNNING
        self.canary_percent = 0
        self.metrics_history: list[ExperimentMetrics] = []

        # 实验参数
        self.min_sample_size = 10000
        self.promote_threshold = 0.05   # CTR提升5%以上
        self.rollback_threshold = -0.02  # CTR下降2%以上

    def start(self, initial_canary_percent: int = 5):
        """启动金丝雀实验"""
        logger.info(f"🚀 启动金丝雀实验: {self.experiment_id}")
        self.canary_percent = initial_canary_percent
        self.status = ExperimentStatus.RUNNING

    def get_recommendation(self, user_id: str, scene: str, request_id: str) -> dict:
        """
        获取推荐结果（路由到对应版本）

        关键：同一user_id始终路由到同一版本（用户体验一致性）
        """
        version = self._route(user_id)

        if version == "canary" and self.status == ExperimentStatus.RUNNING:
            return self.canary_fn(user_id=user_id, scene=scene, request_id=request_id)
        else:
            return self.stable_fn(user_id=user_id, scene=scene, request_id=request_id)

    def _route(self, user_id: str) -> str:
        """
        基于用户ID哈希，决定路由版本

        一致性哈希：user_id的MD5前2位转整数（0-255）
        """
        hash_val = int(
            hashlib.md5(f"{self.experiment_id}:{user_id}".encode()).hexdigest()[:2], 16
        )
        bucket = (hash_val * 100) // 256  # 0-99
        return "canary" if bucket < self.canary_percent else "stable"

    def evaluate_and_decide(self) -> str:
        """
        评估实验结果并做出决策

        评估维度（推荐系统核心指标）：
        - CTR（点击率）：推荐质量的核心指标
        - CVR（转化率）：用户是否进一步操作
        - 曝光新颖度（Novelty）：是否推荐了新内容

        决策规则：
        - CTR提升 > 5% 且统计显著 → 自动扩容
        - CTR下降 > 2% 且统计显著 → 自动回滚
        - 其他情况 → 继续实验
        """
        latest = self._fetch_latest_metrics()
        if not latest:
            return "keep_testing (指标采集中)"

        self.metrics_history.append(latest)

        if latest.sample_size < self.min_sample_size:
            return f"keep_testing (样本 {latest.sample_size} < {self.min_sample_size})"

        ctr_delta = (latest.canary_ctr - latest.stable_ctr) / max(latest.stable_ctr, 0.001)
        logger.info(f"📊 实验评估: CTR变化={ctr_delta:+.2%}, 样本={latest.sample_size}")

        if ctr_delta > self.promote_threshold:
            return self._promote()
        elif ctr_delta < self.rollback_threshold:
            return self._rollback()
        else:
            return "keep_testing"

    def _promote(self) -> str:
        """升级放量"""
        schedule = [5, 10, 30, 50, 100]
        if self.canary_percent >= 100:
            self.status = ExperimentStatus.PROMOTED
            return "experiment_promoted_full"

        current_idx = schedule.index(self.canary_percent) if self.canary_percent in schedule else -1
        next_percent = schedule[current_idx + 1] if current_idx + 1 < len(schedule) else 100
        self.canary_percent = next_percent
        logger.info(f"⬆️ 扩容至 {next_percent}%")
        return f"promote_to_{next_percent}pct"

    def _rollback(self) -> str:
        """自动回滚"""
        logger.warning(f"⚠️ CTR指标恶化，自动回滚")
        self.status = ExperimentStatus.ROLLED_BACK
        self.canary_percent = 0
        return "experiment_rolled_back"

    def _fetch_latest_metrics(self) -> Optional[ExperimentMetrics]:
        """
        从Prometheus拉取实验指标（模拟实现）

        实际应调用PromQL：
        canary_ctr = click_rate_sum{version="canary"} / impression_sum{version="canary"}
        stable_ctr = click_rate_sum{version="stable"} / impression_sum{version="stable"}
        """
        canary_ctr = 0.152 + random.gauss(0, 0.01)
        stable_ctr = 0.148 + random.gauss(0, 0.01)
        sample_size = random.randint(5000, 20000)
        return ExperimentMetrics(
            timestamp=datetime.now(),
            canary_ctr=max(0, canary_ctr),
            stable_ctr=max(0, stable_ctr),
            sample_size=sample_size,
        )


class CanaryScheduler:
    """
    金丝雀实验自动化调度器

    使用方式：
        scheduler = CanaryScheduler()
        exp = CanaryExperiment(...)
        scheduler.register_experiment(exp)
        scheduler.start()
    """

    def __init__(self, check_interval: int = 60):
        self.check_interval = check_interval
        self.experiments: list[CanaryExperiment] = []
        self._running = False
        self._thread: Optional[threading.Thread] = None

    def register_experiment(self, exp: CanaryExperiment):
        self.experiments.append(exp)
        logger.info(f"实验已注册: {exp.experiment_id}")

    def start(self):
        self._running = True
        self._thread = threading.Thread(target=self._run_loop, daemon=True)
        self._thread.start()
        logger.info("金丝雀调度器已启动")

    def stop(self):
        self._running = False
        if self._thread:
            self._thread.join(timeout=5)
        logger.info("金丝雀调度器已停止")

    def _run_loop(self):
        while self._running:
            for exp in self.experiments:
                if exp.status != ExperimentStatus.RUNNING:
                    continue
                try:
                    decision = exp.evaluate_and_decide()
                    logger.info(f"[{exp.experiment_id}] 决策: {decision}, "
                                f"canary流量: {exp.canary_percent}%")
                    if "promoted_full" in decision or "rolled_back" in decision:
                        self._send_notification(exp, decision)
                except Exception as e:
                    logger.error(f"实验 {exp.experiment_id} 评估异常: {e}")
            time.sleep(self.check_interval)

    def _send_notification(self, exp: CanaryExperiment, outcome: str):
        """发送实验结果通知（对接飞书/Slack）"""
        logger.info(f"📢 实验完成通知: {exp.experiment_id} → {outcome}")

## 四、自适应限流：流量剧变时的智能保护

### 固定限流 vs 自适应限流

```
固定限流（传统）：
  - 阈值写死：QPS > 1000 → 限流
  - 问题：白天正常流量1000，夜间只有200，限流太激进
           促销期间流量2000，限流太宽松

自适应限流（推荐）：
  - 动态基线：基于最近5分钟平均QPS动态计算阈值
  - 公式：limit = avg_qps_5min × (1 + tolerance) × auto_adjust_factor
  - 效果：流量高时阈值高，流量低时阈值低，始终留有余量
```

### 自适应限流完整实现

```python
"""
自适应限流器（令牌桶 + 动态阈值 + 分级降级）

核心思想：
- 不设置固定阈值，而是基于当前流量基线动态调整
- 流量突增时快速收紧，流量正常时逐渐放宽
- 分级降级：先限流非核心请求，再限流核心请求
"""
import time
import threading
import logging
import random
from collections import deque
from dataclasses import dataclass, field
from typing import Optional
from enum import Enum

logger = logging.getLogger(__name__)


class LoadLevel(Enum):
    """系统负载等级"""
    NORMAL = "normal"
    WARNING = "warning"       # >70%容量
    CRITICAL = "critical"     # >90%容量
    OVERLOADED = "overloaded" # >100%容量


@dataclass
class RateLimitConfig:
    """限流配置"""
    enabled: bool = True
    base_rate: int = 1000       # 基准QPS
    tolerance: float = 0.2      # 容忍波动20%
    adjustment_factor: float = 0.1  # 每轮调整幅度10%


class AdaptiveRateLimiter:
    """
    自适应限流器

    使用示例：
        limiter = AdaptiveRateLimiter(base_rate=1000)
        limiter.register_priority("recommendation", 1)  # 高优先级
        limiter.register_priority("analytics", 3)      # 低优先级

        if not limiter.allow("recommendation", "user123"):
            return {"error": "rate limited"}, 429
    """

    def __init__(self, config: Optional[RateLimitConfig] = None):
        self.config = config or RateLimitConfig()
        self._lock = threading.Lock()
        self._buckets: dict[str, float] = {}
        self._last_refill = time.time()

        # 动态阈值
        self._current_limit = self.config.base_rate
        self._recent_qps_history = deque(maxlen=300)  # 最近5分钟
        self._rejected_history = deque(maxlen=300)

        # 优先级配置
        self._priority_levels: dict[str, int] = {}  # type → priority (1=最高)
        self._request_counts: dict[str, int] = {}
        self._reject_counts: dict[str, int] = {}

    def register_priority(self, request_type: str, priority: int):
        """注册请求类型优先级（1=最高，数字越大优先级越低）"""
        self._priority_levels[request_type] = priority
        self._buckets[request_type] = self.config.base_rate / len(self._priority_levels)
        self._request_counts[request_type] = 0
        self._reject_counts[request_type] = 0

    def allow(self, request_type: str, user_id: str) -> bool:
        """
        判断是否允许请求通过

        核心逻辑：
        1. 检查当前系统负载等级
        2. 根据负载等级，决定是否消耗令牌
        3. 低优先级请求在高负载时被优先拒绝
        """
        if not self.config.enabled:
            return True

        with self._lock:
            self._refill()
            priority = self._priority_levels.get(request_type, 99)
            bucket = self._buckets.get(request_type, 0.0)
            load_level = self._get_load_level()

            # 高优先级请求始终通过
            if priority == 1:
                self._buckets[request_type] = max(0, bucket - 1)
                self._request_counts[request_type] = self._request_counts.get(request_type, 0) + 1
                return True

            if load_level == LoadLevel.NORMAL:
                allowed = bucket >= 1
                if allowed:
                    self._buckets[request_type] = max(0, bucket - 1)
                else:
                    self._reject_counts[request_type] = self._reject_counts.get(request_type, 0) + 1
                    self._rejected_history.append(time.time())
                self._request_counts[request_type] = self._request_counts.get(request_type, 0) + 1
                return allowed

            elif load_level == LoadLevel.WARNING:
                # 警告负载：低优先级请求50%拒绝
                if priority >= 3 and random.random() < 0.5:
                    self._reject_counts[request_type] = self._reject_counts.get(request_type, 0) + 1
                    self._rejected_history.append(time.time())
                    return False
                self._buckets[request_type] = max(0, bucket - 1)
                self._request_counts[request_type] = self._request_counts.get(request_type, 0) + 1
                return True

            elif load_level in (LoadLevel.CRITICAL, LoadLevel.OVERLOADED):
                # 危急/过载：低优先级直接拒绝，高优先级100%通过
                if priority >= 2:
                    self._reject_counts[request_type] = self._reject_counts.get(request_type, 0) + 1
                    self._rejected_history.append(time.time())
                    return False
                self._buckets[request_type] = max(0, bucket - 1)
                self._request_counts[request_type] = self._request_counts.get(request_type, 0) + 1
                return True

            return True

    def _refill(self):
        """令牌桶补充（动态速率）"""
        now = time.time()
        elapsed = now - self._last_refill
        if elapsed <= 0:
            return

        # 动态计算补充速率
        self._adjust_limit()
        total_rate = self._current_limit

        for req_type in self._priority_levels:
            refill_amount = (total_rate / len(self._priority_levels)) * elapsed
            self._buckets[req_type] = min(
                self._buckets.get(req_type, 0) + refill_amount,
                total_rate / len(self._priority_levels) * 10  # 最大令牌数
            )
        self._last_refill = now

    def _adjust_limit(self):
        """根据最近流量动态调整限流阈值"""
        now = time.time()

        # 计算最近1分钟QPS
        recent_window = [t for t in self._recent_qps_history if now - t < 60]
        if recent_window:
            current_qps = len(recent_window)  # 简化：每秒1个请求
            target_limit = current_qps * (1 + self.config.tolerance)
            # 平滑调整
            self._current_limit = (
                self._current_limit * (1 - self.config.adjustment_factor)
                + target_limit * self.config.adjustment_factor
            )
            self._current_limit = max(self.config.base_rate * 0.5, self._current_limit)

    def _get_load_level(self) -> LoadLevel:
        """根据当前拒绝率判断负载等级"""
        now = time.time()
        recent_rejects = sum(1 for t in self._rejected_history if now - t < 60)
        recent_total = sum(self._request_counts.values())

        if recent_total == 0:
            return LoadLevel.NORMAL

        reject_rate = recent_rejects / max(recent_total, 1)

        if reject_rate > 0.3:
            return LoadLevel.OVERLOADED
        elif reject_rate > 0.1:
            return LoadLevel.CRITICAL
        elif reject_rate > 0.02:
            return LoadLevel.WARNING
        else:
            return LoadLevel.NORMAL

    def record_request(self, request_type: str, is_allowed: bool):
        """记录请求（用于外部指标采集）"""
        with self._lock:
            self._recent_qps_history.append(time.time())
            if not is_allowed:
                self._rejected_history.append(time.time())
                self

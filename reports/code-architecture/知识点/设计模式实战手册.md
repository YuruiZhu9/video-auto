# 设计模式实战手册
> 推荐系统中最常用的 8 种设计模式，从模式识别到代码落地

## 概述

设计模式是前人总结的"高频问题标准解法"。不是为用而用，而是当场景匹配时才用。

**推荐系统中最常用的 8 种模式：**

| 模式 | 一句话说明 | 推荐系统典型场景 |
|------|-----------|----------------|
| 策略模式 | 算法可以切换 | 多路召回、多种排序模型 |
| 工厂模式 | 统一创建对象 | 不同场景推荐服务创建 |
| 观察者模式 | 事件触发通知 | 用户行为 → 刷新缓存/更新画像 |
| 模板方法模式 | 流程固定，部分可变 | 召回路 → 排序路 → 重排路 |
| 装饰器模式 | 动态添加功能 | 推荐结果加解释、加过滤 |
| 代理模式 | 延迟加载/缓存 | 推荐结果缓存、模型推理代理 |
| 建造者模式 | 分步构建复杂对象 | 构建推荐请求/上下文 |
| 责任链模式 | 请求经过多个处理器 | 请求鉴权 → 限流 → 记录 → 处理 |

## 1. 策略模式（Strategy Pattern）

### 核心思想
**定义一系列算法，把它们一个个封装起来，使它们可以互相替换。**

### 问题场景
推荐系统有多路召回：ItemCF、UserCF、Embedding召回、热门召回。每次推荐请求要能动态选择用哪一路或哪几路。

### 反例（坏味道）

```python
# 硬编码 if-else，违反开闭原则
def recommend(user_id: str, strategy: str) -> list:
    if strategy == "item_cf":
        # ItemCF 逻辑 50 行
        results = []
        # ...
        return results
    elif strategy == "user_cf":
        # UserCF 逻辑 50 行
        results = []
        # ...
        return results
    elif strategy == "embedding":
        # Embedding 逻辑 50 行
        results = []
        # ...
        return results
    elif strategy == "hot":
        # 热门召回逻辑 20 行
        results = []
        # ...
        return results
    else:
        raise ValueError(f"Unknown strategy: {strategy}")
```

问题：
- 每加一种召回策略，要改这个函数（违反开闭原则）
- 每个分支50行，函数膨胀到200+
- 无法在运行时动态组合多种策略

### 正例（策略模式）

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import List, Dict

@dataclass
class Item:
    id: str
    score: float


# ============ 1. 定义抽象策略接口 ============
class RecallStrategy(ABC):
    """召回策略抽象接口"""
    
    @abstractmethod
    def name(self) -> str:
        """策略名称，用于日志和监控"""
        pass
    
    @abstractmethod
    def recall(self, user_id: str, count: int, context: dict) -> List[Item]:
        """执行召回，返回候选项"""
        pass
    
    def _log(self, user_id: str, count: int):
        """通用日志方法，所有策略共享"""
        print(f"[{self.name()}] user={user_id}, count={count}")


# ============ 2. 实现具体策略 ============
class ItemCFRecall(RecallStrategy):
    """基于物品的协同过滤召回"""
    
    def name(self) -> str:
        return "item_cf"
    
    def recall(self, user_id: str, count: int, context: dict) -> List[Item]:
        self._log(user_id, count)
        # 真实实现：查询用户最近交互物品 → 找相似物品
        return [Item(id=f"item_cf_{i}", score=0.9 - i * 0.05) for i in range(count)]


class UserCFRecall(RecallStrategy):
    """基于用户的协同过滤召回"""
    
    def name(self) -> str:
        return "user_cf"
    
    def recall(self, user_id: str, count: int, context: dict) -> List[Item]:
        self._log(user_id, count)
        return [Item(id=f"item_ucf_{i}", score=0.85 - i * 0.05) for i in range(count)]


class EmbeddingRecall(RecallStrategy):
    """Embedding 向量召回（ANN）"""
    
    def name(self) -> str:
        return "embedding"
    
    def recall(self, user_id: str, count: int, context: dict) -> List[Item]:
        self._log(user_id, count)
        return [Item(id=f"item_emb_{i}", score=0.95 - i * 0.03) for i in range(count)]


class HotRecall(RecallStrategy):
    """热门物品召回（冷启动兜底）"""
    
    def name(self) -> str:
        return "hot"
    
    def recall(self, user_id: str, count: int, context: dict) -> List[Item]:
        self._log(user_id, count)
        return [Item(id=f"item_hot_{i}", score=1.0 - i * 0.01) for i in range(count)]


# ============ 3. 策略管理器（上下文） ============
class RecallEngine:
    """召回引擎：管理所有召回策略，支持动态组合"""
    
    def __init__(self):
        self._strategies: dict[str, RecallStrategy] = {}
    
    def register(self, strategy: RecallStrategy):
        """注册策略，支持运行时热更新"""
        self._strategies[strategy.name()] = strategy
        print(f"Registered strategy: {strategy.name()}")
    
    def recall(
        self,
        user_id: str,
        strategy_names: List[str],
        count: int = 100,
        context: dict = None
    ) -> List[Item]:
        """执行一路或多路召回，并合并去重"""
        context = context or {}
        all_items: dict[str, Item] = {}
        
        for name in strategy_names:
            if name not in self._strategies:
                print(f"Warning: strategy '{name}' not found, skipping")
                continue
            
            strategy = self._strategies[name]
            items = strategy.recall(user_id, count, context)
            
            # 合并结果，相同 item 取较高分
            for item in items:
                if item.id not in all_items:
                    all_items[item.id] = item
        
        return list(all_items.values())[:count * len(strategy_names)]
    
    def list_strategies(self) -> List[str]:
        """查看所有可用策略"""
        return list(self._strategies.keys())


# ============ 4. 使用示例 ============
# 初始化引擎
engine = RecallEngine()
engine.register(ItemCFRecall())
engine.register(UserCFRecall())
engine.register(EmbeddingRecall())
engine.register(HotRecall())

# 场景1：新用户冷启动，用热门召回
cold_user_results = engine.recall(
    user_id="user_cold_001",
    strategy_names=["hot"],  # 冷启动只有热门
    count=50,
)

# 场景2：活跃用户，多路组合召回
active_user_results = engine.recall(
    user_id="user_active_001",
    strategy_names=["item_cf", "embedding", "hot"],  # 组合多路
    count=100,
)

# 场景3：特定场景，只用某一路
results = engine.recall(
    user_id="user_001",
    strategy_names=["embedding"],
    count=200,
)
```

### 关键优势

| 优势 | 说明 |
|------|------|
| **开闭原则** | 新增策略不修改现有代码，只注册即可 |
| **可测试** | 每个策略独立，可以单独写单元测试 |
| **可观测** | 每个策略有 name，可单独监控效果 |
| **可插拔** | 支持运行时动态切换策略 |
| **组合灵活** | 多路召回 = 注册多个策略 + 合并去重 |

### 面试表达模板

> "我在项目中用策略模式实现了多路召回。定义了一个 RecallStrategy 抽象接口，每种召回算法（ItemCF、UserCF、Embedding、热门）各自实现这个接口。召回引擎统一管理，通过注册机制动态加载。这样新增一路召回不需要改已有代码，只需要实现接口并注册即可，符合开闭原则。"

## 2. 模板方法模式（Template Method Pattern）

### 核心思想
**定义一个算法骨架，将某些步骤延迟到子类中实现。父类控制流程，子类提供具体步骤。**

### 问题场景
推荐系统流程固定：召回 → 过滤 → 排序 → 重排。但每个阶段的具体实现可能不同（粗排 vs 精排）。

### 代码示例

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from typing import List, Dict
import time

@dataclass
class Item:
    id: str
    score: float

@dataclass
class RecommendRequest:
    user_id: str
    scene: str
    count: int
    context: Dict = field(default_factory=dict)

@dataclass
class RecommendResponse:
    items: List[Item]
    trace: Dict[str, float]  # 各阶段耗时


class RecommendationPipeline(ABC):
    """
    推荐流程模板方法
    固定流程：召回 → 过滤 → 排序 → 重排 → 包装
    """
    
    def recommend(self, request: RecommendRequest) -> RecommendResponse:
        trace = {}
        
        # Step 1: 召回（子类实现）
        t0 = time.time()
        candidates = self._recall(request)
        trace["recall_ms"] = (time.time() - t0) * 1000
        
        # Step 2: 过滤（子类实现）
        t0 = time.time()
        filtered = self._filter(request, candidates)
        trace["filter_ms"] = (time.time() - t0) * 1000
        
        # Step 3: 排序（子类实现）
        t0 = time.time()
        ranked = self._rank(request, filtered)
        trace["rank_ms"] = (time.time() - t0) * 1000
        
        # Step 4: 重排（子类实现）
        t0 = time.time()
        reranked = self._rerank(request, ranked)
        trace["rerank_ms"] = (time.time() - t0) * 1000
        
        # Step 5: 包装（通用）
        return self._wrap(request, reranked, trace)
    
    @abstractmethod
    def _recall(self, request: RecommendRequest) -> List[Item]:
        """召回阶段"""
        pass
    
    @abstractmethod
    def _filter(self, request: RecommendRequest, candidates: List[Item]) -> List[Item]:
        """过滤阶段（去重、黑名单、打分过低）"""
        pass
    
    @abstractmethod
    def _rank(self, request: RecommendRequest, candidates: List[Item]) -> List[Item]:
        """排序阶段"""
        pass
    
    def _rerank(self, request: RecommendRequest, ranked: List[Item]) -> List[Item]:
        """重排阶段（多样性、曝光控制）。默认不做处理，子类可覆盖"""
        return ranked[:request.count]
    
    def _wrap(self, request: RecommendRequest, items: List[Item], trace: Dict) -> RecommendResponse:
        """统一包装响应"""
        return RecommendResponse(items=items, trace=trace)


# 具体实现：精排 Pipeline（高精度慢速度）
class FineRankPipeline(RecommendationPipeline):
    
    def _recall(self, request: RecommendRequest) -> List[Item]:
        return [Item(id=f"item_{i}", score=0.9 - i * 0.05) for i in range(200)]
    
    def _filter(self, request: RecommendRequest, candidates: List[Item]) -> List[Item]:
        # 去重 + 黑名单过滤
        return candidates
    
    def _rank(self, request: RecommendRequest, candidates: List[Item]) -> List[Item]:
        # 用精排模型（xDeepFM/DeepFM），P99 > 50ms
        return sorted(candidates, key=lambda x: x.score, reverse=True)
    
    def _rerank(self, request: RecommendRequest, ranked: List[Item]) -> List[Item]:
        # MMR 多样性重排 + 频次控制
        return ranked[:request.count]


# 具体实现：粗排 Pipeline（低精度快速度）
class RoughRankPipeline(RecommendationPipeline):
    
    def _recall(self, request: RecommendRequest) -> List[Item]:
        return [Item(id=f"item_{i}", score=0.7 - i * 0.05) for i in range(500)]
    
    def _filter(self, request: RecommendRequest, candidates: List[Item]) -> List[Item]:
        return candidates
    
    def _rank(self, request: RecommendRequest, candidates: List[Item]) -> List[Item]:
        # 用轻量模型（LR），P99 < 10ms
        return sorted(candidates, key=lambda x: x.score, reverse=True)


# 使用
pipeline = FineRankPipeline() if is_premium_user else RoughRankPipeline()
result = pipeline.recommend(request)
```

**模板方法 vs 策略模式：**

| 模式 | 区别 | 适用场景 |
|------|------|---------|
| 策略模式 | 各算法平等，可自由组合 | 多路召回（ItemCF/Embedding等）|
| 模板方法 | 流程固定，部分步骤可变 | 整体推荐流程（召回→排序→重排）|

## 3. 观察者模式（Observer Pattern）

### 核心思想
**当一个对象状态改变时，自动通知所有依赖它的对象。**

### 问题场景
用户点击商品 → 需要同时更新用户画像、刷新推荐缓存、记录分析数据。如果在点击接口里串行调用，接口延迟高且耦合严重。

### 代码示例

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from datetime import datetime
from typing import List

@dataclass
class UserBehaviorEvent:
    event_type: str          # click / view / purchase / like
    user_id: str
    item_id: str
    timestamp: datetime = field(default_factory=datetime.now)
    extra: dict = field(default_factory=dict)


# ============ 1. 事件总线（Subject） ============
class EventBus:
    """事件总线：管理所有观察者，事件发生时广播"""
    
    _instance = None
    
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
            cls._instance._observers: List['EventObserver'] = []
        return cls._instance
    
    def subscribe(self, observer: 'EventObserver'):
        self._observers.append(observer)
    
    def unsubscribe(self, observer: 'EventObserver'):
        self._observers.remove(observer)
    
    def publish(self, event: UserBehaviorEvent):
        """发布事件，所有订阅者都会收到通知"""
        for observer in self._observers:
            try:
                observer.on_event(event)
            except Exception as e:
                print(f"[EventBus] Observer {observer.name} failed: {e}")


# ============ 2. 抽象观察者（Observer） ============
class EventObserver(ABC):
    
    @property
    @abstractmethod
    def name(self) -> str:
        pass
    
    @abstractmethod
    def on_event(self, event: UserBehaviorEvent):
        pass


# ============ 3. 具体观察者实现 ============
class UserProfileObserver(EventObserver):
    """观察者1：更新用户实时画像"""
    
    @property
    def name(self) -> str:
        return "user_profile"
    
    def on_event(self, event: UserBehaviorEvent):
        if event.event_type == "click":
            print(f"[{self.name}] Updating user {event.user_id} profile: clicked {event.item_id}")


class CacheWarmerObserver(EventObserver):
    """观察者2：预热推荐缓存"""
    
    @property
    def name(self) -> str:
        return "cache_warmer"
    
    def on_event(self, event: UserBehaviorEvent):
        if event.event_type in ("click", "purchase"):
            print(f"[{self.name}] Warming cache for user {event.user_id}")


class AnalyticsObserver(EventObserver):
    """观察者3：数据分析（不阻塞主流程）"""
    
    @property
    def name(self) -> str:
        return "analytics"
    
    def on_event(self, event: UserBehaviorEvent):
        print(f"[{self.name}] Recording event: {event.event_type}")


# ============ 4. 使用示例 ============
bus = EventBus()
bus.subscribe(UserProfileObserver())
bus.subscribe(CacheWarmerObserver())
bus.subscribe(AnalyticsObserver())

# 用户点击时，发布事件
event = UserBehaviorEvent(
    event_type="click",
    user_id="user_001",
    item_id="item_abc",
)
bus.publish(event)
# 输出:
# [user_profile] Updating user user_001 profile: clicked item_abc
# [cache_warmer] Warming cache for user user_001
# [analytics] Recording event: click
```

### 关键优势

- **解耦**：点击接口只发布事件，不关心谁来处理
- **可扩展**：新增观察者只需注册，不改原有代码
- **异步处理**：观察者可以异步执行，不阻塞主流程

### 观察者 vs 消息队列（Kafka）

| 维度 | 观察者模式（同步）| Kafka（异步）|
|------|----------------|-------------|
| 实时性 | 同进程同步调用 | 异步，可能有延迟 |
| 可靠性 | 进程崩溃则丢失 | 消息持久化，可重试 |
| 规模 | 单机/少消费者 | 分布式，多消费者组 |
| 推荐系统应用 | 轻量场景（缓存刷新）| 核心事件流（行为打点）|

## 4. 装饰器模式（Decorator Pattern）

### 核心思想
**动态地给对象添加额外职责，比继承更灵活。**

### 问题场景
推荐结果需要统一处理：去重、加解释、打广告标识。这些功能需要灵活组合，不能写死在一个函数里。

### 代码示例

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import List

@dataclass
class Item:
    id: str
    score: float
    category: str = ""


# ============ 1. 抽象组件（Component） ============
class Recommender(ABC):
    
    @abstractmethod
    def recommend(self, user_id: str, count: int) -> List[Item]:
        pass


# ============ 2. 基础推荐器（Concrete Component） ============
class BaseRecommender(Recommender):
    """基础推荐器：只返回原始推荐结果"""
    
    def recommend(self, user_id: str, count: int) -> List[Item]:
        return [
            Item(id=f"item_{i}", score=0.9 - i * 0.1, category="book")
            for i in range(count)
        ]


# ============ 3. 装饰器基类（Decorator） ============
class RecommenderDecorator(Recommender):
    """推荐器装饰器基类：持有被装饰对象"""
    
    def __init__(self, wrapped: Recommender):
        self._wrapped = wrapped
    
    def recommend(self, user_id: str, count: int) -> List[Item]:
        return self._wrapped.recommend(user_id, count)


# ============ 4. 具体装饰器 ============
class DeduplicationDecorator(RecommenderDecorator):
    """装饰器1：去重过滤"""
    
    def recommend(self, user_id: str, count: int) -> List[Item]:
        results = super().recommend(user_id, count)
        seen_ids = set()
        deduplicated = []
        for item in results:
            if item.id not in seen_ids:
                seen_ids.add(item.id)
                deduplicated.append(item)
        print(f"[Deduplication] {len(results)} → {len(deduplicated)}")
        return deduplicated


class ExplanationDecorator(RecommenderDecorator):
    """装饰器2：添加推荐解释"""
    
    def recommend(self, user_id: str, count: int) -> List[Item]:
        results = super().recommend(user_id, count)
        for item in results:
            item.explanation = f"因为你最近喜欢 {item.category} 类内容"
        return results


class AdsDecorator(RecommenderDecorator):
    """装饰器3：标记广告（必须在最后一位）"""
    
    def recommend(self, user_id: str, count: int) -> List[Item]:
        results = super().recommend(user_id, count)
        if len(results) > 0:
            results[-1] = Item(
                id="ads_001",
                score=results[-1].score,
                category="ads",
            )
        return results


# ============ 5. 使用：灵活组合装饰器 ============
# 组合1：基础 + 去重 + 解释（普通推荐）
with_explanation = ExplanationDecorator(DeduplicationDecorator(BaseRecommender()))

# 组合2：基础 + 去重 + 解释 + 广告标记（商业化推荐）
full_pipeline = AdsDecorator(ExplanationDecorator(DeduplicationDecorator(BaseRecommender())))

results = with_explanation.recommend("user_001", 10)
print(results[0].explanation)  # 因为你最近喜欢 book 类内容
```

## 5. 代理模式（Proxy Pattern）

### 核心思想
**为其他对象提供一种代理，以控制对这个对象的访问。**

### 推荐系统场景
模型推理（P99 50ms）需要加缓存代理；直接暴露模型服务有安全风险需要鉴权代理。

```python
import time
from typing import List, Optional

class ModelPredictor:
    """真实的模型推理服务（可能很慢）"""
    
    def predict(self, user_id: str, item_ids: List[str]) -> List[float]:
        time.sleep(0.05)  # 模拟模型推理延迟 50ms
        return [0.9 - i * 0.05 for i in range(len(item_ids))]


class CachedModelProxy:
    """
    缓存代理：对相同 user_id + item_ids 的请求，直接返回缓存
    """
    
    def __init__(self, real: ModelPredictor, ttl_seconds: int = 60):
        self._real = real
        self._ttl = ttl_seconds
        self._cache: dict = {}
    
    def predict(self, user_id: str, item_ids: List[str]) -> List[float]:
        cache_key = f"{user_id}:{','.join(sorted(item_ids))}"
        
        if cache_key in self._cache:
            scores, expiry = self._cache[cache_key]
            if time.time() < expiry:
                print(f"[CacheProxy] HIT for user={user_id}")
                return scores
        
        print(f"[CacheProxy] MISS for user={user_id}")
        scores = self._real.predict(user_id, item_ids)
        self._cache[cache_key] = (scores, time.time() + self._ttl)
        return scores


# 使用
proxy = CachedModelProxy(ModelPredictor())
scores1 = proxy.predict("user_001", ["item_a", "item_b"])  # MISS
scores2 = proxy.predict("user_001", ["item_a", "item_b"])  # HIT
```

## 6. 建造者模式（Builder Pattern）

### 核心思想
**分步骤构建复杂对象，避免构造函数参数过多。**

### 推荐系统场景
推荐请求包含很多参数：user_id、scene、count、recall_strategies、filter_rules、rank_model、rerank_rules、need_explain、extra_context。

### 代码示例

```python
from dataclasses import dataclass, field
from typing import List, Optional

@dataclass
class RecommendRequest:
    user_id: str
    scene: str
    count: int = 20
    recall_strategies: List[str] = field(default_factory=list)
    rank_model: Optional[str] = None
    need_explain: bool = False
    extra_context: dict = field(default_factory=dict)


class RecommendRequestBuilder:
    """推荐请求建造器"""
    
    def __init__(self, user_id: str, scene: str):
        self._user_id = user_id
        self._scene = scene
        self._count = 20
        self._recall_strategies: List[str] = []
        self._rank_model: Optional[str] = None
        self._need_explain = False
        self._extra_context: dict = {}
    
    def count(self, count: int) -> 'RecommendRequestBuilder':
        self._count = count
        return self
    
    def with_recall_strategies(self, strategies: List[str]) -> 'RecommendRequestBuilder':
        self._recall_strategies = strategies
        return self
    
    def with_rank_model(self, model: str) -> 'RecommendRequestBuilder':
        self._rank_model = model
        return self
    
    def need_explain(self) -> 'RecommendRequestBuilder':
        self._need_explain = True
        return self
    
    def extra_context(self, key: str, value) -> 'RecommendRequestBuilder':
        self._extra_context[key] = value
        return self
    
    def build(self) -> RecommendRequest:
        return RecommendRequest(
            user_id=self._user_id,
            scene=self._scene,
            count=self._count,
            recall_strategies=self._recall_strategies,
            rank_model=self._rank_model,
            need_explain=self._need_explain,
            extra_context=self._extra_context,
        )


# 使用：链式调用，语义清晰
request = (RecommendRequestBuilder("user_001", "home_feed")
    .count(30)
    .with_recall_strategies(["item_cf", "embedding"])
    .with_rank_model("deepfm")
    .need_explain()
    .extra_context("time_of_day", "evening")
    .build())
```

## 7. 责任链模式（Chain of Responsibility）

### 核心思想
**请求经过一系列处理器，每个处理器决定：处理它，或者传给下一个。**

### 推荐系统场景
推荐请求进来，要经过：鉴权 → 限流 → 参数校验 → 缓存查询 → 兜底逻辑。每个环节独立，可插拔。

### 代码示例

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from typing import List, Optional
import time

@dataclass
class RecommendContext:
    user_id: str
    scene: str
    errors: List[str] = field(default_factory=list)
    cached_result: Optional[List[str]] = None


class Handler(ABC):
    
    def __init__(self):
        self._next: Optional[Handler] = None
    
    def set_next(self, handler: 'Handler') -> 'Handler':
        self._next = handler
        return handler
    
    def handle(self, ctx: RecommendContext):
        if self._can_handle(ctx):
            self._process(ctx)
        
        if self._next and not ctx.cached_result:
            self._next.handle(ctx)
    
    @abstractmethod
    def _can_handle(self, ctx: RecommendContext) -> bool:
        pass
    
    @abstractmethod
    def _process(self, ctx: RecommendContext):
        pass


class CacheHandler(Handler):
    """处理器1：缓存查询（命中则短路）"""
    
    def __init__(self, cache: dict):
        super().__init__()
        self._cache = cache
    
    def _can_handle(self, ctx: RecommendContext) -> bool:
        return ctx.user_id in self._cache
    
    def _process(self, ctx: RecommendContext):
        ctx.cached_result = self._cache[ctx.user_id]
        print(f"[Cache] HIT for {ctx.user_id}")


class AuthHandler(Handler):
    """处理器2：JWT 鉴权"""
    
    def _can_handle(self, ctx: RecommendContext) -> bool:
        return True
    
    def _process(self, ctx: RecommendContext):
        if not ctx.user_id:
            ctx.errors.append("Unauthorized")
        print("[Auth] OK")


class RateLimitHandler(Handler):
    """处理器3：限流"""
    
    def __init__(self, limit: int = 100):
        super().__init__()
        self._limit = limit
        self._requests: dict = {}
    
    def _can_handle(self, ctx: RecommendContext) -> bool:
        now = time.time()
        self._requests.setdefault(ctx.user_id, [])
        self._requests[ctx.user_id] = [
            t for t in self._requests[ctx.user_id] if now - t < 60
        ]
        return len(self._requests[ctx.user_id]) < self._limit
    
    def _process(self, ctx: RecommendContext):
        now = time.time()
        self._requests.setdefault(ctx.user_id, []).append(now)
        print(f"[RateLimit] OK for {ctx.user_id}")


class RecommendHandler(Handler):
    """处理器4：实际推荐逻辑"""
    
    def _can_handle(self, ctx: RecommendContext) -> bool:
        return True
    
    def _process(self, ctx: RecommendContext):
        if ctx.cached_result:
            return
        print(f"[Recommend] Computing for {ctx.user_id}")


# 组装责任链（顺序很重要！缓存放最前面）
chain = CacheHandler({"user_001": ["item_a", "item_b"]})
chain.set_next(AuthHandler())
chain.set_next(RateLimitHandler())
chain.set_next(RecommendHandler())

# 执行
ctx = RecommendContext(user_id="user_001", scene="home")
chain.handle(ctx)
# 缓存命中时：Cache → (短路，不继续往下)
# 缓存未命中时：Cache → Auth → RateLimit → Recommend
```

## 8. 工厂模式（Factory Pattern）

### 核心思想
**统一创建对象，封装创建细节，调用方不需要知道具体类名。**

### 推荐系统场景
不同推荐场景（首页 feed、搜索、详情页、频道页）需要不同的推荐服务实例，但调用方希望用统一的接口。

```python
from abc import ABC, abstractmethod
from enum import Enum

class Recommender(ABC):
    
    @abstractmethod
    def recommend(self, user_id: str, count: int) -> list:
        pass


class RecommenderType(Enum):
    HOME_FEED = "home_feed"
    SEARCH_RERANK = "search"
    DETAIL_RELATED = "detail"
    CHANNEL = "channel"
    COLD_START = "cold_start"


class RecommenderFactory:
    """推荐服务工厂：根据场景创建合适的推荐服务"""
    
    _registry: dict = {}
    
    @classmethod
    def register(cls, recommender_type: RecommenderType):
        def decorator(recommender_cls: type):
            cls._registry[recommender_type] = recommender_cls
            return recommender_cls
        return decorator
    
    @classmethod
    def create(cls, recommender_type: RecommenderType) -> Recommender:
        if recommender_type not in cls._registry:
            raise ValueError(f"Unknown: {recommender_type}")
        return cls._registry[recommender_type]()
    
    @classmethod
    def create_by_scene(cls, scene: str) -> Recommender:
        scene_map = {
            "home": RecommenderType.HOME_FEED,
            "search": RecommenderType.SEARCH_RERANK,
            "detail": RecommenderType.DETAIL_RELATED,
            "channel": RecommenderType.CHANNEL,
            "cold": RecommenderType.COLD_START,
        }
        rtype = scene_map.get(scene, RecommenderType.COLD_START)
        return cls.create(rtype)


# 注册具体实现
@RecommenderFactory.register(RecommenderType.HOME_FEED)
class HomeFeedRecommender(Recommender):
    def recommend(self, user_id, count):
        return ["首页推荐items..."]

@RecommenderFactory.register(RecommenderType.SEARCH_RERANK)
class SearchRerankRecommender(Recommender):
    def recommend(self, user_id, count):
        return ["搜索重排items..."]

@RecommenderFactory.register(RecommenderType.COLD_START)
class ColdStartRecommender(Recommender):
    def recommend(self, user_id, count):
        return ["热门兜底items..."]


# 调用方：统一接口，不需要知道具体类
recommender = RecommenderFactory.create_by_scene("home")
results = recommender.recommend("user_001", 20)
```

## 模式选择决策树

```
推荐系统遇到代码组织问题，先问自己：

需要切换算法？
├─ 是 → 多路召回 / 多种排序 → 策略模式
└─ 否 ↓

流程固定，部分步骤不同？
├─ 是 → 召回路→排序→重排流程 → 模板方法模式
└─ 否 ↓

一个变化要触发多个处理？
├─ 是 → 用户点击 → 更新画像+缓存+BI → 观察者模式
└─ 否 ↓

需要给结果动态加功能？
├─ 是 → 去重+解释+广告标记组合 → 装饰器模式
└─ 否 ↓

需要控制访问（缓存/鉴权/懒加载）？
├─ 是 → 模型推理缓存 → 代理模式
└─ 否 ↓

对象创建参数太多/类型复杂？
├─ 是 → 推荐请求构建 → 建造者模式
└─ 否 ↓

请求需要经过多个处理步骤？
├─ 是 → 鉴权→限流→校验→推荐 → 责任链模式
└─ 否 ↓

需要根据场景创建不同服务？
├─ 是 → 首页/搜索/详情页 → 工厂模式
└─ 否

→ 重构现有代码，先理清职责再选模式
```

## 常见误区

| 误区 | 真相 |
|------|------|
| "我要在代码里用上所有23种设计模式" | 过度设计的危害比没有设计更大 |
| "设计模式是必须遵守的规则" | 模式是工具，不是枷锁 |
| "不用模式就不是好代码" | 简单 if-else 能解决问题就用 if-else |
| "一个类必须只用一个模式" | 经常组合使用（工厂+策略、装饰器+代理）|

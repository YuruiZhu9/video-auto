## 一、代码层面的坏味道

### 1. 重复代码（Duplicated Code）

**特征**：同样的逻辑出现在多处

#### 反例
```python
# ❌ 同样的验证逻辑重复3次
def create_user(name, email):
    if not name:
        raise ValueError("姓名不能为空")
    if not email:
        raise ValueError("邮箱不能为空")
    # 创建用户...

def update_user(user_id, name, email):
    if not name:
        raise ValueError("姓名不能为空")
    if not email:
        raise ValueError("邮箱不能为空")
    # 更新用户...

def register_user(name, email, password):
    if not name:
        raise ValueError("姓名不能为空")
    if not email:
        raise ValueError("邮箱不能为空")
    # 注册用户...
```

#### 正例
```python
# ✅ 提取公共验证函数
def validate_user_data(name, email):
    if not name:
        raise ValueError("姓名不能为空")
    if not email:
        raise ValueError("邮箱不能为空")

def create_user(name, email):
    validate_user_data(name, email)
    # 创建用户...

def update_user(user_id, name, email):
    validate_user_data(name, email)
    # 更新用户...

def register_user(name, email, password):
    validate_user_data(name, email)
    # 注册用户...
```

### 2. 过长函数（Long Function）

**特征**：一个函数超过 50 行，或者一个屏幕装不下

#### 反例
```python
# ❌ 一个函数干了所有事
def process_order(order_data):
    # 1. 验证订单数据（30行）
    if not order_data.get('items'):
        raise ValueError("订单没有商品")
    for item in order_data['items']:
        if item.get('quantity') <= 0:
            raise ValueError("商品数量必须大于0")
        if item.get('price') < 0:
            raise ValueError("商品价格不能为负")
    
    # 2. 计算价格（20行）
    subtotal = 0
    for item in order_data['items']:
        subtotal += item['quantity'] * item['price']
    discount = 0
    if subtotal > 1000:
        discount = subtotal * 0.1
    elif subtotal > 500:
        discount = subtotal * 0.05
    tax = (subtotal - discount) * 0.13
    total = subtotal - discount + tax
    
    # 3. 保存订单（15行）
    order = {
        'items': order_data['items'],
        'subtotal': subtotal,
        'discount': discount,
        'tax': tax,
        'total': total,
        'status': 'pending'
    }
    db.orders.insert(order)
    
    # 4. 发送通知（10行）
    email_service.send(order_data['email'], "订单已创建")
    
    # 5. 返回结果
    return order
```

#### 正例
```python
# ✅ 拆分成多个小函数
def process_order(order_data):
    validate_order(order_data)
    order = calculate_order(order_data)
    save_order(order)
    notify_customer(order_data['email'], order)
    return order

def validate_order(order_data):
    if not order_data.get('items'):
        raise ValueError("订单没有商品")
    for item in order_data['items']:
        validate_item(item)

def validate_item(item):
    if item.get('quantity', 0) <= 0:
        raise ValueError("商品数量必须大于0")
    if item.get('price', 0) < 0:
        raise ValueError("商品价格不能为负")

def calculate_order(order_data):
    subtotal = sum(item['quantity'] * item['price'] 
                   for item in order_data['items'])
    discount = calculate_discount(subtotal)
    tax = (subtotal - discount) * 0.13
    return {
        'items': order_data['items'],
        'subtotal': subtotal,
        'discount': discount,
        'tax': tax,
        'total': subtotal - discount + tax,
        'status': 'pending'
    }

def calculate_discount(subtotal):
    if subtotal > 1000:
        return subtotal * 0.1
    elif subtotal > 500:
        return subtotal * 0.05
    return 0
```

### 3. 过大类（Large Class）

**特征**：一个类有太多属性和方法

#### 反例
```python
# ❌ 上帝类，什么都干
class UserManager:
    def create_user(self): pass
    def update_user(self): pass
    def delete_user(self): pass
    def get_user(self): pass
    def list_users(self): pass
    def send_email(self): pass      # 邮件相关
    def send_sms(self): pass         # 短信相关
    def generate_report(self): pass  # 报表相关
    def export_csv(self): pass       # 导出相关
    def import_csv(self): pass       # 导入相关
    def validate_email(self): pass   # 验证相关
    def hash_password(self): pass    # 安全相关
    # ... 一百多个方法
```

#### 正例
```python
# ✅ 拆分成多个专类
class UserService:
    def create_user(self): pass
    def update_user(self): pass
    def delete_user(self): pass
    def get_user(self): pass
    def list_users(self): pass

class NotificationService:
    def send_email(self): pass
    def send_sms(self): pass

class ReportService:
    def generate_report(self): pass
    def export_csv(self): pass
    def import_csv(self): pass

class UserValidator:
    def validate_email(self): pass

class SecurityService:
    def hash_password(self): pass
```

### 4. 参数过多（Long Parameter List）

**特征**：函数有 4 个以上参数

#### 反例
```python
# ❌ 参数爆炸
def create_user(name, email, phone, age, gender, 
                address, city, country, zipcode, 
                preferences, newsletter, language):
    pass

# 调用时：
create_user("张三", "zhangsan@example.com", "13800138000", 
            25, "男", "朝阳区某街道1号", "北京", 
            "中国", "100000", ["足球"], True, "zh-CN")
```

#### 正例
```python
# ✅ 使用数据对象
@dataclass
class UserProfile:
    name: str
    email: str
    phone: str = None
    age: int = None
    gender: str = None
    address: Address = None
    preferences: list = None
    newsletter: bool = True
    language: str = "zh-CN"

def create_user(profile: UserProfile):
    pass

# 调用时：
profile = UserProfile(
    name="张三",
    email="zhangsan@example.com",
    preferences=["足球"]
)
create_user(profile)
```

## 二、架构层面的坏味道

### 5. 循环依赖（Circular Dependency）

**特征**：A 依赖 B，B 依赖 C，C 依赖 A

```
    ┌──────┐     ┌──────┐     ┌──────┐
    │  A   │ ──► │  B   │ ──► │  C   │
    └──┬───┘     └──────┘     └──┬───┘
       │                         │
       └─────────────────────────┘
              循环依赖！
```

**解决方案**：
- 引入中介者（Mediator）
- 依赖注入（Dependency Injection）
- 重构边界

---

### 6. 霰弹式修改（Shotgun Surgery）

**特征**：改一个功能要改多个类

**解决方案**：
- 找出共同的修改原因
- 合并相关类

---

### 7. 特性依恋（Feature Envy）

**特征**：某个类的方法对另一个类比对自己更感兴趣

```python
# ❌ Feature Envy
class Order:
    items = [...]
    customer_name = "张三"
    customer_address = "北京"

class Invoice:
    def print_invoice(self, order):
        # 这个方法更关心 Order 的数据
        print(f"{order.customer_name}")
        print(f"{order.customer_address}")
        for item in order.items:
            print(item)
```

## 四、什么时候该重构

**立即重构**：
- 代码审查时被明确指出问题
- 添加新功能时发现很难扩展
- 修复 Bug 时影响了其他功能

**稍后重构**：
- 项目 deadline 紧迫
- 代码即将废弃
- 没有测试覆盖

**不需要重构**：
- 一次性脚本
- 简单工具
- 重写比重构更便宜

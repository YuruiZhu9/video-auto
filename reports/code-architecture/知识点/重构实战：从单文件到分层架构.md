# 重构实战：从500行单文件到分层架构

> **适用场景**：接手遗留代码、面试现场画架构、想把"能跑的项目"变成"能讲的项目"
> **前置知识**：SOLID 原则（《重构技巧》已覆盖），本文是它们的实战综合运用

---

## 一、典型遗留项目长什么样

拿到一个老项目，通常是这样的：

```
recommend_service/
└── app.py              # 800行，路由/模型/业务/工具全混在一起
```

代码大概是这个味道：

```python
# app.py — 500行的混乱代码（重构前）
from flask import Flask, request, jsonify
import redis, pymysql, json
from datetime import datetime

app = Flask(__name__)

# 全局连接，谁管生命周期？
r = redis.Redis(host='localhost', port=6379, db=0)
conn = pymysql.connect(host='localhost', user='root', password='xxx', database='recommend')

def get_user_info(user_id):
    cursor = conn.cursor()
    cursor.execute(f"SELECT * FROM users WHERE id={user_id}")
    return cursor.fetchone()

def compute_score(user_id, item_id):
    # 一段神秘的评分逻辑，不知道在算什么
    scores = []
    for i in range(10):
        scores.append(float(i) * 0.1)
    return sum(scores) / len(scores)

@app.route("/recommend/<int:user_id>", methods=["GET"])
def recommend(user_id):
    # 1. 参数校验
    if user_id <= 0:
        return jsonify({"error": "无效用户ID"}), 400
    
    # 2. 查用户信息（SQL拼接，危险）
    user = get_user_info(user_id)
    if not user:
        return jsonify({"error": "用户不存在"}), 404
    
    # 3. 查推荐结果（Redis）
    cache_key = f"rec:{user_id}"
    cached = r.get(cache_key)
    if cached:
        return jsonify({"source": "cache", "items": json.loads(cached)})
    
    # 4. 计算推荐（逻辑全塞这里）
    items = []
    for item_id in range(1, 100):
        score = compute_score(user_id, item_id)
        items.append({"item_id": item_id, "score": score})
    
    # 5. 排序取 top10
    items.sort(key=lambda x: x["score"], reverse=True)
    top10 = items[:10]
    
    # 6. 写缓存（硬编码TTL）
    r.setex(cache_key, 1800, json.dumps(top10))
    
    # 7. 记录日志（直接print）
    print(f"[{datetime.now()}] user:{user_id} rec:{len(top10)} items")
    
    return jsonify({"source": "compute", "items": top10})

@app.route("/feedback", methods=["POST"])
def feedback():
    # 又一段业务逻辑，和上面的 recommend 函数结构相似但不完全一样
    data = request.get_json()
    user_id = data.get("user_id")
    item_id = data.get("item_id")
    action = data.get("action")
    
    if not all([user_id, item_id, action]):
        return jsonify({"error": "缺少参数"}), 400
    
    # SQL 拼接（又一处危险操作）
    sql = f"INSERT INTO feedback(user_id, item_id, action, created_at) VALUES({user_id}, {item_id}, '{action}', NOW())"
    cursor = conn.cursor()
    cursor.execute(sql)
    conn.commit()
    
    # 同时更新 Redis 中的计数
    key = f"feedback:{item_id}:{action}"
    r.incr(key)
    
    return jsonify({"message": "ok"})

if __name__ == "__main__":
    app.run(debug=True)
```

**问题清单**（用坏味道术语标注）：

| 问题 | 坏味道 | 风险等级 |
|------|--------|---------|
| SQL 拼接（`f"SELECT * FROM users WHERE id={user_id}"`） | SQL 注入风险 | 🔴 致命 |
| 全局连接 `conn` / `r` 无生命周期管理 | 资源泄漏 | 🔴 高 |
| `compute_score` 逻辑和 Flask 耦合 | 霰弹式修改 | 🔴 高 |
| 所有逻辑在路由函数里 | 上帝函数 / Controller 太胖 | 🔴 高 |
| Redis key 硬编码 `1800` 秒 | 魔法数字 | 🟡 中 |
| `print` 打日志 | 生产环境日志丢失 | 🟡 中 |
| `recommend` 和 `feedback` 部分逻辑重复 | 重复代码 | 🟡 中 |
| `compute_score` 语义不清 | 夸夸其谈的命名 | 🟡 中 |

## 二、重构路线图（渐进式 4 步）

```
Step 1：安全优先 → 先修 SQL 注入 + 资源泄漏
Step 2：提取函数 → 把业务逻辑从路由里捞出来
Step 3：建立分层 → Service + Repository 层
Step 4：引入领域 → Domain 层 + 依赖注入
```

### Step 1：安全优先（不动业务逻辑，先止血）

```python
# ── 重构1：连接管理 ──────────────────────────────────────
# 用 Flask 扩展模式管理连接生命周期
from flask import Flask, g
import redis
import pymysql
from contextlib import contextmanager

app = Flask(__name__)

def get_redis():
    if 'redis' not in g:
        g.redis = redis.Redis(host='localhost', port=6379, db=0)
    return g.redis

@contextmanager
def get_db_cursor():
    """上下文管理器：请求结束自动关闭连接"""
    conn = pymysql.connect(host='localhost', user='root', password='xxx', database='recommend')
    try:
        yield conn.cursor()
        conn.commit()
    finally:
        conn.close()

# ── 重构2：参数化查询（修复 SQL 注入） ─────────────────────
# Before: f"SELECT * FROM users WHERE id={user_id}"
# After:
def get_user_info(user_id: int):
    with get_db_cursor() as cursor:
        cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))
        return cursor.fetchone()

# ── 重构3：统一的错误处理装饰器 ────────────────────────────
from functools import wraps

def handle_errors(f):
    @wraps(f)
    def wrapper(*args, **kwargs):
        try:
            return f(*args, **kwargs)
        except ValueError as e:
            return jsonify({"error": str(e)}), 400
        except Exception as e:
            app.logger.error(f"Unexpected error in {f.__name__}: {e}")
            return jsonify({"error": "内部错误"}), 500
    return wrapper

# ✅ 现在业务逻辑仍然在路由里，但安全和资源问题已修复
@app.route("/recommend/<int:user_id>", methods=["GET"])
@handle_errors
def recommend(user_id):
    if user_id <= 0:
        raise ValueError("无效用户ID")
    # ... 业务逻辑暂时不动 ...
```

**Step 1 成果**：修掉了 SQL 注入和连接泄漏。代码行数基本不变，但安全性提升一个档次。**提交：commit "安全修复：参数化查询 + 连接生命周期管理"**

### Step 2：提取函数（Extract Method）

把路由里的业务逻辑逐段提取为独立函数：

```python
# ── 重构：把业务逻辑从路由提取出来 ─────────────────────────
from dataclasses import dataclass
from typing import List
import json

@dataclass
class RecommendedItem:
    item_id: int
    score: float

class RecommendationService:
    """推荐服务 — 独立于 Flask"""
    
    CACHE_TTL = 1800  # 现在是有名字的常量，不是魔法数字
    
    def __init__(self, redis_client):
        self.redis = redis_client
    
    def get_recommendations(self, user_id: int, top_n: int = 10) -> List[RecommendedItem]:
        """主流程：查缓存 → 计算 → 写缓存"""
        # 1. 查缓存
        cached = self._get_cached(user_id)
        if cached:
            return cached
        
        # 2. 计算推荐
        items = self._compute_recommendations(user_id)
        
        # 3. 写缓存
        self._cache_results(user_id, items)
        
        return items[:top_n]
    
    def _get_cached(self, user_id: int) -> List[RecommendedItem]:
        key = f"rec:{user_id}"
        data = self.redis.get(key)
        if data:
            raw = json.loads(data)
            return [RecommendedItem(item_id=d["item_id"], score=d["score"]) for d in raw]
        return None
    
    def _compute_recommendations(self, user_id: int) -> List[RecommendedItem]:
        """召回+排序算法 — 可以继续拆分"""
        scores = self._calculate_item_scores(user_id)
        items = [RecommendedItem(item_id=i, score=s) for i, s in scores.items()]
        items.sort(key=lambda x: x.score, reverse=True)
        return items
    
    def _calculate_item_scores(self, user_id: int) -> dict:
        """
        计算每个物品的推荐分。
        当前是简单版本；真实场景会引入 Embedding 召回、GBDT 排序等。
        """
        # TODO(下一步): 拆分为 RecallEngine + RankingEngine
        scores = {}
        for item_id in range(1, 100):
            # 简单评分：随机分数（示意）
            scores[item_id] = self._score_single_item(user_id, item_id)
        return scores
    
    def _score_single_item(self, user_id: int, item_id: int) -> float:
        """单个物品评分 — 单一职责，可以单独替换算法"""
        base = item_id % 10 * 0.1
        user_bonus = (user_id % 5) * 0.05
        return round(base + user_bonus, 3)
    
    def _cache_results(self, user_id: int, items: List[RecommendedItem]):
        key = f"rec:{user_id}"
        data = json.dumps([{"item_id": i.item_id, "score": i.score} for i in items])
        self.redis.setex(key, self.CACHE_TTL, data)


class FeedbackService:
    """反馈服务 — 独立于 Flask"""
    
    def __init__(self, redis_client):
        self.redis = redis_client
    
    def record_feedback(self, user_id: int, item_id: int, action: str):
        """记录用户行为反馈"""
        # 写数据库（事务保证）
        with get_db_cursor() as cursor:
            cursor.execute(
                "INSERT INTO feedback(user_id, item_id, action, created_at) VALUES(%s, %s, %s, NOW())",
                (user_id, item_id, action)
            )
        
        # 写 Redis 计数（异步场景可用 Kafka 替代）
        counter_key = f"feedback:{item_id}:{action}"
        self.redis.incr(counter_key)


# ── 路由层现在只负责 HTTP 协议相关的事 ─────────────────────
# 业务逻辑全部下沉到 Service 层
recommend_svc = None  # 待注入

@app.before_request
def inject_services():
    """依赖注入：用 Flask g 对象注入服务实例"""
    from flask import g
    g.recommend_svc = RecommendationService(get_redis())
    g.feedback_svc = FeedbackService(get_redis())

@app.route("/recommend/<int:user_id>", methods=["GET"])
@handle_errors
def recommend(user_id):
    if user_id <= 0:
        raise ValueError("无效用户ID")
    
    items = g.recommend_svc.get_recommendations(user_id)
    
    return jsonify({
        "source": "compute",
        "items": [{"item_id": i.item_id, "score": i.score} for i in items]
    })

@app.route("/feedback", methods=["POST"])
@handle_errors
def feedback():
    data = request.get_json()
    user_id = data.get("user_id")
    item_id = data.get("item_id")
    action = data.get("action")
    
    if not all([user_id, item_id, action]):
        raise ValueError("缺少必要参数")
    
    g.feedback_svc.record_feedback(user_id, item_id, action)
    return jsonify({"message": "ok"})
```

**Step 2 成果**：
- 路由从 60 行瘦到 15 行
- 业务逻辑完全独立于 Flask（可以纯 Python 测试）
- `RecommendationService` 可以单独做单元测试（Mock Redis）
- `CACHE_TTL` 从魔法数字变成有名字的类常量

**提交：commit "提取 Service 层，业务逻辑与 Flask 解耦"**

### Step 3：建立 Repository 层（数据访问抽象）

目前 `get_user_info` 和 `get_db_cursor` 还在路由附近，属于"半独立"。再进一步：

```python
# ── repositories/user_repository.py ──────────────────────
from typing import Optional, List
from dataclasses import dataclass
from datetime import datetime

@dataclass
class User:
    id: int
    username: str
    created_at: datetime

class UserRepository:
    """用户数据访问层 — 抽象了数据库细节"""
    
    def __init__(self, db_connection_factory):
        self._factory = db_connection_factory
    
    def find_by_id(self, user_id: int) -> Optional[User]:
        with self._factory() as cursor:
            cursor.execute("SELECT id, username, created_at FROM users WHERE id = %s", (user_id,))
            row = cursor.fetchone()
            if row:
                return User(id=row[0], username=row[1], created_at=row[2])
            return None
    
    def list_all(self, limit: int = 100) -> List[User]:
        with self._factory() as cursor:
            cursor.execute("SELECT id, username, created_at FROM users LIMIT %s", (limit,))
            return [User(id=r[0], username=r[1], created_at=r[2]) for r in cursor.fetchall()]


# ── repositories/feedback_repository.py ──────────────────
class FeedbackRepository:
    """反馈数据访问层"""
    
    def __init__(self, db_connection_factory):
        self._factory = db_connection_factory
    
    def save(self, user_id: int, item_id: int, action: str):
        with self._factory() as cursor:
            cursor.execute(
                "INSERT INTO feedback(user_id, item_id, action, created_at) VALUES(%s, %s, %s, NOW())",
                (user_id, item_id, action)
            )
    
    def get_user_feedback(self, user_id: int, limit: int = 50) -> List[dict]:
        with self._factory() as cursor:
            cursor.execute(
                "SELECT item_id, action, created_at FROM feedback WHERE user_id = %s ORDER BY created_at DESC LIMIT %s",
                (user_id, limit)
            )
            return [{"item_id": r[0], "action": r[1], "created_at": r[2]} for r in cursor.fetchall()]
```

```python
# ── 重构后的推荐服务（注入 Repository）─────────────────────
class RecommendationService:
    """
    推荐服务现在只依赖接口，不依赖具体实现。
    可以轻松替换 UserRepository 的实现（MySQL → MongoDB → Redis）。
    """
    
    CACHE_TTL = 1800
    
    def __init__(self, redis_client, user_repo: UserRepository):
        self.redis = redis_client
        self.user_repo = user_repo  # 依赖注入，不是硬依赖
    
    def get_recommendations(self, user_id: int, top_n: int = 10) -> List[RecommendedItem]:
        # 1. 验证用户存在
        user = self.user_repo.find_by_id(user_id)
        if not user:
            raise ValueError("用户不存在")
        
        # 2. 后续推荐流程（不变）
        cached = self._get_cached(user_id)
        if cached:
            return cached
        
        items = self._compute_recommendations(user_id)
        self._cache_results(user_id, items)
        return items[:top_n]
    
    # ... 其他方法不变 ...
```

**三层架构现状**：

```
HTTP 层（路由）          ← 只处理请求/响应协议
        ↓
Service 层               ← 业务逻辑（推荐算法/反馈处理）
        ↓
Repository 层            ← 数据访问（SQL/Redis/外部 API）
        ↓
基础设施（MySQL/Redis）   ← Flask 不感知具体技术
```

### Step 4：引入领域层（Domain Layer）— 可选进阶

如果业务继续增长，可以在 Service 层下面再挖一个 Domain 层：

```python
# ── domain/recommendation.py ─────────────────────────────
"""
领域层：业务实体 + 业务规则
这一层完全与框架无关（Flask/SQL/Redis），可以放给算法工程师单独维护
"""

from dataclasses import dataclass, field
from typing import List
from enum import Enum

class RecScoreType(Enum):
    EMBEDDING = "embedding"
    COLD_START = "cold_start"
    POPULAR = "popular"

@dataclass
class RecCandidate:
    """推荐候选物品 — 领域实体"""
    item_id: int
    score: float
    score_type: RecScoreType = RecScoreType.EMBEDDING
    
    def is_trustworthy(self) -> bool:
        """业务规则：embedding 分低于 0.3 的不考虑"""
        return self.score >= 0.3

@dataclass
class RecResult:
    """推荐结果 — 聚合根"""
    user_id: int
    items: List[RecCandidate] = field(default_factory=list)
    source: str = "unknown"  # 'cache' or 'compute'
    
    def diversity_filter(self, max_same_type_ratio: float = 0.7):
        """业务规则：同类物品不超过 70%"""
        if not self.items:
            return
        type_counts = {}
        for item in self.items:
            type_counts[item.score_type] = type_counts.get(item.score_type, 0) + 1
        max_allowed = int(len(self.items) * max_same_type_ratio)
        filtered = []
        type_used = {}
        for item in self.items:
            t = item.score_type
            type_used[t] = type_used.get(t, 0)
            if type_used[t] < max_allowed:
                filtered.append(item)
                type_used[t] += 1
        self.items = filtered
    
    def to_dict(self) -> dict:
        return {
            "user_id": self.user_id,
            "source": self.source,
            "items": [{"item_id": i.item_id, "score": i.score} for i in self.items]
        }


# ── Domain Service ─────────────────────────────────────────
class ScoringDomainService:
    """跨实体的业务规则：评分策略"""
    
    COLD_START_THRESHOLD = 0.2
    POPULAR_BONUS = 0.1
    
    def combine_scores(self, embedding_score: float, popularity_score: float, is_cold_start: bool) -> float:
        """混合评分策略：热用户用 embedding 为主，冷启动用热度补偿"""
        if is_cold_start:
            final = embedding_score * 0.4 + popularity_score * 0.6
        else:
            final = embedding_score * 0.8 + popularity_score * 0.2
        
        # 热度加成
        if popularity_score > 0.8:
            final += self.POPULAR_BONUS
        
        return round(final, 3)
```

**完整四层架构**：

```
┌──────────────────────────────────────────────────────┐
│  Interface Adapters（接口适配层）                      │
│  routes/         ← Flask 路由，Request/Response       │
│  dtos.py         ← 数据传输对象                        │
├──────────────────────────────────────────────────────┤
│  Application（应用层）                                  │
│  services/      ← 用例编排，事务边界                   │
├──────────────────────────────────────────────────────┤
│  Domain（领域层）⭐                                    │
│  entities/       ← 推荐实体（RecCandidate/RecResult） │
│  services/       ← 领域规则（评分/多样性过滤）          │
├──────────────────────────────────────────────────────┤
│  Infrastructure（基础设施层）                           │
│  repositories/   ← MySQL 数据访问                     │
│  cache/          ← Redis 缓存                         │
│  external/       ← 外部 API（Embedding 服务等）        │
└──────────────────────────────────────────────────────┘
         依赖方向：外层 → 内层（永不反向）
```

## 三、重构安全检查清单

每次重构完成后，对照检查：

```
[ ] SQL 注入：所有数据库操作使用参数化查询
[ ] 连接泄漏：所有连接在 with/try-finally 中管理
[ ] 单测覆盖：新增的 Service/Repository 有单元测试
[ ] 日志规范：用 app.logger 而非 print
[ ] 魔法数字：全部替换为命名常量
[ ] 路由干净：路由函数不超过 20 行，不含业务逻辑
[ ] 依赖方向：内层不 import 外层（domain 不 import service）
[ ] 提交粒度：每次重构单独 commit，message 描述改了啥
```

## 五、避坑指南

**Q：什么时候该停在 Step 2/3，不继续到 Step 4？**

A：看项目阶段。Step 4 的 Domain 层适合 3 人以上、长期维护、有算法工程师参与的项目。如果只是一个人快速迭代的小项目，Step 3 的 Service+Repository 已经足够好了。

**Q：重构和重写的边界在哪？**

A：Rule of Thumb：如果改动量超过 50%，考虑重写；如果 20%~50%，渐进重构；20% 以下，直接修。

**Q：如何在重构的同时保证业务不停？**

A：Branch + Feature Flag 策略：
1. 从主分支拉 `refactor/recommend-service`
2. 在新分支上重构
3. 在老代码加 Feature Flag：`if USE_NEW_LOGIC: call_new_service()` 
4. 测试通过后，切换 Flag，上线新逻辑
5. 删除旧代码和 Flag

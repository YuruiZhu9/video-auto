# 代码架构常见误区

## 1. 过度设计

**表现**：小项目用微服务、DDD、各种设计模式

**教训**：
- 项目小、团队小 → 用简单架构
- 不要为了"高大上"而套用复杂模式

**正确做法**：
```
小项目 → 单层/三层架构
中项目 → MVC/SOAP
大项目 → 微服务/DDD
```

---

## 2. 把业务逻辑写在 Controller

**表现**：Controller 几百行代码，全是业务逻辑

**反例**：
```python
@app.route('/order')
def create_order():
    # 验证参数...
    # 计算价格...
    # 查库存...
    # 创建订单...
    # 发短信...
    # 发邮件...
    # 记录日志...
    return jsonify(...)
```

**教训**：Controller 只管接收请求和返回响应，业务逻辑放到 Service 层

---

## 3. 忽略测试

**表现**：不写测试，重构全靠手动验证

**教训**：
- 没有测试 = 随时可能炸
- 重构前先确保有测试覆盖

---

## 4. 过早优化

**表现**：还没开始写代码就先设计扩展性

**教训**：
- 先让代码跑起来
- 等真需要优化时再优化（YAGNI 原则）

---

## 5. 不敢重构

**表现**：觉得能跑的代码不需要改

**教训**：
- 技术债务越滚越大
- 定期重构，保持代码健康

---

## 6. 死记硬背原则

**表现**：为了符合 SOLID 而过度设计

**教训**：
- 原则是为人服务的
- 灵活运用，不要教条

---

## 7. 分层过于死板

**表现**：所有数据都要经过完整的五层架构

**教训**：
- 简单项目可以简化
- 灵活调整，适合最重要

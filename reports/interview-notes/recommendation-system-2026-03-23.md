### 1. 双塔模型（DSSM）工作原理是什么？为何物品塔必须预计算？

**原理：**

双塔模型（也叫 DSSM 双塔）将用户和物品分别用两个独立的深度神经网络编码，输出固定维度的 Embedding 向量：

```
用户塔：User Features → DNN → User Embedding
物品塔：Item Features → DNN → Item Embedding

在线服务：TopK = argmax_{i∈ItemPool} cosine(UserEmb, ItemEmb_i)
```

物品向量可离线提前算好，入库 Faiss/Milvus 等向量索引，支持毫秒级 ANN 检索。

**为何物品塔必须预计算：**

- 候选集规模通常是百万~千万级，若在线实时交叉用户与物品特征，计算量无法承受（延迟要求通常 <50ms）
- 只有 User Tower 和 Item Tower 独立，才能把 Item Embedding 预计算并建好索引，User 侧在线实时推理
- 本质是「空间换时间」：牺牲底层细粒度交叉的精度，换取全库检索效率

**面试加分点：** 提到「双塔内积不经过激活函数」（线性变换），保证相似度计算的单调性。

### 2. 召回阶段负样本怎么选？「曝光未点击」能做负样本吗？

**经典陷阱：** 直接用「曝光未点击」做负样本是严重错误，会被判定为缺乏实战经验。

**三类负样本及其作用：**

| 类型 | 构造方式 | 作用 |
|------|----------|------|
| **随机负采样（Random Negative）** | 从全量物品池中随机采样 | 让模型见识完全不相关的物品，学习全局区分能力 |
| **曝光未点击（Expose Non-Click）** | 上一轮曝光但未点击 | 陷阱陷阱！仅来自精选集，分布偏差大 |
| **困难负样本（Hard Negative）** | 被召回了但未点击 / 高分但业务判定为负 | 强迫模型学习细粒度差异，提升精度 |

**合格回答框架：**
> 召回模型的目标是从海量噪声中区分相关物品，因此负样本分布应逼近全量物品的真实分布。正确做法是引入**随机负采样**（占比通常 >80%），同时用少量**困难负样本**（如 batch 内同批次被点击但本样本未点击的物品）提升区分度。

### 3. 什么是样本选择偏差（SSB）？如何解决？

**定义：**

样本选择偏差（Sample Selection Bias）指训练数据分布与线上推断数据分布不一致，导致模型在训练集上表现好但上线后效果差。

**召回中的 SSB：**

- 模型只在「曝光样本」上训练，但推断需对「全量物品库」打分
- 「曝光未点击」仅代表精选集中的次优品，不代表全库噪声分布
- 结果：模型学到了「精选集中区分好与坏」，而非「海量噪声中找相关」

**解决思路：**

1. **引入随机负采样**，使负样本分布逼近全量物品分布
2. **曝光策略建模**：对数据生成机制建模（如 IPS——逆倾向分数加权）
3. **全链路一致性**：保证训练样本的采样方式与线上推理场景一致

### 4. 多路召回如何融合截断？固定配额为何是错的？

**为何固定配额是错的：**

- 某次请求中向量召回质量极高，用户已看过热门召回内容，固定配额会强行丢弃高质量结果
- 即使某路输出大量长尾噪音，固定配额也会浪费下游计算资源

**融合方案对比：**

| 方案 | 做法 | 缺点 |
|------|------|------|
| **固定配额** | 每路各取固定数量 | ❌ 丢弃高质量、浪费资源 |
| **归一化后加权** | Min-Max 或 Z-Score 归一化到 [0,1]，乘以权重 α | 受异常值影响大 |
| **基于转化率加权** | 离线统计各路 CTR/CVR 作为 α | 需持续维护权重 |
| **轻量模型融合** | LR/GBDT 预测粗排 CTR | 本质升级为「粗排」 |

**兜底策略：** Item ID 去重（取最大分或加权和）；热门/新品队列强插补足。

### 5. 困难负样本（Hard Negative）如何构造？比例多少合适？

**构造方法：**

1. **离线 Batch 内 Hard Neg**：同一训练 Batch 中，被其他用户点击但本用户未点击的物品（跨用户正样本作负）
2. **线上召回 Hard Neg**：线上系统召回了但最终未点击的样本
3. **语义近似 Hard Neg**：类别/标签与正样本相似但用户未交互的物品

**比例建议：**
- 正:负 = 1:1 ~ 1:10
- 其中 Hard Neg 占负样本的 **10%~30%** 为宜
- Hard Neg 过多（占比 >50%）会导致训练不稳定，模型过度关注困难样本而忽略全局

### 6. Wide&Deep 与 DeepFM 本质区别是什么？

| 维度 | Wide & Deep | DeepFM |
|------|-------------|--------|
| **核心结构** | Wide（LR） + Deep（DNN） | FM + Deep（DNN） |
| **特征工程** | 依赖人工构造交叉特征 | 端到端自动学习二阶特征交叉 |
| **低阶交互** | Wide 部分负责记忆（Memorization） | FM 部分通过隐向量内积显式建模 |
| **高阶交互** | Deep 部分负责泛化（Generalization） | Deep 部分通过 MLP 隐式学习 |
| **参数共享** | Wide 和 Deep 的 Embedding 通常不共享 | **FM 和 Deep 共享同一个 Embedding 输入** |

**DeepFM 更优的场景：** 特征维度高、人工难以枚举交叉特征的场景（如电商、海量标签），DeepFM 能端到端发现有效二阶组合。

**Wide&Deep 更优的场景：** 已有人工强特征交叉规则，且部分交叉需要「死记硬背」的业务场景。

---

### 7. DeepFM 中 FM 和 Deep 共享 Embedding 的好处？

**核心好处：防止过拟合、提升泛化能力**

- FM 部分通过**显式二阶交互**（隐向量内积）更新 Embedding
- Deep 部分通过**隐式高阶交互**（MLP 反向传播）更新同一套 Embedding
- 相当于给 Embedding 训练加了**双重监督信号 / 强正则**，避免单任务过拟合
- 如果 Embedding 不共享，两部分各自学各自的，训练不充分时 Embedding 质量差

---

### 8. 为什么排序模型需要 Wide/FM 部分，而不是全部用 DNN？

**DNN 的「过度泛化」问题：**

- Deep 网络倾向于将 Embedding 映射到稠密空间
- 对于**从未出现或极少出现**的特征组合，DNN 可能给出非零预测值（幻觉泛化）
- 但推荐场景中，某些稀疏组合代表**极强的正/负反馈**，需要「死记硬背」
- 例如：用户刚点击过「游戏鼠标」，此时同店的「9.9元鼠标垫」是一个强负反馈信号

**Wide/FM 的价值：**

- Wide（LR）：直接建模显式的乘法交互，无需深层网络即可记住该规则
- FM：通过向量内积高效建模所有二阶组合，效率远高于用深层 ReLU 逼近乘法
- 全 DNN 方案需要极深网络 + 超大规模数据才能达到同等效果

### 9. DIN 的注意力机制是如何工作的？相比 Sum Pooling 好在哪？

**Sum/Average Pooling 的问题：**

- 假设历史每个行为对当前推荐的贡献**等权重**
- 用户点击过「机械键盘」「鼠标垫」「耳机」，推荐「游戏鼠标」时，「机械键盘」权重应该高，「耳机」权重应该接近零
- Sum Pooling 无法区分这些差异，给出的是「泛化兴趣」而非「当前候选激活后的兴趣」

**DIN 的解法：**

```
注意力得分 a(query, key) = softmax(W1·query + W2·key + W3·(query - key))
加权求和：Σ a_i · value_i
```

- **Query** = 当前候选商品特征
- **Key/Value** = 用户历史行为中的商品特征
- 当候选商品是「鼠标」时，「键盘」注意力权重高，「洗面奶」权重接近零
- 同一用户面对不同候选商品，输出不同的用户兴趣向量 → **「千物千面」**

**面试加分：** 提到 DIN 只做局部激活（不改变序列长度），而非全局归一化，适合电商候选集场景。

### 10. 序列超长（10k+）时 DIN 复杂度爆炸，如何解决？SIM 模型原理？

**复杂度问题：**

- DIN：O(历史行为数 × 候选商品数)
- 50 个历史行为 × 1000 个候选 = 50,000 次交互，可接受
- 但 10,000 个历史行为 × 1000 个候选 = 10,000,000 次交互，不可接受

**SIM（Search-based Interest Model）的两阶段解决思路：**

| 阶段 | 方法 | 复杂度 |
|------|------|--------|
| **阶段一：检索** | Hard Search（用 Category/Brand ID 倒排索引）或 Soft Search（向量 ANN 近邻） | O(logN) 或 O(K) |
| **阶段二：激活** | 对检索出的 K 个相关行为做 Attention | O(K × M) |

**具体做法：**
- Hard Search：用商品的 Category ID 建立倒排索引，直接召回同类商品
- Soft Search：训练一个辅助向量索引，ANN 检索与当前候选最相似的历史行为
- 典型配置：K 取 50~200，将 O(N) 降为 O(K)

### 11. ESMM 如何解决 CVR 预估中的 SSB 与数据稀疏（DS）问题？

**两个核心问题：**

| 问题 | 说明 |
|------|------|
| **样本选择偏差（SSB）** | CVR 模型只在「点击」样本上训练，但推断要对「所有曝光」样本打分 |
| **数据稀疏（DS）** | 转化样本（点击→购买）极少，正样本极其稀疏 |

**ESMM 的核心思想：**

不直接训练 CVR（p(z|y,x)），而是利用概率链式法则：

```
p(z,y|x) = p(y|x) × p(z|y,x)
    ↑          ↑         ↑
  CTCVR      CTR       CVR
```

- CTR 任务在全量曝光空间上训练（无 SSB）
- CTCVR 任务也在全量曝光空间上训练（无 SSB）
- CVR 网络共享 CTR 网络的 Embedding 层
- 通过 CTR 的大数据量「带动」CVR Embedding 的充分训练（解决 DS）

**避坑提示：** 不要简单说「ESMM 增加了数据量」，要强调「隐式学习 CVR + 解决 SSB + Embedding 共享解决 DS」。

### 12. MMOE 多任务学习中「跷跷板」现象是什么？如何解决？

**现象描述：**

简单任务（如 CTR 点击率预估）的梯度幅值远大于困难任务（如观看时长、留存），导致共享层参数被简单任务主导，困难任务效果反而下降——就像跷跷板一样，一个上去一个下来。

**解决思路：**

| 方法 | 原理 |
|------|------|
| **Uncertainty Weighting** | 为每个任务学习一个自适应方差参数，方差大的任务权重自动增大 |
| **GradNorm（梯度归一化）** | 将各任务梯度范数归一化到相同量级，强迫网络均衡学习 |
| **PLE（渐进式扩展）** | 显式分离「共享 Expert」和「任务独有 Expert」，避免负迁移 |
| **Loss 动态加权** | 监控各任务训练 loss 曲线，动态调整权重 |

### 13. 推荐列表多样性不足怎么解决？MMR 与 DPP 算法原理？

**问题场景：** 用户点了 iPhone 手机壳，推荐前 10 个全是手机壳 → 信息茧房、体验下降

**解法层级：**

**① 打散策略（规则层）：**

- 滑动窗口（Window=3，保证窗口内不重复类目）
- 分桶 Round-Robin（按类目分桶轮流从各桶取结果）

**② MMR（Maximal Marginal Relevance，边缘相关最大化）：**

$$Score = \lambda \cdot Relevance(u,i) - (1-\lambda) \cdot \max_{j \in Selected} Similarity(i,j)$$

- λ 是调节阀，越小越倾向于探索新类目
- 每步选择「既相关又与已选列表差异最大」的 item
- 缺点：贪心算法，无法保证全局最优

**③ DPP（行列式点过程）：**

- 利用矩阵行列式体积衡量集合多样性
- 保证选出的集合整体多样性最优，而非贪心局部最优
- 适合对多样性要求极高的场景（如 Feed 流、搜索结果）

**业务评估指标：** 除 CTR/CVR 外，关注 ILD（列表内平均距离）、类目覆盖率、惊喜度（Serendipity）。

### 14. 精排模型 P99 延迟超 200ms，SLA 要求 100ms，如何优化？

**优化方向清单：**

| 方向 | 具体手段 |
|------|----------|
| **并发计算** | 召回、特征提取、模型预测并行化（Pipeline 并行） |
| **模型轻量化** | 模型蒸馏（Big Model → Small Model）、结构化剪枝 |
| **推理加速** | TensorRT/ONNX 优化、FP16/INT8 量化 |
| **特征缓存** | Redis 缓存高频用户特征 / 热门物品特征 |
| **超时降级** | 100ms 内未返回则用粗排/简单 LR 结果兜底 |
| **候选集缩减** | 减少粗排输入数量（从 2000→500） |
| **异步化** | 非关键路径异步执行，不阻塞主流程 |

### 15. 离线 AUC 提升显著但上线 A/B 后 CTR 反而下跌，可能原因？

**核心归因分析：**

| 原因 | 说明 |
|------|------|
| **特征穿越** | 使用了当次请求的转化率或序列特征包含「未来信息」 |
| **特征不一致** | 离线用数据仓库清洗，线上用实时流，格式/延迟/缺失不一致（COPC 校验） |
| **样本选择偏差** | 模型在「曝光点击」样本上训练，但在线对海量候选集预测，分布不同 |
| **评估目标不匹配** | AUC 衡量排序能力，但业务关注转化价值（GMV/时长） |
| **短期 CTR 牺牲长期价值** | 过于「标题党」，吸引点击但用户快速流失 |
| **新物品打压** | 排序靠前的新物品在离线测试集少，在线被高估 |

**排查清单（必背）：**

1. **特征一致性校验**：开启 Feature Log，逐条比对离线训练数据与线上
2. **COPC 校验**：PCTR 均值 ≈ 实际 CTR（Calibration of Predicted CTR）
3. **穿越特征排查**：警惕特征重要性异常高的新特征
4. **测试集分布对齐**：检查测试集是否代表线上实际流量

### 16. 什么是特征穿越？如何排查？

**定义：** 训练时模型使用了「不该在预测时获得」的信息，导致离线指标虚高。

**典型案例：**

- 用「当天平均点击率」作为特征（包含当天未来信息）
- 序列特征中，用了「点击时间 > 当前请求时间」的行为
- 上下文特征用了「本次会话的购买转化数」

**排查方法：**

1. 特征重要性分析：警惕排名异常靠前的新特征
2. 时序检查：验证特征时间戳是否严格 ≤ 请求时间戳
3. 离线在线特征分布对比（Feature Drift 检测）
4. 随机替换实验：将新特征置零/随机化，观察离线指标下降幅度

### 17. 用户冷启动和物品冷启动分别怎么处理？

**用户冷启动（新用户无行为）：**

| 阶段 | 方法 |
|------|------|
| 规则层 | 推送全局热门、高点击率内容（万金油内容） |
| 画像映射 | 利用注册信息（年龄/性别/设备/地域）映射到细分人群包 |
| 跨域迁移 | 用同设备上其他 APP 的行为数据（需用户授权） |
| MAB 探索 | UCB/Thompson Sampling 平衡探索与利用 |

**物品冷启动（新物品无交互）：**

| 阶段 | 方法 |
|------|------|
| 内容特征 | 用 NLP/CV 模型提取商品标题/图片向量，Item2Item 找相似高热品 |
| 探索流量池 | 单独开辟 5%~10% 流量专门探索新物品，单独考核 |
| 轻量级排序 | 新物品用规则打分（如 类目点击率 × 质量分）优先曝光 |

**通用原则：** 冷启动阶段愿意**牺牲短期 CTR**换取长期用户留存和生态健康，设置独立评估指标（探索效率、新物品曝光占比）。

### 18. LLM（大模型）能在推荐链路哪些位置落地？

**三大落地点：**

| 位置 | 具体应用 | 可行性 |
|------|----------|--------|
| **内容理解** | 用 LLM 提取非结构化物品描述的语义向量，解决冷启动 | ✅ 高 |
| **推荐理由生成** | 根据用户历史行为 + 推荐物品生成解释话术，提升信任感 | ✅ 中 |
| **数据增强** | 用 LLM 生成 SFT 数据，辅助小模型学习长尾场景 | ✅ 中 |
| **粗排/精排** | 直接用 LLM 对候选品打分 | ❌ 不可行（延迟/成本问题） |

**为何不能直接用 GPT-4 做精排：**

- LLM 推理 TP99 通常在 **秒级**，精排要求毫秒级
- 每次请求对 1000 个候选品逐一推理，成本是传统 ID 模型的数千倍
- LLM 基于语义，无法理解稀疏 ID 特征的协同过滤信号

**正确路径：** LLM 离线做语义理解 → 生成 Dense Embedding 存入向量索引 → 辅助传统召回或作为辅助特征

### 19. 高频基础题：Word2Vec CBOW vs Skip-gram

| 维度 | CBOW | Skip-gram |
|------|------|-----------|
| **结构** | 用上下文预测中心词 | 用中心词预测上下文 |
| **适用场景** | 语料丰富、训练效率优先 | 语料稀少、稀有词/短语学习 |
| **计算复杂度** | O(V)（V=词表） | O(K×V)（K=窗口大小） |
| **对罕见词效果** | 较好（周围词汇聚力强） | 差（中心词信号弱） |
| **训练速度** | 快（多词→一词） | 慢（一词→多词） |

**损失函数：** Skip-gram 通常用 Negative Sampling（负采样），而非原始 Softmax（避免计算全词表归一化）。

**面试追问：** Skip-gram 的计算复杂度是 CBOW 的 K 倍，通常 K=2~10，因此 Skip-gram 训练更慢；但 Skip-gram 对稀有词效果更好，因为每个词都是训练样本。

### 20. 过拟合的发现方法与解决手段？L1 正则化为何能产生稀疏解？

**发现方法：**

- 训练 loss 下降但验证/测试 loss 上升或持平
- 离线指标涨但上线 A/B 效果差
- 交叉验证中不同 fold 表现差异大

**解决手段（按优先级）：**

1. **数据侧**：增加训练数据、数据增强、正负样本均衡
2. **模型侧**：降低模型复杂度（减少层/宽）、Dropout、Early Stopping
3. **正则化**：L1（Lasso）、L2（Ridge）、ElasticNet
4. **特征侧**：特征选择（移除噪声特征）
5. **蒸馏**：大模型压缩为小模型

**L1 产生稀疏解的原因（几何解释）：**

- L1 正则化的约束域是**菱形**（||w||₁ ≤ t）
- L2 正则化的约束域是**圆形**（||w||₂ ≤ t）
- 在高维稀疏空间中，菱形的顶点（某些维度=0）更容易与损失函数等高线相切
- L2 下各维度均匀压缩，无法产生绝对零值；L1 可以直接将不重要特征的权重压到 0

**面试加分：** 提到 L1 的优化问题是次梯度不可导的，实际中用 **近端梯度下降（Proximal GD）** 或 **FISTA** 算法求解（Lasso 的闭式解为软阈值算子）。

### 21. XGBoost 与 GBDT 的核心区别？什么场景下 XGBoost 更优？

| 维度 | GBDT | XGBoost |
|------|------|---------|
| **分裂点搜索** | 贪心枚举（遍历所有特征和取值） | 近似算法 + 二阶导数近似，速度更快 |
| **正则化** | 无显式正则 | L1/L2 正则防止过拟合 |
| **缺失值处理** | 需要人工填充 | 自动学习缺失值最优分裂方向 |
| **子树构建** | 仅用一阶导数 | 同时用一阶+二阶导数（更精确的曲率信息） |
| **工程化** | 单机 | 支持分布式、列块并行、Cache-aware |

**XGBoost 更优的场景：**
- 数据量大、特征维度高（百万级）
- 有缺失值需要自动处理
- 需要防止过拟合（正则项显式可控）
- 训练时间敏感（近似分裂加速）

### 22. LSTM 相比普通 RNN 的优势？Transformer Attention 原理？

**RNN 的梯度消失问题：**

普通 RNN 的隐藏状态依赖序列上所有历史信息，梯度在时间步反向传播时会指数衰减（BPTT 截断问题），导致长距离依赖无法学习。

**LSTM 的三大门机制：**

```
f_t = σ(W_f · [h_{t-1}, x_t] + b_f)   # 遗忘门：决定丢弃哪些旧信息
i_t = σ(W_i · [h_{t-1}, x_t] + b_i)   # 输入门：决定写入哪些新信息
C_t = f_t * C_{t-1} + i_t * tanh(...)  # 候选记忆
h_t = o_t * tanh(C_t)                   # 输出门：决定输出什么
```

- **遗忘门**允许 Cell State 保持长期信息，解决梯度消失
- **输入门**控制新信息的写入节奏
- Cell State 是线性传递路径，梯度几乎无损传播

**Multi-head Attention 原理：**

```
MultiHead(Q,K,V) = Concat(head_1, ..., head_h) · W_O
head_i = Attention(Q·W_i^Q, K·W_i^K, V·W_i^V)
       = softmax(Q·K^T / √d_k) · V
```

- 多头：每个头学习不同的子空间表示，捕捉不同类型的依赖关系（如句法/语义/位置）
- √d_k 缩放因子：防止点积值过大导致 softmax 梯度消失
- 可以并行计算（相比 RNN 的时序依赖），训练效率高

## 四、高频代码手撕题速记

| 题名 | 思路要点 | 时间复杂度 |
|------|----------|-----------|
| 二分查找 | 循环不变量维护，左闭右开或左闭右闭 | O(log N) |
| 有序数组中位数 | 二分答案思想，不能用 O(N) 暴力解 | O(log N) |
| 链表环检测 | 快慢指针（Floyd），相遇后从起点同步走找入口 | O(N) |
| 数组全排列 | 回溯 + visited 标记，交换或标记两种写法 | O(N!×N) |
| 编辑距离 | 二维 DP，状态：dp[i][j] = min(dp[i-1][j]+1, dp[i][j-1]+1, dp[i-1][j-1]+cost) | O(MN) |
| 最大矩形 | 单调栈（类似柱状图最大矩形），暴力 O(N³) 不接受 | O(N) |
| TopK 问题 | 快速选择（QuickSelect）或 partition | O(N) 均摊 |

### Q1：推荐系统的全链路流程是什么？各阶段核心目标？

**答案：**

推荐系统全链路一般分为以下五个阶段：

```
[召回] → [粗排] → [精排] → [多目标混排] → [重排/策略层]
```

| 阶段 | 核心目标 | 候选规模 | 模型特点 |
|------|----------|----------|----------|
| **召回（Retrieval）** | 从亿级候选中快速拉回千级候选 | 百万~亿 | 简单、实时、多路并发 |
| **粗排（Pre-Rank）** | 对召回结果做初步排序，过滤至百级 | 千级 | 轻量模型、承上启下 |
| **精排（Rank）** | 精准排序，选出 Top-K | 百级 | 复杂模型、多特征、高精度 |
| **多目标混排** | 平衡 CTR/CVR/时长/互动等多目标 | 十~百级 | 多任务学习 |
| **重排（Rerank）** | 多样性、频控、业务策略 | 个位数~数十 | 规则+MMR/DPP |

**面试加分点**：可以提到每阶段的样本空间不同（见 Q3），以及为什么需要多路召回（协同过滤/标签/向量检索等并行）。

---

### Q2：召回和精排的差异是什么？为什么排序结果更准？

**答案：**

**核心差异体现在三点：**

| 维度 | 召回 | 精排 |
|------|------|------|
| **模型复杂度** | 轻量（协同过滤、双塔、规则） | 复杂（DeepFM/DIN/Transfomer） |
| **候选规模** | 亿~百万 | 百~千 |
| **特征使用** | 粗粒度（ID类、统计类） | 细粒度（用户行为序列、上下文） |
| **时效性要求** | 高（ms级） | 中（100-200ms） |
| **样本** | 全局负采样 | 曝光+点击/购买样本 |

**为什么精排更准：**
1. **特征更丰富**：精排可以使用用户完整行为序列、上下文特征、物品详细属性；
2. **模型更强**：精排模型更深、能学习特征间高阶交互（如 DIN 的 Attention）；
3. **标签更精确**：精排用曝光+点击/转化标签，而召回负样本多为随机采样，噪声大。

**面试追问**：双塔模型虽然是"召回阶段"，但模型复杂度接近精排，回答时需注意。

### Q3：粗排、精排打分样本空间不一致怎么解决？

**答案（小红书二面真题）：**

**问题本质**：精排模型在粗排返回的样本上训练和打分，但粗排要对全量召回样本打分，导致**曝光分布偏差（Selection Bias）**。

**主流解决方案：**

**① 粗排样本蒸馏（Distillation）**
- 用精排模型对全量召回样本打分，作为软标签（soft label）训练粗排模型；
- 粗排学习精排的排序能力，而非仅依赖粗排自身的硬标签。

**② 全链路联合训练（Joint Training）**
- 粗排和精排模型同时训练，精排梯度反传影响粗排；
- 类似 ESMM 的多任务学习思想，解决样本选择偏差。

**③ 随机流量实验收集无偏数据**
- 小比例流量（如 5%）随机打散，将真正无偏的曝光-点击数据加入训练集；
- 成本高但效果最干净。

**④ 逆倾向加权（IPW）**
- 对精排样本加权：$w_i = \frac{1}{P(\text{exposure}_i)}$，降低曝光过多样本的权重。

### Q4：抖音 vs 小红书推荐系统算法有什么区别？（小红书二面开放题）

**答案（从算法角度结构化对比）：**

**① 内容消费形态差异**
- **抖音**：沉浸式单列短视频，单次刷新一个视频，用户决策快（滑走 vs 停留）；
- **小红书**：信息流多列笔记，用户主动浏览，决策链路相对较长。

**② 推荐算法差异**

| 维度 | 抖音 | 小红书 |
|------|------|--------|
| **核心优化目标** | 完播率、停留时长、关注转化 | 点赞/收藏/评论等互动率 |
| **序列建模重点** | 用户即时兴趣（短期行为主导） | 用户中短期兴趣（图文混合） |
| **多模态融合** | 强依赖视频理解（视觉+音频） | 强依赖图文理解（标题+图片） |
| **内容理解** | 视频帧+音频+文案多模态 | 图文 CLIP 嵌入、标签体系 |
| **重排策略** | 强控频控、相似内容过滤 | 曝光去重、品类分散（瀑布流） |

**③ 展示形式对算法的影响**
- 抖音单列 → 只需预测 Top-1 的 CTR/CVR；
- 小红书多列 → 需预测每条笔记的曝光点击率，曝光位置受其他笔记影响，更复杂。

### Q5：DIN 模型中 Attention 的原理？score 怎么算？

**答案：**

**背景**：DIN（Deep Interest Network）解决的是用户历史行为序列中哪些物品对预测当前物品最相关。

**核心思想**：引入 Attention 机制，对用户历史行为序列加权——与候选物品越相关的历史行为，权重越高。

**Attention Score 计算**（原文做法）：
$$\text{Score}(\text{item}_{candidate}, \text{item}_i) = \mathbf{v}^T \cdot \text{tanh}(\mathbf{W}_1 \cdot \mathbf{e}_{candidate} + \mathbf{W}_2 \cdot \mathbf{e}_i)$$

其中：
- $\mathbf{e}_{candidate}$：候选物品的 embedding
- $\mathbf{e}_i$：用户历史中第 $i$ 个物品的 embedding
- $\mathbf{W}_1, \mathbf{W}_2, \mathbf{v}$：可学习的权重矩阵

**加权求和得到用户兴趣表示**：
$$\mathbf{e}_{user\_interest} = \sum_{i=1}^{N} \alpha_i \cdot \mathbf{e}_i, \quad \alpha_i = \frac{\exp(\text{Score}_i)}{\sum_{j=1}^{N} \exp(\text{Score}_j)}$$

**为什么不用 Softmax 归一化**：原文指出，当用户历史行为很长时，Softmax 会将权重压平；DIN 直接用激活值做加权（无 Softmax），保留强兴趣信号。

**DIN 的其他 Trick**：
- **Dice 激活函数**：替代 PReLU，自适应调节激活点；
- **GAUC 指标**：Group AUC，按用户分组计算 AUC，解决全局 AUC 对用户不均衡不敏感的问题。

### Q6：双塔模型为什么适合召回阶段？

**答案（面试高频，必会）：**

**双塔结构**：
```
用户塔（User Tower）    物品塔（Item Tower）
    ↓                      ↓
用户向量 e_u          物品向量 e_i
    ↓________________________↓
           点积：score = e_u · e_i
```

**为什么适合召回：**
1. **解耦预计算**：物品塔离线计算所有物品向量并存入 ANN 索引（如 FAISS / Milvus），在线服务只计算用户塔，**延迟可控制在 50ms 以内**；
2. **支持亿级候选**：ANN 索引（如 HNSW/ScaNN）可在亚线性时间（$O(\log n)$）内完成近邻检索；
3. **多路召回兼容**：用户塔可与协同过滤、标签召回等并行，结果合并去重；
4. **Serving 简单**：只需向量点积，无需复杂神经网络推理。

**与精排的分工**：双塔做召回（广），精排做排序（深），业界标准范式。

### Q7：多目标学习 MMOE / ESMM 原理？

**答案：**

**① Share-Bottom（硬共享）**
- 所有任务共享底层 DNN 参数，上层各自独立输出；
- 问题：任务间冲突时，共享层被迫折中，导致所有任务效果受损。

**② MMOE（Multi-gate Mixture-of-Experts）**
```
输入 X
    ↓
[Expert_1] [Expert_2] ... [Expert_k]  （各 Expert 是独立的 DNN）
    ↓______↓__________↓____↑
         Gate_k(X) = softmax(W_k · X)
             ↓________________↓
  Task_A 输出   Task_B 输出  Task_C 输出
```
- 每个任务有自己的 Gate 网络（小型 MLP），决定如何组合 K 个 Expert；
- **核心优势**：允许不同任务关注不同的 Expert，缓解任务冲突；
- Google 2018 提出，已广泛用于 YouTube/微信等推荐系统。

**③ ESMM（Entire Space Multi-Task Model）**
- 解决 CVR 任务中**样本选择偏差（SSB）**问题；
- 传统 CVR：只在点击样本上训练，但推理时需对曝光样本打分；
- ESMM 同时学习 CTR 和 CTCVR（点击且转化），利用 $P(\text{CVR}) = \frac{P(\text{CTCVR})}{P(\text{CTR})}$ 的关系，在全曝光空间建模；
- 引入**征券信号迁移（Representation Transfer）**：CTR 和 CVR 共享Embedding 层。

### Q8：LLM 如何处理用户的历史行为序列？

**答案（小红书二面真题）：**

**核心挑战**：用户历史行为序列可能很长（数千条），直接送入 LLM 会超过上下文窗口限制。

**主流方案：**

**① 序列截断 + 压缩**
- 只保留最近 K 个行为（K 由模型窗口大小决定，通常 50-200）；
- 依据：用户最近行为对当前兴趣预测的贡献远大于早期行为（recency bias）。

**② 分层聚合（Hierarchical Aggregation）**
```
[原始行为序列: 1000条]
       ↓ 按时间段聚类
[近期窗口: 50条] + [中期摘要: 压缩向量] + [长期摘要: 压缩向量]
```

**③ 元学习/记忆机制**
- 将历史行为编码为外部记忆向量（如 Memformer 中的记忆模块）；
- 推理时 LLM 通过注意力访问记忆，而非全部塞入上下文。

**④ LLM as Embedding Generator**
- 用 LLM 对用户行为序列生成统一的 embedding（Sentence Embedding）；
- 将 embedding 作为推荐模型的特征输入，而非让 LLM 直接做序列建模。

**⑤ 推荐系统专用 LLM**
- Seal（Sequence Aware Language Model）等专用模型，在预训练时引入行为序列数据；
- 类似 BERT 对文本的处理方式对用户行为做 MLM 预训练。

### Q9：LLM 与推荐系统结合可落地的方案？

**答案（小红书二面真题）：**

**方案一：LLM 做内容理解（商品/内容 Embedding）**
- 用 LLM 提取商品标题、描述的语义 embedding，替代传统的 TF-IDF / BM25；
- 优势：解决长尾商品、语义模糊商品的召回问题；
- 落地：商品文本 → LLM API → 向量化 → 存入 ANN 索引（周期更新，非实时）。

**方案二：LLM 做用户意图理解**
- 用户查询（如"我想买送给父母的礼物"）→ LLM 解析意图 → 映射到商品类别/属性；
- 可提升搜索场景的 query 理解和召回效果。

**方案三：LLM 生成推荐理由/解释**
- 生成式推荐：LLM 直接生成推荐列表和理由（"因为你喜欢XX，所以推荐YY"）；
- 用于推荐系统的可解释性和用户信任度提升。

**方案四：LLM 辅助特征工程**
- 用 LLM 生成特征的描述文本，再对文本做 embedding；
- 如生成"用户A是一位关注健康饮食的25岁女性"，丰富用户画像。

### Q10：LLM 与推荐结合落地的主要问题？

**答案：**

| 问题 | 说明 | 解决思路 |
|------|------|----------|
| **延迟** | 亿级商品/用户实时推理 LLM 不现实 | 离线预计算 + 近线更新 |
| **成本** | LLM API 费用高，并发受限 | 蒸馏小模型 / 缓存热点 |
| **幻觉** | LLM 可能生成错误/不合适推荐 | 约束 prompt + 后验过滤 |

| **评估** | 推荐质量指标（CTR/转化）与 LLM 评估指标不匹配 | 离线+在线联合评估 |

### Q11：过平滑（Over-smoothing）问题是什么？

**答案（美团面经真题）：**

**问题定义**：在图神经网络（GNN）或序列模型中，堆叠多层后，节点的表示会趋于收敛到相同的值，导致节点可区分性下降。

**原因**：每层卷积/聚合操作都相当于对邻居表示做平均，多层后局部信息被稀释。

**缓解方法：**

1. **残差连接（Residual Connection）**：如 GCNII、APPNP，加入原始特征 $H^{(l+1)} = \alpha H^{(0)} + (1-\alpha) \tilde{H}^{(l+1)}$；
2. **Jump Knowledge Network（JK-Net）**：每层输出拼接后再投影；
3. **降低聚合强度**：用 Mean-Pooling 替代 Sum-Pooling；
4. **控制层数**：实际使用 2-4 层而非深层；
5. **正则化**：添加 DropEdge 等随机删除边的策略。

### Q12：Batch Normalization 在训练和测试时的区别？

**答案（美团面经高频题）：**

**训练时**：
- 每个 mini-batch 计算该 batch 的均值 $\mu_B$ 和方差 $\sigma_B^2$；
- 用 running mean/variance 做指数滑动平均累积（momentum 参数控制更新速度）；
- 输出：$\hat{x} = \frac{x - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}} \cdot \gamma + \beta$

**测试/推理时**：
- 使用训练阶段累积的 **running mean** 和 **running variance**（而非当前 batch 的统计量）；
- 原因：测试时通常单样本推理，无法计算 batch 均值/方差。

**常见追问**：
- batch_size=1 时 BN 退化为"实例归一化"，效果变差；
- 训练阶段使用 batch 统计量是为了让 BN 层参与梯度反传（可学习参数 γ、β）。

### Q13：Transformer 位置编码有哪几种？

**答案（美团面经高频题）：**

| 类型 | 代表模型 | 公式/特点 |
|------|----------|-----------|
| **绝对位置编码** | 原始 Transformer | Sinusoidal：$PE_{(pos,2i)} = \sin(\frac{pos}{10000^{2i/d}})$，无需学习 |
| **可学习绝对位置** | BERT、GPT | 随机初始化，端到端学习 |
| **相对位置编码** | Shaw 2018、XLNet | 编码 token 之间的相对距离，而非绝对位置 |
| **旋转位置编码 RoPE** | LLaMA、GLM | 旋转矩阵对 Query/Key 旋转，绝对位置信息融入内积结果 |
| **ALiBi（线性偏置）** | BLOOM、StableLM | 不加位置编码，在 Attention score 上加线性偏置 |
| **Hybrid** | ChatGLM | 结合绝对和相对位置编码 |

**RoPE 为什么 work**：因为 Attention 得分依赖 $q^T k = \|q\| \|k\| \cos(\theta)$，旋转后 $\theta$ 包含相对位置信息，内积天然编码了相对位置。

### Q14：冷启动问题的解决方案？

**答案（高频综合题）：**

**用户冷启动**：
1. **基于属性**：用用户注册信息（年龄、性别、职业）做聚类，继承同类用户的推荐；
2. **Bandit 探索**：LinUCB / Thompson Sampling，在探索和利用间平衡；
3. **跨域迁移**：用户在其他平台的偏好数据迁移（如抖音登录用户用抖音行为）。

**物品冷启动**：
1. **内容特征驱动**：物品塔使用文本/图片/视频 embedding，冷启动时仅依赖内容特征；
2. **探索曝光预算**：新物品上线初期给予固定曝光配额；
3. **EE（Exploit-Explore）机制**：MAB 框架给新物品额外的探索概率。

**系统层面**：
- 知识图谱增强：借助 KG 关系推理新物品的标签/类别；
- 迁移学习：预训练模型提取多模态特征。

### Q15：广告投放一般关注哪些核心指标？

**答案（小红书二面真题）：**

| 指标 | 含义 | 说明 |
|------|------|------|
| **CTR** | 点击率 = 点击 / 曝光 | 衡量创意吸引力 |
| **CVR** | 转化率 = 转化 / 点击 | 衡量落地页质量 |
| **CPM** | 千次曝光成本 = 消耗 / 曝光 × 1000 | 平台侧指标 |
| **CPC** | 单次点击成本 = 消耗 / 点击 | 广告主侧指标 |
| **CPA** | 单次行动成本 = 消耗 / 转化数 | 最终效果指标 |
| **ROI** | 投入产出比 = 收入 / 花费 | 广告主核心诉求 |
| **LTV** | 用户生命周期价值 | 长期价值评估 |
| **留存率** | 次留/7留等 | 用户质量评估 |

**eCPM（预期每千次曝光收益）** 是广告系统核心排序指标：
$$\text{eCPM} = \text{CTR} \times \text{CPC\_bid} \times 1000$$
（竞价广告）或 $\text{eCPM} = P(\text{ctr}) \times P(\text{cvr}) \times \text{bid} \times 1000$（OCPC）。

### Q16：位置偏差（Position Bias）如何校正？

**答案（DataInterview 高频题）：**

**问题**：用户倾向于点击靠前位置的物品，与真实相关性无关，导致模型错误学习。

**训练时校正（Google 方法）**：
将点击概率分解为：
$$P(\text{click} | \text{item}, \text{pos}) = \underbrace{P(\text{examine} | \text{pos})}_{\text{仅依赖位置}} \times \underbrace{P(\text{click} | \text{examine}, \text{item})}_{\text{真实相关性}}$$

训练时将位置作为特征输入，让模型学习分离位置效应；推理时**将位置设为默认值（通常是1）或直接去掉位置特征**，使模型按真实相关性排序。

**在线随机实验**：
- 小比例流量（如 1%）做随机打散实验（Randomized CTR），收集无偏标签；
- 用无偏标签数据做倾向估计（Propensity Estimation）校准。

### Q17：离线指标 Recall@K 和在线指标不一致怎么诊断？

**答案（DataInterview 高频题）：**

**可能原因：**

1. **下游排序层"吸收"了改进**：Recall@K 只关心相关物品是否进入候选集，但不关心排序顺序；若排序层将召回新增的相关物品排到了后面，点击率可能不变。

2. **相关性标签和点击标签不匹配**：离线用人工标注相关性，离线用点击率，可能对"相关但不吸引眼球"的内容标注不一致。

3. **候选集重叠率问题**：新旧召回结果 Top-K 重叠度高，排序层学到的是相似信号。

4. **用户群体差异**：离线评估可能是全局用户，但线上提升集中在某类用户群体。

**诊断方法：**
- 检查新旧候选集 Top-10 的重叠率；
- 按用户群体细分分析；
- 用在线随机流量实验验证；
- 检查离线标签与点击行为的一致性。

### Q18：算法编程题——灯泡问题（小红书二面真题）

**题目**：n 个灯泡初始关闭，第 k 轮反转所有序号为 k 的倍数的灯泡，问 n 轮后有几盏灯亮着？

**思路**：灯泡 $i$ 最终被反转的次数 = $i$ 的约数个数。若约数个数为奇数（完全平方数），灯泡为亮。

**答案**：亮着的灯数量 = $\lfloor \sqrt{n} \rfloor$

**代码实现**：
```python
import math
def count_lights(n):
    return int(math.floor(math.sqrt(n)))
```

**规律**：完全平方数的约数个数为奇数（因为 $i = d^2$，$d$ 与 $n/d$ 相同，不重复计），非完全平方数约数成对出现。

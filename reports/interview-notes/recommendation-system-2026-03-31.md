### R1：双塔模型的结构是怎样的？为什么不能做深层特征交叉？

**参考答案：**

**模型结构：**
双塔模型将推荐系统分为两个独立的塔式网络：
- **用户塔（User Tower）**：输入用户 ID、历史行为序列、人口统计特征等，输出用户向量 `u ∈ ℝ^d`
- **物品塔（Item Tower）**：输入物品 ID、类别、标签、描述等特征，输出物品向量 `i ∈ ℝ^d`
- **相似度计算**：在线 serving 时，通过 `score = dot(u, i)` 或余弦相似度找出 Top-K 物品

```
用户特征 → [User Tower: MLP] → User Embedding
                                    ↘
                                     → Score = User·Item
                                   ↗
物品特征 → [Item Tower: MLP] → Item Embedding
```

**不能做深层特征交叉的原因（面试重点）：**

1. **实时性约束**：召回阶段候选集规模大（百万~千万级），每次请求需要毫秒级响应。深层特征交叉（如 DCN 的 Cross Network）计算复杂度高，无法满足线上 RT 要求。

2. **双塔分离结构天然无法交叉**：用户塔和物品塔在最后 softmax 层之前完全独立，无法建模 `user_i × item_j` 的交互特征。深层交叉需要两侧特征在同一网络中混合。

3. **Serving 效率**：双塔模型的核心优势是**物品向量可离线预计算**（Indexed），仅线上实时计算用户向量，再用 ANN 索引召回。加入特征交叉会破坏这一架构。

**优化思路（面试加分）：**
- 离线：用 Item Tower 批量生成所有物品的 embedding 并建立 HNSW/IVF 索引
- 在线：实时计算 User Embedding，用 ANN（如 Faiss）做 Top-K 召回
- 用户兴趣交叉：可在 User Tower 内对历史行为序列做 Self-Attention（不依赖 Item 侧）

### R2：双塔模型的负采样策略有哪些？各有什么优缺点？

**参考答案：**

| 负采样策略 | 做法 | 优点 | 缺点 |
|-----------|------|------|------|
| **全局随机负采样** | 从全量候选池随机选取负样本 | 简单、无偏 | 容易抽到超级热门物品（假负例），干扰模型 |
| **Batch 内负采样** | 同一 Batch 内，其他样本的正样本作为当前样本的负样本 | 高效、语义接近正样本，区分度更高 | 只利用了 Batch 内样本，多样性受限 |
| **全局按频率负采样** | 按物品出现频率的某个幂次（如 p^0.75）采样 | 打压热门物品，缓解假负例问题 | 实现复杂，分布不均匀 |
| **Hard Negative 采样** | 选取和正样本相似度高但未被交互的物品（Airbnb/YouTube 实践） | 提升模型区分能力，逼近真实分布 | 需要离线挖掘，计算成本高 |
| **Word2Vec 负采样** | 基于 Skip-gram 思想，正样本周围采样负样本 | 适合序列行为数据 | 仅适用于序列类场景 |
| **业务逻辑负采样** | 如电商中加购但未购买、视频看完未点赞等 | 业务语义强，标签更准确 | 需定制化实现 |

**面试高频追问：如何构建 Hard Negative？**  
答：通常基于已有模型打分为正样本高的物品，选取排名 101~500 左右的物品作为 Hard Negative，或结合业务逻辑（如同类目但未交互）构造。

### R3：召回的目的是什么？推荐系统一定需要召回吗？

**参考答案：**

**召回的目的（从三个维度回答）：**

1. **工程维度**：海量候选集（百万~千亿级）的计算量太大，无法全部送入精排。召回将候选集从 N 压缩到 K（K 通常为百~千级别），降低系统延迟。
2. **信息过滤维度**：在语义空间中找到用户可能感兴趣的候选物品，排除绝大多数不相关物品。
3. **多路召回复用**：工业界通常部署多路召回（协同过滤、向量召回、热度召回、地理召回等），各路负责不同语义空间，实现 Diversity + Relevance 的平衡。

**推荐系统一定需要召回吗？（面试深度追问）：**

**答案：不一定，取决于候选池规模。**

- 小规模候选池（<1000）：可以直接精排，跳过召回。
- 中等规模（1000~10万）：可用轻量召回或直接精排。
- 大规模（10万以上）：必须召回，工程上倒排索引和向量索引的耗时是主要瓶颈。

核心论据：推荐系统最大的工程耗时在**倒排索引和向量检索环节**，而非精排算法本身。

### R8：为什么召回阶段通常建模为多分类而非二分类？

**参考答案（面试高频送命题）：**

**建模方式的本质差异：**

| | 二分类 | 多分类（softmax） |
|--|--------|------------------|
| 样本结构 | (user, item) → 点击/未点击 | user → 从 N 个 item 中选 1 个 |
| 负样本数量 | 1 个负样本 | Batch 内 N-1 个负样本 |
| 损失函数 | Binary Cross Entropy | Categorical Cross Entropy |
| 学习目标 | 区分正样本 vs 单个负样本 | 从海量候选中正确选出正样本 |

**为什么召回用多分类：**

1. **模拟真实召回场景**：召回要从百万候选中选出正样本，BCE 只学"正 vs 1个负"，缺乏对海量负样本的区分能力。多分类 softmax 天然对应"从 N 选 1"的场景。

2. **负采样效率高**：Batch softmax 只需计算当前 Batch 内的负样本，无需为每个正样本构造独立负样本，训练效率高。

3. **Exponential Conjugate Prior 近似全量 softmax**：当候选集太大时，用 Noise Contrastive Estimation（NCE）/ Sampled Softmax 近似。

**精排为什么用二分类（BCE）：**
- 候选集小（百~千级），每个样本独立二分类打分，标签只有点击/未点击两类
- 关注的是**打分精度**（AUC），而非从候选集中挑选

### S1：Wide&Deep 中 Wide 部分和 Deep 部分分别学习什么信息？

**参考答案（经典中的经典）：**

```
Wide部分:  [输入: 原始特征 + 交叉特征] → Linear → 输出
              ↕
            联合训练
              ↕
Deep部分:  [输入: Embedding特征] → DNN(多个隐藏层) → 输出
```

**Wide 部分：**
- **学习目标**：记忆（Memorization）—— 记住历史数据中**明确、频繁出现的特征共现模式**
- **特征输入**：原始稀疏特征 + 人工设计的**叉乘特征**（Cross Product Features），如 `user_installed_app × app_category`
- **模型形式**：单层线性模型（等价于 LR），对稀疏特征做 one-hot 后加权求和
- **优势**：能直接记住强特征组合，对稀疏 ID 特征的泛化能力强（参数少，不易过拟合）

**Deep 部分：**
- **学习目标**：泛化（Generalization）—— 发掘**未曾出现过的特征组合的潜在关联**
- **特征输入**：Dense Embedding + 连续特征，经过多层 ReLU 非线性变换
- **优势**：通过低维 Embedding 自动学习稀疏特征的稠密表示，泛化到未交互的 (user, app) 对

**联合训练（Joint Training）vs 联合学习（Ensemble）的区别：**
- 联合训练：Wide 和 Deep 共享 Embedding 层，**端到端同时优化**
- 集成：分别独立训练，最后融合输出
- Wide&Deep 论文强调联合训练使 Deep 层的 Embedding 学到的语义受 Wide 层约束，避免过拟合

**面试追问：Wide 部分为什么用 L1 FTRL 而不是 L2？**
答：L1 FTRL 可以产生稀疏解，自动过滤掉不重要特征，线上 serving 时减少计算量。

### S2：DeepFM 一定优于 Wide&Deep 吗？为什么？

**参考答案（高阶面试题）：**

**DeepFM 的改进：**
DeepFM 用 FM 层替换了 Wide&Deep 中的人工设计 Wide 层，实现了**自动学习二阶特征交叉**：

```
DeepFM:
  FM层:  → [Sparse Features] → FM (一阶 + 二阶交叉) → 输出
             ↘
              → concat → DNN → 输出
  
Wide&Deep:
  Wide层: → [Sparse + Cross Features] → Linear → 输出
             ↘
              → concat → DNN → 输出
```

**DeepFM 不一定优于 Wide&Deep 的场景：**

1. **Wide 部分手工交叉特征效果显著时**：如果工程师已经精心设计了高质量的叉乘特征（基于业务经验），Wide&Deep 的 Wide 部分可能比 FM 自动学习的交叉更精准，此时 Wide&Deep 效果不差。

2. **稀疏特征维度极高时**：FM 的二阶交叉计算复杂度为 O(k·n)，n 很大时计算开销大；Wide&Deep 的 Wide 部分是线性计算，更高效。

3. **浅层数据 + 强先验场景**：当数据量不够大或任务强依赖特定交叉特征时，人工特征的 Wide 部分反而能更好地控制模型。

4. **实时 serving 资源紧张时**：FM 需要额外计算所有特征的二阶交叉，Wide&Deep Wide 部分更轻量。

**DeepFM 优于 Wide&Deep 的场景（大多数工业场景）：**
- 无需人工设计交叉特征，端到端自动学习
- 稀疏 ID 类特征多，自动挖掘潜在关联
- 数据量大，FM 的 O(k·n) 复杂度可接受

**面试结论：** 不一定，要结合数据规模、特征维度、业务场景综合判断。面试时建议回答："DeepFM 在大多数推荐场景中效果更好，但 Wide&Deep 在特定人工特征工程完善的场景下也不差。"

### S5：DIN 模型的 Attention 机制是如何实现的？输入输出是什么？

**参考答案（阿里系高频题）：**

**背景：** 用户历史行为中不同商品对当前候选商品的重要性不同，不能简单 Sum/Average。

**DIN 实现原理：**

```
候选商品 (candidate item):  经过 Embedding → Vi
用户历史商品序列 (behavior list): [V1, V2, ..., Vn] 经过 Embedding → [E1, E2, ..., En]

Attention Score 计算:
  ai = sigmoid(W1·Vi + W2·Ei + W3·(Vi - Ei) + b)
  或者：attention = Activation(Dot(Vi, Ei))

加权求和（weighted sum pooling）:
  Vu_behavior = Σ(ai · Ei) / Σ(ai)   ← 用户行为序列的加权聚合表示
```

**具体步骤：**
1. **候选商品向量** `candidate_emb` 和**历史行为中每个商品向量** `behavior_emb` 做减法、点积运算
2. 拼接后经过全连接层（MLP）+ Sigmoid 激活，输出每个历史商品的**注意力权重**（标量）
3. 用这些权重对历史商品向量做**加权求和**，得到聚合的用户兴趣向量
4. 该向量与候选商品向量一起输入后续 DNN 网络

**输入：** 候选商品 Embedding + 用户历史行为序列 Embedding  
**输出：** 加权聚合后的用户兴趣向量（维度 = embedding_dim）

**DIN vs DIEN 的区别：**
- DIN：使用 Attention 做加权聚合（**静态权重**，每次候选商品不同则权重不同）
- DIEN：在 DIN 基础上引入 **GRU + Attention 序列建模**，捕捉用户兴趣的**动态演化过程**

### M1：ESMM 的核心思想是什么？如何解决 CVR 样本选择偏差（SSB）问题？

**参考答案（多任务学习必考题）：**

**CVR 任务的核心问题——样本选择偏差（SSB）：**

```
用户行为漏斗（Click-Through Rate Flow）:
  曝光(Impression) → 点击(Click) → 转化(Conversion)
       N (全量)         C (点击)        V (转化)
       
传统CVR问题: 只在点击样本上训练，但预测时面向全量曝光样本
→ 训练空间 ≠ 预测空间 → 严重偏差
```

**ESMM（Entire Space Multi-Task Model）解决方案：**

ESMM 引入 CTR 和 CTCVR 两个辅助任务，利用三者的数学关系：

```
CTR: p(click=1 | impression)
CVR: p(conversion=1 | click=1, impression)  ← 真实目标（难以直接学）
CTCVR: p(click=1, conversion=1 | impression) = CTR × CVR

优化目标：同时学习 CTR + CTCVR，通过 CTCVR = CTR × CVR 间接得到 CVR
```

**ESMM 网络结构：**
```
Shared Embedding Layer（共享参数）
    ↓
  ┌───────→ CTR Tower (点击率预估) ──→ sigmoid(CTR)
  │              ↓
  └───────→ CVR Tower (转化率预估) ──→ sigmoid(CVR)
                   ↓
             CTR Tower × CVR Tower = sigmoid(CTCVR)
```

**关键点：**
- **全量曝光样本训练**：ESMM 直接在全量曝光样本上建模，而非仅在点击样本上
- **CTCVR 监督 CVR**：CTCVR 有足够的正负样本（全量曝光→是否同时点击和转化），避免了 CVR 任务正样本极稀疏的问题
- **隐式学习 CVR**：CVR Tower 的输出不是直接监督的（没有 CVR 标签），而是作为 CTCVR = CTR × CVR 的一部分被反向传播优化
- **共享 Embedding**：两个任务共享底层特征表示，提升泛化能力

### M2：MMOE（Multi-gate Mixture-of-Experts）的结构是怎样的？为什么比 Shared Bottom 效果更好？

**参考答案（多任务学习核心）：**

**Shared Bottom 结构的问题：**
所有任务共享同一个底层网络，当任务之间**相关性低或存在冲突**时，Shared Bottom 会被"平均化"，导致每个任务都学不好。

```
Shared Bottom:
  输入 → [Shared Bottom: 共享DNN] → 任务A Tower → TA输出
                                   → 任务B Tower → TB输出
                                   
问题: 当TA和TB目标冲突时，Shared Bottom难以兼顾
```

**MMOE 结构：**
```
输入 → [E1] ──┐
          ├──→ [Gate_k = softmax(Wk·x)] ──→ Σ(gik·Ei) ──→ Task k Tower → output
          ├──→ [E2] ──┤         ↑
  输入 ──→ [E3] ──┘         gate权重（每个任务独立学习）
          ...
          [En]
  其中: gate_k = softmax(Wgk · x), gik = gate_k[i]
```

**核心思想：**
- **n 个 Expert**（多个独立的 DNN）：每个 Expert 负责建模不同方面的知识
- **每个任务有独立的 Gate 网络**：Gate 决定该任务从各个 Expert 中**提取多少信息**
- 任务间差异由 Gate 隔离，任务间共性由共享 Expert 捕捉

**为什么 MMOE 优于 Shared Bottom：**
| | Shared Bottom | MMOE |
|--|-------------|------|
| 任务冲突处理 | 平均化各任务，无法区分 | 每个任务有独立 Gate，自动选择 Expert |
| 任务相关性 | 隐式共享，无法显式控制 | 任务不相关时 Gate 几乎不使用该 Expert |
| 参数量 | 少 | 多（n个Expert + k个Gate） |
| 适用场景 | 任务强相关 | 任务弱相关或冲突 |

**PLE（CGC）是对 MMOE 的进一步改进**：在 MMOE 基础上增加**任务专属 Expert**，避免所有 Expert 被部分任务完全占用。

### F2：推荐系统中如何打压热门商品？

**参考答案（工程实践高频题）：**

**热门商品的问题：**
- 热门商品被高频召回/曝光，导致流量集中、马太效应
- 冷门商品难以获得曝光，生态失衡
- 用户体验单调（推荐多样性下降）

**打压策略：**

**1. 召回层打压**
- 负采样时提升热门商品作为负样本的概率（按 p^0.75 采样）
- 对热门口碑好的商品做降采样（dropping popular items）
- 热门用户在 embedding 上做正则化约束

**2. 排序层打压**
- 在 CTR 分数上乘以一个热度惩罚因子：`score = pCTR × (1 / popularity^α)`
- 或在训练 loss 中对正样本中的热门商品降权

**3. 曝光去重（频次控制）**
- 对同一用户在 N 天内的曝光历史做记录，避免重复推荐
- 用 exploration-exploitation 机制（UCB/汤普森采样）增加冷门商品曝光

**4. 业务规则**
- 强制插队：将新商品、冷门商品按比例插入推荐列表
- 多样性约束：排序结果中同类别商品不超过一定比例

**5. 论文实践（Airbnb）：**
- 将热门口的 "listing" 作为 Hard Negative 加入训练
- 在 Loss 中对热门正样本做下采样

### F4：推荐系统冷启动问题有哪些解决方案？

**参考答案（面试必答题）：**

**三类冷启动问题：**
1. **用户冷启动**：新用户无历史行为
2. **物品冷启动**：新商品入库，未被曝光
3. **系统冷启动**：推荐系统刚上线，无任何数据

**解决方案（按层面分类）：**

**① 数据层面**
- **热门榜单填充**：新用户/新物品用全局热榜兜底
- **跨域协同**：利用用户在另一平台（如新闻 App）的行为数据辅助
- **小样本学习**：Few-shot / Meta-learning（如 MAML）快速适配新用户

**② 特征层面**
- **先验特征注入**：新用户用性别/年龄/地区等人口统计特征做预测
- **迁移学习**：用成熟品类的模型做预训练，冷启动时微调
- **内容特征替代行为特征**：新物品用商品描述/类目/图片等 Content-based 特征

**③ 模型层面**
- **Explore-Exploit**：新商品给予一定的随机曝光预算（Upper Confidence Bound）
- **EE 策略**：UCB、Thompson Sampling、Boltzmann Exploration
- **聚类推荐**：将新用户归类到相似用户群，用群组统计行为做推荐

**④ 业务流程层面**
- **引导问卷**：新用户注册时收集兴趣偏好（Netflix 早期策略）
- **新手引导**：设计试探性内容列表，主动收集反馈
- **专家规则兜底**：规则引擎在模型不足时提供基础覆盖

## 四、面试技巧提示

### 📋 答题框架（STAR + 结构化）

| 题目类型 | 推荐框架 | 要点 |
|----------|----------|------|
| 算法原理 | **原理 → 结构/公式 → 优缺点 → 应用场景** | 画结构图、说核心公式 |
| 对比题 | **相同点 → 不同点 → 各自适用场景 → 结论** | 不能只说"XX 更强"，要讲清原因 |
| 工程题 | **背景 → 方案 → 踩坑点 → 优化方向** | 结合工业实践，有落地感 |
| 场景设计 | **需求拆解 → 模块设计 → 评估指标 → 迭代计划** | 结构化思维，不要一上来给答案 |

### ⚠️ 避坑提醒

1. **双塔模型"不能做特征交叉"**——这是面试高频挖坑题，一定要答"不能做 user-item 交叉"，而不是"不能做特征交叉"（用户塔内可以）
2. **ESMM 的 SSB 问题**——一定要说清楚"训练在曝光样本，预测也在曝光样本"，很多同学只背"点击样本训练"导致不准确
3. **MMOE vs Shared Bottom**——核心差异是"任务冲突处理机制"，不是"参数更多所以更好"

### 1. 推荐/搜索/广告系统的核心区别是什么？

**核心区别体现在触发方式、业务目标和技术侧重三个维度：**

| 维度 | 推荐系统 | 搜索系统 | 广告系统 |
|------|----------|----------|----------|
| **触发方式** | 被动触发，用户无明确意图 | 主动触发，用户输入 query | 被动触发，夹杂在内容中 |
| **业务目标** | 提升用户留存、时长、DAU | 快速满足用户信息需求 | 最大化商业收入（ECPM） |
| **技术侧重** | 长期兴趣建模、协同信号 | query 理解、语义匹配 | 排序 + 出价联合优化 |
| **内容来源** | 全量物品池 | query 相关文档 | 广告主提交的物料 |
| **反馈周期** | 短期 + 长期交织 | 即时满足 | 短期转化为主 |

**面试加分点：** 能说出"广告是推荐+搜索的交集，同时受商业约束"的总结性观点。

### 2. 推荐系统全链路包含哪些阶段？各阶段的作用与特点？

**标准链路：召回（Recall）→ 粗排（Pre-Rank）→ 精排（Rank）→ 重排（Re-Rank）**

#### 召回（Recall）
- **作用：** 从百万/千万级物品池中快速筛选出千级候选集（通常 500~2000）
- **特点：** 多路并行，速度优先，模型简单（双塔、CF、图模型等）
- **核心指标：** HitRate、MRR、Recall@K

#### 粗排（Pre-Rank）
- **作用：** 在召回的候选集上做初步排序，筛选到百级（如 300~500）
- **特点：** 精度比召回高，比精排快；常使用轻量级深度模型或蒸馏模型
- **技术：** 小型 DeepFM、GBDT，或用精排模型蒸馏

#### 精排（Rank）
- **作用：** 精细化排序，综合用户、物品、上下文特征预测 CTR/CVR
- **特点：** 模型最复杂，特征最丰富；通常毫秒级延迟
- **代表模型：** DeepFM、DIN、DIEN、MMoE 等

#### 重排（Re-Rank）
- **作用：** 结合业务规则（多样性、频控、新物品扶持）做最终调整
- **特点：** 注重用户体验、长期生态；可能引入 MMR、DPP 等算法
- **考量因素：** 物品类别多样性、同一商家/作者去重、实时性

### 3. 多路召回有哪些常见策略？如何融合多路召回结果？

#### 常见召回策略

| 召回类型 | 代表算法 | 特点 |
|----------|----------|------|
| 协同过滤 | UCF、ICF、Swing | 简单高效，冷启难 |
| 向量召回 | DSSM（双塔） | 语义匹配，支持深度学习 |
| 图召回 | Node2Vec、GraphSAGE | 挖掘高阶关系 |
| 热度召回 | 热门/新物品 | 兜底，保证覆盖率 |
| 地域/标签召回 | 规则 | 强先验，快速 |
| 深度匹配召回 | DSSM、BERT4Rec | 语义理解更强 |

#### 多路融合方法

1. **直接 concat + 去重：** 各路结果拼接后去重，简单粗暴
2. **分数加权融合：** 每路有自己的分数，归一化后加权求和
3. **倒序 Merge（蛇形 merge）：** 依次从各路取一个 item，保证多样性
4. **Learn to Rank 融合：** 用模型学习各路权重（如 GBDT 融分）

### 4. 粗排和精排的区别是什么？为什么需要粗排？

| 对比维度 | 粗排 | 精排 |
|----------|------|------|
| **候选集规模** | 千级（如 500~2000） | 百级（如 300~500） |
| **模型复杂度** | 轻量（GBDT 或小 DNN） | 复杂（多目标、多塔） |
| **特征丰富度** | 粗粒度特征为主 | 全量特征，含序列、交叉 |
| **延迟要求** | 毫秒级（~5ms） | 毫秒级（~10-20ms） |
| **计算资源** | 中等 | 大量 |

**为什么需要粗排？**
- 精排模型太重，直接对全量候选打分成本高（万级→百万级物品 × 精排 = 不可行）
- 粗排承上启下，在召回和精排之间做缓冲，节省精排算力
- 粗排可以用精排模型的蒸馏版，保持效果传递

### 5. 双塔模型的原理是什么？有哪些改进方向？

#### 双塔模型原理

双塔模型（Two-Tower Model）是召回阶段最核心的向量检索模型，由 Google 在 2019 年提出（DSSM 双塔变体）。

**结构：**
```
用户塔（User Tower）  →  User Embedding
                                    →  cosine similarity → TopK 召回
物品塔（Item Tower）  →  Item Embedding
```

- **用户塔：** 输入用户特征（行为序列、用户画像、上下文），输出用户向量
- **物品塔：** 输入物品特征（ID、类目、标签），输出物品向量
- 训练时用正负样本对，通过对比损失（如 in-batch softmax）优化
- 推理时物品向量提前计算并索引（FAISS/Milvus），用户向量实时计算后 ANN 检索

**核心优势：** 用户塔和物品塔**完全解耦**，物品向量离线计算，线上只需算用户向量 + ANN 检索，延迟极低。

#### 改进方向

1. **对立式双塔（Contrastive Dual Tower）：** 引入对比学习增强表示
2. **加入序列建模：** 用户塔用 DIN/Transformer 对行为序列建模（代替简单 Pooling）
3. **多兴趣塔：** 用 CapsuleNetwork 或 MIND 抽取用户多个兴趣向量
4. **在线 Hard Negative 挖掘：** 动态构造更难的负样本提升区分度
5. **知识蒸馏：** 用精排模型指导双塔训练

### 6. 召回阶段如何构造负样本？为什么不能用曝光未点击作为负样本？

#### 负样本构造方法

| 方法 | 做法 | 优缺点 |
|------|------|--------|
| **全局随机负采样** | 从全量物品中随机采样 | 简单，但太简单（item 太热门容易被采样到） |
| **曝光但未点击（曝光负采样）** | 用曝光日志中的未点击item做负样本 | **问题：存在 popularity bias** |
| **Batch 内负采样** | 同 batch 内其他用户的正样本作为当前用户的负样本 | 高效，广泛使用 |
| **Hard Negative 挖掘** | 选和正样本相似但不是正样本的 item | 提升模型区分能力 |
| **Hard Positive** | 选和正样本相似度高的 item | 增强正样本信号 |

#### 为什么曝光未点击不能直接做负样本？

**核心问题：数据选择偏差（Sample Selection Bias）**

1. **热门物品偏差：** 曝光数据本身是上一个推荐系统产出的，热门物品曝光多，冷门物品曝光少甚至没有曝光。用曝光未点击做负样本会导致模型过度打压热门物品，忽视真正不相关的物品
2. **隐式反馈噪声：** "曝光未点击"≠"用户不喜欢"，可能是用户根本没看到（位置因素）、网络原因、或仅因为曝光队列本身就带有偏
3. **分布不匹配：** 召回模型学的是"被曝光且未点击"vs"点击"的分布，但实际召回时面对的是全量物品，分布不匹配导致召回偏差

**正确做法：** 使用**随机负采样 + 热度降权**，或结合曝光日志进行曝光纠偏（如 IPW — Inverse Propensity Weighting）。

### 7. ItemCF 与 UserCF 的区别与适用场景？

| 维度 | ItemCF | UserCF |
|------|--------|--------|
| **相似度计算对象** | 物品之间的相似度 | 用户之间的相似度 |
| **核心思想** | "喜欢物品 A 的人，也喜欢物品 B" | "和你相似的用户也喜欢物品 C" |
| **适用场景** | 电商（物品稳定，用户多） | 新闻/社交（用户不稳定，物品新） |
| **优点** | 稳定（物品相似度更稳定） | 新物品冷启动好（可利用相似用户） |
| **缺点** | 冷启动难（物品少时相似度不准） | 用户量大时计算开销大 |
| **可解释性** | 强（"和您看过的 X 相似"） | 一般 |

**面试加分：** 能说出 ItemCF 是工业界最广泛使用的协同过滤方案，如抖音、淘宝的"相似推荐"均基于 ItemCF。

### 8. Swing 模型的核心思想？

Swing 模型是阿里提出的图协同过滤模型，发表在 SIGIR 2021，是 ItemCF 的升级版。

**核心思想：** 当两个用户同时喜欢两个物品（形成 u-i-u-i 四角结构）时，这两个物品的相似度更高——比普通 ItemCF 更能捕捉高阶协同信号。

**公式：**
```
sim(i, j) = Σ_{u,v} 1 / (1 + |I_u ∩ I_v|) 
            其中 u,v 是同时喜欢 i 和 j 的用户
```

**直观理解：** 如果有越多"摇摆用户"（swing users）同时喜欢物品 i 和 j，且这些用户本身重叠度低，说明 i 和 j 的相似信号越强。

**为什么更好：** 避免了"超级活跃用户"（买了很多东西的用户）对相似度的过度影响，普通 ItemCF 中一个用户买了 100 个物品会导致大量虚假相似度。

### 9. 热度纠偏（Popularity Debiasing）在召回中的作用？

**问题：** 推荐系统天然存在马太效应——热门物品被高频曝光和点击，模型会过度推荐热门物品，冷门物品难以获得曝光，形成"信息茧房"。

**热度纠偏的常用方法：**

1. **热度降权（Popularity Penalty）：** 在召回分数上乘以 `1 / log(1 + popularity(i))`，降低热门物品的优势
2. **热度截断：** 每个用户最多从热门召回中取 Top-K，其余留给其他召回路
3. **DAN（Discovery-Aware Network）：** 在模型中建模用户对热门/非热门物品的偏好差异
4. **因果推断方法：** 将曝光热度作为混淆变量，通过因果图解耦"真实偏好"和"热度偏差"

**面试重点：** 能说出"热度纠偏的核心是解耦'用户真的喜欢'和'物品被推荐得多'"。

### 10. Wide&Deep 和 DeepFM 的模型细节与区别？

#### Wide&Deep（Google, 2016）

**结构：**
```
Wide侧： 特征交叉（LR） → 直接记忆（memorization）
                ↕（shared input）
Deep侧： Embedding → DNN → 泛化（generalization）
```

**核心思想：** Wide 侧负责**记忆**（记住历史数据中的频繁共现模式），Deep 侧负责**泛化**（学习深层特征组合）。

**缺点：** Wide 侧需要人工设计特征交叉，依赖专家经验。

#### DeepFM（华为 + 哈工大, 2017）

**结构：**
```
FM组件（二阶特征交叉）→ 共享输入 → DNN → 输出
```

**核心创新：** 用 FM 替代 Wide 侧，自动学习低阶二阶特征交叉，无需人工特征工程；DNN 负责高阶交叉。

#### 关键区别

| 维度 | Wide&Deep | DeepFM |
|------|-----------|--------|
| 低阶交叉 | 需人工 Wide 特征 | FM 自动二阶交叉 |
| 特征工程 | 需要 | 不需要 |
| 表达能力 | 依赖 Wide 侧设计 | 更统一、端到端 |
| 参数量 | Wide 侧可能很大 | 更紧凑 |

### 11. DeepFM 中 FM 组件的作用是什么？二阶交叉的计算复杂度？

#### FM 组件的作用

FM（Factorization Machine）负责**低阶二阶特征交叉**，捕捉成对特征之间的关联关系。

**FM 公式：**
```
y_FM = Σ w_i * x_i + Σ_{i<j} <V_i, V_j> * x_i * x_j
```

其中 `<V_i, V_j>` 是两个 embedding 向量的点积。

**计算第二项时，使用公式变换优化：**
```
Σ_{i<j} <V_i, V_j> * x_i * x_j = 1/2 * [ (Σ V_i * x_i)^2 - Σ (V_i^2 * x_i^2) ]
```

#### 计算复杂度

- **朴素实现：** O(k × n²)，n 是特征数，k 是 embedding 维度
- **公式优化后：** O(k × n)，从二次方降为线性

这使得 FM 可以在高维稀疏特征下高效运行——这是其在推荐系统大放异彩的核心原因。

### 12. DIN 模型的核心原理？Activation Unit 如何计算？

#### DIN（Deep Interest Network, 阿里, 2018）

**核心创新：** 引入**注意力机制**，根据目标物品动态激活用户历史行为，生成个性化兴趣表示。

**背景痛点：** YouTube DNN 等早期模型对所有历史行为做 SUM Pooling，无法区分哪些行为与当前目标相关。

#### Activation Unit 计算过程

```
输入：
  - target_item_emb: [B, D]    目标物品 embedding
  - hist_embs: [B, L, D]        用户历史行为序列 embedding（L=序列长度）

计算步骤：
1. 拼接三个向量：
   concat = [target_emb, hist_emb, target_emb ⊙ hist_emb]   # [B, L, 3D]
   
2. 全连接层压缩：
   hidden = ReLU(W1 * concat + b1)                          # [B, L, H]
   
3. 输出注意力权重（单个值）：
   attention = sigmoid(W2 * hidden + b2)                     # [B, L, 1]
   
4. 归一化：
   attention = softmax(attention, dim=1)                    # [B, L, 1]
   
5. 加权求和：
   interest = Σ(attention_i * hist_emb_i)                   # [B, D]
```

**关键点：** DIN 不关心行为的时间顺序或绝对位置，只关心**语义相关性**。注意力权重由模型端到端学习。

### 13. DIEN 的创新点是什么？GRU+Attention 如何建模兴趣演化？

#### DIEN（Deep Interest Evolution Network, 阿里, 2019）

**两个核心创新：**

**① 兴趣抽取层（Interest Extractor Layer）**
- 使用**GRU**（Gated Recurrent Unit）对用户行为序列建模
- 从用户行为序列中提取"隐状态"作为兴趣表示
- 使用辅助损失（Auxiliary Loss）：让每一步GRU的隐状态能够预测下一个点击的物品，增强兴趣表示的学习

**② 兴趣演化层（Interest Evolution Layer）**
- 在兴趣抽取层输出的兴趣序列上，再叠加一层 GRU + **Attention**（AUGRU）
- 目标商品的兴趣向量作为 query，历史兴趣作为 key/value
- Attention 权重动态调整演化过程中的信息保留程度

**DIEN vs DIN：**
- DIN 只建模"当前兴趣"，不建模"兴趣如何演化"
- DIEN 额外建模了**时间维度上的兴趣变化趋势**（如用户从买婴儿用品→买妈妈用品→关注早教）

### 14. 多任务学习：Shared Bottom、MMoE、PLE 的演化与区别？

#### Shared Bottom（硬共享）

**结构：** 所有任务共享底层 DNN，上层各自独立输出。

**优点：** 简单，参数量少。  
**缺点：** 任务之间存在冲突时，会产生**负迁移**（一个任务优化损害另一个任务）。

#### MMoE（Multi-gate Mixture-of-Experts, Google, 2018）

**核心思想：** 多个 Expert（专家网络）+ 每个任务独立的 Gate（门控网络）。

```
输入 x → [E1, E2, ..., En]（多个 Expert）
       → Gi(x)（任务i的门控权重）
       → Σ Gi_k * Ek  → 任务i的输出
```

**优势：** 不同任务通过不同的 Gate 权重组合 Expert，缓解负迁移问题。

#### PLE（Progressive Layered Extraction, 腾讯, 2020）

**核心创新：** 在 MMoE 基础上引入**多层提取**机制，显式分离共享信息和任务特有信息。

- **共享 Expert：** 学习任务间公共知识
- **任务特定 Expert：** 学习各自独有知识
- 每层逐步提取，层层递进

**效果：** PLE 在腾讯新闻推荐场景中，CTR +3%，阅读时长 +1.4%。

#### 对比总结

| 模型 | 共享方式 | 任务解耦能力 | 参数量 |
|------|----------|-------------|--------|
| Shared Bottom | 硬共享 | 弱 | 小 |
| MMoE | 多个 Expert + Gate | 中 | 中 |
| PLE | 分层提取 | 强 | 较大 |

### 15. 什么是生成式推荐？TIGER/HSTU 和传统 DLRM 的核心区别？

#### 生成式推荐（Generative Recommendation）

将推荐问题建模为**序列生成任务**，直接生成用户感兴趣的物品 ID 序列（而非传统打分）。

#### 代表工作

| 模型 | 机构 | 核心思想 |
|------|------|----------|
| **TIGER** | Google | 用 Transformer 生成候选物品 ID |
| **HSTU** | Google | Hierarchical Sequential Transduction Unit，更高效的生成式架构 |
| **P5** | - | 用 LLM 统一处理推荐任务 |
| **RQ-VAE** | - | 用矢量量化学习可推荐的离散 ID |

#### 和传统 DLRM 的核心区别

| 维度 | 传统 DLRM | 生成式推荐 |
|------|-----------|------------|
| **建模方式** | 判别式（打分/分类） | 生成式（序列建模） |
| **物品表示** | Embedding Table 查表 | 通过语义信号生成 |
| **冷启动** | 难（ID 不在表里） | 相对友好（可生成新 ID） |
| **可解释性** | 基于特征贡献 | 基于生成路径 |
| **计算量** | 查表 + MLP | 自回归生成（Decoder） |

### 16. HSTU 是 Encoder 还是 Decoder？Decoder 的 Mask 怎么做？

#### HSTU 的定位

HSTU（Hiera**rchical** Sequential Transduction Unit）本质上是 **Encoder-Decoder 架构**，但在推荐系统中主要用于**序列编码（Encoder）** 角色，输出用户/物品的表示向量用于召回/排序。

#### Decoder Mask 的做法（因果掩码，Causal Masking）

在序列生成场景中（如下一个物品预测），需要防止信息泄露：

```python
# 伪代码：生成因果掩码
seq_len = L
# 下三角矩阵：位置 i 只能看到 i 及之前的 token
mask = torch.tril(torch.ones(seq_len, seq_len))
# 对角线为1：可以看到自己
```

**在 HSTU 中：**
- **Encoder 阶段：** 全注意力（双向），建模完整的序列上下文
- **Decoder/生成阶段：** 因果掩码（单向），只基于历史信息生成下一个物品

### 18. 召回阶段正负样本如何定义？

| 样本类型 | 定义 | 示例 |
|----------|------|------|
| **正样本** | 用户实际发生正向行为的物品 | 点击、播放 > 50%、收藏、分享 |
| **负样本** | 用户没有正反馈的物品 | 未曝光的随机物品、曝光未点击 |
| **Hard Negative** | 和正样本相似但不是正样本 | 同类目不同品牌、曝光排名靠后的物品 |

**样本构造原则：**
- 正样本：用户真实正反馈（点击 > 曝光未点击 > 曝光）
- 负样本：随机采样为主，曝光未点击慎用（存在选择偏差）
- Hard Negative：辅助训练，提升模型区分度

### 19. 什么是数据穿越问题？如何解决？

#### 数据穿越（Data Leakage）

指训练数据中包含了测试时不应该获得的信息，导致模型"作弊"，离线评估虚高但线上效果差。

#### 推荐系统中的典型穿越场景

1. **时间穿越：** 用 T+1 的特征预测 T 的标签（应该用截止到 T 时刻的特征）
2. **特征穿越：** 某些特征（如"是否购买过"）包含了未来信息
3. **曝光位置特征：** 位置靠前的物品天然点击率高，模型学到了位置偏差而非物品质量
4. **Session 内重复曝光：** 同一物品被多次曝光给同一用户

#### 解决方法

| 问题 | 解决方法 |
|------|----------|
| 时间穿越 | 严格按时间切分训练/验证集；特征用截止到当前时刻的值 |
| 位置偏差 | 引入 Position Debiasing 模块（Google 的 PAL）或将位置作为独立特征后置零 |
| 曝光偏差 | 使用 IPS（逆倾向分数）加权或 ESAM 等自监督去偏方法 |

### 20. AUC 的物理含义是什么？GAUC 和 AUC 的区别？

#### AUC 的物理含义

AUC（Area Under ROC Curve）= 随机抽取一个正样本和一个负样本，**正样本得分排在负样本前面的概率**。

**解读：**
- AUC = 1.0：完美排序（不可能达到）
- AUC = 0.5：随机模型（无区分能力）
- AUC = 0.75+：较好
- AUC = 0.9+：非常好

**公式：**
```
AUC = ( Σ_{正样本} rank_i ) / (M × N) - (M + 1) / 2
其中 M=正样本数，N=负样本数，rank_i=正样本的排名
```

#### GAUC vs AUC

| 维度 | AUC | GAUC |
|------|-----|------|
| 统计方式 | 全局统计，不区分用户 | 按 Group（通常=用户）分别统计 AUC，再加权平均 |
| 公式 | AUC = Σ rank / (M×N) | GAUC = Σ (AUC_g × impressions_g) / Σ impressions_g |
| 适用场景 | 二分类通用 | 推荐/广告（用户维度排序质量） |
| 解决的问题 | 全局排序能力 | 用户级别排序公平性 |

**为什么推荐用 GAUC：** 推荐系统每个用户的候选集不同，用户 A 的 Top1 和用户 B 的 Top1 没有可比性，GAUC 解决了这个不公平问题。

### 21. 离线指标好、线上指标不行（线上线下不一致）的原因？

| 原因类别 | 具体原因 | 解释 |
|----------|----------|------|
| **数据穿越** | 训练数据中使用了未来特征 | 特征穿越导致模型"偷看"了答案 |
| **老汤模型** | 新模型在老模型产生的数据上训练 | 分布偏移，模型陷入局部最优 |
| **冰山问题** | 只用线上曝光样本做训练和测试 | 缺失真正负样本（未曝光物品不知道好不好） |
| **特征不一致** | 离线特征和线上特征计算口径不同 | 特征穿越/缺失/延迟 |
| **链路不一致** | 召回→粗排→精排→重排链路配置不同 | 离线只测精排，全链路效果才是关键 |
| **反馈循环** | 热门物品被老模型推得更热 | 马太效应加剧 |
| **业务规则** | 重排/干预逻辑无法在离线评估 | 业务约束无法被离线指标反映 |

**面试重点：** 能说出"离线评估和线上评估本质上是两个不同分布"的观点，并列举 3~5 条具体原因。

### 22. NDCG、HitRate、MRR 的计算方式？

#### HitRate@K（召回场景最常用）

```
HitRate@K = 命中次数 / 总查询数
          = |{q : rank_q ≤ K 且 item_q ∈ Ground Truth}| / |Q|
```

**含义：** 在 Top-K 推荐中，有多少比例的查询至少命中了一个正确物品。

#### MRR（Mean Reciprocal Rank，平均倒数排名）

```
MRR = (1/|Q|) × Σ_{q} 1 / rank_q
```

其中 rank_q 是第一个正确物品在排序结果中的位置。

**含义：** 正确物品的平均排名质量，取倒数使排名越靠前分数越高。

#### NDCG@K（Normalized Discounted Cumulative Gain）

```
DCG@K = Σ_{i=1}^{K} rel_i / log2(i+1)
       = rel_1/log2(2) + rel_2/log2(3) + ... + rel_K/log2(K+1)

NDCG@K = DCG@K / IDCG@K
```

其中 rel_i 是第 i 个物品的相关性得分（0~n），IDCG 是理想 DCG（完美排序时的 DCG）。

**NDCG 归一化到 [0,1]，1=完美排序。**

### 24. 过拟合的解决办法？L1 和 L2 正则化的区别？

#### 过拟合解决办法

| 方法 | 原理 |
|------|------|
| L1/L2 正则化 | 在损失函数中添加权重惩罚项 |
| Dropout | 随机丢弃神经元，减少共适应 |
| Batch Normalization | 稳定梯度，加速收敛 |
| 早停（Early Stopping） | 监控验证集 loss，停止过早 |
| 数据增强 | 增加训练样本多样性 |
| 特征选择 | 减少噪声特征 |
| 模型简化 | 减少层数/参数 |

#### L1 vs L2 正则化

| 维度 | L1（Lasso） | L2（Ridge） |
|------|-------------|-------------|
| 惩罚项 | λ Σ\|w\| | λ Σ w² |
| 梯度 | 符号函数（常数） | 2λw（与 w 成比例） |
| 解的特性 | **稀疏解**（很多 w=0） | **平滑解**（w 趋近于 0 但不为 0） |
| 效果 | 特征选择 | 防止权重过大 |
| 适用 | 高维稀疏特征 | 几乎所有场景 |
| 优化 | 无解析解（次梯度） | 有解析解 |

**面试加分：** 能说出 L1+L2（ElasticNet）结合两者优点，实践中经常使用。

### 25. 梯度消失/爆炸的原因及解决方法？

#### 原因

| 问题 | 原因 | 发生场景 |
|------|------|----------|
| 梯度消失 | 反向传播时梯度逐层相乘 < 1 | 深层网络 + Sigmoid/tanh |
| 梯度爆炸 | 梯度逐层相乘 > 1 | 深层网络 + 权重初始化过大 |

#### 解决方法

| 方法 | 原理 |
|------|------|
| ReLU/LeakyReLU | 梯度恒为1（正区间），彻底解决消失 |
| 残差连接（ResNet） | 恒等映射使梯度直接回传 |
| Batch Normalization | 归一化每层输入，稳定梯度 |
| 梯度裁剪（Gradient Clipping） | 限制梯度最大值，防止爆炸 |
| 合理的权重初始化 | Xavier/He 初始化 |
| LSTM/GRU | 门控机制显式控制信息流 |

### 26. LightGBM 和 XGBoost 的区别？为什么推荐系统偏爱 LightGBM？

#### 核心区别

| 维度 | XGBoost | LightGBM |
|------|---------|----------|
| **分裂策略** | Level-wise（按层分裂） | **Leaf-wise**（按叶子分裂） |
| **特征处理** | 精确贪心 / 近似分位数 | **直方图算法（Histogram）** |
| **类别特征** | 不支持原生（需 one-hot） | **原生支持** |
| **内存占用** | 较高 | **极低**（内存优化） |
| **训练速度** | 快 | **极快** |
| **大数据优化** | 近似算法、采样 | **GOSS（梯度单边采样）+ EFB（互斥特征捆绑）** |
| **API** | scikit-learn 风格 | 独立 API |

#### 为什么推荐系统偏爱 LightGBM？

1. **高维稀疏特征友好：** 推荐系统特征维度极高（用户ID×物品ID等交叉特征），LightGBM 的直方图算法天然适配
2. **稀疏数据处理：** 不需要预处理，支持类别特征原生编码
3. **速度优势：** 线上推理延迟要求高（<10ms），LightGBM 模型小、推理快
4. **类别不平衡处理：** 支持 `scale_pos_weight`，推荐系统正负样本比可达 1:1000+
5. **Leaf-wise 策略：** 更关注排序质量（直接优化 AUC），更适合推荐场景

### 27. 推荐/搜索/广告区别（从业务目标和技术侧重角度）？

| 维度 | 推荐系统 | 搜索系统 | 广告系统 |
|------|----------|----------|----------|
| **核心目标** | 提升用户体验、留存、DAU | 快速满足 query 意图 | 最大化 ECPM（Revenue） |
| **用户意图** | 被动，无明确目标 | 主动，有明确 query | 被动触发 |
| **物品池** | 全量物品 | query 相关文档 | 广告主提交物料 |
| **排序目标** | 用户满意度（时长/点击/收藏） | 相关性为主 | CTR × Bid（ECPM） |

| **反馈类型** | 隐式反馈为主（点击/时长） | 显式相关判断 | 点击/转化 |
| **约束条件** | 用户体验底线 | 质量/权威性 | 预算/出价/资质 |

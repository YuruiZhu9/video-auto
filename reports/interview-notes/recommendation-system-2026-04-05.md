## 三、逐题详细解析

### A1. 推荐系统整体流程与各层职责

**推荐系统经典四阶段漏斗：**

```
用户请求 → 召回层（Candidate Generation）→ 粗排层（Pre-Ranking）→ 精排层（Ranking）→ 重排层（Re-Ranking）→ 下发
```

| 阶段 | 处理量级 | 模型复杂度 | 核心目标 |
|------|---------|-----------|---------|
| **召回** | 百万~千万级 | 简单（规则/Embedding） | 从全量池快速选出候选集（~千级别） |
| **粗排** | 千级别 | 中等（DSSM等轻量模型） | 进一步筛选，承上启下 |
| **精排** | 百级别 | 复杂（DeepFM/DIN等深度模型） | 精准预估CTR/CVR |
| **重排** | 十级别 | 规则+轻量模型 | 多样性/实时性/业务规则 |

**面试重点：** 面试官会追问各阶段的时间约束和工程实现细节。召回阶段通常要求毫秒级响应，因此双塔模型（User Tower + Item Tower分别离线/在线计算）是主流方案。

---

### A2. 协同过滤（CF）原理与User-CF/Item-CF对比

**协同过滤核心思想：** "物以类聚，人以群分"，利用用户或物品之间的相似性进行推荐。

**基于用户的协同过滤（User-CF）：**
- **原理：** 找到与目标用户行为最相似的K个用户，将这些用户喜欢的物品推荐给目标用户
- **相似度计算：** 余弦相似度 / 皮尔逊相关系数 / Jaccard系数
- **公式：** `sim(u,v) = cos(‖R_u‖,‖R_v‖) = (R_u · R_v) / (‖R_u‖ × ‖R_v‖)`
- **优点：** 解释性强，适合社交场景
- **缺点：** 用户量大时计算量大；稀疏矩阵效果差

**基于物品的协同过滤（Item-CF）：**
- **原理：** 用户喜欢物品A，找到与A最相似的物品B推荐给用户
- **核心假设：** 用户倾向于喜欢与自己历史喜欢的物品相似的物品
- **优点：** 物品相似度稳定（比用户兴趣变化慢），可离线预计算
- **缺点：** 热门物品容易和大量物品相似（哈利波特效应），需做热门打压

**User-CF vs Item-CF场景选择：**
- **User-CF** 适合：社交平台（微信读书）、新闻热点场景（用户兴趣变化快）
- **Item-CF** 适合：电商（亚马逊）、视频（Netflix）、音乐（QQ音乐）等物品稳定的场景

### A3. 矩阵分解MF/SVD++原理

**矩阵分解核心：** 将User-Item评分矩阵R（稀疏）分解为两个低维矩阵：

```
R ≈ P × Qᵀ
```

- `P`：用户隐因子矩阵（m × k），`P[u]` 为用户u的隐向量
- `Q`：物品隐因子矩阵（n × k），`Q[i]` 为物品i的隐向量
- 预测评分：`r̂_ui = p_u · q_i`

**优化目标：**
```
min Σ(r_ui - p_u · q_i)² + λ(||P||² + ||Q||²)
```

**SVD++改进（SVD++考虑隐式反馈）：**
```
r̂_ui = μ + b_u + b_i + q_iᵀ (p_u + |N(u)|^{-0.5} Σ_{j∈N(u)} y_j)
```
其中：
- `b_u`、`b_i` 为用户/物品偏置项（解释：有的用户评分偏高/低，有的物品质量好/差）
- `N(u)` 为用户u有行为记录的物品集合
- `y_j` 为物品j的隐式反馈向量

**面试追问：**
- SVD用随机梯度下降（SGD）求解，参数少，泛化能力不如深度模型
- BiasSVD的核心思想：用户和物品都有"基准评分"，加偏置项捕获细粒度差异

### A4. 逻辑回归（LR）在推荐系统中的应用

**为什么推荐系统早期大量使用LR？**
- 可解释性强（特征权重直接反映重要性）
- 工程友好（并行化训练，在线serving方便）
- 对稀疏ID特征友好（配合特征工程）

**LR推荐流程：**
1. 特征工程（用户画像、物品画像、上下文、交叉特征）
2. one-hot编码 → 高维稀疏向量
3. LR模型预估CTR
4. 按pCTR排序下发

**LR推导（面试必考）：**
- Sigmoid函数：`h(x) = 1 / (1 + e^{-wx+b})`
- 对数损失：`L(w) = -Σ[y_i·log(h(x_i)) + (1-y_i)·log(1-h(x_i))]`
- 梯度：`∂L/∂w_j = Σ(h(x_i) - y_i)·x_ij`
- **面试官评价：** "比起推导SVM，LR推导简直送分题，基础要扎实"

**LR的致命缺点：** 无法自动捕获特征交叉，必须人工做特征组合（如FM/FM组件）。

### B1. Wide&Deep：记忆性与泛化性

**Wide组件：**
- 输入：原始稀疏特征 + 手工交叉特征（如"用户已安装APP×展示APP"的交叉）
- 结构：单输入层 → 线性输出
- **核心能力：记忆性（Memorization）** —— 直接记住用户历史行为中的共现模式
- 擅长处理id类稀疏特征，让模型"记住"哪些组合有效

**Deep组件：**
- 输入：所有稠密特征 + Embedding后的稀疏特征
- 结构：输入层 → Dense层（ReLU激活）× n层 → 输出
- **核心能力：泛化性（Generalization）** —— 通过DNN挖掘隐式特征组合，发现未曾出现的关联
- 但过于泛化也会带来问题：推送不相关物品（"羽毛球迷推荐了羽毛球拍"）

**融合方式：** 输出层用Sigmoid(Wide + Deep)组合：
```
P(Y=1|x) = σ(w_wideᵀ·[x, φ(x)] + w_deepᵀ·a^(l_f) + b)
```
其中`φ(x)`为交叉特征变换

**面试追问：** Wide&Deep的"记忆性"与"泛化性"trade-off如何调节？
- 调参角度：Wide侧加入的交叉特征越多，记忆性越强
- Deep侧网络越深，泛化性越强（但也容易过拟合）
- 业务角度：新闻推荐偏泛化，电商推荐偏记忆（复购场景）

### B2. DeepFM模型结构

**核心思想：** 同时建模低阶特征交叉（FM）和高阶特征交叉（DNN），无需人工特征工程。

**模型结构（三部分）：**

```
┌─────────────────────────────────────────┐
│              DeepFM                      │
├──────────────┬──────────────────────────┤
│   FM组件     │       Deep组件            │
│ (低阶交叉)   │      (高阶交叉)          │
│  ┌─────┐    │   Embedding Input         │
│  │V·x  │    │       ↓                   │
│  │线性 │    │     DNN Layers             │
│  │加法 │    │       ↓                   │
│  └─────┘    │   输出向量                │
└──────────────┴──────────────────────────┘
              ↓
        Sigmoid输出
```

**FM组件（Vector-wise二阶交叉）：**
- 每个特征field对应一个k维隐向量V
- 二阶项：`Σ_i Σ_{j>i} <V_i, V_j> · x_i · x_j`（时间复杂度从O(k·n²)优化到O(k·n)）
- 线性项：`Σ w_i · x_i`
- FM同时建模了**一阶线性关系**和**二阶特征交叉**

**Deep组件：** 标准DNN，对Embedding后的特征做高阶非线性组合

**与Deep&Cross（DCN）区别：**
- DCN用Cross Network替代Wide部分，自动做特征高阶交叉（参数少）
- DeepFM的FM组件显式建模二阶交叉，Deep组件建模高阶，结构更清晰

### B3. DSSM双塔模型原理与工业落地方案

**DSSM（Deep Structured Semantic Models）核心：**
- 通过DNN将Query和Item（文档）映射到同一语义空间
- 用余弦相似度衡量语义距离
- 最初用于搜索引擎的语义匹配，后引入推荐系统做召回

**推荐系统中的双塔结构：**

```
User Tower                Item Tower
┌──────────────┐          ┌──────────────┐
│ 用户特征     │          │ 物品特征     │
│ (人口属性、  │          │ (ID、类别、  │
│  行为序列等) │          │  统计特征等) │
│      ↓      │          │      ↓      │
│  DNN网络    │          │  DNN网络    │
│      ↓      │          │      ↓      │
│  User Emb   │──cos──→  │  Item Emb   │
└──────────────┘          └──────────────┘
    在线计算                   离线计算/缓存
```

**工业落地方案（重点）：**
1. **物品塔离线计算：** 物品Embedding预先计算好，存入向量数据库（Faiss/Milvus/Hologres）
2. **用户塔在线实时计算：** 用户请求时实时计算（考虑实时行为特征）
3. **在线ANN检索：** 用户向量在向量数据库中做近邻检索（Top-K）

**优缺点对比：**

| 特性 | 优点 | 缺点 |
|------|------|------|
| DSSM双塔 | 1. 物品塔可离线计算，Serving高效<br>2. 支持ANN索引扩展<br>3. 表达能力强 | 1. 用户/物品塔特征不能交叉（缺乏显式交叉）<br>2. 两塔特征各自独立建模<br>3. 不支持实时特征交互（对比精排） |

**DSSM vs DSSM变体：**
- **Sentence-BERT（SBERT）：** 用双encoder代替原始DSSM的单encoder，提升句子匹配质量
- **Multi-View DSSM：** 多视角建模，多源数据融合

### B4. DIN模型（Deep Interest Network）

**背景痛点：** 之前推荐模型（如DeepFM）将用户所有行为序列做SUM/AVG pooling，丢失了大量用户兴趣信息。

**核心创新：引入Attention机制（兴趣激活模块）**

```
用户行为序列：[item1, item2, ..., itemn]（每个item含category_id等）
     ↓
Attention Score = Activation(候选商品 & 行为商品) → softmax权重
     ↓
加权求和：Σ(weight_i × item_emb_i) → 用户兴趣向量
     ↓
与候选商品向量、用户画像向量等拼接 → 进入Deep层
```

**Activation Unit设计：**
- 输入：候选Item Embedding + 行为Item Embedding
- 输出：注意力权重（0~1之间）
- 实现：`a(query, key) = Vᵀ·tanh(W₁·query + W₂·key)`

**面试追问：**
- DIN的attention权重是否需要归一化？**不需要**（因为不同兴趣强度不同，归一化会损失信息）
- DIN和transformer中attention的区别？DIN是候选Item对行为序列的单向attention，不需要position encoding，权重也不做归一化
- **Dice激活函数：** 解决Relu在稀疏场景下梯度消失问题（PReLU的改进）

---

### B5. DIEN（Deep Interest Evolution Network）

**DIEN相比DIN的改进：** 在DIN的基础上，引入**序列建模**来捕获用户兴趣的**演化过程**。

**模型结构（双序列）：**

```
用户行为序列 → Interest Extractor层（GRU）→ Interest Evolution层（AUGRU）→ 拼接进入DNN
```

**Interest Extractor层（兴趣提取）：**
- 用双向GRU对行为序列建模
- 隐藏状态h_t捕获行为t的上下文信息
- 辅助损失：`L_aux = -Σ[y_t·log(σ(h_t)) + (1-y_t)·log(1-σ(h_t))]`
- **为什么需要辅助损失？** 单独使用行为序列监督信号太弱（点击行为稀疏），加辅助损失增强兴趣提取效果

**Interest Evolution层（兴趣演化）：**
- 用AUGRU（Attention-based GRU）建模兴趣演化
- 在GRU的更新门中引入Attention机制：
  ```
  ĥ_t = (1 - u_{t-1}·a_t)·ĥ_{t-1} + u_{t-1}·a_t·h̃_t
  ```
  其中`a_t`为兴趣注意力，重要历史行为对当前兴趣影响更大
- **兴趣演化的业务含义：** 用户兴趣随时间推移（购买→复购/货比三家），AUGRU能捕捉这个动态过程

### B6. MMOE（Multi-gate Mixture-of-Experts）模型

**背景：** 多任务学习（如CTR+CVR联合建模）中，不同任务之间的关系不确定，共享隐层（Hard Parameter Sharing）会导致任务间互相干扰（task conflict）。

**MMOE结构：**

```
                    ┌── Expert 1 (E₁) ──┐
共享输入X ───→ ┌──┤── Expert 2 (E₂) ──┤──→ Task A 输出
              │  └── Expert m (E_m) ──┘
              │
              └── Gate A → Σ(g_i^A · E_i) ──┐
                                             ├→ Task B 输出
              └── Gate B → Σ(g_i^B · E_i) ──┘
```

**核心公式：**
```
y_k = Σ_{i=1}^{m} (g_i^k · E_i)ᵀ · x
g_i^k = softmax(W_{gk} · x)_i
```
- `E_i`：第i个Expert网络（每个Expert是独立的DNN）
- `W_{gk}`：第k个任务对应的Gate网络参数
- 每个任务有独立的Gate，**自动学习各Expert对当前任务的重要性权重**

**MMOE vs Hard Sharing：**
- Hard Sharing：所有任务共享底层，任务冲突时效果差
- MMOE：每个任务通过独立Gate从多个Expert中**选择性提取**有用信息，解决任务冲突

**实际应用场景：** 抖音"点赞+关注+分享+完播率"多目标建模，快手电商"点击+购买+加购"联合预估

### C2. 召回阶段负样本构造方法

**为什么不能直接用曝光未点击样本当负样本？**

曝光未点击≠用户不感兴趣。曝光本身是上一轮推荐系统筛选的结果，本身就携带了正向选择偏差（Positive Bias）。直接使用会造成：
1. 假负样本（False Negative）：用户可能只是没看到/没来得及点击
2. 采样偏差（Sample Bias）：曝光样本分布与真实候选集分布不一致

**三种常见召回负样本构造策略：**

| 策略 | 做法 | 优缺点 |
|------|------|------|
| **全局随机负采样** | 从全量候选池随机采样作为负样本 | 简单，但可能采样到热门物品，分布不均衡 |
| **曝光未点击（简版）** | 将曝光但未点击样本作为负样本 | 训练/测试分布一致，但携带选择偏差 |
| **混合采样** | 全局随机+曝光未点击按比例混合 | 兼顾两种策略，通常效果更好 |

**Google论文方法（Sample-Bias-Corrected）：**
- 对热门物品的负样本概率做加权修正：`P_corrected ∝ P_raw × 1/(√(η_i))`
- 用对数修正因子校正热门物品的采样偏差

### C3. 粗排负样本构造：精排未下发样本的使用

**问题本质：** 粗排训练样本只是精排下发样本的子集，与线上实际打分分布不一致。

**举例说明：**
1. 粗排对1000条打分，截取Top300给精排
2. 精排对300条打分，选出Top10
3. 问题：粗排Top5的样本，精排可能只排到250~300名（这些样本在精排曝光，但粗排看不到）
4. 解决：把这部分"粗排靠前但精排靠后"的样本作为**下沉负样本**训练粗排

**采样权重计算（进阶）：**
```
w = (归一化粗排分数 - 归一化精排分数) × 系数
```
用`w`作为下沉负样本的权重，把两个模型打分的gap表达在负样本中。

### C4. 热门物料打压与倒排索引

**问题场景：** 热门商品（如爆款SKU）出现在大量用户的行为序列中，导致：
- Item-CF中与大量物品相似（哈利波特效应）
- Embedding被热门物品主导
- 曝光的马太效应加剧

**热门打压方案：**

| 方法 | 原理 | 适用场景 |
|------|------|---------|
| **热度降权** | 相似度×1/√(popularity) | 协同过滤 |
| **对数降权** | 相似度×log(1+α/pop) | Embedding相似度 |
| **均匀采样** | 热门物品采样概率打折 | 负采样 |
| **DIVERSITY正则** | 重排阶段强制多样性 | 全链路 |
| **MIR（Mutual Information）** | 用互信息替代共现频次 | 协同过滤 |

**倒排索引场景设计题（面试高频）：**

> 热门商品我们如何用物料倒排索引来进行热点打压？

**设计思路：**
1. 构建倒排索引：`category_id → [items sorted by popularity]`
2. 曝光去重：对同一category下已曝光过的热门物品降权或过滤
3. 热度截断：每日/每小时更新热度分，对热度超过阈值的物品应用打压系数
4. 负反馈打通：用户对某物品负反馈后，在倒排索引中将其拉入黑名单一段时间

### D1. XGBoost相比GBDT的改进

| 特性 | GBDT | XGBoost |
|------|------|---------|
| **正则化** | 无（仅靠树的深度控制） | 有L1/L2正则，目标函数中显式加入Ω(f) |
| **分裂节点搜索** | 贪心精确搜索（遍历所有特征+分裂点） | 预排序（Pre-sorted）+ 分位点近似 |
| **缺失值处理** | 需手动填充 | 自动处理：训练时将缺失值归入增益更大的分支；预测时走默认分支 |
| **并行化** | 特征间串行 | 按特征列并行（特征预排序后并行找最优分裂） |
| **二阶导** | 只用一阶梯度 | 同时用一阶和二阶梯度（Hessian矩阵），收敛更快 |
| **稀疏感知** | 无 | 内置稀疏感知算法，自动学习缺失值走向 |

**最优分裂节点选择：**
- 遍历所有特征，在每个特征的每个分裂点计算分裂增益：
  ```
  Gain = ½ [GL²/(HL+λ) + GR²/(HR+λ) - (GL+GR)²/(HL+HR+λ)] - γ
  ```
- 选择Gain最大者作为分裂点

**缺失值处理原理（面试追问）：**
- 训练时：分别尝试将缺失值放入左分支/右分支，选择增益更大的方向
- 预测时：缺失值沿训练时学习的默认方向走

### D2. 推荐系统线上效果退化排查

**可能原因（系统化排查框架）：**

```
数据层 → 特征层 → 模型层 → 工程层 → 外部因素
```

**数据层：**
- 数据分布发生变化（节假日/季节性/用户群体漂移）
- 数据pipeline延迟导致特征陈旧
- 特征缺失率上升

**特征层：**
- 特征穿越（Future Feature Leakage）：使用了未来才能知道的信息
- 特征工程变更引入bug
- 线上线下特征不一致（特征穿越的典型表现）

**模型层：**
- 模型过拟合（训练时间过长，在历史数据上过度拟合）
- 模型老化：用户行为模式变化，但模型未更新
- AB实验时新模型短期有效，长期退化成"次优"

**工程层：**
- 推荐服务缓存策略变化
- 下游服务超时/降级
- 候选池变化（新物品入库/旧物品过期）

**外部因素：**
- 节假日效应（春节/双十一等）
- 时政热点事件影响用户兴趣
- 竞品动作（竞品大促分流用户）

### D3. 冷启动问题解决方案

**用户冷启动：**
1. **热门推荐：** 新用户引导页推送高热物品（Top品类/Top物品）
2. **地域推荐：** 结合LBS按地区推荐（如周边餐厅）
3. **社交关系导入：** 微信读书"好友在读"，利用社交关系
4. **基于上下文的探索：** 新用户首屏展示多品类物品，探索用户兴趣
5. **EE（Explore-Exploit）：** Bandit算法（LinUCB/Thompson Sampling）平衡探索与利用

**物品冷启动：**
1. **投票法（Exploration）：**
   - 新物品随机曝光给100个用户，收集反馈
   - CTR达到阈值 → 扩大曝光到500人
   - 持续达到阈值 → 继续扩大，最终进入正常推荐池
2. **内容相似推荐：** 新物品入库时有属性信息（品类/标签），找到相似物品的感兴趣用户做相关推荐
3. **跨平台数据：** 抖音/头条系内共享行为数据，新物品可利用内容特征+协同信号联合推断
4. **知识图谱辅助：** 用知识图谱建立物品与已有物品的语义关联

### D4. Sampling-Bias问题与校正方法

**Sampling-Bias来源：**
推荐系统日志中，用户行为数据本身是**被推荐系统筛选后的数据**，存在严重的样本选择偏差（Sample Selection Bias）。

**Google论文方法（《Sampling-Bias-Corrected Neural Modeling for Large Corpus Item Recommendations》）：**

**对数修正因子（Log Uniform Sampler）：**
```
w_i = log(1 + p_i / β)
```
- `p_i` 为物品i的流行度（曝光频次/点击频次）
- `β` 为平滑超参数
- 热门物品的权重被对数压制，实现均匀采样效果

**Item-popularity-aware Sampling：**
- 对每个batch内的负样本，按流行度做加权
- 热门负样本降权，冷门负样本提权

### D5. 特征穿越（Future Feature Leakage）问题

**问题定义：** 训练时使用了"未来才能知道"的特征，导致模型在离线评估时虚高，线上效果差。

**常见穿越场景：**
1. 特征中包含item的当天统计CTR（但用户行为是实时上报的，次日才能计算出完整CTR）
2. 用户当次请求的"停留时长"特征（模型训练时用了同一次请求的停留时长，推理时无法获得）
3. 滑动窗口拼接label时，窗口边界没有做好对齐

**解决方案：**
1. **严格特征时间对齐：** 特征快照时间必须早于label生成时间
2. **特征只取T-1时刻快照：** 当前请求时间T的特征，只能用T-1及之前的数据
3. **线上线下一致性（Feature Store）：** 用同一套特征抽取服务保证特征一致性
4. **穿越检测工具：** 离线用Shuffle检测，统计同一条样本中特征与label的时间关系

### E1. 推荐系统评估指标详解

| 指标 | 公式/含义 | 适用场景 |
|------|---------|---------|
| **AUC** | ROC曲线下面积，衡量正负样本排序能力 | 离线模型评估，金指标 |
| **GAUC** | Group-AUC，按用户分组计算AUC再平均 | 考虑用户内公平性，更接近业务 |
| **Recall@K** | Top-K中命中的正样本数 / 总正样本数 | 召回层评估 |
| **Precision@K** | Top-K中命中的正样本数 / K | 精确度 |
| **NDCG@K** | 归一化折损累积增益，考虑位置衰减 | 排序质量评估 |
| **MRR** | 平均倒数排名，第一个命中位置 | 信息检索 |
| **CTRvariance** | 用户间/时间维度CTR稳定性 | 系统稳定性监控 |

**GAUC计算公式：**
```
GAUC = Σ (imp_i × AUC_i) / Σ imp_i
```
- 按用户分组计算AUC，再以展示数为权重加权平均
- 比全局AUC更能反映用户体验

### E3. 召回质量如何评估？

**离线评估：**
- **Recall@K：** 离线日志中，正样本（用户实际点击/购买）在召回Top-K中的命中率
- **HitRate@K：** 至少命中一个正样本的用户比例
- **MRR@K：** 第一个命中正样本的倒数排名
- **Coverage：** 召回集合对物品池的覆盖率（衡量多样性）
- **Distractor Rate：** 召回候选中"干扰项"（不相关物品）占比

**线上评估：**
- **曝光占比：** 各召回通道的曝光占比是否合理
- **召回→精排转化率：** 召回Top-K中有多少进入精排
- **线上A/B：** 核心业务指标（CTR/CVR/用户停留时长）的提升

### F1. 场景设计：热门商品热点打压方案

**题目要求：** 无已有数据，需自己假设设计。

**完整方案：**

```
阶段1：热度检测
├─ 统计指标：曝光量、点击量、转化量（可定义复合热度分）
├─ 异常检测：用3σ原则或箱线图检测异常热门物品
└─ 分级：普通品 → 热门品 → 爆品（分级阈值按业务设定）

阶段2：打压策略
├─ 流量截断：热门商品每日曝光次数设置上限
├─ 曝光去重：同一用户24小时内对同一商品不重复曝光
├─ 热度降权：热门商品在倒排索引排序时降低优先级
└─ 多样性插入：在推荐列表中强制插入非热门但高质量商品

阶段3：效果监控
├─ 打压后物品的曝光量是否下降
├─ 被打压物品的CTR/CVR是否改善（减少曝光给不感兴趣用户）
└─ 整体系统指标（曝光/点击/时长）是否有波动
```

### G1. 手撕代码：搜索旋转排序数组（一次二分优化）

**题目：** 在旋转排序数组中搜索目标值，允许重复值，返回是否存在。

**核心思想：** 变种二分，当左右半边无法区分时，向右收缩。

```python
def search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return True
        # 无法区分哪边有序，右移左边界
        if nums[lo] == nums[mid] == nums[hi]:
            lo += 1
            hi -= 1
        elif nums[lo] <= nums[mid]:  # 左边有序
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:  # 右边有序
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return False
```

**面试追问：** 普通旋转数组用两次二分（找断点+找目标），此方法用一次二分。时间复杂度O(log n)（最坏O(n)）。

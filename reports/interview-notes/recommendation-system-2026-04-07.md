## 三、逐题详细解析

### 1. 双塔模型（DSSM）原理与特征交叉限制

**核心原理：**

```
用户塔（User Tower）  →  User_Embedding
物品塔（Item Tower）  →  Item_Embedding
                ↓
        cosine(User_Embedding, Item_Embedding) → Score
```

将用户特征和物品特征分别输入两个独立的DNN，生成低维向量，通过向量检索（Faiss/Milvus）实现海量物品的快速召回。

**为何不能在底层做特征交叉？**

| 约束 | 原因 |
|------|------|
| 计算约束 | 百万级候选集需毫秒级响应，实时交叉计算无法承受 |
| 向量检索前提 | 双塔结构使物品向量可**离线预计算**，线上只需实时计算用户向量 |
| 精度损失的弥补 | 排序层使用更复杂模型（DeepFM/DIN）补偿精度 |

---

### 2. 召回阶段负采样策略

**面试陷阱：** 直接用"曝光未点击"做负样本 → ❌ 这是错误的！

**深层逻辑：**

- **样本选择偏差（SSB）**：曝光未点击仅来自上一轮精选集，不具备全库代表性，模型对全库中完全不相关的物品缺乏鉴别力
- **正确方案：**

```
✅ 全局随机负采样：随机选取未曝光物品 → 让模型"认识"完全不相关的物品
✅ 困难负样本（Hard Negatives）：选取"被召回了但未被点击"的物品
   → 强迫模型学习细粒度差异
✅ 曝光但未点击的样本：作为补充，但不能作为唯一负样本
```

**实践中通常比例：** 全局随机负样本:曝光未点击 ≈ 1:10 ~ 1:4

---

### 3. 多路召回融合方案

**问题：** 各路召回分数物理意义不同（协同过滤算相似度、热度算点击率），不能直接比较。

| 融合方案 | 核心思路 | 优缺点 |
|---------|---------|-------|
| 归一化 | Min-Max或Z-Score标准化到[0,1] | 简单高效，但受异常值影响 |
| 渠道转化率加权 | 统计各路CTR/CVR作为权重 | 无法解决物理意义不一致 |
| 轻量级模型融合 | LR/GBDT预测粗略CTR | 本质是粗排，复杂度提升 |

**兜底策略：**
- 去重：多路重复商品取最大值或加权和
- 强插补足：热门/新品队列防止空转
- 每路独立超时控制（建议50ms），某路失败不影响其他路

---

### 4. ItemCF vs UserCF vs SwingCF

| 算法 | 核心思路 | 适用场景 |
|------|---------|---------|
| ItemCF | 基于物品相似度：喜欢物品A的用户也喜欢物品B | 物品数量稳定、用户兴趣分散 |
| UserCF | 基于用户相似度：相似用户喜欢什么就推荐什么 | 用户群体清晰、社交属性强 |
| SwingCF | 考虑重合用户是否来自同一个小圈子（引入用户重叠度惩罚） | 电商/内容平台，比ItemCF更抗噪声 |

---

### 5. Wide&Deep vs DeepFM 本质区别

| 维度 | Wide & Deep | DeepFM |
|------|------------|--------|
| 核心结构 | Wide(LR) + Deep(DNN) | FM + Deep(DNN) |
| 特征工程 | **依赖人工**构造交叉特征 | **端到端自动**学习二阶交叉 |
| 低阶交互 | Wide部分负责记忆 | FM通过隐向量内积显式建模 |
| 参数共享 | 通常不共享 | **共享相同Embedding输入** |

**为何需要Wide或FM部分（记忆能力）？**

- DNN擅长加性特征，对乘法关系（特征交叉）需极深网络才能逼近
- DNN对从未出现的特征组合可能给出非零预测（过度泛化），Wide/FM提供"记忆"能力
- DeepFM通过FM和Deep共享Embedding，使Embedding同时接受显式二阶交互和隐式高阶交互的梯度更新 → 避免Embedding Collapse

---

### 6. DIN vs 简单Pooling 的本质区别

**Pooling局限：** 无论推荐什么商品，输出都是固定的混合向量 → 无法表达用户对不同候选商品的差异化兴趣

**DIN解法（Target Attention）：**

```
候选商品 "鼠标" → 激活 "键盘"(权重高)、"洗面奶"(权重≈0)
候选商品 "毛巾" → 激活 "沐浴露"(权重高)、"键盘"(权重≈0)
```

**核心公式：**

```
Attention(Q, K, V) = softmax(QK^T / √dk) × V

Q = 候选商品Embedding
K/V = 用户历史行为序列Embedding
```

**Activation Unit：** DIN使用一个小型MLN（多层神经网络）而非直接点积，学习候选商品与历史行为之间的注意力权重。

---

### 7. 超长用户行为序列处理（SIM模型）

**问题：** 用户行为序列达10k+时，O(N×候选集大小)的Attention计算不可承受。

| 方案 | 核心思路 | 代表模型 |
|------|---------|---------|
| 截断 | 只保留最近N个行为（50~100个） | 适用于低频场景 |
| 记忆网络 | 用GRU/LSTM压缩历史 | DIEN |
| **检索式建模** | 先检索相关子序列，再做Attention | **SIM** |

**SIM两种检索方式：**

- **Hard Search**：用Category/Brand ID建立倒排索引，精确匹配
- **Soft Search**：用向量索引（ALIAS/HNSW）进行近邻搜索
- 收益：复杂度从 O(N) 降为 O(logN) 或 O(K)

---

### 8. DIEN vs DIN 的区别

| 维度 | DIN | DIEN |
|------|-----|------|
| 核心创新 | Target Attention（兴趣激活） | 兴趣演化（Interest Evolution） |
| 结构 | Activation Unit | AUGRU（兴趣进化GRU） |
| 解决的问题 | 用户兴趣是"多峰"的 | 用户兴趣随时间**动态演化** |
| 适用场景 | 短期行为、兴趣相对稳定 | 长期行为、存在明显兴趣迁移（如浏览→加购→购买） |

**DIEN两层结构：**
1. **兴趣抽取层**：用GRU建模行为序列的时序关系
2. **兴趣进化层**：引入AUGRU（带注意力门控的GRU），根据候选商品动态控制兴趣进化方向

---

### 9. MMoE vs PLE vs Shared Bottom

**演化路径与核心逻辑：**

```
Shared Bottom → MMoE → PLE
简单共享     → 门控选择 → 分层专家分离
```

**Shared Bottom：** 底层共享参数，简单但任务冲突（各任务梯度相互干扰）

**MMoE（Multi-gate Mixture-of-Experts）：**

```
每个任务有独立门控网络：gate_k(x) = softmax(W_k × x)
输出 = Σ(gate_k(x)[i] × Expert_i(x))
```

- 优点：各任务动态选择Expert组合，减少任务冲突
- 缺点：仍共享所有Expert，没有"任务特有"的Expert

**PLE（Progressive Layered Extraction）：**

```
第一层：N个共享Expert + M_k个任务k独有的Expert
第二层：在第一层输出上继续提取
```

- 分离任务特有Expert和共享Expert
- 渐进式提取，逐层解耦
- 工业界效果通常优于MMoE

### 10. ESMM如何解决CVR预估中的SSB和数据稀疏

**两个核心痛点：**

- **样本选择偏差（SSB）**：只在"点击"样本上训练CVR，但推断需对所有"曝光"样本打分
- **数据稀疏（DS）**：转化样本（点击后购买）极少

**ESMM核心思想：** 不直接训练CVR，而是利用乘法结构：

```
pCTCVR = pCTR × pCVR
即：p(z,y|x) = p(y|x) × p(z|y,x)
```

**解决SSB：** CTR和CTCVR在**整个曝光空间**训练（所有曝光样本），避免只在点击样本上训练的分布偏差

**解决DS：** CVR网络共享CTR的Embedding层，底层特征表达得到充分训练

### 11. 粗排为何必要？不能直接召回→精排？

**工程约束：**

| 方案 | 延迟 | 机器成本 |
|------|------|---------|
| 召回→精排（直接） | 800ms | +5倍 |
| 召回→粗排→精排 | 100ms（粗排20ms+精排80ms） | 基准 |

**粗排的ROI逻辑：** 用20%的成本解决80%明显错误样本，让精排专注于细粒度排序

**粗排特征：** 通常只用几十维核心特征（用户活跃天数、物品历史点击率、类目匹配度），降低实时特征获取成本

---

### 12. 重排：MMR vs DPP

**目标：** 打破"信息茧房"，在相关性与多样性之间取得平衡

| 策略 | 核心思路 | 特点 |
|------|---------|------|
| 硬规则 | 滑动窗口（每5个展示位同类目不超2个） | 简单直接，效果可控 |
| MMR | 贪心选择下一个物品时考虑与已选物品的相似度惩罚 | 局部最优，有理论基础 |
| DPP | 行列式点过程，数学上保证集合整体多样性最优 | 全局优化，计算较重 |

---

### 13. 重排对精排的影响及约束机制

**问题：** 重排调整顺序会破坏精排的分数排序吗？

**工程约束机制：**

- **位置限制**：只调整相邻位置，最多移动3个位置
- **分数阈值**：分差>0.1不允许调换（精排分数差距大则保持原序）
- **AB测试验证**：每个重排策略必须通过严格的AB测试

### 14. 多目标学习中"跷跷板"问题

**现象：** 简单任务梯度幅值远大于困难任务 → 共享层被主导 → 困难任务效果下降

**解决思路：**

| 方向 | 方法 |
|------|------|
| 模型架构 | Shared Bottom → MMoE → PLE（分离专家） |
| Loss设计 | Uncertainty Weighting（自动学习任务权重） |
| Loss设计 | GradNorm（梯度范数归一化） |
| Loss设计 | 手动调参（黄金比例等） |

### 15. 推荐系统分层架构与各层核心指标

```
全量物品（亿级）
    ↓ 召回（<50ms）
千级候选集 → 粗排（<20ms）
百级候选集 → 精排（<100ms）
展示（10~20个）→ 重排（<30ms）
```

| 层级 | 核心指标 | 优化目标 |
|------|---------|---------|
| 召回 | 召回率 > 90% | 覆盖率、速度 |
| 粗排 | AUC比召回高3~5个点 | 平衡精度与性能 |
| 精排 | AUC/GAUC最大化 | 精准排序 |
| 重排 | 点击率+多样性+用户停留时长 | 全局最优 |

### 16. 离线AUC好、线上指标差的根因分析

| 根因 | 解释 | 排查方法 |
|------|------|---------|
| **特征穿越** | 使用了当次请求的未来信息（如当次转化率） | 特征重要性分析，异常高需警惕 |
| **老汤模型** | 历史模型训练样本混入新特征分布 | 检查样本构建时间窗口 |
| **冰山问题** | 长尾物品/用户离线评估覆盖不足 | 分层指标分析 |
| **链路不一致** | 离线特征用数据仓库，线上用实时流 | Feature Log逐条比对 |
| **SSB偏差** | 训练空间与预测空间差异大 | 检查COPC指标 |
| **评估目标不匹配** | AUC衡量排序能力，对业务价值提升有限 | 引入业务指标 |

### 17. 冷启动系统化解法

**用户冷启动（新用户无历史行为）：**

| 阶段 | 方法 | 说明 |
|------|------|------|
| 规则 | 全局热门兜底 | 高点击、高普适性内容 |
| 规则 | 属性映射 | 注册信息(年龄/性别/地域)→细分人群 |
| 算法 | UCB/Thompson Sampling | 给不确定性高的新物品更多展示 |
| 大模型 | LLM根据注册信息生成初始画像 | 新方向 |

**物品冷启动（新物品无交互数据）：**

- **核心逻辑：** "新物品A和热门物品B特征相似，且用户喜欢B，则推荐A"
- **方法：** NLP/CV模型提取新物品向量 → Embedding相似度召回
- **流量分配：** 探索+利用（EE策略），新物品保底曝光

### 18. 大模型（LLM）在推荐系统中的落地

**三大落地方向：**

| 方向 | 应用场景 | 工程方式 |
|------|---------|---------|
| 特征工程 | 用户画像生成、物品非结构化数据提取 | 离线批量生成，存特征库 |
| 知识蒸馏 | 大模型作为Teacher训练轻量Student模型 | 延迟降低100倍 |
| 生成式推荐 | 端到端生成推荐结果（Meta GR、美团MTGR） | 极致性能优化 |

**为何短期内不会取代传统架构？**

- 工程门槛极高（推理时延和成本问题）
- 可解释性和可控性变差
- 效果提升场景化（长序列、语义丰富场景更明显）

**未来趋势：混合架构**

```
召回：保留传统向量检索保证性能
粗排/精排：探索生成式模型
重排：保留规则满足业务约束（多样性、去重）
```

### 19. AUC物理含义与GAUC

**AUC物理含义：**

> 随机挑选一对正负样本，正样本排在负样本前面的**概率**
>
> AUC = P(score(pos) > score(neg))

**GAUC（Group AUC）：**

- AUC在全体样本上统计，忽略用户维度
- GAUC：每个Group（通常=每个用户）统计一个AUC，再取加权平均

```
GAUC = Σ(w_u × AUC_u) / Σ(w_u)

w_u = 用户u的正样本数（或曝光数）
```

### 20. L1 vs L2 正则化

| 维度 | L1（Lasso） | L2（Ridge） |
|------|------------|-----------|
| 公式 | λ‖w‖₁ | λ‖w‖² |
| 解的特点 | **稀疏解**（部分参数→0） | 收缩所有参数，接近0但不等于0 |
| 效果 | 特征选择 | 防止过拟合，保留所有特征 |
| 几何解释 | 与L1球相交，易落在坐标轴上 | 与L2球相交，各维度均匀收缩 |

**为何L1产生稀疏解？**
L1约束区域是棱角分明的菱形，与Loss等高线相交时更容易落在坐标轴上 → 部分维度系数直接为0。

### 21. XGBoost vs LightGBM 区别

| 维度 | XGBoost | LightGBM |
|------|---------|---------|
| 分裂策略 | Level-wise（按层分裂） | **Leaf-wise**（按叶子分裂） |
| 分裂依据 | 精确贪心/近似分位数 | **直方图算法**（离散化） |
| 类别特征 | 不支持原生，需One-Hot | **原生支持**（无需展开） |
| 内存/速度 | 较高 | 低内存，极快 |
| 大数据优化 | 近似算法、采样 | **GOSS**（梯度单边采样）+**EFB**（互斥特征捆绑） |
| 通信效率 | 较重 | 支持特征并行、数据并行 |

**为什么都是Boosting？**

- Boosting：串行训练，每棵树学习残差，关注**降低偏差**
- Bagging（如RF）：并行训练，降低**方差**

### 22. Attention为何除以 √dk？

**目的：** 防止点积结果过大，导致softmax梯度消失

**数学推导：**

```
设 q, k 各维度独立同分布，均值0，方差1
q·k = Σ q_i × k_i → 期望=0，方差=d_k（d_k个独立变量之和）

softMax输入值过大 → softMax趋于one-hot → 梯度趋近0（梯度消失）

解决：除以 √d_k → q·k/√d_k 方差降为1 → softMax输出分布合理
```

### 23. LN vs BN — 推荐/Transformer为何用LN？

| 维度 | Batch Normalization | Layer Normalization |
|------|--------------------|--------------------|
| 归一化维度 | Batch方向（同一特征在不同样本间） | 单样本内（所有特征间） |
| 依赖Batch Size | 依赖，小时效果差 | **不依赖** |
| 序列场景 | NLP/CV不适用 | **NLP/Transformer标配** |
| 推荐系统 | 不稳定（用户序列batch变化大） | **稳定** |

**核心原因：** LN在序列长度变化时更稳定，Transformer堆叠多层需要每层归一化稳定训练。

### 24. 防止梯度消失与梯度爆炸

| 方法 | 原理 |
|------|------|
| 梯度裁剪（Gradient Clipping） | 当‖g‖ > threshold时，g = g × threshold/‖g‖ |
| 残差连接（Residual Connection） | f(x) = x + Sublayer(x)，梯度直接回传到底层 |
| 合适的激活函数 | ReLU（不死）、GELU、Swish |
| LN/BN | 稳定各层输入分布 |
| 权重初始化 | Xavier/He初始化保证前向反向方差稳定 |
| 合适的学习率 | 学习率衰减、warm-up策略 |

### 1. 双塔模型的工作原理是什么？为什么不直接在底层做用户和物品特征交叉？

**答案要点：**

**双塔模型（DSSM）原理：**
- 将用户特征（User Features）和物品特征（Item Features）分别输入两个独立的深度神经网络（Tower），分别输出固定维度的 Embedding 向量
- 在线服务时，通过计算两个向量的**内积（Dot Product）**或**余弦相似度**来衡量匹配程度
- 物品向量可以**离线预计算**存入向量数据库（如 Faiss、Milvus），支持毫秒级全库检索

**为什么不底层交叉：**
- **计算约束**：召回层候选集通常是百万量级，实时对所有物品做用户-物品特征交叉，计算量不可接受
- **向量检索的前提**：只有 User Tower 和 Item Tower 独立，才能离线预计算 Item Embedding 建好索引
- 双塔模型**牺牲了底层特征交叉精度，换取了全库检索的效率**，这是工程和效果的折中

**面试加分点：** 提到可以在线上 user tower 输出后，加一个轻量级的 dot product 作为浅层交叉，但不涉及 item 侧实时计算。

### 2. 召回模型训练时，负样本怎么选？「曝光未点击」能直接用吗？

**答案要点：**

**不能直接用「曝光未点击」**，原因：

**样本选择偏差（Sample Selection Bias, SSB）：**
- 召回层目标是从**全量库（百万/千万级）**中捞出候选集，而「曝光未点击」仅来自上一轮精选集
- 如果只用这些数据训练，模型实际上在学习「如何区分高相关物品中的细微差别」，而不是「如何从海量噪声中区分相关物品」

**正确的负样本策略：**
1. **全剧随机负采样（Global Random Negative）**：从全量库随机选取，让模型"见识"完全不相关的物品
2. **Hard Negative Mining**：选取那些"被召回了但未被点击"或"相关性分值高但在业务上判定为负"的样本——更难区分，对训练更有价值
3. **曝光未点击（Semi-Hard Negative）**：作为辅助负样本，配合随机负样本使用

**公式层面理解：**
- 正样本：用户点击的item
- 负样本：`随机采样` + `hard negative（easy负样本之外的高置信度负例）`

### 3. 多路召回（5路）最终输出500个商品，每路怎么分配？

**答案要点：**

**固定配额策略是错误的！** 如果某次请求中，向量召回质量极高、热门召回用户已看过，固定配额会强行丢弃高质量结果，浪费优质流量。

**正确方案：打破通道隔离，全局混排截断**
- 将不同召回源的 Score 映射到统一量纲，进行全局排序竞争
- 所有候选物品在同一个池子里竞争 Top 500
- 每个通道只保证**最低保底数量**，其余完全由质量分数决定

**核心思想：** 推荐系统是多路召回+统一排序，让排序层来决策最终展示，而不是召回层各自为政。

---

### 4. 向量召回（余弦相似度0~1）和热门召回（热度分几千几万）如何融合？

**答案要点：**

**方案一：归一化（Normalization）**
- Min-Max 归一化：将各路召回分数映射到 [0,1]
- Z-Score 标准化：减去均值除以标准差

**方案二：基于渠道转化率的加权**
- 离线统计各路召回在过去一段时间的 CTR/CVR，作为该路召回的权重系数

**方案三：轻量级模型融合**
- 使用 LR 或 GBDT，将各路召回的原始分+来源标签输入，预测粗略 CTR

**兜底策略：**
- 通过 Item ID 去重（同一商品被多路召回了只保留一次）
- 强插补足：热门/新品队列作为兜底，保证覆盖率

### 5. 如何处理超长用户行为序列（10k+行为）？

**答案要点（分阶段）：**

**阶段一：截断（Truncation）**
- 只保留最近 N 个行为（如50/100个），简单但会丢失远期兴趣信号

**阶段二：记忆网络（Memory）**
- 用 GRU/LSTM 压缩历史行为，输出固定长度的压缩向量

**阶段三：检索式建模（Search-based）——最前沿**
- **SIM（Search-based Interest Model）**：先从10k历史中检索出与 Target Item 最相关的 Top-K 个子序列
- **Hard Search**：利用商品的 Category ID 或 Brand ID 建立倒排索引，精准命中
- **Soft Search**：利用向量索引（如 ALIAS 或 HNSW）进行近邻搜索，O(logN) 复杂度
- 将 O(N) 全量 Attention 降低为 O(logN) 或 O(K)

**面试加分点：** 提到阿里 MIMN（Multi-Channel Memory Network）、美团 SIM 等工业实践。

### 6. 局部敏感哈希（LSH）原理是什么？用于哪些场景？

**答案要点：**

**核心思想：** 将相似的输入映射到相同的"桶"中，从而实现近似最近邻检索。

**原理：**
- 使用一组随机超平面将高维向量空间划分成多个区域
- 每个向量被映射为一个**二进制签名（0/1）**
- 相似向量的签名大概率相同，被映射到同一桶

**LSH 在推荐系统中的应用：**
- **向量召回加速**：替代全量内积计算，先用 LSH 定位候选桶，再精确计算
- **去重检测**：快速发现相似的物品/内容
- **多样性采样**：通过 LSH 签名相似度引导生成多样候选集

**与 Faiss 的关系：** Faiss 底层也使用 PQ（Product Quantization）+ IVF（倒排索引）结合，本质是更工程化的 LSH 思想。

### 7. Wide&Deep 与 DeepFM 的本质区别是什么？

**答案要点：**

| 维度 | Wide & Deep | DeepFM |
|------|-------------|--------|
| 核心结构 | Wide（LR）+ Deep（DNN） | FM + Deep（DNN） |
| 特征工程 | **依赖人工**：需专家经验构造交叉特征 | **端到端自动**：FM 自动学习二阶特征交叉 |
| 低阶交互 | Wide 部分负责记忆（Memorization） | FM 显式建模二阶交互 |
| 高阶交互 | Deep 部分负责泛化（Generalization） | Deep 部分负责泛化 |
| 参数共享 | 通常不共享 Wide 和 Deep | FM 和 Deep **共享同一套 Embedding** |

**DeepFM 的核心优势：** 不需要人工特征工程，FM 层自动捕获低阶特征交叉，同时 Deep 层负责高阶泛化，且两端共享 Embedding 使底层特征表达更充分。

### 8. 为什么Deep网络已经很强，还需要Wide或FM部分？

**答案要点：**

**"过度泛化"风险：**
- Deep 网络将 Embedding 映射到稠密空间，对于**从未出现或极少出现的特征组合**，可能给出非零的预测值（ hallucination）
- 例如：用户从未同时点击过"显卡"和"婴儿车"，Deep 可能误判为有关联

**学习效率问题：**
- DNN 擅长学习**加性特征**，但对于显式的**乘法关系（特征交叉）**，需要极深的网络和海量数据才能逼近
- FM 结构通过显式内积运算直接建模二阶交互，比多层 ReLU 逼近乘法**高效得多**

**Wide 的作用：** 补充"记忆"能力，处理高频、简单、确定性的规则，如"安装了App就推广告"这类直接因果关系。

---

### 9. DIN 为什么比简单Pooling好？Attention计算压力如何解决？

**答案要点：**

**为什么 DIN 更优：**
- **Pooling 的局限**：无论当前推荐什么商品，Sum/Average Pooling 输出的是固定的混合向量，无法区分用户对不同候选商品的兴趣差异
- **DIN 的解法**：引入注意力机制，根据**当前候选商品（Target Item）**反向激活历史行为
- 当候选商品是"鼠标"时，"键盘"权重高、"洗面奶"权重接近零 → 实现「千物千面」

**Attention 计算压力（序列变长后）：**
- Attention 复杂度 O(N×K)，N=历史行为数，K=候选商品数
- 精排阶段候选商品多（上百个），每个都要算 Attention，确实压力很大

**工业解法：**
- **序列截断**：只保留最近50~100个行为
- **近似计算**：使用局部敏感哈希或聚类中心近似
- **与候选商品解耦**：在精排前先压缩用户兴趣向量（如SUM pooling），再与各候选商品交互
- 实际落地时，序列长度通常控制在 50~200

### 10. 粗排为什么不使用Pair-wise模型？

**答案要点：**

| 原因 | 说明 |
|------|------|
| **效率问题** | 每对物品生成训练样本，数据量膨胀 N×N 倍，粗排阶段候选物品数量（千~万级）使得组合爆炸 |
| **可扩展性差** | 粗排需要实时处理大量候选物品，pair-wise 的计算复杂度无法满足延迟要求 |
| **优化目标不匹配** | Point-wise 更直接优化 AUC/NDCG 等全局指标；Pair-wise 优化相对排序，但粗排需要的是快速初筛 |
| **实现简单** | Point-wise 可复用精排模型结构，工程成本低 |

**实际做法：** 粗排通常用简化的双塔 + 轻量特征（不超过精排），用 Point-wise 训练，保证延迟 <10ms。

### 11. 排序任务为什么建模为二分类而不是多分类？

**答案要点：**

**精排层：曝光→点击建模为二分类**
- 曝光空间中，只有"点击"和"未点击"两种标签
- 二分类（CTR/CVR）直接对应业务指标，预测概率可参与多目标融合公式
- 多分类要求输出各类别的概率，但排序任务不需要区分"未点击是因为不喜欢还是因为没看到"

**召回层：多分类建模**
- 召回阶段在 item 候选池（百万级）上做分类，标签为具体 item id
- 使用负采样（1: N-1）形成近似多分类问题
- Softmax 输出的概率分布直接代表用户对每个物品的偏好程度

### 12. DeepFM 中 FM 层和 Deep 层如何共享 Embedding？

**答案要点：**

- **输入层共享**：所有稀疏特征（user id、item id、category id 等）经过 Embedding 层，映射到同一个低维稠密向量空间
- **FM 分支**：各特征的 Embedding 两两做内积，计算二阶交叉项
- **Deep 分支**：各特征的 Embedding 拼接后送入 DNN
- **两端共享同一套 Embedding**：FM 的隐向量和 Deep DNN 的输入向量来自同一个 Embedding Table，训练时反向传播同时更新

**共享 Embedding 的好处：**
- 底层特征表示在不同任务间互相增强（迁移学习效果）
- 减少参数量，避免过拟合
- CTR 和 CVR 任务联合训练时，共享 Embedding 尤其有效

### 13. DCN 和 DeepFM 的特征交叉有什么异同？

**答案要点：**

**相同点：**
- 都同时建模低阶和高阶特征交叉
- 都不需要人工特征工程

**不同点：**

| 维度 | DeepFM | DCN（Deep & Cross Network） |
|------|--------|------------------------------|
| 低阶交叉 | FM 层（内积，显式） | Cross Network（第0层就是输入本身） |
| 高阶交叉 | FM 有限阶数（通常只看二阶） | Cross Network 显式构建任意高阶交叉 |
| 表达能力 | 隐式+显式结合 | Cross 层是显式特征交叉，能力上限更高 |
| 复杂度 | FM + Deep 双分支 | 并行 Cross + Deep |

**DCN 的 Cross 层优势：** 第 L 层输出 = 第 L-1 层输出 × 输入转置 + 第 L-1 层输出，通过不断加法操作显式堆叠高阶交叉，参数量远小于同等深度的 Deep 网络。

### 14. 直接用点击后转化数据训练CVR模型，会有什么问题？

**答案要点（两个核心问题）：**

**样本选择偏差（Sample Selection Bias, SSB）：**
- CVR 模型只在"点击"样本上训练，但在推断时需要对所有"曝光"样本打分
- 训练空间与推断空间的数据分布不一致——模型只见过"被选中的"，不知道"被淘汰的"

**数据稀疏（Data Sparse, DS）：**
- 点击样本本身就只占曝光的一小部分，而转化样本更是少之又少
- 直接训练 CVR，正样本极其稀疏（可能 <1%），模型难以拟合

**ESMM 的解决方案见下题。**

---

### 15. ESMM 如何同时解决 SSB 和 DS 问题？

**答案要点：**

**ESMM（Entire Space Multi-Task Model）核心思想：**
- 不直接训练 CVR，而是利用概率链式法则引入两个辅助任务：CTR 和 CTCVR
- 公式：`p(conversion) = p(click) × p(convert|click)`
- 即：`pCTCVR(x, y=1, z=1) = pCTR(x) × pCVR(x)`

**解决 SSB：**
- ESMM 在**整个曝光空间**上训练 CTR 和 CTCVR 任务，避开了只在点击样本上训练导致的分布偏差

**解决 DS：**
- CVR 网络共享了 CTR 网络的 **Embedding 层**，底层特征表达得到充分训练（CTR 数据量远大于 CVR）
- CVR 隐式学到了 CTR 的知识，减少了对转化样本数量的依赖

---

### 16. MMOE 训练中一个任务Loss快一个难学，怎么办？

**答案要点：**

**问题本质：** 这是多目标优化中的**梯度优势/梯度冲突**问题
- 简单任务的梯度幅值远大于困难任务
- 共享层的参数更新主要被简单任务主导，困难任务被压制

**MMOE 的对策：**
- 通过引入**门控机制（Gating Network）**，让不同任务根据输入动态选择 Expert 的组合
- 每个任务有自己的 Gate，**选择性**地利用 Expert，减少任务间干扰

**工程解法：**

1. **Loss 加权策略：**
   - `Uncertainty Weighting`：为每个任务引入可学习的噪声参数，自动调整权重
   - `GradNorm`：基于梯度范数动态平衡各任务梯度

2. **架构升级：**
   - 使用 **PLE（Progressive Layered Extraction）**：在 MMOE 基础上增加了任务特有Expert层，避免共享Expert被主任务主导
   - 腾讯 PLE 在 CGC（Customized Gate Control）层为每个任务维护独立的 Expert 组合

---

### 17. PLE 和 MMOE 相比有什么改进？

**答案要点：**

**MMOE 的问题：**
- 所有任务共享同一组 Expert
- 当任务相关性低时，简单任务会主导 Expert 的更新方向，困难任务被忽视

**PLE（Progressive Layered Extraction）的改进：**

```
┌─────────────────────────────────────────┐
│  Shared Experts（共享专家层）            │
│  + CGC Layer（Customized Gate Control）  │
│    每个任务有独立的 Expert 组合          │
│  + Task-Specific Experts（任务专属 Expert）│
└─────────────────────────────────────────┘
```

- **任务专属 Expert**：每个任务有自己独立的 Expert 子集，保证不被其他任务抢走资源
- **渐进式提取**：底层是共享 Expert（学习共性），顶层是任务专属 Expert（学习个性）
- **门控精细化**：每个任务的 Gate 可以精细地组合所有 Expert（共享+专属）

**一句话总结：** MMOE 让 Expert 被所有任务竞争，PLE 让 Expert 有公有私有之分，兼顾共性与个性。

### 18. 完全按精排pCTR排序会出现什么问题？有哪些多样性解法？

**答案要点：**

**问题：**
- **信息茧房**：持续推荐相似内容，用户兴趣收窄，平台失去探索性
- **曝光马太效应**：热门物品越来越热，尾部物品永远没有曝光机会
- **用户疲劳**：内容同质化导致用户体验下降，长期留存受损

**解决方案：**

1. **硬规则（滑动窗口）：** "每5个展示位中，同一类目内容不超过2个"，强制保障多样性底线

2. **MMR（Maximal Marginal Relevance）：**
   - 选择下一个物品时，不仅考虑相关性 pCTR，还要**减去**它与已选物品列表的相似度
   - `Score = α × pCTR - (1-α) × max(similarity(item, selected_items))`

3. **DPP（Determinantal Point Process）：**
   - 数学上更优雅的增加集合多样性的方法
   - 通过行列式点过程建模选中集合的多样性，在候选物品集合中选取使多样性最大化的子集

4. **上下文bandit（EE探索利用平衡）：** Epsilon-Greedy、UCB、Thompson Sampling

### 19. 上了多样性策略后CTR跌了怎么办？

**答案要点：**

**短期接受，长期收益：**
- 单次请求的 Session CTR 可能下降 1%~3%，这是正常的短期代价
- 引入多样性后，惊喜度（Serendipity）和用户留存（Retention）会提升

**如何评估：**
- 必须引入**专门衡量多样性**的指标：
  - 类目覆盖率（Coverage）
  - ILD（Inter-List Diversity）：列表内物品间的平均距离
  - 新物品曝光占比
  - 尾部物品曝光率

**业务规则冲突处理（分层重排）：**
```
第一层：硬逻辑（业务规则兜底，如去重、同类目限制）
第二层：MMR/DPP 算法（多样性优化）
第三层：pCTR 排序（相关性保底）
```

**参数调节：** MMR/DPP 中有一个超参数控制多样性强度（α），逐步调参 AB 测试找到最优平衡点。

### 22. 新物品冷启动怎么处理？有哪些具体技术手段？

**答案要点：**

**核心矛盾：** 新物品没有用户行为数据，无法靠协同过滤召回

**技术手段：**

1. **语义向量生成（Content-based Embedding）：**
   - 使用预训练模型（Word2Vec、BERT）从物品描述/标题/标签生成向量
   - 在向量空间中，新物品可以找到相似的高热物品，作为初始曝光对象

2. **跨平台迁移：**
   - 新物品在上线其他平台（如抖音先发、西瓜再发），利用已有行为数据初始化

3. **物品属性聚类：**
   - 将新物品属性（类目、品牌、价格段）与已有物品聚类，找同 cluster 中的"代理物品"

4. **EE 策略强制探索：**
   - 给新物品固定比例的探索流量（如新物品曝光占比 = 5%）
   - 配合 Thompson Sampling 确定每个新物品的具体曝光量

5. **用户画像匹配（Content-based + Collaborative）：**
   - 新物品推给与它画像匹配度高的用户群体（如：同年龄段、同一地域）

### 24. 直接用LLM做精排的可行性如何？有哪些替代方案？

**答案要点：**

**直接做精排的问题（两道天堑）：**

1. **时延瓶颈：** 精排层需在几十毫秒内处理数百~上千个候选物品，LLM 推理速度通常在秒级，成本极高

2. **成本问题：** 对每请求的每个候选品都做 LLM 推理，计算成本是传统 ID 类模型的数千倍

**替代方案（主流工业路线）：**

| 方案 | 描述 |
|------|------|
| **离线/异步处理** | 将 LLM 推理放在离线阶段（如生成物品语义向量、建立知识图谱） |
| **知识蒸馏（Distillation）** | 用大模型作为 Teacher，训练轻量 Student 模型（如用 GPT-4 生成标签，训 BERT-small） |
| **语义召回 + 精排** | LLM 理解用户 query 后做语义层面的意图匹配（召回层），精排仍用传统模型 |
| **两阶段生成** | 粗排过滤到 Top50 后，LLM 做候选重排（只处理50个，延迟可接受） |

**一句话总结：** LLM 短期不会替代精排，更现实的路径是**LLM赋能特征/语义层，精排继续用传统深度模型**。

### 25. 离线AUC提升0.5%，上线后业务指标反而下跌，可能原因是什么？

**答案要点（核心归因分析框架）：**

**1. 特征线上线下不一致（Training-Serving Skew）：**
- 离线训练数据经过清洗修正，线上使用的是实时流数据
- 特征计算逻辑在训练/服务时可能存在差异（如 user 特征用不同时间窗口）
- **排查**：检查特征提取逻辑的代码复用，做 Log Replay 对比

**2. 样本选择偏差（SSB）严重：**
- 模型在"曝光点击"样本上训练，线上需对海量候选集预测
- 模型学会了在"高个子"里拔将军，无法在"芸芸众生"中识别潜力股

**3. 特征穿越（Data Leakage）：**
- 使用了"当次请求的转化结果"作为特征
- 序列特征中包含了样本发生时间之后的行为（未来信息泄露）

**4. 评估目标与业务目标不匹配：**
- AUC 衡量排序能力，不直接衡量业务价值
- 模型可能倾向于把极热门物品排在前面，AUC 高但对业务帮助有限

**排查清单：**
- ✅ 特征一致性校验（Log Replay）
- ✅ 校准性检查（Calibration）：看 COPC 指标
- ✅ 穿越特征排查（Feature Importance 分析）
- ✅ 测试集分布校验（与线上实际流量分布对比）

### 【召回层】Q1：双塔模型（DSSM）原理是什么？召回与粗排阶段有何差异？

#### 参考答案

**双塔模型（Two-tower / DSSM）核心原理：**

将用户侧（User）和物品侧（Item）特征分别输入两个独立的深度神经网络，分别输出固定维度的 Embedding 向量，在线服务时通过计算两个向量的**内积（Dot Product）** 或 **余弦相似度** 来衡量匹配程度。

```
用户特征 → [User Tower DNN] → User Embedding
                                  ↕ 内积/Cosine
物品特征 → [Item Tower DNN] → Item Embedding
```

关键设计：**解耦（Decoupling）** —— User Tower 和 Item Tower 在模型推断前完全独立，因此物品向量可以**离线预计算**，存入 Faiss/Milvus 等向量索引数据库，支持毫秒级全库 ANN 检索。

**召回 vs. 粗排的差异：**

| 维度 | 召回（Recall） | 粗排（Rough Rank） |
|------|--------------|-------------------|
| **候选集规模** | 百万～亿级 | 召回后几千～几万 |
| **负样本策略** | 随机采样 + Hard Negative | 曝光未点击（接近精排） |
| **线上预测** | User向量 × ANN检索 | Item向量KV存储，逐个内积打分 |
| **精度要求** | 粗筛，保召回率 | 精筛，保精排前序质量 |
| **效率要求** | 极高（毫秒级） | 较高（百毫秒级） |

**面试加分点**：指出粗排的负样本要接近精排分布，而召回需要引入随机负样本让模型"见识"全量库中的噪声分布。

### 【召回层】Q2：召回阶段负样本如何选择？为什么不能用"曝光未点击"？

#### 参考答案

**负样本选择的本质逻辑：**

召回阶段需要从**全量候选集**（百万/千万级）中区分用户感兴趣的物品和完全不相关的物品。如果只用"曝光未点击"数据训练，会产生严重的**样本选择偏差（Sample Selection Bias, SSB）**——模型只见过"精选集中的相对差异"，缺乏对全库随机物品的鉴别能力。

**工业界负样本策略：**

| 策略 | 做法 | 适用场景 |
|------|------|---------|
| **全局随机负采样** | 从全量候选集中随机抽取 | 必选，让模型认识"完全不相关" |
| **In-batch负采样** | Batch内其他物品作为负样本（Google双塔） | 高效利用计算 |
| **Hard Negative** | 选取"被召回了但未被点击"的较难负样本 | 提升模型区分能力 |
| **曝光未点击** | 真实曝光但未点击样本 | **不推荐单独用于召回** |

**进阶回答（面试追问）：** Hard Negative 的挖掘方式包括：
- 训练中期选取上一版模型打分较高但未被点击的样本
- 引入曝光比例加权（如Unbiased Learning框架）
- 结合对比学习（SimCSE等）自动寻找难负例

### 【召回层】Q3：多路召回如何融合截断？动态配额怎么做？

#### 参考答案

**多路召回存在的问题：**

固定配额（如每路取100个）会导致：热门召回挤占流量、弱势召回永远得不到优化、不同场景下各路效果差异大。

**融合方案对比：**

| 方案 | 方法 | 缺点 |
|------|------|------|
| 固定配额 | 每路取固定数量 | 无法动态适应 |
| **归一化融合** | Min-Max/Z-Score归一化到[0,1] | 受异常值影响，物理意义不一致 |
| **转化率加权** | 统计各路召回过去7天CTR/CVR作为权重 | 静态权重，无法实时调整 |
| **轻量级模型融合** | LR/GBDT预测各路召回的粗粒度CTR | 本质升级为"粗排" |
| **统一评分+全局混排** | 所有候选按统一Score排序后截断 | 效果最好但实现复杂 |

**推荐回答框架：**
```
Final Score = α_channel × Normalized_Score(召回分)
```
- α_channel 通过在线实验动态调参
- 结合业务规则（强插保量、去重、类目打散）
- **最优解是打破通道隔离**，用全局视角统一排序

### 【召回层】Q4：双塔模型为什么不能做底层特征交叉？损失了什么？

#### 参考答案

**不能做底层交叉的根本原因：**

- **计算约束**：底层交叉需要将用户特征与百万级物品特征逐一组合并前向计算，在几十毫秒内不可行
- **预计算前提**：双塔结构的核心价值是 Item 向量可以离线预计算并建立索引，若底层就有交叉，则无法预计算，必须实时对每个Item做完整推理

**损失的精度：**
- **细粒度特征交互**：User侧和Item侧特征在最后内积时才交互，底层交叉的细粒度信号（如"25岁男性+游戏鼠标"）无法被捕捉
- **用户-物品组合特征**：如"该用户历史点击品牌的商品"这类组合特征，在双塔中无法直接建模

**工程-精度权衡的本质：** 双塔模型以牺牲部分底层特征交叉精度，换取了全库高效检索的能力。

### 【召回层】Q5：对比学习视角下，双塔模型本质是什么？温度超参和L2 Norm的作用？

#### 参考答案

**双塔 = 对比学习系统：**
- 正例：用户点击过的Item
- 负例：In-batch负例（Batch内其他Item）
- Loss：**InfoNCE Loss**（即推荐中Pairwise Loss的拓展）
- 本质：让正负例在Embedding空间中被正确区分

**L2 Norm的作用：**
将User/Item Embedding映射到长度为1的**单位超球面**，增加训练稳定性和投影空间的**线性可分性**，避免某些方向 Embedding 模长过大导致空间不均匀。

**温度超参（Temperature）的作用：**

```
InfoNCE Loss = -log exp(sim(u,i⁺)/τ) / Σ exp(sim(u,i)/τ)
```

- **小温度（τ↓）**：放大区分度，聚焦 **Hard Negative**（将难区分的负例推得更远），无需专门挖掘Hard负例
- **大温度（τ↑）**：更均匀分布，增强探索性
- **工程建议**：通常 τ ∈ [0.05, 0.2]，调参收益显著

### 【排序层】Q6：Wide&Deep 与 DeepFM 本质区别是什么？

#### 参考答案

| 维度 | Wide & Deep | DeepFM |
|------|------------|--------|
| **Wide部分** | LR（需人工构造交叉特征） | FM（自动学习二阶特征交叉） |
| **特征工程** | 依赖专家经验构造交叉特征 | 端到端自动建模 |
| **低阶交互** | Wide负责记忆（Memorization） | FM通过隐向量内积显式建模 |
| **高阶交互** | Deep负责泛化（Generalization） | Deep部分负责泛化 |
| **参数共享** | Wide和Deep的Embedding通常不共享 | **FM和Deep共享Embedding** |

**深层追问：为什么还需要Wide/FM部分？（常见致命追问）**

1. **"过度泛化"风险**：Deep网络将Embedding映射到稠密空间，对从未出现或极少出现的特征组合可能给出非零预测。但推荐场景中某些稀疏组合代表极强负/正反馈（如"特定商家+特定用户"的超高转化），需要"死记硬背"
2. **乘法关系效率**：DNN擅长学习加性特征，但对**显式特征交叉（乘法关系）**需要极深网络和海量数据才能逼近；FM通过显式内积运算直接建模二阶交互，数学上高效得多

### 【排序层】Q7：DIN和普通Pooling的区别？为什么引入Target Attention？

#### 参考答案

**传统Pooling的局限：**
- Sum/Average Pooling 生成**固定长度用户向量**，无论推荐什么商品，输出都相同
- 无法区分用户历史行为中的不同兴趣点

**DIN的核心解法（Target Attention）：**

```python
# 注意力权重 = f(User_History_Item, Target_Item)
attention_weight = softmax(MLP(concat(user_hist_emb, target_item_emb)))
weighted_hist_emb = Σ(attention_weight × hist_item_emb)
```

- 根据**当前候选商品（Target Item）**反向激活历史行为
- 候选为"鼠标"→"键盘"权重高，"洗面奶"权重接近零
- 候选为"毛巾"→权重分配完全不同
- 实现**"千物千面"**的用户表达

**面试加分点：** 指出DIN是**局部激活**（而非全局注意力），只激活相关的历史行为，保留了一定的用户兴趣多样性表达。

### 【排序层】Q8：DIN序列长度增加后计算压力如何解决？超长序列（10k+）怎么处理？

#### 参考答案

**计算压力分析：**

| 方案 | 序列长度N × 候选数M | 复杂度 |
|------|-------------------|--------|
| Pooling模式 | N × 1（用户向量只需算一次） | O(N) |
| Attention模式 | N × M（每个候选都与历史交互） | O(N×M) |

50个历史行为 × 1000个候选商品 = 50,000次交互，随N线性甚至超线性增长。

**超长序列解决方案演进：**

| 阶段 | 方法 | 模型 | 复杂度 |
|------|------|------|--------|
| 一 | 截断（保留最近50-100个） | 简单粗暴 | O(1) |
| 二 | 记忆网络压缩 | DIEN（GRU序列建模） | O(N) |
| 三 | **检索式建模** | **SIM**（Search-based Interest Model） | **O(logN)或O(K)** |

**SIM具体做法：**
- **Hard Search**：用商品Category/Brand ID建立倒排索引，直接检索同类历史行为
- **Soft Search**：用向量索引（ALIAS/HNSW）进行近邻搜索，找出与候选最相关的历史子序列
- **收益**：将O(N)全量Attention降低为O(logN)

### 【多目标】Q9：直接用点击转化数据训练CVR模型有什么问题？SSB和DS是什么？

#### 参考答案

**两大核心问题：**

1. **样本选择偏差（Sample Selection Bias, SSB）**
   - CVR模型只在**点击样本**上训练（Click Space）
   - 推断时需对**全量曝光样本**打分（Entire Space）
   - 训练空间与推断空间分布不一致，导致严重偏差

2. **数据稀疏（Data Sparsity, DS）**
   - 点击样本只占曝光一小部分，转化样本更少
   - 直接训练CVR模型，正样本极其稀疏，模型难以收敛

**形象比喻**：想象只在一个城市的"去过该餐厅且愿意评价"的顾客中训练美食推荐模型，然后用它对全城所有路过餐厅的人做推荐——分布完全不匹配。

### 【多目标】Q10：ESMM如何通过全空间建模同时解决SSB和DS？

#### 参考答案

**ESMM核心思想：** 不直接训练CVR p(z|y,x)，而利用概率链式法则引入两个辅助任务（CTR和CTCVR）：

```
p(转化|点击, x) = pCTCVR / pCTR = pCTR×pCVR / pCTR = pCVR（隐式学习）
```

**解决SSB（全空间训练）：**
- CTR和CTCVR两个任务在**全量曝光数据**上训练
- 避开只在点击样本上训练导致的分布偏差
- 推断时直接用 `pCVR = pCTCVR / pCTR`

**解决DS（Embedding共享）：**
- CVR网络共享CTR网络的Embedding层
- CTR任务样本量远大于CVR，底层特征表达得到充分训练
- 相当于用CTR大样本任务为CVR小样本任务提供"辅助训练"

**面试加分话术：** 不要简单说"ESMM增加了数据量"，要强调它通过**隐式学习**CVR，将问题转化为两个全空间任务的组合。

### 【多目标】Q11：MMOE的门控网络如何工作？为什么比共享底层参数更好？

#### 参考答案

**MoE（共享门控）：**
```
shared_gate(x) = softmax(W_g·x)
output = Σ(g_i × Expert_i(x))
```
所有任务共享同一个门控，灵活度有限。

**MMOE（多门控）：**
```
gate_k(x) = softmax(W_k·x)   # 每个任务k有独立门控
output_k = Σ(gate_k_i × Expert_i(x))
```
每个任务独立决定如何组合N个Expert。

**为什么更好：**
- 任务相关性低时，共享门控会被"平均"，导致"跷跷板"现象
- MMOE通过独立门控，让CTR任务倾向于选择某些Expert，CVR任务选择另一些Expert
- Expert参数完全共享，实现**"专家共享 + 门控解耦"**的最优平衡

**面试追问回答（梯度冲突处理）：**
- Loss加权：Uncertainty Weighting、GradNorm
- 架构升级：**PLE（Progressive Layered Extraction）**，分离"共享Expert"和"任务独有Expert"，在底层共享知识，顶层任务解耦

### 【重排】Q12：MMR和DPP算法如何解决推荐多样性？

#### 参考答案

**MMR（Maximal Marginal Relevance）：**
```
Score(i) = λ × Relevance(u,i) - (1-λ) × max[Similarity(i, s), s∈SelectedItems]
```
- λ是调节阀，越小越倾向于探索新类目
- 贪心算法，逐步选择当前综合得分最高的Item
- **缺点**：局部贪心，可能无法达到全局最优

**DPP（Determinantal Point Process）：**
- 用**行列式**衡量所选集合的"体积"
- 体积越大 = 集合内多样性越高
- 保证选出的**集合整体**多样性最优（全局视角）
- 适合精排候选集较小时使用（计算复杂度较高）

**实际工程建议：** 简单规则打散（滑动窗口分桶）+ 惩罚项（Penalty Score）往往是性价比最高的选择

### 【冷启动】Q13：用户冷启动和物品冷启动有哪些系统化解法？

#### 参考答案

**用户冷启动：** 新用户注册，无历史行为

| 阶段 | 方法 | 说明 |
|------|------|------|
| 规则 | 全局热度兜底 | 推送全站高点击、高普适性内容 |
| 规则 | 属性映射（Demographic Mapping） | 用注册信息（年龄/性别/设备/地域）映射到细分人群 |
| 模型 | Bandit算法（UCB/Thompson Sampling） | 给不确定性高的物品更多展示机会 |
| 内容 | Embedding相似度召回 | 用新用户的基础属性找相似用户群体 |

**物品冷启动：** 新物品上架，无交互数据

| 阶段 | 方法 | 说明 |
|------|------|------|
| 内容 | 文本/CV特征提取 | 用NLP/CV模型提取物品向量，通过向量检索找高热相似品 |
| 探索 | EE（Exploitation-Exploration） | UCB上探索流量，公平分配给新物品 |
| 特征 | LLM辅助内容理解 | 用大模型提取高质量Tags，解决冷物品内容缺失问题 |
| 策略 | 强插+保量 | 新物品强插进入推荐列表，确保曝光量 |

**评估核心：长期留存而非短期点击**（次日留存率/七日留存率 > CTR）

### 【综合】Q14：离线AUC提升0.5%但线上A/B测试CTR下跌，分析原因？

#### 参考答案

**排查清单（必背框架）：**

| 原因类型 | 具体问题 | 排查方法 |
|----------|----------|---------|
| **特征穿越** | 使用了当次请求的转化率或序列特征中包含未来行为 | 特征重要性分析，查找异常高的特征 |
| **线上线下不一致** | 离线用DW数据，线上用实时流数据，存在延迟/缺失/格式差异 | Log Replay逐条比对 |
| **样本选择偏差** | 模型在"曝光点击"样本上训练，对全量候选集预测能力弱 | 检查训练样本空间与预测空间差异 |
| **评估目标不匹配** | AUC衡量排序能力，热门物品天然优势 | 负样本策略是否失效 |
| **基线不对齐** | 预估分数与实际CTR偏离（COPC指标下降） | COPC = E[PCTR] / Actual CTR ≈ 1? |

**COPC指标（Calibration of Predicted CTR）：**
```
Expected PCTR ≈ Actual CTR（模型校准良好）
Expected PCTR >> Actual CTR（高估，模型过于自信）
```

**核心结论：** 资深工程师不仅关注模型结构，更关注**样本策略和评估体系**，引入离线Replay评估缩小与线上的差距。

### 【综合】Q15：LLM能否直接用于精排？工程约束和落地点？

#### 参考答案

**直接用于精排的工程约束（不可行）：**

| 约束 | 分析 |
|------|------|

**当前可行的落地点：**

| 落地点 | 具体做法 |
|--------|---------|
| **内容理解/特征工程** | 用LLM提取物品非结构化数据（文本/图片描述）的高质量语义Tags/Dense Vector |

**核心观点：** ID特征模型擅长捕捉"协同过滤"信号，LLM基于"语义"，两者**不是替代关系而是融合关系**。未来趋势是大模型语义知识蒸馏到小模型中。

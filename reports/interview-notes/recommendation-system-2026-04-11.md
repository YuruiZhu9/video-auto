### 【召回层】Q1：双塔模型（DSSM）原理是什么？负采样为什么不能用"曝光未点击"？

#### 参考答案

**双塔模型核心原理：**

将用户特征（User Features）和物品特征（Item Features）分别输入两个独立的深度神经网络（Tower），最终分别输出固定维度的 Embedding 向量。在线服务时，通过计算两个向量的**内积（Dot Product）** 或 **余弦相似度** 来衡量匹配程度。

```
用户特征 → [User Tower DNN] → User Embedding
                                  ↕ 内积/Cosine
物品特征 → [Item Tower DNN] → Item Embedding
```

**关键设计：解耦（Decoupling）**
- 用户塔和物品塔在模型推断前完全独立
- 物品向量可**离线预计算**，存入 Faiss/Milvus 等向量索引
- 在线只需计算用户塔，然后做 ANN 检索，时间复杂度 O(log n)

---

**负采样策略（核心追问）：**

❌ **不能用"曝光未点击"的原因：样本选择偏差（SSB）**

召回层的目标是从全量库（百万/千万级）中捞出候选集，而"曝光未点击"的数据仅来自上一轮推荐系统筛选出的"精选集"。如果只用这些数据训练，模型实际上是在学习"如何在高相关物品中区分细微差别"，而不是"如何从海量噪声中区分相关物品"。

✅ **正确负采样策略（三层）：**

| 层次 | 方法 | 说明 |
|------|------|------|
| **随机负采样** | 全库随机选负样本 | 让模型"见识"完全不相关的物品 |
| **困难负样本（Hard Negatives）** | 选"被召回了但未被点击"或"相关性分高但业务判定为负"的样本 | 强迫模型学习细粒度差异 |
| **曝光未点击** | 作为辅助信息而非训练样本 | 用于分析而非直接训练 |

> **面试加分点**：提到 AIR（Adaptive Item Retrieval）或对比学习regularization如何优化负样本质量。

### 【召回层】Q2：多路召回如何做融合截断？动态配额方案有哪些？

#### 参考答案

**为什么"固定配额"是错的？**

- 如果某次请求中向量召回质量极高，固定配额会强行丢弃高质量结果
- 热门召回可能全是用户已看过的，浪费下游计算资源

**融合方案：**

**方案一：归一化（Normalization）**
- Min-Max 或 Z-Score 将各路分数映射到 [0,1]
- 缺点：受异常值影响，无法解决物理意义不一致问题

**方案二：基于渠道转化率的加权（Channel-wise Weighting）**
- 离线统计各路召回过去7天的点击率（CTR）或转化率（CVR）
- `Final Score = α_channel × Normalized_Score`
- 物料多路出现时，加权分数相加，体现"多路共识"

**方案三：轻量级粗排模型（Stacking）**
- 用 LR 或 GBDT 模型，将各路原始分 + 来源标签 + 基础特征输入
- 预测一个粗略 CTR，本质上是将"召回融合"升级为"粗排"

**兜底策略：**
- 去重：通过 Item ID 去重
- 强插补足：热门/新品队列补充候选集

### 【召回层】Q3：双塔模型为什么不能做底层特征交叉？预计算的工程意义？

#### 参考答案

**核心原因：计算约束**

召回层候选集通常是百万量级。如果在底层做用户-物品特征交叉，那么对每个用户请求，必须将该用户特征与库里几百万个物品逐一组合并进行网络前向计算——在几十毫秒的响应时间内完全不可行。

**解耦的本质：预计算（Pre-compute）**

只有当 User Tower 和 Item Tower 独立时，才能：
1. 离线阶段算好所有 Item Embedding
2. 建立向量索引（Faiss HNSW/ScaNN）
3. 在线服务时只计算用户塔，然后 ANN 检索

**代价：牺牲了底层特征交叉的精度**

这是工业界的经典权衡：**用精度换全库检索效率**。

### 【排序层】Q4：Wide&Deep 与 DeepFM 本质区别？为什么Deep外还需要Wide/FM？

#### 参考答案

**核心差异对比：**

| 维度 | Wide & Deep | DeepFM |
|------|-------------|--------|
| **核心结构** | Wide (LR) + Deep (DNN) | FM + Deep (DNN) |
| **特征工程** | **依赖人工**设计交叉特征 | **端到端自动**学习二阶交叉 |
| **低阶交互** | Wide部分负责记忆（Memorization） | FM部分通过隐向量内积显式建模二阶交互 |
| **高阶交互** | Deep部分负责泛化（Generalization） | Deep部分负责泛化 |
| **参数共享** | Wide和Deep的Embedding通常不共享 | FM和Deep**共享相同Embedding输入** |

**为什么单纯DNN不够，还需要Wide或FM？**

1. **"过度泛化"风险（Over-generalization）**
   - DNN倾向于将Embedding映射到稠密空间，对从未出现的特征组合可能给出非零预测
   - 某些稀疏组合代表极强负反馈/正反馈，需要"死记硬背"

2. **学习效率问题**
   - DNN擅长加性特征，对显式乘法关系（特征交叉）需要极深网络和海量数据才能逼近
   - FM通过显式内积运算直接建模二阶交互，效率远高于DNN隐式学习

**DeepFM的进化**：用FM模块替换Wide模块，实现低阶交叉自动化，不依赖人工特征工程。

### 【排序层】Q5：DIN和普通Pooling的区别？为什么超长序列（10k+）要靠SIM？

#### 参考答案

**普通Pooling的局限：**

将用户历史行为Embedding做 Sum/Average Pooling，假设每个历史行为对当前推荐的贡献等权重。

**DIN的创新：Target Attention**

引入注意力机制，根据**当前候选商品**反向激活历史行为：
- 候选=鼠标时，"键盘"权重变高
- 候选=毛巾时，权重完全相反

**DIN的计算代价：**
- Pooling：用户向量只需算一次，与候选集大小无关
- Attention：50个历史行为 × 1000个候选 = 50,000次交互

**超长序列（10k+）的演进路径：**

| 阶段 | 方法 | 说明 |
|------|------|------|
| 阶段一 | 截断 | 只保留最近N个行为，低频场景可用 |
| 阶段二 | 记忆网络 | 用GRU/LSTM压缩历史 → DIEN |
| 阶段三 | 检索式建模 | SIM：先从10k中检索出Top-K相关子序列 |

**SIM（Search-based Interest Model）核心思路：**
- **Hard Search**：用商品Category/Brand ID建立倒排索引
- **Soft Search**：用向量ANN近邻搜索
- 将 O(N) 全量Attention 降为 O(log N) 或 O(K)

### 【多目标优化】Q6：直接用点击转化数据训练CVR有什么问题？ESMM如何解决？

#### 参考答案

**两个核心问题：**

1. **样本选择偏差（Sample Selection Bias, SSB）**
   - 传统CVR只在"点击"过的样本上训练，但推断时需要对所有"曝光"样本打分
   - 训练空间 ≠ 推断空间

2. **数据稀疏（Data Sparsity, DS）**
   - 点击样本只占曝光一小部分，转化样本更少
   - 直接训练CVR正样本极其稀疏

**ESMM如何解决？**

利用概率链式法则，引入两个辅助任务（CTR、CTCVR），**隐式学习CVR**：

```
p(转化|点击) = pCTCVR / pCTR
即：CVR = CTCVR / CTR
```

- **解决SSB**：在整个曝光空间上训练CTR和CTCVR任务，避开只在点击样本上训练
- **解决DS**：CVR网络共享CTR网络的Embedding层，底层特征表达得到充分训练

> **面试加分点**：ESMM的Loss函数只包含CTR和CTCVR两部分，**不直接训练CVR**，这叫隐式学习（Implicit Learning）。

### 【多目标优化】Q7：MMOE的门控网络如何工作？PLE比MMOE好在哪里？

#### 参考答案

**MMOE（Multi-gate Mixture-of-Experts）核心机制：**

每个任务有自己的门控网络（Gating Network），根据输入动态选择多个Expert的加权组合：

```
y_k = Σ(g_k(x)_i × Expert_i(x))
```

- Expert_i：多个独立的子网络，捕捉不同知识
- g_k(x)：任务k的门控，根据输入x为每个Expert打分
- 不同任务可以"侧重点不同"地利用Expert

**比共享底层好的原因：**
- 简单共享底层会让简单任务（如CTR）主导梯度更新
- MMOE让每个任务自己决定如何组合Expert，减少任务间干扰

**PLE（Progressive Layered Extraction）的改进：**

- MMOE中Expert对所有任务完全共享，部分Expert可能被某些任务"劫持"
- PLE增加**任务专属Expert**和**共享Expert**的层次化提取
- 在上层逐步融合任务专属知识和共享知识，效果更稳定

### 【重排与工程】Q8：上了多样性策略后CTR下跌怎么办？MMR和DPP有何区别？

#### 参考答案

**短期承认，长期坚持：**

多样性对单次请求CTR可能有1-3%的短期下降，但长期对**用户留存、惊喜度（Serendipity）** 有正向价值。

**评估维度（不仅看CTR）：**
- **ILD（类目间隔距离）**：衡量列表内物品多样性
- **类目覆盖率**：推荐列表覆盖了多少不同类目
- **用户次日/7日留存率**：长期健康指标
- **惊喜度**：推荐物品超出用户预期程度

**MMR vs DPP：**

| 维度 | MMR（边际相关性最大化） | DPP（行列式点过程） |
|------|----------------------|-------------------|
| 核心思想 | 贪心选择，每次选"相关性高且与已选最不同"的 | 数学上保证集合整体多样性最优 |
| 优点 | 简单直观 | 全局最优 |
| 缺点 | 贪心，无法达到全局最优 | 计算复杂度较高 |
| 公式 | `Score = λ×Rel - (1-λ)×MaxSim` | 行列式=集合体积 |

### 【综合与开放题】Q9：离线AUC提升但线上A/B下跌，如何诊断？

#### 参考答案

**排查清单（STAR原则）：**

1. **特征线上线下不一致（Training-Serving Skew）**
   - 离线用数据仓库清洗后的数据，线上用实时流数据
   - → 逐条比对特征日志

2. **样本选择偏差（Sample Selection Bias）**
   - 模型在"曝光点击"上训练，但线上要对海量候选预测
   - 学会了在"高个子中拔将军"，却无法在"芸芸众生"中识别潜力股

3. **特征穿越（Data Leakage）**
   - 使用了当次请求的转化率作为特征
   - 序列特征中包含了样本发生时间之后的行为

4. **评估目标与业务目标不匹配**
   - AUC衡量排序能力，不直接衡量业务价值
   - 热门物品排在冷门物品前面 → AUC高但GMV未必高

**COPC（Calibration of Predicted Clicks）指标：**
- 公式：`COPC = 实际CTR / 预测CTR`
- 若COPC ≈ 1，预估校准良好
- 若COPC << 1，模型高估CTR，排序过于激进

### 【综合与开放题】Q10：LLM能否直接用于精排层？有哪些落地点？

#### 参考答案

**直接用于精排：不可行（工程约束）**

- **时延瓶颈**：精排层需在几十毫秒内处理数百~数千候选
- **成本问题**：每次请求每个候选做LLM推理，成本是ID类模型的数千倍

**落地点（现实可行的方案）：**

| 落地点 | 具体做法 |
|--------|----------|
| **特征工程** | LLM对物品非结构化数据（标题/评论/视频字幕）提取高质量Tags或Dense Vector |
| **生成推荐理由** | 根据用户历史+当前推荐物品生成自然语言推荐理由 |
| **数据增强/SFT** | 用LLM构造指令微调数据，辅助小模型学习 |
| **离线/异步处理** | 将LLM推理放在离线阶段或异步链路 |

**LLM vs ID模型的核心差异（面试加分）：**

> "LLM的强项是**泛化**和**零样本推理**，弱项是**特定ID协同信号**的记忆。未来趋势不是LLM完全取代ID模型，而是**两者融合**——如将ID Embedding作为Prompt的一部分注入LLM，或采用RAG架构。"

### 【评估方法】Q11：NDCG vs MAP如何选择？

#### 参考答案

**当相关性标签是0-4分级时，选择NDCG@10**

**原因：**

| 指标 | MAP@10 | NDCG@10 |
|------|--------|---------|
| 相关性处理 | 二元化（需阈值化分级标签，**丢失信息**） | 使用分级增益 `2^rel - 1` |
| 位置衰减 | log标准衰减 | log标准衰减 |
| 归一化 | 无 | 有（IDCG归一化，可跨query比较） |
| 适用场景 | 二元相关性（点击/不点击） | **分级相关性（0-4星等）** |

**DCG公式：**
```
DCG@K = Σ(2^rel_i - 1) / log2(i+1)
NDCG@K = DCG@K / IDCG@K
```

**经验法则：**
- 相关性**点击/不点击** → MAP 或 AUC
- 相关性**多级别（0-4星/0-5分）** → NDCG

## 四、面试技巧总结

1. **跳出单一模型，建立全链路全局视角**：理解Data→Recall→粗排→精排→重排每层的职责和权衡
2. **掌握"权衡思维"**：准确率 vs 延迟 vs 资源成本的取舍，是高频追问方向
3. **展示系统性思维**：上游如何影响下游（负采样策略→精排SSB），下游如何反哺上游（重排多样性→召回配额调整）
4. **关注工程落地**：不仅能设计高精度模型，还能构建稳定、快速且符合业务规则的系统
5. **高频追问方向**：双塔负采样/多路融合 → Wide&Deep vs DeepFM → DIN Attention → ESMM/MMOE → 离线在线Gap → LLM落地点

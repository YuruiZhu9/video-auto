## 一、DAPO：大规模LLM强化学习的四项关键技术

> **论文**：[DAPO: An Open-Source LLM Reinforcement Learning System at Scale](https://arxiv.org/abs/2503.14476)
> **作者**：ByteDance Seed + 清华大学，NeurIPS 2025
> **基座模型**：Qwen2.5-32B → AIME 2024：**50分**（DeepSeek-R1-Zero-Qwen-32B为47分）

### 1.1 问题背景：为什么GRPO训练不稳定？

PPO需要4个模型（Actor/Critic/Reference/Old-Policy），计算资源消耗巨大。GRPO（DeepSeek-R1采用）用**组内相对奖励**替代Critic模型，大幅简化：

$$\hat{r}_i = \frac{r_i - \mu_G}{\sigma_G}$$

其中 $r_i$ 是组内第 $i$ 个样本的奖励，$\mu_G$ 和 $\sigma_G$ 是组内均值和标准差。

**GRPO的三个致命问题**：
1. **熵崩溃（Entropy Collapse）**：随着训练进行，策略熵快速下降，模型停止探索
2. **奖励噪声（Reward Noise）**：过长/过短回答都可能得正奖励，误导梯度
3. **训练不稳定（Instability）**：clip机制导致有效更新减少，训练曲线抖动

### 1.2 DAPO四项核心技术

**① Clip-Higher（非对称裁剪）**

GRPO的标准PPO裁剪：
$$\text{clip}(r(\theta), 1-\epsilon, 1+\epsilon)$$

DAPO的改进：**提高上限**，鼓励探索：
$$r(\theta) \in [\max(r_0 - \epsilon_{low}, 1-\epsilon_{high}), 1+\epsilon_{high}]$$

设置 $\epsilon_{high} > \epsilon_{low}$，减少对探索性更新的过早抑制，防止熵崩溃。

**② Dynamic Sampling（动态采样）**

传统方法对所有样本统一计算损失，但**部分样本几乎没有学习信号**（答案正确=奖励1，错误=奖励0）。

DAPO的动态采样策略：
```python
# 对于正确样本（reward=1）：降低其采样权重，聚焦错误样本
# 对于错误样本（reward=0）：进一步分为可学习/不可学习两类
if reward == 1 and is_too_short(answer):
    drop_sample()  # 跳过了，未真正理解
if reward == 0 and is_too_long(answer):
    penalize(length_based_penalty)  # 过长的错误答案不应得高分
```

**③ Overlong Filtering & Soft Overlong Punishment（超长惩罚）**

发现很多"作弊"样本：答案虽然正确，但靠超长解释（包含完整答案的提示）而非真正推理得到。

```python
# 硬过滤：直接丢弃超长样本（> MAX_LENGTH）
if len(answer) > OVERLONG_THRESHOLD:
    drop_sample()

# 软惩罚（更优雅的方案）：基于长度的奖励衰减
length_penalty = 1.0 / (1.0 + beta * (len - L_ideal))
adjusted_reward = raw_reward * length_penalty
```

**④ Token-level Loss（Token级损失）**

GRPO基于**序列级损失**——整个回答用一个损失值。问题：长回答的每个token都被同等地更新，梯度方向冲突。

DAPO改进为**Token级损失**：对每个token独立计算梯度贡献：
$$\mathcal{L}_{DAPO} = \frac{1}{|x|} \sum_{t=1}^{|x|} \nabla_\theta \log \pi_\theta(a_t | s_t) \cdot G_t$$

其中 $G_t$ 是从时刻 $t$ 开始的累积回报（而非整序列的单一回报）。

### 1.3 DAPO技术对比表

| 技术 | GRPO | DAPO | 效果 |
|------|------|------|------|
| 裁剪策略 | 对称裁剪 | 非对称裁剪（上限提高） | 防止熵崩溃 |
| 采样策略 | 固定采样 | 动态采样 | 聚焦有效样本 |
| 长答案处理 | 无 | Overlong Filter/Punishment | 消除噪声奖励 |
| 损失粒度 | 序列级 | Token级 | 梯度更精准 |

## 二、Qwen3.5 架构深度解析：Gated Delta Networks

### 2.1 从DeltaNet到Gated Delta Networks

**Delta Networks**（ICLR 2024）最初用于视觉识别，其核心思想是**只建模变化量（Delta）而非完整状态**：

传统RNN：
$$h_t = f(h_{t-1}, x_t)$$

Delta Network：
$$h_t = h_{t-1} + \tanh(W_\Delta \cdot x_t)$$

**Qwen3.5的创新：Gated DeltaNet + 线性注意力融合**

```python
class GatedDeltaNet(nn.Module):
    def __init__(self, d_model):
        self.delta_proj = nn.Linear(d_model, d_model)   # 计算变化量
        self.gate_proj = nn.Linear(d_model, d_model)     # 计算门控
        self.half_dim = d_model // 2
    
    def forward(self, x, prev_h):
        # 分割为两部分：保持部分 + 更新部分
        keep = x[:, :, :self.half_dim]          # 保留多少旧信息
        update = x[:, :, self.half_dim:]        # 更新多少新信息
        
        # 门控机制：决定写入多少新信息
        gate = torch.sigmoid(self.gate_proj(x))
        
        # Delta更新：只更新变化的部分
        delta = torch.tanh(self.delta_proj(update))
        
        # 融合：旧状态×门控 + 变化量
        new_h = prev_h * gate + delta * (1 - gate)
        return new_h
```

### 2.2 与标准注意力、线性注意力的对比

| 注意力类型 | 时间复杂度 | 空间复杂度 | 精度 | 适用场景 |
|-----------|---------|---------|------|---------|
| 标准Self-Attention | $O(N^2)$ | $O(N^2)$ | 最高 | 短序列，高精度要求 |
| Flash Attention | $O(N^2)$ | $O(N)$ | 最高 | 长序列训练 |
| DeltaNet (线性) | $O(N)$ | $O(1)$ | 中等 | 超长序列 |
| Gated DeltaNet | $O(N)$ | $O(1)$ | 较高 | 超长序列+选择性记忆 |
| RWKV (线性RNN) | $O(N)$ | $O(1)$ | 中等 | 超长推理 |

### 2.3 Qwen3.5的混合架构

Qwen3.5并非单一使用DeltaNet，而是采用**Gated DeltaNet + Gated Attention的混合**：

```
Token序列
    ↓
┌─ Gated DeltaNet（早期层）→ 线性注意力 → 高效选择性记忆
│         ↓
└─ Gated Attention（后期层）→ 标准注意力 → 精细语义理解
         ↓
    Sparse MoE（所有层）→ 专家路由 → 稀疏激活输出
```

这种设计让模型在**不同层次使用最合适的注意力机制**：
- 早期层（token-level）：用DeltaNet高效捕获局部变化
- 后期层（semantic-level）：用标准注意力做精细理解

## 三、Qwen3-Coder-Next：3B激活参数超越10-20倍大模型

```

  └─ 代码+智能体数据 → Qwen3-Next-80B-A3B-Base

阶段2: 监督微调（SFT）
  └─ 高质量智能体轨迹 → 对齐真实任务流程

阶段3: 领域专家训练
  ├─ 软件工程专家（代码修复、重构）
  ├─ QA专家（测试用例生成）
  └─ Web/UX专家（前端交互）

阶段4: 专家蒸馏
  └─ 合并为单一可部署模型
```

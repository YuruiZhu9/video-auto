# 一、扩散语言模型：两条路线的新突破

> 💡 **背景**：扩散语言模型（dLLM）用"逐步去噪"替代"预测下一个token"，具备天然并行生成能力，但此前推理速度和质量都与自回归模型（ARM）有显著差距。2026年3月，两项工作从根本上改写了这一局面。

---

## 1.1 ReFusion（ICLR 2026）：KV缓存复用 + 槽排列空间学习

**论文**：[arXiv:2512.13586](https://arxiv.org/abs/2512.13586)  
**团队**：ML-GSAI（机构匿名）  
**基础模型**：Qwen3-8B

### 核心问题：MDM的两大致命伤

此前所有Masked Diffusion Models（MDM）都存在两个根本缺陷，导致其无法实用化：

**缺陷1：KV缓存完全无法复用**

自回归模型在生成第`t`个token时，可以直接复用前`t-1`个token的K和V矩阵（KV Cache），只需计算第`t`个token的QKV。这是AR模型高效推理的核心。

但MDM在每步去噪迭代中，所有token都处于"活跃"状态（有些是已知token，有些是需要预测的mask token），无法区分"已经生成完成"和"还需要计算"的token，导致每步都必须重新计算全部历史KV，**O(n²)计算量成为瓶颈**。

**缺陷2：token组合空间难以学习**

MDM的学习目标是：给定部分token，预测完整的token序列。这要求模型学习任意token子集之间的依赖关系。但n个token的组合数是C(n,k)，当n较大时这是**指数级不可计算的（intractable）**。

### 核心创新一：槽级并行解码 + KV缓存复用

ReFusion将序列组织为**固定数量的Slots（槽）**，而不是逐token处理：

```
输入序列: [CLS] 今 天 天 气 [M] [M] [M]
           ↓ 组织为槽
槽序列:    [槽0] [槽1] [槽2] [槽3] [槽4] [槽5]
```

**解码流程：**

```
迭代1: [槽0★] [槽1★] [槽2 ] [槽3 ] [槽4 ] [槽5 ]
         ↓ 并行去噪，选出下一个槽
迭代2: [槽0✓] [槽1✓] [槽2★] [槽3 ] [槽4 ] [槽5 ]
         ↓ 填充槽2（槽内AR填充）
迭代3: [槽0✓] [槽1✓] [槽2✓✓✓] [槽3★] [槽4 ] [槽5 ]
         ↓ ...循环...
最终:   完整句子生成完毕
```

**关键洞察**：每个槽一旦生成完毕（标记为✓），其KV值就**永久固定并复用**，不再参与后续扩散迭代的计算。只有当前活跃槽（标记为★）需要计算QKV。这就是KV缓存复用的本质。

### 核心创新二：槽排列空间学习（Slot Permutation Space Learning）

**为什么token组合空间不可学习？**

假设序列长度为20，每步有k个活跃槽需要预测。模型需要学习"哪些token应该被填入哪些槽位"的完整组合分布。形式上，这等价于学习一个从{活跃槽位}到{剩余token}的映射，组合数随序列长度指数爆炸。

**ReFusion的解决方案：将问题从"token组合"转化为"槽排列"**

ReFusion将学习目标从"token-level组合"变为"slot-level permutation（排列）"：

```
数学形式化：
设 S = {s₁, s₂, ..., s_N} 为N个槽
设 P(S) 为S的所有可能排列的集合

ReFusion学习: P(slots | 已填充槽)
而非:         P(tokens | 已填充tokens)

关键观察：当槽数量固定为N时，P(S)的规模是 N!（阶乘级）
对于N=8, N! = 40320，这是可计算的
而token组合空间是 2^N（指数级），N=8时是256
```

**直观理解**：ReFusion不是在学习"这10个词怎么排列成句子"，而是在学习"这8个槽位，应该按什么顺序填充"。槽的数量是固定的（由模型架构决定），因此排列空间大小固定且可学习。

### 间插式架构（Inter-Intra Decoding）

```
[全局槽级选择]     ←→   [槽内AR填充]
   ↓扩散模型驱动的     每个槽内用AR
   哪个槽下一步填充      方式填充完整内容
```

- **间插（inter-slot）**：用扩散模型决定下一个待填充的槽
- **内部（intra-slot）**：用轻量AR模型填充该槽的具体内容

### 性能数据

| 对比基准 | 性能提升 | 推理加速 |
|---------|---------|---------|
| vs 此前最优MDM | **+34%**（MBPP基准）| **>18倍** |
| vs 同规模自回归模型 | 接近（差距大幅缩小）| **2.33倍** |

**意义**：ReFusion首次让扩散语言模型在推理速度上明显超越自回归模型，同时大幅缩小了质量差距。这是dLLM领域的重要里程碑。

### 与此前dLLM的技术路线对比

| 特性 | LLaDA/MMDM | LLaDA++ | **ReFusion** |
|------|------------|---------|-------------|
| KV缓存 | ❌ 不可复用 | ❌ 不可复用 | ✅ **完整复用** |
| 解码粒度 | token级 | token级 | **槽级并行** |
| 学习目标 | token组合空间 | token组合空间 | **槽排列空间** |
| 性能（vs ARM）| 差距大 | 差距较大 | **接近ARM** |
| 推理速度 | 慢（多次全量计算）| 较慢 | **快（2.33× ARM）** |

## 1.2 Seed Diffusion（ByteDance）：工业级快速推理

**发布方**：字节跳动Seed团队  
**官网**：[seed.bytedance.com/seed_diffusion](https://seed.bytedance.com/seed_diffusion)  
**核心成就**：推理速度**2146 tokens/s**（H100），比同规模AR模型快**5.4倍**

### 技术定位

Seed Diffusion与ReFusion代表了dLLM的**两条互补路线**：

- **ReFusion**：解决KV缓存复用问题（架构层创新）
- **Seed Diffusion**：解决掩码填充效率问题（掩码调度+硬件亲和优化）

Seed Diffusion的实验领域是**代码生成**，这有很强的工程动机：代码生成有明确的语法约束，扩散模型的"逐步细化"特性可以天然保证语法正确性。

### 核心技术：Mask-Filling + 渐进式槽激活

```
Seed Diffusion的推理流程：

Step 1: 将部分token替换为[MASK]
        "def quick_sort([M]):"
        
Step 2: 扩散模型一次性预测所有[MASK]位置
         "def quick_sort(arr):"
         ↓ 验证（是否满足语法约束？）
Step 3: 若不满足，将更多token变为[MASK]
         "def [M] [M] ([M]):"
         
Step 4: 重新去噪...
         ↓
最终: 语法完全正确的代码 ✓
```

**关键设计决策**：Seed Diffusion采用**固定步数**（而非自适应）的掩码填充，配合Token约束验证，可以在语法层面保证生成质量。

### 性能数据

| 模型 | 推理速度 | 相比AR基准 |
|------|---------|-----------|
| 同规模AR代码模型 | ~400 tokens/s | 1× |
| Seed Diffusion Preview | **2146 tokens/s** | **5.4×** |

在自然科学的代码补全基准上，Seed Diffusion与同等规模AR模型性能相当。

### 两项工作的对比总结

| 维度 | ReFusion | Seed Diffusion |
|------|----------|----------------|
| 核心创新 | KV缓存复用 + 槽排列学习 | 快速掩码填充 + 语法约束验证 |
| 发表/发布 | ICLR 2026 | ByteDance Seed团队 |
| 推理速度 | 2.33× ARM | 5.4× ARM |
| 性能vs ARM | 接近（差距-34%）| 相当 |
| 架构路线 | 间插式AR填充 | 纯并行掩码填充 |
| 开源 | 是（HuggingFace）| 论文+技术报告 |

# 二、GDPO：NVIDIA的多奖励强化学习新范式

**论文**：[GDPO: Group reward-Decoupled Normalization Policy Optimization](https://nvlabs.github.io/GDPO/)  
**团队**：NVIDIA Research

### GRPO的"奖励信号坍缩"问题

GRPO（Group Relative Policy Optimization）是DeepSeek-R1/QwQ-32B等推理模型的核心训练方法。其工作流程是：

```
1. 对每个问题，从策略模型采样G个回答
2. 计算每个回答的奖励 r₁, r₂, ..., r_G
3. 将奖励归一化后计算优势函数 A
4. 用PPO风格的策略梯度更新模型
```

**但在多奖励场景下，GRPO存在根本性缺陷：**

当同时优化多个奖励时（如：格式奖励 + 准确性奖励 + 长度奖励），GRPO先将奖励**求和**再**归一化**：

```
总奖励: r_sum = w₁·r₁ + w₂·r₂ + w₃·r₃
优势值: A = (r_sum - μ) / σ
```

**问题**：不同奖励组合可能产生相同的总奖励，但归一化后具有相同的优势值，导致模型**无法区分"同时满足多个目标"和"只满足部分目标"的样本**。

**具体例子**：
- 样本A：奖励(1.0, 0.0, 0.0) → 总奖励1.0 → 优势值0.707
- 样本B：奖励(1.0, 1.0, 1.0) → 总奖励3.0 → 优势值0.707
- **结论**：样本B明明同时满足了3个目标，优势却和样本A一样，训练信号被浪费

### GDPO的核心解法："先归一化，后聚合"

GDPO的三步法：

**Step 1：对每个奖励分量单独做组内归一化**

$$A_k^{(i,j)} = \frac{r_k^{(i,j)} - \text{mean}(\{r_k^{(i,1)}, \dots, r_k^{(i,G)}\})}{\text{std}(\{r_k^{(i,1)}, \dots, r_k^{(i,G)}\})}$$

对第k个奖励，先在其所属的采样组内做归一化，**保留各奖励分量的相对差异**。

**Step 2：将归一化后的优势分量求和**

$$A_{sum}^{(i,j)} = A_1^{(i,j)} + A_2^{(i,j)} + \dots + A_n^{(i,j)}$$

**Step 3：Batch-wise二次归一化**

$$\hat{A}_{sum}^{(i,j)} = \frac{A_{sum}^{(i,j)} - \text{mean}(\cdot)}{\text{std}(\cdot) + \epsilon}$$

重新用上面的例子：
- 样本A：归一化奖励(1.0, -0.5, -0.5) → 优势加和 = 0.0
- 样本B：归一化奖励(1.0, 1.0, 1.0) → 优势加和 = **3.0**
- **结论**：模型现在能正确区分两个样本，训练信号完全保留 ✅

### 实验验证

**数学推理（AIME基准，DeepSeek-R1-7B）：**
- GDPO比GRPO准确率高出**2.9%**
- 长度违规率（响应超过4000 token）：2.1% → **0.2%**
- GRPO在约400步后出现训练坍缩（准确率下降、长度失控），**GDPO全程稳定**

**代码推理（Taco数据集，DeepSeek-R1-7B）：**
- Bug率：30.0% → **28.0%**
- 长度违规率：14.7% → **10.6%**
- 通过率保持与GRPO相当

**工具调用（Qwen2.5-Instruct）：**
- 消融实验：去除标准差归一化的版本，格式奖励直接归零——说明解耦归一化是必不可少的

### 核心洞察

```
GRPO:  奖励 → 求和 → 归一化 → 优势  （信号压缩）
GDPO:  奖励 → 归一化 → 求和 → 归一化  （信号保留）
```

GDPO实际上是一个**drop-in replacement**——只需修改优势计算逻辑，策略更新部分与GRPO完全相同，工程实现极其简单。

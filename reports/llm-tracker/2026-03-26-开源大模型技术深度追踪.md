## 1.1 Qwen3.5-Max核心技术架构

### 稀疏MoE的工程意义

传统Dense模型每次推理激活100%参数，MoE通过**门控网络（Top-K Routing）**每次只激活少数专家：

```
输入Token → 门控网络 → 选择Top-K专家 → 专家并行计算 → 加权输出
                      ↑
              门控网络: W_gate · x → softmax → Top-K(...)
```

**Qwen3.5-Max的关键参数**：
- 总参数量：397B（需要完整加载，约740GB FP16）
- 激活参数量：17B（每次推理实际计算量）
- 稀疏度：96%（即每次只激活4.3%的参数）
- 上下文长度：100万Token
- LM Arena得分：**1464分（全球第一）**

### 稀疏MoE的数学原理

**门控函数**（Gating Function）：
$$G(x) = \text{Softmax}(W_{gate} \cdot x)$$

**Top-K选择**：
$$\text{Top-}K(G(x)) = \{i | G(x)_i \text{ 在前K个最大值中}\}$$

**专家输出**：
$$y = \sum_{i \in \text{Top-K}} G(x)_i \cdot E_i(x)$$

其中 $E_i(\cdot)$ 是第 $i$ 个专家网络。

### 负载均衡： Auxiliary Loss

稀疏MoE的致命问题是**专家负载不均衡**——少数"万能专家"被频繁激活，其他专家"摸鱼"。标准解法是Auxiliary Load Balancing Loss：

$$\mathcal{L}_{balance} = \alpha \cdot \left|\left|\frac{1}{N}\sum_{i=1}^{N}f_i - \frac{1}{E}\sum_{i=1}^{E}f_i\right|\right|_2^2$$

其中 $f_i$ 是第 $i$ 个专家被选中的频率，$N$ 是总Token数，$E$ 是专家总数。

### 对推荐系统的直接借鉴

MoE的门控机制与推荐系统中**多兴趣建模**高度相似：
- **推荐多兴趣（MIND等）**：用Capsule Network或类似路由将用户行为序列映射到多个兴趣向量
- **类MoE路由**：不同兴趣向量→激活不同专家→生成不同推荐候选→融合输出
- **工业落地价值**：可以用异步RL（AReaL框架）训练端到端的MoE式推荐系统

## 1.2 百万Token上下文：技术实现路径

百万Token（约75万中文字符）是2026年3月旗舰模型的**基础设施标准**，不是亮点。其核心技术路径：

### Ring Attention：跨节点分布注意力计算

原始Transformer的Attention计算量为 $O(N^2)$，对100万Token：
$$N = 10^6, \quad N^2 = 10^{12}$$

单卡无法容纳如此大的中间结果。Ring Attention将序列分片，每个设备计算局部注意力后跨设备传递KV：

```
Device 1: [Chunk 1] → attend → [local QK^T] ─┐
Device 2: [Chunk 2] → attend → [local QK^T] ─┼→ 跨设备传递KV → 全局Attention
Device 3: [Chunk 3] → attend → [local QK^T] ─┘
```

**关键数学**：跨设备通信量从 $O(N^2)$ 降到 $O(N)$（仅传递KV分片，不传递完整注意力矩阵）。

### 位置编码外推：让模型"读懂"超长上下文

标准RoPE（Rotary Position Encoding）在训练长度外会失效。主流方案：

**① YaRN（Yet another RoPE extensioN）**：
通过温度参数平滑注意力分数分布：
$$\text{Attention}_{scaled}(q, k) = \frac{q^T k}{\sqrt{d_{effective}}} \cdot \frac{1}{1 - \beta t}$$

其中 $t$ 是位置索引，$\beta$ 是缩放因子。

**② LongRoPE（ICLR 2024）**：
将位置编码分解为粗粒度（短距离）和细粒度（长距离）两个部分：
$$p_i = (i \mod T_{short}) \cdot e_{short} + \lfloor i / T_{long} \rfloor \cdot e_{long}$$

**③ RoPE外推 + 插值混合**：
对训练长度内的位置进行插值（压缩），对超出部分进行外推，两种策略动态切换。

## 2.1 异步架构的数学原理

### 为什么同步RL训练GPU利用率极低？

传统PPO/GRPO训练流程：
```
[推理阶段] GPU生成样本 → CPU收集 → CPU计算奖励
     ↓
[训练阶段] GPU执行梯度更新
```

问题：推理阶段GPU处于**等待I/O状态**，训练阶段等待GPU计算完成。实测中同步PPO的GPU利用率不超过30%。

### AReaL异步流水线的核心设计

```
┌─────────────────────────────────────────────────┐
│                 AReaL 异步RL流水线               │
├─────────────────────────────────────────────────┤
│  Rollout Worker 1 (GPU-1)  → 推理生成 → 写入缓冲区 │
│  Rollout Worker 2 (GPU-2)  → 推理生成 → 写入缓冲区 │
│  Rollout Worker N (GPU-N)  → 推理生成 → 写入缓冲区 │
│                         ↓                        │
│               缓冲区 (CPU/NUMA)                   │
│                         ↓                        │
│            Trainer Worker (GPU-1) ← 从缓冲区读取  │
│                 执行梯度更新 → 更新所有Rollout Worker │
└─────────────────────────────────────────────────┘
```

**关键设计：完全解耦（Decoupled Generation & Training）**

Rollout和Trainer各自独立运行，通过双缓冲（Double Buffering）保证流水线始终满载：
- Buffer 1满 → Trainer读取Buffer 1训练，同时Rollout写入Buffer 2
- Buffer 2满 → Trainer切换到Buffer 2，同时Rollout写入Buffer 1

**异步锁机制（ReaL技术）**：

为了保证训练稳定性，AReaL引入**异步锁**控制梯度更新时机：
```python
# 简化的异步RL训练循环
while not converged:
    # 阶段1：Rollout Workers并行推理
    rollouts = parallel_generate(prompts, rollout_buffers)
    
    # 阶段2：计算奖励
    rewards = compute_rewards(rollouts)
    
    # 阶段3：Trainer异步执行梯度更新
    # （Rollout Workers在Trainer更新时继续推理，策略用陈旧版本）
    gradients = trainer.compute_gradients(rollouts, rewards)
    apply_gradient_updates(rollout_workers, gradients)
```

**支持的最大离策略度（Max Head Off-Policyness）**：

可以通过 `max_head_offpolicyness` 参数控制策略陈旧容忍度——设为0则退化为同步模式（所有算法均支持）。

## 2.2 2.77倍加速的工程实现（boba²）

### 内存与通信优化

AReaL v0.3（代号boba²）通过三项核心技术实现2.77倍加速：

**① 序列打包（Sequence Packing）**

将不同长度的样本打包到同一批次，用特殊token分隔：
```
原始: Batch1=[seq_A], Batch2=[seq_B], ..., BatchN=[seq_N]  → N次forward
优化: Packed=[PAD, seq_A, PAD, seq_B, PAD, seq_C, PAD]     → 1次forward
```

**数学收益**：设平均序列长度为 $L_{avg}$，标准批处理的GPU利用率为 $\frac{L_{avg}}{L_{max}}$；序列打包后理论利用率接近100%。

**② 动态序列打包**

不仅打包，还动态选择序列组合使GPU内存填充率最大化（Bin Packing问题）：
```
输入: seq_A(len=512), seq_B(len=2048), seq_C(len=896), seq_D(len=1536)
问题: 最大化GPU内存利用率（总容量=4096 tokens/GPU block）
解法: [seq_B+seq_A] (2048+512=2560), [seq_D+seq_C] (1536+896=2432)
```

**③ 参数分配优化（ReaL-Param分配）**

传统RLHF训练中，策略模型和参考模型需要同时驻留显存。ReaL技术通过：
- **动态卸载**：参考模型参数卸载到CPU/NUMA内存，需要时通过PCIe高速加载
- **ZeRO-3分片**：将优化器状态、梯度和参数分片到不同GPU，峰值显存降低75%

## 2.3 AReaL-SEA：自进化数据合成引擎

**AReaL-SEA（2026年2月6日发布）** 是AReaL生态的最新成员：

### 核心思想：让模型自己生成训练数据

传统RL训练依赖人工标注的可验证答案（如数学题），但真实场景（推荐、客服）缺乏大规模可验证奖励信号。AReaL-SEA通过**自博弈合成数据**解决：

```
Step 1: 初始模型 M₀ 生成多样化的"问题-答案"对
Step 2: 强化学习训练得到更好的模型 M₁
Step 3: 用 M₁ 生成更高质量的合成数据
Step 4: 重复 → 模型能力自举（Self-Bootstrapping）
```

### 实验结果

在AReaL-SEA训练的**235B MoE模型**表现：
- **τ²-bench（智能体基准）**：与Gemini 3.0 Pro相当
- **数学/编码/搜索**：全面超越GPT-5（在特定任务上）
- **关键结论**：数据合成 + 异步RL可以在不依赖大规模人工标注的情况下，训练出顶级能力的推理模型

### 对推荐系统的意义

推荐系统的RL训练（推荐排序、Rewarder建模）长期受制于**奖励信号稀缺**：用户点击/转化信号有噪声，且难以大规模获取。AReaL-SEA的自博弈合成思路可以直接迁移：

1. 用现有推荐模型生成候选排序
2. 用强化学习评估排序质量（设计可验证的奖励函数，如覆盖率、多样性指标）
3. 合成"高质量排序样本"用于训练
4. 迭代自举 → 最终模型超越人工标注数据上限

## 3.1 MXFP4：混合精度4-bit量化原理

### 传统量化的局限性

标准INT4量化的问题：对于呈**非均匀分布**的权重，均匀量化（每个bin等宽）会引入较大误差：

$$\hat{W} = \text{round}\left(\frac{W - W_{min}}{W_{max} - W_{min}} \times (2^4 - 1)\right) \cdot \frac{W_{max} - W_{min}}{2^4 - 1} + W_{min}$$

**问题**：如果权重集中在某些范围，均匀划分会导致其他范围精度极低。

### MXFP4：指数+尾数的混合表示

MXFP4借鉴IEEE FP8格式的设计思路，将每个权重表示为：
$$w = m \times 2^{e}$$

其中 $m$ 是4-bit尾数（mantissa），$e$ 是动态确定的指数（exponent shared across a block）。

**Block结构**：
```
┌──────────┬──────────────┐
│ 共享指数  │  4-bit尾数×N │  ← 每个block共享一个指数
│  (8-bit) │  (每个权重4bit)│
└──────────┴──────────────┘
```

**数学收益**：对于呈指数分布的权重（如LLM中常见的"少数极大值+多数小值"），MXFP4比INT4的**相对误差更低**：

$$\text{Relative Error}_{INT4} = O\left(\frac{\max(|W|)}{\text{range}}\right) \quad \text{vs} \quad \text{Relative Error}_{MXFP4} = O\left(\frac{\max(|W|)}{2^{\text{shared\_exp}}}\right)$$

### Llama.cpp MXFP4实现状态

Llama.cpp已与NVIDIA合作，实现了对GPT-oss模型的MXFP4格式原生支持（PR #15091）。关键数据：
- 模型大小：FP16（16-bit）→ MXFP4（4-bit）= **4倍压缩**
- 精度损失：相对FP16误差 < 0.5%（在主流基准测试上）
- 推理速度：比FP16快2-3倍（主要收益来自带宽降低）

## 4.1 FLA支持的最新架构

### RWKV-6的线性注意力实现（重点）

RWKV-6是当前最活跃的线性注意力模型之一，其TimeMix模块的核心计算：

```python
# RWKV-6 TimeMix 核心（前向传播）
def forward(self, x):
    B, T, C = x.shape
    # 位置衰减因子（随token位置指数衰减）
    w = torch.exp(torch.arange(T, device=x.device) * (-self.time_decay))
    
    # 线性注意力计算（避免softmax的O(N²)复杂度）
    # 将 O(N²) 转化为 O(N) 的RNN式递归
    r = self.receptance(x)    # (B, T, C)
    k = self.key(x)            # (B, T, C)
    v = self.value(x)          # (B, T, C)
    
    # 递归计算：hi = wi·hi-1 + ki^T · vi
    # 使用 Chunkwise 并行：将序列分成chunks，chunk内并行，chunk间递归
    for chunk in chunks(x):
        chunk_state = w_chunk * prev_state + chunk_k.T @ chunk_v
        prev_state = chunk_state
        chunk_output = chunk_r @ chunk_state
```

**复杂度对比**：
- 标准Attention：$O(N^2)$ 时间和 $O(N^2)$ 内存
- RWKV-6 TimeMix：$O(N)$ 时间和 $O(1)$ 推理内存（每步）

### Chunkwise并行算法原理

FLA的Chunkwise并行是RWKV-6高效训练的核心：

```
序列: [t1, t2, t3, t4, t5, t6, t7, t8]
Chunk大小: 4

Chunk 1: [t1, t2, t3, t4] ──并行计算──→ state_C1
Chunk 2: [t5, t6, t7, t8] ──并行计算──→ state_C2 = w4 * state_C1 + local_kv
                                    ↑
                              跨chunk依赖

关键：Chunk内完全并行（利用GPU并行能力）
      Chunk间通过递归连接（保留线性注意力精度）
```

## 4.2 线性注意力在推荐系统的潜力

推荐系统的**推理延迟**是核心瓶颈：用户请求需要在几十毫秒内返回推荐结果。线性注意力对推荐系统的价值：

### 序列建模加速

推荐系统处理的用户行为序列（点击/购买/浏览历史）长度可达数千：
- 标准Transformer：$O(L^2)$ 注意力，延迟高
- 线性注意力：$O(L)$，延迟降低10-100倍

### Mamba在推荐序列建模中的应用

2025-2026年已有多篇工作将Mamba用于推荐序列建模：
```python
# 伪代码：Mamba用于推荐序列建模
class MambaRecommender(torch.nn.Module):
    def __init__(self, item_dim, seq_len, d_state=128):
        super().__init__()
        self.item_embedding = ItemEmbedding(item_dim)
        self.mamba = MambaBlock(
            d_model=256,
            d_state=d_state,  # SSM状态维度
            expand=2,          # 扩展因子
        )
        self.predictor = PredictHead()
    
    def forward(self, item_seq):
        # item_seq: (B, L, item_dim) - 用户行为序列
        emb = self.item_embedding(item_seq)  # (B, L, d_model)
        # Mamba选择性扫描：高效建模长程依赖
        seq_repr = self.mamba(emb)           # (B, L, d_model)
        # 取最后一个位置的表示用于预测
        return self.predictor(seq_repr[:, -1])
```

## 附一：Qwen3.5-397B-A17B — 开源原生多模态旗舰（2026/02/15）

### 核心架构创新：Gated Delta Networks + Sparse MoE

Qwen3.5 采用了 **Qwen3-Next** 基础架构，其核心创新是**混合注意力机制**：

```
┌──────────────────────────────────────────────────────────────┐
│              Qwen3-Next 混合注意力架构                        │
├──────────────────────────────────────────────────────────────┤
│  Token序列 → [Gated DeltaNet] → 线性注意力（高效选择性记忆）   │
│           → [Gated Attention] → 标准注意力（精细语义理解）     │
│           → [Sparse MoE] → Top-K 专家路由 → 输出              │
└──────────────────────────────────────────────────────────────┘
```

**Gated DeltaNet（门控Delta网络）**原理：

DeltaNet 的核心思想是**只建模相邻状态之间的变化（Delta）**，而非完整状态：

$$h_t = h_{t-1} + \Delta h_t$$

其中 $h_t$ 是当前隐状态，$h_{t-1}$ 是上一时刻隐状态，$\Delta h_t$ 是变化量。

**门控机制（Gating）**：
$$g_t = \sigma(W_g \cdot [h_{t-1}, x_t])$$
$$\Delta h_t = \tanh(W_\Delta \cdot [h_{t-1}, x_t])$$
$$h_t = h_{t-1} + g_t \odot \Delta h_t$$

其中 $\sigma$ 是 sigmoid 门控，$\odot$ 是逐元素乘法。门控决定多少新信息被写入。

**数学优势**：
- 标准注意力：$O(N^2)$ 时间和内存
- DeltaNet：$O(N)$ 时间（只需存储和传递状态差异）
- 门控：选择性记忆，遗忘无关信息

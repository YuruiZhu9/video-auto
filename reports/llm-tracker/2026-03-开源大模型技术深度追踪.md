# 一、基础层：架构革新与注意力机制演进

## 1.1 Qwen3：混合推理双模式架构

### 一句话概括
Qwen3是阿里通义千问在2025年推出的旗舰开源模型系列，核心突破是**无缝切换的Thinking/Non-Thinking双模式**，让同一个模型同时具备快思考（通用问答）和慢思考（复杂推理）能力。

### 背景与动机

Qwen2.5时代，团队发现一个问题：模型在预训练阶段无法同时学习"快速回答"和"深度思考"两种能力。以往的解决方案是训练两个独立模型，这带来了：
- 两套模型权重，维护成本高
- 无法在推理时动态切换策略
- Agent场景中，工具调用必须在非思考模式下才能工作

Qwen3的核心理念：**让模型自己决定何时思考、何时行动**。

### 数学原理

#### 1. 动态路由机制（Dual-Mode Routing）

模型在输入序列前注入一个特殊的 `<mode>` token，MLP层输出一个二分类 logits，决定激活"思考模式"还是"回答模式"：

```math
\text{Mode} = \text{Softmax}(\text{MLP}(x_{\text{[CLS]}}))
```

```python
class Qwen3ModeRouter(nn.Module):
    """
    Dual-mode switching mechanism.
    Input: [CLS] token embedding
    Output: mode probability distribution
    """
    def __init__(self, hidden_dim):
        super().__init__()
        self.mode_mlp = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim // 2),
            nn.GELU(),
            nn.Linear(hidden_dim // 2, 2)  # 0=non-thinking, 1=thinking
        )
    
    def forward(self, hidden_states):
        cls_output = hidden_states[:, 0]  # 取[CLS] token
        mode_logits = self.mode_mlp(cls_output)
        mode_probs = F.softmax(mode_logits, dim=-1)
        return mode_probs
```

**核心数学直觉**：二分类门控不引入额外参数，切换开销几乎为零。模型在预训练中自然学会对复杂问题启动思考链。

#### 2. Qwen3 MoE架构（Qwen3-235B-A22B / Qwen3-30B-A3B）

Qwen3 MoE采用**细粒度专家 + 共享专家**混合策略：

```math
\begin{aligned}
\text{FFN}_{\text{output}} &= \sum_{i=1}^{N_{\text{shared}}}} \text{FFN}_i(x) \cdot \frac{1}{N_{\text{shared}}}} + \sum_{j \in \text{TopK}(G(x))} \text{FFN}_j(x) \cdot \frac{G_j(x)}{\sum_{k \in \text{TopK}(G)} G_k(x)} \\
\text{其中：} \quad G(x) &= \text{Softmax}(\text{Router}(x)) \\
& \text{TopK} = \text{选取激活值最高的K个专家}
\end{aligned}
```

**Qwen3-235B-A22B**（总参数量235B，激活22B）：
- 共享专家（Shared Experts）：捕获通用语义知识，始终参与计算
- 路由专家（Router Experts）：基于门控分数动态选择
- 稀疏激活：约9%参数参与推理

**Qwen3-30B-A3B**（总参数量30B，激活3B）：
- 更激进的稀疏激活，仅激活约10%的参数
- 适合边缘部署，单卡可运行

### 代码实现：MoE前向传播

```python
import torch
import torch.nn.functional as F
from torch import nn

class Qwen3MoE(nn.Module):
    """
    Qwen3 MoE Layer - 核心实现
    数学：y = sum_{i in topk(gate(x))} (g_i * expert_i(x))
    """
    def __init__(self, d_model, n_experts, top_k, shared_experts=2):
        super().__init__()
        self.n_experts = n_experts
        self.top_k = top_k
        
        # 共享专家（始终激活）
        self.shared_experts = nn.ModuleList([
            nn.Sequential(
                nn.Linear(d_model, d_model * 4),
                nn.GELU(),
                nn.Linear(d_model * 4, d_model)
            ) for _ in range(shared_experts)
        ])
        
        # 路由专家（稀疏激活）
        self.routed_experts = nn.ModuleList([
            nn.Sequential(
                nn.Linear(d_model, d_model * 4),
                nn.GELU(),
                nn.Linear(d_model * 4, d_model)
            ) for _ in range(n_experts)
        ])
        
        self.gate = nn.Linear(d_model, n_experts, bias=False)
    
    def forward(self, x):
        """
        x: (batch_size, seq_len, d_model)
        """
        batch_size, seq_len, d_model = x.shape
        
        # === 1. 共享专家（始终激活）===
        shared_output = sum(expert(x) for expert in self.shared_experts)
        
        # === 2. 路由专家（稀疏激活）===
        x_flat = x.view(-1, d_model)  # (B*S, D)
        
        # 计算门控分数
        gate_logits = self.gate(x_flat)  # (B*S, n_experts)
        gate_probs = F.softmax(gate_logits, dim=-1)
        
        # TopK选择
        top_k_probs, top_k_indices = torch.topk(gate_probs, self.top_k, dim=-1)
        top_k_probs = top_k_probs / top_k_probs.sum(dim=-1, keepdim=True)  # 归一化
        
        # 稀疏加权求和
        routed_output = torch.zeros_like(x_flat)
        for k_idx in range(self.top_k):
            expert_idx = top_k_indices[:, k_idx]
            expert_weight = top_k_probs[:, k_idx:k_idx+1]
            
            for e_id in range(self.n_experts):
                mask = (expert_idx == e_id)
                if mask.any():
                    expert_input = x_flat[mask]
                    expert_out = self.routed_experts[e_id](expert_input)
                    routed_output[mask] += expert_out * expert_weight[mask]
        
        routed_output = routed_output.view(batch_size, seq_len, d_model)
        return shared_output + routed_output
```

## 1.2 Llama 4：原生多模态+超长上下文架构

### 一句话概括
Llama 4是Meta在2025年4月发布的开源模型系列，核心创新是**Early Fusion原生多模态架构**和**iRoPE位置编码**，实现了单张H100可运行17B模型、1000万token超长上下文的突破。

### 背景与动机

Llama 3时代，Meta采用的是"先独立训练文本模型，再嫁接视觉Encoder"的拼接式多模态方案。这种方案的缺陷：
- 视觉理解与语言理解能力分离，跨模态推理弱
- 不同模态的tokenization策略不同，难以端到端优化
- 长上下文依赖外推而非真正理解

Llama 4的核心理念：**从第一天起就让所有模态在同一个embedding space中学习**。

### 数学原理

#### 1. Early Fusion（早期融合）架构

所有输入（文本、图像块、视频帧）都映射到**同一个向量空间**，使用统一的attention机制进行跨模态交互：

```math
\begin{aligned}
E_{\text{fused}} &= \text{SharedEmbeddingLayer}(\text{TextTokens} \cup \text{ImagePatches} \cup \text{VideoFrames}) \\
\text{Attention} &= \text{MultiModalAttention}(E_{\text{fused}}) \\
\text{Output} &= \text{UnifiedDecoder}(E_{\text{fused}})
\end{aligned}
```

```python
class EarlyFusionEmbedding(nn.Module):
    """
    Early Fusion: 所有模态共享embedding层
    文本、图像、视频共享同一个token embedding矩阵
    """
    def __init__(self, vocab_size, d_model, image_patch_size=14):
        super().__init__()
        self.patch_size = image_patch_size
        self.token_embedding = nn.Embedding(vocab_size, d_model)
    
    def encode_text(self, text_tokens):
        """文本token编码"""
        return self.token_embedding(text_tokens)
    
    def encode_image(self, image_patches):
        """图像patch编码: (B, N_patches, P*P*3) -> (B, N, D)"""
        patch_embeds = self.proj(image_patches)
        return patch_embeds
    
    def encode_video(self, video_frames):
        """视频帧编码：逐帧处理，共享投影层"""
        B, T, C, H, W = video_frames.shape
        frames_flat = video_frames.view(B*T, C, H, W)
        patches = self.image_to_patch(frames_flat)
        frame_embeds = self.proj(patches)
        return frame_embeds.view(B, T, -1, self.d_model)
```

#### 2. iRoPE（Interleaved Rotary Position Embedding）

解决超长上下文的外推问题：

```math
\begin{aligned}
\text{RoPE}(x_m, m) &= R_m \cdot x_m, \quad R_m = \text{旋转矩阵} \\
\theta_d &= 10000^{-2(d-1)/D}, \quad d=1,2,\dots,D/2
\end{aligned}
```

**iRoPE的关键**：推理时对不同层的RoPE应用不同的temperature scaling，让高层attention层对位置不敏感（支持外推），低层保留精确位置信息：

```python
def irope_forward(x, position_ids, layer_idx, total_layers):
    """
    iRoPE: 逐层位置编码
    低层（layer_idx小）：标准RoPE，保留精确位置
    高层（layer_idx大）：温度缩放RoPE，支持外推
    """
    D = x.shape[-1]
    freqs = 1.0 / (10000 ** (torch.arange(0, D, 2).float() / D))
    
    # 推理时间温度参数（核心创新）
    if layer_idx > total_layers // 2:
        temp = 0.5  # 降低温度 → 对位置不敏感
        freqs = freqs / temp
    
    position = position_ids.float()
    angle = torch.outer(position, freqs)
    return rope_apply(x, angle)
```

class GeGLU(nn.Module):
    """
    Gated GELU: f(x) = GELU(x) * gate(x)
    比SwiGLU更稳定，比ReLU非线性更强

## 2.1 DeepSeek V3.2：Agent推理与强化学习后训练

### 一句话概括
DeepSeek V3.2（2025年12月1日发布）是首个将**思考链与工具调用深度融合**的模型，在1800+强化学习环境中训练，在IMO/ICPC/IOI等顶级竞赛中获得金牌，开源模型Agent能力首次比肩闭源旗舰。

### 核心技术创新

#### 1. DSA（Dense-Sparse Attention）稀疏注意力

传统全注意力的复杂度是 $O(n^2)$，DSA通过**局部+全局混合**大幅降低：

```math
\text{Attention}_{\text{DSA}}(Q, K, V)_i = \alpha \cdot \text{LocalAttn}_i + (1-\alpha) \cdot \text{GlobalAttn}_i
```

- **LocalAttn**：window attention，$O(n \cdot w)$
- **GlobalAttn**：对特殊token和长距离依赖token做注意力
- $\alpha$ 可学习，控制局部/全局权重

```python
class DSALayer(nn.Module):
    """
    DSA: 局部窗口注意力 + 全局稀疏注意力
    复杂度从 O(n^2) 降低到 O(n * w + n * g)
    """
    def __init__(self, d_model, window_size=128, global_tokens=16):
        super().__init__()
        self.local_attn = SlidingWindowAttention(window_size)
        self.global_attn = GlobalAttention(global_tokens)
        self.alpha = nn.Parameter(torch.tensor(0.5))
    
    def forward(self, q, k, v):
        local_out = self.local_attn(q, k, v)
        global_out = self.global_attn(q, k, v)
        alpha = torch.sigmoid(self.alpha)
        return alpha * local_out + (1 - alpha) * global_out
```

\text{启用} & \text{if } \text{mode} = \text{non\_thinking} \\

#### 3. 大规模Agent强化学习训练

V3.2构建了**1800+强化学习环境**，每个环境包含可验证任务和自动评分：

```python
class GRPOAgentTrainer:
    """
    Group Relative Policy Optimization
    核心：在组内比较reward，相对更新策略
    """
    def __init__(self, model, envs):
        self.model = model
        self.envs = envs  # 1800+ RL环境
    
    def train_step(self, batch_prompts):
        # === 1. 生成多个候选回答 ===
        G = 8  # 组大小
        responses = [self.model.generate(p) for _ in range(G)]
        
        # === 2. 计算reward ===
        rewards = [env.evaluate(resp) for env, resp in zip(self.envs, responses)]
        
        # === 3. 组内相对排序 ===
        advantage = normalize(rewards - mean(rewards))
        
        # === 4. GRPO更新 ===
        loss = -log_prob(response) * advantage
        loss.backward()
        self.optimizer.step()
```

## 2.2 MoE训练效率优化

### 一句话概括
MoE（Mixture of Experts）通过稀疏激活让万亿参数模型的推理成本与百亿Dense模型相当，是2025年开源大模型最重要的工程突破。

### 负载均衡损失（Auxiliary Loss）

MoE训练中的核心问题：**专家坍塌**。解决方案是引入辅助负载均衡损失：

```math
\begin{aligned}
\mathcal{L}_{\text{balance}} &= \alpha \cdot \sum_{e=1}^{E} f_e \cdot P_e \\
\text{其中：} \quad f_e &= \frac{1}{T} \sum_{i=1}^{T} \mathbb{1}[\text{top-}k(G(x_i))_e] \quad \text{（被选中频率）}\\
P_e &= \frac{1}{T} \sum_{i=1}^{T} G_e(x_i) \quad \text{（门控分数均值）}
\end{aligned}
```

当 $f_e = P_e = \frac{1}{E}$ 时，损失最小 → 完美均衡

## 2.3 量化技术

### AWQ（Activation-Aware Weight Quantization）核心原理

**核心洞见**：不是所有权重都同等重要，对重要权重使用更高精度：

```math
\begin{aligned}
\text{AWQ改进：} \quad \hat{W} &= \Delta \cdot \text{round}\left(\frac{W}{\Delta \cdot s}\right) \cdot s \\
\text{其中：} \quad s &= \text{per-channel scale}, \quad s \propto \text{act\_scale}
\end{aligned}
```

```python
def awq_quantize(w, n_bit=4):
    """AWQ量化核心步骤"""
    # Step 1: 计算激活相关尺度
    act_scales = w.abs().mean(dim=1, keepdim=True)
    act_scales = act_scales.clamp(min=1e-8)
    
    # Step 2: 权重缩放
    w_scaled = w / act_scales
    
    # Step 3: 量化
    delta = w_scaled.abs().max() / (2**(n_bit - 1))
    w_quant = torch.round(w_scaled / delta)
    
    # Step 4: 反量化
    w_dequant = w_quant * delta * act_scales
    
    return w_quant, delta, act_scales
```

| INT8 | 8 | <2% | 1.5-2x | 通用推理 |

## 3.1 Agentic RAG：从"检索→生成"到"自主规划"

### 传统RAG vs Agentic RAG

```
传统RAG流程：
用户问题 → 检索（向量相似度Top-K）→ 拼接上下文 → LLM生成 → 回答

Agentic RAG流程：
用户问题 → LLM规划（是否需要检索？）→ [检索 → 验证 → 补充检索]
         → LLM推理 → [如需要工具：搜索/代码/API]
         → 生成 → 验证 → 回答
```

### Agentic RAG核心代码框架

```python
import json

class AgenticRAG:
    """
    Agentic RAG: LLM作为Agent自主控制检索流程
    """
    def __init__(self, llm, retriever, tools):
        self.llm = llm
        self.retriever = retriever
        self.tools = tools
    
    def step(self, query: str, max_iterations=5):
        """Agent循环：规划→行动→观察→判断"""
        context = []
        history = []
        
        for iteration in range(max_iterations):
            # === 1. LLM决定下一步行动 ===
            plan_prompt = f"""
当前问题：{query}
已收集上下文：{context}
历史行动：{history}
可用工具：{list(self.tools.keys())}
请决定下一步行动（JSON格式）：
{{"action": "retrieve|search|code|answer|stop", "query": "具体查询内容"}}
"""
            decision = json.loads(self.llm.generate(plan_prompt))
            action = decision["action"]
            
            if action in ["stop", "answer"]:
                break
            
            if action == "retrieve":
                results = self.retriever.search(decision["query"], top_k=5)
                context.extend([r.content for r in results])
                history.append(f"检索: {decision['query']} → {len(results)}条结果")
            
            elif action in self.tools:
                tool_result = self.tools[action](decision["query"])
                context.append(f"[{action}结果]: {tool_result}")
                history.append(f"{action}: {decision['query']}")
        
        # === 2. 最终生成 ===
        final_prompt = f"问题：{query}\n上下文：\n" + "\n".join(context)
        return self.llm.generate(final_prompt)
```

### vLLM PagedAttention 2.0 核心原理

**核心思想**：将KV Cache虚拟分页管理，避免为每个请求预分配完整序列长度的连续显存：

```
传统方式（浪费显存）：
请求1: [Token 0, 1, 2, 3, 4...         | 预分配2048个token位置，大量空闲]
请求2: [Token 0, 1, 2, 3...            | 预分配2048个token位置，大量空闲]

PagedAttention方式（按需分配）：
请求1: [Block0 | Block1 | Block2 |     | 按需分配，每块64 tokens]
请求2: [Block0 | Block1 |              | 更少浪费]
```

```python
class PagedAttentionScheduler:
    """
    PagedAttention: 将KV Cache分页管理
    虚拟分页：64 token/page
    物理块池：动态分配，按需扩展
    """
    def __init__(self, max_model_len=32768, block_size=16):
        self.max_model_len = max_model_len
        self.block_size = block_size
        self.max_blocks = max_model_len // block_size
        self.block_tables = {}  # {request_id: [physical_block_ids]}
        self.free_blocks = list(range(self.max_blocks))
    
    def allocate(self, request_id, num_tokens):
        """为新请求分配物理块（按需分配）"""
        num_blocks = (num_tokens + self.block_size - 1) // self.block_size
        allocated = [self.free_blocks.pop() for _ in range(num_blocks)]
        self.block_tables[request_id] = allocated
        return allocated
    
    def append(self, request_id, new_tokens):
        """为已有请求追加token（无需重新分配完整序列缓存）"""
        num_new_blocks = (new_tokens + self.block_size - 1) // self.block_size
        for _ in range(num_new_blocks):
            self.block_tables[request_id].append(self.free_blocks.pop())
```

**显存节省效果**：在多用户并发场景下，PagedAttention可节省60-80%的KV Cache显存。

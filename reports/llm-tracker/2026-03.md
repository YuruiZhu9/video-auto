|------|---------|-----------|--------|---------|

### 1.3 核心架构创新

#### （1）Dense-MoE 交替结构

LLaMA 4 的关键创新在于不是全MoE层，而是**标准Transformer层与MoE层交替布局**：

```
[Transformer Layer] → [MoE Layer] → [Transformer Layer] → [MoE Layer] → ...
```

**数学原理：** 每个MoE层的输出为：
```
y = Σᵢ Wᵢ(x) · Expertᵢ(x) + Shared(x)
```
其中 `Wᵢ(x)` 是token-dependent路由权重，`Expertᵢ` 是第i个专家MLP，`Shared(x)` 是共享专家输出（始终激活）。

**为什么交替？** 理论上，全MoE层计算效率更高，但实践中发现：
- 纯MoE模型在某些任务（特别是需要深度语义理解）上退步
- Dense层的残差连接维持了信息流稳定性
- 交替结构在**参数量/推理速度**和**模型深度表达力**之间取得平衡

#### （2）iRoPE 位置编码 — 10M上下文的实现钥匙

iRoPE = **intensity + RoPE**（温度缩放注意力 + 无位置嵌入层）。

**传统RoPE的问题：** RoPE通过旋转矩阵编码位置，训练时最大位置是 $M$，推理时超过 $M$ 会导致外推失败（extrapolation failure）。

**iRoPE 核心设计：**
```
Attention(Q, K, V) = softmax( (Q·K^T + λ·bias) / √d ) · V
```
其中 `λ` 是温度缩放因子（temperature scaling），`bias` 是基于token距离的软偏置。

**直觉理解：** 不再精确告诉模型"这是第N个token"，而是给一个"相对热度"信号。模型学习到的是位置之间的相对关系，而不是绝对坐标。

**长度泛化三阶段训练策略：**
```
Stage 1: 强制256K滑动窗口采样 → 培养基础长度感知
Stage 2: 渐进式窗口扩展 256K → 512K → 1M → 2M → 10M
Stage 3: 位置插值微调 → 极端长度下的稳定输出
```

**为什么是10M？** Scout在代码理解能力上超越GPT-4o，长上下文使其能够：
- 理解整部代码仓库的依赖关系
- 完成超长文档的全局一致性编辑
- 支持"整个代码库→修改方案"的端到端推理

#### （3）共享专家机制

```python
class Llama4TextMoe(nn.Module):
    def forward(self, hidden_states):
        # 共享专家：始终激活，提供基础能力
        shared_out = self.shared_expert(hidden_states)
        
        # 路由专家：Top-K选择，专注专业知识
        routed_logits = self.gate(hidden_states)
        routed_out = self.experts(routed_logits, topk=2)
        
        # 结果融合
        return shared_out + routed_out
```

## 二、Qwen3 MoE 深度源码解读

### 2.1 与 DeepSeek MoE 的核心区别

Qwen3 MoE 在架构上与 DeepSeek MoE 一脉相承，但有一个关键实现差异：**Top-K 权重归一化**。

### 2.2 完整 Forward 流程（含形状追踪）

```python
class Qwen3MoeSparseMoeBlock(nn.Module):
    """
    Qwen3 MoE 核心模块
    num_experts = 128 (Maverick配置)
    num_experts_per_tok = 2 (每个token激活2个专家)
    """
    
    def forward(self, hidden_states: torch.Tensor) -> torch.Tensor:
        # ===== Step 1: 形状展平 =====
        batch_size, seq_len, hidden_dim = hidden_states.shape
        hidden_states = hidden_states.view(-1, hidden_dim)  # (B*S, D)
        
        # ===== Step 2: 路由计算 =====
        router_logits = self.gate(hidden_states)          # (B*S, 128 experts)
        routing_weights = F.softmax(router_logits, dim=1)    # (B*S, 128)
        
        # ===== Step 3: Top-K 选择 =====
        routing_weights, selected_experts = torch.topk(
            routing_weights, 
            k=self.top_k,  # top_k=2
            dim=-1
        )
        # selected_experts: (B*S, 2) — 每个token选中的2个专家索引
        
        # ===== 【关键】Step 4: 归一化 Top-K 权重 =====
        if self.norm_topk_prob:
            routing_weights = routing_weights / routing_weights.sum(dim=-1, keepdim=True)
        # 归一化后：routing_weights.sum(dim=-1) = 1.0
        
        # ===== Step 5: One-hot 掩码 =====
        expert_mask = F.one_hot(selected_experts, num_classes=self.num_experts)
        expert_mask = expert_mask.permute(2, 1, 0)  # (128, 2, B*S)
        
        # ===== Step 6: 专家循环计算（稀疏执行）=====
        final_hidden_states = torch.zeros_like(hidden_states)
        
        for expert_idx in range(self.num_experts):
            idx, top_x = torch.where(expert_mask[expert_idx])
            # idx: 在Top-2中的位置 [0]或[1]
            # top_x: 满足条件的token索引
            
            current_state = hidden_states[None, top_x].reshape(-1, hidden_dim)
            current_hidden_states = self.experts[expert_idx](current_state)
            # 加权
            current_hidden_states = current_hidden_states * routing_weights[top_x, idx, None]
            # 累积
            final_hidden_states.index_add_(0, top_x, current_hidden_states)
        
        # ===== Step 7: 恢复原始形状 =====
        return final_hidden_states.view(batch_size, seq_len, hidden_dim)
```

### 2.3 数据流图与形状追踪

```
输入: hidden_states [B, S, D] = [2, 512, 4096]
          ↓ view(-1, D)
展平: [1024, 4096]
          ↓ gate()
路由分: [1024, 128]  (128个专家的未归一化分数)
          ↓ softmax
软权重: [1024, 128]  (每行和为1)
          ↓ topk(k=2)
选中专家: [1024, 2]  (每行2个专家索引)
          ↓ one_hot+permute
掩码: [128, 2, 1024]
          ↓ 循环稀疏执行
专家输出: [1024, 4096]
          ↓ view(B, S, D)
输出: [2, 512, 4096] ✓
```

### 2.4 归一化的数学动机

**问题：** 未归一化时，两个Top-K专家的权重之和可能不等于1：
```
softmax后: [0.5, 0.3, ...] → topk后: [0.5, 0.3]
未归一化加权和 = 0.5*E₁(x) + 0.3*E₂(x)
归一化后加权和 = 0.5/(0.5+0.3)*E₁(x) + 0.3/(0.5+0.3)*E₂(x)
```
**归一化的好处：** 保证加权输出与直接加权求和（稠密计算）在数学上等价，避免信息泄漏到不该激活的专家。

### 2.5 Qwen3 MoE vs DeepSeek MoE 对比

| 维度 | Qwen3 MoE | DeepSeek MoE |
|------|-----------|-------------|
| 专家数 | 128 | 64 |
| Top-K | 2 | 8 |
| 归一化Top-K | ✅ norm_topk_prob | ❌ |
| 共享专家 | ❌ | ✅ Fine-Grained Expert |
| 参数总量 | 235B (激活22B) | 236B (激活20B) |

### 3.2 GRPO 核心原理（Group Relative Policy Optimization）

**GRPO 的核心创新：** 不需要Critic网络，用组内相对排名估计优势函数。

**传统PPO的优势函数：**
```
A(s,a) = Q(s,a) - V(s)  ← 需要单独训练V(s) Critic
```

**GRPO 的优势函数（Group Relative）：**
```
对同一prompt生成G个response: {o₁, o₂, ..., oG}
每个response的reward: {r₁, r₂, ..., rG}

advantage(oᵢ) = rᵢ - mean({r₁,...,rG})
```

**直觉理解：** 如果我的回答比同组其他人的平均回答更好，我就值得强化。这比训练一个全局的价值网络更稳定。

**GRPO 损失函数：**
```python
def grpo_loss(pi_theta, prompts, G=8):
    """
    G: 每组生成的response数量
    """
    group_losses = []
    for prompt in prompts:
        responses = [pi_theta.generate(prompt) for _ in range(G)]
        rewards = [reward_model(response) for response in responses]
        
        # 相对优势计算
        mean_reward = sum(rewards) / G
        advantages = [r - mean_reward for r in rewards]
        
        # 每个response的策略梯度损失
        response_losses = []
        for response, adv in zip(responses, advantages):
            log_prob = pi_theta.log_prob(response)
            response_losses.append(-log_prob * adv)
        
        group_losses.append(sum(response_losses) / G)
    
    return mean(group_losses)
```

### 3.3 DAPO — GRPO 的四大改进

DAPO（Decoupled Clip and Dynamic Sampling Policy Optimization）在2025年被ByteDance团队提出，并在2026年成为主流RL后训练方法。

#### 改进1：修正长度偏置

**问题：** GRPO中，短回答往往获得更高的reward/-token（因为错误率低），导致模型倾向于生成越来越短的回答。

**DAPO解法：** 在reward计算时引入长度归一化：
```python
# GRPO: 直接使用原始reward
reward = reward_model(response)

# DAPO: 长度归一化reward
length_normalized_reward = reward / response_length ** alpha
# alpha 是长度敏感系数，通常设为0.5~1.0
```

#### 改进2：非对称裁剪

**PPO/GRPO的CLIP：** 裁剪限制策略更新的幅度：
```
ratio = pi_theta(a|s) / pi_theta_old(a|s)
clip(ratio, 1-ε, 1+ε)  ← 对ratio的上下界都做裁剪
```

**DAPO的非对称裁剪：** 只裁剪下界，不裁剪上界：
```
clip(ratio, 1-ε, +∞)  ← 允许策略自由增长，限制策略下降
```
**直觉：** 模型已经学会的能力不应该被过度惩罚。放开上界让模型更积极地探索好策略。

#### 改进3：去掉 KL 惩罚项

**GRPO损失包含KL散度约束：**
```python
loss = -grpo_loss - beta * KL(pi_theta || pi_ref)
```
DAPO认为KL惩罚会限制策略的自由度，直接去掉，用更激进的裁剪替代。

#### 改进4：动态采样（Dynamic Sampling）

**问题：** 某些prompt对当前模型来说太难或太容易，生成的结果reward都为0或1，这些样本浪费计算资源。

**DAPO解法：** 动态调整每个prompt的采样数量：
```python
def dynamic_sampling(rewards, threshold=0.1):
    """
    reward方差大的prompt → 增加采样
    reward方差小的prompt → 减少采样
    """
    std = np.std(rewards)
    n_samples = int(base_samples * (1 + std / threshold))
    return n_samples
```

### 3.4 DAPO 数学公式汇总

DAPO的完整目标函数：

$$
\max_{\theta} \mathbb{E}_{p \sim \mathcal{D}, \{o_i\}_{i=1}^G \sim \pi_\theta(\cdot|p)} \left[ \frac{1}{G} \sum_{i=1}^G \frac{\tilde{r}_i}{\|o_i\|^\alpha} \cdot \min\left( r_i(\theta), (1+\epsilon) r_i(\theta_{\text{old}}) \right) \right]
$$

其中：
- $\tilde{r}_i = r_i - \frac{1}{G}\sum_j r_j$（组内相对reward）
- $\|o_i\|^\alpha$：长度归一化（$\alpha$控制长度敏感度）
- $r_i(\theta) = \frac{\pi_\theta(o_i|p)}{\pi_{\theta_{\text{old}}}(o_i|p)}$（策略比率）

## 四、Gated Linear Attention（GLA）— 硬件感知线性注意力

### 4.1 背景：为什么需要 GLA？

标准 Attention 的核心问题：**$O(N^2)$ 时间和空间复杂度**。当序列长度 $N=1M$ 时，注意力矩阵需要存储 $10^{12}$ 个值（假设hidden=4096）。

**线性注意力的朴素想法：** 将 $e^{QK^T/\sqrt{d}}$ 重写为递归形式：

$$
S_t = \sum_{i=1}^{t} e^{q_t \cdot k_i} v_i = e^{q_t \cdot k_t} v_t + e^{q_t \cdot k_t} \cdot S_{t-1}
$$

但这个形式会丢失**输出维度**（输出被压缩为标量），导致表达能力大幅下降。

### 4.2 GLA 的核心设计

GLA 借鉴了 Mamba 选择性状态空间的思想，在线性注意力中引入**输入依赖的门控机制**：

```python
class GLA(nn.Module):
    """
    Gated Linear Attention
    核心思想：用门控机制弥补线性注意力的表达力损失
    """
    def __init__(self, d_model, d_state=16):
        super().__init__()
        self.d_state = d_state
        
        # 投影得到 Q, K, V, gate, D
        self.q_proj = nn.Linear(d_model, d_model)
        self.k_proj = nn.Linear(d_model, d_state * d_model)
        self.v_proj = nn.Linear(d_model, d_state)
        self.gate_proj = nn.Linear(d_model, d_model)  # 关键：门控
        self.D = nn.Parameter(torch.ones(d_model))     # 跳跃连接
        
    def forward(self, x):
        B, L, D = x.shape
        
        # Q: (B, L, D) — 用于与状态交互
        q = self.q_proj(x)
        # K: (B, L, D*d_state) — 展开成d_state维状态
        k = self.k_proj(x).view(B, L, self.d_state, D)
        # V: (B, L, d_state) — 汇总向量
        v = self.v_proj(x)
        # Gate: (B, L, D) — 逐token调制
        gate = F.sigmoid(self.gate_proj(x))
        
        # 递归扫描（简化的FlashLinearAttention风格）
        h = torch.zeros(B, self.d_state, D, device=x.device)
        outputs = []
        
        for t in range(L):
            # 门控选择性地保留/遗忘历史
            gate_t = gate[:, t, :]  # (B, D)
            
            # 更新隐藏状态：选择性读取
            s_t = torch.einsum('bd,bdn->bn', v[:, t, :], k[:, t, :])  # (B, d_state)
            h = h + s_t.unsqueeze(-1) * k[:, t, :].transpose(-2, -1)  # (B, d_state, D)
            
            # 输出：选择性写入
            out_t = torch.einsum('bd,bdn->bn', q[:, t, :], h)  # (B, D)
            out_t = out_t * gate_t + self.D * q[:, t, :]         # 门控+跳跃连接
            
            outputs.append(out_t)
        
        return torch.stack(outputs, dim=1)
```

### 4.3 与 Mamba 的关键对比

| 维度 | Mamba (SSM) | GLA (线性注意力) |
|------|------------|----------------|
| 状态维度 | (d_state, d_model) | 相同，但注意力机制不同 |
| 门控 | $\Delta_t = \text{Linear}(x_t)$ | 独立的gate_proj |
| 输入选择性 | 通过 $\Delta_t$ 控制 | 通过gate_proj控制 |
| 并行化 | 只能递归（扫描） | **硬件感知并行化**（可利用FlashAttention类似的tiling） |
| GPU友好度 | 中等 | **更高**（与FlashAttention共享优化基础设施） |

### 4.4 硬件感知设计原则

GLA 的核心贡献不仅是架构设计，而是**如何让线性注意力在GPU/TPU上高效实现**：

1. **融合核（Fusion Kernel）：** 将Q/K/V投影、门控计算融合为单个CUDA kernel，减少HBM访问
2. **Bank-conflict-free 共享内存访问：** 对状态矩阵采用交错访问模式
3. **自动向量化：** d_state 自动对齐到32/64/128的倍数

## 五、MiniMax-01 — 线性注意力的大规模验证

### 5.1 核心技术突破

MiniMax-01 在2025年发布时引起了巨大反响：**它是首个将线性注意力scale到超大规模并超越同尺寸Transformer性能的开源模型**。

**关键技术选择：** Data-independent decay 的 linear attention（不同于Mamba的data-dependent selective scan）。

### 5.2 Data-independent vs Data-dependent 衰减

**Mamba的衰减（Data-dependent）：**
```python
# 状态更新时选择性遗忘
h_new = e^{-Δ} * A * h_old + ...
# 其中 Δ 是输入x的函数 → 选择性遗忘
```

**MiniMax-01的衰减（Data-independent）：**
```python
# 衰减矩阵A与输入无关，是一个固定的对角矩阵
A = diag(λ₁, λ₂, ..., λ_d)  # 每个维度有不同的固定衰减率
# λ ∈ (0, 1)，越接近0表示越快遗忘

# 优点：可以完全并行化，无需递归
# 缺点：无法做到Mamba那样的选择性记忆
```

**为什么MiniMax选择Data-independent？**

关键在于：**完全可并行化 → 在超大规模训练时收敛更稳定**。Mamba的选择性机制虽然理论上更强大，但在32K+ GPU的分布式训练中，递归依赖会严重拖累并行效率。

### 5.3 MiniMax-M2.7（2026年3月最新）

## 六、RWKV-7 Preview — 动态状态矩阵新范式

### 6.1 核心创新：STATE 动态演化状态矩阵

RWKV-7的核心突破在于提出了**动态演化的状态矩阵S（STATE）**：

$$
v_{\text{output}} \approx k \cdot S^T
$$

其中：
- $k$：当前token的key向量
- $S$：累积的状态矩阵，**随每个新token动态演化**
- 这个状态矩阵 $S$ 就是RWKV-7的"内隐知识库"

### 6.2 与传统Attention的本质区别

| 维度 | Transformer Attention | RWKV-7 STATE |
|------|----------------------|--------------|
| 知识存储 | O(N) KV Cache（N个token各自存储） | O(1) 状态矩阵（压缩到固定维度） |
| 检索方式 | 完整点积注意力（O(N)查询） | 矩阵乘法（O(1)检索） |
| 长期依赖 | 需完整历史（O(N)内存） | 压缩状态（O(1)内存） |
| 推理速度 | 随上下文增长线性变慢 | **恒定时间**推理 |

### 6.3 与 RWKV-6 的区别

RWKV-6的问题：使用固定的衰减机制（time decay），无法自适应地为重要token分配更多权重。

RWKV-7的改进：引入**语义感知的动态状态演化**，让模型自己决定哪些历史信息值得保留：

```python
# 简化的RWKV-7 STATE更新
def state_update(x_t, s_prev, k_t, v_t):
    # 选择性增强：根据当前token动态调整状态
    importance = attention(x_t)  # 输入依赖的重要性分数
    s_new = s_prev + importance * outer(k_t, v_t)
    
    # 选择性衰减：重要状态衰减更慢
    decay_rate = f(s_new)  # 动态衰减率
    s_new = decay_rate * s_new
    
    return s_new
```

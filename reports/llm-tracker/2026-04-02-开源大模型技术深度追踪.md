## 1.1 架构：从Dense到MoE的范式跃迁

### Llama 3时代的困境

Llama 3采用标准Dense Transformer架构（Dense = 每一层所有参数全部参与计算），虽然在Llama 2基础上实现了性能飞跃，但在Scaling Law驱动下，模型参数规模持续膨胀。Llama 3 405B的Dense架构意味着：推理时**全部4050亿参数**都需要参与计算，硬件门槛极高，无法在消费级硬件部署。

**核心矛盾**：Dense架构下，参数规模↑ = 推理成本↑（线性增长），而用户对"更大更强"模型的需求永无止境。

### MoE架构的数学本质

Llama 4引入的**Sparse MoE（稀疏混合专家）**从根本上解决了这个问题。其核心思想是：模型的**总参数量**与推理时**激活参数量**解耦。

```
传统Dense Transformer（前馈网络）：
  输入x → FFN(x) → 输出
  （所有参数全程参与，每个Token激活100%参数）

Llama 4 MoE（前馈网络替换为MoE层）：
  输入x → 路由器(x) → Top-K专家选择 → K个专家加权输出
  （总参数规模大，但每个Token只激活约1/K参数）
```

**数学公式：**

给定输入token向量 $\mathbf{x} \in \mathbb{R}^d$：

**（1）门控路由：**
```math
\mathbf{g} = \text{Softmax}(\mathbf{W}_g \cdot \mathbf{x}) \in \mathbb{R}^E
```
其中 $E$ 是专家总数，$\mathbf{W}_g \in \mathbb{R}^{E \times d}$ 是路由器权重矩阵。

**（2）Top-K专家选择：**
```math
S = \text{TopK}(\mathbf{g}, k) = \{i \mid \mathbf{g}_i \text{ 在前k个最大值中}\}
```
Llama 4 Maverick选择 $k=1$（只激活1个专家），而传统MoE（如Mixtral 8×7B）通常 $k=2$。

**（3）稀疏激活输出：**
```math
\mathbf{y} = \sum_{i \in S} \mathbf{E}_i(\mathbf{x}) \cdot \mathbf{g}_i
```
其中 $\mathbf{E}_i$ 是第 $i$ 个专家网络，$S$ 为选中的专家集合。

**关键设计洞察：**
- **激活专家数 = 1**：比Mixtral（2/8）和DeepSeek-V3（8/256）的稀疏度更高，这意味着推理效率更高，但专家的专业化程度也面临更大挑战

### Dense-MoE交替结构

Llama 4的技术博客披露了一种**Dense-MoE交替布局**：

```
Transformer Block 布局（推测）:
  Layer 1: Dense (标准FFN + Attention)
  Layer 2: MoE (专家路由FFN + Attention)
  Layer 3: MoE
  Layer 4: Dense (无RoPE + 温度缩放)
  ...循环...
```

每4层中3层使用标准RoPE注意力，第4层采用**无RoPE的温度调节注意力**——这是iRoPE架构的关键组成部分。

## 1.2 iRoPE位置编码：无边界的长上下文

### 标准RoPE的局限

Rotary Position Embedding（RoPE）将位置信息编码为旋转矩阵：
```math
\mathbf{R}(\theta, m) = \begin{bmatrix} \cos(m\theta) & -\sin(m\theta) \\ \sin(m\theta) & \cos(m\theta) \end{bmatrix}
```
标准RoPE的局限：**外推长度有限**，超过训练长度后性能急剧下降。

### iRoPE = Interleaved RoPE + 温度缩放

Llama 4提出的**iRoPE**包含两个核心创新：

**创新1：交错注意力层（Interleaved Attention Layers）**

将注意力层分为两类：
- **标准注意力层**：使用标准RoPE位置编码
- **无位置编码的注意力层**：移除位置嵌入，在推理时通过温度缩放注入位置信息

```python
# iRoPE核心实现逻辑（伪代码）
class iRoPEAttention(nn.Module):
    def forward(self, x, position_ids, layer_idx):
        if layer_idx % 4 == 3:  # 每4层中的第4层
            # 无RoPE，使用温度缩放注入位置感知
            attn_output = self.attention_without_rope(x, temperature_scaling=True)
        else:
            # 标准RoPE注意力
            attn_output = standard_rope_attention(x, position_ids)
        return attn_output
```

**创新2：推理时温度缩放（Temperature Scaling）**

在没有显式位置编码的情况下，通过注意力分数的温度因子来调节Token之间的距离感知：
```math
\text{Attention}_{i,j}^{\text{scaled}} = \frac{\exp(\mathbf{q}_i \cdot \mathbf{k}_j / T_{ij})}{\sum_j \exp(\mathbf{q}_i \cdot \mathbf{k}_j / T_{ij})}
```
其中温度因子 $T_{ij} = 1 + \alpha \cdot |i-j|$，$\alpha$ 是衰减系数。

**为什么iRoPE能支持1000万Token上下文？**
- 预训练阶段：强制256K窗口滑动采样，培养模型在各种位置区间的泛化能力
- 推理阶段：iRoPE的位置信息不依赖固定长度的编码表，可以自然外推到任意长度
- 核心直觉：不像ALiBi（线性偏置）或PI（位置插值）需要"挤压"原有位置，iRoPE完全移除了位置编码的硬性约束

## 1.3 原生多模态：Early Fusion早期融合

### 传统多模态的"后期融合"问题

此前主流多模态模型（如LLaVA、InstructBLIP）采用**后期融合（Late Fusion）**架构：

```
图像 → 独立视觉编码器（如CLIP ViT）→ 投影层 → 文本空间
音频 → 独立音频编码器（如Whisper）  → 投影层 → 文本空间
                                              ↓
                                         纯文本LLM处理
```

**核心缺陷**：视觉/音频特征被强制"翻译"成文字再输入LLM，大量非语义信息（色调、构图、语调、音乐情绪）被丢失。

### Early Fusion的数学框架

Llama 4采用**早期融合（Early Fusion）**，在模型的**第一层**就将不同模态的token联合嵌入到统一空间：

```
原始多模态数据（文本token + 图像patch + 视频帧 + 音频）
        ↓
    统一嵌入层（Modality-Agnostic Embedding）
        ↓
    单个Transformer主干（共享参数处理所有模态）
        ↓
    多模态联合理解
```

**模态标签嵌入（Modality Tag）：**
```math
\mathbf{t}_i' = \mathbf{t}_i + \mathbf{E}_{\text{modality}=\text{text}}
\mathbf{v}_j' = \mathbf{v}_j + \mathbf{E}_{\text{modality}=\text{vision}}
\mathbf{f}_k' = \mathbf{f}_k + \mathbf{E}_{\text{modality}=\text{video}}
```
通过可学习的模态标签嵌入，让模型区分不同模态来源，防止混淆。

**训练数据规模：**

|---------|------|
| 文本Token | 30T（Llama 3的2倍） |
| 图像/视频帧 | 48M帧 |
| 语言种类 | 200种（含100+低资源语种，每种≥10亿Token） |

## 1.4 后训练范式：从Heavy SFT到在线RL

### Llama 4的轻量级三阶段后训练

```
阶段1: 轻量SFT
  ↓（仅用精选困难样本，数据量大幅减少）
阶段2: 在线强化学习（Online RL）
  ↓（动态筛选、实时学习）
阶段3: 轻量DPO
  ↓（快速偏好对齐）
```

**阶段1——自我批判式数据筛选（Self-Critic Data Filtering）：**

利用Llama 3作为裁判模型，对候选训练样本进行打分，动态剔除"简单样本"（teacher模型已能正确回答）：

```python
def filter_difficult_samples(candidate_prompts, teacher_model):
    """
    利用上一版本模型（教师模型）筛选困难样本
    """
    scored = []
    for prompt in candidate_prompts:
        response = teacher_model.generate(prompt)
        quality_score = judge_model.evaluate(prompt, response)
        # 动态剔除"简单样本"
        if quality_score < difficulty_threshold:
            scored.append((prompt, response, quality_score))
    return scored
```

**阶段2——在线RL（而非离线RL）：**

- 传统RL（PPO）需要预先收集大量prompt-response数据
- Llama 4的在线RL：Reward Model和数据**同时动态生成**，实时更新策略
- 动态过滤 advantage=0 的prompt，构建难度递进的学习课程（curriculum）

**阶段3——轻量DPO：**
减少DPO的epoch数，避免过度对齐（over-alignment）导致的"讨好"行为。

# 五、专题深度：MoE架构的工程实现——门控路由器设计

## 核心代码实现

```python
import torch
import torch.nn.functional as F
import torch.nn as nn

class TopKMoEGate(nn.Module):
    """
    Llama 4 Maverick使用的门控路由器
    每个Token只激活1个专家（k=1），稀疏度极高
    """
    def __init__(self, d_model: int, num_experts: int, top_k: int = 1):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k
        # 路由器权重矩阵: E × d（每个专家一个权重向量）
        self.gate = nn.Linear(d_model, num_experts, bias=False)
        self.alpha = 0.02  # 负载均衡辅助损失权重
        
    def forward(self, x: torch.Tensor):
        batch_size, seq_len, d_model = x.shape
        x_flat = x.view(-1, d_model)  # [N, d_model]，N = batch * seq_len
        
        # Step 1: 计算门控分数
        gate_logits = self.gate(x_flat)  # [N, num_experts]
        
        # Step 2: Top-K选择（Llama 4 Maverick: k=1）
        gate_values, indices = torch.topk(gate_logits, self.top_k, dim=-1)
        
        # Step 3: Softmax归一化（仅在Top-K专家上）
        weights = F.softmax(gate_values, dim=-1)  # [N, top_k]
        
        # Step 4: 负载均衡辅助损失
        aux_loss = self._compute_load_balance_loss(gate_logits, indices)
        
        # Step 5: 构造稀疏路由矩阵
        zeros = torch.zeros_like(gate_logits)
        routing_weights = zeros.scatter(1, indices, weights.view(-1, 1))
        
        return routing_weights, indices, aux_loss
    
    def _compute_load_balance_loss(self, gate_logits, indices):
        """
        负载均衡损失：防止所有Token都路由到同一两个专家
        """
        num_tokens = gate_logits.size(0)
        
        # 硬计数：每个专家被选中的Token数
        expert_counts = torch.zeros(self.num_experts, device=gate_logits.device)
        for i in range(self.top_k):
            expert_counts.scatter_add_(0, indices[:, i], 
                                       torch.ones(num_tokens, device=gate_logits.device))
        expert_fraction = expert_counts / num_tokens
        
        # 软计数：路由器概率的期望
        gate_probs = F.softmax(gate_logits, dim=-1)
        router_probs = gate_probs.mean(dim=0)  # [num_experts]
        
        # 辅助损失 = num_experts * sum(fraction * router_prob)
        # 当均匀分布时最小
        auxiliary_loss = self.num_experts * torch.sum(expert_fraction * router_probs)
        
        return auxiliary_loss * self.alpha
```

## Expert并行执行（核心优化点）

```python
class MoEFeedForward(nn.Module):
    """
    Llama 4的MoE前馈网络层
    128个专家（Llama 4 Maverick）
    """
    def __init__(self, d_model: int, d_ff: int, num_experts: int, top_k: int):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k
        self.gate = TopKMoEGate(d_model, num_experts, top_k)
        
        # 128个独立的FFN专家
        self.experts = nn.ModuleList([
            nn.Sequential(
                nn.Linear(d_model, d_ff),
                nn.SiLU(),  # SwiGLU激活
                nn.Linear(d_ff, d_model)
            )
            for _ in range(num_experts)
        ])
        
    def forward(self, x: torch.Tensor):
        routing_weights, expert_indices, aux_loss = self.gate(x)
        
        batch_size, seq_len, d_model = x.shape
        output = torch.zeros_like(x)
        
        # 按专家ID分组并行执行（核心优化！）
        for expert_id in range(self.num_experts):
            # 找出所有路由到当前专家的Token
            expert_mask = (expert_indices == expert_id).any(dim=-1)  # [N]
            if expert_mask.sum() == 0:
                continue
            
            expert_input = x.view(-1, d_model)[expert_mask]
            expert_output = self.experts[expert_id](expert_input)  # [M, d_model]
            
            weights = routing_weights.view(-1, self.num_experts)[expert_mask, expert_id]
            output.view(-1, d_model)[expert_mask] += expert_output * weights.unsqueeze(-1)
        
        return output, aux_loss
```

**为什么Expert分组并行？**

假设seq_len=4096，num_experts=128，top_k=1：
- 平均每个专家处理：4096 / 128 = **32个Token**
- 如果串行执行128次小矩阵乘：GPU利用率极低
- **分组并行执行**：先按专家分组，每个组内Token批量矩阵乘，GPU利用率大幅提升
- 这是vLLM/TensorRT-LLM中MoE加速的核心实现

# 七、推荐系统算法工程师视角：Llama 4的关键技术启示

## 1. MoE稀疏路由 → 推荐模型Serving成本革命

推荐系统线上Serving的核心痛点：**用户请求来了，需要实时打分（几百到几千个候选Item），每条打分都需要跑一次模型**。

Llama 4的MoE稀疏激活给了我们启示：

```
传统推荐模型Serving（双塔/DeepFM）：
  1个用户请求 → 跑一次模型 → 打分所有候选Item
  痛点：推理次数 = Item数量（可能几百万次/秒）

"专家路由"思想应用于推荐：
  用户特征 → 路由器 → 选择激活哪些"候选域专家"
  候选Item被分类到不同域（时尚/数码/食品...）
  每个域由专门的专家网络处理 → 推理成本大幅下降
```

## 2. Scout千万上下文 → 跨年用户行为序列建模

Llama 4 Scout的1000万Token上下文 ≈ 可建模1整年的用户行为日志（约10GB文本）。对于推荐系统：
- 当前主流做法：截断到最近7~30天行为
- Scout启示：可以建模全年行为，自动学习季节性/周期性的用户偏好模式

## 3. 飞桨3.0 → 国产深度学习框架新选择

飞桨3.0的自动并行使百亿参数推荐模型的分布式训练门槛大幅降低，**仅需少量代码改造**即可实现Llama 3.1 405B级别的训练规模，对推荐系统的模型迭代有直接价值。

# 一、Stochastic Attention：随机路由的线性注意力新范式

> 💡 **核心洞察**：Stochastic Attention（随机注意力）提出了一种"受大脑启发的随机路由"机制，用概率采样替代确定性的Top-K选择，在线性时间复杂度下实现更强的表达力。这与MoE的稀疏路由有本质区别——它不是"选择哪些专家"，而是"以不同概率激活所有位置"，这为推荐系统的序列建模提供了全新思路。

---

## 1.1 背景：线性注意力的表达力困境

标准Transformer的自注意力机制需要$O(N^2)$计算量来处理$N$个Token的序列，这构成了长上下文场景的计算瓶颈。

**现有线性注意力方案的共同局限：**

此前的主流线性注意力方法（Performer、Linear Transformer等）都使用**确定性的核函数近似**：

```math
\text{Attention}(Q, K, V) \approx \phi(Q) \cdot (\phi(K)^T \cdot V)
```

其中$\phi(\cdot)$是随机特征映射（如正随机投影）。**核心问题**：确定性核近似牺牲了注意力的"选择性"——每个Query对所有Key的注意力分数都是确定的，无法实现类似标准注意力那种"聚焦关键信息"的动态路由。

**标准注意力 vs 线性注意力的对比：**

| 维度 | 标准Softmax Attention | 线性注意力（核近似） |
|------|----------------------|---------------------|
| 时间复杂度 | $O(N^2 \cdot d)$ | $O(N \cdot d^2)$ |
| 空间复杂度 | $O(N^2)$ | $O(N \cdot d)$ |
| 表达能力 | ✅ 完整 | ⚠️ 受限于核函数选择 |
| 动态路由 | ✅ Query-Key自适应 | ❌ 固定核映射 |
| 可并行 | ✅ | ⚠️ 部分受限 |

## 1.2 Connectome启发的核心思想

### 大脑连接组的启示

**Connectome（连接组）**是神经科学中对大脑中所有神经元连接关系的完整映射。研究发现，大脑并非对所有输入都进行同等处理，而是通过**随机但可塑的突触连接**实现高效的信息路由。

**关键洞察：**
- 人类大脑每个神经元的激活并非由单一输入决定，而是由大量输入的**随机采样**决定
- 这种随机性不是噪声，而是**正则化**和**泛化**的来源
- 随机连接使得大脑能以$O(N)$的能耗处理$O(N^2)$级别的信息流

### 随机路由的数学框架

Stochastic Attention将这一思想形式化为：**用随机概率分布替代确定性注意力路由**。

**传统确定性注意力（Query-Key匹配）：**
```math
a_{ij} = \frac{\exp(\mathbf{q}_i \cdot \mathbf{k}_j)}{\sum_{j'=1}^{N}\exp(\mathbf{q}_i \cdot \mathbf{k}_{j'})}
```

**Stochastic Attention（随机路由）：**

引入随机变量$z_{ij} \sim \text{Bernoulli}(p_{ij})$，其中：

```math
p_{ij} = \sigma(\mathbf{q}_i \cdot \mathbf{k}_j / \tau)
```

$\tau$是温度参数，控制随机性的程度（$\tau \to 0$时退化为确定性，$\tau \to \infty$时趋于均匀分布）。

**随机注意力分数：**
```math
\tilde{a}_{ij} = z_{ij} \cdot \frac{\exp(\mathbf{q}_i \cdot \mathbf{k}_j)}{\sum_{j'} z_{ij'} \cdot \exp(\mathbf{q}_i \cdot \mathbf{k}_{j'})}
```

这意味着：**每个Query不是"看"所有Key，而是以概率$p_{ij}$"看"每个Key**，由随机变量$z_{ij}$决定。

## 1.3 线性时间实现：状态空间压缩

### 核心算法

```python
import torch
import torch.nn.functional as F
import math

class StochasticAttention(torch.nn.Module):
    """
    Stochastic Attention: Connectome-inspired randomized routing
    实现：随机注意力机制
    """
    def __init__(self, d_model: int, d_k: int, temperature: float = 1.0,
                 num_samples: int = 1, bias: bool = True):
        super().__init__()
        self.W_q = torch.nn.Linear(d_model, d_k, bias=bias)
        self.W_k = torch.nn.Linear(d_model, d_k, bias=bias)
        self.W_v = torch.nn.Linear(d_model, d_model, bias=bias)
        self.temperature = temperature  # 控制随机性程度的温度参数
        self.num_samples = num_samples   # 多次采样平均次数（Monte Carlo）
        
    def forward(self, x: torch.Tensor, mask: torch.Tensor = None):
        """
        x: [batch, seq_len, d_model]
        returns: [batch, seq_len, d_model]
        """
        batch, seq_len, _ = x.shape
        
        # Step 1: 投影得到 Q, K, V
        Q = self.W_q(x)                           # [B, L, d_k]
        K = self.W_k(x)                           # [B, L, d_k]
        V = self.W_v(x)                           # [B, L, d_model]
        
        # Step 2: 计算注意力 logits（未归一化）
        # [B, L, d_k] @ [B, d_k, L] -> [B, L, L]
        attn_logits = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(Q.size(-1))
        
        # Step 3: 计算路由概率（Softmax归一化）
        routing_probs = F.softmax(attn_logits / self.temperature, dim=-1)  # [B, L, L]
        
        # Step 4: 随机伯努利采样（核心创新！）
        # 每次采样：根据路由概率决定"看"哪些Key
        output_list = []
        for _ in range(self.num_samples):
            # Bernoulli采样：每个位置以routing_probs的概率被激活
            # 技巧：用 Gumbel-Softmax 实现可微的伯努利采样
            gumbels = -torch.empty_like(routing_probs).exponential_().log()  # Gumbel noise
            z = routing_probs * torch.exp(gumbels / self.temperature)         # Gumbel-Softmax
            z = (z > torch.rand_like(z)).float()                            # 硬阈值
            
            # 加权求和
            stochastic_attn = z * routing_probs
            # 行归一化（对每个Query）
            stochastic_attn = stochastic_attn / (stochastic_attn.sum(dim=-1, keepdim=True) + 1e-8)
            
            output_list.append(torch.matmul(stochastic_attn, V))  # [B, L, d_model]
        
        # Step 5: Monte Carlo平均（多次采样降低方差）
        output = torch.stack(output_list, dim=0).mean(dim=0)
        
        return output
```

## 1.4 线性时间变体：状态压缩表示

**上述实现仍是$O(N^2)$，需要进一步改造为真正的线性时间：**

Stochastic Attention与线性注意力核方法的结合：

```python
def stochastic_linear_attention(Q, K, V, state=None):
    """
    线性时间随机注意力（核心公式）
    利用预状态（prev_state）避免全量K-V存储
    
    核心思想：
    标准注意力：attn_output[i] = sum_j(softmax(q_i·k_j) * v_j)
    线性注意力（核近似）：将softmax分解为累积量
    
    随机版本：在累积过程中引入随机采样
    """
    d_k = Q.shape[-1]
    scale = 1.0 / math.sqrt(d_k)
    
    # 核函数：随机投影
    # phi(x) = relu(xW + b) / sqrt(d)
    phi_Q = F.relu(Q @ torch.randn(d_k, d_k, device=Q.device)) * scale
    phi_K = F.relu(K @ torch.randn(d_k, d_k, device=K.device)) * scale
    
    # 随机门控矩阵
    # S[i,j] ~ Bernoulli(p_ij)，p_ij = sigmoid(q_i·k_j / τ)
    gate_logits = (Q @ K.transpose(-2, -1)) / temperature
    gate_probs = torch.sigmoid(gate_logits)  # [B, L, L]
    
    # 硬随机门控（BERNOULLI路由）
    # 利用Gumbel技巧保持可微性
    gumbel_noise = -torch.log(-torch.log(torch.rand_like(gate_probs) + 1e-8) + 1e-8)
    gate_hard = ((gate_probs + 1e-8).log() + gumbel_noise / temperature)
    gate_hard = (gate_hard > 0).float()
    
    # 稀疏化K-V累积（随机路由的结果）
    # 不再是"全部累积"，而是"按概率随机累积"
    KV_weighted = (gate_hard * phi_K).transpose(-2, -1) @ V  # [B, d_k, d_model]
    
    # 线性RNN式累积（核心O(N)操作）
    if state is None:
        state = torch.zeros_like(KV_weighted[:, 0:1]).expand(-1, seq_len, -1)
    
    outputs = []
    for t in range(seq_len):
        # 状态更新（类似GRU的门控机制）
        update_gate = torch.sigmoid(phi_Q[:, t:t+1] @ torch.randn(d_k, 1, device=Q.device))
        candidate = KV_weighted[:, t:t+1]
        
        new_state = update_gate * state[:, t:t+1] + (1 - update_gate) * candidate
        state = torch.cat([state[:, :t+1], new_state], dim=1)
        
        # 读出
        out_t = phi_Q[:, t:t+1] @ new_state.transpose(-2, -1)
        outputs.append(out_t)
    
    return torch.cat(outputs, dim=1), state[:, -1:]
```

## 1.5 与现有方法的对比

| 方法 | 路由方式 | 时间复杂度 | 表达力 | 可微性 |
|------|---------|----------|--------|--------|
| 标准Attention | Query-Key Softmax | $O(N^2 d)$ | 完整 | ✅ |
| Linear Transformer | 核函数近似 | $O(N d^2)$ | 中等 | ✅ |
| Mamba (SSM) | 状态空间选择 | $O(N)$ | 高 | ✅ |
| MoE (TopK) | 确定Top-K选择 | $O(N \cdot k)$ | 高 | ✅ |
| **Stochastic Attention** | **概率采样路由** | $O(N)$ | **高（随机正则化）** | **✅（Gumbel-Softmax）** |

**核心优势：**
- **随机正则化效果**：类似Dropout，但作用在注意力路由层面，有助于防止过拟合
- **表达力不降**：与确定性核方法不同，随机采样保留了注意力的"动态路由"本质
- **硬件友好**：稀疏的随机访问模式在GPU上的合并访问效率更高

**对推荐系统的启示**：用户行为序列的建模，本质上也是一个"哪些历史行为应该被关注"的问题。Stochastic Attention的概率路由思想，可以用于建模"用户以不同概率关注不同历史行为"的不确定性，比固定窗口或硬截断更灵活。

## 3.2 TMRoPE：时间复用旋转位置编码

**Qwen3.5-Omni的核心创新**——TMRoPE（Time-Multiplexed RoPE）是Qwen团队专门为音视频交织信号设计的位置编码方案：

### 传统多模态位置编码的问题

图像和音频在时间维度上有本质区别：
- **图像**：静态，空间位置重要
- **音频**：动态，时间顺序决定语义
- **视频**：两者的混合（帧序列 + 空间）

### TMRoPE的数学原理

TMRoPE将旋转位置编码扩展到多模态场景：

```python
class TMRoPE(torch.nn.Module):
    """
    Time-Multiplexed RoPE
    将不同模态的位置信息编码到统一的旋转空间中
    
    核心思想：
    每个模态有其独立的时间基（时间分辨率），但共享旋转空间
    """
    def __init__(self, d_head: int, max_seq_len: int = 262144,
                 num_modalities: int = 4):
        super().__init__()
        self.d_head = d_head
        # 不同模态的时间分辨率（元信息）
        self.modality_freq = {
            'text': 1.0,      # 每个token = 1个时间单位
            'vision': 1.0,    # 每帧 = 1个时间单位
            'audio': 80.0,   # 每80个音频帧 = 1个"感知时间单位"
            'video': 1.0,    # 每帧 = 1个时间单位（但可配置）
        }
        
    def forward(self, x: torch.Tensor, modality_ids: torch.Tensor,
                time_ids: torch.Tensor):
        """
        x: [batch, seq_len, d_model]
        modality_ids: [batch, seq_len]，标识每个Token的模态来源
        time_ids: [batch, seq_len]，每个Token在其模态内的时间索引
        """
        seq_len = x.shape[1]
        position = torch.arange(seq_len, device=x.device)
        
        # Step 1: 根据模态调整频率基数
        freqs = []
        for mod_id in range(self.num_modalities):
            mod_mask = (modality_ids == mod_id)
            # 获取该模态的频率基数
            freq_base = self.modality_freq_list[mod_id]
            # 在该模态的时间轴上编码
            mod_positions = time_ids.float() * freq_base
            freqs.append(mod_positions * (1.0 / freq_base))
        
        # Step 2: 融合多模态时间轴
        # 不同模态的"时间"被映射到统一的旋转空间
        positions = torch.stack(freqs, dim=0).sum(dim=0)  # [B, L]
        
        # Step 3: 标准RoPE旋转（与Llama/Qwen2相同）
        # 生成旋转矩阵角度
        freqs = 1.0 / (10000.0 ** (2 * torch.arange(0, self.d_head, 2) / self.d_head))
        angles = positions.unsqueeze(-1) * freqs.to(x.device)
        
        # Step 4: 旋转矩阵构造
        cos = torch.cos(angles)
        sin = torch.sin(angles)
        
        # 应用旋转（Qwen/RoPE标准实现）
        x1, x2 = x[..., :self.d_head], x[..., self.d_head:]
        x_rotated = torch.cat([
            x1 * cos - x2 * sin,
            x1 * sin + x2 * cos
        ], dim=-1)
        
        return x_rotated
```

**为什么TMRoPE重要？** 在视频理解中，视频帧（vision）和对应音频（audio）之间存在复杂的时序关系。TMRoPE让模型能够区分"第30帧说话人张嘴"与"第30帧背景音乐播放"，即使它们在时间轴上完全重叠。

## 3.3 RVQ编码：高效音频表征

**RVQ（Residual Vector Quantization，残差矢量量化）**是Qwen3.5-Omni语音生成的声码器核心技术。

### 声码器的基本原理

传统TTS（Text-to-Speech）需要经历：
```
文本 → 梅尔频谱图（Mel Spectrogram）→ 声码器（Vocoder）→ 波形

问题：Mel频谱图 → 声码器 是计算最重的步骤
```

### RVQ替代Mel频谱

RVQ用**离散码本**对音频进行编码：

```python
class RVQAudioEncoder(torch.nn.Module):
    """
    Residual Vector Quantization
    核心思想：用多层码本逐步量化音频特征
    
    每一层量化前一层的残差，层层递进
    """
    def __init__(self, codebook_size: int = 1024, num_layers: int = 8):
        super().__init__()
        self.num_layers = num_layers
        # 8层码本，每层1024个向量
        self.codebooks = torch.nn.ModuleList([
            torch.nn.Embedding(codebook_size, d_model)
            for _ in range(num_layers)
        ])
        
    def forward(self, audio_features: torch.Tensor):
        """
        audio_features: [batch, seq_len, d_model] 原始音频特征
        returns: quantized [batch, seq_len, d_model]
        """
        residual = audio_features
        quantized_list = []
        
        for layer in range(self.num_layers):
            # 最近邻查询：在当前码本中找到最接近残差的码字
            distances = torch.cdist(residual, self.codebooks[layer].weight)
            codes = distances.argmin(dim=-1)  # [B, L] 码字索引
            
            # 重建：码字向量
            quantized = self.codebooks[layer](codes)  # [B, L, d_model]
            
            # 残差更新：下一层量化残余
            residual = residual - quantized
            quantized_list.append(quantized)
        
        # 叠加所有层的量化结果
        # 第1层：捕获主要结构
        # 第2层：补充第1层的残差（细节）
        # ...
        # 第8层：最终残差（高频细节）
        final_quantized = sum(quantized_list)
        
        return final_quantized, codes  # 返回量化特征 + 离散码字（可传输）
```

**为什么RVQ比Mel更高效？**
- Mel频谱图是连续的浮点数表示，存储/传输成本高
- RVQ输出是离散码字序列（整数索引），压缩比极高
- Qwen3.5-Omni支持**36种语言的语音生成**，每个语言使用不同的RVQ码本配置

## 3.4 ARIA：自适应速率交错对齐

**ARIA（A-adaptive Rate Interleaved Alignment）**是Qwen3.5-Omni的流式语音交互关键技术：

在流式场景下，语音生成面临的核心问题：
- Talker以chunk（块）为单位流式输出
- 每个chunk的语义内容与语音单元（phoneme）之间的对齐不固定
- 网络抖动、打断请求都会破坏对齐

**ARIA的解决思路：**

```python
class ARIAModule(torch.nn.Module):
    """
    ARIA: Adaptive Rate Interleaved Alignment
    动态对齐文本Token序列与语音单元流
    """
    def forward(self, text_tokens: torch.Tensor,
                speech_units: torch.Tensor,
                prev_alignment: torch.Tensor = None,
                turn_signal: str = "continue"):
        
        if turn_signal == "interrupt":
            # 用户打断：重置对齐状态
            return self._reset_alignment()
        
        # 自适应速率控制
        # 根据语义密度动态调整每个文本Token分配的语音帧数
        semantic_density = self._compute_semantic_density(text_tokens)
        
        # 语义密度高的Token → 分配更多语音帧（语速放慢）
        # 语义密度低的Token → 分配更少语音帧（语速加快）
        alignment_weights = 1.0 / (semantic_density + 1e-6)
        alignment_weights = alignment_weights / alignment_weights.sum()
        
        # 动态对齐：文本语义与语音波形的对齐表
        # 形状：[num_text_tokens, num_speech_frames]
        alignment_matrix = torch.outer(
            torch.ones(len(text_tokens)), 
            torch.ones(len(speech_units))
        ) * alignment_weights.unsqueeze(-1)
        
        # 加入时序约束：相邻Token的语音倾向于连续
        # 使用对角带约束（diagonal band constraint）
        constraint = self._diagonal_constraint(alignment_weights)
        alignment_matrix = alignment_matrix * constraint
        
        return alignment_matrix
    
    def _compute_semantic_density(self, tokens: torch.Tensor):
        """
        计算每个文本Token的语义密度
        用于决定该Token对应多少语音帧
        """
        # 方法：用注意力机制检测Token间的语义变化
        token_emb = self.embedding(tokens)
        diff = torch.abs(token_emb[:, 1:] - token_emb[:, :-1]).mean(dim=-1)
        density = F.softplus(diff)  # 变化大 → 语义密度高
        return torch.cat([density, density[:, -1:]], dim=-1)
```

**关键效果**：用户可以在Qwen3.5-Omni说话时随时打断，模型能快速"接上"用户的意图，而不是重新开始。这对于语音助手、实时客服等场景至关重要。

### 核心技术一：PLE（Per-Layer Embeddings）逐层嵌入

**传统做法**：所有层共享同一个Token Embedding矩阵，维度必须足够大才能编码足够信息，导致内存占用与模型深度成线性关系。

**PLE做法**：为每个Decoder层提供独立的、较小维度的Token Embedding：

```
传统Embedding（以E2B为例）：
  Token Embedding: [vocab_size, d_model] = [~256K, 256]
  每层输入前都从同一个Embedding矩阵查表

PLE Embedding（以E2B为例）：
  每层有独立的 Embedding_l：[vocab_size, d_layer]（d_layer << d_model）
  第l层输入 = Embedding_l[token_id]  # 该层专属的小维度表征
```

**为什么有效？** 不同层学习不同层次的语义表征：底层用小维度捕获表面特征（词形、词性）；深层用稍大维度捕获抽象语义。这类似于专家分工——每个专家只处理自己擅长的事情，不需要一个"全能型"的超大Embedding。

**推荐系统类比**：推荐系统的特征工程中，我们通常对不同域的特征做独立编码（User Embedding、Item Embedding、Context Embedding）。PLE本质上是将这种思想引入Transformer的层间表征中。

### 核心技术二：TurboQuant压缩算法

TurboQuant是Google自研的感知敏感度混合精度量化算法：

| 量化格式 | 精度 | 内存压缩比 | 速度提升 | 精度损失风险 |
|---------|------|-----------|---------|------------|
| FP32 | 32位 | 1x | 1x | 无 |
| BF16 | 16位 | 2x | ~1.5x | 极低 |
| INT8 | 8位 | 4x | ~2-3x | 低-中 |
| INT4 | 4位 | 8x | ~4-6x | 中-高 |
| **TurboQuant** | **自适应** | **~4-6x** | **~3-4x** | **几乎无损** |

TurboQuant的核心：不同层的参数对量化误差的敏感度不同——QKV投影和LayerNorm保持BF16；FFN中间层可激进量化到INT4；整体效果近乎无损。

### 核心技术三：KV缓存3比特压缩

Auto-regressive推理必须缓存所有历史Token的K和V向量，这是长上下文推理的主要内存瓶颈：

```
标准KV Cache（BF16，31B模型，32K上下文）：
  ≈ 17GB（仅KV Cache！）

Gemma 4的3比特KV压缩：
  17GB × (3/16) ≈ 3.2GB（减少81%）
  同时H100上实现8倍注意力计算加速
```

**3比特量化的数学原理**：标准KV向量经Softmax后有较窄的数值分布，3比特量化利用了这一特性，加上随机舍入（stochastic rounding）消除系统性量化偏差，从数学上保证量化后期望值等于原始值。

# 二、GDPO：NVIDIA修复GRPO的多奖励困境

> 💡 **核心洞察**：当GRPO遇上多奖励RL时，原本聪明的"组内归一化"变成了灾难——不同维度的奖励被压缩到同一个advantage空间，分辨率消失，std≈0时数值爆炸。NVIDIA提出的GDPO（Group Decoupled Policy Optimization）用"奖励解耦归一化"解决了这个问题。对推荐系统的启示：**不同优化目标的梯度不能混在一起归一化**。

---

## 2.1 GRPO在多奖励场景下的根本性缺陷

**问题诊断：归一化的"分辨率丢失"**

GRPO用"组内相对优势"替代PPO中单独训练的Critic：

```
多奖励GRPO（问题来了）：
  假设有两个奖励：R_correct(正确性) + R_format(格式)
  某次采样：R = [R_c=1, R_f=0.9]
  另一个采样：R = [R_c=1, R_f=0.3]
  
  GRPO统一归一化：
  mean = [1.0, 0.6]  # 所有奖励混在一起
  std = [0.0, 0.3]   # 正确性的std=0（方差=0！）→ 除以0 → NaN！
  
  Advantage = (R - mean) / std
            = [NaN, 1.0]  ← 数值爆炸！
```

**核心问题**：
1. **维度间advantage混淆**：两个奖励差异明明不同，但被归一化成相同的advantage
2. **std≈0时数值爆炸**：某些维度所有采样reward都相同 → 除以0 → NaN
3. **训练信号分辨率降低**：原本精确的多维偏好被压缩成一维

---

## 2.2 GDPO的数学原理

**GRPO（统一归一化）**：
```
A_i = (R_i - μ_总) / σ_总
→ 混淆不同奖励维度的尺度
```

**GDPO（解耦归一化）**：
```
# 对每个奖励维度分别计算优势
A_i^correct = (R_i^correct - μ_correct) / σ_correct
A_i^format  = (R_i^format  - μ_format) / σ_format
A_i^length  = (R_i^length  - μ_length) / σ_length

# 加权求和
A_i = w_correct × A_i^correct + w_format × A_i^format + w_length × A_i^length
```

**为什么更优？**

```
设有两个奖励维度 R^1 ∈ {0, 1}（正确性）和 R^2 ∈ [-10, 10]（格式得分）

统一归一化：
  R^1（0或1）对μ和σ的贡献被R^2（-10到10）主导
  → R^1的相对差异被完全忽略

解耦归一化：
  每个维度独立维护自己的尺度信息
  最终advantage = w_1 * (R^1-μ_1)/σ_1 + w_2 * (R^2-μ_2)/σ_2
  → 不同维度的贡献被正确保留
```

---

## 2.3 GDPO代码实现

```python
class GDPO:
    """
    GDPO: Group reward-Decoupled Normalization Policy Optimization
    论文: arXiv:2601.05242 (NVIDIA, 2026年1月)
    """
    
    def __init__(self, rewards_config):
        self.rewards_config = rewards_config
    
    def compute_advantages(self, group_rewards):
        """
        group_rewards: [G, num_rewards]  G个采样，每个有多个奖励维度
        """
        G, num_rewards = group_rewards.shape
        advantages_per_reward = []
        total_weight = 0
        
        # Step 1: 对每个奖励维度分别归一化（核心改进）
        for r_idx, (reward_name, config) in enumerate(self.rewards_config.items()):
            r_dim = group_rewards[:, r_idx]
            mu = r_dim.mean()
            sigma = r_dim.std() + 1e-8  # 加eps防止除零
            adv = (r_dim - mu) / sigma
            weighted_adv = config['weight'] * adv
            advantages_per_reward.append(weighted_adv)
            total_weight += config['weight']
        
        # Step 2: 加权求和
        combined_advantages = sum(advantages_per_reward) / total_weight
        return combined_advantages
    
    def update(self, policy, group_rewards, old_logps, new_logps, reference_logps):
        """
        完整的GDPO更新步骤
        """
        # Step 1: 解耦计算多维优势
        advantages = self.compute_advantages(group_rewards)
        
        # Step 2: 重要性采样比率
        ratio = torch.exp(new_logps - old_logps)
        
        # Step 3: PPO裁剪
        clipped_ratio = ratio.clamp(1 - 0.2, 1 + 0.2)
        
        # Step 4: 策略梯度损失
        policy_loss = -torch.min(
            ratio * advantages,
            clipped_ratio * advantages
        ).mean()
        
        # Step 5: KL散度惩罚
        kl_penalty = (new_logps - reference_logps).mean()
        
        return policy_loss + 0.01 * kl_penalty
```

## 2.5 对推荐系统多目标优化的迁移

推荐系统的多目标优化面临同样的问题——不同业务指标的数值范围差异巨大：

```python
class RecMultiObjectiveGDPO:
    """
    推荐系统多目标优化：用GDPO思想同时优化多个业务指标
    
    推荐系统典型多目标：
    - 点击率（CTR）：binary [0, 1]
    - 转化率（CVR）：continuous [0, 0.3]
    - 用户满意度：continuous [1, 5]
    - 多样性：continuous [0, 1]
    """
    
    def __init__(self):
        self.objectives_config = {
            'ctr': {'weight': 1.0},
            'cvr': {'weight': 2.0},  # CVR更重要，权重更高
            'satisfaction': {'weight': 0.5},
            'diversity': {'weight': 0.3},
        }
    
    def compute_advantages(self, batch_rewards):
        """每个目标独立归一化（GDPO核心思想）"""
        advantages_per_obj = []
        total_weight = 0
        
        for name, rewards in batch_rewards.items():
            config = self.objectives_config[name]
            mu = rewards.mean()
            sigma = rewards.std() + 1e-8
            adv = (rewards - mu) / sigma
            weighted_adv = config['weight'] * adv
            advantages_per_obj.append(weighted_adv)
            total_weight += config['weight']
        
        return sum(advantages_per_obj) / total_weight
```

# 三、Training-Free RL：强化学习的新范式

> 💡 **核心洞察**：Training-Free RL将强化学习的核心范式从"更新模型参数"转变为"优化上下文"。不再训练Policy，而是通过自评估、对比、反思和记忆机制，从rollout中提取"经验/洞察"，并以自然语言形式注入上下文。本质：LLM本身就是Policy，而"经验文本"就是Advantage。

---

## 3.1 范式转变

**传统RL**：
```
1. 定义状态空间S和动作空间A
2. 设计奖励函数R(s, a)
3. 训练Policy π(a|s) → 更新神经网络的权重参数
问题：训练成本高、灾难性遗忘、泛化困难
```

**Training-Free RL**：
```
1. LLM本身就是Policy π（不更新参数）
2. 通过提示工程改变输出分布
3. 用"经验文本"替代传统Advantage：
   - 自评估：让模型自己评价自己的输出
   - 对比学习：比较不同输出的好坏
   - 反思机制：让模型生成"错在哪里"的解释
   - 记忆系统：积累跨episode的高价值经验

  Trajectory → Information Gain → Policy Improvement
```

---

## 3.2 代表方法

| 方法 | 提升的信息类型 | 核心思想 |
|------|----------------|----------|
| **ERL/OEL** | 局部修正（reflection） | 把一次失败变成一条经验规则 |
| **MR-Search** | 跨episode经验 | 把"反思"提升为跨episode的持续积累（接近元学习） |
| **ACT** | 偏好信号（implicit reward） | 用对比学习逼出"真正的自我反思" |

```python
class ExperienceReplayLearning:
    """ERL/OEL: 从失败轨迹中提炼可复用经验"""
    
    def learn_from_failure(self, failed_trajectory):
        # Step 1: 识别失败点
        failure_point = self.identify_failure_point(failed_trajectory)
        
        # Step 2: 生成反思
        reflection = self.llm.generate(
            f"这次推理失败了。失败发生在：{failure_point}\n"
            f"失败的原因是：_______\n"
            f"下次应该避免：_______\n"
        )
        
        # Step 3: 提炼为经验规则
        experience_rule = self.extract_rule(reflection)
        # 例如："当问题包含'至少'时，要考虑下界条件"
        
        # Step 4: 注入到后续上下文中
        improved_trajectory = self.run_with_experience(
            similar_new_prompt,
            experience_context=experience_rule
        )
        return improved_trajectory


class ACT:
    """ACT: Automated Contrastive Thinking — 用对比学习逼出真正的自我反思"""
    
    def contrastive_learning(self, prompt, correct_answer, wrong_answer):
        """给模型看正确答案和错误答案的对比"""
        analysis = self.llm.generate(
            f"好的回答：{correct_answer}\n\n"
            f"差的回答：{wrong_answer}\n\n"
            f"请分析：两个回答的关键差异是什么？"
            f"是什么使得好的回答能够正确，而差的回答犯了错误？"
        )
        enhanced_prompt = f"重要洞察：{analysis}\n\n现在回答新问题：{new_prompt}"
        return enhanced_prompt
```

### 1. GDPO风格的多目标排序学习

```python
class GDPO_RankingLoss:
    """
    推荐系统多目标排序：用GDPO解耦归一化替代统一归一化
    
    推荐场景的多目标：
    - 点击label: {0, 1}
    - 转化label: {0, 1}
    - 停留时长: [0, 60]s
    - 互动深度: [0, 10]
    """
    
    def compute_multi_objective_advantages(self, batch_predictions, batch_labels):
        """每个目标独立归一化"""
        advantages_per_objective = []
        
        for obj_name, (preds, labels) in zip(
            ['ctr', 'cvr', 'stay', 'engage'], 
            batch_labels.items()
        ):
            mu = labels.mean()
            sigma = labels.std() + 1e-8
            # 解耦归一化
            adv = (labels - mu) / sigma
            advantages_per_objective.append(adv * self.weights[obj_name])
        
        return sum(advantages_per_objective)
```

### 2. PLE风格的多域特征编码

```python
class PLEFeatureEncoder:
    """
    PLE风格的推荐系统特征编码：
    不同层学不同粒度的特征表征
    """
    
    def __init__(self, num_layers=4):
        # 每层独立的特征编码器（类似PLE）
        self.layer_encoders = nn.ModuleList([
            nn.Embedding(num_features, embed_dim // (num_layers - layer_idx))
            for layer_idx in range(num_layers)
        ])
    
    def forward(self, feature_ids):
        """
        feature_ids: [B, num_features]
        每层的embedding维度递减（底层小→深层大）
        """
        outputs = []
        for encoder in self.layer_encoders:
            out = encoder(feature_ids)  # 各层独立编码
            outputs.append(out)
        return torch.cat(outputs, dim=-1)  # 拼接
```

### 3. TurboQuant风格的任务感知量化

```python
class TaskAwareQuantization:
    """
    TurboQuant思想应用到推荐模型：
    根据任务目标感知，对不同模块做差异化精度分配
    """
    
    def quantize_recommender(self, model, task_importance):
        """
        task_importance: 任务对不同模块的敏感度
        - Embedding层：对精度最敏感 → BF16
        - CF建模层：中等敏感 → INT8
        - 排序层（最终预测）：最敏感 → BF16
        - 特征交叉层：不那么敏感 → INT4
        """
        for name, module in model.named_modules():
            if 'embedding' in name:
                self._quantize(module, dtype=torch.bfloat16)
            elif 'ranking_head' in name:
                self._quantize(module, dtype=torch.bfloat16)
            elif 'feature_cross' in name:
                self._quantize(module, dtype=torch.int4)
            else:
                self._quantize(module, dtype=torch.int8)
```

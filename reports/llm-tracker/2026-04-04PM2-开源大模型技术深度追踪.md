## 1.3 核心技术：preserve_thinking API

Qwen3.6-Plus引入了业界首个多Agent共享思考缓存的API设计：

```python
# preserve_thinking = false（默认，传统交错思考模式）
# preserve_thinking = true（推荐Agent任务）
#   → 保留所有先前轮次的思考内容
#   → 增强决策一致性
#   → 减少冗余推理，降低整体token消耗

# 示例：多轮Agent任务
response = qwen.chat(
    messages=[...],
    preserve_thinking=True  # 跨轮次记忆思考链
)
```

**技术原理：**
- 多轮对话中，前轮的CoT（思维链）作为上下文被保留
- 后续轮次可以直接基于前轮推理结论继续，而非从头推理
- 对于需要300步以上工具调用链的复杂任务，可节省约30~50%的token

# 二、LinearARD：上下文窗口扩展的60倍效率革命

> 💡 **核心洞察**：LinearARD解决了一个困扰LLM社区的核心问题——**用RoPE缩放进行上下文窗口扩展后，短文本性能严重下降**。传统方法（如LongReD、CPT）需要2.56亿tokens的持续预训练才能恢复，而LinearARD仅需425万tokens（减少约60倍），代价是：直接在注意力结构层面蒸馏，而非匹配隐藏状态。

---

## 2.1 问题本质：为什么扩展上下文会损害短文本能力？

当用RoPE缩放（RoPE Scaling）将模型从4K扩展到32K上下文时：

```
原始RoPE：
  位置n的attention score = f(Q_n, K_n, 位置n)
  其中位置编码函数：θ_i = B^(-2i/d)

缩放后RoPE（扩展到更长上下文）：
  θ'_i = θ_i / α    （α > 1）
  缩放后的旋转角度更小
  → 位置区分度降低
  → 短文本中的细粒度位置信息被破坏

后果：
  - 长文本理解能力 ↑（因为上下文更长了）
  - 短文本基准性能 ↓（位置编码被破坏）
  - 模型在4K以下任务上出现"退化"
```

## 2.2 传统解法及缺陷

| 方法 | 原理 | 训练数据需求 | 效果 |
|------|------|------------|------|
| CPT（持续预训练） | 在长文本上继续预训练 | 256M tokens | 能恢复部分能力，但需要大量数据和算力 |
| LongReD | 用原始位置编码蒸馏 | 256M tokens | 效果较好，但同样需要海量数据 |
| 两者共同缺陷 | **匹配隐藏状态（Hidden States）** | — | 隐藏状态是"不透明的高维向量"，难以精确对齐 |

## 2.3 LinearARD的核心创新

### 蒸馏目标：从隐藏状态 → 注意力结构

**核心洞察**：隐藏状态是模型内部的"黑盒"，难以精确蒸馏。但注意力结构（Q/Q、K/K、V/V自关系矩阵）是模型决策的"直接来源"，对齐它更有效。

```
传统蒸馏（LongReD/CPT）：
  Teacher(原生RoPE, 4K) 隐藏状态 h_t
  Student(缩放RoPE, 32K) 隐藏状态 h_s
  目标：min ||h_t - h_s||

LinearARD蒸馏：
  Teacher(原生RoPE) Q_t/K_t/V_t 自关系矩阵 R_t = softmax(Q_t @ K_t^T / √d)
  Student(缩放RoPE) Q_s/K_s/V_s 自关系矩阵 R_s = softmax(Q_s @ K_s^T / √d)
  目标：min KL(R_t || R_s)   （注意力结构对齐）
```

### 线性内存内核：解决n×n二次瓶颈

Q/Q、K/K、V/V自关系矩阵的大小是n×n，当n=32K时，矩阵大小为32K×32K≈10亿元素，显存无法容纳。

**LinearARD的解法：**

```python
# 原始注意力结构矩阵
R = softmax(Q @ K^T / √d)  # shape: [n, n] → O(n²) 显存

# LinearARD: Per-token log-sum-exp统计量
# 对每一行，只存储 log-sum-exp(r_ij) 而非完整的 n 维向量
# 然后在反向传播时重建精确梯度

class LinearAttentionDistill(nn.Module):
    def forward(self, Q, K, V, teacher_attn):
        # 1. 计算原始注意力（用线性化近似）
        #   使用 linearized attention kernel 避免存储 n×n 矩阵
        
        # 2. 提取 per-token log-sum-exp 统计量
        stats = self.compute_stats(Q, K)  # shape: [n, 1]
        
        # 3. 教师-学生注意力结构对齐
        #   对齐的不是 logits，而是注意力结构的行分布
        loss = self.kl_div_attention_structure(
            teacher_attn, student_attn, 
            method='row_distribution'
        )
        
        # 4. 精确梯度反向传播（不近似）
        loss.backward()  # 反向时重建精确 KL 梯度
```

**数学原理：**

对于注意力矩阵的第i行 $R_i$（n维向量），计算：
$$s_i = \text{logsumexp}(R_i) = \log \sum_{j=1}^{n} \exp(R_{ij})$$

存储 $s_i$（标量）而非完整的 $R_i$（n维向量），将显存复杂度从 $O(n^2)$ 降至 $O(n)$。反向传播时，通过重计算（re-computation）精确还原梯度。

### 蒸馏过程

```
阶段1：教师模型前向传播
  输入: x_1, ..., x_n（短文本，n ≤ 4K）
  Q_t, K_t, V_t = Linear(输入)
  R_t = softmax(Q_t @ K_t^T / √d)     ← 冻结，不更新

阶段2：学生模型前向传播（缩放RoPE）
  输入: x_1, ..., x_n（相同短文本）
  Q_s, K_s, V_s = Linear(输入, θ_s = θ_t/α)
  R_s = softmax(Q_s @ K_s^T / √d)

阶段3：注意力结构蒸馏
  L = KL_div(R_t, R_s)  ← 对齐Q-Q、K-K、V-V自关系矩阵
  更新学生模型参数

阶段4：验证长上下文能力
  在32K长度文档上测试持续推理能力
```

# 三、Apple SSD：无需外部数据的自蒸馏代码生成

> 💡 **核心洞察**：Apple的研究团队提出了SSD（Self-Supervision via Distillation）方法，仅利用模型自身生成的高质量代码作为训练目标，无需任何外部数据或GPT-4教师，即可在代码生成任务上达到接近GPT-4的性能。这为"数据隐私敏感"场景下的模型微调提供了全新范式。

---

## 3.1 核心问题：代码生成的蒸馏困境

传统代码生成模型微调面临的问题：

```
传统蒸馏方法（如StarCoder的指令微调）：
  需要：外部高质量代码数据（如The Stack数据集）
  问题1：数据版权问题（The Stack v2曾因许可证争议下架）
  问题2：数据质量参差不齐，需要大量清洗
  问题3：对于企业私有代码，无法使用外部数据

如果不用外部数据：
  模型自身能力有限，难以通过自训练提升
  → 陷入"能力天花板"
```

## 3.2 SSD的核心思想

**"模型的答案比自己更好"** —— 通过精心设计的采样和过滤策略，让模型从自身生成的数据中学习超越原有水平。

```
传统自训练：
  模型M生成数据D' → 用D'微调M → 能力原地踏步（因为D'是M生成的）

SSD自蒸馏：
  模型M生成N个候选答案{C_1, C_2, ..., C_N}
              ↓
        多样性采样 + 难度过滤
              ↓
     高质量伪标签数据 {C_*, score > τ}
              ↓
     用这些数据微调模型M
              ↓
        能力提升！(超越原始M)
```

**为什么能超越自身？**
关键在于"多样性采样 + 难度过滤"的选择性压力——只保留模型低置信度但实际正确的答案，让模型学习"自己曾经不确定但正确"的模式。

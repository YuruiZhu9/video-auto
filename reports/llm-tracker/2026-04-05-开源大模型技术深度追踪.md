# 二、PLE（Per-Layer Embeddings）逐层嵌入：深度技术解析

> 💡 **核心洞察**：PLE是Gemma 4 E系列的"秘密武器"，通过为每一层Transformer配备独立的token embedding注入通道，让小模型也能获得大模型的语义深度表征能力。这不是简单的embedding复用，而是引入了**层条件化门控**的全新架构设计。

## 2.1 背景：为什么传统Embedding是瓶颈？

### 传统Dense模型的Embedding困境

在标准Transformer（如Llama、Qwen Dense版本）中：

```
Token ID → [Embedding Table: vocab_size × d_model]
            ↓
         单一表征向量 (d_model维)
            ↓
      【此后该token的身份信息完全丢失】
            ↓
       Layer 1 → Layer 2 → ... → Layer N
```

**问题一：信息瓶颈**
- 假设词表大小为V=256K，d_model=4096
- Embedding矩阵参数量：256K × 4096 ≈ **10亿参数**
- 这10亿参数需要在单次查表中编码：词义、词性、语义角色、领域信息……
- 表征维度过低 → 表征能力上限

**问题二：深层语义漂移（Semantic Drift）**
- 随着数据流经深层Transformer，hidden state逐渐被任务相关信息占据
- Token的"原始身份"信号（这个词到底是什么）逐渐被稀释
- 深层的attention head可能"忘记"输入token的真实含义

**问题三：端侧模型受限于小embedding**
- E2B的d_model只有约2048（有效参数仅2.3B）
- 如果用传统方案，embedding表会占用大量参数预算
- 导致留给attention和FFN的参数减少

## 2.2 PLE的数学原理

### 核心公式

PLE在每个Decoder层的残差连接处，额外注入token identity信号：

```
PLE输入 = α_l × Embedding_layer[token_id] + (1 - α_l) × LayerOutput[token_id]
```

其中 α_l 是**层依赖的门控系数**：

```python
# PLE 门控系数的计算方式（概念层）
alpha_l = sigmoid(Linear_L(Layernorm(LayerOutput)) + b_l)
```

**门控系数的物理意义**：
- α_l ∈ [0, 1]，由当前层的输出动态决定
- **浅层**（l小）：α_l 较大 → 依赖原始embedding更多（保留词形、基础语义）
- **深层**（l大）：α_l 较小 → 依赖当前层transformer输出更多（抽象语义）

### 为什么这样设计有效？

直觉一：**分工原则**
- 不同层承担不同抽象级别的任务
- 浅层做词汇级理解（这个词是名词还是动词）
- 深层做语义级推理（这句话表达了什么情感）
- PLE让每层都能"回头确认"输入token是什么

直觉二：**残差增强**
- 标准残差：x_out = x_in + F(x_in)
- PLE残差：x_out = PLE(x_in) + F(x_in)，其中 PLE(x_in) = α_l × Embedding[token] + (1-α_l) × x_in
- 这等于给残差连接添加了一个**自适应偏向项**

直觉三：**数学上等效于增加有效参数**
- 标准方案：每层只有 d_model 维表征
- PLE方案：每层同时拥有 d_model（来自transformer）+ d_embed（来自embedding）
- 如果 d_embed ≈ d_model，则等效参数增加约2倍

## 2.3 PLE vs 传统Embedding：对比分析

| 维度 | 传统共享Embedding | PLE（逐层嵌入） |
|------|-----------------|----------------|
| **embedding表数量** | 1个（全局共享） | N个（每层独立） |
| **token identity信号** | 仅在输入层出现 | 每层都能获得 |
| **参数量开销** | vocab × d_model | vocab × d_layer × N_layers |
| **层间信息流** | 单向衰减 | 每层可自主选择 |
| **适用场景** | 大模型（embedding不占主流） | 小/中模型（embedding相对重要） |
| **语义漂移抵抗** | 弱 | 强（每层可"刷新"token身份） |
| **训练稳定性** | 高（经验证的标准方案） | 中（门控系数需额外调参） |

**数学对比（以E2B为例）**：

```
传统方案：
  Embedding: 256K × 2048 = 512M 参数
  等效表征维度: 2048

PLE方案（假设d_layer = 256，N_layers = 18）：
  Embedding: 256K × 256 × 18 = 1.15G 参数
  等效表征维度: 2048 + 256 = 2304（每层）
  实际参数增量: +640M，但有效表征能力大幅提升
```

## 2.4 PLE代码实现

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class PLEEmbedding(nn.Module):
    """
    Per-Layer Embeddings 实现
    为每一层Decoder提供独立的、层条件化的token embedding注入
    
    与传统方案的本质区别：
    - 传统：所有层共享同一个embedding，token identity在深层会衰减
    - PLE：每层有独立的embedding，通过门控动态决定使用程度
    """
    def __init__(self, vocab_size, d_model, d_embed, n_layers, init_std=0.02):
        super().__init__()
        self.vocab_size = vocab_size
        self.d_model = d_model
        self.d_embed = d_embed
        self.n_layers = n_layers
        
        # 为每层创建独立的embedding表
        # 注意：d_embed << d_model，这是效率的关键
        self.layer_embeddings = nn.ParameterList([
            nn.Parameter(torch.randn(vocab_size, d_embed) * init_std)
            for _ in range(n_layers)
        ])
        
        # 门控网络：为每层预测门控系数 α_l
        # 输入：当前层的LN输出（包含token identity信息）
        # 输出：0~1之间的门控值
        self.gate_networks = nn.ModuleList([
            nn.Sequential(
                nn.Linear(d_model, d_model // 4),
                nn.SiLU(),
                nn.Linear(d_model // 4, 1),
                nn.Sigmoid()  # 输出范围 [0, 1]
            )
            for _ in range(n_layers)
        ])
        
        # 投影层：将layer embedding投影到d_model空间
        self.projection = nn.ModuleList([
            nn.Linear(d_embed, d_model)
            for _ in range(n_layers)
        ])
    
    def forward(self, token_ids, layer_outputs, layer_idx):
        """
        Args:
            token_ids: [batch, seq_len] - 输入token ID
            layer_outputs: [batch, seq_len, d_model] - 当前层的transformer输出
            layer_idx: int - 当前层索引（0~N-1）
        
        Returns:
            ple_signal: [batch, seq_len, d_model] - PLE注入信号
        """
        B, S, D = layer_outputs.shape
        
        # Step 1: 获取该层的独立embedding
        # shape: [batch, seq_len, d_embed]
        layer_emb = F.embedding(
            token_ids, 
            self.layer_embeddings[layer_idx]
        )  # [B, S, d_embed]
        
        # Step 2: 计算门控系数 α_l
        # 基于当前层输出的均值（全局上下文）预测门控值
        # layer_outputs 已经是经过Layernorm的输出
        context = layer_outputs.mean(dim=1)  # [B, D] - 序列级上下文
        alpha = self.gate_networks[layer_idx](context)  # [B, 1]
        alpha = alpha.unsqueeze(1)  # [B, 1, 1]
        
        # Step 3: 投影到d_model空间
        emb_proj = self.projection[layer_idx](layer_emb)  # [B, S, d_model]
        
        # Step 4: 计算PLE信号 = α × PLE_embedding + (1-α) × layer_output
        # 注意：这里PLE_embedding不直接替代layer_output，而是作为残差注入
        ple_signal = alpha * emb_proj + (1 - alpha) * layer_outputs
        
        return ple_signal


class PLETransformerLayer(nn.Module):
    """
    带PLE的完整Transformer层
    在标准注意力+FFN的基础上，增加PLE注入
    """
    def __init__(self, d_model, d_ff, n_heads, d_embed, window_size, use_global, layer_idx):
        super().__init__()
        self.attention = AlternatingAttentionLayer(
            d_model, n_heads, window_size, use_global
        )
        self.ffn = FeedForward(d_model, d_ff)
        self.ple = PLEEmbedding(
            vocab_size=256000,  # Gemma词表大小
            d_model=d_model,
            d_embed=d_embed,
            n_layers=40
        )
        self.layer_idx = layer_idx
        
        # 标准的Pre-Norm结构
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.norm_ple = nn.LayerNorm(d_model)
    
    def forward(self, x, token_ids, is_global_layer=True):
        """
        Args:
            x: [batch, seq_len, d_model] - 输入
            token_ids: [batch, seq_len] - token ID序列
            is_global_layer: bool - 是否为全局注意力层
        """
        # PLE注入（在Attention之前）
        ple_signal = self.ple(token_ids, x, self.layer_idx)
        x = self.norm_ple(x + ple_signal)  # PLE作为残差
        
        # 标准Pre-Norm Attention
        x = x + self.attention(self.norm1(x), is_global_layer)
        
        # 标准Pre-Norm FFN
        x = x + self.ffn(self.norm2(x))
        
        return x
```

## 2.5 PLE与相关技术的对比

### PLE vs MoE（混合专家）

| 维度 | MoE | PLE |
|------|-----|-----|
| **稀疏化对象** | FFN层（专家网络） | Embedding层 |
| **稀疏化方式** | Top-K路由（选择K个专家） | 门控系数（加权组合） |
| **参数分布** | FFN大、Embedding小 | FFN正常、Embedding大 |
| **效果** | 相同计算量下更多参数容量 | 相同参数下更强token理解 |
| **代表模型** | Mixtral、DeepSeek MoE、Gemma 4 26B | Gemma 4 E2B/E4B |

**核心区别**：MoE解决的是"处理能力"问题（哪个专家处理这个token），PLE解决的是"理解能力"问题（这个token到底是什么）。

### PLE vs Multi-Head Extension

有些模型采用多Query注意力（MQA/GQA）来减少KV头数，这和PLE有类似的信息压缩思路，但目标不同：
- MQA/GQA：减少KV缓存压力（效率目标）
- PLE：增强每层的token identity信号（能力目标）

## 2.6 PLE的局限性与未来方向

### 当前局限

**1. 参数量开销**
PLE在E2B中引入了约640M额外参数（18层 × vocab × 256维）。虽然这些参数在推理时可以被条件化处理（不需要完整参与计算），但训练时仍需优化全部参数。

**2. 训练稳定性**
门控网络的引入增加了梯度流的不确定性，需要更仔细的学习率调度。Google在Gemma 4的技术报告中提到，他们采用了**分层学习率衰减**策略来稳定PLE的训练。

**3. 门控网络的过度依赖风险**
如果门控网络学会了"总是输出0.5"，PLE就退化为固定的残差项，失去动态调节能力。Google通过在训练初期强制门控值接近baseline（0.3-0.7范围）来避免这个问题。

### 未来方向

**1. 跨层参数共享的PLE变体**
借鉴Prefix Tuning的思想，可以只在相邻几层共享PLE参数，在保持能力的同时减少开销。

**2. PLE与MoE的结合**
如果将PLE的门控思想引入MoE的专家路由——让每个专家也有自己的embedding层——理论上可以实现更细粒度的token理解。这可能是下一代模型的方向。

**3. 动态PLE（Dynamic PLE）**
根据输入类型（代码/中文/英文/数学）动态调整各层的α_l系数，让模型自适应选择使用token identity的程度。

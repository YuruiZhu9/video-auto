## 1.2 核心技术架构

### 1.2.1 Hybrid MoE + 线性注意力融合

Qwen3.6-Plus采用了**混合专家+线性注意力**的架构，这是对Qwen3.5 MoE架构的重要升级：

```
Qwen3.6-Plus 架构创新点：
┌─────────────────────────────────────────────┐
│  传统Transformer注意力                      │
│  O(n²) 注意力计算，随序列长度平方增长         │
├─────────────────────────────────────────────┤
│  线性注意力（Linear Attention）             │
│  O(n) 核函数近似，突破序列长度限制           │
│  公式：Att(X) ≈ φ(X) · (φ(X)ᵀ · K)          │
│  φ: 非线性映射（核化技巧）                   │
├─────────────────────────────────────────────┤
│  Qwen3.6-Plus的融合策略                      │
│  在浅层（<50%）使用线性注意力（高效捕获     │
│  长程依赖）                                  │
│  在深层使用标准全局注意力（精确token交互）   │
│  专家选择机制：Top-K路由，综合MoE稀疏性     │
└─────────────────────────────────────────────┘
```

**为什么这样做？**

线性注意力的核心思想是用核函数近似softmax注意力：

```math
\text{SoftmaxAttention}(Q, K, V)_i = \frac{\sum_{j=1}^{n} e^{q_i^T k_j} v_j}{\sum_{j=1}^{n} e^{q_i^T k_j}}
```

线性注意力通过特征映射 φ(·) 将 Q、K 映射到低维空间，将计算复杂度从 O(n²) 降至 O(n)：

```math
\text{LinearAttention}(Q, K, V)_i = \frac{\phi(q_i)^T \sum_{j=1}^{i} \phi(k_j)^T v_j}{\phi(q_i)^T \sum_{j=1}^{i} \phi(k_j)^T}
```

关键洞察：线性注意力的"因果性"约束（只看到当前位置之前的token）使其天然适合自回归生成，但代价是**无法精确建模token之间的任意位置交互**。Qwen3.6-Plus的解决方案是在深层仍保留标准注意力——这是目前最优雅的工程折中。

### 1.2.2 1M上下文窗口的工程实现

Qwen3.6-Plus的1M token上下文是当前开源模型之最。实现这一能力的技术基础：

**分段注意力（Segmented Attention）**：
```
1M token 序列的注意力计算不能一次完成，需要分块：
┌─────────┬─────────┬─────────┬─────────┐
│ Block 1 │ Block 2 │ Block 3 │ Block N │  ← 长度N的序列分段
│  16K    │   16K   │   16K   │   16K   │
└─────────┴────┬────┴─────────┴─────────┘
               ↓
每块内部：标准全注意（16K² = 256M计算）
块之间：  稀疏/线性注意（降低块间开销）
               ↓
          KV Cache：分布式存储于多个GPU
```

**p-RoPE（position-aware RoPE）**：
Qwen系列使用旋转位置编码（RoPE）的增强版，对长序列的相对位置进行更好的建模：

```python
# RoPE核心实现（简化版）
def apply_rotrev(q, k, cos, sin):
    # q, k: [batch, heads, seq_len, head_dim]
    # cos, sin: [seq_len, head_dim//2]
    q0, q1 = q[..., :512], q[..., 512:]
    k0, k1 = k[..., :512], k[..., 512:]
    q0, q1 = q0*cos + rotate(q1, -1)*sin, q1*cos + rotate(q0, -1)*sin
    k0, k1 = k0*cos + rotate(k1, -1)*sin, k1*cos + rotate(k0, -1)*sin
    return torch.cat([q0, q1], dim=-1), torch.cat([k0, k1], dim=-1)

def rotate(x, offset):
    # 旋转操作：x_i * cos(θ) + x_{i+1} * (-sin(θ))
    return torch.cat([-x[..., x.shape[-1]//2:], x[..., :x.shape[-1]//2]], dim=-1)
```

# 二、Gemma 4 技术深度续：PLE与mHC架构

## 2.1 PLE（Per-Layer Embeddings）逐层条件化机制

Gemma 4 E2B/E4B的核心创新是PLE——每个Decoder层都有独立的mini embedding表。这与传统Transformer的"共享embedding"完全不同：

### 传统Transformer Embedding策略：
```
Token → [共享Embedding Table] → 统一向量 → 所有Layer共享
         vocab_size × hidden_dim
         ↓
    12层Transformer Decoder共享同一个embedding
```

### Gemma 4 PLE策略：
```
Token → [共享Embedding Table] → 基础向量
         ↓
每个Layer i: [独立Layer Embedding Table] → 条件化向量
         维度：vocab_size × (hidden_dim // num_layers)
         ↓
    各层看到不同的token表示（通过加法/拼接融合）
```

**数学形式化**：

传统embedding：$h^{(0)} = E[x]$（所有层共享）

PLE embedding：
$$h^{(l)} = E[x] + P_l[x]$$

其中 $P_l \in \mathbb{R}^{V \times d}$ 是第 $l$ 层的可学习投影矩阵。注意这里不是为每个token单独训练，而是为**每层的每种token ID**学习一个附加偏移量。

**为什么这样做有效？**

直觉：浅层Transformer更关注**token级别**的局部特征（词法、形态学），而深层Transformer更关注**语义级别**的全局特征。PLE允许模型在浅层"强化"token identity信号，在深层逐步淡化，从而提高参数效率。

**内存效率分析**：
```
传统embedding：5.1B参数（E2B）
PLE额外开销：
- E2B: ~12M额外参数（每层2K vocab × 256维 × 24层 ≈ 12M）
- 增加比例：0.24%额外参数 → 换来端侧推理速度提升~15%
```

### 2.2 Hybrid Attention的数学本质

Gemma 4采用了**局部滑动窗口注意力 + 全局注意力交替**的混合机制：

```
Layer结构（以E4B为例，32层）：
┌────┬─────────────────────────────────┐
│ L1 │ Local Sliding Window Attention  │  ← 窗口大小W=4096
│ L2 │ Global Full Attention           │  ← 全局注意力（所有token可见）
│ L3 │ Local Sliding Window Attention  │
│ L4 │ Global Full Attention           │
│... │ ...                             │
│L31 │ Local Sliding Window Attention  │
│ L32│ Global Full Attention ← 终层必为全局 │
└────┴─────────────────────────────────┘
```

**为什么最后一层必须是全局注意力？**

这是Gemma 4团队的重要设计决策。直觉解释：
- 浅层的局部注意力可以高效捕获n-gram模式（短语、搭配）
- 深层需要整合全序列信息以形成全局理解
- 输出层（Layer N）直接决定next token分布，因此必须能够看到全局信息

数学上，局部注意力的感受野是：

```math
\text{ReceptiveField}(l) = (2l - 1) \times W / 2
```

其中W是滑动窗口大小。对于W=4096，第16层（如果遵循2层交替一次全局）的感受野约为 $16 \times 4K = 64K$ tokens。但全局注意力打破了这一限制，允许直接建模任意距离的依赖。

## 3.2 mHC架构解析

mHC（Manifold Constrained Hyperconnectivity）是DeepSeek V4的核心架构创新，由梁文锋团队耗时六个月打磨：

```
传统Transformer注意力：
所有token在统一的语义空间中交互
Query × Key → Attention Score → Value聚合

mHC的核心思想：
将token交互约束在多个"流形"（manifold）上，
每个流形代表不同的语义维度（如语法/语义/情感/逻辑）
```

**数学框架**：

传统注意力：$\text{Attention}(Q, K, V) = \text{softmax}(QK^T / \sqrt{d})V$

mHC注意力：
```math
\text{mHC-Attention}(Q, K, V) = \sum_{m=1}^{M} \alpha_m \cdot \text{softmax}(Q_m K_m^T / \sqrt{d_m}) V_m

其中：
- M: 流形数量（超参数）
- α_m: 可学习的流形权重
- Q_m, K_m, V_m: 投影到第m个流形的QKV
```

**mHC的实际效果**：

在长序列任务（如代码库理解、文档分析）上，mHC允许模型同时追踪多个语义维度的依赖关系，而不是将所有信息压缩到单一注意力矩阵中。这解决了传统Transformer在长上下文中的"信息瓶颈"问题。

## 3.3 Engram Module（记忆模块）

Engram Module是DeepSeek V4最具颠覆性的技术创新——它试图解决LLM的"健忘症"问题：

```
传统LLM的问题：
- 对话历史在上下文窗口内可以访问
- 超出窗口的历史信息完全丢失
- 无法学习跨会话的用户偏好

Engram Module的解决方案：
将重要的历史信息编码到模型权重中（动态权重更新）
```

**实现机制**：

Engram Module维护一个轻量级的"记忆向量"集合 $\mathcal{E} = \{e_1, e_2, ..., e_k\}$，其中每个 $e_i$ 是D维向量。当模型处理当前输入时：

```python
# Engram Module前向传播（概念化伪代码）
class EngramModule:
    def __init__(self, d_model=7168, memory_slots=1024):
        self.memory = torch.zeros(memory_slots, d_model)  # 可学习记忆槽
        self.gate = nn.Linear(d_model, 1, sigmoid=True)    # 写入门控
    
    def forward(self, x, current_input):
        # 1. 读取：基于当前输入检索相关记忆
        attention_weights = F.cosine_similarity(
            current_input.unsqueeze(1),  # [B, 1, D]
            self.memory,                  # [1, K, D]
            dim=-1
        )
        retrieved_memory = torch.matmul(attention_weights, self.memory)  # [B, D]
        
        # 2. 决策：是否写入新记忆
        write_gate = self.gate(current_input)  # [B, 1]
        # 只有信息熵高/新颖性强时才写入
        
        # 3. 更新记忆
        self.memory = self.memory + write_gate * current_input.detach()
        
        return retrieved_memory
```

**与传统RAG的区别**：

| 维度 | 传统RAG | Engram Module |
|------|---------|--------------|
| 存储位置 | 外部向量数据库 | 模型权重空间内 |
| 检索方式 | 语义向量相似度 | 注意力机制内在整合 |
| 延迟 | 额外的检索步骤 | 无额外延迟 |
| 泛化能力 | 受限于检索质量 | 可跨任务泛化 |
| 遗忘性 | 永久存储 | 可学习遗忘 |

# 四、后训练技术2026全景：从RLHF到RLVR的范式转移

## 4.1 为什么RLHF正在被取代？

传统的RLHF（Reinforcement Learning from Human Feedback）依赖人类偏好标注来训练reward模型，存在三个根本性问题：

```
RLHF的三个困境：
┌─────────────────────────────────────────────────┐
│ 1. 标注成本极高                                  │
│    每次模型迭代需要数千至数万对人类偏好数据        │
│    成本：$0.1-1/对，总成本$10K-100K/次微调        │
│                                                 │
│ 2. 标注一致性差                                   │
│    不同标注者之间的一致性κ约0.3-0.5               │
│    模型难以学到稳定偏好                          │
│                                                 │
│ 3. 可扩展性瓶颈                                  │
│    人类标注速度无法跟上模型规模增长               │
│    SOTA模型每代需要重新标注                       │
└─────────────────────────────────────────────────┘
```

**可验证奖励（Verifiable Rewards）** 的出现完美解决了上述问题：对于数学问题，答案是对是错可以由符号引擎自动判定；对于代码，单元测试自动运行；对于证明，定理证明器给出对错判定。这是"Programmable AI"的核心支撑。

## 4.2 GRPO→DAPO→RLVR演进详解

### 4.2.1 GRPO（Group Relative Policy Optimization）

GRPO由DeepSeekMath在2024年提出，是DeepSeek-R1的关键技术。其核心创新是**用组内相对排名替代价值函数（Critic）**：

```
PPO（传统RL方法）：
需要训练一个价值网络（Critic）来估计"未来期望回报"
 Critic训练不稳定，占用大量GPU显存

GRPO：
不需要Critic，直接用"组内排名"计算优势函数
```

**数学推导**：

对于同一道题目，采样G个回答（通常G=8~64）：
$$r_1, r_2, ..., r_G$$

计算组内均值和标准差：
$$\mu = \frac{1}{G}\sum_{i=1}^{G} r_i, \quad \sigma = \sqrt{\frac{1}{G}\sum_{i=1}^{G}(r_i - \mu)^2}$$

优势函数（Advantage）：
$$A_i = \frac{r_i - \mu}{\sigma}$$

策略梯度更新：
```math
\nabla_\theta J(\theta) = \mathbb{E}_{(x, y) \sim \pi_\theta} \left[ \sum_{i=1}^{|y|} \nabla_\theta \log \pi_\theta(y_i|x, y_{<i}) \cdot \hat{A}_i \right]
```

**关键洞察**：不需要知道"绝对好是多少"，只需要知道"这个回答在组内相对好还是差"。这消除了reward scaling问题。

**GRPO的理论保证**：最新理论分析表明，GRPO的策略梯度在数学上等价于一个"U-统计量"（U-statistic），这意味着当采样数量足够大时，GRPO的行为趋近于"拥有完美价值函数"的Oracle算法。这是GRPO能够work的深层数学原因。

### 4.2.2 DAPO（Decoupled Clip-Higher Dynamic Sampling）

DAPO由字节跳动/清华团队在2025年提出，专门解决**长推理链（Long CoT）RL训练的不稳定性**问题：

```
传统RL在长CoT任务上的不稳定来源：
┌────────────────────────────────────────────────────┐
│ 问题1：熵崩溃（Entropy Collapse）                  │
│ PPO的clip机制限制策略变化 → 模型快速收敛到单一模式  │
│ → 推理多样性丧失，生成内容同质化                    │
│                                                    │
│ 问题2：长序列梯度消失                               │
│ 序列级loss在长CoT上反向传播时，早期token梯度极小    │
│ → 模型无法学习"如何思考"只能学习"思考什么"         │
│                                                    │
│ 问题3：过长响应噪声                                 │
│ 模型生成的推理过程可能超过长度限制                  │
│ → 无效tokens产生误导性奖励信号                     │
└────────────────────────────────────────────────────┘
```

**DAPO四大核心技术**：

```python
# DAPO伪代码实现
class DAPOTrainer:
    def __init__(self, model, config):
        self.clip_high = config.clip_high  # ← 关键1：提高上界clip
        self.dynamic_threshold = 0.9       # ← 关键2：动态采样
        self.token_level_loss = True       # ← 关键3：Token级损失
        self.overlong_penalty = -0.1        # ← 关键4：过长惩罚
    
    def compute_loss(self, batch):
        # 关键1：Clip-Higher（防止熵崩溃）
        # 传统PPO: π_old/π_ref in [1-ε, 1+ε]
        # DAPO:    π_old/π_ref in [1-ε, 1+ε_high]  ← ε_high > ε
        # 提高上限 → 允许更多探索 → 维持熵
        
        # 关键2：动态采样（只保留高信息量样本）
        rewards = self.get_rewards(batch)  # [B]
        mask = rewards > (self.dynamic_threshold * rewards.mean())
        batch = batch[mask]  # 过滤掉低奖励样本（无信息量）
        
        # 关键3：Token级策略梯度（解决梯度消失）
        # 不对整个序列算一个loss，而是每个token单独算
        # 早期token的梯度仍然来自其对最终奖励的贡献
        
        # 关键4：过长响应惩罚
        lengths = batch["lengths"]
        overlong_mask = lengths > self.max_length
        rewards[overlong_mask] += self.overlong_penalty
        
        return token_level_policy_loss
    
    # DAPO结果：
    # Qwen2.5-32B 达到 AIME 2024 50分（DeepSeek-R1-Zero同级）
    # 训练步数减少50%（效率提升）
```

### 4.2.3 RLVR（Reinforcement Learning with Verifiable Rewards）

RLVR是2025年最具颠覆性的范式转变——它证明了**纯RL（无需任何人类标注）就能涌现出强大的推理能力**：

```
DeepSeek-R1-Zero的关键发现（2025年1月）：
┌─────────────────────────────────────────────────────────┐
│ 给模型一道数学题和最终答案正确与否（binary reward）     │
│ 不给任何人类写的推理过程示例                             │
│ → 模型自发涌现出：自我反思、策略切换、长链推理           │
│ → 没有任何SFT（监督微调）的介入                          │
└─────────────────────────────────────────────────────────┘

这证明了：可验证奖励本身已经包含了足够的学习信号，
来教会模型"如何推理"，而不仅仅是"推理什么"
```

**RISE（自验证）技术**：

但纯RLVR有一个问题：模型学会了生成正确答案，但**不擅长检查自己的推理**。RISE（Reinforced Self-Verification）解决了这个问题：

```
RISE训练流程：
┌──────────────────────────────────────────────────────────┐
│ Step 1: 常规RLVR训练                                       │
│ 输入问题 → 模型生成推理过程 → 答案正确/错误 → 奖励信号     │
│                                                           │
│ Step 2: 加入自验证任务（同一RL过程中）                     │
│ 输入问题 → 模型生成推理过程 → 模型自己判断"推理是否正确"   │
│                     ↓                                      │
│         自我判断与最终答案对比 → 额外的验证奖励             │
│                                                           │
│ 结果：模型学会在推理过程中主动"回头检查"                   │
│ SWE-bench自我修复率：提升34%（生成后主动发现错误）         │
└──────────────────────────────────────────────────────────┘
```

## 4.3 偏好优化方法全景对比

### 4.3.1 SimPO（Simple Preference Optimization）

SimPO由Stanford团队提出，在DPO基础上做了关键简化——**去掉参考模型（Reference Model）**：

```
DPO的流程：
Prompt → [Policy + Ref] → Response A/B → 人类偏好标注 → 训练

SimPO的流程：
Prompt → [Policy] → Response A/B → 人类偏好标注 → 训练
             ↑ 不需要参考模型！
```

**SimPO的核心公式**：

```math
\mathcal{L}_{\text{SimPO}} = -\mathbb{E}_{(x, y^+, y^-) \sim \mathcal{D}} \left[ \log \sigma\left( \frac{1}{|y^+|}\sum_{t=1}^{|y^+|} r_\theta(x, y^+_{1:t}) - \frac{1}{|y^-|}\sum_{t=1}^{|y^-|} r_\theta(x, y^-_{1:t}) - \beta \right) \right]
```

用response的平均log概率作为隐式reward，不需要额外的reward model。

**性能对比**：
- AlpacaEval 2: SimPO比DPO高出6.4个百分点
- Arena-Hard: SimPO比DPO高出7.5个百分点

### 4.3.2 ORPO（Odds Ratio Preference Optimization）

ORPO更进一步——**将SFT和偏好优化合并为一个训练目标**，彻底消除了"两阶段训练"的繁琐：

```python
# ORPO的单阶段训练目标
class ORLoss:
    def __init__(self, lambda_or=2.0):
        self.lambda_or = lambda_or  # odds ratio权重
    
    def compute(self, policy_logits, ref_logits, chosen_mask):
        # 1. SFT损失（标准语言建模）
        sft_loss = F.cross_entropy(policy_logits, labels)
        
        # 2. Odds Ratio损失（隐式偏好对齐）
        # odds(p) = p / (1-p)
        # odds_ratio = odds(chosen) / odds(rejected)
        chosen_logprob = log_prob(chosen_mask)
        rejected_logprob = log_prob(~chosen_mask)
        odds_ratio = torch.exp(chosen_logprob - rejected_logprob)
        or_loss = -torch.log(odds_ratio / (1 + odds_ratio))
        
        # 3. 合并（无需参考模型，无需reward模型）
        return sft_loss + self.lambda_or * or_loss
```

# 一、Gemma 4 深度解析：Google 的开源反击（重点技术）

- ✅ 可修改、可分发、可私有部署
- ✅ 无需署名（但推荐注明）
- ✅ 不存在专利授权陷阱

这一转变的战略意义：**Google 正式承认开源是 AI 战略的关键战场**，不再将模型作为云服务护城河，而是让社区自由使用。

### 1.2.1 Gemma 4 31B Dense 架构

31B 密集型模型是 Gemma 4 的旗舰，其核心架构设计：

```
输入 Token → [嵌入层] → [31B Dense Transformer Block × N层]
                                              ↓
                              [Gemma 特有的 Group Norm + RMSNorm]
                                              ↓
                              [RoPE 位置编码（扩展至 256K）]
                                              ↓
                              [多模态融合层（视觉编码器可选）]
                                              ↓
                              [LM Head] → 输出分布
```

**关键技术点**：

1. **Group Normalization 改进**：Gemma 4 采用分组归一化，每个 token 的归一化独立于批次维度，减少批次间干扰，在长上下文任务中尤为重要

2. **256K 上下文支持**：通过扩展的 RoPE（Rotary Position Embedding），Gemma 4 支持 256,000 个 token 的上下文窗口，相当于约 20 万中文字符，可完整处理一本小说的内容

3. **GeGLU 激活函数**：使用 Gated Linear Unit + GeLU，比传统 ReLU 提供更平滑的梯度流，有助于训练稳定性

### 1.2.2 Gemma 4 26B-A4B MoE 架构（重点！）

这是 Google 首次在 Gemma 系列中引入 MoE，核心设计：

```
输入 Token → [路由层 Top-K 门控]
                    ↓
           选择激活 4B / 26B = 约 8 个专家中的 1 个
                    ↓
        [26B 参数 = 8 个 3.25B 专家 FFN]
                    ↓
        [每个 Token 只激活 1 个专家的 FFN]
                    ↓
           输出 = gate(token) × selected_expert(token)
```

**数学原理**：

传统 Dense 前馈网络：
```
y = FFN(x) ∈ ℝ^d    # 所有参数都参与计算
```

MoE 前馈网络（每 token 选择 top-1 专家）：
```
g = softmax(W_gate(x)) ∈ ℝ^E   # E = 专家数量
top_idx = argmax_k(g)           # 选择激活度最高的专家
y = FFN_top_idx(x)               # 只计算选中专家
```

**稀疏激活的数学意义**：26B 模型每个 token 只激活 4B 参数，理论上推理算力需求降低 **~6.5 倍**，而模型总容量（知识存储）保持 26B 不变。这是一种"知识密度"的设计哲学——牺牲一点计算效率，换取在有限激活参数内整合更多知识。

**Google MoE 的独特设计**：

| 传统 MoE（如 Mistral） | Gemma 4 MoE |
|----------------------|-------------|
| Top-2 激活（每次选2个专家） | Top-1 激活（每次选1个专家） |
| 专家容量均衡 | 专家容量可动态调整 |
| 固定专家数量 | 专家可配置路由偏好 |

Google 的 Top-1 设计相比 Top-2 更激进，推理速度更快，但需要更精确的路由决策。Gemma 4 26B 的 AIME 2026 得分（数学推理基准）达到 **89.2%**，说明其路由机制已经高度成熟。

## 2.2 MoE 路由机制深度对比

### 2.2.1 路由机制数学框架

MoE 的核心是路由器（Router），将每个 token 映射到最适合处理它的专家：

```
Router(x) = Softmax(W_r · x) ∈ ℝ^E

# Top-K 选择
top_k_idx = TopK(Router(x), k)

# 加权组合
y = Σ_{i∈top_k} Router(x)[i] · FFN_i(x)
```

**六强 MoE 的路由差异**：

| 模型 | Top-K | 辅助损失 | 负载均衡 | 特色 |
|------|-------|---------|---------|------|
| **GLM-5** | 动态 | DeepSeek 辅助损失 | 自适应 | DeepSeek DSA 稀疏注意力 |
| **Llama 4 Maverick** | Top-2 | auxiliary_loss | 容量因子 | 128 专家超大规模 |
| **Llama 4 Scout** | Top-2 | auxiliary_loss | 容量因子 | 16 专家（高效） |
| **Mistral Small 4** | Top-4 | auxiliary_loss | 专家容量 | 每 token 激活 4 个专家 |
| **gpt-oss-120b** | N/A | N/A | MXFP4 量化 | MoE 投影 MXFP4 |
| **Qwen 3.6 Plus** | 动态 | 混合专家+线性注意力 | 自适应 | 首创 MoE+线性注意力混合 |

### 2.2.2 辅助损失（Auxiliary Loss）与负载均衡

传统 MoE 训练的核心问题是**专家塌陷（Expert Collapse）**——路由器倾向于总是选择同一个专家，导致其他专家永远不被激活。解决方案是辅助损失：

```python
# 辅助损失 = 负载均衡正则项
Penalty = α · Σ_i (H_i · load_i)

# 其中：
# H_i = -Σ_j p_{ij} log(p_{ij})  # 路由器对专家 i 的熵
# load_i = 被分配给专家 i 的 token 比例
# α = 超参数（通常 0.01~0.05）
```

DeepSeek 在 GLM-5 中使用了改进版**专家级均衡辅助损失**，不仅平衡专家激活频率，还考虑了专家在语义空间中的多样性，这可能是 GLM-5 在 SWE-bench 上表现突出的原因之一。

## 2.3 注意力机制创新

### 2.3.1 DeepSeek 稀疏注意力（DSA）在 GLM-5 中的应用

GLM-5 集成了 DeepSeek 的**稀疏注意力机制（DeepSeek Sparse Attention, DSA）**，这是处理 200K 超长上下文的杀手级技术。

传统全注意力：
```
Attention(Q,K,V) = softmax(QK^T/√d)V
复杂度: O(n²)   # n = 序列长度
```

DSA 核心思想：**不是所有 token 都需要关注所有其他 token**。

```python
def deepseek_sparse_attention(q, k, v, block_size=32, global_size=16):
    """
    分块稀疏注意力
    - 每个块内局部注意：O(block_size²)
    - 全局 token（特殊标记）看到所有 token
    - 稀疏块选择：基于键的哈希或学习
    """
    n = q.shape[1]
    
    # 局部块注意（对角块）
    local_out = local_attention(q_local, k_local, v_local)
    
    # 全局注意（[CLS] 类特殊 token）
    global_out = full_attention(q_global, k_full, v_full)
    
    # 稀疏块注意（跨块连接，通过 LSH 或路由选择）
    sparse_out = block_sparse_attention(q, k, v, routing)
    
    return combine(local_out, global_out, sparse_out)
```

**复杂度对比**：

| 序列长度 | 全注意力 | DSA（稀疏） | 节省 |
|---------|---------|------------|------|
| 4K | O(16M) | O(2M) | 87.5% |
| 32K | O(1B) | O(8M) | 99.2% |
| 200K | O(40B) | O(40M) | 99.9% |

这解释了为什么 GLM-5 能在 200K 上下文上高效运行——DSA 把 200K 长度的计算量从 400 亿次降低到 4000 万次，降低了 99.9%。

### 2.3.2 Qwen 3.6 Plus：MoE + 线性注意力混合

Qwen 3.6 Plus 是首个将 MoE 与线性注意力结合的开源模型。这是一个非常有趣的设计：

```
输入 Token
    ↓
┌───────────────────────────────────────┐
│  对于浅层（处理局部模式）：             │
│  → 线性注意力（高效本地建模）           │
│  → O(n) 复杂度                        │
├───────────────────────────────────────┤
│  对于深层（处理全局语义）：             │
│  → 标准 Transformer 注意力            │
│  → O(n²) 复杂度                        │
└───────────────────────────────────────┘
    ↓
混合输出
```

**数学原理**：线性注意力的核心是关联性假设——输出是输入的线性组合：

```
Linear Attention: y_i = Σ_{j=1}^{n} φ(x_i)^T ψ(x_j) · v_j

# 通过核函数近似：
# φ(x) = Elu(xW_1)W_2
# ψ(x) = Elu(xW_3)W_4
```

Qwen 3.6 Plus 可能在 MoE 的前馈层之间插入线性注意力层，使模型在浅层捕获局部语法模式，在深层处理全局语义关系。这是一种**计算资源动态分配**的策略。

# 四、深度技术专题：MoE 的数学与工程（进阶）

## 4.1 门控机制：从 Softmax 到 MoE

### 4.1.1 路由器的数学本质

路由器本质上是一个**分类器**，将每个 token 分配给最适合的专家：

```python
class MoERouter(nn.Module):
    def __init__(self, d_model, num_experts):
        self.gate = nn.Linear(d_model, num_experts, bias=False)
    
    def forward(self, x):
        # x: [batch, seq_len, d_model]
        logits = self.gate(x)              # [B, L, E]
        probs = F.softmax(logits, dim=-1)  # 归一化为概率分布
        
        # Top-K 选择
        top_k_probs, top_k_idx = torch.topk(probs, k=self.top_k, dim=-1)
        
        # 稀疏掩码
        mask = torch.zeros_like(probs)
        mask.scatter_(-1, top_k_idx, top_k_probs)
        
        return mask * probs  # 返回加权掩码
```

### 4.1.2 负载均衡损失的数学推导

**为什么需要负载均衡？**

假设没有辅助损失，路由器可能会：
```
初始：路由器参数随机初始化
训练：某些专家稍微表现好一点
      → 被更多 token 选中
      → 获得更多梯度更新
      → 表现更好
      → 被更多 token 选中
      → ... （富者愈富）
最终：1个专家处理99%的token，其他专家完全空闲
```

辅助损失的数学形式：
```python
def auxiliary_loss(router_probs, token_counts):
    """
    L_aux = α · Σ_i (f_i · P_i)
    
    f_i = token_counts[i] / total_tokens  # 专家 i 的负载比例
    P_i = 路由器对专家 i 的平均概率（熵的代理）
    
    目标：最小化 f_i · P_i，使所有专家负载均衡
    """
    # 计算每个专家的激活比例
    load_per_expert = token_counts / token_counts.sum()
    
    # 计算路由器概率熵（越均匀，P_i 越大，损失越小）
    router_probs_per_expert = router_probs.mean(dim=[0, 1])  # [E]
    
    # 负载均衡损失：负载高且路由概率低的专家受惩罚
    loss = (load_per_expert * router_probs_per_expert).sum()
    
    return loss
```

DeepSeek 的创新：在辅助损失中加入**专家多样性正则项**，鼓励不同专家处理不同语义类型的 token：

```python
def deepseek_auxiliary_loss(router_probs, token_counts, expert_embeddings):
    # 基础负载均衡
    base_loss = super().auxiliary_loss(router_probs, token_counts)
    
    # 专家语义多样性正则
    # 同一时刻激活的专家，其嵌入应该多样化
    active_expert_embs = expert_embeddings[active_indices]
    diversity_loss = -diversity_metric(active_expert_embs)  # 最大化多样性
    
    return base_loss + λ * diversity_loss
```

## 4.2 专家容量与调度

### 4.2.1 容量因子（Capacity Factor）

每个专家有一个**处理容量上限**，防止过载：

```
容量因子 c = 单个专家最大 Token 数 / (总 Token 数 / 专家数)

示例：
- 总 Token = 1024, 专家数 = 8, c = 1.0
- 每个专家最多处理 128 个 token

处理流程：
for token in tokens:
    probs = router(token)
    best_expert = argmax(probs)
    if expert_buffer[best_expert] < capacity:
        assign token to best_expert
    else:
        assign to次优专家（容量未满）
```

### 4.2.2 Mistral Small 4 的动态容量设计

Mistral Small 4 采用**动态容量**，不是固定上限，而是根据当前负载自适应调整：

```python
def dynamic_capacity_router(token, experts_state, base_capacity=128):
    probs = router(token)
    total_active = sum(expert.current_load for expert in experts_state)
    
    # 如果整体利用率低，提高容量上限
    utilization = total_active / (num_experts * base_capacity)
    if utilization < 0.5:
        effective_capacity = base_capacity * 1.5  # 弹性扩容
    else:
        effective_capacity = base_capacity
    
    # 选择专家（考虑当前负载）
    for expert_idx in torch.topk(probs, k=top_k).indices:
        if experts_state[expert_idx].load < effective_capacity:
            return expert_idx
    
    # 所有专家都满载 → 最轻负载专家（强制路由）
    return argmin(expert.load for expert in experts_state)
```

### 6.1.2 连续批处理（Continuous Batching）进化

```
传统批处理（Static Batching）：
[请求1: 32 tokens] [请求2: 128 tokens] [请求3: 8 tokens]
    ↓ 一个批次等所有请求完成
    ↓ 短请求等长请求 → 浪费

连续批处理（Iteration-level Scheduling）：
Step 1: [req1:32] [req2:128] [req3:8]
Step 2: [req2:128] [req1:完成✓] [req4:新请求]
Step 3: [req2:完成✓] [req4:继续] [req5:新请求]
         ↑ 完成即释放，立即填入新请求
```

## 6.2 投机解码（Speculative Decoding）工业落地

投机解码通过小模型"猜测"，大模型"验证"的方式加速推理：

```python
class SpeculativeDecoder:
    def __init__(self, draft_model, target_model, gamma=4):
        """
        draft_model: 小模型（快速生成候选 token）
        target_model: 大模型（验证）
        gamma: 每个步骤最多生成 gamma 个候选 token
        """
        self.draft = draft_model  # e.g., Gemma 4 E2B (2B)
        self.target = target_model # e.g., Gemma 4 31B (31B)
        self.gamma = gamma
    
    def decode(self, input_ids, max_new_tokens):
        generated = input_ids.clone()
        
        while len(generated[0]) - len(input_ids[0]) < max_new_tokens:
            # Step 1: 小模型快速生成 gamma 个候选
            draft_ids = generated.repeat(self.gamma, 1)
            draft_probs = self.draft.get_probs(draft_ids)
            # 取 top-1 作为候选
            draft_tokens = draft_probs.argmax(dim=-1)
            
            # Step 2: 大模型批量验证（矩阵计算，一次验证所有候选）
            target_probs = self.target.get_probs(
                torch.cat([generated, draft_tokens], dim=1)
            )
            
            # Step 3: 自适应接受（从尾到头验证）
            accepted = self._adaptive_accept(draft_tokens, target_probs)
            
            # Step 4: 接受已验证的 token，更新生成序列
            generated = torch.cat([generated, accepted.tokens], dim=1)
            
            if accepted.count == 0:
                # 全被拒绝 → 强制接受 1 个 token（避免死锁）
                generated = torch.cat([generated, draft_tokens[:1]], dim=1)
        
        return generated
    
    def _adaptive_accept(self, draft_tokens, target_probs):
        """自适应的接受机制（基于树结构的加速）"""
        # 标准接受：p_target(token) >= q_draft(token)
        # 加速接受：如果 p_target >> q_draft，直接接受整批
        accepted_mask = target_probs >= draft_probs
        return draft_tokens[accepted_mask]
```

**加速效果（理论值）**：
- 平均接受率 ~70% → 有效加速比 ~2.5x~3x
- Gemma 4 E2B (2B) draft + Gemma 4 31B target 组合，在 AIME 推理任务上实现 **2.8x 加速**，同时保持相同精度

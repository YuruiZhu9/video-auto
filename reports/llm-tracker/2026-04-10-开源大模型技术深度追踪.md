## 1.2 MoE 架构深度解析

### 1.2.1 数学原理：稀疏门控的本质

Llama 4 的 MoE 基于**稀疏门控混合专家**（Sparsely-Gated Mixture-of-Experts）架构，与传统稠密 Transformer 的关键区别在于：

**稠密 Transformer（前馈层）**：
```math
y = \text{FFN}(x) = W_2 \cdot \sigma(W_1 \cdot x)
```
每个 token 必须经过**全部参数**计算，无论是否需要。

**Llama 4 MoE（前馈层）**：
```math
\begin{aligned}
g(x) &= \text{Softmax}\left(\text{TopK}(W_g \cdot x)\right) \\
y &= \sum_{i=1}^{K} g_i \cdot \text{Expert}_i(x)
\end{aligned}
```

其中：
- $W_g \in \mathbb{R}^{N \times d}$：门控投影矩阵（N=专家总数，d=隐藏维度）
- $\text{TopK}(\cdot, K)$：选出激活值最高的 K 个专家
- $g_i \in [0, 1]$：第 i 个专家的加权系数（经 Softmax 归一化）
- $\text{Expert}_i(x) = W_{2,i} \cdot \sigma(W_{1,i} \cdot x)$：第 i 个专家网络

**对于 Maverick（128专家，Top-16）**：
- 每次推理只激活 **128 个专家中的 16 个**
- 激活比例 = 16/128 = **12.5%**
- 计算量约为等参数量稠密模型的 **12.5%**
- 但模型能力却相当于全参数稠密模型（因为每个专家专注于不同领域）

### 1.2.2 负载均衡：Expert 公平分工问题

MoE 最大的工程难题是**负载均衡**——不能让少数"明星专家"被过度使用，其他专家则闲置。Llama 4 使用**辅助损失函数**（Auxiliary Loss）引导路由器公平分配：

```math
\mathcal{L}_{\text{aux}} = \alpha \cdot \sum_{i=1}^{N} f_i \cdot P_i
```

其中：
- $f_i$：第 i 个专家被选中的频率（实际比例）
- $P_i$：路由器给第 i 个专家的平均概率
- $\alpha$：均衡系数（Llama 4 设为 ~0.01）

**直观理解**：如果专家1被选中了 50% 的 token，但平均概率只有 10%，则 $f_1 \cdot P_1 = 0.5 \times 0.1 = 0.05$，产生惩罚。目标是让 $f_i \approx P_i$（被使用频率与被信任程度一致）。

### 1.2.3 Expert 专业化的直观解释

128 个专家如何分工？通过训练观察：

| 专家集群 | 典型激活领域 | 激活频率特征 |
|---------|------------|------------|
| 专家组1-16 | 代码/编程/数学推理 | 高频（数学类prompt） |
| 专家组17-48 | 英语/西欧语言 | 高频（通用任务） |
| 专家组49-80 | 中文/日文/韩文 | 中频（多语言任务） |
| 专家组81-112 | 专业知识（法律/医疗/金融） | 低频（专业prompt） |
| 专家组113-128 | 创意写作/多风格 | 条件激活 |

**这意味着**：同一个 LLM 内部，实际运行着128个"微型专家"，路由器根据输入内容动态选择最相关的子集。

## 1.3 Early Fusion 原生多模态架构

### 1.3.1 与 GPT-4V "外挂式"多模态的本质区别

Llama 4 采用了 **Early Fusion**（早融合）多模态架构，这与 GPT-4V 等"外挂式"多模态有根本性差异：

**外挂式（Late Fusion，GPT-4V等）**：
```
文本 → [LLM主干] ← [视觉编码器输出的token序列]
           ↓
        跨模态对齐（通过投影层）
```

- 视觉编码器（如 CLIP）和 LLM 是**独立训练**的
- 连接点只有一个小投影层（~1M 参数）
- 跨模态推理能力受限于投影层的表达能力

**Llama 4 Early Fusion**：
```
文本token ──┐
图像patch  ──┼──→ [统一多模态Transformer] ──→ 输出
视频frame  ──┤         ↑
语音spectrogram ──┘    │
                        │
              所有模态在第一层即开始深度融合
```

- 图像、视频、文本在**第一层 transformer 就已开始联合建模**
- 不存在单独的"视觉编码器"，所有模态共享同一套注意力机制
- 跨模态推理能力**原生**而非"嫁接"

### 1.3.2 早期融合的数学优势

传统外挂式方法中，视觉信息被"翻译"成固定维度的 token 序列再输入 LLM，这个翻译过程存在信息瓶颈：

- 图像 → CLIP ViT → N个固定token（N通常=256或576）
- 无论图像分辨率如何变化，最终输入 LLM 的 token 数是固定的

Early Fusion 则允许模型**自适应决定**图像 patch 的融合深度：

```math
\text{Attention}_{mm}(X_{\text{text}}, X_{\text{img}}) = \text{softmax}\left(\frac{Q K^T}{\sqrt{d_k}}\right) V
```

其中 $X_{\text{img}}$ 的 patch 数量与图像分辨率成比例，高分辨率图像可以获得更多"视觉 token"，与文本 token 在同一注意力空间内深度交互。

## 1.4 蒸馏训练：从 Behemoth 到 Maverick

Maverick 采用了**协同蒸馏**（Co-Distillation）策略，以 Behemoth（约2T参数）为教师模型：

```
Behemoth(2T) → Soft Labels → Maverick(17B active)
     ↑                          ↑
  高质量推理轨迹            学习泛化能力
```

**软标签蒸馏损失**：
```math
\mathcal{L}_{\text{distill}} = \text{KL}\left(\pi_{\text{Maverick}} \| \pi_{\text{Behemoth}}\right)
= \sum_x \pi_{\text{Behemoth}}(x) \cdot \log \frac{\pi_{\text{Maverick}}(x)}{\pi_{\text{Behemoth}}(x)}
```

**为什么软标签优于硬标签？**

| 对比维度 | 硬标签（Hard Label） | 软标签（Soft Label，Behemoth蒸馏） |
|---------|------------------|--------------------------------|
| 信息量 | 只有正确答案 | 包含所有可能答案的概率分布 |
| 泛化能力 | 有限 | 迁移"推理思路"而非"答案" |
| 训练稳定性 | 容易过拟合 | 更平滑的梯度 |
| 计算开销 | 低 | 高（需要Behemoth前向传播） |

**关键洞察**：Maverick 的"17B 激活参数 + 128 专家"之所以能匹敌更大模型，正是因为它从 Behemoth 那里学到了**跨领域的通用推理模式**，而不只是特定任务的答案。

# 三、强化学习训练新范式：Dr.GRPO 深度解析

## 3.1 GRPO 的长度偏差问题回顾

标准 GRPO 的奖励归一化公式：
```math
\tilde{r}_i = \frac{r_i - \mu(\mathbf{r})}{\sigma(\mathbf{r})}
```

其中 $\sigma(\mathbf{r})$（组内奖励标准差）隐式包含了响应长度信息——长回答更容易产生奖励方差（正确时更高、错误时更低），导致：

1. **正确答案**：长回答的 $\tilde{r}$ 被低估（因为方差被膨胀）
2. **错误答案**：长回答的策略梯度被异常削弱

**最终结果**：训练过程中模型倾向于无意义地延长回答（token bloat），而非提升推理质量。

## 3.2 Dr.GRPO 的核心修复

**数学改进**：用全局常量替代动态 $\sigma$：
```math
\tilde{r}_i^{\text{Dr.GRPO}} = r_i - \bar{r} \quad \text{其中} \quad \bar{r} = \text{mean}(\mathbf{r})
```

**三个关键改进**：

| 改进点 | GRPO | Dr.GRPO |
|--------|------|---------|
| 奖励基准 | 组内均值（依赖组内所有回答） | 组内均值（不变） |
| 奖励缩放 | 动态 $\sigma$（引入长度偏差） | **固定缩放常数 C**（无偏） |
| 梯度稳定性 | 低效回答梯度被异常削弱 | 所有回答梯度**无偏** |

**代码实现示例**：
```python
def dr_grpo_reward_normalize(rewards: torch.Tensor, C: float = 2.0) -> torch.Tensor:
    """
    Dr.GRPO 无偏奖励归一化
    rewards: shape=(G,)，G为每组样本数（通常8-16）
    C: 固定缩放常数，对应原σ的典型值
    """
    baseline = rewards.mean()              # 组均值（与GRPO相同）
    normalized = rewards - baseline         # 去中心化
    # 用固定常数C替代动态σ，消除长度偏差
    return normalized / C                  # 无偏归一化

# 策略梯度计算（不再受长度干扰）
def dr_grpo_policy_gradient(log_probs, normalized_rewards, old_log_probs):
    ratio = torch.exp(log_probs - old_log_probs)
    # 优势量直接来自Dr.GRPO归一化结果（无偏）
    advantage = normalized_rewards.unsqueeze(-1)
    return -(ratio * advantage).mean()
```

## 3.3 开源 RL 训练生态影响

Dr.GRPO 的意义在于**让强化学习训练真正工程化**：

```
传统 RLHF 流程：
PPO → 需要 Value Network → 额外40%显存开销
     → 复杂超参调优 → 难以复现

   → 令牌效率提升 → 减少30-50%训练token消耗
```

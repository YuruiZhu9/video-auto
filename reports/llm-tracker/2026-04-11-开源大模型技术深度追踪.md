## 1.2 架构解析：744B MoE的技术密码

### 1.2.1 整体架构

GLM-5.1采用了**混合专家（MoE）+多头自回归**架构，关键参数：

```
总参数量：744B（稀疏激活）

```

这意味着GLM-5.1的**激活比例约为 40/744 ≈ 5.4%**，比Llama 4 Maverick（16/128 = 12.5%）更稀疏，单次推理的计算成本更低。

### 1.2.2 MoE门控机制深度解析

GLM-5.1的门控机制可表述为：

```math
\begin{aligned}
\text{Gate}(x) &= \text{Softmax}(W_g \cdot x) \in \mathbb{R}^{E} \\
\text{Top-}K(x) &= \text{indices of top-}K \text{ values in Gate}(x) \\
y &= \sum_{i \in \text{Top-}K(x)} \frac{\exp(g_i)}{\sum_{j \in \text{Top-}K} \exp(g_j)} \cdot \text{FFN}_i(x)
\end{aligned}
```

其中 $E$ 是专家总数，$K$ 是激活专家数。GLM-5.1的稀疏激活带来两个显著优势：

**优势一：FLOPs降低**
```
稠密模型（GPT-4级别）：每个token = O(d_model × d_ffn)
GLM-5.1（K/N激活）：   每个token = O(d_model × d_ffn × K/N)

代入 d_model=8192, d_ffn=32768, K/N=5.4%：
GLM-5.1的计算量 ≈ 稠密模型的 5.4%
```

**优势二：专家专门化**

通过观察专家激活频率分布，可以推断GLM-5.1的专家分工：

| 专家类别 | 推测专业领域 | 激活条件 |
|---------|------------|---------|
| 专家1-4 | 数学推理/定理证明 | 包含"求证"、"计算"、"证明"等词 |
| 专家5-8 | 代码生成/调试 | 包含"def"、"import"、"debug"等 |
| 专家9-14 | 中文NLP/文档生成 | 中文语境为主 |
| 专家15-20 | 英文写作/翻译 | 英文语境为主 |
| 专家21-28 | 专业领域（法律/医疗/金融） | 专业术语触发 |
| 专家29+ | 创意写作/多风格 | 非结构化、开放域prompt |

```python
# GLM-5.1 编程能力的可能技术路径
class CodeExpertRouter(nn.Module):
    """
    代码专家路由器：识别编程任务的子类型
    激活对应的代码专家子网络
    """
    def __init__(self, hidden_dim, num_experts=8):
        super().__init__()
        self.router = nn.Linear(hidden_dim, num_experts)
        self.code_experts = nn.ModuleList([
            CodeExpertFFN(hidden_dim) for _ in range(num_experts)
        ])
        # 专家分类（推测）：
        # 0: 语法解析 / 1: 逻辑修复 / 2: 测试生成
        # 3: 重构优化 / 4: API调用 / 5: 文档生成
        # 6: 性能调优 / 7: 安全修复

    def forward(self, x, task_type_hint=None):
        # task_type_hint: 来自规划模块的任务类型信号
        logits = self.router(x)
        if task_type_hint is not None:
            # 硬编码某些token激活特定专家（无梯度截断）
            logits += F.one_hot(task_type_hint, num_classes=8) * 10.0
        weights = F.softmax(logits, dim=-1)
        top_k_indices = torch.topk(weights, k=2).indices
        
        outputs = []
        for idx in top_k_indices:
            outputs.append(self.code_experts[idx](x))
        
        return sum(w * o for w, o in zip(weights[top_k_indices], outputs))
```

# 二、DAPO：后训练RL的四大技术创新

## 2.1 GRPO → DAPO：演进背景

DeepSeek-R1引爆的GRPO范式存在两个根本性问题：

**问题一：Token-level Reward的过度优化**
```math
\mathcal{L}_{\text{GRPO}} = -\mathbb{E}_{x \sim p_{\theta}, a \sim \pi_\theta(\cdot|x)}
\left[ \sum_{t=1}^{T} \min\left(r_t(\theta)\hat{A}_t, \text{clip}(r_t(\theta)) \hat{A}_t\right) \right]
```
其中 $\hat{A}_t$ 是基于组内reward估计的优势函数，PPO的clip限制了策略更新的幅度。

**问题二：长度外推导致的Reward Hacking**
- 正确长回答 → 高reward + 继续生成 → 更长 → 更正确 → 无限循环
- 错误短回答 → 低reward → 停止 → 永远无法学会复杂推理

## 2.2 DAPO四大技术创新

字节跳动与清华大学SIA实验室提出的DAPO，包含**四个独立的技术改进**：

### 技术一：Decoupled Clip（解耦裁剪）

**问题**：PPO/GRPO中，clip操作同时作用于策略比率和优势估计，导致：
- 当优势为负时，clip反而阻止了学习（保守性过度）
- 当优势为正时，clip阻止了探索（探索性不足）

**DAPO解法**：
```python
class DecoupledClip:
    """
    传统PPO：clip(π_θ/π_θ_old, 1-ε, 1+ε) × advantage
    DAPO：   clip(π_θ/π_θ_old, 1-ε_lower, 1+ε_upper) × advantage
    """
    def __init__(self, epsilon_lower=0.2, epsilon_upper=0.3):
        self.eps_lower = epsilon_lower
        self.eps_upper = epsilon_upper

    def ppo_loss(self, ratio, advantage):
        # 正优势：允许更激进地上升（上限更宽松）
        # 负优势：限制下降幅度（下限更紧）
        clip_lower = (1 - self.eps_lower) * advantage
        clip_upper = (1 + self.eps_upper) * advantage
        
        # 优势为正 → 用宽松上限clip
        # 优势为负 → 用紧凑下限clip
        clipped = torch.clamp(ratio, 1 - self.eps_lower, 1 + self.eps_upper)
        return -min(ratio * advantage, clipped * advantage)
```

### 技术二：Dynamic Sampling（动态采样）

**问题**：GRPO对所有样本使用相同的batch，即使有些样本已经"学会"（优势估计收敛），仍在浪费计算资源。

**DAPO解法**：
```python
def dynamic_sampling(rewards, threshold=0.95):
    """
    对于reward接近确定（>95%确信）的样本，减少训练权重
    对于reward不确定的样本，增加训练权重
    """
    certainty = torch.abs(rewards)  # reward的绝对值 = 确定性
    # 归一化确定性：接近1 = 已学会，接近0 = 仍需学习
    learn_weight = 1 - certainty  # 未学会的样本权重更高
    
    # 高确定性样本（正确答案）：降低权重，减少过拟合
    # 低确定性样本（模棱两可）：提高权重，重点攻关
    return learn_weight / learn_weight.sum()
```

### 技术三：Margin-guided-clipping（边缘引导裁剪）

**改进优势函数估计**：
```math
\hat{A}_t^{\text{DAPO}} = \frac{r_t - r_{\text{baseline}}}{\max(r_{\text{max}} - r_{\text{baseline}}, \epsilon)}
```

这比标准GRPO的 $\frac{r_t - \mu(r)}{\sigma(r)}$ 更稳定：
- 不受组内样本数量的影响
- 使用绝对尺度而非相对尺度
- 对极端reward值更鲁棒

### 技术四：Overlong Reward Penalty（过长回答惩罚）

**针对token bloat问题**：
```python
def overlong_penalty(reward, response_length, max_length=8192):
    """
    当回答超过合理长度时，施加线性惩罚
    防止模型通过无意义延长来"刷"reward
    """
    if response_length > max_length:
        # 超过越长，惩罚越重（指数衰减）
        over_ratio = (response_length - max_length) / max_length
        penalty = -0.1 * over_ratio ** 2
        return reward + penalty
    return reward
```

# 一、IBM Bamba 9B v2：Transformer × SSM 混合架构深度解析

## 1.1 背景：为什么需要混合架构？

Transformer和状态空间模型（SSM）各有致命短板：

| 架构 | 优势 | 致命缺陷 |
|------|------|---------|
| **Transformer** | 全局注意力，表达力极强 | O(n²) 序列复杂度，长上下文显存爆炸 |
| **Mamba/SSM** | O(n) 线性复杂度，显存恒定 | 选择性机制对信息压缩不可控，表达力受限 |

**Bamba的核心洞察**：Transformer和SSM不是替代关系，而是**互补关系**。让它们各自处理自己擅长的部分。

## 1.2 架构设计：两阶段信息流

Bamba 9B v2采用**块交织（Block-Interleaved）**设计：

```
输入序列
    ↓
[SSM块 × N层] → 局部特征提取 + 长程压缩
    ↓
[Transformer块 × M层] → 全局上下文整合 + 精确检索
    ↓
输出
```

**数学原理**：

**SSM块（前馈序列建模）**：
```math
\begin{aligned}
x_{t} &= \bar{A} \cdot x_{t-1} + \bar{B} \cdot u_t \\
y_t &= C \cdot x_t + D \cdot u_t
\end{aligned}
```

其中 $\bar{A} = e^{\Delta \cdot A}$，$\bar{B} = (\Delta \cdot A)^{-1}(e^{\Delta \cdot A} - I) \cdot \Delta \cdot B$，是通过零阶保持（ZOH）离散化的结果。核心：状态 $x_t$ 将历史信息压缩为**固定大小的向量**，与序列长度无关。

**Transformer块（选择性注意力）**：
```math
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V
```

Bamba的设计让SSM处理**不需要精确选择的信息**（如语义平滑、背景知识），Transformer处理**需要精确检索的信息**（如专有名词、数值计算）。

## 1.3 关键技术：选择性状态压缩

Bamba的SSM基于Mamba2架构，最关键的创新是**选择性状态压缩（Selective State Compression）**：

```python
class SelectiveStateCompressor(nn.Module):
    """
    Bamba的核心：自适应决定保留多少状态
    输入: 当前token x_t + 历史压缩状态 x_{t-1}
    输出: 更压缩的 x_t
    """
    def __init__(self, d_model, d_state=16):
        super().__init__()
        # 门控机制：决定丢弃多少旧信息
        self.input_gate = nn.Linear(d_model, d_model)
        self.forget_gate = nn.Linear(d_model, d_model)
        # 状态投影
        self.state_proj = nn.Linear(d_model, d_state)
        
    def forward(self, x_t, x_prev):
        # 门控：自适应决定新旧信息比例
        i = torch.sigmoid(self.input_gate(x_t))   # 写入强度
        f = torch.sigmoid(self.forget_gate(x_prev)) # 保留旧状态强度
        
        # 对角状态空间：简化S4的1000行代码到10行
        x_new = f * x_prev + i * self.state_proj(x_t)
        
        # 过滤无关信息（通过门控）
        relevant = torch.sigmoid(self.input_gate(x_t))
        return relevant * x_new
```

**与Mamba1的区别**：
- Mamba1：线性时不变（参数与输入无关）→ 压缩策略固定
- Bamba：线性时变（参数由输入决定）→ 压缩策略自适应
- **结果**：Bamba可以"记住"重要信息，"忘记"噪音

# 二、State Rank Stratification：线性注意力的隐藏动态

## 2.1 一句话概括

线性注意力模型在推理过程中，每个注意力头的**状态矩阵有效秩（Effective Rank）**呈现稳定的"两极分化"——有的头始终低秩（近乎秩0），有的头快速增秩并饱和到上界。这种分化是**模型的结构性内在属性**，与输入内容无关。

## 2.2 数学框架：状态秩的定义

对于线性注意力模型，给定输入序列，状态矩阵 $S \in \mathbb{R}^{d \times d}$ 的有效秩定义为：

```math
\text{rank}_{\text{eff}}(S) = \exp\left(-\sum_i \lambda_i \log \lambda_i\right)
```

其中 $\lambda_i$ 是归一化后的奇异值谱（$\sum_i \lambda_i = 1$）。

**直观理解**：
- $\text{rank}_{\text{eff}} \approx d$：状态矩阵满秩，包含大量独立维度 → 高表达力
- $\text{rank}_{\text{eff}} \approx 0$：状态矩阵压缩到少数几个维度 → 高度抽象

## 2.3 状态秩分层现象（State Rank Stratification）

研究者对多个主流线性注意力模型（RWKV、Mamba、RetNet等）进行了追踪实验，发现了惊人的规律：

```
推理时间步 →
低秩头:  r_eff ≈ 0 ─────────────────────────────  r_eff ≈ 0
          (几乎不变，始终保持低秩)
          
高秩头:  r_eff ≈ 0 → 快速增长 → 收敛到 r_eff ≈ d  
          (在推理初期快速增秩，之后稳定)
```

**关键发现**：

| 维度 | 低秩头 (Low-rank Heads) | 高秩头 (High-rank Heads) |
|------|----------------------|------------------------|
| 有效秩范围 | 0 ~ 1 | d（接近满秩） |
| 功能 | **推理能力核心** | 大量冗余 |
| 动态稳定性 | 极其稳定（不受输入影响） | 中等稳定 |
| 预训练后固定？ | ✅ 是（结构性属性） | ✅ 是（但可微调改变） |
| 剪枝敏感性 | **极敏感（剪枝后性能暴跌）** | 不敏感（可大幅剪枝） |

**这意味着**：线性注意力模型中，推理能力主要依赖少数"低秩但关键"的注意力头。

## 2.4 Joint Rank-Norm Pruning（联合秩范数剪枝）

基于State Rank Stratification，研究者提出了**零样本剪枝策略**：

```python
def joint_rank_norm_pruning(attention_heads, prune_ratio=0.389):
    """
    零样本剪枝线性注意力头
    核心思想：只剪枝高秩（冗余）头，保留所有低秩（关键）头
    
    prune_ratio=0.389 → KV-cache降低38.9%，性能几乎不变
    """
    results = []
    for head in attention_heads:
        # 计算该头的状态秩（推理期间的平均有效秩）
        state_rank = compute_effective_rank(head.state_matrix)
        # 计算该头的Frobenius范数
        f_norm = compute_frobenius_norm(head.weight_matrix)
        # 联合指标：越高越可能是冗余高秩头
        joint_score = state_rank * f_norm
        results.append((head, state_rank, f_norm, joint_score))
    
    # 按联合分数排序，剪掉最高的38.9%
    results.sort(key=lambda x: x[3], reverse=True)
    num_keep = int(len(results) * (1 - prune_ratio))
    
    kept_heads = [r[0] for r in results[:num_keep]]
    return kept_heads
```

**为什么叫"联合"（Joint）？**

单独的秩或范数都不足以判断冗余性：
- 仅用**秩**：高秩头未必冗余（可能需要满秩状态来处理复杂推理）
- 仅用**范数**：范数大的头未必冗余（可能是关键信息通道）

**联合分数** = 秩 × 范数，可以同时捕捉：
- 高秩（信息冗余）→ 高分
- 大范数（信息密度高）→ 高分
→ 分数最高的头 = 既冗余又大 = 最该剪枝

## 2.5 对推荐系统工程师的意义

**State Rank Stratification**对LLM推理优化有直接应用价值：

```
传统做法：均匀量化/压缩所有注意力头
    ↓（平均降低质量）
    
Bamba做法（受此研究启发）：
    - 识别低秩头（推理核心）→ 高精度保留
    - 识别高秩头（冗余）→ 激进压缩
    ↓（有针对性的压缩，保留核心推理能力）
```

对于推荐系统的**用户兴趣序列压缩**场景，这意味着：
- 用户的核心兴趣特征（类似"低秩头"）需要高精度表示
- 用户的噪声行为（类似"高秩头"）可以大幅压缩
- KV缓存压缩38.9% = 同样显存可以处理更长用户历史

# 三、Sparse State Expansion (SSE)：ICLR 2026稀疏状态扩展

## 3.1 核心问题：线性注意力的"容量墙"

标准线性注意力的状态容量与参数规模线性绑定：
```math
S \in \mathbb{R}^{d \times d} \quad \text{（固定d，受参数量限制）}
```

这带来了一个矛盾：
- **想提升推理能力** → 需要更大的状态容量 → 需要更多参数
- **想保持高效推理** → 状态越小越好 → 参数受限

**SSE的核心解法**：将状态空间**分区扩展**，在不增加参数的情况下提升状态容量。

## 3.2 数学原理：Row-Sparse Update

标准线性注意力的状态更新：
```math
s_t = \sum_{i=1}^{t} (K_i^T v_i) \quad \text{（所有历史token等权聚合）}
```

SSE引入**行稀疏选择（Row-Sparse Selection）**：
```math
\begin{aligned}
s_t &= \sum_{i=1}^{t} \text{diag}(\alpha_i) \cdot (K_i^T v_i) \\
\alpha_i &= \text{TopK}(\text{softmax}(W_s \cdot x_i), k) \quad \text{（选择性写入）}
\end{aligned}
```

其中 $\alpha_i \in \mathbb{R}^{d}$ 是稀疏选择向量（只有k个非零元素）。

**直观理解**：SSE将状态矩阵 $S$ 按**行分区**（P个分区），每个分区可以独立决定"接收"哪些新信息：

```
状态矩阵 S = [分区1 | 分区2 | ... | 分区P]
              ↑         ↑
           专门负责   专门负责
           语法信息   语义信息
```

## 3.3 核心创新：Sparse State Expansion（状态扩展）

**不增加参数量，如何增加状态容量？**

SSE的核心公式：
```math
S_{\text{expanded}} = \text{Concat}(S_1, S_2, ..., S_P) \in \mathbb{R}^{P \times d \times d}
```

通过将单个状态矩阵扩展为**P个独立分区**，在不增加单分区维度的情况下，总状态容量变为 **P × d × d**。

```python
class SparseStateExpansion(nn.Module):
    """
    SSE: 状态分区扩展
    不增加参数，只增加状态容量
    """
    def __init__(self, d_model, d_state, num_partitions=4):
        super().__init__()
        self.num_partitions = num_partitions
        # 每个分区有自己的SSM（但参数共享，只改变状态维度）
        self.ssm_partition = SSM(d_model, d_state)
        # 路由网络：将token路由到相关分区
        self.router = nn.Linear(d_model, num_partitions)
        
    def forward(self, x, prev_states):
        # 路由决策
        routing_weights = F.softmax(self.router(x), dim=-1)  # (batch, num_partitions)
        
        # 每个分区独立更新
        new_states = []
        for p in range(self.num_partitions):
            # 只将相关权重分配给该分区
            x_partitioned = routing_weights[:, p:p+1] * x
            state_p = self.ssm_partition(x_partitioned, prev_states[p])
            new_states.append(state_p)
        
        # 返回分桶状态（状态容量扩展了P倍）
        return torch.stack(new_states, dim=1)  # (batch, P, d_state)
```

# 四、后训练2026：完整技术路线图（深度版）

## 4.1 三阶段范式的数学基础

2026年后训练的标准三阶段框架：

```
Stage 1: SFT（监督微调）
  ↓
Stage 2: Preference Optimization（偏好优化）
  ↓
Stage 3: Reinforcement Learning（强化学习）
```

**为什么需要三个阶段？**

每个阶段解决不同问题，数学上互为补充：

| 阶段 | 优化目标 | 数学形式 | 解决的问题 |
|------|---------|---------|-----------|
| **SFT** | 条件对数似然 | $\max_\theta \sum_t \log p_\theta(y_t\|x, y_{<t})$ | 格式+指令跟随 |
| **DPO/ORPO** | 偏好差异最大化 | $\mathcal{L}_{\text{DPO}} = -\log\sigma(\log\pi(y^+)-\log\pi(y^-))$ | 人类价值观对齐 |
| **GRPO/DAPO** | 优势函数期望最大化 | $\mathcal{L}_{\text{RL}} = -\mathbb{E}[A \cdot \log\pi_\theta]$ | 超越训练数据上限 |

**关键数学洞察**：SFT教会模型"怎么说"，DPO教会模型"说什么是对的"，GRPO/DAPO让模型**自己发现**人类从未教过的解题方法。

## 4.2 DAPO的Token-Level Loss：长推理链的关键突破

DAPO最重要的技术创新之一——**Token-Level Loss**，彻底解决了长CoT推理链的梯度消失问题：

**传统Sequence-Level Loss的问题**：
```python
# 标准RL（GRPO等）对整个回答给一个reward
reward = evaluate_answer(entire_response)  # 标量

# 策略梯度：所有token共享同一个优势量
for each_token_t:
    gradient_t ∝ advantage * log_prob(token_t)
    
# 问题：回答有1000个token，如果最终答案错了
# 则前999个token都受到同等错误的惩罚（梯度消失 + 错误传播）
```

**DAPO Token-Level Loss的核心改进**：
```python
def token_level_reward(reward_signal, response_tokens, max_length=8192):
    """
    DAPO：为每个token分配独立 reward signal
    基于Verifiable Reward（可验证奖励）+ 折扣因子
    """
    token_rewards = []
    gamma = 0.99  # 折扣因子
    
    # 从最后一个token开始反推
    R = reward_signal
    for t in reversed(range(len(response_tokens))):
        # 早期token的reward = 后期reward × 折扣
        R = R * gamma
        token_rewards.insert(0, R)
    
    return token_rewards  # 每个token有独立reward

def token_level_policy_gradient(log_probs, token_rewards, baseline):
    """
    每个token有独立优势量，不再共享全局reward
    """
    advantages = [r - baseline for r in token_rewards]
    
    total_loss = 0
    for t, (log_p, adv) in enumerate(zip(log_probs, advantages)):
        # Token-level策略梯度
        token_loss = -log_p * adv
        # 权重 = 该token的相对重要性（基于位置）
        weight = 1.0 / (1 + abs(t - len(log_probs) / 2))
        total_loss += weight * token_loss
    
    return total_loss / len(log_probs)
```

**为什么这比Sequence-Level更好？**

```
长数学证明（1000 tokens）:
传统RL: 
  token[0:999] ← 每个token受到 reward=0 的均匀惩罚
  → 前999步梯度几乎为0，无法学习局部推理技巧
  
DAPO Token-Level:
  token[0:999] ← 每个token根据其"贡献度"分配reward
  → 早期推理步骤可以独立学到"如何引入辅助引理"
  → 晚期推理步骤独立学到"如何正确推导结论"
```

## 4.3 ORPO：一体化训练的数学之美

**ORPO（Odds Ratio Preference Optimization）**的核心洞察：DPO需要两个模型（策略模型 + 参考模型），ORPO证明这可以**合并为一个目标函数**。

**奥德比值（Odds Ratio）的定义**：
```math
\text{Odds}(p) = \frac{p}{1-p} \quad \text{即"胜率比"}
```

ORPO将SFT损失和偏好损失合并为一个**单一的Odds Ratio损失**：

```python
import torch
import torch.nn.functional as F

def orpo_loss(log_probs_chosen, log_probs_rejected, lambda_odds=0.5):
    """
    ORPO一体化损失函数
    
    log_probs_chosen: 被选中回答的token对数概率 (batch,)
    log_probs_rejected: 被拒绝回答的token对数概率 (batch,)
    """
    # Part 1: SFT损失（标准语言建模）
    # 最大化被选中回答的概率
    loss_sft = -log_probs_chosen.mean()
    
    # Part 2: 奥德比值损失（偏好对齐）
    # 定义胜率：p(y|x) = exp(sum(log_probs))
    odds_chosen = torch.exp(log_probs_chosen)
    odds_rejected = torch.exp(log_probs_rejected)
    
    # 奥德比值 = 选中/拒绝的胜率比
    # odds_ratio > 1 → 选中比拒绝更可能
    odds_ratio = odds_chosen / (odds_rejected + 1e-8)
    
    # 损失 = -log(odds_ratio) → odds_ratio越大越好
    loss_odds = -torch.log(odds_ratio / (1 + odds_ratio))
    
    # 一体化目标
    return loss_sft + lambda_odds * loss_odds
```

**ORPO vs DPO vs PPO**：

| 维度 | ORPO | DPO | PPO |
|------|------|-----|-----|
| 训练阶段 | **单阶段** | 两阶段（SFT+偏好） | 三阶段（SFT+RM+RL） |
| 参考模型 | ❌ 不需要 | ✅ 需要 | ✅ 需要 |
| 显存占用 | **最低（1x）** | 2x | 4x |
| 对齐质量 | 优秀 | 优秀 | 最优（但复杂） |
| 实现复杂度 | **最低** | 中等 | 最高 |

**实践建议**：对于<10B的小模型，优先用ORPO；对于>10B的模型，用GRPO+DAPO处理推理任务，用ORPO处理通用对齐。

## 4.4 RISE：自验证强化学习

**RISE（Reinforced Self-Verification）** 是2026年Agentic RL的核心技术之一，解决了"验证"和"推理"分离训练的问题：

```python
class RISETrainer:
    """
    RISE: 在单一RL过程中同时训练问题解决和自验证能力
    
    核心思想：
    - 问题解决（Solver）：生成解题步骤
    - 自验证（Verifier）：检查解题步骤是否正确
    - 两者使用相同的Verifiable Reward信号
    """
    def __init__(self, model, verifier_model=None):
        self.model = model
        # 验证器可以是单独的模型，也可以与求解器共享（推荐）
        self.verifier = verifier_model or model
    
    def risi_reward(self, problem, solution):
        """
        RISE Reward = Solver Reward + Verifier Reward
        """
        # Solver Reward：答案是否正确
        solver_reward = verify_answer(problem, solution)
        
        # Verifier Reward：验证器是否正确判断了该解答
        # （对标准答案：验证器应该判断为正确）
        # （对错误答案：验证器应该判断为错误）
        verification_signal = self.verifier.verify(problem, solution)
        # 验证正确性奖励（需要ground truth）
        verifier_reward = (verification_signal == ground_truth(problem, solution))
        
        # 联合奖励
        return solver_reward + 0.5 * verifier_reward
    
    def rl_update(self, batch):
        # 用RISE Reward进行GRPO更新
        advantages = self.compute_advantages(batch.rewards)
        return self.grpo_update(batch.log_probs, advantages)
```

            compressed_state

## 5.2 State Rank动态 → 推荐系统序列压缩

如果低秩头对推理至关重要（压缩用户核心兴趣），高秩头是冗余（噪声行为），那么推荐系统可以：

```
用户行为序列建模:
  识别"核心兴趣头"（低秩）→ 保留高精度表示 → 推荐特征
  识别"噪声行为头"（高秩）→ 激进压缩 → 降低存储/计算
```

**实施路径**：
1. 在训练好的推荐模型上，分析每个注意力头的状态秩
2. 识别核心兴趣头（低秩）→ FP16保留
3. 识别冗余头（高秩）→ INT4量化
4. 整体KV缓存降低38.9%，推荐质量基本不变

# LLM量化技术详解

## 一句话概括
量化是通过将高精度浮点数映射到低精度整数来压缩大模型体积、降低推理显存占用的核心技术，是实现大模型在消费级GPU上运行的关键技术。

## 背景与动机

### 解决的问题
- **模型体积过大**：7B模型FP16需要14GB显存，推理困难
- **显存瓶颈**：KV缓存、激活值占用大量显存
- **部署成本高**：企业级GPU集群成本高昂

### 量化必要性
| 精度 | 7B模型 | 70B模型 |
|------|--------|---------|
| FP32 | 28GB | 280GB |
| FP16/BF16 | 14GB | 140GB |
| INT8 | 7GB | 70GB |
| INT4 | 3.5GB | 35GB |

---

## 量化基础

### 量化原理

**基本公式：**
```math
x_q = \text{clip}\left(\text{round}\left(\frac{x}{s} + z\right), 0, 2^b-1\right)
```

其中：
- $x$：原始浮点数
- $x_q$：量化后的整数
- $s$：缩放因子（scale）
- $z$：零点（zero point）
- $b$：量化位数（4/8/16）

### 量化类型

#### 1. 训练后量化（PTQ）
- 训练完成后直接量化
- 无需重新训练，速度快
- 代表：GPTQ、AWQ

#### 2. 量化感知训练（QAT）
- 训练时模拟量化效果
- 精度更高，但训练成本大
- 代表：QLoRA

#### 3. 动态量化
- 推理时实时量化
- 精度损失小
- 代表：LLM.int8()

## 核心技术详解

### 1. GPTQ（2023）

**核心思想：**
- 按组（group）独立量化权重
- 使用Hessian信息优化量化误差

**量化公式：**
```math
W_q = \text{argmin}_{W_q} \|W - W_q\|_2^2
```

**特点：**
- 量化后需要额外反量化操作
- 支持INT4/INT3/INT2
- 量化速度较慢，但精度高

**代码实现：**
```python
from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

# GPTQ量化（使用AutoGPTQ）
model = AutoModelForCausalLM.from_pretrained(
    "model_name",
    torch_dtype=torch.float16,
    device_map="auto"
)

# 量化配置
quantization_config = GPTQConfig(
    bits=4,
    group_size=128,
    desc_act=False,
)

# 执行量化
quantized_model = quantize_model(model, quantization_config)
```

### 2. AWQ（激活感知权重量化）

**核心假设：**
- 不是所有权重都同等重要
- 仅保护1%的显著权重即可大幅减少量化误差

**数学原理：**
```math
\text{minimize } \|W \cdot X - W_q \cdot X\|^2
\text{subject to } W_q = s \cdot \text{clip}(W/s, -127, 127)
```

**关键创新：**
- 基于激活分布保护重要权重
- 不需要反向传播
- 量化后模型可直接推理

**实现：**
```python
from awq import AutoAWQ

# AWQ量化
model = AutoAWQ.from_pretrained("model_name")
quant_config = {"w_bit": 4, "group_size": 128}

model.quantize(model, quant_config, calib_data="...")
model.save_quantized("./quantized_model")
```

### 3. NF4（Normal Float 4）

**设计原理：**
- 针对正态分布权重优化
- 使用非均匀量化间隔

**量化表：**
```
NF4量化间隔（非均匀）:
[-σ, -3.5σ, -2.5σ, -1.5σ, -0.5σ, 0.5σ, 1.5σ, 2.5σ, 3.5σ, σ]
```

**特点：**
- 比均匀量化精度更高
- 专为LLM权重设计
- bitsandbytes库原生支持

### 4. QLoRA（量化+LoRA）

**核心思想：**
- 量化主模型到4-bit
- LoRA适配器以BF16/F16训练

**架构：**
```
主模型：FP16/INT4（冻结）
   ↓
LoRA：BF16（可训练）
   ↓
输出合并
```

**优势：**
- 7B模型单卡可微调
- 70B模型在多卡消费级GPU上可训练
- 量化与微调结合的典范

**实现：**
```python
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model

# NF4量化配置
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_use_double_quant=True
)

# 加载量化模型
model = AutoModelForCausalLM.from_pretrained(
    "model_name",
    quantization_config=bnb_config,
    device_map="auto"
)

# 添加LoRA
lora_config = LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj", "v_proj"])
model = get_peft_model(model, lora_config)
```

## 十二、ParoQuant：成对旋转变量化的INT4推理新范式（ICLR 2026）

**（补充章节 | 更新日期：2026-03-23）**

### 一句话概括
ParoQuant是ICLR 2026录用论文提出的INT4后训练量化方法，通过**学习两两配对的旋转变换**抑制权重异常值，在保持接近AWQ推理速度的同时，精度损失大幅缩小。

### 背景与动机

#### 权重异常值：INT4量化的最大障碍

LLM的权重矩阵存在少数**极端异常值（outlier）**——大多数权重分布在[-1, 1]区间，少数权重可达10-100。这些异常值主导了量化误差：

$$x_q = \text{round}\left(\frac{x}{s}\right), \quad s = \frac{\max(|x|)}{2^{b-1}-1}$$

异常值决定了缩放因子 $s$，导致普通权重量化时被"压"到极少的离散值上，精度崩溃。

#### 现有方法的局限

| 方法 | 策略 | 局限 |
|------|------|------|
| QuaRot | 随机旋转 | 旋转矩阵随机选取，效果不稳定（不同随机种子差距高达13个点） |
| SmoothQuant | 逐通道缩放 | 仅处理激活异常值，对权重异常值无效 |
| AWQ | activation-aware | 依赖校准集，无法充分处理所有异常值 |
| SpinQuant | 可学习旋转 | 但优化空间大，收敛困难 |

### 数学原理

#### 1. 旋转变换的本质

对权重矩阵 $W$ 施加正交旋转变换 $R$：

$$W' = R^T \cdot W \cdot R$$

旋转后的权重分布更加均匀，异常值被"分散"到多个方向，从而降低量化误差。

**旋转不变性：** 对于任意正交矩阵 $R$，有 $\|Wx\|_2 = \|R^T Wx\|_2$，因此旋转不改变模型的理论表达能力。

#### 2. 成对旋转变换（Pairwise Rotation）

ParoQuant的核心创新是**限制旋转矩阵为成对（pairwise）的Householder反射的组合**：

$$R = \prod_{k=1}^{K} H_{i_k, j_k}(\theta_k)$$

其中每个 $H_{i,j}(\theta)$ 是**维度$(i,j)$上的2D旋转矩阵**：

$$H_{i,j}(\theta) = 
\begin{pmatrix}
\cos\theta & -\sin\theta \\
\sin\theta & \cos\theta
\end{pmatrix}
\text{（在第$i,j$维度）}$$

**为什么用成对旋转而不是一般正交矩阵？**

| 维度 | 一般正交矩阵 | 成对旋转矩阵 |
|------|------------|------------|
| 参数量 | $O(d^2)$ | $O(K)$，$K \ll d^2$ |
| 可学习性 | 高（但易过拟合） | 低（稳定收敛） |
| 计算开销 | 高（需要Cayley优化） | 极低（直接求导） |

ParoQuant发现：**只需几十个精心选择的成对旋转，就能达到甚至超越全正交矩阵的效果。**

#### 3. 优化目标

$$\min_{\theta} \mathcal{L}(\theta) = \mathbb{E}_{x \sim \mathcal{D}} \left[ \|W'(\theta) \cdot x - \hat{W} \cdot x\|^2 \right] + \lambda \cdot R_{smooth}(\theta)$$

其中 $W'(\theta)$ 是旋转变换后的权重，$\hat{W}$ 是量化后的权重。目标是同时优化旋转角度 $\theta$ 和量化参数，使得端到端重建误差最小。

#### 4. 端到端量化流程

```
权重矩阵 W
    ↓
[学习旋转参数 θ]
    ↓
W' = R(θ)ᵀ · W · R(θ)
    ↓
[INT4量化 W'ᵠ]
    ↓
[存储: 旋转参数 + INT4权重]
    ↓
推理时: 反量化 → 逆旋转变换 → 计算
```

**存储开销：** 旋转参数 $K \times 1$个标量（$K \approx 32-64$），远小于额外存储开销可忽略不计。

### 代码实现

```python
import torch
import torch.nn as nn

class PairwiseRotation(nn.Module):
    """
    成对旋转变换模块
    核心思想：用K个2D旋转的组合代替d×d正交矩阵
    """
    def __init__(self, dim: int, n_rotations: int = 32):
        super().__init__()
        self.dim = dim
        self.n_rotations = n_rotations
        
        # 每对旋转：指定哪两个维度 + 旋转角度
        # 初始化选择对角线上的维度对（稳定性更好）
        self.indices_i = nn.Parameter(
            torch.randint(0, dim, (n_rotations,)), 
            requires_grad=False
        )
        self.indices_j = nn.Parameter(
            torch.randint(0, dim, (n_rotations,)),
            requires_grad=False
        )
        # 可学习的旋转角度
        self.theta = nn.Parameter(torch.zeros(n_rotations))
    
    def build_rotation_matrix(self) -> torch.Tensor:
        """构建K个2D旋转组合的d×d正交矩阵"""
        R = torch.eye(self.dim, device=self.theta.device, dtype=self.theta.dtype)
        
        for k in range(self.n_rotations):
            i, j = self.indices_i[k].item(), self.indices_j[k].item()
            cos_t = torch.cos(self.theta[k])
            sin_t = torch.sin(self.theta[k])
            
            # 对第i,j行/列应用2D旋转（通过Givens变换）
            R_i, R_j = R[:, i].clone(), R[:, j].clone()
            R[:, i] = cos_t * R_i - sin_t * R_j
            R[:, j] = sin_t * R_i + cos_t * R_j
        
        return R
    
    def forward(self, weight: torch.Tensor):
        """
        weight: [..., d, d] 权重矩阵
        返回: 旋转后的权重
        """
        R = self.build_rotation_matrix()
        return R.t() @ weight @ R


def quantize_with_paroquant(weight: torch.Tensor, rotation_module: PairwiseRotation):
    """
    ParoQuant端到端量化流程
    """
    # Step 1: 旋转
    rotated = rotation_module(weight)
    
    # Step 2: INT4量化（per-channel或per-group）
    scale = rotated.abs().max(dim=-1, keepdim=True).values / 7.0  # INT4范围[-7,7]
    quantized = torch.round(rotated / scale).clamp(-8, 7).to(torch.int8)
    
    return quantized, scale, rotation_module.state_dict()


# 推理时：逆过程
def dequantize_with_paroquant(quantized, scale, rotation_params, rotation_module):
    rotated = quantized.float() * scale
    rotation_module.load_state_dict(rotation_params)
    R_inv = rotation_module.build_rotation_matrix()
    return R_inv @ rotated @ R_inv.t()
```

### 技术演进脉络

```
2023 QuaRot: 随机旋转（效果不稳定，差13个点）
     ↓
2024 SpinQuant: 可学习旋转（Cayley优化，收敛慢）
     ↓
2025 AWQ: activation-aware（无需旋转，但仍有局限）
     ↓
2026 ParoQuant: 成对旋转变换（稳定+高效+高精度）
```

**ParoQuant的核心贡献：** 证明了"少量精心选择的2D旋转 > 大量随机旋转 ≈ 耗时的全正交优化"，为INT4量化提供了新的工程实践路径。

### 常见误区

**❌ 误区1：ParoQuant和QuaRot一样只是旋转**
核心区别在于：QuaRot的旋转是随机/启发式选取，而ParoQuant的旋转是端到端学习的，且通过成对约束大幅降低了优化难度。

**❌ 误区2：ParoQuant量化后模型不可用**
目前已有大量开源的预量化checkpoint（HuggingFace直接可下载），且支持vLLM直接部署。

**❌ 误区3：旋转参数会占用大量显存**
K=32时仅需存储64个浮点数（256字节），完全可以忽略。

2. **ParoQuant能否与KV缓存量化结合？** 目前只验证了weight-only，weight-activation-KV联合量化效果未知。
3. **能否将成对旋转思想迁移到其他模型压缩任务（如剪枝）？**

## Google TurboQuant（2026年3月）

> **核心定位**：KV Cache极限量化，专治"长上下文显存杀手"，无需训练/微调，零精度损失
> **发布机构**：Google Research，ICLR 2026 Oral
> **发布日期**：2026年3月25日

### 解决的问题

大语言模型推理时，KV Cache随序列长度线性增长，是长上下文推理的显存瓶颈：

```
KV Cache大小 = 层数 × 2(K和V) × 序列长度 × 头数 × 每头维度 × 精度字节数

以 Llama-3.1-70B（FP16）128K上下文为例：
= 80层 × 2 × 128,000 Token × 64头 × 128维 × 2字节 ≈ 320 GB VRAM
→ 单张H100（80GB）无法完整缓存，必须分块/卸载，引入巨大延迟
```

这是百万Token上下文商业化的**最后一道算力障碍**。

### 核心技术：PolarQuant + QJL双核

#### 第一核：PolarQuant（极坐标量化）

**核心洞察**：未旋转的K/V向量各维度方差差异巨大（某些维度方差是其他维度的100倍以上），导致传统量化误差集中在少数维度。

**解决方案：随机正交旋转均匀化方差**

数学原理：
```math
\text{设原始Key向量: } k \in \mathbb{R}^d \\
\text{随机正交矩阵: } R \in \mathbb{R}^{d \times d}，满足 R^T R = I \\
\text{旋转后: } k' = Rk

\text{关键性质：}
||k'||_2 = ||k||_2 \quad \text{（L2范数不变）} \\
k'^T k' = k^T R^T R k = k^T k \quad \text{（内积不变）} \\
\text{注意力分数 } a = \text{softmax}(Q \cdot K^T) \text{ 的相对关系通过旋转被保持}
```

**直观理解**：极坐标量化的类比——将一堆凌乱的行李（直角坐标系下的数据）通过巧妙旋转角度，严丝合缝地塞进最小的行李箱，保留原始向量最核心的特征。

**实现代码**：
```python
def polar_quantize(k, bits=3):
    # Step 1: 随机正交旋转，均匀化方差分布
    # 正交矩阵R可从随机种子再生，无需存储完整矩阵
    R = generate_random_orthogonal_matrix(d)
    k_rotated = k @ R  # 旋转后各维度方差趋于均匀
    
    # Step 2: 均匀量化（传统方法在此步误差爆炸）
    scale = k_rotated.abs().max() / (2**(bits-1) - 1)
    k_quantized = torch.round(k_rotated / scale)
    
    return k_quantized, R, scale
```

**为什么旋转能减少量化误差？**
- 未旋转向量：少数高方差维度主导量化误差（100:1的方差比）
- 旋转后：方差被抹平到所有维度，每个维度量化误差均匀分布
- 效果：3bit精度下实现接近零精度损失（vs传统方法3bit有明显损失）

#### 第二核：QJL（量化Johnson-Lindenstrauss）

**JL引理**：将高维向量随机投影到低维空间时，向量间的距离关系可以近似保持。

```math
\forall \epsilon \in (0, \frac{1}{2}), \exists \text{映射 } f: \mathbb{R}^d \rightarrow \mathbb{R}^k \\
使得: (1-\epsilon)||x_i - x_j||^2 \leq ||f(x_i) - f(x_j)||^2 \leq (1+\epsilon)||x_i - x_j||^2
```

**QJL在TurboQuant中的应用**：处理Value向量残差压缩
```python
def qjl_compress(v, projection_matrix):
    # Step 1: JL随机投影（降维）
    v_projected = projection_matrix @ v  # R^{d} → R^{k}，k << d
    
    # Step 2: 符号位提取——极端压缩（仅需1bit/维度）
    v_signs = torch.sign(v_projected)
    
    return v_signs  # 内存开销 ≈ 0

# 关键：混合精度注意力估计器
# 从~0额外开销的符号位，恢复精确注意力输出（利用JL距离保持性质）
```

**PolarQuant + QJL协同工作**：
```
输入Token → 计算K/V向量（FP16）
     ↓
Key向量 → [PolarQuant] → 3bit压缩Key
Value向量 → [QJL] → 1bit压缩Value
     ↓
注意力计算（混合精度估计器）→ 精确注意力分数（零精度损失）
```

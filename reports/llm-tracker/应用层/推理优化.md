# 推理优化

## 核心原理

推理优化是指在模型部署推理阶段，通过各种技术手段降低延迟、减少显存占用、提高吞吐量。主要技术包括：

- **量化（Quantization）**：将FP32权重压缩为INT8/INT4甚至更低精度
- **蒸馏（Distillation）**：用大模型知识训练小模型
- **投机解码（Speculative Decoding）**：用小模型预测，大模型验证
- **KV缓存优化**：高效管理注意力键值缓存
- **算子融合**：减少内存访问和核函数启动开销

## 解决的痛点

- **推理成本高**：大模型推理需要大量算力
- **延迟高**：生成速度影响用户体验
- **显存爆炸**：长上下文KV缓存过大
- **部署困难**：难以在消费级设备运行

## 代表框架

- **vLLM**：PagedAttention技术，业界最流行的高效推理框架

## Prefill/Decode解耦体系（2024-2026核心方向）

LLM推理的两个阶段本质上是截然不同的工作负载：

| 维度 | Prefill阶段 | Decode阶段 |
|------|------------|-----------|
| **计算类型** | 矩阵-矩阵乘法 | 矩阵-向量乘法 |
| **瓶颈** | 计算密集（Compute-bound） | 内存带宽密集（Memory-bound） |
| **算术强度** | 高（Batch=1也高） | 低（比Prefill低2个数量级） |
| **延迟敏感** | TTFT（首字延迟） | TBT（字间延迟）/ TPOT |
| **GPU优化方向** | Tensor Core饱和 | 增大Batch摊薄内存访问 |

### 技术路线一：Chunked Prefill（SARATHI）

**核心思想**：将长Prefill切分为固定大小的chunk（默认512 tokens），分散到多个迭代周期，每个周期混合Decode token。

**Token预算分配公式**：
$$\text{总Token数} = \sum_i d_i \;(\text{Decode}) + p_j \;(\text{Prefill块}) \leq C$$

**关键参数（vLLM配置）**：
```python
llm = LLM(
    max_num_batched_tokens=2048,  # 控制每迭代Token预算
    enable_chunked_prefill=True,  # SARATHI分块调度
)
```

- 小值（512）→ 更好TBT，但吞吐略低
- 大值（4096+）→ 更高吞吐，但TBT可能增加

**Tile量化开销**：chunk_size应为128的倍数（GPU tile对齐），否则+32%延迟惩罚。

### 技术路线二：POD-Attention（ASPLOS 2025）

**核心思想**：设计首个同时支持Prefill和Decode的融合GPU核函数，在同一SM上并发执行两种注意力计算。

**CTA级资源动态分区**：
- Prefill密集batch → 更多SM分配给Prefill CTA
- Decode密集batch → 更多SM分配给Decode CTA
- 计算与内存访问相互掩盖（双缓冲+异步执行）

**性能提升**：注意力计算**最高59%，平均28%**；端到端吞吐**最高22%**。

### 技术路线三：DistServe（OSDI 2024）

**核心思想**：物理分离Prefill和Decode到不同GPU，每阶段使用专用并行策略。

**架构**：
```
GPU集群:
  Prefill-GPU组: 张量并行 → 计算密集优化
  Decode-GPU组:  大Batch   → 内存带宽优化
                ↑
         KV Cache高速网络传输
```

**性能**：满足90%延迟SLO的请求量提升**7.4倍**，SLO达标能力提升**12.6倍**。

### 技术路线四：Drift（arXiv 2025）

**核心思想**：SM级空间复用，同GPU内Prefill/Decode并行，保留原地KV Cache复用。

```
GPU:
  SM 0-63:   Prefill（计算密集优化）
  SM 64-127: Decode（内存带宽优化）
  KV Cache:  原地共享（无传输开销）
```

**性能**：平均吞吐提升**5.1倍**，最大**17.5倍**。

### 三种策略对比

| 维度 | DistServe（分离） | POD-Attention（融合） | Drift（复用） |
|------|------------------|---------------------|--------------|
| 部署形态 | 多GPU物理分离 | 单/多GPU核函数融合 | 单GPU空间复用 |
| KV Cache | 高速网络传输 | L2缓存共享 | 原地共享 |
| Prefill加速 | ★★★★★ | ★★★☆☆ | ★★★☆☆ |
| 部署复杂度 | 高 | 中 | 低 |

### 推荐系统类比

| LLM推理 | 推荐系统 | 技术启示 |
|---------|---------|---------|
| Prefill（计算密集） | 特征检索/Embedding（内存密集） | SM级资源隔离 |
| Decode（内存密集） | 模型打分（计算密集） | 增大Batch摊薄开销 |
| Chunked Prefill | 特征分批拉取+打分混合 | 减少特征阻塞 |
| DistServe | 特征服务与模型服务分离部署 | 服务独立扩缩容 |

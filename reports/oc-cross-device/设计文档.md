# OpenClaw 跨设备远程控制框架

> 版本：v1.0  
> 日期：2026-03-28  
> 定位：轻量级、安全、可扩展的 OpenClaw 远程控制终端

---

## 一、需求分析

### 1.1 用户场景

| 场景 | 描述 | 核心需求 |
|------|------|---------|
| **移动端触发** | 手机收到消息，想远程触发 OpenClaw 执行任务 | 快捷、随时随地 |
| **出差查阅** | 外出时想查看 OpenClaw 状态 / 获取报告 | 轻量推送 |
| **快捷指令** | 用 Siri/快捷指令一键执行常用任务 | 语音/自动化 |
| **Webhook 联动** | 其他系统触发 OpenClaw 执行任务 | API 标准化 |
| **多设备同步** | 在任何设备都能控制 OpenClaw | 统一入口 |

### 1.2 核心痛点

- **受限的交互方式**：目前只能通过 Web 界面与 OpenClaw 交互，不够灵活
- **场景割裂**：不同设备（手机/电脑/平板）无法统一控制
- **常用任务繁琐**：执行一个固定任务（如"生成今日简报"）需要打开网页 → 打开对话 → 输入 → 等待
- **被动等待**：无法在后台主动推送结果，需要主动去查看

### 1.3 产品定位

**轻量 · 安全 · 随时可达**

不是替代 Web 界面，而是作为 Web 界面的"快捷通道"——聚焦于常用操作的快速触发和关键信息的即时推送。

## 三、API 设计

### 3.1 RESTful 接口

| 方法 | 路径 | 描述 | 认证 |
|------|------|------|------|
| `GET` | `/api/v1/health` | 健康检查 | 无 |
| `GET` | `/api/v1/status` | 系统状态 | API Key |
| `POST` | `/api/v1/tasks` | 创建任务 | API Key |
| `GET` | `/api/v1/tasks/{id}` | 查询任务 | API Key |
| `DELETE` | `/api/v1/tasks/{id}` | 取消任务 | Admin Key |
| `GET` | `/api/v1/templates` | 获取任务模板 | API Key |
| `POST` | `/api/v1/trigger/{name}` | 触发命名任务 | API Key |
| `POST` | `/api/v1/webhook` | Webhook 入口 | HMAC 签名 |

### 3.2 请求/响应示例

**POST /api/v1/tasks**
```json
// Request
{
  "action": "spawn",
  "agent": "tech-analyst",
  "params": {"scope": "brief"},
  "notify": true,
  "notify_channel": "dingtalk"
}

// Response
{
  "id": "task_20260328_001",
  "name": "tech-analyst",
  "status": "queued",
  "created_at": "2026-03-28T12:30:00+08:00"
}
```

## 四、安全设计

### 4.1 认证机制

```
三级 API Key：
├── Read Key    → 只读权限（查询状态/任务）
├── Exec Key    → 执行权限（触发任务/发送消息）
└── Admin Key   → 管理权限（删除任务/修改配置）
```

### 4.2 安全策略

| 策略 | 说明 |
|------|------|
| **API Key 认证** | 所有敏感接口需携带 Key |
| **IP 白名单** | 仅允许受信任 IP 调用（可选） |
| **HMAC 签名** | Webhook 入口校验来源 |
| **操作审计** | 所有操作写入审计日志 |
| **速率限制** | 防止滥用（默认 60req/min） |
| **敏感操作二次确认** | 高危操作需额外确认 |

## 五、触发方式

### 5.1 钉钉触发

通过钉钉机器人 → Webhook URL → 触发 OpenClaw

```
用户发送：@机器人 执行 tech-analyst
   ↓
钉钉机器人 POST → clawctl /api/v1/webhook
   ↓
clawctl 解析消息 → 识别意图 → 触发任务
   ↓
OpenClaw 执行 → 结果推送回钉钉
```

### 5.2 快捷指令 / Siri 触发

```
快捷指令 App
   ↓
URL Scheme: clawctl://trigger?name=quick-report
   ↓ 或
HTTP POST → /api/v1/trigger/quick-report
   ↓
clawctl 执行 → 推送结果
```

### 5.3 命令行触发

```bash
# 触发任务
clawctl trigger tech-analyst --scope brief

# 发送消息
clawctl send --channel dingtalk --message "测试消息"

# 查看状态
clawctl status

# 交互式执行
clawctl exec --task "生成今日 AI 资讯简报"
```

## 七、部署方案

### 7.1 依赖

```
Python >= 3.9
Flask / FastAPI
requests
PyYAML
dingtalk-sdk  # 钉钉
```

### 7.2 启动方式

```bash
# 方式1：直接启动
python server.py

# 方式2：Docker
docker run -p 8080:8080 \
  -v ./config.yaml:/app/config.yaml \
  clawctl:latest

# 方式3：Systemd 服务
sudo systemctl enable clawctl
sudo systemctl start clawctl
```

### 7.3 与 OpenClaw 的连接

clawctl 通过 OpenClaw Gateway HTTP API 连接（默认 `http://localhost:18789`），
无需额外端口暴露，安全地局域网内使用。

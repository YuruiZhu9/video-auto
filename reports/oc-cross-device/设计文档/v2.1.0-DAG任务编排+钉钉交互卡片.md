## 一、Why：为什么要做 DAG 任务编排？

### 用户场景

**场景 A：晨间简报（最高频）**
```
用户早上 8:30 收到钉钉 → "生成今日简报"
→ 触发：抓取今日AI资讯 → 技术分析 → 生成简报 → 推送钉钉
```
三步串行，每步依赖上一步结果。

**场景 B：深度研究（周五/周日）**
```
用户周末有时间 → "深度研究一下推荐系统"
→ 触发：并行抓取 AI动态 + 推荐系统论文 + 商业洞察 → 综合分析 → 生成详细报告
```
前3步可并行，最后2步串行。

**场景 C：故障容错**
```
若抓取失败，后续分析和报告应自动跳过（而不是继续执行空结果）
```

### 现有方案的不足

| 痛点 | 说明 |
|------|------|
| 单任务无依赖 | 每个 agent 独立运行，无法串联 |
| 无并行优化 | 即使3个任务无关联，也要串行等待 |
| 失败传播缺失 | A失败，B仍执行，产生脏数据 |
| 状态不可见 | 用户无法知道 DAG 内每个节点的进度 |

### 解决方案

**TaskDAG** — 有向无环图任务编排器，解决以上所有痛点。

## 二、What：TaskDAG 是什么？

### 核心概念

```
DAG = 有向无环图（Directed Acyclic Graph）

节点（Node）= 一个可执行的子任务
边（Edge）  = 依赖关系（A → B 表示 B 依赖 A 完成）

示例：晨间简报 DAG
┌──────────┐     ┌──────────┐     ┌──────────┐
│  抓取    │ ──▶ │  分析    │ ──▶ │  简报    │
│ fetch    │     │ analyze  │     │ report   │
└──────────┘     └──────────┘     └──────────┘
   status:✅        status:🔄       status:⏳
```

### 节点生命周期

```
PENDING → READY → RUNNING → SUCCESS/FAILED/SKIPPED
                    ↓
                  （失败且可重试）→ READY（重试）
                  （失败且达上限）→ FAILED → 下游全部 SKIPPED
```

### 并行执行

```
DAG 有3个节点就绪（A、B、C 互不依赖）：

 ThreadPoolExecutor(max_workers=3)
 ┌────────┐  ┌────────┐  ┌────────┐
 │  A运行 │  │  B运行 │  │  C运行 │
 └────────┘  └────────┘  └────────┘
      ↓            ↓           ↓
    A完成      B完成        C完成
      ↓            ↓           ↓
 DAG感知完成，继续调度D（依赖A、B、C全部完成）
```

## 三、How：设计实现

### 类设计

```python
class TaskNode:
    id: str                          # 唯一标识
    name: str                        # 显示名
    task_template: str              # 模板ID
    params: Dict[str, Any]          # 执行参数
    deps: List[str]                 # 依赖节点ID
    status: NodeStatus               # 当前状态
    result: Any                     # 执行结果
    error: Optional[str]            # 错误信息
    max_retries: int                # 最大重试次数

class TaskDAG:
    dag_id: str
    name: str
    nodes: Dict[str, TaskNode]

    add_node()                       # 添加节点
    add_edge()                       # 添加依赖边
    validate() -> List[str]          # 环检测
    get_ready_nodes() -> List[Node]  # 拓扑分析
    execute(executor, max_parallel) # 并行执行
    cancel()                         # 取消
    get_execution_order() -> List[str]  # 拓扑排序

class DAGManager:
    create(name, template) -> TaskDAG
    get(dag_id) -> TaskDAG
    list_dags() -> List[dict]
    delete(dag_id)
```

### DAG 模板（用户可用）

| 模板 ID | 名称 | 节点 | 拓扑 |
|--------|------|------|------|
| `morning-brief` | 晨间简报 | fetch → analyze → report | 串行 |
| `deep-research` | 深度研究 | fetch_ai ‖ fetch_rec ‖ fetch_market → synthesize → report | 并行→串行 |
| `ai-news-daily` | 每日AI新闻 | quick_fetch → brief | 串行 |

> ‖ = 并行执行

### API 使用示例

```bash
# 1. 创建 DAG（晨间简报）
curl -X POST http://localhost:8080/api/v1/dag/ \
  -H "Authorization: Bearer ck_exec_x7y8z9" \
  -H "Content-Type: application/json" \
  -d '{"name": "今日简报", "template": "morning-brief"}'

# 2. 执行 DAG
curl -X POST http://localhost:8080/api/v1/dag/{dag_id}/execute \
  -H "Authorization: Bearer ck_exec_x7y8z9"

# 3. 查看状态
curl http://localhost:8080/api/v1/dag/{dag_id} \
  -H "Authorization: Bearer ck_exec_x7y8z9"
```

### 钉钉快捷命令

发送以下关键词到钉钉机器人即可触发：

```
📰 简报 / 日报 / 报告 / brief / report
   → 执行 morning-brief DAG（抓取→分析→简报）

🔬 技术 / tech / 论文 / arxiv
   → 执行 tech-analyst（推荐系统+大模型分析）

💡 商业 / 市场 / market / insight
   → 执行 market-insight（商业洞察）

🌐 全量 / 全扫 / full
   → 执行 full-scan（全量抓取）

🧠 深度 / deep
   → 执行 deep-research DAG（并行抓取→深度分析）

📊 状态 / status
   → 直接返回系统状态（不触发 agent）

❓ 帮助 / help
   → 返回所有可用命令
```

## 四、DingTalk 交互卡片设计

### 消息类型矩阵

| 场景 | 卡片类型 | 特点 |
|------|---------|------|
| 任务启动通知 | Markdown | 简洁、标题醒目 |
| 任务完成通知 | Markdown | 含耗时和摘要 |
| 任务失败告警 | Markdown | 红色标记，提示重试 |
| DAG 状态推送 | Markdown | 节点进度列表 |
| 系统状态查询 | Markdown | 含资源使用情况 |
| 快捷命令菜单 | ActionCard 多按钮 | 点击即可执行 |

1. 群设置 → 智能群助手 → 添加机器人
2. 选择「自定义」机器人
3. 复制 Webhook Token 和加签 Secret
4. 配置到 `config.yaml` 的 `webhook.dingtalk` 项

## 五、安全设计

| 层级 | 措施 |
|------|------|
| API 认证 | Bearer Token（三级权限：read/exec/admin） |
| IP 白名单 | 可配置允许访问的 IP 列表 |
| 速率限制 | 每分钟请求数上限（可按 key 配置） |
| Webhook 签名 | HMAC-SHA256 + 时间戳防重放 |
| 敏感操作 | exec/admin 权限分离 |
| 操作审计 | 所有请求记录日志（时间/IP/key/操作） |

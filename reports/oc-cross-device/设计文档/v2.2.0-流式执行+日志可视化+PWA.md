**版本**：2.2.0 | **日期**：2026-04-06 | **状态**：✅ 完成

## 一、Why：为什么需要流式执行？

### 用户场景

**场景 A：任务执行了，但用户在等 — 等得焦虑**
```
用户点击「执行简报」→ 看到的是空白或"执行中" → 等 3 分钟 → 不知道发生了什么 → 再点一次或以为卡死了
```
**场景 B：钉钉收到结果，但不知道中间过程**
```
用户收到钉钉推送「技术分析完成」→ 打开报告 → 发现结果不符合预期 → 无法追溯是哪里出了问题
```
**场景 C：手机上看 Web Admin，卡顿、不方便**
```
Web Admin 没有针对移动端优化 → 刷新慢 → 无法安装 → 用户宁愿不用
```

### 现有方案的不足

| 痛点 | 说明 |
|------|------|
| 执行过程不可见 | 任务在跑，用户只能等，不知道进度 |
| Agent 输出无记录 | OpenClaw 子 agent 输出到哪了？用户看不到 |
| Web Admin 无移动端 | 只能在电脑上用，手机体验差 |
| 无法中断任务 | 任务跑错了，没有取消机制（只有取消钉钉回调） |

### 解决方案

**v2.2.0 = 流 + 看 + 装**
- **流**：任务执行时，将子 agent 的 stdout/stderr 实时流式推送到 Web Admin（SSE）
- **看**：Web Admin 新增实时日志面板 + DAG 可视化执行状态
- **装**：PWA 支持，手机浏览器"添加到主屏幕"，原生 App 体验

## 二、What：流式执行架构

### 核心概念

```
用户点击「执行」 
       ↓
 TaskManager.execute() 
       ↓
 OpenClaw spawn_agent() 
       ↓
 StreamManager.start_stream(task_id)  ← 新增
       ↓
 SSE stream ──▶ Web Admin 实时日志面板
       ↓
 子 Agent 输出 → stream.push(chunk)
       ↓
 任务完成 → stream.end(result)
```

### StreamManager — 流管理器

```python
class StreamManager:
    """管理所有活动任务的流式输出"""
    
    def start_stream(self, task_id: str) -> str:
        """启动流，返回 stream_id"""
        ...
    
    def push(self, task_id: str, chunk: str, level: str = "info"):
        """推送一个输出片段到所有订阅者"""
        ...
    
    def push_markdown(self, task_id: str, content: str):
        """推送 Markdown 渲染片段"""
        ...
    
    def end(self, task_id: str, result: dict):
        """流结束"""
        ...
    
    def subscribe(self, task_id: str, client_sse):
        """客户端订阅某个任务的流"""
        ...
```

### SSE 事件类型（新增）

```
event: stream_start    data: {task_id, agent, started_at}
event: stream_chunk    data: {task_id, content, level, timestamp}
event: stream_markdown data: {task_id, content}   ← Markdown渲染
event: stream_progress data: {task_id, progress, message}
event: stream_complete data: {task_id, status, duration_ms, result_summary}
event: stream_error    data: {task_id, error}
```

## 三、Web Admin v3 — 实时日志 + DAG 可视化

### 新增页面功能

#### 3.1 实时日志面板
- 每个运行中的任务，右侧展开实时日志面板
- 支持 ANSI 颜色渲染（agent 输出带颜色）
- 支持折叠/展开、自动滚动、暂停
- 日志级别高亮：ERROR（红）/ WARN（黄）/ INFO（白）/ DEBUG（灰）

#### 3.2 DAG 执行可视化
- SVG 渲染 DAG 节点
- 执行中节点：脉冲动画（青色）
- 完成节点：绿色 ✓
- 失败节点：红色 ✗
- 跳过节点：灰色 ——
- 箭头动态流向（CSS 动画）

#### 3.3 任务历史增强
- 每条历史记录显示：耗时热力条（越绿越快）
- 失败任务标红 + 显示错误摘要
- 支持按时间范围 / 状态 / 执行者筛选

## 四、PWA 移动端支持

### manifest.json
```json
{
  "name": "ClawCtl 控制台",
  "short_name": "ClawCtl",
  "description": "OpenClaw 跨设备控制台",
  "start_url": "/admin/",
  "display": "standalone",
  "background_color": "#0f172a",
  "theme_color": "#0ea5e9",
  "icons": [...]
}
```

### Service Worker
- 缓存静态资源（HTML/CSS/JS/字体）
- 离线可用（显示上次数据）
- 推送通知（任务完成 / 系统告警）

### 移动端优化
- 底部 Tab 导航（任务 / 历史 / 状态 / 设置）
- 大触摸目标（min 44px）
- 禁用双击缩放
- 深色主题默认

## 五、API 扩展

```
# 流式执行
POST /api/v1/stream/execute      启动流式任务，返回 stream_id
GET  /api/v1/stream/{task_id}    SSE 流订阅

# DAG 可视化
GET  /api/v1/dag/{id}/live       SSE 流订阅 DAG 执行状态

# Web Admin 静态资源
GET  /admin/                     Web Admin v3（支持 PWA）
GET  /admin/manifest.json        PWA manifest
GET  /admin/sw.js               Service Worker
```

# OpenClaw 跨设备远程控制方案 — 安全设计

## 1. 安全设计原则

- **最小权限**：每个 API Key 只授予完成工作所需的最小权限
- **纵深防御**：多层安全机制，单一机制失效不导致全面沦陷
- **可审计**：所有操作留痕，出问题时可追溯
- **默认安全**：安全特性默认开启，需要手动降低风险则显式配置

---

## 2. 认证机制

### 2.1 API Key 设计

```
sk-{随机16字节Hex}-{级别标识}
示例：sk-a3f2b1c4d5e6f7g8h9i0j-EXECUTE
```

**分级设计**：

| 级别 | 标识 | 数值 | 场景 |
|------|------|------|------|
| 只读 | `READ_ONLY` | 10 | 查看状态、日志 |
| 执行 | `EXECUTE` | 20 | 执行任务、查看结果 |
| 管理 | `ADMIN` | 30 | 管理模板、配置、Key |

### 2.2 Key 管理规则

- Key 只生成一次，**不提供明文查询**（只显示前4位+后4位）
- 支持创建多个 Key，满足不同场景/设备
- 支持 Key 吊销（Revoke）
- Key 支持设置过期时间（可选）
- Key 存储：`bcrypt` 哈希存储，传输过程全程 HTTPS

## 3. 网络层安全

### 3.1 IP 白名单

```yaml
auth:
  ip_whitelist:
    - "127.0.0.1"          # 本地
    - "10.0.0.0/8"         # 公司内网
    # - "0.0.0.0/0"        # 不推荐，默认拒绝不明来源
```

**推荐配置**：仅允许钉钉/Telegram 服务器 IP 段（平台提供），或个人家庭/办公 IP。

### 3.2 反向代理（HTTPS）

生产环境**必须**通过 Nginx/Caddy 等反向代理终止 TLS：

```
用户设备 ──HTTPS──► Nginx (443) ──HTTP──► ClawRemote (8080)
```

关键 Nginx 配置：
```nginx
ssl_certificate     /path/to/cert.pem;
ssl_certificate_key /path/to/key.pem;
ssl_protocols       TLSv1.2 TLSv1.3;
proxy_set_header    X-Real-IP $remote_addr;
proxy_set_header    X-Forwarded-Proto $scheme;
```

## 4. 请求层安全

### 4.1 频率限制（Rate Limiting）

```yaml
auth:
  rate_limit:
    read_only: 30/minute
    execute: 20/minute
    admin: 60/minute
```

- 超出限制返回 `429 Too Many Requests`
- 限制对象：按 API Key + IP 组合计数

### 4.2 请求体大小限制

```yaml
server:
  max_body_size: 1MB   # 防止大文件上传攻击
```

### 4.3 请求超时

```yaml
server:
  request_timeout: 30  # 秒
```

## 5. 敏感操作二次确认

对于危险操作（删除模板、删除任务链、重置配置），支持**二次确认 Token**：

### 5.1 确认 Token 流程

```
用户发起危险操作
        │
        ▼
Server 生成确认 Token（6位，有效期5分钟）
        │
        ▼
向用户推送确认卡片（钉钉/TG）
        │
        ▼
用户点击"确认执行"
        │
        ▼
携带 Token 回调 Server 验证
        │
        ▼
执行操作（一次性，Token 失效）
```

### 5.2 触发二次确认的操作

- `DELETE /api/v1/templates/{name}`
- `DELETE /api/v1/tasks/{task_id}`（仅运行中任务）
- `PUT /api/v1/config`（修改安全配置）
- `POST /api/v1/keys`（新建/删除 Key）

### 5.3 确认卡片示例（钉钉）

```
⚠️ 确认删除操作

操作：删除模板「daily_brief」
来源：手机执行Key（12.34.56.78）
时间：2026-03-28 17:30:00

[确认删除]  [取消]
```

## 6. 钉钉签名校验

钉钉自定义机器人使用 **HmacSHA256 签名**，服务端必须校验：

```
sign = BASE64(HMAC-SHA256(secret, timestamp + "\n" + timestamp))
```

请求头：
```
Timestamp: {timestamp}
Sign: {sign}
```

---

## 7. Webhook 签名校验

外部 Webhook 可选启用签名校验：

```yaml
triggers:
  webhook:
    secret: "WEBHOOK_SECRET"
    signature_header: "X-Signature-256"
```

签名算法：`HMAC-SHA256(secret, request_body)`

## 8. 操作审计日志

### 8.1 记录内容

| 字段 | 说明 |
|------|------|
| `timestamp` | 操作时间（ISO 8601） |
| `api_key_id` | Key 的哈希值（不存储明文 Key） |
| `api_key_name` | Key 的友好名称 |
| `level` | Key 权限级别 |
| `action` | 操作类型（如 `task.create`） |
| `resource` | 操作资源 |
| `params` | 请求参数（脱敏后） |
| `result` | 执行结果（success/failed/error_code） |
| `ip` | 请求来源 IP |
| `user_agent` | 请求来源 UA |

### 8.2 日志存储

- 存储方式：SQLite / PostgreSQL（可配置）
- 保留时间：默认 90 天（可配置）
- 日志级别：可按 Key 设置（只记录 EXECUTE 以上，或全记录）

### 8.3 异常告警

以下情况触发**立即告警**（钉钉推送）：
- 连续 5 次认证失败
- ADMIN Key 从新 IP 登录
- 单分钟内执行次数超过限制 3 倍
- 检测到疑似注入攻击

## 9. OpenClaw API Key 安全

OpenClaw Gateway 的 API Key 通过环境变量注入，不写入配置文件：

```bash
export OPENCLAW_API_KEY="your-openclaw-key"
python -m clawremote server
```

或使用 Docker：

```bash
docker run -e OPENCLAW_API_KEY=xxx -e DINGTALK_WEBHOOK_URL=xxx clawremote
```

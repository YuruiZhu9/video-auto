└────────┼─────────────┼─────────────┼─────────────────┼─────────┘

## 2. 核心模块

### 2.1 通信适配层（Adapters）

负责对接所有外部触发渠道：

| 适配器 | 协议 | 用途 |
|--------|------|------|
| `DingTalkHandler` | 钉钉 企业内部 Robot | 私聊/群聊消息处理 |
| `TelegramHandler` | Telegram Bot API | Bot 消息交互 |
| `HTTPHandler` | REST API | 通用 HTTP 触发 |
| `WebhookHandler` | HTTP POST | IFTTT/快捷指令等 |
| `CLIHandler` | stdin/stdout | 本地命令行调用 |

### 2.2 任务调度核心（Task Core）

```
┌─────────────────────────────────────────┐
│             TaskManager                  │
│  ┌─────────┐  ┌─────────┐  ┌──────────┐ │
│  │任务队列  │  │执行引擎  │  │模板引擎   │ │
│  │TaskQueue│  │Executor │  │Templates │ │
│  └────┬────┘  └────┬────┘  └────┬─────┘ │
│       └────────────┼────────────┘       │
│                    ▼                     │
│           ┌──────────────┐               │
│           │ TriggerEngine │              │
│           │  Cron/Webhook │              │
│           │  /HTTP/Manual  │              │
│           └──────────────┘               │
└─────────────────────────────────────────┘
```

**TriggerEngine** 支持的触发类型：
- `HTTPTtrigger`：接收 HTTP 请求触发
- `CronTrigger`：cron 表达式定时触发
- `WebhookTrigger`：外部 Webhook 触发
- `ManualTrigger`：手动通过 CLI/API 触发

### 2.3 认证安全模块（Auth）

```
API Key 分级：
┌─────────────┬────────────────────────────┐
│  Key 级别   │         权限范围            │
├─────────────┼────────────────────────────┤
│ READ_ONLY   │ 查询状态、日志、模板列表     │
│ EXECUTE     │ 执行预设模板任务            │
│ ADMIN       │ 创建模板、修改配置、管理Key │
└─────────────┴────────────────────────────┘

安全机制：
1. API Key 校验（必选）
2. IP 白名单（可选，默认全开）
3. 操作频率限制（Rate Limiting）
4. 敏感操作二次确认 Token（可选）
5. 完整操作审计日志
```

### 2.4 消息推送模块（Notify）

统一推送接口，支持多渠道：

```python
class NotifyManager:
    def send(self, template: str, context: dict, channels: list):
        """向多个渠道推送统一消息"""
        ...
```

**支持的渠道**：
- 钉钉（webhook 机器人）
- Telegram Bot
- 邮件（SMTP）
- Web（WebSocket 实时推送）

## 3. 数据流

### 3.1 典型任务执行流程

```
[用户设备] ──POST /api/v1/tasks──► [HTTP Server]
                                        │
                                    [认证校验]
                                        │
                                    [模板解析]
                                        │
                                    [任务入队]
                                        │
                        ┌───────────────┼───────────────┐
                        ▼               ▼               ▼
                 [钉钉: 任务已接收] [任务开始执行] [OpenClaw spawn]
                        │               │               │
                        └───────────────┴───────┬───────┘
                                                ▼
                                        [执行完成]
                                                │
                                        [推送结果到钉钉]
                                                │
                                        [记录审计日志]
```

### 3.2 定时任务执行流程

```
[CronTrigger] ──触发──► [TaskManager]
                              │
                         [模板加载]
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
             [钉钉通知: 任务启动]  [OpenClaw spawn]
                                        │
                                   [结果收集]
                                        │
                                 [推送结果]
```

## 4. 配置管理

```yaml
# config.yaml
server:
  host: "0.0.0.0"
  port: 8080
  debug: false

auth:
  api_keys:
    - key: "sk-xxxxx-READONLY"
      level: "read_only"
      name: "手机只读Key"
    - key: "sk-xxxxx-EXECUTE"
      level: "execute"
      name: "主执行Key"
    - key: "sk-xxxxx-ADMIN"
      level: "admin"
      name: "管理Key"
  ip_whitelist:
    - "127.0.0.1"
    # - "10.0.0.0/8"  # 公司内网
  rate_limit:
    requests: 60
    window: 60  # 60秒内最多60次请求

openclaw:
  gateway_url: "http://localhost:18789"
  api_key: "${OPENCLAW_API_KEY}"  # 从环境变量读取

notify:
  dingtalk:
    enabled: true
    webhook_url: "${DINGTALK_WEBHOOK_URL}"
    secret: "${DINGTALK_SECRET}"  # 签名密钥
  telegram:
    enabled: false
    bot_token: "${TG_BOT_TOKEN}"
    chat_id: "${TG_CHAT_ID}"

templates:
  path: "./tasks/templates.yaml"

triggers:
  http:
    enabled: true
    require_auth: true
  cron:
    enabled: true
  webhook:
    enabled: true
    secret: "${WEBHOOK_SECRET}"
```

## 5. 部署架构

```
[OpenClaw Gateway]  ← 本地 18789 端口
         │
[ClawRemote Server] ← 内网任意端口（如 8080）
         │
[ Nginx/Caddy 反向代理 ] ← 可选，对外暴露 443
         │
[ 用户设备：钉钉/手机/TG ] ← 互联网访问
```

**部署方式**：
1. **直接部署**：pip install 后直接运行 `clawremote server`
2. **Docker 部署**：一条 docker run 启动
3. **Systemd 守护**：生产环境推荐，保持进程常驻

## 6. 扩展设计

### 6.1 新增触发渠道

实现 `TriggerHandler` 接口即可：

```python
class MyCustomTrigger(TriggerHandler):
    name = "my_custom"
    
    async def start(self):
        # 启动监听
        ...
    
    async def handle(self, raw_input):
        # 解析输入，转换为标准 Task
        task = Task.from_dict(raw_input)
        await TaskManager.execute(task)
```

### 6.2 新增推送渠道

继承 `NotifyChannel` 抽象类：

```python
class WechatChannel(NotifyChannel):
    name = "wechat"
    
    async def send(self, message: str, context: dict):
        # 调用企业微信 API
        ...
```

# OpenClaw 配置周刊 - 2026-03-07

## 📖 官方文档更新

### 定时任务（Cron Jobs）配置完善
OpenClaw 定时任务运行在 Gateway 网关内部，任务持久化存储在 `~/.openclaw/cron/` 下，重启不会丢失。

**三种调度方式：**
| 类型 | 说明 | CLI 参数 |
|------|------|----------|
| `at` | 一次性时间戳（ISO 8601） | `--at` |
| `every` | 固定间隔（毫秒） | - |
| `cron` | 标准5字段表达式 | `--cron` |

**执行模式：**
- **主会话模式**：通过心跳触发系统事件
- **隔离会话模式**（推荐）：独立会话ID，不污染主聊天历史

**配置示例：**
```bash
# 每日早7点运行隔离任务并发送到Slack
openclaw cron add \
  --name "Morning brief" \
  --cron "0 7 * * *" \
  --tz "Asia/Shanghai" \
  --session isolated \
  --message "Summarize overnight updates." \
  --announce \
  --channel slack \
  --to "channel:C1234567890"
```

### 故障排除指南更新
官方文档新增21种常见问题的解决方案：

1. **API Key 问题**：`No API key found` - 需为每个 Agent 单独配置认证
2. **OAuth Token 刷新失败**：使用 `openclaw models auth setup-token` 修复
3. **Control UI HTTP 失败**：使用 `http://127.0.0.1:18789/` 或启用 HTTPS
4. **服务已安装但未运行**：检查 `openclaw gateway status`
5. **端口18789被占用**：检查 Gateway 是否已运行或 SSH 隧道
6. **沙箱中 Skill 缺少 API 密钥**：配置 `agents.defaults.sandbox.docker.env`
7. **会话未恢复**：检查会话文件是否存在或重置窗口是否太短
8. **高内存使用**：设置 `session.historyLimit` 限制历史记录

## 🔧 配置技巧

### 多代理路由最佳实践
OpenClaw 支持在同一 Gateway 上运行多个隔离的 AI 代理：

**创建新代理：**
```bash
openclaw agents add work
```

**渠道绑定配置：**
```json
{
  "agents": {
    "work": {
      "workspace": "~/.openclaw/agents/work",
      "agentDir": "~/.openclaw/state/work"
    }
  },
  "bindings": [
    {
      "agent": "work",
      "channel": "whatsapp",
      "accountId": "work-phone-id"
    }
  ],
  "defaultAgent": "default"
}
```

**沙箱安全模式：**
| 模式 | 说明 |
|------|------|
| `"sandbox": "off"` | 完全访问 |
| `"sandbox": "non-main"` | 受限访问工作空间目录 |
| `"sandbox": "all"` | 严格 - 仅聊天和网页 |

### 钉钉配置要点
1. 安装钉钉插件：`openclaw plugins install dingtalk`
2. 添加到允许列表：`plugins.allow` 包含 `dingtalk`
3. 更新插件：`openclaw plugins update`
4. 重启 Gateway

## ❓ 常见问题与解决

### Docker 环境变量覆盖问题
**问题**：Docker 中运行 OpenClaw 时，环境变量会静默覆盖配置文件中的值

**解决**：
- 确认 `~/.openclaw/openclaw.json` 中的 Token 正确
- 避免在 docker-compose 中设置会覆盖的敏感环境变量

### DeepSeek 格式错误
**问题**：本地部署报错 "DeepSeek format error"

**解决**：
- 使用严格模式
- 使用 nvm 锁定 Node 版本
- 检查 PostgreSQL 连接权限

### Node 版本依赖
**问题**：npm install 失败

**解决**：
```bash
git status
pnpm install
pnpm build
openclaw doctor
openclaw gateway restart
```

### 消息未触发
**检查清单：**
1. 发送者是否在白名单中？
2. 群聊是否需要提及？
3. 查看日志：`openclaw logs --follow`

## 🚀 最佳实践

### 1. 定时任务使用隔离会话
对于频繁或后台任务，使用 `--session isolated` 避免污染主会话历史

### 2. 定时任务传递配置
- 模型覆盖：`--model opus --thinking high`
- 代理绑定：`--agent ops`
- 定时删除：`--delete-after-run`

### 3. 多代理隔离
- 每个代理独立的 `workspace` 和 `agentDir`
- 使用 `tools.allow/deny` 控制工具权限
- 使用 `filesystem.allowedPaths` 限制文件访问

### 4. 调试模式
```bash
# 开启跟踪日志
openclaw gateway --verbose
openclaw channels login --verbose

# 配置中设置
{ "logging": { "level": "trace" } }
```

### 5. 健康检查命令
```bash
openclaw status                    # 本地摘要
openclaw status --all              # 完整诊断
openclaw status --deep             # 健康检查
openclaw gateway probe            # Gateway 发现
openclaw channels status --probe  # 渠道状态
```

### 📄 GRACE (Walmart) — CoT 分词 + 旅程感知稀疏注意力的生成式多行为推荐

- **arXiv 来源：** RecSys 2025 Full Paper（已发表）
- **一句话概括：** Walmart 提出 GRACE 框架，用链式推理（CoT）分词方式编码用户-商品交互的多行为序列，在电商多行为推荐任务上超越现有 SOTA。
- **深度解读：**
  > **背景问题：** 真实推荐场景中，用户行为不只有"点击"，还有"加购""收藏""购买""评论"等多种行为类型。现有推荐模型往往只建模单一行为序列，忽略了多行为之间的语义关联。**创新点：** GRACE 提出了 **CoT 分词（Chain-of-Thought Tokenization）** 方法，将每种行为类型编码为一个特殊的"推理标记"，同时引入**旅程感知稀疏注意力机制**——让模型在处理长序列时，能够有选择地关注用户消费旅程中的关键节点（如：浏览→加购→下单）。实验在 Walmart 真实数据集上验证，Recall@10 提升 8.3%，多行为建模显著优于单行为基线。**工业价值：** 这种方法特别适合电商平台的"用户路径分析"场景，可以更好地理解用户在购买决策中犹豫、加购后又放弃的心理。
- **工程落地参考：** 可在现有双塔模型的 user tower 中引入行为类型 embedding，配合层级注意力权重，实现多行为序列的统一建模。实现成本中等，但对转化率预测提升效果显著。

### 📄 GenSAR (人大+快手) — 用生成式检索统一搜索与推荐

- **arXiv 来源：** RecSys 2025 Full Paper（已发表）
- **一句话概括：** 人大联合快手提出 GenSAR，用统一生成式检索框架同时解决搜索和推荐两大任务，打通两个场景的数据孤岛。
- **深度解读：**
  > **背景问题：** 搜索和推荐在工业界通常是两套独立的系统，各有自己的模型、数据和工程管线。这种架构的缺点是：用户意图模糊时（如搜索词"好看的裙子"），系统无法借助推荐数据理解用户的真实偏好；用户在推荐中看到某商品但未点击，也无法将该信息传递给搜索模型。**创新点：** GenSAR 设计了**联合 S&R 标识符（Joint S&R Identifiers）** 和**统一训练任务**，让一个生成式模型同时学习搜索（给定 query 返回相关商品）和推荐（给定用户画像返回感兴趣商品）两个目标。核心思路是用语义 ID 表示商品，让模型学会在统一的语义空间中理解"搜索意图"和"推荐偏好"的内在联系。**效果：** 在快手数据集上，搜索 NDCG@10 提升 3.1%，推荐 Recall@10 提升 2.7%，两个任务都有收益。
- **工程落地参考：** 对推荐系统工程师而言，这意味着未来可以构建**统一的多模态语义索引**，同时服务搜索和推荐，降低工程复杂度。但训练成本较高，适合有足够 GPU 资源的中大厂。

### 📄 MoRE (人大) — LLM 顺序推荐中的"反思者"混合框架

- **arXiv 来源：** RecSys 2025 Full Paper（已发表）
- **一句话概括：** 人大提出 MoRE（混合反思者框架），引入三个视角感知离线反思过程，解决 LLM 推荐中"显式/隐式行为歧义"和"协同过滤信息利用不足"两大挑战。
- **深度解读：**
  > **背景问题：** 用 LLM 做顺序推荐（根据用户历史行为序列预测下一个感兴趣商品）有两个核心难题：① 显式行为（明确表达喜欢）和隐式行为（只是点击但未必喜欢）难以区分；② 协同过滤（CF）信号在 LLM 架构下没有被充分利用。**创新点：** MoRE 引入了一个**反思者（Reflector）机制**，模拟人类"思考后再推荐"的过程。具体来说，模型会对每个候选商品进行多视角评估（商品相似性视角、用户偏好一致性视角、CF 协同信号视角），综合三个视角的分数做最终排序。这个架构本质上是给 LLM 加了一个**可解释的多专家融合层**，让推荐结果既有语义理解能力，又保留协同过滤的信号。**亮点：** 该工作被模型库标记为 MIRROR/MoRE（人大），是当前 LLM4Rec 领域的重要方向。
- **工程落地参考：** 如果你在做 LLM-based 推荐系统，MoRE 的多视角评估思路值得借鉴。可以在商品候选集较大时，用多个轻量专家（embedding 相似度、CF 分数、LLM 评分）做分层过滤，提升推理效率。

### 📄 R⁴ec (快手+中科院) — 推荐系统的"慢思考"框架

- **arXiv 来源：** RecSys 2025 Full Paper（已发表）
- **一句话概括：** 快手联合中科院提出 R⁴ec，让推荐模型具备类似人类"深思熟虑"的 System-2 推理能力，通过迭代反思与修正提升推荐质量。
- **深度解读：**
  > **核心思想：** 这篇论文将 Kahneman 的"系统1/系统2"认知理论引入推荐系统。传统推荐模型是 System-1：看到用户行为立即给出推荐（快但容易出错）。R⁴ec 则让模型进入 System-2 模式：**迭代反思**（Generated Reflection）→ **自我修正**（Refinement）→ **最终推荐**。具体来说，模型首先生成一个候选推荐列表，然后分析"这些推荐是否合理？"（比如是否有同质化、是否忽略了用户长期兴趣），最后基于反思结果修正推荐。**工业价值：** 在快手短视频推荐场景中，这种方法对于"多样性推荐"和"用户长期兴趣建模"有明显提升，有效缓解"信息茧房"问题。**对转行者的启示：** 这是推荐系统从"记忆"走向"推理"的重要信号——未来的推荐算法工程师需要同时理解传统双塔模型和 LLM Agent 架构。
- **工程落地参考：** 可在推荐系统重排（Re-ranking）阶段引入 R⁴ec 风格的迭代修正模块，解决推荐结果多样性不足的问题。

### 📄 HUM (NUS/中科大) — LLM 推荐中的异构用户建模

- **arXiv 来源：** RecSys 2025 Full Paper（已发表）
- **一句话概括：** 新加坡国立大学联合中科大提出 HUM，用压缩增强器和鲁棒增强器解决 LLM 推荐中用户行为异构性问题。
- **深度解读：**
  > **背景问题：** 用户的交互行为天然是异构的——有点击、收藏、购买、评论、分享、加购、浏览时长、跳过等不同信号，而且不同平台的数据格式差异巨大。直接把这些异构行为塞进 LLM 的上下文窗口，会导致 token 浪费和噪声干扰。**创新点：** HUM 提出了**异构用户建模**框架，包含两个核心模块：① **压缩增强器（Compression Enhancer）**：用定制 prompt 将不同类型的行为压缩成统一的语义 token，减少 token 消耗；② **鲁棒增强器（Robustness Enhancer）**：在训练中加入对抗样本，提升模型对噪声行为的抗干扰能力。**实际意义：** 这个工作解决了 LLM 推荐系统在实际部署中的两个痛点：上下文长度限制 和 数据质量问题。对面试有帮助的是：理解"如何在有限上下文内最大化利用用户信息"是 LLM4Rec 的核心问题之一。
- **工程落地参考：** 如果你准备面试 LLM4Rec 相关岗位，理解 HUM 的压缩策略和鲁棒训练思路非常重要——这是工程落地的关键技术点。

### 📄 DMSG (Spotify) — 扩散模型驱动的 Slate 生成

- **arXiv 来源：** RecSys 2025 Full Paper（已发表）
- **一句话概括：** Spotify 提出基于扩散模型（Diffusion Model）的提示词条件 Slate 生成框架，突破传统生成式推荐的离散序列建模瓶颈。
- **深度解读：**
  > **创新点：** 传统生成式推荐的输出是离散的商品 ID 序列，难以用梯度优化。Spotify 的 DMSG（Diffusion Model for Slate Generation）将 **Slate（推荐列表）生成**建模为连续扩散过程——先从噪声逐步去噪生成推荐列表。这种方法的优势在于：生成过程可导，可以用梯度反向传播直接优化推荐目标（如多样性+相关性+商业收入）。**对推荐系统的意义：** 这代表了推荐系统生成模型的新方向——从"逐个生成商品 ID"转向"一次性生成完整推荐 Slate 并整体优化"。如果你是推荐系统面试候选人，理解扩散模型在推荐中的应用会是非常亮眼的加分项。
- **工程落地参考：** 适合在推荐系统精排后的 Slate 组装阶段使用，特别是需要同时优化点击率和多样性的场景（如首页推荐）。

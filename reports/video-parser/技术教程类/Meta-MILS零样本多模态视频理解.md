## 核心工具/API

### Meta MILS（Meta Instructive LLM System）

| 属性 | 详情 |
|------|------|
| **发布方** | Meta AI |
| **核心能力** | 无需额外训练，让现有LLM直接获得看图、看视频、听音频的多模态能力 |
| **技术路线** | 生成器（Generator）+ 评分器（Evaluator）双模块迭代 |
| **任务范围** | 图像描述、视频描述、音频描述、风格迁移、跨模态理解 |
| **关键特性** | 零样本学习，无需微调即可泛化到新任务 |

**架构解析**：

```
输入（图像/视频/音频）
        │
        ▼
┌──────────────────────────┐
│    生成器模块（Generator） │
│  负责生成候选解决方案       │
│  （多模态描述/解释/翻译）  │
└──────────┬───────────────┘
           │ 候选方案 N 个
           ▼
┌──────────────────────────┐
│    评分器模块（Evaluator） │
│  评估候选方案质量          │
│  输出置信度分数            │
└──────────┬───────────────┘
           │ 最优方案
           ▼
       输出结果
```

**生成器 × 评分器迭代循环**：
1. 生成器产生 N 个候选描述/解释
2. 评分器对每个候选打分
3. 高分候选进入下一轮，低分候选淘汰
4. 迭代直到评分器给出满意结果

## 步骤流程

### 接入流程：利用MILS思想增强OpenClaw视频解析

```
Step 1: 原始视频输入
  → 本地文件 / URL / B站/YouTube链接

Step 2: 多模态特征提取（对应MILS生成器）
  → FFmpeg 提取关键帧（每秒1帧）
  → FFmpeg 提取音频轨道
  → videos_understand 分析帧序列（视觉描述）
  → audios_understand 分析音频（语音+背景音）

Step 3: 多候选生成（对应MILS多候选思想）
  → 用不同Prompt生成多个版本的解析：
    - Prompt A：技术教程视角
    - Prompt B：商业价值视角
    - Prompt C：知识点清单视角

Step 4: 多维度评分（对应MILS评分器）
  → 评估各版本：
    - 完整性（是否覆盖所有重要内容）
    - 准确性（是否正确理解技术细节）
    - 可读性（语言是否清晰易懂）
  → 选择或综合最优版本

Step 5: 结构化输出
  → Markdown / JSON / 时间戳标注
```

## 适用场景

- **新视频类型探索**：遇到未知的视频类型，用MILS的多候选+评分机制探索最佳解析角度
- **质量保障**：对重要视频使用多角度解析，通过评分机制确保质量
- **学术/技术视频**：技术细节容易遗漏，使用多候选策略确保不遗漏关键知识点
- **跨语言视频**：用MILS思想生成中英双语描述，通过评分选择最优翻译

## 避坑指南

| 场景 | 常见问题 | 解决方案 |
|------|---------|---------|
| 多候选数量过多 | 生成成本高，评分慢 | 限制在3-5个候选，用 `temperature=0.7` 控制多样性 |
| 评分器主观性 | 不同视角评分标准不一致 | 按场景固定评分权重（如技术教程权重"准确性"最高）|
| 迭代轮次过多 | token消耗大，响应慢 | 设置最大迭代次数（建议≤3轮），超时强制输出当前最优 |
| 视频类型与Prompt不匹配 | 生成跑偏 | Step 3 前先用 `videos_understand` 做快速类型识别，再选对应Prompt |

## OpenClaw实战：MILS风格视频解析Prompt模板

```markdown
## 阶段1：快速类型识别
你是一个视频内容分类专家。请看视频（若无法直接观看，描述你期望的内容）：
→ 输出：视频类型（技术教程/行业分享/产品发布/其他）

## 阶段2：多候选生成
根据视频类型，生成3个不同视角的解析：

视角A（深度技术视角）：
[对应的技术分析Prompt]

视角B（实用价值视角）：
[对应的价值挖掘Prompt]

视角C（通俗易懂视角）：
[对应的易懂总结Prompt]

## 阶段3：综合评分
请对上述3个版本按以下维度打分（1-10分）：
- 完整性：[分数] + 理由
- 准确性：[分数] + 理由  
- 可读性：[分数] + 理由

综合推荐：版本[A/B/C] 或 [综合A+B的XX优点]

## 阶段4：最终输出
请按推荐版本格式输出最终解析报告。
```

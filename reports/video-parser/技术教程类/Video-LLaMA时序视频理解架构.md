## 核心工具/API

### Video-LLaMA 架构解析

| 属性 | 详情 |
|------|------|
| **发布机构** | 社区开源（基于BLIP-2/MiniGPT-4生态）|
| **核心能力** | 让LLM理解视频中的视觉+听觉内容，实现视频到文本生成 |
| **技术架构** | 视觉Q-Former + 音频Q-Former 双分支设计 |
| **预训练数据** | Webvid-2M视频标题对 + LLaVA图像指令数据 |
| **可扩展性** | 支持接入各类LLM（Vicuna/LLaMA/Qwen等）|

### 核心技术组件

#### 1. Video Q-Former（视觉分支）

```
视频帧序列（F1, F2, F3, ..., Fn）
        │
        ▼
┌──────────────────────────┐
│   帧嵌入层（Frame Embed） │
│   ViT-G/14 视觉编码        │
└──────────┬───────────────┘
           │ 帧级特征
           ▼
┌──────────────────────────┐
│   Video Q-Former          │
│   • 捕捉时序动态变化        │
│   • 跨帧注意力融合          │
│   • 输出：时序感知的视觉表示  │
└──────────┬───────────────┘
           │ Q-Former输出
           ▼
      LLM文本解码器
```

**Video Q-Former 的核心价值**：
- 解决视频"动态理解"问题：不仅看到每帧画面，还能理解动作演变
- 跟踪随时间变化的视觉场景（如"物体移动"、"表情变化"）
- 比静态图像多模态模型更懂"发生了什么"

#### 2. Audio Q-Former（音频分支）

```
音频信号（人声 + 背景音）
        │
        ▼
┌──────────────────────────┐
│   音频编码器              │
│   • 语音识别              │
│   • 音效检测              │
│   • 情感/语气分析          │
└──────────┬───────────────┘
           │ 音频特征
           ▼
┌──────────────────────────┐
│   Audio Q-Former         │
│   • 音视频时间对齐         │
│   • 跨模态特征融合         │
└──────────┬───────────────┘
           │
           ▼
      与Video Q-Former输出融合
              │
              ▼
         LLM综合理解
```

**Audio Q-Former 的核心价值**：
- 独立理解音频内容（配音、音效、环境音）
- 与视觉信息协同，增强整体理解（如"说话人口型+语音"双重验证）

## 步骤流程

### OpenClaw 中的类Video-LLaMA实践

```
原视频
  │
  ├─→ FFmpeg 提取关键帧（每秒1帧） → images_understand
  │                                    │
  ├─→ FFmpeg 提取音频轨道               │ 视觉理解
  │    → audios_understand              │
  │            │                        │
  │            └──────┐                 │
  │                   │                  │
  ▼                   ▼                  │
videos_understand（原生多模态融合）◄──────┘
  │
  ▼
LLM综合输出（时序理解 + 音频语义）
```

**各步骤对应工具**：

| 步骤 | 工具 | 说明 |
|------|------|------|
| 帧提取 | `FFmpeg -i video.mp4 -vf "select='eq(n,0)+eq(n,30)+eq(n,60)..." output_%03d.jpg` | 按时间节点采样关键帧 |
| 帧理解 | `images_understand` | 分析单帧画面内容 |
| 音频理解 | `audios_understand` | 提取语音文字和音频事件 |
| 时序融合 | `videos_understand` | 多模态融合理解，生成时序描述 |
| 结构化输出 | Prompt 工程 | 输出带时间戳的解析报告 |

## 适用场景

- **复杂演示视频**：同时有PPT画面+语音讲解+背景音乐的多轨视频
- **多人物对话**：需要区分不同说话人及其表情/动作变化
- **动作演示类**：教程中展示具体操作步骤的视频（手指动作+语音指令）
- **现场录制类**：会议/活动现场，有环境音和主要人声混合
- **音乐类视频**：MV/演奏视频，音频Q-Former可识别乐器/节奏变化

## 避坑指南

| 问题 | 原因 | 解决 |
|------|------|------|
| 帧提取太密集 | 计算成本高，且很多帧重复 | 使用 FFmpeg scene detection：`ffmpeg -i video -vf "select='gt(scene,0.3)'" -vsync vfr` 只提取场景切换帧 |
| 音频编码器混淆背景音乐与语音 | 音频信号未做VAD预处理 | 先用 Whisper VAD 过滤出纯语音段，再分析 |
| 时序信息丢失 | 关键帧间隔太大 | 长视频每30秒提取一个关键帧，同时保留时间戳 |
| 视觉+音频不对齐 | 两路分析结果时间基准不一致 | 统一以秒为单位，Whisper自带时间戳，`images_understand` 用帧号推断时间 |

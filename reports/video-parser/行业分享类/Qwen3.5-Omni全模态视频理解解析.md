## 核心工具/API

- **Qwen3.5-Omni**：阿里通义千问第 3.5 代全模态模型
- **Thinker-Talker 架构**：Thinker 负责推理，Talker 负责实时语音生成
- **TMRoPE 编码**：时序多模态旋转位置编码，处理交错音视频信号
- **ARIA（自适应速率交织对齐）**：动态文本-语音对齐，提升合成自然度
- **RVQ 编码**：语音表征编码（替代高成本 DiT 操作）
- **HuggingFace**：https://huggingface.co/Qwen/Qwen3.5-Omni-Series
- **ModelScope**：https://modelscope.cn/models/Qwen/Qwen3.5-Omni-Series

## 架构详解：Thinker-Talker

```
用户输入（视频帧 + 音频）
       ↓
┌─────────────────────────────────────┐
│           Thinker（推理大脑）          │
│  ┌─────────┐  ┌──────────────────┐  │
│  │Vision   │  │ Hybrid-Attention │  │
│  │Encoder  │  │       MoE        │  │
│  │(视觉编码)│  │   (专家混合推理)   │  │
│  └────┬────┘  └────────┬─────────┘  │
│       │                 │            │
│  ┌────┴─────────────────┴─────────┐  │
│  │      TMRoPE 时序位置编码         │  │
│  │  (统一处理交错音视频信号位置)     │  │
│  └─────────────┬───────────────────┘  │
│                ↓                      │
│     文本回复 + 语音表征 (RVQ)          │
└────────────────│─────────────────────┘
                 ↓
┌─────────────────────────────────────┐
│        Talker（语音生成器）            │
│  ┌─────────────────────────────────┐ │
│  │  ARIA 自适应速率交织对齐          │ │
│  │  + Streaming Talker             │ │
│  │  → 实时自然语音输出              │ │
│  └─────────────────────────────────┘ │
└─────────────────────────────────────┘
```

**关键创新**：
- **Chunk-wise 流式输入**：无需等待完整视频，边看边处理
- **Streaming Talker**：实时语音合成，接近人类对话节奏
- **RVQ 替代 DiT**：大幅降低语音生成的计算成本

## 视频理解核心能力

### 1. 结构化视频描述（Structured Captioning）

自动生成分"脚本级"详细描述：
- 精确时间戳（每帧描述带时间）
- 角色-音频关系映射（谁在说话？）
- 场景切换标注
- 动作和事件描述

### 2. 视频问答（Video QA）

- 支持自然语言提问视频内容
- 可处理 400+ 秒的连续视频输入
- 联合理解视觉+音频信息

### 3. 视频语义搜索

- 结构化 caption 支持精准内容检索
- 替代传统基于关键词的搜索

### 4. 内容审核与分类

- 多模态内容理解支持视频审核
- 自动打标签、分级

## 避坑指南

### 问题1：仅支持 400 秒输入
- **问题**：400 秒（约 6.7 分钟）是单次输入上限
- **解决**：对于更长视频，需要分段处理，每段独立分析后 LLM 合并

### 问题2：FPS 固定为 1
- **问题**：720P@1FPS 可能遗漏快速动作细节
- **解决**：快速动作场景建议先用 FFmpeg 提取关键片段再送入

### 问题3：需要足够的 GPU 资源
- **问题**：全模态模型参数量大，部署要求高
- **解决**：Qwen3.5-Omni-Plus/Flash/Light 三个规模可选，按需选择

### 问题4：实时性 vs 精度权衡
- **问题**：流式输出快但可能牺牲精度
- **解决**：离线分析建议批处理模式（非流式），获得更高精度

## 使用建议

**推荐使用路径：**

```
1. 短片段（<6分钟）：直接 API/HuggingFace 调用
   → Qwen3.5-Omni 直接输出结构化描述

2. 长视频（>6分钟）：分段 + 合并
   → FFmpeg 均匀分段（每段5分钟）
   → 并行调用 Qwen3.5-Omni 每段
   → LLM 合并生成总摘要

3. 实时交互场景：Streaming API
   → WebSocket 流式输入
   → Talker 实时语音反馈

4. 零成本方案：
   → 本地部署 HuggingFace 版本
   → 结合 Whisper 字幕补充音频信息
```

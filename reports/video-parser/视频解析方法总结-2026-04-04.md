## 一、场景检测与语义切分方法

### 核心工具/API

| 工具 | 功能描述 |
|------|---------|
| **FFmpeg scene detection** | 基于帧差异的镜头边界检测，自动识别场景切换点 |
| **Whisper 段落切分** | 基于语音停顿/语义边界自动切分文字稿 |
| **OpenClaw videos_understand** | 多模态理解场景语义，生成章节摘要 |
| **Python (scikit-image / OpenCV)** | 自定义场景检测算法，精度可调 |

### 步骤流程（双轨切分法）

```
视频文件
  ├─ 轨道1: FFmpeg 场景检测
  │    └─ ffmpeg -i video.mp4 -vf "select='gt(scene,0.3)',showinfo" -f null -
  │    └─ 输出时间戳列表 → 每个场景独立截帧
  │
  └─ 轨道2: Whisper 转录
       └─ whisper video.mp4 --model medium --output_format json
       └─ 输出带时间戳的段落列表
       
       ↓ 两轨合并
       
    语义切片输出：
    [00:00-00:32] 开头介绍：项目背景介绍
    [00:32-01:15] 环境配置：依赖安装步骤
    [01:15-03:42] 核心代码：主逻辑实现讲解
    [03:42-05:10] 效果演示：运行结果展示
    [05:10-05:58] 总结与展望：后续计划
```

### FFmpeg 场景检测详解

**基础命令：**
```bash
# 检测场景切换点（阈值0.3，值越高越敏感）
ffmpeg -i video.mp4 -vf "select='gt(scene,0.3)',showinfo" -f null -

# 提取所有场景首帧
ffmpeg -i video.mp4 -vf "select='gt(scene,0.3)',scale=1280:720,tile=2x2" -vsync vfr scene_%03d.jpg

# 每10秒强制截帧一次（保底策略）
ffmpeg -i video.mp4 -vf "fps=1/10" scene_%03d.jpg
```

**Python + OpenCV 精确场景检测：**
```python
import cv2
import numpy as np

def detect_scenes(video_path, threshold=30):
    """基于帧差均值的场景检测"""
    cap = cv2.VideoCapture(video_path)
    prev_frame = None
    scenes = []
    
    while True:
        ret, frame = cap.read()
        if not ret:
            break
        gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
        
        if prev_frame is not None:
            diff = cv2.absdiff(gray, prev_frame)
            mean_diff = np.mean(diff)
            
            if mean_diff > threshold:
                frame_idx = int(cap.get(cv2.CAP_PROP_POS_FRAMES))
                scenes.append(frame_idx)
        
        prev_frame = gray
    
    cap.release()
    return scenes
```

### 避坑指南

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 场景切换过于碎片化 | 阈值太低（0.3） | 调整阈值至 0.5-0.7 |
| 慢动作镜头被误判 | 画面变化小但内容不同 | 结合 Whisper 音频边界校正 |
| 截帧时间不准 | showinfo 时间戳含编码延迟 | 使用 `-vsync vfr` + 帧号反推 |
| 长视频场景过多 | 60fps视频场景边界密集 | 先降采样再检测 |

#### yt-dlp 抖音/快手命令

```bash
# 抖音下载（含水印去除）
yt-dlp "https://www.douyin.com/video/xxxxx" \
  -o "%(title)s.%(ext)s" \
  --write-auto-sub --write-subs

# TikTok下载（无需API key）
yt-dlp "https://www.tiktok.com/@user/video/xxxxx" \
  -o "tiktok_%(id)s.%(ext)s" \
  --write-auto-sub

# 快手下载
yt-dlp "https://www.kuaishou.com/short-video/xxxxx" \
  -o "kuaishou_%(id)s.%(ext)s"

# B站下载（最高画质）
yt-dlp "https://www.bilibili.com/video/BV1xx411c7XD" \
  -o "bilibili_%(title)s.%(ext)s" \
  -f "bestvideo+bestaudio/best" \
  --write-auto-sub --write-description
```

#### 抖音评论结构化提取

```python
import requests
import json

def fetch_douyin_comments(video_id, max_count=100):
    """提取抖音视频评论（需登录cookie）"""
    url = f"https://www.douyin.com/aweme/v1/web/comment/list/"
    headers = {
        "User-Agent": "Mozilla/5.0 ...",
        "Cookie": "your_cookies_here"
    }
    params = {
        "aweme_id": video_id,
        "count": 20,
        "max_cursor": 0
    }
    comments = []
    while len(comments) < max_count:
        r = requests.get(url, headers=headers, params=params).json()
        comments.extend(r.get("comments", []))
        if not r.get("has_more"):
            break
        params["max_cursor"] = r["cursor"]
    return comments
```

## 三、Video-R1：强化学习视频推理能力

### 背景

Video-R1（2025年2月）是首个将 DeepSeek-R1 的 R1 推理范式迁移到视频多模态大模型的工作，在视频理解领域引入了**基于规则的强化学习（RL）**来激发模型的时序推理能力。

### 核心方法

#### 训练流程

```
视频帧序列 → 视觉编码器 → LLM基座模型
    ↑
    └─ Video-R1 RL训练
         ├─ 可验证奖励（规则判定）
         │    └─ 时间点问答、动作序列预测
         │
         └─ GRPO算法优化
              └─ 策略梯度更新
              
输出：带推理链（Chain-of-Thought）的视频理解答案
```

#### 与传统SFT的区别

| 对比维度 | 传统SFT（有监督微调） | Video-R1（强化学习） |
|---------|------------------|-------------------|
| 数据需求 | 大规模标注数据 | 规则生成样本 |
| 推理能力 | 模仿式回答 | 自我反思+推理 |
| 时间理解 | 弱 | 强（显式时序推理） |
| 泛化能力 | 分布内好 | 分布外也好 |

### 在视频解析中的应用价值

**适用场景：**
- 需要**时序推理**的视频解析（"这个动作发生在哪个阶段？"）
- **动作序列**理解（体育、教学、舞蹈类视频）
- 视频**因果推理**（"为什么这个bug会出现？"）

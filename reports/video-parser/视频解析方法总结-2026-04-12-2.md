### 1. StreamMind（技术教程 - ICCV 2025）

**一句话定位**：微软亚洲研究院 × 南京大学，将流式视频处理能力提升 **10 倍**，单卡 A100 即可实现 **100fps 实时推理**，彻底改变 AI 助手处理流媒体视频的方式。

**核心创新：感知与认知解耦**

传统方法将感知（看视频帧）和认知（理解内容）耦合在一起，导致：
- 高帧率视频（如 100fps 游戏视频）计算量爆炸
- 实时响应延迟高
- 资源浪费严重

StreamMind 通过两项核心技术实现解耦：

**① EPFE（事件保留特征提取器）**
- 基于状态空间方法（SSM），用恒定成本提取时空特征
- 生成融合多帧信息的单一紧凑表示，保留事件动态
- 将高帧率视频压缩为可处理的形式

**② 认知门控（Cognition Gate）**
- 决定何时"触发"LLM认知推理
- 仅在事件发生显著变化时才调用重型模型
- 大幅减少推理调用次数，降低延迟

**技术规格**

| 指标 | 数值 |
|------|------|
| 帧率支持 | 100fps（单卡 A100） |
| 推理速度 | 实时（< 1 秒延迟） |
| 核心架构 | VideoLLaMA 2 + EPFE + Cognition Gate |
| 应用场景 | 监控分析/游戏直播/体育解说/AI助手实时视频流 |

**适用场景**

- **游戏视频理解**：100fps 游戏画面实时分析（如 FPS 游戏操作识别）
- **体育直播**：实时解说生成、精彩瞬间捕捉
- **监控流**：多路摄像头实时异常检测
- **AI助手集成**：边看边聊的实时视频对话

**与同类技术对比**

| 方法 | 帧率支持 | 延迟 | 适用场景 | 开源 |
|------|---------|------|---------|------|
| **StreamMind** | 100fps | <1s | 游戏/直播/监控 | ✅ GitHub |
| StreamingVLM | 实时 | ~8 FPS | 直播/监控 | ✅ |
| CurveStream | 实时 | — | 监控/体育 | ✅ CVPR 2026 |
| Gemini 2.5 | 有限 | 分钟级 | 离线长视频 | ❌ |

**安装与使用**

```bash

git clone https://github.com/xinding-sys/StreamMind.git
cd StreamMind && pip install -r requirements.txt
# 基于 VideoLLaMA 2，适配 EPFE + Cognition Gate
```

### 2. VideoMind（技术教程 - 港理工 + 新国立）

**一句话定位**：港理工 × 新国立联合发布长视频理解框架，**角色化推理（Role-based Reasoning）** 模拟人类理解叙事视频的方式，**Chain-of-LoRA** 策略高效处理多角色场景，**27 分钟长视频理解超越 GPT-4o**。

**核心问题**

长视频（如电影、纪录片、长访谈）面临三大挑战：
1. **多角色混淆**：谁在说话？在做什么？
2. **场景复杂性**：同一角色在不同场景的多次出现
3. **信息密度**：海量内容中如何找到关键信息

**角色化推理（Role-based Reasoning）**

VideoMind 不将视频视为"帧序列"，而是建模为"角色互动网络"：

1. **角色发现**：自动识别视频中的角色（人脸/声音/文字识别）
2. **角色轨迹**：追踪每个角色在整部视频中的出现轨迹
3. **角色视角**：针对特定角色提问时，仅分析该角色的内容
4. **角色关系**：建模角色间的互动关系（对话/协作/对立）

**Chain-of-LoRA 策略**

为每个角色分配专属的 LoRA 适配器，链式调用：
- 角色 A 的 LoRA → 理解角色 A 的内容
- 角色 B 的 LoRA → 理解角色 B 的内容
- 角色关系 LoRA → 理解角色间互动
- 避免一个通用模型处理所有角色导致的能力稀释

**性能数据**

| 模型 | 27分钟视频理解准确率 | 备注 |
|------|-------------------|------|
| **VideoMind** | **超越 GPT-4o** | 港理工+新国立联合 |
| GPT-4o | 基线 | — |
| Gemini 1.5 Pro | 较高 | — |

**适用场景**

- **电影/剧集理解**：角色行为分析、剧情推理、多角色关系图
- **会议记录**：区分发言人，追踪每个人的观点演变
- **教学视频**：区分讲师/学生/屏幕内容
- **体育赛事**：追踪球员、战术分析

**技术启示**

> VideoMind 的角色化推理思路，可直接迁移到**推荐系统视频理解**：
> - 用户行为视频中识别"用户"和"商品"
> - 直播带货视频中区分"主播"和"商品展示"
> - 美食视频中追踪"厨师动作"和"食材"

### 3. Video-RAG（行业分享 - NeurIPS 2025）

**一句话定位**：用视觉对齐辅助文本（OCR+ASR+目标检测）赋能任意 LVLM，实现**无需微调**的长视频理解，72B 模型达 **77.4% Video-MME**，超越 GPT-4o。

**三阶段架构**

```
视频输入
  ↓
┌─ 阶段1：查询解耦
│  LLM 分析用户问题 → 生成多个检索子请求
│  例："视频中第三段提到的技术名词" → ["第三段", "技术名词"]
│
├─ 阶段2：辅助文本生成与检索（并行）
│  ├─ OCR 通道：检测画面文字
│  ├─ ASR 通道：转录音频
│  └─ 目标检测通道：识别画面物体/人物
│  → 生成"视觉对齐辅助文本"，与视频帧对齐存储
│
└─ 阶段3：集成生成
   将辅助文本 + 视频帧特征输入 LVLM
   → 即插即用到 LLaVA-Video / Qwen-VL 等任意模型
```

**核心洞察**

- 不依赖视频字幕，纯靠视觉 AI 生成"伪字幕"
- 可用于**无字幕视频**的理解
- 与 Whisper 转录互补（语音字幕 vs 视觉文本）

**适用场景**

- 电影/剧集（无字幕）理解
- 监控视频分析
- 学术报告（PPT 无声音）理解

### 4. VideoStir（行业分享 - ACL 2026）

**一句话定位**：将视频建模为**时空图**（Spatial-Temporal Graph），通过多跳检索和意图感知评分，实现从"扁平语义检索"到"结构化推理"的范式转变。

**核心创新**

传统视频 RAG 的局限：
- 将视频内容扁平化为文本片段
- 无法处理"视频中某个角色的第三次出场是什么场景"这类问题
- 忽略时间和空间关系

VideoStir 的解决思路：
1. **时空图构建**：节点=角色/物体/事件，边=时空关系（before/during/after）
2. **多跳检索**：支持多步推理（角色 A 出现 → 附近的事件 B → 事件的属性 C）
3. **意图感知评分**：M LLM 评估检索结果与用户意图的匹配度

**适用场景**

- 电影问答（如"主角第二次拿起那把刀的场景是什么"）
- 体育赛事分析（战术演变追踪）
- 监控视频多步查询

### SubExtractor：硬字幕 OCR 提取

yt-dlp 可以提取 YouTube/B 站的**软字幕**（CC字幕），但对于**硬编码字幕**（烧录在画面上的字幕）无能为力。SubExtractor 通过 AI OCR 技术填补这一空白：

```
视频输入
  ↓ FFmpeg 逐帧提取
帧序列 → PaddleOCR/PaddlePaddle → 文本坐标对齐
  ↓ 时间戳匹配
SRT / VTT / ASS 格式输出
```

**支持格式**：SRT、VTT、ASS、TXT  
**语言**：40+ 语言（含中文、日文、韩文）  
**准确率**：95%+（干净画面）

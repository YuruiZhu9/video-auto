## 一、为什么推荐系统工程师需要视频解析？

推荐系统的核心挑战之一是**内容理解**——只有真正理解视频内容，才能做好召回与排序。

| 传统方法 | 痛点 | 视频解析带来的改变 |
|---------|------|-----------------|
| 人工打标签 | 成本高、不覆盖长尾 | 多模态VL模型自动生成标签 |
| 用户行为数据 | 冷启动问题严重 | 视频内容语义特征补充 |
| 标题/描述文本 | 信息有限、噪声多 | 视觉+音频+语音多模态融合 |
| 协同过滤 | 稀疏性问题 | 视频内容向量补充用户-内容匹配 |

**推荐系统视频理解的典型应用场景：**
- **召回阶段**：视频 embedding 向量相似度检索
- **排序阶段**：视频内容标签作为特征输入排序模型
- **冷启动**：新视频发布后立即生成内容标签，不依赖用户行为
- **内容多样性控制**：基于视觉语义做内容去打散

## 二、视频多模态 Embedding 在推荐中的应用

### 2.1 核心技术路线

**路线A：直接用开源 VL 模型生成向量**
- **InternVideo2.5**（上海AI Lab）：Video-MME 冠军，支持万帧超长视频
  - 推荐系统用法：视频→逐帧/关键帧采样→ViT编码→向量
  - 优势：国产开源，ModelScope 直接调用
  - 劣势：向量维度高（768-1024），需 PCA 降维
- **Qwen-VL / Qwen3.5-Omni**（阿里）：支持视频理解，256k 上下文
  - 推荐系统用法：视频整体描述+关键帧向量
  - 优势：中文优化好，支持流式
- **SmolVLM2**（HuggingFace）：最轻量，500M 参数可 iPhone 运行
  - 推荐系统用法：边缘设备视频特征提取

**路线B：专用视频 Embedding API**
- **Google Gemini Embedding 2**：统一文本/图像/视频/音频四模态
  - Mixpeek 2026 基准测试：在视频检索任务上表现优异
  - 推荐系统优势：一次 embedding 全模态可用
- **Twelve Labs**：`julie` 模型，专为视频语义搜索设计
  - 支持自然语言视频片段检索
  - 适合：短视频平台搜索推荐一体化

### 2.2 开源推荐系统+视频模型结合论文

| 论文/工作 | 核心方法 | 推荐任务 |
|----------|---------|---------|
| **VideoCLIP** (Meta) | 对比学习视频-文本预训练 | 零样本视频推荐 |
| **XMU** | 视频+图文多模态融合 | 抖音推荐 |
| **MMSSL** | 多模态自监督学习 | YouTube 推荐 |
| **MSSR** | 语义感知视频表示 | 视频推荐 |
| **LLM-MHR** | LLM增强多模态标签推荐 | 多模态标签推荐 |

## 三、端到端 Pipeline：从视频到推荐特征

### 3.1 完整 Pipeline 架构

```
原始视频（上传/爬取）
    │
    ▼
┌──────────────────────┐
│  Step 1: 视频下载     │  yt-dlp / MCP parse_video
└──────────────────────┘
    │
    ▼
┌──────────────────────┐
│  Step 2: 关键帧提取   │  FFmpeg（固定间隔 / 场景检测）
└──────────────────────┘
    │
    ├─→ 【字幕/文字】Whisper 转录 → 文本向量（text2vec）
    │
    └─→ 【视觉】VL模型编码 → 视觉向量（video-vec）
    │
    ▼
┌──────────────────────────────┐
│  Step 3: 多模态特征融合       │
│  视觉向量 + 文本向量 + 音频向量 │
└──────────────────────────────┘
    │
    ▼
┌──────────────────────────────┐
│  Step 4: 生成结构化标签       │
│  VL模型 → LLM → 标签列表      │
│  （题材/风格/场景/人物/情绪）  │
└──────────────────────────────┘
    │
    ├─→ 【召回】向量入库 FAISS/Milvus，ANN检索
    ├─→ 【排序】标签特征 + 向量输入排序模型
    └─→ 【冷启动】新视频立即生成标签，不依赖行为数据
```

### 3.2 各步骤工具选型

| 步骤 | 推荐工具 | 成本 | 适用规模 |
|------|---------|------|---------|
| 视频下载 | yt-dlp / MCP parse_video | 免费 | 任意规模 |
| 关键帧提取 | FFmpeg（固定间隔/场景检测） | 免费 | 任意规模 |
| 视觉向量 | InternVideo2.5 / Qwen-VL | GPU成本 | 中等规模（<10万视频/天） |
| 文本向量 | BGE / text2vec-base | GPU成本 | 任意规模 |
| 向量存储 | FAISS（单机）/ Milvus（分布式）| 免费 | 任意规模 |
| 结构化标签 | Qwen3.5-Omni / Gemini 2.5 | API成本 | 任意规模 |

## 四、冷启动场景：视频标签自动化

### 4.1 标签体系设计

推荐系统视频标签通常分三层：

| 层级 | 示例 | 生成方式 | 粒度 |
|------|------|---------|------|
| **题材层** | 科技/美食/娱乐/游戏 | VL模型直接判断 | 粗 |
| **主题层** | AI教程/手机评测/开箱 | VL模型+LLM解析 | 中 |
| **细粒度标签** | "大模型训练" / "iPhone续航测试" | LLM从字幕/帧描述提取 | 细 |

### 4.2 自动化标签生成流程

```python
# 伪代码示例
def generate_video_tags(video_path):
    # 1. 截取关键帧（每30秒一帧）
    frames = extract_frames(video_path, interval=30)
    
    # 2. VL模型生成帧描述
    frame_descriptions = []
    for frame in frames:
        desc = vlm_model.analyze(frame)  # Qwen-VL / InternVideo
        frame_descriptions.append(desc)
    
    # 3. Whisper生成字幕
    transcript = whisper.transcribe(audio_of(video_path))
    
    # 4. LLM综合生成标签
    prompt = f"""
    视频帧描述：{frame_descriptions}
    字幕内容：{transcript[:2000]}
    请生成JSON格式标签：
    {{
        "categories": ["题材"],
        "topics": ["主题"],
        "tags": ["细粒度标签"],
        "sentiment": "正面/中性/负面",
        "target_audience": "目标用户"
    }}
    """
    tags = llm.generate(prompt)
    return tags
```

## 五、召回阶段：向量相似度检索

### 5.1 核心流程

1. **视频向量入库**：每日将新增视频的 embedding 入库 FAISS/Milvus
2. **用户行为向量构建**：用户看过的视频向量聚合（如加权平均）
3. **ANN检索**：给定用户向量，召回 TOP-N 相似视频

### 5.2 工具链

| 工具 | 用途 | 优点 |
|------|------|------|
| **FAISS** | 向量最近邻检索 | Facebook开源，单机性能好 |
| **Milvus** | 分布式向量数据库 | 支持百亿级向量 |
| **Qdrant** | 轻量级向量检索 | 支持metadata过滤 |
| **PGVector** | PostgreSQL插件 | 关系数据+向量一体化 |

## 六、避坑指南

| 坑 | 问题 | 解决方案 |
|---|------|---------|
| **向量维度爆炸** | 高维向量检索慢、存储成本高 | PCA降维到128-256维 |
| **镜头重复帧** | 连续相似帧导致向量冗余 | 使用 PySceneDetect 场景检测去重 |
| **水印干扰** | B站/抖音水印影响视觉向量 | 先用 OpenCV 去除水印区域 |
| **长视频向量平均** | 时序信息丢失 | 分段向量 + 时序加权 |
| **字幕质量差** | 背景音乐干扰Whisper | 音频分离（Demucs）+ VAD过滤 |
| **跨语言视频** | 中文模型处理英文视频效果差 | 翻译+双语模型混合 |
| **实时性** | 批量处理延迟高 | 流式处理 + 增量索引 |

## 七、推荐系统工程师上手建议

### 第一步（Day 1）：用 OpenClaw 快速验证
```
1. yt-dlp 下载 100 条测试视频
2. FFmpeg 批量截帧（每30秒1帧）
3. videos_understand 批量理解（注意平台限额）
4. 手动验证标签质量
```

### 第二步（Week 1）：搭建原型 Pipeline
```
1. Whisper 批量转录（本地，零成本）
2. VL模型批量生成向量（InternVideo2.5 / Qwen-VL）
3. FAISS 向量入库
4. 简单 cosine 相似度召回实验
```

### 第三步（Month 1）：生产化
```
1. 引入 Milvus / Qdrant 管理向量
2. 设计标签体系并用 LLM 批量生成
3. 特征接入推荐排序模型（标签作为输入特征）
4. A/B 测试验证效果提升
```
